7.1 IV-Adaptive Grid — ปรับ Step ตาม Implied Volatility

แทนที่จะใช้ ATR (backward-looking) — ใช้ Implied Volatility จาก Options market ซึ่งเป็น forward-looking:

$$\text{Step}_\text{IV} = 0.5 \times \frac{\text{IV}_\text{annual}}{\sqrt{365}} \times P \qquad \text{(1-day vol × price)}$$
IV-Adaptive Step Implementation: def iv_adaptive_step(iv_annual_pct, current_price, fee_rate=0.001, step_factor=0.5): """ iv_annual_pct: Implied Volatility ต่อปี (เช่น 0.65 = 65%) """ # Convert annual IV to daily IV iv_daily = iv_annual_pct / (365 ** 0.5) # 1-day expected move (1σ) expected_daily_move = iv_daily * current_price # Step = fraction of expected daily move step = step_factor * expected_daily_move # Ensure profitability (≥ 3× fee) min_step = 3 * current_price * fee_rate * 2 step = max(step, min_step) return round(step / 100) * 100 # round to $100 # ตัวอย่าง: # BTC IV (7d ATM) = 65% annualized, P = $100,000 # iv_daily = 65% / sqrt(365) = 3.40%/day # expected_move = 3.40% × $100,000 = $3,400 # step = 0.5 × $3,400 = $1,700 → round → $1,700 # เทียบ ATR-based (ATR=2,500): # step_atr = 0.5 × $2,500 = $1,250 # → IV-based step ใหญ่กว่า เพราะ market expect volatility สูง
IV Rank — เลือก Zone Width ตาม IV Percentile

IV Rank = (IV_current − IV_min_52w) / (IV_max_52w − IV_min_52w) × 100

  • IV Rank < 20 (low IV): zone แคบ, step เล็ก → grid fill บ่อย (mean-reverting regime)
  • IV Rank 20–60 (normal): zone ปกติ, step ≈ 0.5 × IV_daily × P
  • IV Rank 60–80 (elevated): zone กว้างขึ้น, step เพิ่ม 20–40% → ระวัง breakout
  • IV Rank > 80 (high IV): zone กว้าง, step ใหญ่ → ป้องกัน excess fill ใน high vol

อ้างอิง: Vol Series Part 2 สำหรับ IV Rank calculation

IV Rank กำหนด Step และ Zone Width — IV ต่ำ: grid แน่น / IV สูง: grid กว้าง ป้องกัน over-fill

7.2 Funding Rate Adaptive Grid

Funding Rate ของ BTC Perpetual เปลี่ยนตาม market sentiment — grid สามารถ adapt ตาม Funding Rate ได้ (กลไกว่าทำไม funding มีอยู่และทำไมพลิกทิศได้ ดู Part 1C §1C.3 "ค่าเช่าความห่าง" — เลข ×3/วัน ที่ใช้ทั้ง section นี้คือรอบเก็บของ exchange ที่เก็บทุก 8 ชม. ไม่ใช่กฎธรรมชาติ เช็คคู่มือ exchange จริงก่อนตั้งในบอท):

Funding Rate Grid Rules: Funding Rate > 0 (Long จ่าย Short รับ): → Short Layer (Part 1B) ได้ income เพิ่ม → เพิ่ม Q ของ short layer → เปิด Grid Hedge (Part 1C) ได้ดี Funding Rate < 0 (Short จ่าย Long รับ): → Short layer เสียต้นทุนเพิ่ม → ลด Q short layer หรือปิด short ชั่วคราว → ถ้า negative มาก → หยุด hedge def funding_adaptive_short_size(funding_rate_8h, base_q_short, threshold_high=0.001, threshold_low=-0.0005): """ funding_rate_8h: funding rate ต่อ 8 ชั่วโมง (เช่น 0.001 = 0.1%) """ if funding_rate_8h > threshold_high: # High positive funding → เพิ่ม short (เก็บ funding มากขึ้น) multiplier = min(2.0, 1 + (funding_rate_8h - threshold_high) / 0.001) elif funding_rate_8h < threshold_low: # Negative funding → ลด short (ลด cost) multiplier = max(0.0, 1 + (funding_rate_8h - threshold_low) / 0.001) else: # Normal range → ไม่เปลี่ยน multiplier = 1.0 return base_q_short * multiplier Funding Income Calculation (สำหรับ Hedge Grid): short_notional = inventory_btc × current_price daily_funding = short_notional × funding_rate_8h × 3 # 3 periods/วัน monthly_funding = daily_funding × 30 ตัวอย่าง: Inventory = 0.05 BTC, Price = $100k, Rate = 0.05%/8h Daily funding = (0.05 × $100k) × 0.05% × 3 = $5,000 × 0.15% = $7.50/วัน Monthly = $7.50 × 30 = $225/เดือน (ได้เพิ่มจาก hedge)

7.3 Cash-Secured Put (CSP) + Grid — Inventory Entry

แทนที่จะซื้อ BTC ตรงๆ ผ่าน BUY limit order — ใช้ CSP (Cash-Secured Put) เพื่อซื้อ BTC ในราคาที่ต้องการ พร้อมรับ premium:

CSP + Grid Concept: ปัญหาของ BUY limit order: วาง BUY $90,000 รอ → อาจรอนาน หรือไม่ fill เลย → capital idle CSP Solution: SELL PUT $90,000 expiry 2 สัปดาห์ → รับ premium $500 ทันที → ถ้า BTC < $90,000 → ถูก assign = ซื้อ BTC ที่ $90,000 (ตามแผน) → ถ้า BTC > $90,000 → PUT หมดอายุ = เก็บ premium $500 โดยไม่ต้องซื้อ Net effect: ซื้อ BTC ที่ effective price = $90,000 − $500 = $89,500 (ถูกกว่า limit order) หรือเก็บ premium $500 ถ้าไม่ถูก assign def csp_vs_limit_order(target_price, option_premium): """ เปรียบ CSP กับ limit order — คืนทั้ง 2 scenario ที่เป็นไปได้ ณ expiry (ไม่ต้องรู้ expiry_price ล่วงหน้าเพื่อเปรียบเทียบ เพราะอยากเห็นทั้งคู่พร้อมกัน) """ # Limit Order: รอ fill ที่ target_price limit_effective_cost = target_price # CSP: 2 scenario ที่เป็นไปได้เมื่อถึง expiry csp_cost_if_assigned = target_price - option_premium # BTC < strike → assign csp_income_if_not_assigned = option_premium # BTC >= strike → หมดอายุ เก็บ premium return { "limit_cost": limit_effective_cost, "csp_cost_if_assigned": csp_cost_if_assigned, "csp_income_if_not_assigned": csp_income_if_not_assigned } สำหรับ Grid: แทน BUY order แต่ละ level ด้วย CSP Level $90k → SELL PUT $90k strike Level $92k → SELL PUT $92k strike Level $94k → SELL PUT $94k strike (ขาย multiple CSP แทน multiple limit orders)
ข้อจำกัดของ CSP + Grid
  • ต้องการ capital เต็มสำหรับ assignment (เช่น SELL PUT $90k ต้องมี $90,000 พร้อม)
  • BTC Options บน Deribit/Bybit — liquidity ต่ำกว่า spot หรือ perp
  • Expiry ต้องตรงกับ grid horizon (ไม่ควร expiry นานเกินกว่า 2× grid rebalance cycle)
  • ใน downtrend แรง: PUT ถูก assign ทุก level → ซื้อ BTC ที่ราคาลงต่อ (เหมือน Close System)

7.4 Short Strangle + Grid — Income Enhancement

เมื่อ grid อยู่ในโซน sideway + IV สูง: SELL CALL ที่ zone_high และ SELL PUT ที่ zone_low → เก็บ premium จาก "range-bound expectation":

Short Strangle + Grid: Grid Zone: BTC $90k–$110k Short Strangle: SELL PUT $90,000 (strike = zone_low) SELL CALL $110,000 (strike = zone_high) Premium received: PUT $800 + CALL $600 = $1,400 total Scenarios: 1. BTC อยู่ $90k–$110k → Strangle ไม่ถูก assign → เก็บ $1,400 Grid cashflow ยังทำงาน → Double income 2. BTC < $90k → PUT assign → ซื้อ BTC $90k (= zone_low grid ทำงาน) Grid ก็ BUY ที่ $90k อยู่แล้ว → Strangle ช่วยลด cost 3. BTC > $110k → CALL assign → ขาย BTC $110k (= zone_high grid ก็ขาย) Grid SELL ที่ $110k อยู่แล้ว → Strangle ช่วยเพิ่ม income ข้อดี: ทั้ง 3 scenarios เป็นผลดี — strangle "align" กับ grid zone ข้อระวัง: ถ้า BTC พุ่งเกิน $110k ไกลมาก → CALL loss สูง (unlimited loss) → ต้อง hedge CALL → ซื้อ OTM CALL เป็น hedge → เปลี่ยนเป็น Iron Condor (max loss ถูก cap) Iron Condor ตัวอย่าง (Grid zone $90k–$110k): Short Strangle เดิม: SELL PUT $90k + SELL CALL $110k → premium $1,400 (unlimited risk) Iron Condor (เพิ่ม long wings + ขยับ short strike ออกไปอีกหน่อย — ไกลจาก spot มากขึ้น premium ฝั่ง short ต้องต่ำกว่าเดิม ไม่ใช่ premium เท่าเดิม): SELL PUT $88k + BUY PUT $82k → net premium: +$550 − $100 = +$450 SELL CALL $113k + BUY CALL $120k → net premium: +$400 − $120 = +$280 Total net premium = +$730 (ลดลงจาก $1,400 ทั้งจาก long wings และจาก short strike ที่ไกลขึ้น แต่ risk ถูก cap) Max loss ถ้าทดสอบฝั่ง PUT เท่านั้น: ($88k − $82k) − $730 (net premium รวมทั้งคู่) = $5,270 Max loss ถ้าทดสอบฝั่ง CALL เท่านั้น: ($120k − $113k) − $730 (net premium รวมทั้งคู่) = $6,270 (มีแค่ฝั่งเดียวที่ถูกทดสอบตอน expiry เสมอ — อีกฝั่งหมดอายุไร้ค่า เก็บ premium เต็ม ดังนั้น max loss รวม = max(PUT width $6k, CALL width $7k) − net premium รวม $730) เปรียบเทียบ: Short Strangle: premium $1,400 · CALL loss ไม่จำกัด Iron Condor: premium $730 · max loss ~$6,270 (defined risk — ไม่ใช่ผลรวม max loss ของแต่ละฝั่งแยกกัน) def grid_strangle_income(zone_low, zone_high, put_premium, call_premium, grid_daily_cashflow, days_to_expiry): """ ประมาณ total income ต่อ expiry cycle """ option_income = put_premium + call_premium grid_income = grid_daily_cashflow * days_to_expiry total = option_income + grid_income return { "option_premium": option_income, "grid_cashflow": grid_income, "total": total, "daily_equivalent": total / days_to_expiry }

7.5 GARCH-Based Volatility Forecasting สำหรับ Step

GARCH (Generalized Autoregressive Conditional Heteroskedasticity) คือโมเดลทำนาย volatility ที่คำนึงถึง volatility clustering — ช่วง vol สูงมักตามด้วย vol สูงต่อเนื่อง (อ้างอิงเต็มใน Vol Series Part 2) สอนวิธี fit + ใช้ GARCH(1,1) ตั้ง step เต็มรูปแบบไว้แล้วใน Part 3 §3.6 (รวม fit window 90 วัน, forecast horizon 7 วัน, และตัวอย่างว่า step ปรับตัวเร็วแค่ไหนหลัง flash crash) — ในบทนี้แค่เชื่อมว่า GARCH ที่ตั้ง step มาแล้ว เอาไปผสมกับ funding-adaptive sizing (§7.2) และ IV-adaptive step (§7.1) ได้อย่างไรเมื่อเปิด grid จริง

7.6 Running Example — IV + Funding + Grid

🔁 Running Example: Advanced Grid ที่ใช้ IV + Funding Rate

Setup: BTC=$100k · IV(7d)=70% · Funding rate=0.08%/8h · Grid capital=$20,000

Step 1: IV-Adaptive Step iv_daily = 70% / sqrt(365) = 3.66%/day step = 0.5 × 3.66% × $100k = $1,830 → $1,800 (round) ✓ ใหญ่กว่า ATR-based ($1,250) เพราะ market expect vol สูง Step 2: Funding Rate Assessment Rate = 0.08%/8h = 0.24%/วัน threshold_high = 0.1% → Rate (0.08%) < threshold → multiplier = 1.0 (ไม่ปรับ Q) แต่ positive funding → เปิด hedge short เพื่อเก็บ funding income (ดู Part 1C) Step 3: Grid Hedge (Part 1C) Inventory BTC (5 levels): 0.05 BTC worst case Perp short: 0.05 BTC × $100k = $5,000 notional (10× → $500 margin) Daily funding: $5,000 × 0.08% × 3 = $12/วัน Step 4: Short Strangle SELL PUT $88,000 (zone_low − 2σ buffer) → premium $400 SELL CALL $113,000 (zone_high + 1σ buffer) → premium $350 Total premium = $750 / 14 วัน = $53.6/วัน Step 5: Total Daily Income Grid cashflow: $54/วัน Funding income: $12/วัน Strangle income: $53.6/วัน Total: $119.6/วัน = 0.60%/วัน บน $20,000 ✓ เทียบ grid alone: $54/วัน = 0.27%/วัน (+121% จาก integration)

7.7 แบบฝึกหัด

แบบฝึกหัด Part 7
ข้อ 1: BTC IV(7d)=80%, P=$95,000 — IV-adaptive Step คือเท่าไหร่?

คำตอบ:

iv_daily = 80% / √365 = 80% / 19.1 = 4.19%/day

expected_move = 4.19% × $95,000 = $3,980

step = 0.5 × $3,980 = $1,990 → round → $2,000

min_step = 3 × $95k × 0.1% × 2 = $570 → ผ่าน (2,000 > 570) ✓

ข้อ 2: Funding rate = −0.03%/8h · Short notional $8,000 · Grid cashflow $40/วัน — Net P&L/วัน?

คำตอบ:

Funding cost (short จ่ายเพราะ rate ลบ) = $8,000 × 0.03% × 3 = $7.2/วัน

Grid cashflow = $40/วัน

Net P&L = $40 − $7.2 = $32.8/วัน

ยังกำไรอยู่ แต่ถ้า rate ลบเพิ่มเป็น −0.15%/8h → cost = $36/วัน → net = $4/วัน → ควรลด short size

ข้อ 3: Short Strangle: SELL PUT $88k + SELL CALL $115k · Premium $1,200 · Grid คาดว่า BTC อยู่ $90k–$112k · Expiry 2 สัปดาห์ — ความเสี่ยงหลักคืออะไร?

คำตอบ:

ความเสี่ยงหลัก: Tail events

CALL risk: BTC พุ่งเกิน $115k → CALL assign → ต้องขาย BTC ที่ $115k แม้ราคาตลาดสูงกว่า → เสียโอกาสกำไร (หรือขาดทุนถ้าไม่มี BTC)

PUT risk: BTC ดิ่งต่ำกว่า $88k → PUT assign → ซื้อ BTC $88k แม้ราคาต่ำกว่า → Inventory เพิ่มเยอะ

ป้องกัน: ซื้อ Iron Condor แทน (SELL PUT $88k + BUY PUT $82k + SELL CALL $115k + BUY CALL $121k) → จำกัด max loss แต่เสียบาง premium

ข้อ 4: เมื่อไหร่ควรใช้ CSP แทน BUY limit order ใน grid?

คำตอบ:

ใช้ CSP แทน BUY limit order เมื่อ:

  • IV สูง (IV Rank > 50) → premium สูงคุ้มกว่า rounding ของ limit order
  • Sideways market ชัดเจน → PUT likely expire worthless → เก็บ premium โดยไม่ต้องซื้อ BTC
  • มี Options liquidity บน Exchange นั้น (Deribit, OKX)
  • Horizon ตรงกัน: ถ้า grid rebalance ทุก 2 สัปดาห์ → expiry 2 สัปดาห์

ไม่ใช้ CSP เมื่อ: IV ต่ำมาก (premium น้อยเกิน), Options spread กว้าง (bid-ask cost เยอะ), ราคาใกล้ zone_low มาก (PUT likely assign ทันที)
