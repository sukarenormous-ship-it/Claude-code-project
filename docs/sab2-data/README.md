# sab2-data · ชุดข้อมูลกลางของเล่ม 2

ชุดข้อมูลจริง 📡 ที่ทุกบทของเล่ม 2 ใช้ร่วมกัน สร้างและตรวจด้วย `tools/sab2_realdata.py` (Python ล้วน ไม่ต้องติดตั้งอะไรเพิ่ม)

## มีอะไรบ้าง

| ไฟล์ | คืออะไร |
|---|---|
| `closes-daily.csv` | ราคาปิดรายวันตามเวลา UTC (เวลาสากลเชิงพิกัด) ของ 10 เหรียญ: BTC ETH BNB SOL XRP ADA DOGE LTC LINK DOT หน่วย USDT จาก Binance Spot (ตลาดซื้อขายทันที) · 2022-11-15 ถึง 2026-11-14 · 1,461 วัน ครบทุกวัน |
| `funding-8h.csv` | Funding Rate (อัตราค่าธรรมเนียมการถือสถานะ) ทุกรอบ 8 ชั่วโมง ของ Perpetual Futures (สัญญาล่วงหน้าแบบไม่มีวันหมดอายุ) BTC-USDT-SWAP · ETH-USDT-SWAP · SOL-USDT-SWAP จาก OKX · 2026-08-10 16:00 ถึง 2026-11-14 16:00 UTC · 289 รอบต่อสัญญา |
| `splits.json` | ช่วงแบ่งตายตัวทั้งเล่ม (ดูด้านล่าง) |
| `manifest.json` | ทุกไฟล์ดิบ: URL · เวลาที่ดึง · ขนาด (ไบต์) · sha256 |
| `raw/` | คำตอบของ API ตามที่ได้มา ไม่แก้แม้แต่ไบต์เดียว (Binance 20 ไฟล์ · OKX 12 ไฟล์ · Kraken 2 ไฟล์) |

หัวของ CSV ทั้งสองไฟล์ (บรรทัดที่ขึ้นด้วย `#`) บอกแหล่ง เวลาดึง และผลตรวจของแต่ละเหรียญ/สัญญา

## ทำไมเลือกเหรียญเหล่านี้

เป็นเหรียญใหญ่ที่ซื้อขายบน Binance คู่กับ USDT ต่อเนื่องตลอดสี่ปีโดยไม่มีวันหาย ทั้ง 10 ตัวที่ตั้งใจไว้ผ่านการตรวจครบ จึงไม่ได้ตัดเหรียญใดออก

## ผลการตรวจ (รัน `python3 tools/sab2_realdata.py --check`)

- **ราคาปิด:** วันซ้ำ 0 · วันหาย 0 · ราคาเป็นศูนย์หรือติดลบ 0 · เวลาเปิดแท่งที่ไม่ใช่ 00:00 UTC 0 · ตัดแท่งวันที่ 2026-11-15 ของทุกเหรียญ เพราะตอนดึงข้อมูลแท่งนั้นยังไม่ปิด (ราคา "ปิด" ยังเปลี่ยนได้)
- **ตรวจข้ามแหล่งกับ Kraken** (ราคาเป็น USD ส่วน Binance เป็น USDT · Kraken ให้ย้อนหลังได้แค่ราว 720 วัน = 2024-11-25 ถึง 2026-11-14): BTC ส่วนต่างราคาปิด Median (มัธยฐาน) 0.043% มากสุด 0.25% · ETH มัธยฐาน 0.043% มากสุด 0.25% — สองแหล่งตรงกันพอสำหรับงานรายวัน
- **Funding:** รอบซ้ำ 0 · รอบที่ห่างไม่เท่า 8 ชั่วโมง 0 · เวลาที่ไม่ใช่ 00/08/16 UTC 0 · ค่าที่ประกาศกับค่าที่ชำระจริงตรงกันทุกรอบ · ตัดสองรอบของวันที่ 2026-11-15 ให้ตรงกับช่วงราคา

## ช่วงแบ่งของเล่ม

| ช่วง | วันที่ | จำนวนวัน | ใช้ทำอะไร |
|---|---|---|---|
| Formation Period (ช่วงเลือก) | 2022-11-15 ถึง 2024-11-14 | 731 | ประมาณ h · ทดสอบ · เลือกพารามิเตอร์ |
| Validation (ช่วงตรวจ) | 2024-11-15 ถึง 2025-11-14 | 365 | ตรวจสิ่งที่เลือก · walk-forward |
| Final Test (ช่วงทดสอบสุดท้าย) | 2025-11-15 ถึง 2026-11-14 | 365 | **ล็อกไว้ เปิดครั้งเดียวในบท 17** |

ช่วงเลือกสองปีพอให้หน้าต่าง 60/120/250 วัน และ PCA ของ 10 เหรียญ · ช่วงตรวจหนึ่งปีพอสำหรับ walk-forward สามหน้าต่าง · ช่วงทดสอบสุดท้ายคือปีล่าสุด

ในโค้ดของบท ใช้ `load_closes("formation")` หรือ `load_funding("validation")` · ถ้าขอ `"final_test"` (หรือทั้งช่วง) ฟังก์ชันจะปฏิเสธ เว้นแต่ส่ง `unlock_final=True` ซึ่งใช้ได้ในบท 17 เท่านั้น

## ข้อจำกัดที่ต้องรู้

1. **Funding ทั้งหมดอยู่ในช่วงทดสอบสุดท้าย** — OKX เก็บประวัติย้อนหลังให้ดึงได้แค่ราว 3 เดือน ช่วงเลือกและช่วงตรวจจึงไม่มีข้อมูล funding เลย (`load_funding` คืนรายการว่าง) บทที่อยากใช้ funding จริงก่อนบท 17 ต้องตัดสินใจเรื่องนี้ก่อน
2. ราคาเป็น USDT ไม่ใช่ USD และเป็นราคาจากตลาดเดียว
3. เล่ม 1 ภาคผนวก K แสดงราคา BTC/ETH ช่วง 2025-01-01 ถึง 2026-11-14 ไปแล้ว ผู้อ่านเล่ม 1 จึงเคยเห็นราคาสองเหรียญนี้ในช่วงทดสอบสุดท้ายมาบ้าง

## สร้างซ้ำ

```
python3 tools/sab2_realdata.py --check   # ตรวจ: sha256 ของไฟล์ดิบ · CSV ตรงกับที่สร้างใหม่ทุกไบต์ · ช่วงแบ่งต่อกันพอดี
python3 tools/sab2_realdata.py           # สร้าง CSV ใหม่จากไฟล์ดิบ
python3 tools/sab2_realdata.py --fetch   # (ผู้ดูแลเท่านั้น) ดึงไฟล์ดิบชุดใหม่ — ตัวเลขทั้งเล่มจะเปลี่ยน
```
