บทที่ 32: กรณีศึกษาจริง

32.1 Renaissance Technologies — Stat Arb ที่สำเร็จที่สุด

Medallion Fund: 66% avg return/year (1988-2018)

ใช้ math + physics + data science หาสัญญาณใน noise
ทำ หลายพัน trades/วัน แต่ละ trade edge เล็กมาก → Law of Large Numbers
บทเรียน: small edge × many trades × low correlation = consistent returns

32.2 LTCM — ถูกต้องแต่ตาย (ดูรายละเอียดในบท 26)

สรุป: Bond convergence arb + 25:1 leverage = bankrupt

Strategy ถูกต้อง (bonds converged ภายหลัง) แต่ leverage สูงเกินไป → margin call → เสีย $4.6 billion
บทเรียน #1: Size < Survival. ถ้ารอดไม่ถึงวัน converge = ไม่มีประโยชน์

32.3 Knight Capital — software bug (ดูรายละเอียดในบท 26)

$440M loss ใน 45 นาที

Bug ใน trading software ส่ง orders ผิดพลาดเป็นล้านรายการ → ล้มละลาย
บทเรียน #2: Automated ต้องมี kill switch + position limit + staging test

32.5 บทเรียน 10 ข้อ

  1. Pure Arb หายากมาก — ส่วนใหญ่เป็น Near-Arb หรือ Bounded-Loss
  2. Transaction costs กิน edge — คิดก่อน execute เสมอ
  3. Leverage kills — ถูกต้อง + leverage สูง = ตายก่อนชนะ (LTCM)
  4. Simple > Complex — Baseline comparison ทุกครั้ง
  5. Size < Survival — อยู่รอดก่อน กำไรทีหลัง
  6. Label your claims — Exact ≠ Heuristic ≠ Observed
  7. Automate with safeguards — kill switch + position limit (Knight Capital)
  8. Regime matters — strategy ที่ดีใน bull อาจแย่ใน bear
  9. Diversify across strategies — ไม่ใช่แค่ across assets
  10. Keep learning — ตลาดเปลี่ยน edge หายไป ต้องหาใหม่ตลอด
