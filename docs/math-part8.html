5.1 Scatter Plot & Correlation — ρ แต่ละค่าหน้าตายังไง

🚶 อ่านเป็นภาษาคนก่อน: scatter plot คือเอาของสองอย่างมาวางบนแกน x กับ y แล้วจิ้มจุดทีละคู่ · ถ้าจุดเรียงเป็นแนวชัด = สองสิ่งนี้ไปด้วยกัน · ค่า correlation (ρ) คือการย่อ "ความเป็นแนว" นั้นให้เหลือตัวเลขเดียวระหว่าง −1 ถึง +1 (เจอครั้งแรกใน เล่ม 1 Part II)

❌ กับดักที่ 1 — ρ = 0 ไม่ได้แปลว่า "ไม่เกี่ยวกัน"

ดูใบขวาสุด · จุดเรียงเป็นรูปตัว U ชัดเจน รู้ x ปุ๊บทำนาย y ได้แทบเป๊ะ · แต่ค่า ρ ที่คำนวณได้คือ 0.000 พอดี

เพราะ correlation วัดเฉพาะความสัมพันธ์แบบเส้นตรงเท่านั้น · ครึ่งซ้ายลง ครึ่งขวาขึ้น หักล้างกันหมดพอดี · ρ = 0 แปลว่า "ไม่มีความสัมพันธ์เชิงเส้น" ไม่ใช่ "ไม่มีความสัมพันธ์" — ต้องดูกราฟถึงจะแยกออก

❌ กับดักที่ 2 — correlation ≠ causation

ρ สูงบอกแค่ว่า "สองสิ่งนี้ขยับไปด้วยกัน" ไม่ได้บอกว่าใครทำให้ใครขยับ · อาจมีปัจจัยที่สามขับทั้งคู่อยู่ (เช่น หุ้นสองตัวขึ้นพร้อมกันเพราะดอกเบี้ยลด ไม่ใช่เพราะเกี่ยวกันเอง) · ในการเทรด ความต่างนี้สำคัญมาก เพราะ hedge ที่อิง correlation ล้วนจะพังทันทีที่ปัจจัยที่สามเปลี่ยนพฤติกรรม

🐍 Python — พิสูจน์ว่ารูปตัว U ให้ ρ = 0
# pip install numpy
import numpy as np

x = np.linspace(-1.7, 1.7, 20)
y_line = x                       # เส้นตรง
y_u    = x**2                    # รูปตัว U — สัมพันธ์ชัดเจน แต่ไม่เป็นเส้นตรง

print(f"เส้นตรง : rho = {np.corrcoef(x, y_line)[0,1]:+.3f}")   # เส้นตรง : rho = +1.000
print(f"รูปตัว U: rho = {np.corrcoef(x, y_u)[0,1]:+.3f}")      # รูปตัว U: rho = +0.000
print("→ rho=0 แต่ y ทำนายได้จาก x เกือบสมบูรณ์")
# → rho=0 แต่ y ทำนายได้จาก x เกือบสมบูรณ์

  • ชุดที่ 4 (มี leverage point): ตัดจุดนั้นออก → x ที่เหลือเท่ากันหมด (= 8 ทุกตัว) · คำนวณความชันไม่ได้เลย — แปลว่าความชัน 0.500 ที่เห็น มาจากจุดเดียวล้วน ๆ
🐍 Python — ทดสอบว่าจุดเดียวมีอำนาจแค่ไหน
# pip install numpy
import numpy as np

x  = np.array([10,8,13,9,11,14,6,4,12,7,5], float)
y3 = np.array([7.46,6.77,12.74,7.11,7.81,8.84,6.08,5.39,8.15,6.42,5.73])

b_all, a_all = np.polyfit(x, y3, 1)
print(f"ใช้ข้อมูลครบ    : beta = {b_all:.3f}")     # ใช้ข้อมูลครบ    : beta = 0.500

keep = y3 < 12                                  # ตัดจุด outlier (y=12.74) ออก
b_cut, a_cut = np.polyfit(x[keep], y3[keep], 1)
print(f"ตัด outlier ออก : beta = {b_cut:.3f}")     # ตัด outlier ออก : beta = 0.345
print(f"เปลี่ยนไป {abs(b_cut-b_all)/b_all*100:.0f}% เพราะจุดเดียว")
# เปลี่ยนไป 31% เพราะจุดเดียว
✅ แล้วต้องทำยังไง

เจอจุดที่มีอำนาจสูง อย่าเพิ่งลบทิ้ง — ให้ถามก่อนว่ามันคืออะไร:

  • ข้อมูลผิด (พิมพ์ผิด, ราคาที่ยังไม่ปรับ split) → แก้หรือลบได้
  • เหตุการณ์จริง (วัน crash, วันประกาศงบ) → ห้ามลบ เพราะนั่นคือความเสี่ยงจริงที่คุณต้องรู้ · ให้รายงานผลทั้งแบบมีและไม่มีจุดนั้นแทน

5.3 Residual Plot — กราฟที่สำคัญที่สุดที่คนไม่ค่อยดู

อ่าน Residual Plot OLS diagnostics ★★★ ต้องรู้จัก

🎯 Thesis

"เส้น regression บอกสิ่งที่โมเดลจับได้ · residual บอกสิ่งที่โมเดลจับไม่ได้ — และความจริงที่เจ็บปวดมักซ่อนอยู่ในกองที่จับไม่ได้"

🚶 อ่านเป็นภาษาคนก่อน: residual = ค่าจริง − ค่าที่โมเดลทำนาย · เอามันมาพล็อตกับแกนนอน แล้วดูว่า "เหลือรูปแบบอะไรทิ้งไว้ไหม" · ถ้าโมเดลดี residual ควรกระจายสุ่มไร้รูปแบบรอบเส้นศูนย์ — เพราะทุกอย่างที่มีรูปแบบ โมเดลควรจับไปหมดแล้ว · ถ้ายังเห็นรูปแบบ = โมเดลยังพลาดอะไรอยู่

residual = y จริง − y ที่โมเดลทำนาย เป้าหมาย: กระจายสุ่มรอบ 0 · ไม่มีรูปทรง · ความกว้างสม่ำเสมอ
เห็นรูปแบบนี้แปลว่าทำยังไงต่อ
✅ สุ่มไร้รูปแบบโมเดลจับสิ่งที่จับได้หมดแล้วใช้ผลได้ตามปกติ
❌ โค้ง (U หรือ ∩)ความสัมพันธ์จริงไม่เป็นเส้นตรงเติมพจน์ x² · หรือใช้ log · หรือเปลี่ยนโมเดล
❌ กรวย (บานออก)heteroskedasticity — ความผันผวนของ error ไม่คงที่β ยังใช้ได้ แต่ SE/p-value ผิด → ใช้ robust SE (บทที่ 6)
❌ คลื่นautocorrelation — error วันนี้เกี่ยวกับเมื่อวานใช้ Newey-West SE · หรือใส่ตัวแปร lag (เล่ม 2·D บทที่ 8)
💎 กรวยใบนั้น คุณเคยเจอมาแล้วในเล่ม 1

รูป "กรวยบานออก" คือภาพของ ความผันผวนที่ไม่คงที่ — และนั่นคือ volatility clustering ที่เล่ม 1 Part IV §8.2 สอนไว้เป๊ะ ๆ

ชื่อทางการของอาการนี้คือ heteroskedasticity · และถ้าเอาไปเทียบกับชื่อเต็มของโมเดลที่เราใช้พยากรณ์ σ จะเห็นว่า ARCH = AutoRegressive Conditional Heteroskedasticity — ตัว H ตัวนั้นคือคำนี้ · เล่ม 1 สอน GARCH ไปแล้วโดยไม่เคยบอกว่าชื่อมันแปลว่าอะไร ตอนนี้คุณรู้แล้ว: GARCH เกิดมาเพื่อจัดการกับ "กราฟกรวย" ใบนี้โดยเฉพาะ

🐍 Python — วาด residual plot ของข้อมูลตัวเอง
# pip install matplotlib numpy
import numpy as np
import matplotlib
matplotlib.use("Agg")            # บันทึกเป็นไฟล์ (ไม่ต้องมีหน้าจอ)
import matplotlib.pyplot as plt

rng = np.random.default_rng(11)
x = np.linspace(0, 1, 120)
y = 2 + 3*x + rng.normal(0, 0.15 + 0.9*x)    # จงใจให้ error บานตาม x

beta, alpha = np.polyfit(x, y, 1)
resid = y - (alpha + beta*x)                  # ★ หัวใจ: ค่าจริง − ค่าทำนาย

plt.figure(figsize=(6,3))
plt.axhline(0, color="gray", ls="--", lw=1)
plt.scatter(x, resid, s=14, color="#d97706")
plt.xlabel("x"); plt.ylabel("residual")
plt.tight_layout(); plt.savefig("residual.png", dpi=120)

# วัดเป็นตัวเลขด้วย: เทียบความกว้างของ residual ครึ่งแรก vs ครึ่งหลัง
half = len(x)//2
sd_left, sd_right = resid[:half].std(), resid[half:].std()
print(f"SD ครึ่งซ้าย = {sd_left:.3f}")        # SD ครึ่งซ้าย = 0.358
print(f"SD ครึ่งขวา = {sd_right:.3f}")        # SD ครึ่งขวา = 0.880
print(f"อัตราส่วน = {sd_right/sd_left:.1f} เท่า → กรวยชัดเจน")
# อัตราส่วน = 2.5 เท่า → กรวยชัดเจน
✅ อ่านผลลัพธ์

ไม่ต้องเดาจากตาอย่างเดียว — วัดได้ · residual ครึ่งขวากว้างกว่าครึ่งซ้าย 2.5 เท่า = กรวยของจริง · กฎนิ้วโป้ง: อัตราส่วนเกิน ~2 เท่าเมื่อไร ให้ถือว่ามี heteroskedasticity แล้วเปลี่ยนไปใช้ robust SE

🎯 3 อย่างที่ต้องจำเรื่อง residual
  • residual ที่ดีต้องน่าเบื่อ — สุ่ม ไร้รูปแบบ ความกว้างสม่ำเสมอ
  • เห็นรูปทรง = โมเดลส่งสัญญาณว่ายังพลาดอะไรอยู่ (โค้ง/กรวย/คลื่น = คนละปัญหา คนละวิธีแก้)

5.4 Correlation Heatmap — เห็นทั้งพอร์ตในภาพเดียว

อ่าน Correlation Heatmap Portfolio ★★★ ต้องรู้จัก

🚶 อ่านเป็นภาษาคนก่อน: พอร์ต 5 ตัวมีคู่ความสัมพันธ์ 10 คู่ · พอร์ต 20 ตัวมี 190 คู่ — อ่านเป็นตารางตัวเลขไม่ไหว · heatmap คือเอาตารางนั้นมาระบายสีแทนตัวเลข แล้วดูด้วยตาทีเดียวจบ · นี่คือหน้าตาของ covariance matrix (Σ) จาก เล่ม 2 · A ที่มองเห็นได้จริง

✅ อ่าน heatmap ใบนี้เป็นภาษาคน
  • แนวทแยงเป็น 1.00 เสมอ (ทุกอย่างสัมพันธ์กับตัวเองเต็มร้อย) — และตารางสมมาตรรอบแนวทแยง จึงอ่านแค่ครึ่งเดียวก็พอ
  • กรอบม่วง: TECH-A กับ TECH-B มี ρ = 0.86 — สูงมาก · ถือทั้งคู่แทบไม่ต่างจากถือตัวเดียวเป็นสองเท่า
  • BOND เป็นน้ำเงินทั้งแถว (−0.30, −0.26, −0.44) = สวนทางกับหุ้นทุกตัว · นี่คือของมีค่าที่สุดในพอร์ต เพราะช่วยพยุงตอนหุ้นร่วง
  • GOLD เกือบขาวหมด (−0.05, −0.02, 0.10) = แทบไม่เกี่ยวกับใครเลย — ก็มีประโยชน์ในแบบของมัน (ลดความเสี่ยงโดยไม่ผูกกับใคร)
❌ กับดักการทำ heatmap ที่เจอบ่อยที่สุด
  • ใช้ colormap สายรุ้ง (rainbow/jet) — ตาคนอ่านลำดับของสีรุ้งไม่ออก และมันสร้าง "ขอบปลอม" ที่ข้อมูลไม่มีจริง · correlation มีจุดกลางที่มีความหมาย (0) จึงต้องใช้ diverging colormap ที่ 0 = สีขาว/กลาง แล้วไล่ไปคนละทางสองข้าง (เช่น coolwarm, RdBu)
  • ไม่ล็อกสเกลสีที่ −1 ถึง +1 — ถ้าปล่อยให้ auto-scale ตามข้อมูล พอร์ตที่ correlation อยู่ 0.7–0.9 ทั้งหมดจะดูมีทั้งแดงทั้งน้ำเงิน ทั้งที่จริงสัมพันธ์กันสูงหมดทุกคู่ · ต้องกำหนด vmin=-1, vmax=1 เสมอ
  • ลืมว่า correlation เปลี่ยนตามเวลา — เลขในตารางคือค่าเฉลี่ยของช่วงที่เลือก · ตอนตลาด crash correlation ของหุ้นมักพุ่งเข้าหา 1 พร้อมกันหมด (ดู §5.5)
🐍 Python — วาด correlation heatmap ให้ถูกหลัก
# pip install matplotlib numpy
import numpy as np
import matplotlib; matplotlib.use("Agg")
import matplotlib.pyplot as plt

names = ["TECH-A","TECH-B","BANK","GOLD","BOND"]
C = np.array([[ 1.00, 0.86, 0.42,-0.05,-0.30],
              [ 0.86, 1.00, 0.38,-0.02,-0.26],
              [ 0.42, 0.38, 1.00, 0.10,-0.44],
              [-0.05,-0.02, 0.10, 1.00, 0.18],
              [-0.30,-0.26,-0.44, 0.18, 1.00]])

fig, ax = plt.subplots(figsize=(5,4))
im = ax.imshow(C, cmap="coolwarm", vmin=-1, vmax=1)   # ★ diverging + ล็อกสเกล
ax.set_xticks(range(5), names, rotation=45)
ax.set_yticks(range(5), names)
for i in range(5):
    for j in range(5):                                 # เขียนตัวเลขทับลงไปด้วย
        ax.text(j, i, f"{C[i,j]:.2f}", ha="center", va="center", fontsize=8)
fig.colorbar(im); fig.tight_layout(); fig.savefig("heatmap.png", dpi=120)

# อ่านเป็นตัวเลข: คู่ไหนสัมพันธ์สูงสุด (ไม่นับแนวทแยง)
iu = np.triu_indices(5, k=1)                           # เอาสามเหลี่ยมบน
pairs = sorted(zip(C[iu], [(names[i],names[j]) for i,j in zip(*iu)]), reverse=True)
for v,(a,b) in pairs[:3]:
    print(f"{a:7s} & {b:7s}: {v:+.2f}")
# TECH-A  & TECH-B : +0.86
# TECH-A  & BANK   : +0.42
# TECH-B  & BANK   : +0.38
print(f"\ncorrelation เฉลี่ยทั้งพอร์ต = {C[iu].mean():+.3f}")
# correlation เฉลี่ยทั้งพอร์ต = +0.087
🎯 3 อย่างที่ต้องจำเรื่อง heatmap
  • diverging colormap + ล็อก vmin/vmax ที่ −1..+1 เสมอ (ไม่งั้นสีหลอก)
  • มองหา "กลุ่มสีแดงติดกัน" = ของที่ซ้ำกันในพอร์ต ไม่ใช่การกระจายเสี่ยงจริง
  • ช่องสีน้ำเงิน คือของหายาก — สินทรัพย์ที่สวนทางคือตัวที่ทำให้ wᵀΣw หดลงจริง (เล่ม 2 · A)

5.5 🎓 เอาไปใช้จริง — จากกราฟสู่การตัดสินใจ

อ่านกราฟเป็นแล้วต้องจบที่ "แล้วยังไงต่อ" · สามสถานการณ์ที่ใช้ได้ทันที:

🧮 สถานการณ์ที่ 1 — "พอร์ตผมกระจายความเสี่ยงจริงหรือหลอก"

ทำ: วาด heatmap ของพอร์ตตัวเอง แล้วดู correlation เฉลี่ย (ไม่นับแนวทแยง)

  • เฉลี่ย > 0.7 → ถือ 10 ตัวลดความผันผวนได้แค่ ~15% · และต่อให้ถือ 100 ตัวก็ลดได้แค่ ~16% — มีเพดานอยู่ที่ √ρ ซึ่งเพิ่มจำนวนหุ้นไม่มีวันทะลุ · เพิ่มจำนวนไม่ช่วยแล้ว ต้องหาของคนละประเภท
  • เฉลี่ย 0.3–0.7 → ปกติสำหรับหุ้นตลาดเดียวกัน
  • เฉลี่ย < 0.3 → กระจายได้ดี (พอร์ตตัวอย่างข้างบน = +0.087 ถือว่าดีมาก เพราะมีทั้งทองและพันธบัตร)

ต่อยอด: เอา Σ ก้อนนี้ไปเข้า Markowitz ใน เล่ม 2 · B เพื่อหาน้ำหนักที่ดีที่สุดได้เลย

❌ แต่ "ρ เฉลี่ย" มีจุดบอดใหญ่ — มันไม่รู้จักน้ำหนักของคุณเลย

ρ เฉลี่ยคำนวณจากคู่ของสินทรัพย์ล้วน ๆ · มันเหมือนกันเป๊ะไม่ว่าคุณจะถือแต่ละตัวเท่ากัน หรือทุ่ม 80% ไปที่หุ้นเทคสองตัวที่ ρ = 0.85 ต่อกัน

ใช้ Σ ก้อนเดียวกันข้างบน เปลี่ยนแค่น้ำหนัก:

น้ำหนักρ เฉลี่ยความผันผวนพอร์ตจริง
เท่ากันทุกตัว (20% × 5)0.11514.1%
เทไปทางเทค (40/40/10/5/5)0.115 ← เท่าเดิมเป๊ะ23.5% ← สูงขึ้น 66%

ตัวเลขที่คุณใช้ตัดสินว่า "กระจายดีไหม" มองไม่เห็นสิ่งที่กำหนดคำตอบเลย

💡 ตัววัดที่ถูกต้องกว่า — Diversification Ratio:

DR = (Σ wᵢσᵢ) / σ_พอร์ต = "ถ้าไม่มีการหักล้างกันเลย จะเป็นเท่าไร" ÷ "ของจริงเป็นเท่าไร" DR = 1.00 → ไม่ได้กระจายเลย (เหมือนถือตัวเดียว) DR สูง → ยิ่งหักล้างกันได้มาก

พอร์ตน้ำหนักเท่ากันได้ DR = 1.47 · พอร์ตที่เทไปทางเทคได้ DR = 1.13 — ตัวเลขนี้จับความต่างได้ทันที ในขณะที่ ρ เฉลี่ยจับไม่ได้เลย

คำนวณได้ในบรรทัดเดียว: dr = (w @ sd) / np.sqrt(w @ S @ w) — และสังเกตว่าตัวส่วนคือ √(wᵀΣw) ตัวเดียวกับใน เล่ม 2 · A เป๊ะ

🧮 สถานการณ์ที่ 2 — "Beta ที่ได้มา เอาไป hedge ได้ไหม"

ทำ: ก่อนใช้ β จาก เล่ม 2 · A ให้ดู 2 กราฟเสมอ

  • scatter → มีจุดไหนโดดเดี่ยวคุมเส้นอยู่ไหม (ลองตัดออกแล้วคำนวณใหม่ — ถ้า β เปลี่ยนเกิน ~20% อย่าเชื่อ · เกณฑ์ 20% นี้เป็นกฎนิ้วโป้งที่ผมตั้งเอง ไม่ใช่ค่ามาตรฐานทางสถิติ)
  • residual plot → เป็นกรวยไหม · ถ้าใช่ β ยังพอใช้ได้ แต่ "ช่วงความมั่นใจ" ที่โปรแกรมรายงานจะมักแคบเกินจริง → ต้องใช้ robust SE (บทที่ 6)
  • กราฟที่สาม ซึ่งสำคัญที่สุดและคนมองข้ามบ่อยที่สุด: β แบบ rolling → ดูข้อถัดไป
❌ ช่องโหว่ที่ใหญ่ที่สุดของทั้งเล่ม — β ไม่ใช่ค่าคงที่

ทุกอย่างในบทที่ 6 สอนให้ไม่เชื่อ β ด้วยเหตุผลเรื่องการสุ่มตัวอย่าง (SE · ช่วงความเชื่อมั่น · outlier · robust SE) · แต่เหตุผลที่ทำให้ hedge พังจริง ๆ ในโลกจริงไม่ใช่เรื่องนั้นเลย

มันคือ β เปลี่ยนไปตามเวลา · β ที่ประมาณจากข้อมูล 250 วันที่ผ่านมา ไม่ใช่ β ของพรุ่งนี้ — โครงสร้างธุรกิจเปลี่ยน · หนี้เปลี่ยน · ระบอบตลาดเปลี่ยน

หนังสือเล่มนี้มีหลักฐานอยู่ในตัวเองแต่ไม่ได้ชี้ให้ดู: §6.4 วาง β = 1.5391 (6 เดือน) กับ β = 1.2226 (1 ปี) ไว้ข้าง ๆ กัน แล้วอธิบายความต่างว่าเป็นเรื่องขนาดตัวอย่าง · คนที่เทรดจริงเห็นสองระบอบ

3 อย่างที่ต้องทำเพิ่ม:

  1. พล็อต β แบบ rolling 60 หรือ 120 วัน ก่อนใช้เสมอ · ถ้ามันเดินขึ้นลงเป็นเทรนด์ ไม่ใช่แกว่งรอบค่าคงที่ — ช่วงความเชื่อมั่นที่คำนวณจากข้อมูลทั้งก้อนไม่มีความหมายเลย เพราะมันตั้งอยู่บนสมมติฐานว่ามี β เดียวที่จริงอยู่
  2. ใช้ shrinkage เข้าหา 1 — วิธีที่วงการใช้จริงและไม่มีอยู่ในเล่มนี้เลย:
    β_ปรับแล้ว = 0.67 × β̂ + 0.33 × 1.0 (Blume / "adjusted beta" — ตัวที่ Bloomberg รายงาน)
    เหตุผล: β มีแนวโน้มถดถอยเข้าหา 1 ตามเวลาอย่างเป็นระบบ · สำหรับตัวอย่าง §6.4: 1.5391 → 1.36
  3. เลือกปลายของช่วงที่ผิดแล้วเจ็บน้อยกว่า — เมื่อ §6.4 บอกว่าช่วงคือ [1.118, 1.960] คำถามที่ต้องตอบคือ "แล้วใช้เลขไหน" · hedge เกินไปเสียโอกาสขาขึ้น · hedge ขาดไปเสียเงินต้น · ถ้าคุณรับความเสี่ยงขาลงไม่ได้ ให้เลือกปลายบน ไม่ใช่ค่ากลาง
🧮 สถานการณ์ที่ 3 — "correlation ที่เห็น จะอยู่ถึงพรุ่งนี้ไหม"

ทำ: อย่าดู correlation ค่าเดียวจากข้อมูลทั้งก้อน · ให้พล็อต rolling correlation (คำนวณจากหน้าต่างเลื่อน เช่น 60 วัน) แล้วดูว่ามันนิ่งหรือเหวี่ยง

สิ่งที่มักเห็น: correlation ระหว่างหุ้นที่ปกติอยู่ราว 0.3–0.5 พุ่งเข้าหา 0.9 ตอนตลาด crash · แปลว่าการกระจายเสี่ยงหายไปพอดีตอนที่คุณต้องการมันที่สุด — นี่คือเหตุผลที่กล่องเตือน "estimation error" ใน เล่ม 2 · B มีอยู่

🧠 มุมที่มองต่าง — กราฟไม่ใช่ของประดับรายงาน

มือใหม่เห็น: "วาดกราฟไว้ใส่สไลด์ให้ดูเป็นมืออาชีพ"
คนทำงานกับข้อมูลเห็น: กราฟคือเครื่องมือตรวจสอบที่ใช้ก่อนเชื่อตัวเลขใด ๆ · ลำดับที่ถูกคือ วาดกราฟ → เห็นปัญหา → เลือกโมเดล/แก้ข้อมูล → ค่อยคำนวณ · ไม่ใช่คำนวณเสร็จแล้วค่อยวาดกราฟไปแปะรายงาน

✍️ ลองทำเอง — ทดสอบตัวเอง

กลับไปดูภาพเปิดบท (Anscombe 4 ใบ) อีกครั้งโดยไม่ดูเฉลย · ถ้าคุณมีข้อมูลจริงแล้ววาด residual plot ออกมาได้หน้าตาเหมือนชุดที่ 2 คุณควรทำอะไรต่อ?

ดูเฉลย

ชุดที่ 2 = ความสัมพันธ์จริงเป็นเส้นโค้ง · residual จะออกมาเป็นรูป โค้ง (ใบขวาบนใน §5.3) · วิธีแก้ไม่ใช่ลบข้อมูล แต่คือ เปลี่ยนโมเดล — เติมพจน์ x² เข้าไป หรือแปลงตัวแปรด้วย log แล้ว fit ใหม่ · ถ้ายังใช้เส้นตรงต่อไป จะพยากรณ์ผิดเป็นระบบทั้งสองปลายของช่วงข้อมูล

สรุปบทที่ 5 — ตอนนี้คุณ
  • รู้ว่าสถิติชุดเดียวกันมาจากข้อมูลคนละเรื่องได้ (Anscombe) จึงดูกราฟก่อนเสมอ
  • อ่าน scatter ออก และรู้ว่า ρ=0 ไม่ได้แปลว่าไม่เกี่ยวกัน
  • จับ outlier กับ leverage point ได้ และรู้วิธีวัดอำนาจของมัน (ตัดออกแล้วคำนวณใหม่)
  • อ่าน residual plot 4 หน้าตา และรู้ว่าแต่ละแบบต้องแก้ยังไง
  • อ่าน heatmap ของพอร์ต และบอกได้ว่ากระจายเสี่ยงจริงหรือหลอก
กราฟบอกคุณว่า "ตัวเลขนี้เชื่อได้ไหม" — บทต่อไปบอกว่า "เชื่อได้แค่ไหน" เป็นตัวเลข
📖 อ่านต่อ — บทที่ 6: OLS ที่เชื่อถือได้

residual plot บอกเราว่า "กรวยแปลว่า p-value หลอก" — แต่ p-value คืออะไร และดูตรงไหน? · บทที่ 6 จะกาง standard error · t-stat · p-value · confidence interval และสอนอ่านตาราง summary() ของ statsmodels ทีละช่อง พร้อมวิธีแก้เมื่อเจอ heteroskedasticity ด้วย robust SE

📖 ศัพท์ใหม่ในตอนนี้

Anscombe's Quartet = ชุดข้อมูล 4 ชุดที่สถิติเหมือนกันแต่กราฟต่างกัน · Scatter plot = กราฟจุดสองแกน · Outlier = จุดที่ y หลุดจากแนว · Leverage point = จุดที่ x ไกลจากกลุ่มจนคุมเส้นได้ · Residual = ค่าจริง − ค่าที่โมเดลทำนาย · Heteroskedasticity = ความผันผวนของ error ไม่คงที่ (residual เป็นกรวย) · Homoskedastic = ตรงข้าม (ความกว้างสม่ำเสมอ) · Autocorrelation = error เกี่ยวพันข้ามเวลา (residual เป็นคลื่น) · Diverging colormap = ชุดสีที่มีจุดกลางมีความหมาย · Rolling correlation = correlation จากหน้าต่างเลื่อน

บทที่ 6: OLS ที่เชื่อถือได้ — จาก "β เท่าไร" สู่ "เชื่อ β ได้แค่ไหน"

เล่ม 2 · A สอนหา β ด้วย regression แล้วเอาไปใช้เป็น hedge ratio · แต่ตัวเลขตัวเดียวไม่เคยบอกความจริงทั้งหมด — β = 1.54 ที่คำนวณจากข้อมูล 6 เดือน กับ β = 1.54 ที่คำนวณจากข้อมูล 6 ปี ไม่ได้น่าเชื่อถือเท่ากัน ทั้งที่เลขหน้าจอเหมือนกันเป๊ะ

บทนี้คือเครื่องมือวัดว่า "เชื่อได้แค่ไหน" — และวิธีอ่านตารางที่คนทำงานจริงเปิดดูทุกวัน

6.2 Standard Error · t-stat · p-value — "บังเอิญหรือของจริง"

🔧 กรอบคิดที่ต้องมีก่อนอ่าน p-value — ทุกอย่างในหัวข้อนี้ตั้งอยู่บนมัน

ก่อนดูตัวเลขใด ๆ ต้องรู้ว่าสถิติกำลังตอบคำถามอะไร · มันไม่ได้ถามว่า "β เท่าไร" — มันตั้งศาลแล้วพิจารณาคดี:

เรียกว่าในกรณี β ของเรา
สมมติฐานว่างH₀"β = 0 จริง ๆ — ตลาดไม่มีผลต่อหุ้นตัวนี้เลย · ที่เห็นเป็นความบังเอิญล้วน"
สมมติฐานทางเลือกH₁"β ≠ 0 — มีความสัมพันธ์จริง"

กติกาคือ H₀ เป็นจำเลยที่ถือว่าบริสุทธิ์ไว้ก่อน · เราจะไม่ปฏิเสธมันจนกว่าหลักฐานจะแรงพอ

p-value คือคำตอบของคำถามเดียวนี้: "ถ้า H₀ เป็นจริง (β = 0 จริง ๆ) โอกาสที่จะบังเอิญได้ข้อมูลที่ดูแรงเท่าที่เราเห็นนี้ มีแค่ไหน"

  • p เล็ก (< 0.05) → "บังเอิญยากมาก" → ปฏิเสธ H₀ → เชื่อว่ามีความสัมพันธ์จริง
  • p ใหญ่ → "บังเอิญได้ง่าย" → ยังปฏิเสธ H₀ ไม่ได้

⚠️ สองข้อที่คนเข้าใจผิดตลอด: (1) p ไม่ใช่ "โอกาสที่ H₀ จะเป็นจริง" — มันคือโอกาสของข้อมูลโดยสมมติว่า H₀ จริง คนละเรื่องกัน · (2) "ปฏิเสธ H₀ ไม่ได้" ไม่เท่ากับ "H₀ ถูก" — มันแปลว่าหลักฐานไม่พอ เท่านั้น (ศาลยกฟ้อง ≠ พิสูจน์ว่าบริสุทธิ์)

📌 §7.4 จะกลับมาที่กรอบนี้อีกครั้งเพื่อตอบว่า "แล้วค่าวิกฤตที่ใช้ตัดสินมาจากไหน" — และทำไมมันถึงเป็น t ไม่ใช่ z

อ่านความมั่นใจใน β Inference ★★★ ต้องรู้จัก

🎯 Thesis

"β คือค่าที่ดีที่สุดที่ประมาณได้จากข้อมูลชุดนี้ — ถ้าเก็บข้อมูลชุดใหม่ จะได้ β อีกค่าหนึ่ง · standard error คือการวัดว่ามันจะเหวี่ยงแค่ไหน"

🚶 อ่านเป็นภาษาคนก่อน: จินตนาการว่าคุณเก็บข้อมูล 6 เดือนแล้วได้ β = 1.54 · ถ้าย้อนเวลาไปเก็บอีก 6 เดือนที่ต่างออกไป จะได้ 1.61 · อีกรอบได้ 1.42 — β เหวี่ยงไปมาเพราะข้อมูลเป็นตัวอย่างจากความจริง ไม่ใช่ความจริงเอง

  • Standard Error (SE) = "β เหวี่ยงประมาณเท่าไร" · SE เล็ก = ประมาณได้แม่น
  • t-stat = β ÷ SE = "β ใหญ่กว่าความเหวี่ยงของตัวเองกี่เท่า" · ยิ่งเยอะยิ่งมั่นใจว่าไม่ใช่ศูนย์
  • p-value = "ถ้าความจริงคือ β = 0 (ไม่เกี่ยวกันเลย) โอกาสที่จะบังเอิญเห็นเลขแรงขนาดนี้มีเท่าไร" · น้อย = ไม่น่าใช่เรื่องบังเอิญ
t = β̂ / SE(β̂) กฎนิ้วโป้ง: |t| > 2 ≈ p < 0.05 ≈ "มีนัยสำคัญ"
❌ p-value ไม่ได้แปลว่าสิ่งที่คนส่วนใหญ่คิด
  • p ไม่ใช่ "โอกาสที่ผลลัพธ์จะถูก" และไม่ใช่ "โอกาสที่ β = 0"
  • p เล็ก ≠ สำคัญมาก — ข้อมูลเยอะพอ อะไรก็ "มีนัยสำคัญ" ได้ทั้งนั้น แม้ผลจริงจะเล็กจนไร้ประโยชน์ทางการเงิน · ให้ดูขนาดของ β ควบคู่เสมอ
  • p > 0.05 ≠ ไม่มีความสัมพันธ์ — อาจแปลแค่ว่าข้อมูลน้อยเกินจะสรุปได้
🧮 เดินเลขจริง — จากตัวอย่าง 250 วัน

Regression ผลตอบแทนหุ้น กับ ผลตอบแทนตลาด 250 วันทำการ (≈ 1 ปี) ได้:

β̂ = 1.2226 SE = 0.04807 (ผลลัพธ์ปัดแสดงเป็น 0.0481) t = 1.2226 / 0.04807 = 25.43 → ใหญ่กว่าความเหวี่ยงของตัวเอง 25 เท่า p ≈ 0.0000 → แทบเป็นไปไม่ได้ที่จะบังเอิญ

อ่านเป็นภาษาคน: "หุ้นตัวนี้เหวี่ยงกว่าตลาด ~1.22 เท่า และเรามั่นใจมากว่าตัวเลขนี้ไม่ใช่เรื่องบังเอิญ"

✅ แถว const บอกอะไร

แถว const คือ α (alpha) — ผลตอบแทนส่วนที่ไม่ได้มาจากตลาด · ที่นี่ได้ 0.0003 แต่ p = 0.503 (สูงมาก) แปลว่า แยกจากศูนย์ไม่ได้ · อ่านเป็นภาษาคน: "หุ้นตัวนี้ไม่ได้เก่งหรือแย่กว่าตลาดอย่างมีนัยสำคัญ มันแค่เหวี่ยงกว่า" — ซึ่งเป็นผลลัพธ์ปกติที่สุดในโลกจริง (การหา α ที่มีนัยสำคัญคืองานยากที่สุดของวงการ)

🐍 Python — รัน OLS แล้วดึงเฉพาะช่องที่ต้องดู
# pip install statsmodels numpy
import numpy as np, statsmodels.api as sm

rng = np.random.default_rng(2024)
n   = 250
mkt = rng.normal(0.0004, 0.011, n)                      # ผลตอบแทนตลาด
stk = 0.0002 + 1.20*mkt + rng.normal(0, 0.008, n)       # หุ้น (beta จริง = 1.20)

X = sm.add_constant(mkt)          # ★ ต้องเติมคอลัมน์ 1 เพื่อให้มี alpha
m = sm.OLS(stk, X).fit()
# print(m.summary())   ← ตารางเต็มข้างบน

lo, hi = m.conf_int()[1]
print(f"beta   = {m.params[1]:.4f}")        # beta   = 1.2226
print(f"SE     = {m.bse[1]:.4f}")           # SE     = 0.0481
print(f"t-stat = {m.tvalues[1]:.2f}")       # t-stat = 25.43
print(f"p      = {m.pvalues[1]:.2e}")       # p      = 4.66e-71
print(f"95% CI = [{lo:.4f}, {hi:.4f}]")     # 95% CI = [1.1279, 1.3173]
print(f"R2     = {m.rsquared:.4f}")         # R2     = 0.7229

6.4 ช่วงความเชื่อมั่น — ทำไม hedge ratio ต้องเป็น "ช่วง"

🚶 อ่านเป็นภาษาคนก่อน: ถ้าให้เลือกอ่านค่าเดียวจากตาราง อย่าเลือก p-value — เลือกช่วงความเชื่อมั่น เพราะมันตอบคำถามที่คุณอยากรู้จริง ๆ ว่า "β ที่แท้จริงน่าจะอยู่ระหว่างเท่าไรถึงเท่าไร"

💎 กลับไปดู β = 1.54 จาก เล่ม 2 · A อีกครั้ง

ใน เล่ม 2 · A §2.1 เราคำนวณ β จากผลตอบแทน 6 เดือน ได้ 1.5391 และเอาไปใช้เป็น hedge ratio ทันที · คราวนี้ลองคำนวณช่วงความเชื่อมั่นของมันดู:

📌 ค่า SE มาจากไหน: เล่ม 2 · A รายงานแค่ β̂ · SE = 0.1516 คือค่าที่ statsmodels คำนวณให้จากข้อมูลชุดเดียวกัน (ช่อง std err ใน summary() ตามที่เห็นใน §6.3) · และ "6 เดือน = 6 จุดข้อมูล" เพราะเป็นผลตอบแทนรายเดือน ส่วน "250 วัน" เป็นรายวัน — สองกรณีนี้ใช้ความถี่ต่างกัน

n = 6 เดือน: β̂ = 1.5391 SE = 0.1516 p = 0.0005 95% CI = [ 1.118 , 1.960 ] ← กว้าง 0.84 n = 250 วัน: β̂ = 1.2226 SE = 0.0481 p ≈ 0 95% CI = [ 1.128 , 1.317 ] ← กว้าง 0.19

ทั้งสองกรณี p-value เล็กทั้งคู่ ("มีนัยสำคัญ" เหมือนกัน) แต่ความหมายต่างกันลิบ:

  • ถ้าถือหุ้น ฿1,000,000 แล้ว hedge ตาม β = 1.54 → short ดัชนี ฿1,540,000
  • แต่ความจริงอาจเป็น β = 1.12 (ควร short ฿1,120,000) หรือ β = 1.96 (ควร short ฿1,960,000)
  • ช่วงห่างกันถึง ฿840,000 — นั่นคือความไม่แน่นอนที่ตัวเลข "1.54" ตัวเดียวซ่อนไว้จากคุณ

บทเรียน: ข้อมูล 6 จุดให้ β ที่ "มีนัยสำคัญ" ได้ แต่ยังไม่แม่นพอจะเอาไปกำหนดขนาด hedge จริง · ยิ่งข้อมูลมาก ช่วงยิ่งแคบ (SE หดตาม 1/√n — เพื่อนเก่าจาก Monte Carlo ในเล่ม 1)

6.5 Heteroskedasticity → Robust Standard Error

🚶 อ่านเป็นภาษาคนก่อน: จำ "กราฟกรวย" จาก §5.3 ได้ไหม · เมื่อเจอมัน β ยังใช้ได้ แต่ SE ที่โปรแกรมรายงานจะเล็กเกินจริง = คุณจะมั่นใจเกินเหตุ · ทางแก้ง่ายมาก: เปลี่ยนวิธีคำนวณ SE เป็นแบบ robust โดยเติมพารามิเตอร์เดียว

🐍 Python — SE ปกติ vs robust บนข้อมูลที่เป็นกรวย
# pip install numpy statsmodels
import numpy as np, statsmodels.api as sm

rng = np.random.default_rng(7)
n = 300
x = rng.normal(0, 1, n)
y = 1 + 2*x + rng.normal(0, 0.3 + 1.6*np.abs(x))   # error บานตาม |x| = กรวย
X = sm.add_constant(x)

ols = sm.OLS(y, X).fit()                      # แบบปกติ
rob = sm.OLS(y, X).fit(cov_type="HC3")        # ★ robust — เติมแค่นี้

print(f"beta (เท่ากันทั้งคู่) = {ols.params[1]:.4f}")   # beta (เท่ากันทั้งคู่) = 1.9690
print(f"SE ปกติ    = {ols.bse[1]:.4f}   t = {ols.tvalues[1]:.2f}")
# SE ปกติ    = 0.1022   t = 19.26
print(f"SE robust  = {rob.bse[1]:.4f}   t = {rob.tvalues[1]:.2f}")
# SE robust  = 0.1555   t = 12.66
print(f"robust ใหญ่กว่า {(rob.bse[1]/ols.bse[1]-1)*100:.0f}%")
# robust ใหญ่กว่า 52%
✅ อ่านผลลัพธ์ — ความมั่นใจปลอมหายไป 52%
  • β ไม่เปลี่ยนเลย (1.9690 ทั้งคู่) — ยืนยันว่า heteroskedasticity ไม่ได้ทำให้ β ผิด
  • SE โตขึ้น 52% → t ร่วงจาก 19.26 เหลือ 12.66 · ช่วงความเชื่อมั่นกว้างขึ้นจาก 0.402 เป็น 0.610
  • ถ้าใช้ SE ปกติ คุณจะมั่นใจเกินจริงไปครึ่งหนึ่ง — ในการเงินที่ข้อมูลเป็นกรวยแทบตลอด (volatility clustering!) นี่เป็นเรื่องปกติที่ต้องระวังทุกครั้ง
💡 เลือกชนิด robust ให้ถูกงาน
  • cov_type="HC3" — แก้ heteroskedasticity (กรวย) · ใช้เป็นค่าเริ่มต้นที่ดีกับข้อมูลตัดขวาง
  • cov_type="HAC", cov_kwds={"maxlags":5} — Newey-West แก้ทั้งกรวยและคลื่น (autocorrelation) · ใช้กับข้อมูลอนุกรมเวลา ซึ่งคือกรณีของผลตอบแทนรายวันเกือบทั้งหมด

กฎง่าย ๆ: ทำ regression กับข้อมูลตลาดเมื่อไร ให้ใช้ robust ไว้ก่อนเสมอ — ถ้าไม่จำเป็นก็แค่ได้ SE ที่ระมัดระวังขึ้นนิดหน่อย

⚠️ แต่ "เสมอ" มีข้อยกเว้นที่สำคัญ: robust SE ต้องการข้อมูลพอสมควร (~50 จุดขึ้นไป) · สูตร HC/HAC ถูกต้องแบบ asymptotic คือ "แม่นเมื่อ n ใหญ่พอ" · กับข้อมูลไม่กี่จุดอย่างตัวอย่าง §6.4 ที่มี 6 จุด มันไม่ช่วยเลย และอาจแย่กว่าเดิมด้วยซ้ำ

⚠️ และ maxlags ไม่ควรตั้งเป็น 5 ตามใจ · ค่าที่แนะนำคือ ≈ 4(n/100)^(2/9) หรือตั้งตามระยะเวลาที่ข้อมูลซ้อนทับกันจริง (เช่น ถ้าคำนวณผลตอบแทน 5 วันแบบเลื่อนทุกวัน ให้ใช้ 4)

🔧 ทดสอบ heteroskedasticity ด้วยตัวเลข ไม่ใช่แค่มองกรวยด้วยตา

ตลอดบทนี้เราตรวจกรวยด้วยการดูรูป กับกฎนิ้วโป้ง "อัตราส่วนเกิน ~2 เท่า" (ซึ่งเป็นเกณฑ์ที่ผมตั้งเอง ไม่ใช่ค่ามาตรฐาน) · มีการทดสอบอย่างเป็นทางการที่ใช้ได้ในบรรทัดเดียว:

from statsmodels.stats.diagnostic import het_breuschpagan lm, lm_p, f, f_p = het_breuschpagan(model.resid, model.model.exog) # p < 0.05 → มี heteroskedasticity จริง (ไม่ใช่แค่ตาลาย)

ใช้คู่กัน: ดูรูปเพื่อรู้ว่ามันเป็นรูปแบบไหน (กรวย · โค้ง · เป็นก้อน) · ใช้ Breusch-Pagan เพื่อรู้ว่ามันแรงพอให้กังวลไหม

6.6 Multicollinearity — เมื่อตัวแปรต้นซ้ำกันเอง

🚶 อ่านเป็นภาษาคนก่อน: ใน factor model (เล่ม 2 · A §2.2) เราใส่หลายปัจจัยพร้อมกัน · ถ้าสองปัจจัยนั้นเกือบเป็นตัวเดียวกัน โมเดลจะแยกไม่ออกว่าผลมาจากใคร — เหมือนถามว่า "ในทีมนี้ใครทำงาน" แต่สองคนนั้นทำงานเหมือนกันเป๊ะทุกอย่าง

ผลคือ β ของทั้งคู่จะเหวี่ยงมั่ว (SE พุ่ง) และอาจได้เครื่องหมายกลับด้านจากที่ควรเป็น · เครื่องมือตรวจชื่อ VIF (Variance Inflation Factor)

🐍 Python — ตรวจ VIF ของ factor model
# pip install numpy statsmodels
import numpy as np, statsmodels.api as sm
from statsmodels.stats.outliers_influence import variance_inflation_factor as vif

rng = np.random.default_rng(3)
N = 400
market = rng.normal(0, 1, N)
size   = rng.normal(0, 1, N)
value  = 0.95*market + 0.1*rng.normal(0, 1, N)   # จงใจให้เกือบซ้ำกับ market

F = np.column_stack([np.ones(N), market, size, value])
for i, name in [(1,"market"), (2,"size"), (3,"value")]:
    print(f"VIF {name:7s} = {vif(F, i):.2f}")
# VIF market  = 95.64   ← สูงมาก
# VIF size    = 1.01    ← สะอาด
# VIF value   = 95.74   ← สูงมาก (คู่กับ market)
✅ อ่านค่า VIF

5 – 10เริ่มทับซ้อนระวังตอนตีความ β
> 10ทับซ้อนรุนแรงดูกล่องข้างล่างก่อนตัดสินใจ — อย่าเพิ่งตัดทิ้ง

ในตัวอย่างนี้ VIF ≈ 96 ทั้งคู่ = market กับ value เล่าเรื่องเดียวกัน · ควรเก็บไว้ตัวเดียว · สังเกตว่า size ที่เป็นอิสระจริงได้ VIF = 1.01 พอดี

💡 โยงกลับบทที่ 5: multicollinearity มองเห็นได้ใน heatmap — มันคือ "กลุ่มสีแดงเข้มติดกัน" นั่นเอง · ตรวจด้วยตาก่อนด้วย heatmap แล้วยืนยันด้วย VIF

❌ "VIF สูง = ตัดทิ้ง" เป็นคำแนะนำที่ผิดบ่อยที่สุดเรื่องหนึ่ง

คำถามแรกที่ต้องถามคือ "คุณจะเอาโมเดลไปทำอะไร" — คำตอบเปลี่ยนคำแนะนำทั้งหมด

เป้าหมายVIF สูงเป็นปัญหาไหมทำยังไง
พยากรณ์ yไม่เลย ✓ปล่อยไว้ได้ · ค่าทำนายกับ R² ไม่กระทบแม้แต่นิดเดียว
ตีความ β รายตัวใช่ ❌ต้องแก้ — แต่ดูวิธีข้างล่าง

ข้อเท็จจริงที่คนไม่ค่อยรู้: multicollinearity ไม่ทำให้การพยากรณ์แย่ลงเลย · มันทำแค่ทำให้ β แต่ละตัวตีความไม่ได้ เพราะโมเดลแยกไม่ออกว่าเครดิตควรไปที่ใคร · ถ้าคุณไม่ได้จะอ่าน β รายตัว มันไม่ใช่ปัญหาของคุณ

และถ้าต้องแก้จริง — การตัดทิ้งคือทางเลือกที่แย่ที่สุด เพราะถ้าปัจจัยนั้นมีผลต่อ y จริง การตัดมันออกจะทำให้ β ของตัวที่เหลือเอนผิด (เรียกว่า omitted-variable bias) ซึ่งมักแย่กว่า SE ที่กว้างที่คุณพยายามแก้ตั้งแต่แรก

2 วิธีที่ดีกว่า:

  1. Orthogonalize — regress value บน market ก่อน แล้วใช้ residual แทน value · ตอนนี้มันเป็นอิสระจาก market โดยสิ้นเชิง และ β ของมันแปลว่า "ส่วนของ value ที่ market อธิบายไม่ได้" ซึ่งเป็นสิ่งที่คุณอยากรู้อยู่แล้ว · นี่คือสิ่งที่ Fama-French ทำจริงกับปัจจัยของเขา
  2. รวมสองตัวเป็นตัวเดียว — ถ้ามันเล่าเรื่องเดียวกัน ก็ยอมรับเสียว่ามันคือปัจจัยเดียว (เช่น เฉลี่ยกัน หรือใช้ PCA จาก เล่ม 2 · A §1.4)

6.7 R² ที่หลอกลวง — Adjusted R² และ Train/Test

🚶 อ่านเป็นภาษาคนก่อน: R² มีนิสัยเสียอย่างหนึ่ง — มันเพิ่มขึ้นเสมอเมื่อใส่ตัวแปรเพิ่ม แม้ตัวแปรนั้นจะเป็นเลขสุ่มล้วน ๆ · ดังนั้น "R² สูง" จึงไม่ใช่หลักฐานว่าโมเดลดี · Adjusted R² แก้โดยหักค่าปรับตามจำนวนตัวแปร แต่วิธีที่ซื่อสัตย์ที่สุดคือ ทดสอบกับข้อมูลที่โมเดลไม่เคยเห็น

🐍 Python — ใส่ตัวแปรขยะ 15 ตัว แล้วดูว่าเกิดอะไร
# pip install numpy statsmodels
import numpy as np, statsmodels.api as sm

rng = np.random.default_rng(5)
N = 200
x_real = rng.normal(0, 1, (N, 1))
y      = 1 + 1.5*x_real[:,0] + rng.normal(0, 1, N)
junk   = rng.normal(0, 1, (N, 15))          # ตัวแปรขยะล้วน ๆ ไม่เกี่ยวกับ y
X_all  = np.column_stack([x_real, junk])

tr, te = slice(0,150), slice(150,N)         # แบ่ง 150 ฝึก / 50 ทดสอบ
for k, label in [(1,"ตัวแปรจริง 1 ตัว"), (16,"+ ขยะอีก 15 ตัว")]:
    Xk = sm.add_constant(X_all[:, :k])
    m  = sm.OLS(y[tr], Xk[tr]).fit()
    pred = m.predict(Xk[te])                # ทำนายข้อมูลที่ไม่เคยเห็น
    r2_out = 1 - ((y[te]-pred)**2).sum() / ((y[te]-y[te].mean())**2).sum()
    print(f"{label:18s}: R2(in)={m.rsquared:.3f}  adjR2={m.rsquared_adj:.3f}  R2(out)={r2_out:.3f}")
# ตัวแปรจริง 1 ตัว  : R2(in)=0.662  adjR2=0.660  R2(out)=0.805
# + ขยะอีก 15 ตัว   : R2(in)=0.709  adjR2=0.674  R2(out)=0.770
❌ ดูให้ดี — นี่คือหน้าตาของ overfitting
  • R²(in) เพิ่มขึ้น 0.662 → 0.709 · ตัวแปรขยะ 15 ตัวทำให้โมเดล "ดูดีขึ้น" กับข้อมูลที่มันเห็น
  • Adjusted R² เพิ่มน้อยกว่ามาก 0.660 → 0.674 · มันหักค่าปรับให้ แต่ยังโดนหลอกอยู่ดี
  • R²(out) ลดลง 0.805 → 0.770 ← ตัวนี้พูดความจริง · กับข้อมูลใหม่ โมเดลที่ใส่ขยะแย่ลงจริง

ถ้าดูแค่ R²(in) คุณจะเลือกโมเดลที่ผิด · ตัวเลขเดียวที่เชื่อได้คือผลกับข้อมูลที่โมเดลไม่เคยเห็น

📌 "เอ๊ะ ทำไม R²(out) = 0.805 สูงกว่า R²(in) = 0.662 ล่ะ?" — คำถามที่ถูกต้องมาก และคำตอบคือ ไม่ใช่เรื่องผิดปกติ · ช่วงทดสอบบังเอิญมี x แกว่งกว้างกว่าช่วงฝึก (variance 1.18 vs 0.84) · เมื่อ x กระจายกว้าง ความสัมพันธ์จริงจะเด่นเหนือ noise มากขึ้น R² จึงสูงขึ้นเอง · สิ่งที่ต้องดูคือ "การเปลี่ยนแปลง" ระหว่างสองแถว ไม่ใช่ระดับของตัวเลข — และการเปลี่ยนแปลงบอกชัดว่าใส่ขยะแล้วแย่ลง

❌ ข้อมูลอนุกรมเวลา ห้ามสุ่มแบ่ง — และเครื่องมือยอดนิยมสุ่มให้โดยอัตโนมัติ

สังเกตว่าโค้ดข้างบนแบ่งด้วย slice(0,150) และ slice(150,N) คือ แบ่งตามลำดับเวลา — อดีตฝึก อนาคตทดสอบ · นี่คือวิธีเดียวที่ถูกต้องสำหรับข้อมูลการเงิน

แต่ขั้นตอนถัดไปที่ผู้อ่านเกือบทุกคนจะทำคือหันไปใช้:

from sklearn.model_selection import train_test_split X_tr, X_te, y_tr, y_te = train_test_split(X, y, test_size=0.25) ← shuffle=True เป็นค่าปริยาย!

มันสลับลำดับข้อมูลให้โดยอัตโนมัติ · ผลคือชุดฝึกมีข้อมูลของเดือนธันวาคม ส่วนชุดทดสอบมีข้อมูลของเดือนมีนาคม — คุณเพิ่งให้โมเดลเห็นอนาคตแล้วเอาไปทำนายอดีต

ผลลัพธ์คือ backtest ที่ดูดีเกินจริงอย่างมาก และไม่มีอะไรแจ้งเตือนคุณเลย · ต้องใส่ shuffle=False เองเสมอ หรือใช้ TimeSeriesSplit · เรื่องนี้จะกลับมาสำคัญมากใน เล่ม 2 · D ซึ่งทั้งเล่มเป็นข้อมูลอนุกรมเวลา

🧠 มุมที่มองต่าง — ทำไมนักเทรดถึงกลัว R² สูง

มือใหม่เห็น: "backtest ได้ R² = 0.95 กลยุทธ์นี้เทพมาก"
คนในตลาดเห็น: R² สูงผิดปกติกับข้อมูลอดีต = สัญญาณอันตราย ไม่ใช่สัญญาณดี · เพราะตลาดจริงมี noise เยอะมาก โมเดลที่อธิบายอดีตได้เกือบสมบูรณ์มักแปลว่ามันจำ noise ไปแล้ว และจะพังทันทีกับข้อมูลใหม่

  • รายงาน β เป็นช่วง ไม่ใช่จุดเดียว — และรู้ว่าข้อมูลน้อยทำให้ช่วงกว้างแค่ไหน
  • ใช้ robust SE กับข้อมูลตลาด และตรวจ VIF ใน factor model
  • ไม่ตกหลุม R² สูงหลอก — วัดด้วย out-of-sample
เราใช้ t-stat กับ p-value มาทั้งบท — แต่ "t" มาจากไหน และ "สมมติฐาน" ที่ p-value กำลังทดสอบคืออะไร?
📖 อ่านต่อ — บทที่ 7: อ่านกราฟการแจกแจง

บทที่ 7 จะปิดช่องว่างที่เหลือ: t-distribution คืออะไร (และทำไม CI ของ n=6 ถึงกว้าง) · กรอบการทดสอบสมมติฐาน ที่ p-value ยืนอยู่บนนั้น · กราฟการแจกแจงที่ยังไม่ได้สอน (QQ plot · box plot) · และคำถามใหญ่ที่สุด — ทำไมเรายังใช้ mean/SD ทั้งที่ราคาสินทรัพย์ไม่เป็น Normal

📖 ศัพท์ใหม่ในตอนนี้ (บทที่ 6)

Standard Error (SE) = ค่าประมาณเหวี่ยงแค่ไหน · t-stat = β ÷ SE · p-value = โอกาสเห็นผลแรงขนาดนี้ถ้าจริง ๆ ไม่มีความสัมพันธ์ · Confidence Interval = ช่วงที่ค่าจริงน่าจะอยู่ · Robust SE (HC3 / Newey-West) = SE ที่ทนต่อกรวยและคลื่น · Multicollinearity = ตัวแปรต้นซ้ำกันเอง · VIF = ตัววัด multicollinearity · Adjusted R² = R² ที่หักค่าปรับตามจำนวนตัวแปร · Out-of-sample = ทดสอบกับข้อมูลที่โมเดลไม่เคยเห็น · Overfitting = จำ noise แทนเรียน pattern

บทที่ 5 สอนอ่านกราฟความสัมพันธ์ระหว่างสองตัวแปร (scatter · residual · heatmap) · บทนี้ถอยมาดูตัวแปรตัวเดียว: มันกระจายตัวหน้าตายังไง เป็นระฆังจริงไหม และถ้าไม่ใช่ — เครื่องมือทั้งหมดที่เราสร้างมายังใช้ได้อยู่หรือเปล่า

🔗 ต่อจากที่เรียนมาแล้ว

7.1 Histogram + เส้นระฆังทาบ — อ่าน mean/SD จากภาพ

🚶 อ่านเป็นภาษาคนก่อน: histogram คือการนับว่า "ค่าตกอยู่ในช่วงไหนกี่ครั้ง" แล้ววาดเป็นแท่ง · mean คือจุดกลาง ของกองแท่ง · SD คือความกว้าง ของกอง · เอาเส้นระฆัง Normal ทฤษฎีมาทาบทับ จะเห็นทันทีว่าข้อมูลจริง "ไม่ตรง" ตรงไหน

🔧 ก่อนไปต่อ — SD ที่คุณคำนวณอาจไม่เท่ากับ SD ที่เพื่อนคำนวณ

มีรายละเอียดเล็ก ๆ ที่ทำให้คนสับสนกันบ่อยมาก · numpy กับ pandas หาร SD ด้วยตัวเลขคนละตัว:

np.std(x) → หารด้วย n (ddof=0 · "SD ของประชากร") pd.Series(x).std() → หารด้วย n−1 (ddof=1 · "SD ของตัวอย่าง")

โค้ดทั้งเล่มนี้ใช้ numpy (ddof=0) · ถ้าคุณย้ายไป pandas แล้วได้เลขไม่ตรงกับในหนังสือ นี่คือสาเหตุ ไม่ใช่ความผิดพลาดของคุณ

ต่างกันแค่ไหน: ที่ n = 3,000 ต่างกัน 0.017% — ไม่มีความหมาย · ที่ n = 6 (เช่นตัวอย่าง β ใน §6.4) ต่างกัน ~9% ซึ่งมีความหมายมาก · ยิ่งข้อมูลน้อย ยิ่งต้องรู้ว่ากำลังใช้ตัวไหน · ใส่ np.std(x, ddof=1) ถ้าต้องการให้ตรงกับ pandas

❌ กับดักที่ 1 — histogram เปลี่ยนรูปได้ตามความกว้างแท่ง

สามภาพข้างล่างคือข้อมูลชุดเดียวกันเป๊ะ ต่างกันแค่จำนวนแท่ง:

✅ วิธีใช้ให้ปลอดภัย
  • ลองหลาย bin เสมอ ก่อนสรุปรูปทรง · ถ้ารูปเปลี่ยนไปมา แปลว่าข้อมูลยังน้อยเกินจะสรุป
  • กฎนิ้วโป้ง: จำนวนแท่ง ≈ √n (ข้อมูล 400 จุด → ~20 แท่ง) เป็นจุดตั้งต้นที่ดี
  • อย่าดู histogram อย่างเดียว — ถามว่า "Normal ไหม" ให้ใช้ QQ plot (§7.2) ซึ่งไม่ขึ้นกับ bin
❌ กับดักที่ 2 — mean กับ SD ไวต่อค่าสุดขั้วมาก

mean กับ SD คำนวณจากผลรวมของ (ค่า − ค่าเฉลี่ย)ยกกำลังสอง · ค่าที่อยู่ไกลจึงมีน้ำหนักมหาศาล — จุดเดียวขยับ SD ได้ทั้งชุด (เหมือน leverage point ใน §5.2) · ถ้าข้อมูลมีค่าสุดขั้ว ให้รายงาน median กับ IQR ควบคู่ไปด้วยเสมอ

7.2 QQ Plot — เครื่องมือที่ตรงคำถามที่สุดว่า "Normal ไหม"

🚶 อ่านเป็นภาษาคนก่อน: QQ plot เอา "ค่าที่ข้อมูลจริงมี" ไปวางคู่กับ "ค่าที่ Normal ควรจะมี" ทีละเปอร์เซ็นไทล์ · ถ้าข้อมูลเป็น Normal จริง จุดทุกจุดจะเรียงอยู่บนเส้นตรง · จุดที่หลุดออกจากเส้น = ตรงนั้นแหละที่ข้อมูลจริงไม่เหมือน Normal

เห็นแบบนี้แปลว่าผลต่อการเทรด
✅ จุดเกาะเส้นNormal ใช้ได้เครื่องมือมาตรฐานเชื่อได้
❌ ปลายงอออก (ทั้ง 2 ข้าง)fat tails — เหตุการณ์สุดขั้วเกิดบ่อยกว่าที่ Normal ทำนายVaR ต่ำเกินจริง · ประเมินความเสี่ยงหางพลาด
❌ ปลายซ้ายงอลงข้างเดียวเบ้ซ้าย — ตกหนักกว่าขึ้นหางซ้ายอันตรายเป็นพิเศษ (OTM Put แพง)
❌ โค้งทั้งเส้นเบ้ (skew) ทั้งการแจกแจงmean กับ median ห่างกัน
💎 ทำไม QQ plot ดีกว่า histogram สำหรับคำถามนี้

Histogram แสดง "ตรงกลาง" ได้ดี แต่หางมีข้อมูลน้อย แท่งจึงเตี้ยจนมองไม่เห็นความต่าง · แต่หางคือที่ที่เงินหายไป · QQ plot ขยายหางให้ใหญ่ขึ้นโดยธรรมชาติ เพราะมันเทียบทีละเปอร์เซ็นไทล์ — จุดสุดขั้วจึงกระโดดออกจากเส้นให้เห็นชัด · นี่คือกราฟที่ทำให้ "fat tails" ที่ Part II พูดถึงเป็นตัวเลข กลายเป็นสิ่งที่เห็นด้วยตา

🐍 Python — วาด QQ plot ของข้อมูลตัวเอง
# pip install scipy matplotlib numpy
import numpy as np
from scipy import stats
import matplotlib; matplotlib.use("Agg")
import matplotlib.pyplot as plt

rng = np.random.default_rng(11)
normal_data = rng.normal(0, 1, 3000)
fat_data    = stats.t.rvs(df=4, size=3000, random_state=11)
fat_data    = fat_data / fat_data.std()          # ปรับ SD ให้ = 1 เท่ากัน

fig, ax = plt.subplots(1, 2, figsize=(8,4))
for a, d, t in [(ax[0], normal_data, "Normal"), (ax[1], fat_data, "fat tails")]:
    stats.probplot(d, dist="norm", plot=a)       # ★ บรรทัดเดียวได้ QQ plot
    a.set_title(t)
fig.tight_layout(); fig.savefig("qq.png", dpi=120)

# วัดเป็นตัวเลข: ปลายหางจริง เทียบกับที่ Normal ควรเป็น
for name, d in [("Normal   ", normal_data), ("fat tails", fat_data)]:
    lo, hi = np.quantile(d, [0.002, 0.998])
    print(f"{name}: หางจริง = [{lo:+.2f}, {hi:+.2f}] SD")
print(f"Normal ทฤษฎีควรเป็น = [{stats.norm.ppf(0.002):+.2f}, {stats.norm.ppf(0.998):+.2f}] SD")
# Normal   : หางจริง = [-2.88, +2.97] SD
# fat tails: หางจริง = [-4.31, +4.32] SD   ← ยาวกว่าที่ควรเป็นมาก
# Normal ทฤษฎีควรเป็น = [-2.88, +2.88] SD

7.3 Box Plot — และกับดักที่ทำให้คนตัดข้อมูลดีทิ้ง

🚶 อ่านเป็นภาษาคนก่อน: box plot ย่อข้อมูลทั้งกองเหลือ 5 ตัวเลข · กล่องคือช่วงที่ข้อมูลตรงกลาง 50% อยู่ (Q1 ถึง Q3) · เส้นในกล่องคือ median · หนวดยืดไปถึงค่าที่ยัง "ปกติ" · จุดที่เลยหนวดออกไปมักถูกเรียกว่า outlier

❌ กับดักใหญ่ที่สุดของ box plot — "จุดนอกหนวด = outlier ต้องตัดทิ้ง"

กฎ 1.5×IQR เป็นแค่ข้อตกลงเชิงสถิติ ไม่ใช่การตรวจจับข้อผิดพลาด · ลองสร้างข้อมูล Normal แท้ ๆ 3,000 จุด (ไม่มีอะไรผิดเลยสักจุด) แล้วนับดู:

ข้อมูลจุดที่ถูกเรียกว่า outlierความจริง
Normal แท้ 3,000 จุด37 จุด (1.23%)
ค่าคาดหวังตามทฤษฎี ~0.70%		ไม่มีจุดไหนผิดเลย
fat tails 3,000 จุด116 จุด (3.87%)หางหนาจริง

ถ้าคุณ "ทำความสะอาดข้อมูล" โดยตัดจุดนอกหนวดทิ้งทุกครั้ง — ในตลาดการเงินคุณกำลังตัดวัน crash ทิ้ง ซึ่งเป็นวันที่สำคัญที่สุดต่อการวัดความเสี่ยง · ผลคือ VaR ที่คำนวณได้จะสวยเกินจริงอย่างเป็นระบบ

❌ กับดักที่ 2 — box plot ซ่อนรูปทรงของข้อมูล

box plot รู้จักแค่ 5 ตัวเลข มันจึงแยกไม่ออกระหว่าง "กองเดียว" กับ "สองกองแยกกัน" · ข้อมูลที่มี 2 ยอด (bimodal) จะให้ box plot หน้าตาเหมือนข้อมูลยอดเดียวทุกประการ · ถ้าสงสัย ให้ดู histogram หรือ violin plot (box plot ที่วาดรูปทรงไปด้วย) ควบคู่

✅ แล้ว box plot เก่งเรื่องอะไร

เก่งที่สุดตอน เทียบหลายกลุ่มพร้อมกัน — เช่น เทียบการกระจายผลตอบแทนของ 10 หุ้นในภาพเดียว หรือเทียบผลตอบแทนรายเดือนทั้ง 12 เดือน · ตรงนั้น histogram 10 ใบจะอ่านยากกว่ามาก

🐍 Python — นับว่ากฎ 1.5×IQR เรียก outlier กี่จุด
# pip install numpy scipy
import numpy as np
from scipy import stats

rng = np.random.default_rng(11)
normal_data = rng.normal(0, 1, 3000)               # Normal แท้ ไม่มีจุดผิดเลย
fat_data    = stats.t.rvs(df=4, size=3000, random_state=11)
fat_data    = fat_data / fat_data.std()

for name, d in [("Normal แท้", normal_data), ("fat tails", fat_data)]:
    q1, q3 = np.percentile(d, [25, 75])
    iqr = q3 - q1
    lo, hi = q1 - 1.5*iqr, q3 + 1.5*iqr            # ★ กฎมาตรฐานของ box plot
    n_out = ((d < lo) | (d > hi)).sum()
    print(f"{name}: IQR={iqr:.2f} | โดนเรียก outlier {n_out} จุด ({n_out/len(d)*100:.2f}%)")
# Normal แท้: IQR=1.32 | โดนเรียก outlier 37 จุด (1.23%)
# fat tails: IQR=1.06 | โดนเรียก outlier 116 จุด (3.87%)
print("→ แม้แต่ Normal สมบูรณ์แบบก็มีจุดนอกหนวด อย่าเหมาว่าเป็นข้อมูลผิด")
# → แม้แต่ Normal สมบูรณ์แบบก็มีจุดนอกหนวด อย่าเหมาว่าเป็นข้อมูลผิด

# ★ ค่าที่ควรได้ตามทฤษฎี — 1.5xIQR ของ Normal = 2.698 SD
print(f"ทฤษฎี: Normal ควรมี {2*stats.norm.cdf(-2.698)*100:.2f}% (1 ใน {1/(2*stats.norm.cdf(-2.698)):.0f} จุด)")
# ทฤษฎี: Normal ควรมี 0.70% (1 ใน 143 จุด)
🔧 ทำไม 1.23% ถึงไม่ใช่ตัวเลขที่ควรจำ — จำ 0.70% แทน

ค่า 1.23% ที่ได้คือผลของ seed เดียว · ค่าที่ถูกต้องตามทฤษฎีคือ 0.70% (เพราะ 1.5×IQR ของ Normal ตรงกับ 2.698 SD พอดี)

ผมรันซ้ำด้วย 300 seed: ค่าเฉลี่ยได้ 0.70% ตรงทฤษฎีเป๊ะ · แต่ช่วง 5–95% กว้างถึง [0.40%, 1.03%] · 1.23% ของเราจึงสูงกว่าเปอร์เซ็นไทล์ที่ 95 ด้วยซ้ำ — เป็น seed ที่โชคไม่ดีเป็นพิเศษ

ข้อสรุปไม่เปลี่ยน (Normal แท้ก็มีจุดนอกหนวดเสมอ) แต่ตัวเลขที่ควรติดหัวไปคือ ~0.7% หรือราว 1 ใน 143 จุด ไม่ใช่ 1.23%

💎 และนี่คือบทเรียนซ้อนบทเรียน: ตัวอย่างที่ตั้งใจสอนว่า "อย่าเชื่อว่าจุดสุดขั้วคือข้อมูลผิด" กลับสาธิตความไม่แน่นอนของการสุ่มให้ดูพร้อมกันโดยบังเอิญ — ตัวเลขจาก 3,000 จุดยังเด้งได้เกือบ 2 เท่าระหว่าง seed

7.4 t-Distribution — เฉลยปริศนา CI ที่กว้างผิดคาด

🚶 อ่านเป็นภาษาคนก่อน: ในบทที่ 6 เราคำนวณช่วงความเชื่อมั่นโดย "เอา SE คูณด้วยค่าวิกฤต" · ค่าวิกฤตนั้นมาจาก t-distribution ไม่ใช่ Normal · t หน้าตาเหมือนระฆังแต่หางหนากว่า และความหนาขึ้นกับว่ามีข้อมูลมากแค่ไหน

🔧 ทำไมต้องมี t แยกจาก Normal

เวลาเราคำนวณ CI เราไม่รู้ σ ที่แท้จริง — ต้องประมาณจากข้อมูลเดียวกันนั้น · การประมาณนั้นมีความไม่แน่นอนของตัวมันเองซ้อนอยู่ · t-distribution คือการเผื่อความไม่แน่นอนชั้นที่สองนี้ โดยทำหางให้หนาขึ้น · ยิ่งข้อมูลน้อย ยิ่งไม่มั่นใจใน σ ยิ่งต้องเผื่อมาก

จำนวนข้อมูลdfค่าวิกฤต 95%เทียบ Normal
n = 642.776กว้างกว่า 42%
n = 752.571กว้างกว่า 31%
n = 12102.228กว้างกว่า 14%
n = 32302.042กว้างกว่า 4%
n = 1021001.984กว้างกว่า 1%
n → ∞∞1.960= Normal พอดี
💎 ปิดวงกับ บทที่ 6.4 — ทำไม CI ของ β=1.54 ถึงกว้าง

จำ β = 1.5391 จากข้อมูล 6 เดือนได้ไหม · CI ที่ได้คือ [1.118, 1.960] ซึ่งกว้างจนน่าตกใจ · ตอนนั้นเราบอกแค่ว่า "ข้อมูลน้อย" — ตอนนี้เห็นกลไกจริงแล้ว:

CI = β̂ ± (ค่าวิกฤต) × SE = 1.5391 ± 2.776 × 0.1516 ← ใช้ t(df=4) ไม่ใช่ z=1.96 = 1.5391 ± 0.4209 = [1.118 , 1.960] ✓ ถ้าเผลอใช้ z = 1.96 จะได้ [1.242, 1.836] — แคบกว่าความจริง

ความต่าง 42% นั้นไม่ใช่รายละเอียดปลีกย่อย · แปลงเป็นเงินกับพอร์ต ฿1,000,000 โดยเอาความกว้างของ CI คูณเงินต้น:

ใช้ t (ถูกต้อง): กว้าง = 2 × 2.776 × 0.1516 = 0.842 → ฿842,000 ใช้ z (ผิด): กว้าง = 2 × 1.960 × 0.1516 = 0.594 → ฿594,000 ส่วนต่างที่หายไป = ฿248,000 ของความไม่แน่นอนที่คุณมองไม่เห็น

ใช้ z ทั้งที่ข้อมูลน้อย = มั่นใจเกินจริงอย่างเป็นระบบ — และมันซ่อนความเสี่ยงเป็นเงินจริงเกือบสองแสนห้าจากคุณ

🔧 แล้ว "สมมติฐาน" ที่ p-value ทดสอบคืออะไร

บทที่ 6 ใช้ p-value ตลอดโดยยังไม่ได้บอกกรอบของมัน · กรอบนั้นมี 2 ฝั่งเสมอ:

  • H₀ (สมมติฐานว่าง) — "ไม่มีอะไรเกิดขึ้น" · ในกรณี regression คือ β = 0 (ตลาดไม่เกี่ยวกับหุ้นตัวนี้เลย)
  • H₁ (สมมติฐานทางเลือก) — "มีอะไรบางอย่าง" · คือ β ≠ 0

p-value = "ถ้า H₀ จริง โอกาสที่จะบังเอิญเห็นข้อมูลแรงขนาดนี้หรือแรงกว่า มีเท่าไร" · p น้อย = ข้อมูลนี้อธิบายด้วย "ไม่มีอะไร" ได้ยาก → เราจึงปฏิเสธ H₀

สังเกตว่าเราไม่เคย "พิสูจน์ว่า H₁ จริง" — เราแค่บอกว่า H₀ อธิบายได้ยาก · นี่คือเหตุผลที่ "p > 0.05" แปลว่า "หลักฐานไม่พอ" ไม่ใช่ "ไม่มีความสัมพันธ์" (กับดักที่เตือนไว้ใน §6.2)

🐍 Python — ค่าวิกฤต t เทียบ z และคำนวณ CI เอง
# pip install scipy
from scipy import stats

print(f"Normal (z) = {stats.norm.ppf(0.975):.3f}")      # Normal (z) = 1.960
for df in [4, 10, 30, 100]:
    t = stats.t.ppf(0.975, df)
    print(f"  t(df={df:3d}) = {t:.3f}   กว้างกว่า {(t/1.96-1)*100:4.1f}%")
#   t(df=  4) = 2.776   กว้างกว่า 41.7%
#   t(df= 10) = 2.228   กว้างกว่า 13.7%
#   t(df= 30) = 2.042   กว้างกว่า  4.2%
#   t(df=100) = 1.984   กว้างกว่า  1.2%

# สร้าง CI ของ beta จากบทที่ 6.4 ขึ้นมาเอง (n=6 → df = 6-2 = 4)
beta, se, df = 1.5391, 0.1516, 4
crit = stats.t.ppf(0.975, df)
print(f"\nCI = [{beta-crit*se:.3f}, {beta+crit*se:.3f}]")   # CI = [1.118, 1.960]
print(f"ถ้าใช้ z ผิด ๆ = [{beta-1.96*se:.3f}, {beta+1.96*se:.3f}]")
# ถ้าใช้ z ผิด ๆ = [1.242, 1.836]  ← แคบเกินจริง

เมื่อไปถึง §7.6 เรื่องนี้จะกลับมาอีกครั้ง — และเป็นเหตุผลที่ทำไมการเปลี่ยนไปใช้โมเดลหางหนาไม่ได้แก้ปัญหาฟรี ๆ

🐍 Python — วัด kurtosis และหางของสองชุดที่ SD เท่ากัน
# pip install numpy scipy
import numpy as np
from scipy import stats

rng = np.random.default_rng(11)
normal_data = rng.normal(0, 1, 3000)
fat_data    = stats.t.rvs(df=4, size=3000, random_state=11)
fat_data    = fat_data / fat_data.std()          # ★ บังคับให้ SD = 1 เท่ากัน

for name, d in [("Normal   ", normal_data), ("fat tails", fat_data)]:
    print(f"{name}: SD={d.std():.2f} | excess kurtosis={stats.kurtosis(d):+5.2f} "
          f"| เกิน 3SD={(abs(d)>3).mean()*100:.2f}% | แย่สุด={abs(d).max():.2f} SD")
# Normal   : SD=1.01 | excess kurtosis=+0.12 | เกิน 3SD=0.37% | แย่สุด=3.73 SD
# fat tails: SD=1.00 | excess kurtosis=+10.48 | เกิน 3SD=1.43% | แย่สุด=11.30 SD

7.6 🎓 ทำไมเรายังใช้ mean/SD ทั้งที่ราคาสินทรัพย์ไม่เป็น Normal

ถึงตรงนี้เราพิสูจน์แล้วว่าตลาดจริงมีหางหนา · คำถามที่ตามมาอย่างเลี่ยงไม่ได้คือ — แล้วทำไมทั้งวงการยังใช้ mean, SD, Markowitz, Black-Scholes ที่สร้างบน Normal อยู่? คำตอบไม่ใช่ "เพราะขี้เกียจ" แต่มีเหตุผลที่หนักแน่น 5 ข้อ

🚶 อ่านเป็นภาษาคนก่อน: ข่าวดีคือ σ ไม่ได้พังทั้งหมด — มันพังเฉพาะที่หาง · ลองนึกถึงไม้บรรทัดที่วัดระยะสั้น ๆ ได้แม่นมาก แต่พอวัดของยาว ๆ เริ่มเพี้ยน · คุณไม่ทิ้งไม้บรรทัด คุณแค่รู้ว่ามันเชื่อได้ถึงตรงไหน

ห้าข้อข้างล่างบอกว่าทำไมมันยังใช้ได้ · และกล่อง "ต้องระวังอะไร" ท้ายหัวข้อบอกว่าห้ามใช้ตรงไหน · อ่านคู่กันเสมอ — ข้อใดข้อหนึ่งอย่างเดียวจะทำให้เข้าใจผิด

🔧 ศัพท์ 5 คำที่จะเจอในหัวข้อนี้ — อ่านก่อนเริ่ม
  • โมเมนต์ (moment) = ตัวเลขชุดหนึ่งที่บรรยายรูปทรงของการแจกแจง เรียงจากหยาบไปละเอียด · ที่ 1 = ค่าเฉลี่ย (อยู่ตรงไหน) · ที่ 2 = variance (กว้างแค่ไหน) · ที่ 3 = ความเบ้ (เอียงข้างไหน) · ที่ 4 = kurtosis (หางหนาแค่ไหน) · "ใช้แค่ 2 โมเมนต์แรก" จึงแปลว่า มองแค่ตรงไหนกับกว้างแค่ไหน แล้วโยนที่เหลือทิ้ง
  • Finite variance = การแจกแจงที่คำนวณ σ ออกมาเป็นตัวเลขจำกัดได้ · ฟังดูเหมือนต้องเป็นเสมอ แต่ไม่ใช่ — บางการแจกแจงหางหนามากจน σ ลู่ออกเป็นอนันต์ (เช่น Cauchy หรือ t ที่ df ≤ 2) · กับพวกนั้น σ ไม่มีความหมายเลย ไม่ใช่แค่ไม่แม่น
  • EVT (Extreme Value Theory) = ทฤษฎีที่โมเดลเฉพาะหางโดยไม่สนตรงกลาง — เอาไว้ตอบว่า "เหตุการณ์ที่แย่กว่าที่เคยเห็นมา มีโอกาสแค่ไหน"
  • MAD (Mean/Median Absolute Deviation) = วัดการกระจายด้วยระยะห่างสัมบูรณ์แทนการยกกำลังสอง · ทนต่อค่าสุดขั้วกว่า σ มาก เพราะไม่ขยายค่าผิดปกติด้วยกำลังสอง
  • Basel = ชุดกฎกำกับธนาคารสากล ที่กำหนดว่าธนาคารต้องกันทุนสำรองเท่าไรต่อความเสี่ยงที่แบกอยู่

5 เหตุผลที่ mean/SD ยังใช้ได้ แม้ข้อมูลไม่ Normal ★★★ ต้องรู้จัก

1️⃣ σ ไม่เคยต้องการ Normal ตั้งแต่แรก

นี่คือความเข้าใจผิดที่ฝังลึกที่สุด · variance นิยามได้กับการแจกแจงใดก็ได้ที่มี finite variance — ไม่ต้องเป็นระฆัง · σ แค่ตอบว่า "ค่าเบี่ยงเบนจากค่าเฉลี่ยโดยเฉลี่ยเป็นเท่าไร" ซึ่งเป็นคำถามที่ถูกต้องเสมอ

Markowitz ก็เช่นกัน — สูตร wᵀΣw ใน เล่ม 2 · A ใช้แค่ 2 โมเมนต์แรก (mean กับ variance) ไม่เคยมีบรรทัดไหนสมมติว่าผลตอบแทนเป็น Normal

แต่ต้องแยกสองเรื่องนี้ให้ขาด — และครึ่งหลังคือครึ่งที่อันตราย:

ใช้ได้กับทุกการแจกแจงไหม
นิยาม σ — "เบี่ยงเบนเฉลี่ยเท่าไร"ใช่ ✓ ขอแค่มี finite variance
จัดอันดับพอร์ตด้วย (μ, σ) แค่สองตัวไม่ ❌ — ถูกต้องเฉพาะเมื่อผลตอบแทนเป็นตระกูล elliptical (Normal เป็นหนึ่งในนั้น) หรือผู้ลงทุนมี quadratic utility
❌ ตัวอย่างที่ทำให้เห็นว่า "σ ต่ำกว่า" ไม่ได้แปลว่า "ดีกว่า"

ทีนี้ดูสิ่งที่ σ มองไม่เห็น — อัตราทบต้นจริงเมื่อใส่ leverage (ต่อจาก เล่ม 2 · E §11.1):

💎 บทเรียน: μ กับ σ ไม่มีข้อมูลใดเลยที่บอกว่าสินทรัพย์ไหนทนแรงกดดันได้มากกว่า · ความต่างทั้งหมดอยู่ในความเบ้ ซึ่งเป็นโมเมนต์ที่สามที่กรอบนี้โยนทิ้ง · และโปรไฟล์แบบ B — ขายออปชัน · carry trade · ขายประกันความเสี่ยง — คือโปรไฟล์ที่ mean-variance ชอบที่สุดและโลกจริงลงโทษหนักที่สุด

ใช้ mean-variance ต่อไปได้ แต่ต้องดูความเบ้ของแต่ละตัวก่อนใส่เข้า optimizer เสมอ

2️⃣ CLT ทำงานกับ "ผลรวม" — และการเงินเต็มไปด้วยผลรวม

ต่อให้ผลตอบแทนรายวันของหุ้นตัวเดียวหางหนา แต่สิ่งที่เราสนใจจริง ๆ มักเป็นผลรวม:

  • ผลตอบแทนรายเดือน = ผลรวมของรายวัน ~20 วัน · นี่คือกรณีที่ CLT ช่วยได้จริง เพราะผลตอบแทนรายวันเกือบไม่มี autocorrelation (ดู เล่ม 2 · D)
  • ผลตอบแทนของกองทุนดัชนีระยะยาว = ผลรวมข้ามเวลาหลายพันวัน

CLT (Part II §6.5) บอกว่าผลรวมของตัวแปรที่เป็นอิสระต่อกันจะเข้าหา Normal · และมันเกิดขึ้นจริงเร็วกว่าที่คิด — ลองเอาข้อมูลหางหนาจัด (excess kurtosis = 10.48) มาเฉลี่ยเป็นกลุ่ม:

ข้อมูลดิบ (1 ตัว): excess kurtosis = +10.48 ← หางหนามาก เฉลี่ยจาก 5 ตัว: excess kurtosis = +2.13 เฉลี่ยจาก 20 ตัว: excess kurtosis = +0.30 เฉลี่ยจาก 60 ตัว: excess kurtosis = +0.19 ← เกือบ Normal แล้ว

แปลว่า ยิ่งรวมข้ามเวลานาน Normal ยิ่งใช้ได้ดีขึ้น · ปัญหาหางหนารุนแรงที่สุดตอนดู "รายวัน ตัวเดียว" ซึ่งเป็นระดับที่เทรดเดอร์ระยะสั้นทำงานอยู่พอดี

❌ กับดักใหญ่ที่สุดของข้อ 2 — การรวมหลายสินทรัพย์ ไม่ใช่การรวมแบบที่ CLT พูดถึง

คำที่ต้องขีดเส้นใต้ใน CLT คือ "เป็นอิสระต่อกัน" · การเฉลี่ย 20 ตัวข้างบนทำให้หางบางลงจริง เพราะข้อมูลนั้นถูกสุ่มมาแบบอิสระ · หุ้น 20 ตัวในพอร์ตของคุณไม่ได้เป็นอิสระต่อกันเลย

ผมทดสอบด้วยข้อมูลหางหนาสองแบบ — แบบอิสระจริง กับแบบที่มีปัจจัยร่วม (ρ ≈ 0.5) — แล้วเฉลี่ย 20 ตัวเหมือนกัน:

1 ตัวเฉลี่ย 20 ตัวผล
อิสระจริง (ρ = 0)+4.58+0.29หางบางลง ✓ CLT ทำงาน
มีปัจจัยร่วม (ρ ≈ 0.5)+2.36+3.60หางหนาขึ้น ❌

อ่านแถวสองอีกครั้ง — พอร์ตหางหนากว่าหุ้นเดี่ยว · เพราะช็อกร่วมกระทบทุกตัวพร้อมกัน มันจึงไม่หักล้างกัน แต่บวกกันเต็ม ๆ ขณะที่ส่วนที่เป็นของแต่ละตัวเองหักล้างกันไป · สิ่งที่เหลืออยู่คือช็อกร่วมล้วน ๆ ซึ่งหางหนากว่าเดิม

และหนังสือเล่มนี้เตือนไว้เองแล้วใน §5.5 ว่า correlation พุ่งเข้าหา 0.9 ตอนตลาด crash · แปลว่าในวันที่คุณต้องการให้การกระจายความเสี่ยงทำงานที่สุด มันทำงานน้อยที่สุดพอดี

💡 สรุปข้อ 2 ให้ถูก: CLT ช่วยเรื่องการรวมข้ามเวลา (รายวัน → รายเดือน) ได้จริง · แต่ไม่ได้ช่วยเรื่องการรวมข้ามสินทรัพย์ เว้นแต่สินทรัพย์เหล่านั้นเป็นอิสระกันจริง — ซึ่งในตลาดจริงแทบไม่เคยเป็น

3️⃣ มันพังเฉพาะที่หาง ไม่ได้พังทั้งการแจกแจง

ดูตาราง §7.5 อีกครั้ง: ที่ระดับ ±2 SD Normal กับข้อมูลหางหนาให้สัดส่วนสะสมใกล้กันมาก (95.26% vs 95.45%) · ที่พลาดหนักคือ ~1% สุดขั้ว

นั่นแปลว่า ใช้ Normal กับงานประจำวันได้ (ตั้งราคา option ที่ ATM · วัดความเสี่ยงปกติ · จัดพอร์ต) แล้วใช้เครื่องมือแยกสำหรับหางโดยเฉพาะ — ไม่ใช่ทิ้ง Normal ทั้งหมด

ที่ ±2 SD มันใกล้กัน ส่วนหนึ่งเพราะเราบังคับให้ variance เท่ากัน ไม่ใช่เพราะรูปทรงเหมือนกัน · ลองขยับเข้ามาดูตรงกลางจริง ๆ:

💡 ใช้ให้ถูกคือ: Normal เชื่อถือได้กับคำถามแบบ "สัดส่วนของวันที่อยู่ในช่วงกว้าง ๆ" (เช่น ±2 SD) · เชื่อไม่ได้กับคำถามเรื่องหาง และเชื่อไม่ได้กับคำถามที่ต้องการรูปทรงตรงกลางแม่น ๆ

4️⃣ เป็นภาษากลางที่ทุกคนใช้ร่วมกัน

เหตุผลเดียวกับที่ Part V §11.6 อธิบายเรื่อง Black-Scholes ไว้: โมเดลที่ผิดแต่ทุกคนผิดเหมือนกัน กลายเป็นหน่วยวัดร่วม

เวลาคนพูดว่า "หุ้นตัวนี้ vol 30%" ทุกคนเข้าใจตรงกันทันที เพราะทุกคนคำนวณด้วยนิยามเดียวกัน · ถ้าแต่ละคนใช้โมเดลหางหนาคนละแบบ ตัวเลขจะเทียบกันไม่ได้เลย · คุณค่าของมาตรฐานร่วม บางครั้งมากกว่าคุณค่าของความแม่นยำ

5️⃣ ทางเลือกมีต้นทุนของมันเอง

โมเดลหางหนา (t-distribution, jump diffusion, EVT) แม่นกว่าในทฤษฎี แต่ต้องประมาณพารามิเตอร์เพิ่ม — และพารามิเตอร์ที่คุมหางต้องอาศัยข้อมูลหางซึ่งมีน้อยที่สุดโดยธรรมชาติ

ผลคือ estimation error เพิ่มขึ้น (ปัญหาเดียวกับที่เตือนไว้ใน เล่ม 2 · B เรื่อง Markowitz) · โมเดลที่ซับซ้อนกว่าจึงอาจให้ผลจริงแย่กว่าโมเดลง่าย ๆ ที่เรารู้ข้อจำกัดของมันดี

🐍 Python — พิสูจน์ข้อ 2: หางจางลงเมื่อเฉลี่ยหลายตัว
# pip install numpy scipy
import numpy as np
from scipy import stats

rng = np.random.default_rng(11)
fat = stats.t.rvs(df=4, size=3000, random_state=11)
fat = fat / fat.std()                              # ข้อมูลหางหนา

print(f"ข้อมูลดิบ      : excess kurtosis = {stats.kurtosis(fat):+.2f}")
for k in [5, 20, 60]:
    means = np.array([fat[rng.integers(0, 3000, k)].mean() for _ in range(4000)])
    print(f"เฉลี่ยจาก {k:2d} ตัว: excess kurtosis = {stats.kurtosis(means):+.2f}")
# ข้อมูลดิบ      : excess kurtosis = +10.48
# เฉลี่ยจาก  5 ตัว: excess kurtosis = +2.13
# เฉลี่ยจาก 20 ตัว: excess kurtosis = +0.30
# เฉลี่ยจาก 60 ตัว: excess kurtosis = +0.19
print("→ ยิ่งรวมหลายตัว หางยิ่งจาง = CLT ทำงาน")
# → ยิ่งรวมหลายตัว หางยิ่งจาง = CLT ทำงาน

# ★★ แต่ข้างบนสุ่มแบบ "อิสระต่อกัน" — ลองใส่ปัจจัยร่วมดูบ้าง
N, k = 40_000, 20
common = stats.t.rvs(df=4, size=(N, 1), random_state=21)   # ช็อกที่กระทบทุกตัวพร้อมกัน
idio   = stats.t.rvs(df=4, size=(N, k), random_state=22)   # ช็อกเฉพาะตัว
mix    = (common + idio)/np.sqrt(2)                        # rho ระหว่างคู่ ~ 0.5

print(f"\n--- มีปัจจัยร่วม (rho = {np.corrcoef(mix[:, :2].T)[0,1]:.2f}) ---")
# --- มีปัจจัยร่วม (rho = 0.50) ---
print(f"หุ้นเดี่ยว       : excess kurtosis = {stats.kurtosis(mix[:, 0]):+.2f}")
# หุ้นเดี่ยว       : excess kurtosis = +4.37
print(f"เฉลี่ยจาก {k} ตัว: excess kurtosis = {stats.kurtosis(mix.mean(axis=1)):+.2f}")
# เฉลี่ยจาก 20 ตัว: excess kurtosis = +9.49
print("→ หางกลับหนาขึ้น 2 เท่า — CLT ไม่ช่วยเมื่อมีปัจจัยร่วม")
# → หางกลับหนาขึ้น 2 เท่า — CLT ไม่ช่วยเมื่อมีปัจจัยร่วม

🧮 "stress test" ที่ตารางแนะนำ — มันคืออะไรและทำยังไง

ตารางข้างบนสั่งให้ใช้ stress test ถึงสองที่ แต่ยังไม่ได้บอกว่ามันคืออะไร · ข่าวดีคือมันง่ายที่สุดในบรรดาเครื่องมือทั้งหมดในบทนี้ — ไม่ต้องใช้โมเดลเลยแม้แต่ตัวเดียว

ขั้นตอน:

  1. เลือกวันเลวร้ายจริงในประวัติศาสตร์ — ต้มยำกุ้ง 2540 · ฟองสบู่ dot-com 2543 · วิกฤตแฮมเบอร์เกอร์ 2551 · flash crash พ.ค. 2553 · โควิด มี.ค. 2563
  2. ถามตรง ๆ ว่า "ถ้าวันนั้นเกิดซ้ำพรุ่งนี้ พอร์ตนี้ขาดทุนกี่บาท" — เอาเปอร์เซ็นต์ที่ตลาดตกวันนั้นคูณ β ของพอร์ตคุณ
  3. ถามคำถามที่สำคัญกว่า: "แล้วเหลือเงินประกันพอไหม" — ถ้าไม่พอ คุณไม่ได้แค่ขาดทุน คุณถูกบังคับปิดในราคาที่แย่ที่สุด

ทำไมมันเหนือกว่า σ ตรงนี้: σ ตอบว่า "วันปกติเหวี่ยงแค่ไหน" ซึ่งเป็นคำถามที่ผิดเมื่อพูดถึงการอยู่รอด · stress test ใช้ตัวเลขที่เกิดขึ้นจริงแล้ว ไม่มีสมมติฐานเรื่องการแจกแจงให้ผิดได้เลย

💎 กฎกำหนดขนาดสถานะที่ปิดวงจรทั้งหมดของบทนี้: ขนาดที่ถูกต้องคือขนาดที่ทำให้วันเลวร้ายที่สุดในประวัติศาสตร์ยังไม่บังคับปิดสถานะของคุณ · ไม่ใช่ขนาดที่ optimizer บอก ไม่ใช่ขนาดที่ Sharpe สูงสุด · เล่ม 2 · E §11.5 จะลงรายละเอียดพร้อมโค้ดที่รันได้จริง

🔧 Expected Shortfall — เครื่องมือที่ควรใช้คู่กับ VaR

Part II §4.4 สอน VaR ไว้แล้ว: "ในกรณีเลวร้าย 5% จะขาดทุนอย่างน้อยเท่าไร" · แต่ VaR มีจุดบอดใหญ่ — มันบอกแค่ "เส้นเริ่มต้นของหายนะ" ไม่บอกว่าเลยเส้นไปแล้วแย่แค่ไหน

  • VaR 95% = ขาดทุนที่เปอร์เซ็นไทล์ 5 · เช่น "แย่กว่านี้ไม่เกิน 5% ของวัน"
  • Expected Shortfall (ES / CVaR) = ค่าเฉลี่ยของการขาดทุนใน 5% ที่แย่ที่สุดนั้น — ตอบว่า "ถ้าวันแย่มาถึงจริง จะแย่เฉลี่ยแค่ไหน"

ตลาดที่หางหนาทำให้ VaR สองพอร์ตเท่ากันได้ ทั้งที่ ES ต่างกันลิบ · ES จึงเป็นมาตรฐานที่กฎเกณฑ์ธนาคารสมัยใหม่ (Basel) เปลี่ยนไปใช้แทน VaR

แต่เหตุผลที่แท้จริงที่ Basel เปลี่ยน แรงกว่านั้นมาก — VaR ลงโทษการกระจายความเสี่ยง

❌ ตัวอย่าง 3 บรรทัดที่ทำให้ VaR หมดความน่าเชื่อถือ

มีหุ้นกู้ 2 ตัว เป็นอิสระต่อกัน · แต่ละตัวมีโอกาส 4% ที่จะผิดนัดชำระและขาดทุน 100

  • ถือตัวเดียว: โอกาสเจ๊ง 4% ซึ่งน้อยกว่า 5% → VaR₉₅ = 0 · "ไม่มีความเสี่ยง" ตามนิยาม
  • ถือทั้งสองตัว: โอกาสที่อย่างน้อยหนึ่งตัวเจ๊ง = 1 − 0.96² = 7.84% ซึ่งเกิน 5% → VaR₉₅ = 100
VaR(A) + VaR(B) = 0 + 0 = 0 VaR(A + B) = 100 ← กระจายความเสี่ยงแล้ว "เสี่ยงขึ้น" จาก 0 เป็น 100

นี่ขัดกับสามัญสำนึกและขัดกับทฤษฎีพอร์ตทั้งหมด · คุณสมบัติที่ VaR ขาดไปเรียกว่า sub-additivity — "ความเสี่ยงของส่วนรวมต้องไม่เกินผลรวมของความเสี่ยงแต่ละส่วน"

ES ไม่มีปัญหานี้: ES₉₅(A) = ES₉₅(B) = 80.0 · ES₉₅(A+B) = 103.2 ซึ่งน้อยกว่า 80 + 80 = 160 ✓ · ES ให้เครดิตกับการกระจายความเสี่ยงอย่างถูกต้อง

ผลในโลกจริง: ธนาคารที่วัดความเสี่ยงด้วย VaR มีแรงจูงใจให้ซุกความเสี่ยงไว้ใต้เส้น 5% — ขายประกันภัยพิบัติ · ขายออปชัน OTM ลึก ๆ · ถือสินทรัพย์ที่เจ๊งยากแต่เจ๊งแล้วเจ๊งหนัก · ทุกอย่างนี้ทำให้ VaR ดูสวยขึ้นขณะที่ความเสี่ยงจริงเพิ่มขึ้น

❌ แต่ ES เองก็ไม่ฟรี — สองข้อที่ต้องรู้ก่อนเปลี่ยนไปใช้

1. ES มีค่าคลาดเคลื่อนสูงกว่า σ มาก · ES₉₅ จากข้อมูล 250 วัน คำนวณจากแค่ ~13 จุดข้อมูลที่แย่ที่สุด · จำลอง 2,000 ครั้งพบว่าค่าที่ได้แกว่งอยู่ในช่วง ±25% · คุณกำลังเอาตัวเลขที่ไม่แน่นอนกว่าไปแทนตัวเลขที่แน่นอนกว่า — แลกความถูกต้องเชิงแนวคิดกับความไม่แน่นอนเชิงสถิติ

2. ES ตรวจย้อนหลัง (backtest) ยาก · VaR ตรวจง่ายมาก — นับว่าปีนี้ทะลุเส้นกี่วัน ควรได้ ~5% · แต่ ES เป็นค่าเฉลี่ยของสิ่งที่แทบไม่เคยเกิด จึงตรวจว่ามันถูกหรือเปล่าได้ยาก · Basel จึงใช้ทั้งคู่ — ใช้ ES คิดทุนสำรอง แต่ยังใช้ VaR ในการ backtest

คนทำงานจริงเห็น: ทุกโมเดลผิดหมด คำถามคือผิดตรงไหนและผิดไปทางไหน · Normal ผิดแบบรู้ทิศทาง — มันประเมินหางต่ำไปเสมอ ไม่เคยสูงไป · โมเดลที่ผิดแบบคาดเดาได้ ใช้งานได้ · โมเดลที่ผิดแบบเดาไม่ถูก ต่างหากที่อันตราย · นี่คือหลักการเดียวกับที่เล่ม 1 ใช้กับ Black-Scholes ทั้งเล่ม

✍️ ลองทำเอง

พอร์ต A รายงาน σ = 15%/ปี และ excess kurtosis ≈ 0 · พอร์ต B รายงาน σ = 15%/ปี เท่ากัน แต่ excess kurtosis = 9 · ถ้าคุณต้องเลือกลงเงินก้อนใหญ่ที่กู้มาบางส่วน (1) ควรเลือกพอร์ตไหน · (2) มีข้อมูลอะไรอีกที่คุณต้องถามก่อนตัดสินใจจริง?

ดูเฉลย

(1) เลือก A · แม้ "ความเสี่ยงเฉลี่ย" เท่ากันเป๊ะ แต่ B มีโอกาสเจอวันที่รุนแรงกว่ามาก · เมื่อมีเงินกู้เข้ามาเกี่ยว วันเดียวที่แรงพอสามารถบังคับปิดสถานะได้ ซึ่ง σ ไม่ได้เตือนคุณเลย

(2) คำถามที่ต้องถามคือ "หางข้างไหนหนา" ไม่ใช่แค่ "หางหนาแค่ไหน" — และโจทย์ข้อนี้จงใจไม่บอก เพราะ kurtosis ไม่แยกซ้ายขวา

ถ้า B มีความเบ้...โปรไฟล์แบบไหนใช้ leverage ได้ไหม
เป็นบวก (หางขวายาว)ซื้อออปชัน · trend followingได้ ✓ — ขาดทุนเล็กบ่อย ๆ กำไรใหญ่นาน ๆ ครั้ง · วันสุดขั้วเข้าข้างคุณ
เป็นลบ (หางซ้ายยาว)ขายออปชัน · carry · ขายประกันเครดิตอันตรายมาก ❌ — กำไรเล็กบ่อย ๆ ขาดทุนใหญ่นาน ๆ ครั้ง · วันสุดขั้วล้างพอร์ตคุณ

excess kurtosis = 9 พร้อมความเบ้บวก กับ excess kurtosis = 9 พร้อมความเบ้ลบ เป็นสินทรัพย์คนละโลกกันสิ้นเชิง · ตัวแรกใส่ leverage ได้อย่างมีเหตุผล ตัวหลังคือสิ่งที่ทำให้กองทุนล้มมาแล้วนับไม่ถ้วน

บทเรียน: เมื่อใช้ leverage ให้ตัดสินใจด้วยหาง (ความเบ้ + ES + stress test) ไม่ใช่ด้วย σ · และถ้าใครรายงานแค่ σ กับ kurtosis ให้คุณ — ยังขาดตัวเลขที่สำคัญที่สุดไปหนึ่งตัว
