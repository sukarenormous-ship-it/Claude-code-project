บทที่ 10: Linear Programming

อุปมา: ร้านขนมที่มีส่วนผสมจำกัด

สมมติเปิดร้านขนม ทำได้ 2 อย่าง: ขนมปัง A (กำไร 8 บาท) และ ขนมปัง B (กำไร 5 บาท)

แต่มีข้อจำกัด: แป้ง 20 ถ้วย (A ใช้ 5 ถ้วย, B ใช้ 2 ถ้วย) และ เวลา 5 ชั่วโมง (แต่ละชิ้น 1 ชั่วโมง)

คำถาม: ทำ A กี่ชิ้น B กี่ชิ้น จึงจะกำไรมากสุด? — นี่คือ Linear Programming!

ทรัพยากรจำกัด → ตั้ง Constraints → เขียน Objective → หาจุด Optimal

LP = หาค่า maximum/minimum ของฟังก์ชันเชิงเส้น ภายใต้เงื่อนไข (constraints) ที่เป็นเชิงเส้น

10.1 แนวคิดและการตั้งโจทย์

Maximize z = c₁x₁ + c₂x₂    (Objective Function)
Subject to:
  a₁₁x₁ + a₁₂x₂ ≤ b₁    (Constraint 1: ทรัพยากร 1)
  a₂₁x₁ + a₂₂x₂ ≤ b₂    (Constraint 2: ทรัพยากร 2)
  x₁, x₂ ≥ 0             (Non-negativity: ซื้อไม่ได้ติดลบ)
ทำไมสมการถึงเขียนแบบนี้?

c₁, c₂ = "กำไรต่อหน่วย" ของแต่ละตัวเลือก → เป้าหมายคือ maximize ผลรวม

a, b = "ส่วนผสมที่ใช้" vs "ส่วนผสมที่มี" → ข้อจำกัดทางกายภาพ

ทุก constraint เป็น "เส้นตรง" → ทำให้ feasible region เป็น "รูปหลายเหลี่ยม" → คำตอบอยู่ที่มุม!

ตัวอย่าง: จัดพอร์ต Options

Maximize Expected Payoff = 8x₁ + 5x₂
(x₁ = จำนวน Call K=100, x₂ = จำนวน Call K=110)
Subject to:
Premium: 5x₁ + 2x₂ ≤ 20 (budget ฿20)
Risk: x₁ + x₂ ≤ 5 (ไม่เกิน 5 สัญญา)
x₁, x₂ ≥ 0

10.2 Graphical Method

อุปมา: แผนที่ที่มีรั้วกั้น

นึกภาพแผนที่ 2 มิติ Constraint แต่ละข้อคือ "รั้ว" ที่กั้น พื้นที่ที่เหลือ (ข้างใน) คือ Feasible Region — บริเวณที่ทำได้จริง

Objective Function คือ "เส้นระดับความสูง" ที่ขนานกัน → เลื่อนเส้นออกไปเรื่อยๆ จนชนรั้ว → จุดนั้นคือ optimal!

สำหรับ 2 ตัวแปร แก้ได้ด้วยกราฟ: วาด constraints → หา feasible region → เช็ค corner points

Corner Point Theorem

คำตอบ optimal ของ LP อยู่ที่มุม (corner) ของ feasible region เสมอ!
ดังนั้นเช็คแค่ทุก corner → เลือกค่า z สูงสุด

1หา corner points จากจุดตัดของ constraints:

  • (0,0) — origin
  • (0,5) — constraint 2 ตัด y-axis: x₁=0 → x₂=5
  • (10/3, 5/3) — constraints 1 และ 2 ตัดกัน: แก้ระบบ 5x₁+2x₂=20, x₁+x₂=5
  • (4,0) — constraint 1 ตัด x-axis: x₂=0 → 5x₁=20 → x₁=4

2คำนวณ z ที่แต่ละ corner:

  • z(0,0) = 8(0)+5(0) = 0
  • z(0,5) = 8(0)+5(5) = 25
  • z(10/3, 5/3) = 8(10/3)+5(5/3) = 80/3+25/3 = 105/3 = 35 ← Maximum!
  • z(4,0) = 8(4)+5(0) = 32

3สรุป: ซื้อ Call K=100 จำนวน 3.33 สัญญา + Call K=110 จำนวน 1.67 สัญญา → Payoff = ฿35

10.3 Simplex Method

อุปมา: เดินป่าในความมืด หาจุดสูงสุด

ลองนึกถึงการเดินป่าตอนกลางคืน มองไม่เห็นทิวทัศน์ทั้งหมด แต่ รู้สึกได้ ว่าทิศไหนลาดขึ้นชัน

วิธี Simplex: ยืนอยู่ที่มุมหนึ่ง → มองไปมุมใกล้ๆ → เดินไปมุมที่สูงกว่า → ทำซ้ำจนไม่มีมุมที่สูงกว่า

ไม่ต้องสำรวจทุกมุม! ในทางปฏิบัติ Simplex เร็วมากแม้มีหลายร้อยตัวแปร

เมื่อมีหลายตัวแปร (ใช้กราฟไม่ได้) ใช้ Simplex Algorithm:

  1. เริ่มที่ corner หนึ่ง (มักเป็นจุด origin)
  2. มองไปรอบๆ ว่า corner ไหนดีกว่า (ดู "reduced cost")
  3. เดินไปที่ corner ที่ดีขึ้นมากที่สุด (pivot)
  4. ทำซ้ำจนไม่มี corner ที่ดีกว่า → optimal!
Corner Point Theorem → คำตอบอยู่ที่มุม → เดินจากมุมสู่มุมที่ดีขึ้น → หยุดเมื่อไม่มีมุมดีกว่า → Optimal!
Simplex ไม่ต้องจำขั้นตอน แค่เข้าใจหลักการ

"เดินไปตาม edge ของ feasible region จาก corner สู่ corner ที่ดีขึ้นเรื่อยๆ"
ในทางปฏิบัติใช้ software (Excel Solver, Python scipy.optimize.linprog)

10.4 Dual Problem & Shadow Price

อุปมา: "ถ้าได้วัตถุดิบเพิ่ม 1 หน่วย กำไรเพิ่มเท่าไหร่?"

เจ้าของร้านขนมถามว่า "ถ้าซื้อแป้งเพิ่ม 1 ถ้วย (ราคา ฿?) กำไรจะเพิ่มขึ้นเท่าไหร่?" — นั่นคือ Shadow Price!

Shadow Price = "ราคาเงา" ของ constraint — บอกว่า constraint ไหน "แพง" ที่สุด ควรไปผ่อนคลายก่อน

ทุก LP (Primal) มีคู่ (Dual) — ให้มุมมองเพิ่มเติม:

Primal: Max cTx s.t. Ax ≤ b, x ≥ 0
Dual:   Min bTy s.t. ATy ≥ c, y ≥ 0

Weak Duality: ค่า Dual ≥ ค่า Primal เสมอ
Strong Duality: ที่ optimal ค่าเท่ากัน!
ทำไม Dual มีอยู่?

Primal ถามว่า "จัด resource ยังไงให้ได้กำไรสูงสุด?"

Dual ถามว่า "resource แต่ละอย่างมี มูลค่า เท่าไหร่?" (y* = shadow prices)

Strong Duality: ทั้งสองคำถามมีคำตอบที่สอดคล้องกันที่ optimal → สามารถใช้ Dual แก้แทน Primal ได้เมื่อสะดวกกว่า

Shadow Price (y*) = "ถ้าเพิ่ม resource (b) อีก 1 หน่วย ค่า objective จะเพิ่มเท่าไหร่?"

1จากตัวอย่าง Options: ที่ optimal (10/3, 5/3) — budget constraint: 5x₁+2x₂=20 (active)

2Shadow price ของ budget constraint = ฿1/บาท budget (จาก Dual: y₁=1, y₂=3)

3ถ้า budget เพิ่มจาก ฿20 → ฿21 → Expected Payoff เพิ่มจาก ฿35 → ฿36

4ถ้า risk constraint active: shadow price บอกว่า "การเพิ่ม 1 สัญญา" มีมูลค่าเท่าไหร่

เชื่อมกับ Options

Shadow Price ของ budget constraint = "ถ้ามีเงินเพิ่มอีก ฿1 expected payoff จะเพิ่มเท่าไหร่?"
ใช้ตัดสินใจว่าควร "ขยาย budget" หรือ "ลด risk limit" — constraint ไหน "แพง" กว่า

10.5 Sensitivity Analysis

ถ้า parameter เปลี่ยน คำตอบเปลี่ยนไหม? — สำคัญเพราะ input มักไม่แน่นอน

  • Coefficient ใน objective เปลี่ยน: ถ้า expected payoff ของ Call เปลี่ยน → basis ยังเหมือนเดิมไหม? (มี "allowable range")
  • RHS ของ constraint เปลี่ยน: ถ้า budget เพิ่ม → ใช้ shadow price คำนวณได้ทันที (ตราบที่อยู่ใน range)
Sensitivity ใน Options Trading

Greeks ของ Options ก็คือ sensitivity analysis! Delta = sensitivity ของ option price ต่อ S, Vega = sensitivity ต่อ σ
Simplex sensitivity = sensitivity ของ optimal solution ต่อ parameters ของโจทย์ LP

10.6 Integer Linear Programming (ILP)

อุปมา: ซื้อตั๋วเครื่องบินครึ่งใบไม่ได้

LP อาจตอบว่า "ควรซื้อ 3.7 สัญญา" — แต่สัญญา Options ซื้อเป็นจำนวนเต็มเท่านั้น! (1 contract = 100 shares)

ILP แก้ปัญหานี้โดยบังคับให้ตัวแปรเป็นจำนวนเต็ม

ILP = LP ที่ตัวแปรต้องเป็นจำนวนเต็ม

Max cTx   s.t. Ax ≤ b, x ≥ 0, x ∈ ℤ (integers)
แก้ LP Relaxation → ตัวแปรไม่เต็ม? → Branch (x≤3 หรือ x≥4) → แก้ใหม่แต่ละ branch → Integer Solution
ILP ยากกว่า LP มาก!

LP แก้ได้ใน polynomial time แต่ ILP เป็น NP-hard → ไม่มี algorithm ที่เร็วเสมอ
วิธีแก้: Branch and Bound — แก้ LP relaxation ก่อน แล้ว branch ที่ตัวแปรที่ไม่เป็นจำนวนเต็ม

เชื่อมกับ Options

Options ซื้อเป็น สัญญา (1 contract = 100 หุ้น) → ต้องเป็นจำนวนเต็ม!
ตัวอย่าง: เลือก combination ของ option contracts ที่ maximize payoff-to-risk ภายใต้ budget constraint → ILP problem

บทที่ 11: Nonlinear Optimization

อุปมา: โลกจริงไม่ใช่เส้นตรง

Portfolio risk ไม่ใช่ linear — เพิ่ม 2 เท่าของสินทรัพย์ ไม่ได้เพิ่ม risk 2 เท่า (เพราะ diversification!)

Nonlinear optimization จัดการกับฟังก์ชันที่ "โค้ง" — อย่าง Portfolio Variance = wᵀΣw ซึ่งเป็น quadratic (โค้งพาราโบลา)

โลกจริงไม่เป็นเส้นตรง — Portfolio Optimization ของ Markowitz เป็น Quadratic ไม่ใช่ Linear

11.1 Unconstrained Optimization

หา min/max ของ f(x) โดยไม่มี constraints:

เงื่อนไขจำเป็น: f'(x*) = 0    (slope = 0 ที่จุด optimal)
เงื่อนไขเพียงพอ:
  f''(x*) > 0 → minimum (โค้งขึ้น "ชาม")
  f''(x*) < 0 → maximum (โค้งลง "โดม/หลังเต่า")
ทำไม f'=0 คือ optimal?

ถ้า slope ≠ 0 หมายความว่าเดินไปอีกนิดจะ "ดีขึ้น" → ยังไม่ optimal!

ที่ optimal จริง: ทุกทิศทางจาก x* จะ "แย่ลง" → slope ต้องเป็น 0 (หรือ gradient = 0 สำหรับหลายตัวแปร)

11.2 Gradient Descent — "เดินลงเขา"

อุปมา: ตาบอด ลงเขาในหมอก

ลองนึกถึงการลงเขาตอนหมอกลง มองไม่เห็นทาง แต่รู้สึกได้ว่าทิศไหน "ลาดชันลงมากที่สุด"

วิธี Gradient Descent: คำนวณทิศที่ "ชันขึ้น" (gradient) แล้วเดินสวนทาง → ลงเร็วที่สุด

ขนาดก้าว (α = learning rate): เล็กเกินไป = ช้า, ใหญ่เกินไป = กระโดดข้ามหุบเขา!

x(t+1) = x(t) - α × ∇f(x(t))
α = learning rate (ขนาดก้าว)
∇f = gradient (ทิศทางที่ f เพิ่มเร็วที่สุด) → เดินสวนทาง = ลดเร็วที่สุด
คำนวณ ∇f (gradient) → เดินสวนทาง (-α∇f) → Update x → ทำซ้ำ → |∇f|≈0 → หยุด

1โจทย์: Minimize f(x) = x² โดยใช้ Gradient Descent, α=0.3, เริ่มที่ x₀=4

2f'(x) = 2x    (gradient)

3Iteration 1: x₁ = 4 − 0.3×(2×4) = 4 − 2.4 = 1.6

4Iteration 2: x₂ = 1.6 − 0.3×(2×1.6) = 1.6 − 0.96 = 0.64

5Iteration 3: x₃ = 0.64 − 0.3×(2×0.64) = 0.64 − 0.384 = 0.256

6เข้าใกล้ 0 (คำตอบจริง) ทุก iteration! หลังหลาย iteration → x → 0

เชื่อมกับ Options

ใช้ Gradient Descent สำหรับ:
• Model Calibration: หา parameters ที่ทำให้ model price ≈ market price
• Volatility Surface Fitting: minimize ผลต่างระหว่าง model vol vs market vol

11.3 Lagrange Multipliers — Optimization ที่มี Constraints

อุปมา: เดินบนถนน (constraint) หาจุดที่สูงสุด

ถ้าต้องเดินอยู่บนถนน (constraint g=0) แต่อยากหาจุดที่ "สูงที่สุด" (maximize f)

จุด optimal คือจุดที่ "ทิศทางขึ้นสูง" ชี้ ตั้งฉากกับถนน — ถ้าไม่ตั้งฉาก แปลว่าเดินต่อบนถนนแล้วจะสูงขึ้นได้อีก!

Lagrange Multiplier (λ) = อัตราส่วนระหว่าง gradient ของ f กับ gradient ของ g ที่จุด optimal

หา min/max ของ f(x) ภายใต้เงื่อนไข g(x) = 0:

สร้าง Lagrangian: L(x, λ) = f(x) - λ × g(x)
แก้: ∂L/∂x = 0 และ ∂L/∂λ = 0 (= g(x) = 0)

เงื่อนไข: ∇f = λ∇g    (gradient ขนานกัน!)
λ = Lagrange multiplier = "ถ้าผ่อน constraint อีกนิด objective เปลี่ยนเท่าไหร่"

1Markowitz Problem: Minimize σ²_p = wᵀΣw s.t. wᵀμ = r* (target) และ wᵀ1 = 1

2Lagrangian: L = wᵀΣw − λ₁(wᵀμ − r*) − λ₂(wᵀ1 − 1)

3∂L/∂w = 0 → 2Σw − λ₁μ − λ₂1 = 0 → w* = Σ⁻¹(λ₁μ + λ₂1)/2

4ปรับ λ₁, λ₂ ให้ตรงกับ constraints → ได้ efficient portfolio!

5ทำสำหรับ r* ต่างๆ → ได้ Efficient Frontier (เส้นโค้ง risk vs return)

เชื่อมกับ Options — Markowitz Portfolio Optimization!

Minimize Portfolio Risk: σ²_p = wTΣw
Subject to: wTμ = target return, wT1 = 1

ใช้ Lagrange: L = wTΣw - λ₁(wTμ - r*) - λ₂(wT1 - 1)
→ หา Efficient Frontier (เส้นโค้งของ risk vs return ที่ดีที่สุด)

11.4 Convex Optimization

อุปมา: ชาม vs อาน

Convex function = รูปชาม → มีก้นชามเดียว ไม่ว่าเริ่มจากจุดไหน Gradient Descent จะหาก้นชามเจอ

Non-convex = รูปอาน (saddle) หรือภูมิประเทศขรุขระ → มีหลายหุบเขา อาจติดอยู่ที่ "หุบเขาเล็ก" ที่ไม่ใช่ที่ดีสุด

ข่าวดีสำหรับ Quant: Portfolio optimization (Markowitz) เป็น convex!

ทำไม Convex สำคัญ?

• Convex → มี minimum เดียว (global) → Gradient Descent จะหาเจอเสมอ ไม่ว่าเริ่มจากไหน
• Non-convex → มีหลาย local minimum → อาจติดอยู่ที่จุดที่ไม่ใช่ global minimum
• การตรวจสอบ: f convex ⟺ Hessian (matrix of second derivatives) เป็น PSD

ข่าวดี: Portfolio optimization (Markowitz) เป็น convex! → มีคำตอบเดียวที่ดีที่สุด

ข่าวร้าย: Calibration ของบาง model (เช่น Stochastic Volatility) เป็น non-convex → ต้องใช้เทคนิคพิเศษ

11.5 Quadratic Programming (QP)

ทำไม QP ถึงเป็น "ชั้นพิเศษ" ของ Nonlinear Optimization?

QP = objective เป็น quadratic (โค้งพาราโบลา) + constraints เป็น linear

นี่คือ "จุดกึ่งกลาง": ยากกว่า LP (เพราะ objective ไม่เส้นตรง) แต่ง่ายกว่า nonlinear ทั่วไป (เพราะ convex)

ข้อดี: มี solver ที่เร็วและแม่นยำ — แก้ Markowitz ได้ใน milliseconds!

Minimize ½xTQx + cTx
Subject to: Ax ≤ b
Q = 2Σ (Covariance) → objective = wᵀΣw → constraints = budget + return → QP Solver → Efficient Portfolio!
เชื่อมกับ Options

Mean-Variance Optimization ของ Markowitz เป็น QP พอดี!
Q = 2Σ (covariance matrix), c = 0 หรือ -μ
ใช้ QP solver ใน Python (cvxpy, scipy) แก้ได้ในเสี้ยววินาที → optimal portfolio weights!

1ตัวอย่าง QP 2 สินทรัพย์: หน้า 4, Σ = [[0.04, 0.01],[0.01, 0.09]], μ = [0.10, 0.15]

2Minimize wᵀΣw = w₁²(0.04) + 2w₁w₂(0.01) + w₂²(0.09)

3Subject to: w₁+w₂=1, 0.10w₁+0.15w₂ = 0.12 (target return)

4จาก constraints: w₂=0.4, w₁=0.6 (แก้ระบบเส้นตรง)

5σ²_p = 0.36(0.04)+2(0.24)(0.01)+0.16(0.09) = 0.0144+0.0048+0.0144 = 0.0336

6σ_p = √0.0336 ≈ 18.3% ← portfolio risk ที่ optimal สำหรับ return 12%

Maximize z = 3x₁ + 2x₂

หาทุก corner points และบอกว่า optimal solution คืออะไร?

ดูเฉลย

    z(4,2) = 3(4)+2(2) = 12+4 = 16 ← Maximum!

Optimal: x₁=4, x₂=2, z=16

โจทย์ 3: Gradient Descent Iterations

กำหนด f(x) = x² + 4x + 5, α = 0.1, เริ่มที่ x₀ = 3

คำนวณ 3 iterations ของ Gradient Descent แล้วบอกว่าเข้าใกล้คำตอบจริงไหม?

ดูเฉลย

f'(x) = 2x + 4

คำตอบจริง (f'=0): 2x+4=0 → x* = -2

Iteration 1: f'(3) = 2(3)+4 = 10 → x₁ = 3 − 0.1(10) = 2.0

Iteration 2: f'(2) = 2(2)+4 = 8 → x₂ = 2 − 0.1(8) = 1.2

Iteration 3: f'(1.2) = 2(1.2)+4 = 6.4 → x₃ = 1.2 − 0.1(6.4) = 0.56

เข้าใกล้ -2 ทุก iteration (3 → 2 → 1.2 → 0.56 → ... → -2)

ต้องใช้หลาย iterations เพิ่มเติม (เพราะ α เล็ก แต่เสถียร)
