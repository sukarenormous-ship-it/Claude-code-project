8.1 Stationary — เส้นแบ่งที่สำคัญที่สุดของบทนี้

🚶 อ่านเป็นภาษาคนก่อน: อนุกรม stationary (นิ่ง) คืออนุกรมที่ "หน้าตาเหมือนเดิมไม่ว่าจะดูช่วงไหน" — มีจุดยึดที่มันวนกลับมาหา และเหวี่ยงด้วยความกว้างพอ ๆ กันตลอด · ส่วนอนุกรม non-stationary (ไม่นิ่ง) คือพวกที่ลอยไปเรื่อย ๆ ไม่มีจุดยึด

อนุกรมลักษณะตัวอย่างในตลาดนิ่งไหม
White noiseวนรอบค่าเดิม ความกว้างคงที่ผลตอบแทนรายวัน (คร่าว ๆ)✅ นิ่ง
Random walkเดินสุ่มไปเรื่อย ไม่มีจุดยึดราคาหุ้น❌ ไม่นิ่ง
TrendลอยไปทิศเดียวชัดเจนGDP · ดัชนีระยะยาว❌ ไม่นิ่ง
✅ ทางแก้ที่ง่ายที่สุด — ทำ differencing

ราคาไม่นิ่ง แต่ ผลตอบแทน (ผลต่างของราคา) นิ่ง · นี่คือเหตุผลที่หนังสือทั้งเล่มทำงานกับ log return ไม่ใช่ราคา — ตั้งแต่เล่ม 1 Part I แล้ว

ราคา: S₁, S₂, S₃, … ← ไม่นิ่ง (random walk) ผลตอบแทน: ln(S₂/S₁), ln(S₃/S₂), … ← นิ่ง ✓ (นี่คือ "differencing")

📖 อ่านสูตรว่า: S₁, S₂, S₃ อ่านว่า "ราคาวันที่ 1, วันที่ 2, วันที่ 3" · กับดักการอ่าน: ในเล่มนี้ตัวห้อยคือเวลา ต่างจาก เล่ม 2·A ที่ตัวห้อย x₁, x₂ คือหมายเลขปัจจัย และต่างจาก EMA₁₂ ที่ตัวห้อยคือพารามิเตอร์ — ตัวห้อยตัวเดียวมีสามความหมายในคลังนี้ ต้องดูบริบทเสมอ · ln(S₂/S₁) อ่านว่า "ล็อกธรรมชาติของราคาวันที่ 2 หารราคาวันที่ 1" = ผลตอบแทนแบบล็อก ซึ่งใกล้เคียง (S₂ − S₁)/S₁ มากเมื่อการเปลี่ยนแปลงเล็ก · โครงที่ต้องเห็น: differencing คือการเปลี่ยนจาก "ระดับ" (S) ไปเป็น "การเปลี่ยนแปลงระหว่างจุดติดกัน" (ΔS หรือ Δln S) — จำนวนจุดจะหายไปหนึ่งจุด และตัว d ใน ARIMA(p, d, q) ของ §8.5 นับว่าทำขั้นนี้กี่ครั้ง

ใน ARIMA ตัวอักษร "I" (Integrated) ก็คือขั้นตอนนี้ — หาผลต่างเพื่อทำให้นิ่งก่อนสร้างโมเดล

8.2 ACF — ลายนิ้วมือของอนุกรม

🚶 อ่านเป็นภาษาคนก่อน: ACF (Autocorrelation Function) ตอบว่า "ค่าวันนี้เกี่ยวกับค่าเมื่อ k วันก่อนแค่ไหน" ไล่ทีละ k แล้วเอามาวางเป็นแท่ง · รูปร่างของแท่งพวกนี้บอกชนิดของอนุกรมได้ทันที

ส่วน random walk ที่ lag 8 ยังสัมพันธ์กับวันนี้ถึง 0.715 เพราะมันไม่เคยลืมอดีตเลย

❌ กับดัก: ACF ไม่ใช่ R²

เห็น 0.715 แล้วอย่าอ่านว่า "อธิบายวันนี้ได้ 72%" · ACF เป็นค่าสหสัมพันธ์ ไม่ใช่สัดส่วนความแปรปรวนที่อธิบายได้ · ต้องยกกำลังสองก่อน: 0.715² = 51% ต่างหาก

นี่คือกับดักตัวเดียวกับที่ เล่ม 2 · C บทที่ 6 เตือนไว้เรื่อง r กับ R² — มันกลับมาหลอกอีกครั้งในหน้าตาใหม่

8.3 ADF Test — ตัดสินด้วยตัวเลขแทนการเดา

🚶 อ่านเป็นภาษาคนก่อน: ดูกราฟแล้วเดาว่านิ่งหรือไม่นิ่งเป็นเรื่องอัตวิสัย · ADF test (Augmented Dickey-Fuller) ให้คำตอบเป็นตัวเลข · อ่านง่ายมาก — ดูแค่ค่าเดียวคือ p-value

p น้อย (< 0.05) → นิ่ง (stationary) ← ใช้ regression ได้ p มาก (> 0.05) → ไม่นิ่ง ← ต้อง difference ก่อน
💡 ทิศทางของ p ในการทดสอบนี้กลับกับที่คุ้นเคย

ปกติเราหวังให้ p น้อยเพื่อ "เจอบางอย่าง" · ที่นี่ p น้อยแปลว่า "ปฏิเสธสมมติฐานว่าไม่นิ่ง" = ยืนยันว่านิ่ง · จำง่าย ๆ: p น้อย = ข่าวดี = ทำงานต่อได้

🐍 Python — ADF test กับ 3 อนุกรม + differencing
# pip install statsmodels numpy
import numpy as np
from statsmodels.tsa.stattools import adfuller

rng = np.random.default_rng(42)
n = 200
white_noise = rng.normal(0, 1, n)                          # นิ่ง
random_walk = np.cumsum(rng.normal(0, 1, n))               # แบบราคาหุ้น
trend       = 0.05*np.arange(n) + rng.normal(0, 1, n)      # มีเทรนด์

for name, s in [("white noise", white_noise),
                ("random walk", random_walk),
                ("trend      ", trend)]:
    p = adfuller(s)[1]
    verdict = "นิ่ง ✓" if p < 0.05 else "ไม่นิ่ง ✗"
    print(f"{name}: p = {p:.4f}  → {verdict}")
# white noise: p = 0.0000  → นิ่ง ✓
# random walk: p = 0.5250  → ไม่นิ่ง ✗
# trend      : p = 0.6746  → ไม่นิ่ง ✗

# ★ ทางแก้ที่ 1 (สำหรับ unit root): หาผลต่าง แล้วทดสอบใหม่
print(f"\ndiff(random walk): p = {adfuller(np.diff(random_walk))[1]:.6f}  → นิ่งแล้ว ✓")
# diff(random walk): p = 0.000000  → นิ่งแล้ว ✓

# ★ ทางแก้ที่ 2 (สำหรับเทรนด์): บอก ADF ให้เผื่อเทรนด์ด้วย regression='ct'
print(f"trend ด้วย regression='ct': p = {adfuller(trend, regression='ct')[1]:.2e}")
# trend ด้วย regression='ct': p = 5.61e-20   ← นิ่งรอบเทรนด์ ✓
print(f"ถ้าดันไป difference: ACF lag1 = {np.corrcoef(np.diff(trend)[:-1], np.diff(trend)[1:])[0,1]:.3f}")
# ถ้าดันไป difference: ACF lag1 = -0.447   ← พังกว่าเดิม
✅ อ่านผลลัพธ์

random walk ได้ p = 0.5250 — ห่างจาก 0.05 ลิบลับ ยืนยันว่าไม่นิ่ง · แต่พอ differencing ครั้งเดียว p ร่วงเหลือ ~0 ทันที

❌ กับดักใหญ่: "ไม่นิ่ง" มี 2 แบบ และแก้คนละวิธี

สังเกตแถวสุดท้ายของผลลัพธ์แรก — trend ก็ได้ p = 0.6746 เหมือนกัน · แต่ มันเป็นคนละโรคกับ random walk โดยสิ้นเชิง

แบบหน้าตาตัวอย่างวิธีแก้ที่ถูก
Unit rootเดินสุ่ม ไม่มีจุดยึดราคาหุ้นdifference ✓
Trend-stationaryแกว่งรอบเส้นเทรนด์ที่ชัดเจนGDP · จำนวนประชากรถอดเทรนด์ออก หรือใช้ regression='ct'

อนุกรม trend ในโค้ดคือ 0.05×t + noise — ไม่มี unit root เลยแม้แต่นิดเดียว · มันแกว่งรอบเส้นตรงอย่างสงบ · ที่ ADF บอกว่า "ไม่นิ่ง" เพราะค่าปริยายของ adfuller คือ regression='c' ซึ่งเผื่อไว้แค่ค่าคงที่ ไม่เผื่อเทรนด์ · พอบอกให้มันเผื่อเทรนด์ด้วย p ร่วงเหลือ 5.6 × 10⁻²⁰ ทันที

และถ้าเชื่อกฎ "ไม่นิ่งก็ difference" แล้วลุยไปเลย จะได้อนุกรมที่ ACF ที่ lag 1 = −0.447 — ติดลบแรง · อาการนี้เรียกว่า over-differencing และมันจะทำให้ ARIMA ที่ฟิตทับลงไปพังหนักกว่าตอนไม่ทำอะไรเลย

💡 กฎที่ปลอดภัยกว่า: พล็อตกราฟดูด้วยตาก่อนเสมอ · ถ้าเห็นเส้นเทรนด์ชัด ๆ ให้ลอง regression='ct' ก่อน · จะ difference ก็ต่อเมื่อมันดู "ไร้ทิศทาง" แบบราคาหุ้นจริง ๆ

8.4 AR(1) — โมเดลที่ใช้อดีตของตัวเองทำนาย

AR(1) และ Mean Reversion Yule 1927 ★★★ ต้องรู้จัก

🎯 Thesis

"ค่าวันนี้ = สัดส่วนหนึ่งของค่าเมื่อวาน + ช็อกใหม่ · สัดส่วนนั้น (φ) ตัดสินทุกอย่าง — ถ้ามันน้อยกว่า 1 อนุกรมจะดึงตัวเองกลับหาค่าเฉลี่ยเสมอ"

🚶 อ่านเป็นภาษาคนก่อน: AR ย่อจาก AutoRegressive = "regression กับตัวเอง" · แทนที่จะใช้ตัวแปรอื่นทำนาย เราใช้อดีตของตัวมันเอง

xₜ = φ · xₜ₋₁ + εₜ |φ| < 1 → นิ่ง · ดึงกลับหาค่าเฉลี่ย (mean reversion) φ = 1 → random walk พอดี — ไม่มีแรงดึงกลับ ราคาหุ้นอยู่ตรงนี้ |φ| > 1 → ระเบิด (ไม่มีในธรรมชาติของราคา)

📖 อ่านสูตรว่า: "เอ็กซ์ ณ เวลาที เท่ากับ ฟี คูณ เอ็กซ์ ณ เวลาทีลบหนึ่ง บวก เอปไซลอน ณ เวลาที" · ตัวห้อย t และ t−1 คือ "วันนี้" กับ "เมื่อวาน" · φ (ฟี) เป็นพารามิเตอร์ตัวเดียวที่ไม่มีตัวห้อยเวลา = ค่าคงที่ของโมเดล · εₜ (เอปไซลอน) = ช็อกใหม่ของวันนี้ที่เมื่อวานยังไม่รู้ · โครงที่ต้องเห็น: สูตรอ้าง "ตัวมันเองเมื่อวาน" (recursive) โครงเดียวกับ EMA — จึงซ่อนทุกวันในอดีตไว้ด้วยน้ำหนัก φ, φ², φ³, … · อ่านอีกแบบที่ตำราขั้นสูงใช้: E[xₜ | xₜ₋₁] = φ·xₜ₋₁ — "ค่าคาดหวังของวันนี้ เมื่อรู้เมื่อวานแล้ว" ขีดตั้ง | อ่านว่า "given" ไม่ใช่การหาร นี่คือคำนิยามของโมเดลพยากรณ์ทุกตัว: มันคือ E[อนาคต | สิ่งที่รู้ตอนนี้] · กับดักการอ่าน: |φ| มีขีดตั้งสองข้างคือค่าสัมบูรณ์ (ทิ้งเครื่องหมาย) คนละตัวกับขีดตั้งเดี่ยวใน E[· | ·]

💎 φ = 1 คือเส้นแบ่งระหว่าง "เทรดได้" กับ "เทรดไม่ได้"

ดูสมการอีกครั้ง · ถ้า φ = 0.7 ค่าที่สูงผิดปกติจะถูกดึงกลับ 30% ทุกก้าว — แปลว่าคาดเดาได้ และเทรดได้ (ซื้อตอนต่ำ ขายตอนสูง) · แต่ถ้า φ = 1 ช็อกทุกตัวจะอยู่ถาวร ไม่มีแรงดึงกลับ — ทำนายทิศไม่ได้เลย

นี่คือเหตุผลเชิงคณิตศาสตร์ว่าทำไม ราคาหุ้นทำนายไม่ได้ แต่ spread ของคู่หุ้นที่ cointegrated ทำนายได้ — ตัวแรก φ ≈ 1 ตัวหลัง φ < 1 ชัดเจน · ทั้งบทที่ 9 สร้างอยู่บนความต่างข้อนี้ข้อเดียว

🐍 Python — สร้าง AR(1) แล้วให้โมเดลหา φ กลับมา
import numpy as np
from statsmodels.tsa.arima.model import ARIMA

rng = np.random.default_rng(9)
m = 300
x = np.zeros(m)
for t in range(1, m):
    x[t] = 0.7*x[t-1] + rng.normal(0, 1)      # φ จริง = 0.7

fit = ARIMA(x, order=(1,0,0)).fit()           # (p,d,q) = (1,0,0) = AR(1)
phi = fit.arparams[0]                         # ★ ใช้ .arparams ไม่ใช่ .params[1] (ดูกล่องข้างล่าง)
mu  = fit.params[0]                           # ค่าเฉลี่ยที่โมเดลฟิตได้
print(f"phi ที่ประมาณได้ = {phi:.4f}")             # phi ที่ประมาณได้ = 0.6888

fc = fit.forecast(6)                          # พยากรณ์ 6 ก้าวข้างหน้า
print("พยากรณ์:", " ".join(f"{v:.3f}" for v in fc))
# พยากรณ์: 0.478 0.343 0.250 0.185 0.141 0.110

# ★ อัตราการหดที่แท้จริง — ต้องวัดจาก "ระยะห่างจากค่าเฉลี่ย"
print("อัตราส่วนดิบ:      ", [round(float(fc[i+1]/fc[i]), 3) for i in range(5)])
# อัตราส่วนดิบ:       [0.717, 0.728, 0.742, 0.761, 0.784]   ← ไม่คงที่
print("วัดจากค่าเฉลี่ย:", [round(float((fc[i+1]-mu)/(fc[i]-mu)), 3) for i in range(5)])
# วัดจากค่าเฉลี่ย: [0.689, 0.689, 0.689, 0.689, 0.689]   ← = phi เป๊ะ
✅ อ่านผลลัพธ์ — พยากรณ์ค่อย ๆ ตายเข้าหาค่าเฉลี่ย

โมเดลหา φ = 0.6888 กลับมาได้ (ค่าจริง 0.70) ✓ · และดูค่าพยากรณ์: 0.478 → 0.343 → 0.250 → … แต่ละก้าวเหลือ ~69% ของก้าวก่อน (= หดลง 31%)

แปลว่ายิ่งพยากรณ์ไกล ยิ่งเข้าใกล้ค่าเฉลี่ย · นี่คือธรรมชาติของ AR ทุกตัว — มันไม่ได้ "รู้อนาคต" มันแค่รู้ว่าปัจจุบันจะจางกลับสู่ปกติเร็วแค่ไหน

❌ กับดัก 2 ข้อที่ทำให้อ่านตัวเลขนี้ผิด

1. "หดลง 69%" กับ "เหลือ 69%" ไม่เหมือนกัน · φ = 0.69 แปลว่าแต่ละก้าวเหลือ 69% (= หดลง 31%) · ถ้าอ่านว่า "หดลง 69%" คุณกำลังคิดว่า φ = 0.31 ซึ่งผิดไปคนละเรื่อง · ตลอดเล่มนี้ผมจะเขียนว่า "เหลือ X%" เสมอเพื่อไม่ให้สับสน

2. อัตราส่วนจะเท่ากับ φ เป๊ะ ก็ต่อเมื่อวัดจากระยะห่างจากค่าเฉลี่ย · ดูสองบรรทัดสุดท้ายของโค้ด — อัตราส่วนดิบ (0.717 → 0.784) ไม่คงที่และไม่เท่ากับ φ เพราะค่าเฉลี่ยที่โมเดลฟิตได้ไม่ใช่ศูนย์พอดี · แต่พอลบค่าเฉลี่ยออกก่อน จะได้ 0.689 เป๊ะทุกก้าว · สูตร AR พูดถึงส่วนเบี่ยงจากค่าเฉลี่ยเสมอ ไม่ใช่ค่าดิบ

(ก) φ̂ = 0.9572 ไม่ใช่ 0.98 — และนี่คือบทเรียนที่สำคัญที่สุดของข้อนี้ · ยิ่ง φ จริงใกล้ 1 การประมาณยิ่งเอนต่ำกว่าความจริงอย่างเป็นระบบ (เรียกว่า Kendall/Hurwicz bias) · มันไม่ใช่ความบังเอิญของ seed นี้ — มันเกิดเสมอ

(ข) เหลือ ~96% ต่อก้าว (วัดจากค่าเฉลี่ย) — แทบไม่ลดเลย เพราะแรงดึงกลับอ่อนมาก · ถ้าดูอัตราส่วนดิบจะเห็น 0.926 → 0.915 (เหลือ ~92%) ซึ่งต่างกันเพราะค่าเฉลี่ยที่ฟิตได้ไม่เป็นศูนย์ ตามกับดักข้อ 2 ข้างบน

8.4½ Ornstein-Uhlenbeck — AR(1) ตัวเดิม แต่ปล่อยให้เวลาไหลต่อเนื่อง

🚶 อ่านเป็นภาษาคนก่อน: AR(1) ข้างบนเดินทีละ "วัน" · แต่ราคาจริงไม่ได้กระโดดเป็นก้าว มันขยับตลอดเวลา · ถ้าเราหด Δt ลงจนเล็กจิ๋ว AR(1) จะกลายเป็นสมการเชิงอนุพันธ์สุ่มที่มีชื่อว่า Ornstein-Uhlenbeck (OU) · มันไม่ใช่โมเดลใหม่ — มันคือตัวเดิมในหน่วยเวลาต่อเนื่อง

AR(1) เวลาไม่ต่อเนื่อง: xₜ = φ·xₜ₋₁ + εₜ OU เวลาต่อเนื่อง: dx = θ·(μ − x)·dt + σ·dW

📖 อ่านสูตรว่า: "ดีเอ็กซ์ เท่ากับ ธีตา คูณ (มิว ลบ เอ็กซ์) ดีที บวก ซิกมา ดีดับเบิลยู" · d นำหน้าตัวแปรอ่านว่า "การเปลี่ยนแปลงจิ๋วของ…" — dx คือ x ขยับไปเท่าไรใน dt (ช่วงเวลาสั้นมาก) · dW คือ "ก้าวสุ่มจิ๋ว" ของการเดินแบบบราวน์ (เพื่อนเก่าจาก เล่ม 1 Part IV) ที่มีขนาดราว √dt · โครงที่ต้องเห็น: ทุกสมการรูป dx = (…)dt + (…)dW มีสองส่วนเสมอ — ส่วนหน้า dt คือแรงที่คาดเดาได้ (drift) ส่วนหน้า dW คือความสุ่ม · ตรงกับ AR(1) ที่แยกเป็น "φ·xₜ₋₁" กับ "εₜ" · อ่าน drift ให้จบประโยค: θ·(μ − x) = "ยิ่ง x อยู่ต่ำกว่า μ มาก แรงดึงขึ้นยิ่งมาก และกลับกัน" — เครื่องหมายของ (μ − x) คือทิศ θ คือความแรง · เทียบสองบรรทัดจะเห็นว่า φ = e−θΔt ≈ 1 − θΔt เมื่อ θΔt เล็ก: "แรงดึงกลับต่อก้าว" กับ "สัดส่วนที่เหลือจากเมื่อวาน" เป็นเลขตัวเดียวกันคนละมุม

อ่านสมการ OU เป็นภาษาคน: "ยิ่งอยู่ห่างจากค่ากลาง μ มาก ยิ่งถูกดึงกลับแรง" — เพราะพจน์แรกเป็นสัดส่วนกับระยะห่าง (μ − x) ตรง ๆ · θ คือความแรงของหนังยาง · ส่วน σdW คือช็อกสุ่มที่คอยดึงมันออกไป (Brownian motion จาก เล่ม 1 Part IV)

🐍 Python — เดิน OU แล้วถอด θ กลับมาด้วย AR(1)
# pip install numpy
import numpy as np, math

def ou_exact(theta, sigma, mu, dt, n, seed):
    """เดิน OU แบบเป๊ะ — ทำได้เพราะ OU มีคำตอบปิด"""
    phi = math.exp(-theta*dt)                              # ★ นี่คือ phi ของ AR(1) พอดี
    s   = sigma*math.sqrt((1 - math.exp(-2*theta*dt))/(2*theta))
    rng = np.random.default_rng(seed); z = rng.standard_normal(n)
    x = np.empty(n); x[0] = mu
    for t in range(1, n):
        x[t] = mu + (x[t-1] - mu)*phi + s*z[t]
    return x

def fit_phi(x):                                            # ฟิต AR(1) ด้วย OLS ธรรมดา
    a, b = x[:-1], x[1:]
    return float(((a-a.mean())*(b-b.mean())).sum() / ((a-a.mean())**2).sum())

theta, sigma, dt = 0.10, 0.02, 1.0                         # theta ต่อวัน
x = ou_exact(theta, sigma, 0.0, dt, 200_000, seed=5)
phi_hat = fit_phi(x)
print("ข้อมูลยาวมาก (200,000 วัน) — ยืนยันว่าการจับคู่เป็นจริง")
print(f"  phi        exp(-theta*dt)     = {math.exp(-theta*dt):.4f}   ฟิตได้ = {phi_hat:.4f}")
print(f"  ครึ่งชีวิต  ln2/theta          = {math.log(2)/theta:.2f} วัน   -ln2/ln(phi) = {-math.log(2)/math.log(phi_hat):.2f} วัน")
print(f"  SD คงตัว   sigma/sqrt(2theta) = {sigma/math.sqrt(2*theta):.4f}   วัดได้ = {x.std():.4f}")

hl = np.array([-math.log(2)/math.log(fit_phi(ou_exact(theta, sigma, 0.0, dt, 250, seed=s)))
               for s in range(200)])
print("\nข้อมูลจริง 1 ปี (250 วัน) — ครึ่งชีวิตที่วัดได้เหวี่ยงแค่ไหน")
print(f"  ความจริง {math.log(2)/theta:.2f} วัน | ค่ากลางที่วัดได้ {np.median(hl):.2f} | "
      f"ช่วง 5-95% [{np.percentile(hl,5):.2f}, {np.percentile(hl,95):.2f}] วัน")

rng = np.random.default_rng(1); n = 500_000               # ถ้าเดินด้วย Euler แทนที่จะเป๊ะ
z = rng.standard_normal(n); e = np.empty(n); e[0] = 0.0
for t in range(1, n):
    e[t] = (1 - theta*dt)*e[t-1] + sigma*math.sqrt(dt)*z[t]
print(f"\nเดินด้วย Euler-Maruyama แทน: SD คงตัว = {e.std():.4f} "
      f"(สูงกว่าค่าจริง {e.std()/(sigma/math.sqrt(2*theta))-1:+.2%})")

#   phi        exp(-theta*dt)     = 0.9048   ฟิตได้ = 0.9038

#   SD คงตัว   sigma/sqrt(2theta) = 0.0447   วัดได้ = 0.0446

8.5 MA · ARIMA — ต่อจิ๊กซอว์ให้ครบ

🚶 อ่านเป็นภาษาคนก่อน: AR ใช้ "ค่าในอดีต" ทำนาย · MA (Moving Average) ใช้ "ความผิดพลาดในอดีต" ทำนาย · เอามารวมกันได้ ARMA · เติมขั้นตอน differencing เข้าไปได้ ARIMA ซึ่งเป็นชื่อที่เจอบ่อยที่สุด

❌ ระวังชื่อซ้ำ: MA ตัวนี้ ไม่ใช่ เส้น MA50 / MA200 ที่คุณเห็นในกราฟเทรด

นี่น่าจะเป็นจุดที่สับสนง่ายที่สุดในบทนี้ เพราะคนไทยที่เทรดหุ้นเห็นคำว่า "MA" มาก่อนแล้วแทบทุกคน

🔬 เจาะลึก (ข้ามได้) — เลือก p กับ q ยังไง

วิธีคลาสสิกคือดูรูป ACF/PACF (Partial ACF = ความสัมพันธ์ระหว่างวันนี้กับ lag k หลังหักอิทธิพลของ lag 1…k−1 ออกหมดแล้ว · ถ้า ACF ค่อย ๆ จางแต่ PACF ตัดจบที่ lag p ทันที แปลว่าเป็น AR(p) — ถ้ากลับกันเป็น MA(q)) · แต่ในทางปฏิบัติคนนิยมลองหลายชุดแล้วเลือกด้วย AIC (ตัวเลขที่ยิ่งต่ำยิ่งดี ซึ่งหักค่าปรับตามจำนวนพารามิเตอร์ — แนวคิดเดียวกับ adjusted R² ในบทที่ 6) · และต้องยืนยันด้วย out-of-sample เสมอ ไม่เชื่อ AIC อย่างเดียว

8.6 ❌ ความจริงที่ต้องพูด — ARIMA พยากรณ์ราคาหุ้นไม่ได้

ถึงตรงนี้อาจคิดว่า "มีโมเดลพยากรณ์อนุกรมเวลาแล้ว เอาไปทำนายราคาหุ้นเลยสิ" · มันไม่ทำงาน และเหตุผลอยู่ในสิ่งที่เราเพิ่งเรียนไปทั้งหมด

❌ ทำไมถึงไม่ได้ผล
  • ราคาหุ้นคือ ARIMA(0,1,0) — random walk เกือบสมบูรณ์ · ทำ differencing แล้วเหลือ "ผลตอบแทน" ที่มี ACF ≈ 0 ทุก lag (เล่ม 1 Part IV §8.2 วัดไว้แล้ว) · ไม่มีโครงสร้างให้โมเดลจับ
  • พยากรณ์ที่ดีที่สุดของ random walk คือ "ราคาวันนี้" — ARIMA จะบอกแบบนั้นเป๊ะ ๆ ซึ่งถูกต้องแต่ไร้ประโยชน์ในการเทรด
  • ถ้า ARIMA พยากรณ์ทิศทางราคาได้จริง คนจะเทรดจนช่องว่างหายไปทันที — ตลาดที่มีสภาพคล่องจะไม่ยอมให้มีของฟรีแบบนี้ค้างอยู่
✅ แล้ว ARIMA ใช้กับอะไรได้จริงในการเงิน
  • สิ่งที่ mean-revert จริง ๆ — spread ของคู่ที่ cointegrated (บทที่ 9), ส่วนต่างอัตราดอกเบี้ย, basis ของ futures
  • ความผันผวน ไม่ใช่ทิศทาง — σ มี autocorrelation สูงจริง (volatility clustering) · GARCH ในเล่ม 1 Part IV คือญาติของ ARIMA ที่ทำงานกับ variance
  • ปริมาณและสภาพคล่อง — volume มีรูปแบบตามฤดูกาลชัดเจน

ข้อสรุป: อย่าใช้ ARIMA ทำนายว่าราคาจะขึ้นหรือลง · ใช้กับสิ่งที่มีจุดยึดให้ดึงกลับ

🧠 มุมที่มองต่าง — "ทำนายไม่ได้" ไม่ได้แปลว่า "ทำอะไรไม่ได้"

มือใหม่เห็น: "ถ้าทำนายราคาไม่ได้ ก็เทรดไม่ได้สิ"
คนในตลาดเห็น: เงินส่วนใหญ่ไม่ได้มาจากการทายทิศ แต่มาจาก ความสัมพันธ์ที่ mean-revert (pairs, basis, spread), การขายความผันผวน (เล่ม 1 Part IV) และ การจัดพอร์ต (เล่ม 2 · A/B) · ทั้งสามอย่างไม่ต้องรู้ว่าพรุ่งนี้ตลาดขึ้นหรือลงเลย

  • เช็ค stationary ก่อนเสมอ — ADF p < 0.05 = นิ่ง = ทำงานต่อได้ · ไม่นิ่งให้ difference
  • ACF ที่ลดช้ามาก = สัญญาณอนุกรมไม่นิ่ง (random walk ที่ lag 8 ยังสูง 0.72)
  • φ = 1 คือเส้นแบ่ง — φ < 1 ดึงกลับหาค่าเฉลี่ย (เทรดได้) · φ = 1 คือราคาหุ้น (ทายทิศไม่ได้)
  • AR(1) กับ Ornstein-Uhlenbeck คือตัวเดียวกัน — φ = e−θΔt · ครึ่งชีวิต ln2/θ · แต่ที่ข้อมูล 1 ปี ครึ่งชีวิตที่วัดได้ต่ำกว่าความจริง 14% และเหวี่ยงได้ตั้งแต่ 3.6 ถึง 9.0 วัน — อย่าตั้งกฎที่ไวต่อครึ่งชีวิตระดับวันเดียว

📖 อ่านต่อ — บทที่ 9: Cointegration → Pairs Trading

บทที่ 9 จะตอบว่า regression บนอนุกรมที่ไม่นิ่งใช้ได้เมื่อไร — เมื่อ residual ของมันนิ่ง · กรณีพิเศษนั้นเรียกว่า cointegration และเป็นฐานของกลยุทธ์ pairs trading ที่จะสร้างกันตั้งแต่ต้นจนจบ พร้อม backtest

บทที่ 9: Cointegration → Pairs Trading

บทที่ 8 จบด้วยข่าวร้าย: ราคาหุ้นไม่นิ่ง เอามา regress กันตรง ๆ ได้ผลลวง · บทนี้คือข้อยกเว้น — กรณีเดียวที่ regression บนราคาที่ไม่นิ่งใช้ได้จริง และมันกลายเป็นกลยุทธ์เทรดที่ใช้กันจริงมาตั้งแต่ยุค 1980

9.1 Cointegration — สองคนเมาที่จูงหมาไว้ด้วยกัน

🚶 อ่านเป็นภาษาคนก่อน: มีอุปมาคลาสสิกเรื่องนี้ · คนเมาเดินเซสุ่มไปเรื่อย ทำนายไม่ได้ว่าจะไปทางไหน (= random walk) · คนเมาสองคนเดินแยกกัน ระยะห่างก็สุ่มไปเรื่อยเช่นกัน · แต่ถ้าสองคนนั้นจูงเชือกเส้นเดียวกันไว้ — แต่ละคนยังเดินเซทำนายไม่ได้เหมือนเดิม แต่ "ระยะห่าง" ระหว่างเขาจะถูกดึงกลับเสมอ · คำว่า arbitrage ใน statistical arbitrage ที่กลยุทธ์นี้สังกัดอยู่ เป็นคำกล่าวเชิงลิมิต (โอกาสขาดทุน → 0 เมื่อถือนานพอ) ไม่ใช่การันตี — Arbitrage เล่ม 1 §1.5 นิยามและเดินเลขให้ว่าที่ T จำกัดเหลือโอกาสขาดทุนเท่าไร

A ไม่นิ่ง (random walk) B ไม่นิ่ง (random walk) แต่ B − β·A นิ่ง → A กับ B cointegrated

📖 อ่านสูตรว่า: "บี ลบ เบต้าคูณเอ" = ถือ B หนึ่งหน่วย และ short A จำนวน β หน่วย — สูตรนี้คือพอร์ต ไม่ใช่แค่สมการ · β ตัวนี้มาจาก regression ของ B บน A (โครง Cov/Var ของ เล่ม 2·A) จึงเรียกว่า hedge ratio และเป็นตัวเดียวกับ 1.51 ในคำสั่งเทรดของ §9.2 · โครงที่ต้องเห็น: "ผลรวมเชิงเส้น" (linear combination) ของสองอนุกรมที่ไม่นิ่ง อาจนิ่งได้ — คำว่า cointegrated จึงไม่ได้พูดถึง A หรือ B ตัวใดตัวหนึ่ง แต่พูดถึงส่วนต่างที่ถ่วงน้ำหนักแล้ว · ค่าของสูตรนี้ในแต่ละวันคือ spread ที่ทั้งบทที่ 9 จะทดสอบ (ADF/coint) วัดครึ่งชีวิต และแปลงเป็น z-score

ความหมายในตลาด: หุ้นสองตัวที่ขับเคลื่อนด้วยปัจจัยพื้นฐานเดียวกัน (ธนาคารสองแห่ง · สายการบินสองสาย · โรงกลั่นสองโรง) ราคาต่างก็เดินสุ่ม แต่ส่วนต่างของมันมีจุดยึด — เมื่อถ่างผิดปกติ มันมักหุบกลับ

🧮 ทดสอบด้วย 3 ขั้น (Engle-Granger)
  1. ยืนยันว่าทั้งคู่เป็น I(1) — ADF ของราคา A และ B ต้องได้ p > 0.05 ทั้งคู่ (ไม่นิ่ง) และ ADF ของ ผลต่าง ทั้งคู่ต้องได้ p < 0.05 (นิ่ง) · ครบสองเงื่อนไขถึงเรียกว่า I(1)
  2. Regress B บน A → ได้ β (นี่คือ hedge ratio) และ residual ซึ่งเราจะเรียกว่า spread
  3. ทดสอบว่า spread นิ่งไหม — ด้วย coint() ไม่ใช่ adfuller() · ถ้า p < 0.05 แปลว่า cointegrated ✓

ขั้นที่ 3 คือหัวใจ · มันคือความต่างเดียวระหว่าง "ความสัมพันธ์จริง" กับ "spurious regression" ในบทเปิด — ของจริง residual จะนิ่ง ของปลอมจะไม่นิ่ง

🚶 ก่อนไปต่อ — "spread" ในบทนี้คืออะไรกันแน่: มันไม่ใช่สเปรด bid-ask ที่คุณเห็นในหน้าจอเทรด · spread ในบทนี้คือ residual จากบทที่ 6 นั่นเอง — "ส่วนที่ regression อธิบายไม่ได้" · ซึ่งในบริบทนี้แปลตรง ๆ ได้ว่า "ตอนนี้ B แพงหรือถูกกว่าที่ควรจะเป็นอยู่เท่าไร" · นั่นคือสิ่งที่เราจะเอาไปเทรด

❌ กับดักที่นักวิเคราะห์มืออาชีพยังพลาด: adfuller บน residual ใช้ตารางผิด

วิธีที่คนเขียนกันเกลื่อนอินเทอร์เน็ตคือ adfuller(spread) ตรง ๆ · มันผิด และผิดในทิศที่อันตราย

เหตุผล: spread ไม่ใช่ข้อมูลที่หล่นมาจากฟ้า — เราเลือก β มาเพื่อให้มันนิ่งที่สุดเท่าที่จะทำได้อยู่แล้ว (นั่นคือสิ่งที่ least squares ทำ) · มันจึงดู "นิ่ง" กว่าความจริงโดยกลไก · ตาราง Dickey-Fuller มาตรฐานไม่ได้เผื่อเรื่องนี้ไว้ ต้องใช้ตารางของ MacKinnon สำหรับ cointegration ซึ่งเข้มกว่า

# pip install statsmodels numpy
import numpy as np
from statsmodels.tsa.stattools import adfuller, coint
from statsmodels.tsa.arima.model import ARIMA

rng = np.random.default_rng(0)
n = 500
A = 100 + np.cumsum(rng.normal(0, 1, n))          # หุ้น A: random walk
B = 5.0 + 1.5*A + rng.normal(0, 2, n)             # หุ้น B: ผูกกับ A (beta จริง = 1.5)

# ขั้น 1 — ทั้งคู่ต้องเป็น I(1): ราคาไม่นิ่ง แต่ผลต่างนิ่ง
print(f"ADF ราคา A = {adfuller(A)[1]:.3f}   | ADF diff(A) = {adfuller(np.diff(A))[1]:.1e}")
# ADF ราคา A = 0.725   | ADF diff(A) = 0.0e+00   ← ไม่นิ่ง แต่ diff นิ่ง = I(1) ✓
print(f"ADF ราคา B = {adfuller(B)[1]:.3f}   | ADF diff(B) = {adfuller(np.diff(B))[1]:.1e}")
# ADF ราคา B = 0.660   | ADF diff(B) = 0.0e+00   ← I(1) ✓

# ขั้น 2 — regress B บน A ได้ hedge ratio + spread
beta, alpha = np.polyfit(A, B, 1)
spread = B - (alpha + beta*A)
print(f"hedge ratio beta = {beta:.4f}")            # hedge ratio beta = 1.5068

# ขั้น 3 — ★ ใช้ coint() ไม่ใช่ adfuller() (ดูกล่องกับดักข้างบน)
t_stat, p_val, crit = coint(B, A)
print(f"coint: t = {t_stat:.2f} | ค่าวิกฤต 5% = {crit[1]:.3f} | p = {p_val:.4f}")
# coint: t = -21.62 | ค่าวิกฤต 5% = -3.348 | p = 0.0000
print("cointegrated ✓" if t_stat < crit[1] else "ไม่ cointegrated ✗")
# cointegrated ✓

# เทียบให้เห็นว่าวิธีผิดใช้เกณฑ์หลวมกว่าแค่ไหน
print(f"(ถ้าใช้ adfuller: ค่าวิกฤต 5% = {adfuller(spread)[4]['5%']:.3f} — หลวมกว่า)")
# (ถ้าใช้ adfuller: ค่าวิกฤต 5% = -2.867 — หลวมกว่า)

# ★ ตัวเลขที่สำคัญที่สุดแต่คนมักลืม: ครึ่งชีวิตของการกลับตัว
phi = ARIMA(spread, order=(1,0,0)).fit().arparams[0]
print(f"spread phi = {phi:.4f} → ครึ่งชีวิต = {-np.log(2)/np.log(abs(phi)):.2f} วัน")
# spread phi = 0.0339 → ครึ่งชีวิต = 0.20 วัน   ← สั้นจนเป็นไปไม่ได้ในโลกจริง

🚶 อ่านเป็นภาษาคนก่อน: §9.1 หา β ด้วย OLS แล้วล็อกไว้ราวกับเป็นตัวเลขเดียวที่มีอยู่ · ความจริง β ของคู่เดียวกันมีหลายตัว ขึ้นกับว่าคุณสั่งให้เครื่องมือย่ออะไร: OLS ย่อระยะแนวตั้ง (ความผิดพลาดอยู่ที่ B เท่านั้น) · สลับข้างแล้ว OLS ย่อระยะแนวนอน · TLS ย่อระยะตั้งฉาก (ทั้งสองขาผิดพลาดได้) · Box-Tiao เลือกน้ำหนักให้ spread ที่ได้กลับตัวเร็วที่สุด · เมื่อความสัมพันธ์แน่นมาก ทุกวิธีให้เลขเกือบเท่ากันและคุณจะไม่รู้ว่ามีปัญหา · เมื่อราคามี noise จากตลาด (bid-ask, ราคาปิดที่กระตุก) วิธีเหล่านี้แยกกันคนละทาง และ OLS จะต่ำกว่าจริงเสมออย่างเป็นระบบ

OLS (B บน A): β = Cov(A, B) / Var(A) ย่อ Σ(B − βA)² — สมมติ A ไม่มี noise OLS สลับ (A บน B): β = Var(B) / Cov(A, B) ย่อ Σ(A − B/β)² — สมมติ B ไม่มี noise TLS: β = ความชันของ eigenvector ตัวแรกของ covariance [A, B] ย่อระยะตั้งฉาก — noise เท่ากันสองขา Box-Tiao / min half-life: เลือก β ที่ทำให้ spread = B − βA มี φ² ต่ำสุด (ทำนายได้น้อยสุด = กลับตัวเร็วสุด) เมื่อ A ที่เห็น = A จริง + noise (variance σ²_u): E[β̂_OLS] ≈ β × Var(A จริง) / (Var(A จริง) + σ²_u) < β

📖 อ่านสูตรว่า: บรรทัดแรกคือสูตร Cov/Var ของ 2 · A §2.1 ตัวเดิม · บรรทัดสองสลับตัวแปรแล้วกลับเศษส่วน — ถ้าข้อมูลไม่มี noise เลย สองบรรทัดนี้ให้ค่าเท่ากัน ต่างกันเมื่อไรแปลว่ามี noise · บรรทัดสุดท้ายอ่านว่า "ค่าคาดหวังของเบต้าหมวก ประมาณ เบต้า คูณ แวเรียนซ์ของเอจริง หารด้วย แวเรียนซ์ของเอจริง บวก ซิกมากำลังสองยู" — σ²u คือ variance ของ noise ที่ทับราคา A · โครงที่ต้องเห็น: บรรทัดสุดท้ายคือ "การลดทอน" (attenuation) — ตัวคูณ Var/(Var + σ²u) น้อยกว่า 1 เสมอ OLS จึงประเมิน β ต่ำไป และต่ำลงตามสัดส่วนของ noise ต่อการเคลื่อนไหวจริงของ A · ถ้า noise เท่ากับการเคลื่อนไหวจริงพอดี β̂ เหลือครึ่งเดียว · กับดักการอ่าน: TLS ใช้ eigenvector ตัวเดียวกับ PCA ของ 2 · A §1.4 — สองสินทรัพย์ PC1 ก็คือเส้นที่ผ่านกลุ่มจุดโดยระยะตั้งฉากน้อยสุด · Box-Tiao ในสองสินทรัพย์ลดเหลือการค้น β ตัวเดียวที่ทำให้ φ² ต่ำสุด แต่ระวัง: มันเลือก β จากสิ่งที่คุณจะเอาไปเทรด (ความเร็วการกลับตัว) จึงเป็นการจูนในตัวอย่างโดยนิยาม

สี่ตัวเลขนี้ตอบคนละคำถาม: β ราคาตอบ "ถือกี่หุ้น" · β return ตอบ "ถือกี่บาท" (อัตราส่วนมูลค่าเงิน 0.75 บาท A ต่อ 1 บาท B — ไม่ใช่ dollar-neutral ซึ่งคือ 1 ต่อ 1) แล้วต้องหารด้วยราคาเอง · β log ตอบความยืดหยุ่น · การเอา β จาก return ไปใช้เป็นจำนวนหุ้นตรง ๆ (0.75 หุ้น A ต่อ 1 หุ้น B แทนที่จะเป็น 1.51) คือความผิดพลาดที่พบบ่อยที่สุดในโค้ด pairs ของมือใหม่ และมันไม่มีทางถูกจับได้จาก R² เพราะ regression แต่ละแบบก็ fit ดีในหน่วยของตัวเอง

✅ เลือกวิธีไหน
  • hedge กับดัชนีหรือ futures ที่สภาพคล่องสูง → OLS พอ เพราะตัวแปรทางขวาแทบไม่มี noise · นี่คือกรณีของ β ใน 2 · A §2.1
  • คู่หุ้นสองตัวที่ noise พอกัน → TLS หรือค่ากลางของสอง OLS · และรายงานทั้งสอง OLS เป็นช่วง ไม่ใช่รายงานตัวเดียว
  • ตะกร้าที่ต้องการ spread กลับตัวเร็วสุด → Box-Tiao หรือ min half-life แต่ต้องแบ่งข้อมูล: เลือก β จากช่วงแรก วัดครึ่งชีวิตในช่วงหลัง มิฉะนั้นครึ่งชีวิตที่รายงานคือครึ่งชีวิตที่จูนแล้ว (บทเรียนของ 2 · F §12.5)
  • ทุกกรณี — ระบุหน่วยของ β ก่อนแปลงเป็นจำนวนหุ้น และ β ทุกตัวมีช่วงความเชื่อมั่น (2 · C §6.4) ไม่ใช่ตัวเลขเดียว

9.2 จาก spread สู่สัญญาณเทรด — z-score

🚶 อ่านเป็นภาษาคนก่อน: spread นิ่งแล้ว แต่หน่วยของมันอ่านยาก (บาท? จุด?) · แปลงเป็น z-score ให้อ่านง่าย — "ตอนนี้ spread ห่างจากค่าเฉลี่ยกี่เท่าของส่วนเบี่ยงเบนมาตรฐาน" ซึ่งเป็นเครื่องมือเดียวกับที่เรียนใน เล่ม 1 Part II

z = (spread − ค่าเฉลี่ยของ spread) / ส่วนเบี่ยงเบนมาตรฐานของ spread z = +2 → spread กว้างผิดปกติ → ขาย spread = short B 1 หน่วย + long A 1.51 หน่วย z = −2 → spread แคบผิดปกติ → ซื้อ spread = long B 1 หน่วย + short A 1.51 หน่วย z ≈ 0 → กลับสู่ปกติ → ปิดสถานะทั้งสองขา

📖 อ่านสูตรว่า: "ซี เท่ากับ สเปรดวันนี้ ลบ ค่าเฉลี่ยของสเปรด หารด้วย เอสดีของสเปรด" · โครงที่ต้องเห็น: เศษและส่วนเป็นหน่วยเดียวกัน (บาท) หารกันแล้วหน่วยหาย — z จึงอ่านว่า "วันนี้ห่างจากปกติกี่ SD" เป็นโครง "ค่า ลบ จุดอ้างอิง หารด้วย สเกล" · กับดักการอ่าน: โครงนี้หน้าตาเหมือน t = β̂/SE ใน เล่ม 2·C และเหมือน Sharpe = (R − r_f)/σ ใน เล่ม 2·E เป๊ะ แต่ตอบคนละคำถาม — z ถามว่า "วันนี้อยู่ตรงไหนในประวัติของตัวเอง" t ถามว่า "ค่าประมาณห่างจากศูนย์กี่เท่าของความไม่แน่นอน" Sharpe ถามว่า "ได้ผลตอบแทนเท่าไรต่อความเสี่ยง 1 หน่วย" · รูปเดียวกันไม่ได้แปลว่าความหมายเดียวกัน ให้ดูว่าอะไรอยู่ในเศษ · เลข 2 ที่เป็นเกณฑ์เข้าไม่ได้มาจากทฤษฎีของ spread ตัวนี้ แต่มาจากธรรมเนียม "2 SD" ของโค้งปกติ — spread ที่หางหนากว่านั้นจะทะลุ ±2 บ่อยกว่าที่ 4.6% สัญญาไว้

❌ อย่าลืม β ในคำสั่งเทรด

ทิศทางถูกอย่างเดียวไม่พอ — จำนวนต้องถ่วงด้วย hedge ratio เสมอ · ถ้าเทรด 1:1 (short B 1 หุ้น long A 1 หุ้น) คุณจะเหลือ exposure ทิศทางตลาดค้างอยู่ ซึ่งเป็นสิ่งเดียวที่กลยุทธ์นี้มีไว้เพื่อกำจัด · ตัวเลข 1.51 มาจาก β = 1.5068 ที่คำนวณได้ใน §9.1

❌ อ่านก่อนดูตัวเลข — ข้อมูลชุดนี้ปลอม และปลอมในทางที่เข้าข้างกลยุทธ์

ผมสร้างข้อมูลให้ cointegrated จริงตั้งแต่ต้น · ที่แย่กว่านั้น: B = 5.0 + 1.5*A + noise ทำให้ spread เป็น noise อิสระล้วน ๆ ไม่จำอดีตเลย (ACF ทุก lag ≈ 0 · ครึ่งชีวิต 0.2 วัน ตามที่เห็นใน §9.1)

ผลที่ตามมาคือ ทุกไม้ที่เปิดจะปิดด้วยกำไรเสมอโดยโครงสร้าง — เข้าเมื่อ |z|>2 ออกเมื่อ |z|<0.5 ไม่มี stop ไม่มีเวลาจำกัด · ทางเดียวที่จะขาดทุนคือไม้ที่ไม่มีวันปิด ซึ่งข้อมูลแบบนี้ทำให้เกิดไม่ได้

ดูตัวเลขข้างล่างในฐานะ "กลไกทำงานยังไง" เท่านั้น ห้ามดูในฐานะ "กลยุทธ์นี้ทำเงินได้เท่าไร" · ผลลัพธ์จริงอยู่ในตารางถัดจากนี้

🐍 Python — สร้างสัญญาณ + backtest ง่าย ๆ
# pip install statsmodels numpy
import numpy as np

rng = np.random.default_rng(0)
n = 500
A = 100 + np.cumsum(rng.normal(0, 1, n))
B = 5.0 + 1.5*A + rng.normal(0, 2, n)
beta, alpha = np.polyfit(A, B, 1)
spread = B - (alpha + beta*A)
z = (spread - spread.mean()) / spread.std()       # ★ แปลงเป็น z-score

print(f"z อยู่ระหว่าง {z.min():.2f} ถึง {z.max():.2f}")
# z อยู่ระหว่าง -3.04 ถึง 2.76
print(f"วันที่ |z| > 2 = {(abs(z) > 2).sum()} วัน จาก {n}")
# วันที่ |z| > 2 = 22 วัน จาก 500

# --- backtest: เข้าเมื่อ |z|>2 ออกเมื่อ z กลับเข้าใกล้ 0 · stop ที่ |z|>4 ---
pos, pnl, trades, stops = 0, 0.0, 0, 0
closed, holds, hold = [], [], 0
for i in range(1, n):
    if pos == 0:
        if   z[i] >  2: pos, entry, trades, hold = -1, spread[i], trades+1, 0   # ขาย spread
        elif z[i] < -2: pos, entry, trades, hold = +1, spread[i], trades+1, 0   # ซื้อ spread
    else:
        hold += 1
        if abs(z[i]) > 4:                                              # ★ stop loss
            p = pos*(spread[i]-entry); pnl += p; closed.append(p)
            holds.append(hold); pos = 0; stops += 1
        elif (pos == -1 and z[i] <  0.5) or (pos == 1 and z[i] > -0.5):
            p = pos*(spread[i]-entry); pnl += p; closed.append(p)       # ปิดปกติ
            holds.append(hold); pos = 0

print(f"เทรดทั้งหมด {trades} ครั้ง  กำไรรวม {pnl:.1f} (หน่วยของ spread)")
# เทรดทั้งหมด 21 ครั้ง  กำไรรวม 113.7 (หน่วยของ spread)
print(f"เฉลี่ยต่อเทรด {pnl/len(closed):.2f}  (sd ของ spread = {spread.std():.2f})")
# เฉลี่ยต่อเทรด 5.41  (sd ของ spread = 1.88)

# ★★ ใบรายงานผลที่ซื่อสัตย์ — ตัวเลขที่ backtest ส่วนใหญ่ไม่ยอมพิมพ์
eq = np.cumsum([0.0] + closed)
dd = eq - np.maximum.accumulate(eq)
print(f"ชนะ {sum(1 for p in closed if p > 0)}/{len(closed)} ไม้ | ไม้แย่สุด {min(closed):+.2f}")
# ชนะ 21/21 ไม้ | ไม้แย่สุด +3.07
print(f"drawdown ลึกสุด {dd.min():.2f} | ถือเฉลี่ย {np.mean(holds):.2f} วัน | โดน stop {stops} ครั้ง")
# drawdown ลึกสุด 0.00 | ถือเฉลี่ย 1.24 วัน | โดน stop 0 ครั้ง
print(f"ค้างสถานะตอนจบ: {'มี' if pos else 'ไม่มี'}")
# ค้างสถานะตอนจบ: ไม่มี
❌ ใบรายงานผลนี้คือหลักฐานว่าข้อมูลปลอม ไม่ใช่หลักฐานว่ากลยุทธ์ดี

ดูสามบรรทัดสุดท้ายให้ดี · ชนะ 21 จาก 21 ไม้ · ไม้ที่แย่ที่สุดยัง +3.07 · drawdown ลึกสุด = 0.00

ตัวเลขชุดนี้เป็นไปไม่ได้ในโลกจริง · ถ้าคุณเห็น backtest ของใครแล้วมันหน้าตาแบบนี้ — ไม่ว่าจะกลยุทธ์อะไร — สิ่งแรกที่ต้องสงสัยคือข้อมูลหรือกฎการทดสอบมีอะไรผิด ไม่ใช่ "เจอขุมทรัพย์แล้ว"

และสังเกต "โดน stop 0 ครั้ง" · ผมใส่ stop ที่ |z| > 4 ไว้แล้ว แต่บนข้อมูลนี้มันไม่เคยทำงานเลยแม้แต่ครั้งเดียว · ในโลกจริงมันคือสิ่งเดียวที่กันคุณจากการล้างพอร์ต (ดู §9.3)

ถือเฉลี่ยแค่ 1.24 วัน ก็ควรจุดสัญญาณเตือนเช่นกัน — คู่หุ้นจริงถือกัน 5–30 วัน · 1.24 วันคือลายเซ็นของ spread ที่ไม่มีความจำ

❌ บั๊กที่ซ่อนอยู่ในโค้ดนี้: lookahead bias

สังเกตว่าเราคำนวณ beta, spread.mean() และ spread.std() จากข้อมูลทั้ง 500 วัน แล้วเอาไปเทรดตั้งแต่วันที่ 1 · แปลว่าวันแรกของ backtest รู้ราคาของวันสุดท้ายแล้ว

ที่ร้ายที่สุดคือ β — มันคือ hedge ratio ที่ดีที่สุดสำหรับทั้งช่วงรวมอนาคต ซึ่งวันนั้นคุณไม่มีทางรู้

ในตัวอย่างนี้ผลกระทบเล็ก (walk-forward ได้ 68.7 vs in-sample 61.4 บน 250 วันหลัง) แต่เล็กเพราะข้อมูลปลอมเท่านั้น — spread นิ่งคงที่ อนาคตจึงไม่บอกอะไรเพิ่ม · บนคู่หุ้นจริงที่ β เลื่อนไปตามเวลา มันกัดหนัก

💡 วิธีแก้: คำนวณใหม่ทุกวันจากข้อมูลถึงเมื่อวานเท่านั้น — for i in range(250, n): b, a = np.polyfit(A[:i], B[:i], 1) · เพิ่ม 4 บรรทัด แต่เป็น 4 บรรทัดที่แยก backtest ที่เชื่อได้ออกจาก backtest ที่หลอกตัวเอง

lookahead bias คือสาเหตุอันดับหนึ่งที่ backtest สวยแล้วเทรดจริงเจ๊ง

💎 บทเรียนที่แพงที่สุดในบทนี้: คู่หุ้นที่ "ดี" ในแง่ทดสอบสถิติ (φ สูง = ความสัมพันธ์แน่นและยาวนาน) กับคู่ที่ "ดี" ในแง่เทรด (φ ต่ำ = หุบกลับไว) เป็นคนละคู่กัน · และคู่ที่ให้ผลตอบแทนสวยที่สุดใน backtest มักเป็นคู่ที่ spread แทบไม่มีความจำ — ซึ่งแปลว่ามันไม่ได้ cointegrated จริงจัง แต่บังเอิญเป็น noise ที่วนรอบศูนย์

9.2½ Distance method — ฐานที่ทุกวิธีต้องชนะก่อน

🚶 อ่านเป็นภาษาคนก่อน: ก่อนจะมี cointegration และ z-score นักวิจัยใช้วิธีที่โง่กว่านี้มาก และมันคือฐานเปรียบเทียบที่ดีที่สุดที่คุณมี: ปรับราคาทุกตัวให้เริ่มที่ 1 บาท แล้วจับคู่ที่เส้นราคาเดินใกล้กันที่สุด วัดด้วยผลรวมของผลต่างยกกำลังสอง · ไม่มี β ไม่มีการทดสอบ ไม่มีสมมติฐานเรื่อง OU · ถ้าวิธีที่ซับซ้อนกว่าของคุณชนะวิธีนี้ไม่ได้หลังหักต้นทุน ความซับซ้อนนั้นไม่ได้จ่ายค่าตัวเอง

📖 อ่านสูตรว่า: ตัวหนอน ~ บน A อ่านว่า "เอ-ทิลเดอ" = A ที่ปรับฐานแล้ว (ธรรมเนียมเดียวกับ x̄ ขีดบน = ค่าเฉลี่ย ในตารางสัญลักษณ์ของ notation — เครื่องหมายบนหัวตัวแปรบอกว่า "ผ่านการแปลง") · SSD อ่านว่า "เอส-เอส-ดี" = Sum of Squared Differences ผลรวมของผลต่างยกกำลังสอง · โครงที่ต้องเห็น: นี่คือ spread ของ §9.1 ในกรณีพิเศษที่บังคับ β = 1 บนราคาปรับฐาน (เท่ากับ β = B₀/A₀ บนราคาจริง) — ทุกอย่างที่ §9.1 หาด้วย regression วิธีนี้กำหนดล่วงหน้า · กับดักการอ่าน: "2 × SD ในช่วงก่อตัว" ใช้ SD ที่วัดจากอดีตช่วงเดียว ไม่ได้ปรับเมื่อเวลาผ่านไป ต่างจาก z-score ของ §9.2 ที่มักคำนวณแบบ rolling

🧮 เดินเลขจริง

คู่ A/B ของตาราง §9.1½ (500 วัน): Ã, B̃ เริ่มที่ 1 ทั้งคู่ · SSD = 0.164 · เทียบกับคู่เดินสุ่มที่ไม่เกี่ยวกันเลย (seed 5 · เริ่ม 100 กับ 155): SSD = 4.072 — ต่างกัน 25 เท่า · วิธีนี้แยก "คู่ที่เดินด้วยกัน" จาก "คู่ที่ไม่เกี่ยวกัน" ได้โดยไม่ต้องรู้จัก ADF เลย · สิ่งที่มันแยกไม่ได้คือ "เดินด้วยกันเพราะมีกลไก" กับ "เดินด้วยกันโดยบังเอิญในช่วงที่วัด" — ซึ่งเป็นคำถามที่ cointegration ตอบได้ดีกว่าเล็กน้อย และไม่มีวิธีไหนตอบได้จริง (§9.3 ข้อแรก)

❌ ทำไมมันจึงเป็นฐาน ไม่ใช่กลยุทธ์

SSD น้อยสุด = spread แปรปรวนน้อยสุด = กำไรต่อไม้น้อยสุด — วิธีเลือกคู่กับวิธีทำกำไรขัดกันเอง คู่ที่ "ดีที่สุด" ตามเกณฑ์นี้คือคู่ที่ไม่ค่อยถ่างออกให้เทรด · ธรรมเนียม 12 เดือนก่อตัว / 6 เดือนเทรดของงานต้นฉบับทำให้ β = B₀/A₀ ค้างเป็นค่าเดียวหกเดือน · และผลตอบแทนของวิธีนี้ในงานวิจัยลดลงชัดหลังทศวรรษ 2000 (edge เสื่อม) — มันจึงเหมาะเป็น "คู่แข่งที่ต้องชนะ" สำหรับทุกวิธีในบทนี้ และเป็นเครื่องเตือนว่าความซับซ้อนที่เพิ่มต้องแสดงตัวเลขที่ดีกว่านี้ให้ได้

9.3 ❌ ทำไม pairs trading ถึงเจ๊ง

ตัวเลขข้างบนสวยเพราะผมสร้างข้อมูลให้ cointegrated จริงตั้งแต่ต้น · โลกจริงไม่ให้ของขวัญแบบนั้น นี่คือสิ่งที่ backtest ง่าย ๆ ไม่ได้บอก

❌ 5 อย่างที่ฆ่ากลยุทธ์นี้
  • Cointegration พังได้ และมักพังตอนสำคัญ — ความสัมพันธ์อิงปัจจัยพื้นฐาน · วันที่บริษัทหนึ่งถูกซื้อกิจการ เปลี่ยน CEO หรือโดนคดี ความสัมพันธ์ขาดถาวร · spread ที่ "ต้องกลับ" จะไม่กลับอีกเลย และคุณถือสถานะที่ขาดทุนเพิ่มทุกวัน
  • ไม่มี stop = หายนะ — ตรรกะ "ยิ่งถ่างยิ่งน่าเข้า" ทำให้คนเติมสถานะสวนไปเรื่อย ๆ · ถ้าความสัมพันธ์ขาดจริง นี่คือวิธีขาดทุนไม่จำกัด · ต้องมี stop ที่ z ระดับหนึ่ง (เช่น 4) เสมอ แม้จะขัดความรู้สึก
  • ต้นทุนกินกำไร — และกินมากกว่าที่คิดมาก · 21 เทรดในตัวอย่างคือ 84 fills (21 เทรด × เข้า-ออก × 2 ขา) · มูลค่ารวมต่อ 1 หน่วยของ spread ≈ ฿296 (long B ~฿150 + short A 1.51 หน่วย ~฿146) · คิดต้นทุน 25 bps ต่อข้าง กำไรจะเหลือ 51.5 จาก 113.7 (หายไป 55%) · ที่ 50 bps กำไรกลายเป็นติดลบ −10.7 · บวกอีกว่าต้องเสียค่ายืมหุ้นสำหรับขาย short ซึ่งแพงและอาจถูกเรียกคืนกลางทาง
  • Overfitting จากการค้นหาคู่ — สแกนหุ้น 500 ตัว = 124,750 คู่ · ที่ระดับนัยสำคัญ 5% จะมี ~6,200 คู่ที่ "ดูเหมือน" cointegrated โดยบังเอิญ · และถ้าคุณใช้ adfuller แทน coint (ตามกับดักใน §9.1) ตัวเลขจะพุ่งเป็น ~19,000 คู่ — สามเท่า · ต้องมีเหตุผลเชิงเศรษฐกิจรองรับก่อนเสมอ ไม่ใช่ให้คอมพิวเตอร์หาคู่ล้วน ๆ
  • 🇹🇭 สำหรับนักลงทุนรายย่อยไทย: กลยุทธ์นี้ต้อง short ขาหนึ่งเสมอ — ซึ่งบน SET ทำได้เฉพาะหุ้นในลิสต์ SBL ต้องมีบัญชีมาร์จิ้นและข้อตกลงยืมหุ้น · และมักยืมไม่ได้พอดีในหุ้นกลางเล็กที่คู่น่าสนใจที่สุด · ถ้า short ไม่ได้ กลยุทธ์นี้ทำไม่ได้ ไม่ใช่แค่แพงขึ้น — นี่เป็นปัญหาเรื่องการเข้าถึง ไม่ใช่เรื่องต้นทุน และควรเป็นคำถามแรกที่คุณถามโบรกเกอร์ก่อนลงแรงกับบทนี้
  • β ไม่นิ่ง — hedge ratio ที่คำนวณจากอดีตอาจเปลี่ยนไปแล้ว · และมันเป็นค่าประมาณที่มีช่วงความเชื่อมั่น (เล่ม 2 · C §6.4) ไม่ใช่ตัวเลขศักดิ์สิทธิ์
🧠 มุมที่มองต่าง — กลยุทธ์นี้ยังใช้ได้อยู่ไหม

มือใหม่เห็น: "backtest กำไร แปลว่าใช้ได้"
คนในตลาดเห็น: pairs trading แบบง่าย ๆ นี้ถูกเก็บกินไปหมดแล้วตั้งแต่ยุค 2000 · สิ่งที่ยังเหลือคือเวอร์ชันที่ซับซ้อนกว่ามาก (หลายสินทรัพย์พร้อมกัน · คุมความเสี่ยงเชิง factor · ความเร็วระดับมิลลิวินาที) · คุณค่าของบทนี้ไม่ใช่กลยุทธ์สำเร็จรูป แต่คือกรอบคิด — หาความสัมพันธ์ที่ mean-revert แล้วเทรดค่าเบี่ยงเบนของมัน ซึ่งใช้ได้กับ basis ของ futures, ส่วนต่างดอกเบี้ย, และ vol spread ที่เล่ม 1 สอนไปแล้ว

9.3½ เวลาปิดไม้ และเกณฑ์เข้าที่เลื่อนตามต้นทุน

🚶 อ่านเป็นภาษาคนก่อน: §9.1 แก้คำอ่านของครึ่งชีวิตไว้แล้วว่ามันคือเวลาที่ค่าคาดหวังลดครึ่ง ไม่ใช่เวลาปิดไม้ · หัวข้อนี้ให้ตัวเลขว่าไม้จริงใช้เวลาเท่าไร (มันคือ first passage time — เวลาที่กระบวนการสุ่มแตะเส้นครั้งแรก) แล้วต่อด้วยคำถามที่ตาราง ✍️ ของ §9.3 เปิดไว้: เข้าที่ z เท่าไรถึงดีที่สุด · คำตอบเชิงทฤษฎีมีอยู่ และมันบอกสิ่งเดียวกับตารางนั้นในภาษาทั่วไป: เกณฑ์เข้าที่ดีที่สุดสูงขึ้นตามต้นทุน ไม่มีค่าตายตัว

first passage time τ = เวลาแรกที่ spread แตะเส้นเป้า (เช่น 0) นับจากวันเข้า ตัวแปรสุ่ม ไม่ใช่ตัวเลข ครึ่งชีวิต t½ = −ln 2 / ln φ บอกแค่ค่าคาดหวังของระดับ ส่วน τ มีค่ากลาง หาง และเปอร์เซ็นไทล์ของมันเอง กำไรต่อวัน(z) = [ กำไรต่อรอบ(z) − ต้นทุนต่อรอบ c ] / เวลาต่อรอบ(z) เลือก z ที่ทำให้ค่านี้สูงสุด กำไรต่อรอบ โตตาม z · จำนวนรอบ หดตาม z · ต้นทุน c เท่าเดิมทุกรอบ → z ที่ดีที่สุดเลื่อนขึ้นเมื่อ c ขึ้น

📖 อ่านสูตรว่า: τ (เทา) คือตัวแปรสุ่ม "เวลาแรกที่แตะ" — คนละตัวกับ T เวลาหมดอายุของ options และคนละตัวกับ t เวลาปฏิทิน · โครงที่ต้องเห็น: บรรทัดกำไรต่อวันคือเศษส่วนที่เศษและส่วนโตตาม z ทั้งคู่ — เข้าไกล ได้มากต่อรอบแต่รอนาน เข้าใกล้ ได้น้อยต่อรอบแต่หมุนเร็ว · เมื่อ c = 0 เศษไม่ถูกหักอะไร การหมุนเร็วชนะ · เมื่อ c ใหญ่ รอบที่ได้น้อยกว่า c กลายเป็นขาดทุน ต้องเข้าไกลขึ้นให้แต่ละรอบคุ้ม · กับดักการอ่าน: "เวลาต่อรอบ" ไม่ใช่ครึ่งชีวิต และไม่ใช่แค่ τ จาก z ไป 0 — ต้องรวมเวลารอให้ spread ถ่างกลับไปถึง z อีกครั้งด้วย · หน่วยของ z และ c ในตารางข้างล่างคือ SD ของ spread ไม่ใช่บาท จึงเทียบข้ามคู่ได้

9.4 Kalman filter — β ที่เปลี่ยนตามเวลา

ข้อสุดท้ายในรายการของ §9.3 คือ "β ไม่นิ่ง" — และมันเป็นข้อเดียวที่บทนี้ยังไม่ได้ให้เครื่องมือแก้ · ทุกอย่างใน §9.1–9.2 ยืนอยู่บน β = 1.5068 ตัวเดียวที่คำนวณจากข้อมูลทั้ง 500 วัน · ถ้าความสัมพันธ์ระหว่าง A กับ B เลื่อนไปช้า ๆ ตัวเลขนั้นจะผิดมากขึ้นทุกวันโดยที่คุณไม่เห็น · หัวข้อนี้คือเครื่องมือมาตรฐานที่ทำให้ β "หายใจ" ตามข้อมูลได้

🎯 Thesis

"OLS ให้ β ตัวเดียวสำหรับข้อมูลทั้งชุด · Kalman filter ให้ β ของทุกวัน — อัปเดตทันทีที่ราคาวันใหม่มาถึง และบอกด้วยว่าตอนนี้ไม่แน่ใจใน β อยู่เท่าไร"

❓ ทำไมต้องรู้จัก

§9.3 บอกว่าคู่หุ้นตายเมื่อความสัมพันธ์เลื่อน · แต่ β จาก §9.1 คือค่าเฉลี่ยของทุกวันในอดีตด้วยน้ำหนักเท่ากัน — มันมองการเลื่อนไม่เห็นโดยโครงสร้าง วันที่ β จริงกลายเป็น 1.3 ไปแล้ว มันจะยังบอก 1.5 อยู่อีกหลายเดือน · วิธีแก้ที่โต๊ะ stat-arb ใช้เป็นมาตรฐานคือมอง β เป็นสถานะที่มองไม่เห็นและเปลี่ยนตามเวลา (state-space model · time-varying hedge ratio) แล้วให้ Kalman filter ประมาณมันใหม่ทุกวันจากราคาที่เห็น · Arb Part V บทที่ 19 (หัวข้อ 19.2) เอ่ยถึงเรื่องนี้ไว้หนึ่งย่อหน้า — ที่นี่คือบ้านของมัน

🔧 ใช้ทำอะไร
  • hedge ratio รายวัน — ตัวเลข 1.51 ในคำสั่งเทรดของ §9.2 กลายเป็นตัวเลขที่ขยับได้ตามความสัมพันธ์ล่าสุด
  • spread ที่ไม่มี lookahead โดยโครงสร้าง — β̂ ของวันที่ t ใช้ราคาถึงวันที่ t−1 เท่านั้น จึงปิดบั๊กที่กล่อง ❌ ใน §9.2 จับได้ โดยไม่ต้องรัน regression ใหม่ทุกวัน
  • ช่วงความไม่แน่นอนของ β — ได้ตัวเลข P (variance ของ β̂) แถมมาทุกวัน ใช้ตัดสินได้ว่าสัญญาณวันนี้มาจาก spread จริง หรือจาก β ที่เรายังไม่แน่ใจ

🚶 อ่านเป็นภาษาคนก่อน: Kalman filter ทำสามอย่างซ้ำทุกวัน — "ทายก่อน วัดจริง แล้วเลื่อนความเชื่อไปหาสิ่งที่วัดได้ตามสัดส่วนความมั่นใจ" · เช้านี้คุณเชื่อว่า β ≈ 1.50 (ทาย) · พอตลาดปิด B อยู่สูงกว่าที่ β = 1.50 ทำนายไว้ 2 บาท (วัดจริง) · คุณจะเลื่อน β ขึ้นเท่าไร ขึ้นกับว่าเชื่อความเชื่อเดิมแค่ไหน เทียบกับเชื่อค่าวัดใหม่แค่ไหน — ถ้าเมื่อวานยังไม่แน่ใจ β เลย ก็เลื่อนตามค่าวัดเกือบทั้งหมด · ถ้ามั่นใจ β มาก และรู้ว่าราคามี noise เยอะ ก็เลื่อนแค่นิดเดียว · สัดส่วนที่เลื่อนนั้นเรียกว่า Kalman gain (K) และมันคือทั้งหมดของเครื่องมือนี้ — ที่เหลือคือสูตรบอกว่า K ควรเป็นเท่าไรในแต่ละวัน

สถานะ (มองไม่เห็น): βₜ = βₜ₋₁ + ηₜ Var(η) = Q ← β เดินสุ่มช้า ๆ สิ่งที่วัดได้: Bₜ = βₜ·Aₜ + εₜ Var(ε) = R ← ราคาที่เห็น มี noise ทาย: Pₜ⁻ = Pₜ₋₁ + Q (β̂ ยังเดิม แต่มั่นใจน้อยลง) ชั่งน้ำหนัก: Kₜ = Pₜ⁻·Aₜ / (Aₜ²·Pₜ⁻ + R) เลื่อน: β̂ₜ = β̂ₜ₋₁ + Kₜ·(Bₜ − β̂ₜ₋₁·Aₜ) ← เก่า + K × innovation Pₜ = (1 − Kₜ·Aₜ)·Pₜ⁻

📖 อ่านสูตรว่า: บรรทัดตัวหนาอ่านว่า "เบต้า-แฮต วันนี้ เท่ากับ เบต้า-แฮต เมื่อวาน บวก เค คูณ (บี วันนี้ ลบ เบต้า-แฮตเมื่อวาน คูณ เอ วันนี้)" · วงเล็บท้ายสุดคือ "ของจริง ลบ ที่ทายไว้" ตำราเรียกว่า innovation — และมันคือ spread ของ §9.1 ตัวเดียวกัน (B − β·A) เพียงแต่ใช้ β ของเมื่อวานแทน β ของทั้งชุด · โครงที่ต้องเห็น: "สูตรอ้างตัวเองเมื่อวาน" โครงเดียวกับ EMA และ AR(1) ใน §8.4 (ดู notation หมวด 0) — EMA คือ ค่าเก่า + 2/(n+1) × (ราคาใหม่ − ค่าเก่า) ด้วยน้ำหนักที่ตั้งไว้ตายตัว · Kalman คือ ค่าเก่า + Kₜ × (ของจริง − ที่ทาย) ด้วยน้ำหนักที่ปรับเองทุกวัน ตามว่าเรามั่นใจ β เก่าแค่ไหน (P) เทียบกับราคามี noise แค่ไหน (R) · เขียนแบบ E[·|·] ตามตารางถอดโครง: β̂ₜ = E[βₜ | ราคาที่วัดได้ถึง t] — หลังขีดคือราคา ไม่ใช่ β เพราะ β จริงไม่มีใครเห็น มีแต่ราคาที่มี noise · กับดักการอ่าน: η (เอตา) คือก้าวสุ่มของ β ในแต่ละวัน — คนละตัวกับ ε (เอปไซลอน) ที่เป็น noise ของราคา · ตัวยก ⁻ บน P อ่านว่า "ก่อนเห็นข้อมูลวันนี้" (prior) ไม่ใช่เครื่องหมายลบ · K มีหน่วยเป็น 1/A (คูณกับ innovation ที่เป็นหน่วยราคาแล้วได้หน่วยของ β) — ตัวที่เทียบกับ "สัดส่วน 0 ถึง 1" ของ EMA ได้จริงคือ Kₜ·Aₜ ไม่ใช่ Kₜ เปล่า ๆ · Q กับ R เป็น variance ไม่ใช่ SD — Q = 0.0001 แปลว่า β เดินสุ่มวันละราว √0.0001 = 0.01 · ขีดตั้ง | ใน E[βₜ | …] อ่านว่า "given" ไม่ใช่การหาร

🧮 เดินเลขจริง — สองวันแรกของ filter ด้วยมือ

ตั้งต้น: β̂₀ = 1.50 · P₀ = 0.01 (ยังไม่ค่อยแน่ใจ — SD ของ β ≈ 0.1) · Q = 0.0001 · R = 1.0 · วันที่ 1: A = 100, B = 152.0

  1. ทาย — P₁⁻ = 0.01 + 0.0001 = 0.0101 · ทายว่า B ควรอยู่ที่ 1.50 × 100 = 150.0
  2. ชั่งน้ำหนัก — K₁ = 0.0101 × 100 / (100² × 0.0101 + 1) = 1.01 / (101 + 1) = 1.01 / 102 = 0.009902 · K₁·A = 0.990 → วันนี้เชื่อค่าวัดใหม่ 99% เพราะความเชื่อเดิมยังหลวมมาก
  3. เลื่อน — innovation = 152.0 − 150.0 = +2.0 (B แพงกว่าที่ β บอก 2 บาท = spread เป็นบวก) · β̂₁ = 1.50 + 0.009902 × 2.0 = 1.50 + 0.019804 = 1.519804 · P₁ = (1 − 0.990196) × 0.0101 = 0.009804 × 0.0101 = 0.0000990

วันที่ 2: A = 101, B = 151.0

  1. ทาย — P₂⁻ = 0.0000990 + 0.0001 = 0.0001990 · ทายว่า B = 1.519804 × 101 = 153.5002
  2. ชั่งน้ำหนัก — K₂ = 0.0001990 × 101 / (101² × 0.0001990 + 1) = 0.020101 / (2.0302 + 1) = 0.020101 / 3.0302 = 0.006634 · K₂·A = 0.670 → เชื่อค่าวัดใหม่แค่ 67% แล้ว เพราะเมื่อวานเรียนรู้ไปแล้วรอบหนึ่ง
  3. เลื่อน — innovation = 151.0 − 153.5002 = −2.5002 · β̂₂ = 1.519804 + 0.006634 × (−2.5002) = 1.519804 − 0.016585 = 1.503219 · P₂ = (1 − 0.669989) × 0.0001990 = 0.330011 × 0.0001990 = 0.0000657

อ่านผล: หลังสองวัน β̂ = 1.5032 ± 0.0081 (± คือ √P₂ = √0.0000657) · สังเกตว่า K·A ตกจาก 0.99 เหลือ 0.67 ในวันเดียว — ยิ่งเห็นข้อมูลมาก filter ยิ่งดื้อขึ้นเอง ไม่ต้องมีใครสั่ง · และสังเกตว่า P⁻ ทุกวันบวก Q กลับเข้าไป: Q คือสิ่งที่กันไม่ให้ filter มั่นใจจนหูหนวก ถ้า Q = 0 สักวัน P จะเหลือศูนย์ และ K จะเหลือศูนย์ตามไป — filter จะไม่ฟังอะไรอีกเลย

🐍 Python — Kalman สเกลาร์บนคู่ A/B ตัวเดิมของ §9.1
# pip install numpy
import numpy as np

rng = np.random.default_rng(0)                        # ★ seed เดียวกับ §9.1 — ข้อมูลชุดเดียวกันเป๊ะ
n = 500
A = 100 + np.cumsum(rng.normal(0, 1, n))
B = 5.0 + 1.5*A + rng.normal(0, 2, n)

b, P, Q, R = 1.0, 1.0, 1e-6, 4.0                      # เริ่มจาก "ไม่รู้" (P₀ ใหญ่) · R = 2² ตามที่สร้าง B
beta_k, innov = np.empty(n), np.empty(n)
for t in range(n):
    P_prior  = P + Q                                  # ทาย: β ยังเดิม แต่มั่นใจน้อยลง
    K        = P_prior*A[t] / (A[t]**2*P_prior + R)   # ชั่งน้ำหนัก
    innov[t] = B[t] - b*A[t]                          # ของจริง − ที่ทาย  (= spread ที่ไม่มี lookahead)
    b        = b + K*innov[t]                         # เลื่อนความเชื่อ
    P        = (1 - K*A[t])*P_prior
    beta_k[t] = b

for t in [0, 1, 5, 50, 250, 499]:
    print(f"วัน {t:3d}: β̂ = {beta_k[t]:.4f}")
# วัน   0: β̂ = 1.5755
# วัน   1: β̂ = 1.5673
# วัน   5: β̂ = 1.5526
# วัน  50: β̂ = 1.5534
# วัน 250: β̂ = 1.5440
# วัน 499: β̂ = 1.5501
print(f"OLS ทั้งชุด (มี α) = {np.polyfit(A, B, 1)[0]:.4f} | OLS ไม่มี α = {(A@B)/(A@A):.4f}")
# OLS ทั้งชุด (มี α) = 1.5068 | OLS ไม่มี α = 1.5499
print(f"β̂ เหวี่ยง (วัน 50→499): {beta_k[50:].min():.4f}–{beta_k[50:].max():.4f} · ±√P สุดท้าย = ±{np.sqrt(P):.4f}")
# β̂ เหวี่ยง (วัน 50→499): 1.5389–1.5626 · ±√P สุดท้าย = ±0.0047
print(f"sd ของ innovation = {innov[50:].std():.2f}  (sd ของ spread OLS ใน §9.2 = 1.88)")
# sd ของ innovation = 1.90  (sd ของ spread OLS ใน §9.2 = 1.88)
✅ อ่านผลลัพธ์
  • วันที่ 0 ได้ 1.5755 จากจุดเริ่ม 1.0 ในก้าวเดียว — เพราะ P₀ = 1 ใหญ่มาก K·A จึงเกือบ 1 (0.9996) และ β̂ วันแรกจึงเกือบเท่ากับ B₀/A₀ = 1.5758 · จากนั้น K·A ร่วงต่ำกว่า 0.1 ภายในสิบวัน (0.097 ที่วัน 10) แล้วค่อย ๆ นิ่งอยู่ราว 0.05 ตั้งแต่วันที่ 30 เป็นต้นไป — filter หา "น้ำหนักที่เหมาะ" ให้เองจาก Q กับ R
  • β̂ เข้าที่ราว 1.55 ไม่ใช่ 1.5068 · นี่ไม่ใช่บั๊ก — รุ่นสเกลาร์นี้ไม่มี α · ข้อมูลถูกสร้างจาก B = 5.0 + 1.5·A ค่าคงที่ 5.0 จึงไม่มีที่ไป และถูกดูดเข้า β เป็น 5/A ≈ 0.05 · ดูบรรทัด OLS ไม่มี α = 1.5499 — Kalman ให้ 1.5501 ต่างกันแค่ 0.0002 (และถ้าตั้ง Q = 0 มันจะกลายเป็น OLS ไม่มี α ที่คำนวณทีละวันเป๊ะ) · บทเรียน: filter ตอบคำถามที่คุณตั้งไว้ในสมการสถานะ ถ้าอยากได้ α ด้วยต้องใส่ α เป็นสถานะตัวที่สอง (ดู 📍)
  • β̂ เหวี่ยงระหว่าง 1.539–1.563 และ filter บอกเองว่า ± 0.0047 — ตัวเลข P นี้คือของแถมที่ OLS ตัวเดียวไม่ให้ (ต้องไปหา SE เอาเองแบบ เล่ม 2 · C §6.4) · ในข้อมูลนี้ β จริงคงที่ 1.5 การเหวี่ยงทั้งหมดจึงเป็น noise ที่ Q ปล่อยให้เข้ามา
  • sd ของ innovation = 1.90 ใกล้ 1.88 ของ spread OLS ใน §9.2 — ยืนยันว่า innovation คือ spread ตัวเดียวกัน แต่เป็นรุ่นที่วันที่ t ไม่รู้อะไรหลังวันที่ t−1 · นี่คือคำตอบของบั๊ก lookahead ใน §9.2 ที่ได้มาฟรีจากโครงสร้างของสูตร

ถึงตรงนี้ควรถามคำถามเดียวกับที่ถาม AR(1): มันใช้ได้เมื่อไร และมันพังตอนไหน · คำตอบทั้งสองข้อวนกลับมาที่ตัวเลขสองตัวที่เราตั้งเองโดยไม่มีสูตรบอก — Q กับ R

✅ ใช้ได้เมื่อไร
  • β เลื่อนช้าและต่อเนื่อง — สมการสถานะสมมติว่า β เดินสุ่มทีละน้อย (random walk ที่ Q เล็ก) ซึ่งตรงกับความสัมพันธ์ที่ค่อย ๆ เปลี่ยนตามปัจจัยพื้นฐาน
  • noise ใกล้ Gaussian (Normal) — สูตร K ที่ให้มาคือคำตอบที่ดีที่สุดเมื่อ η และ ε เป็น Normal · หางหนาระดับปกติของราคายังพอไหว แต่ต้องรู้ว่ากำลังใช้เกินสมมติฐาน
  • รู้สเกลของ Q และ R อย่างมีเหตุผล — R ประมาณจาก variance ของ spread ในอดีตได้ (ในตัวอย่างคือ 2² = 4) · Q ต้องตอบคำถาม "β ควรเปลี่ยนได้วันละเท่าไร" ซึ่งเป็นคำถามเชิงเศรษฐกิจ ไม่ใช่เชิงสถิติ
❌ พังเมื่อไร
  • Q/R ตั้งผิด — และมันพังเงียบ ๆ ทั้งสองทิศ · Q ใหญ่เกิน → K ใหญ่ → β̂ วิ่งตาม noise ทุกวัน และ spread ที่คำนวณด้วย β̂ วันนี้จะไม่เคยดูกว้างเพราะ β ดูดซับความเบี่ยงเบนไปหมด (ดูตัวเลขใน ✍️ ข้างล่าง: ที่ Q = 0.01 sd ของ residual หลังอัปเดตเหลือ 0.10 จาก 1.81) · Q เล็กเกิน → K → 0 → กลับเป็น OLS ตัวเดียวที่มองการเลื่อนไม่เห็น ซึ่งคือปัญหาที่เราตั้งใจมาแก้
  • ความสัมพันธ์กระโดด ไม่ได้เลื่อน — M&A · เปลี่ยนโครงสร้างธุรกิจ · หลุดดัชนี · สมการสถานะรู้จักแค่ "เดินทีละน้อย" วันที่ β กระโดดจาก 1.5 เป็น 1.0 filter จะเห็น innovation มหึมาแล้วอ่านว่า spread ถ่างผิดปกติ ไม่ใช่ β เปลี่ยน — และพาคุณเข้าไม้สวนในวันที่ผิดที่สุด แบบเดียวกับข้อแรกของ §9.3 · ต้องมี regime detection แยกต่างหากเสมอ
  • outlier ตัวเดียว — สูตรอัปเดตเป็นเส้นตรงกับ innovation · ค่าผิดปกติ 10σ เลื่อน β̂ ไป K × 10σ เต็ม ๆ ไม่มีอะไรหักห้าม · รุ่น Gaussian ไม่มีคำว่า "ไม่น่าเชื่อ"
  • จูน Q/R บนข้อมูลชุดเดียวกับที่เอาไปเทรด — เลือก Q ที่ทำให้ backtest สวยที่สุด แล้วรายงานผล backtest นั้น = data leakage แบบเดียวกับ เล่ม 2 · F §12.4 · Q/R ต้องตั้งจากเหตุผลหรือจากข้อมูลช่วงก่อนหน้า แล้วล็อกไว้
⚖️ ข้อดี
  • ไม่มี lookahead โดยโครงสร้าง — ไม่ต้องเขียน loop คำนวณ regression ใหม่ทุกวัน
  • ได้ P (ความไม่แน่นอนของ β̂) แถมมาทุกวัน
  • คำนวณเบามาก — เก็บแค่ β̂ กับ P สองตัว ไม่ต้องเก็บหน้าต่างข้อมูล
  • ขยายเป็นหลายสถานะ (α, β) หรือหลายสินทรัพย์ได้ด้วยโครงเดิม
⚖️ ข้อเสีย
  • เพิ่มพารามิเตอร์ที่ต้องเลือกอีกสองตัว (Q, R) ซึ่งไม่มีสูตรบอก และตอบยากกว่าเลือกหน้าต่าง
  • β̂ เปลี่ยนทุกวัน = ต้อง rebalance ขา hedge ทุกวัน = ต้นทุนแบบที่ §9.3 คิดไว้เพิ่มอีกชั้น
  • อธิบายให้คนอื่นเข้าใจยากกว่า "β = 1.51" ตัวเดียว
  • การทดสอบ cointegration แบบ coint() ตั้งอยู่บน β คงที่ — พอปล่อยให้ β เปลี่ยน ตัวทดสอบเดิมไม่ตรงกับโมเดลอีกต่อไป

ทั้งหมดข้างบนคือกลไก · ข้างล่างคือคำถามที่กลไกนี้บังคับให้คุณตอบเอง

🧠 มุมที่มองต่าง — ยิ่งตามไว ยิ่งแม่น?

มือใหม่เห็น: "β เปลี่ยนได้ ก็ตั้ง Q ใหญ่ ๆ ให้มันตามข้อมูลไวที่สุด จะได้ hedge แม่นที่สุด"
quant เห็น: ทุกอย่างที่คุณปล่อยให้ β ดูดซับ จะหายไปจาก spread — ถ้า β ตามไวพอ spread จะเป็นศูนย์ตลอดและไม่มีอะไรเหลือให้เทรด · Q จึงไม่ใช่พารามิเตอร์เทคนิค มันคือคำตอบของคำถามว่า "การเบี่ยงเบนวันนี้คือความสัมพันธ์ที่เปลี่ยน หรือคือโอกาส" · และไม่มีข้อมูลชุดไหนตอบคำถามนี้แทนคุณได้

📍 ปัจจุบันใช้จริง

เป็นเครื่องมือมาตรฐานของโต๊ะ stat-arb สำหรับ hedge ratio ที่เปลี่ยนตามเวลา · รุ่นที่ใช้จริงมักมีสองสถานะ (α, β) เพื่อไม่ให้ค่าคงที่ถูกดูดเข้า β อย่างที่เห็นในโค้ด และมักทำบน log ราคา · สำหรับตะกร้าหลายตัวใช้รุ่นหลายมิติ (สถานะเป็นเวกเตอร์ P เป็น matrix — สูตรเดิมทุกบรรทัด แค่เปลี่ยนการหารเป็น inverse) · เมื่อ noise ไม่ใช่ Gaussian หรือสมการไม่เป็นเส้นตรง จึงขยับไป extended/unscented Kalman หรือ particle filter · โครงเดียวกันนี้คือตัวที่ rates desk ใช้ประมาณ level/slope/curvature ของเส้นอัตราดอกเบี้ยแบบเรียลไทม์ (เล่ม B-I) — สมการเปลี่ยน แต่ "ทาย วัด เลื่อน" ไม่เปลี่ยน

9.5 VAR และ VECM — เมื่อสองอนุกรมพยากรณ์กันและกัน

§9.4 ปิดข้อ "β ไม่นิ่ง" ไปแล้ว · แต่ยังมีคำถามหนึ่งที่ §9.1–9.2 ไม่เคยตอบ ทั้งที่มันตัดสินว่าคุณจะได้เงินจากขาไหน — วันที่ spread ถ่างออก ใครเป็นคนหุบ · B ตกลงมาหา A หรือ A ขึ้นไปหา B หรือทั้งคู่ขยับคนละครึ่ง · AR(1) บน spread มองไม่เห็นคำถามนี้ เพราะมันยุบสองราคาเหลือตัวเลขเดียวก่อนเริ่มคิด · หัวข้อนี้แยกกลับออกมาเป็นสองสมการ แล้วให้ข้อมูลตอบเอง

🎯 Thesis

"AR(1) ให้อนุกรมหนึ่งพยากรณ์ตัวเอง · VAR ให้หลายอนุกรมพยากรณ์กันและกัน · VECM คือ VAR รุ่นที่ต้องใช้เมื่ออนุกรมเหล่านั้น cointegrated — มันเพิ่มพจน์เดียวคือ spread ของเมื่อวาน และพจน์นั้นก็คือ mean reversion ของ §9.1–9.2 ที่เขียนใหม่เป็นสมการพยากรณ์"

ใน §9.1 เราทำสองขั้นแยกกัน: regress B บน A ได้ β แล้วค่อยฟิต AR(1) บน spread ต่างหาก · ผลคือรู้ว่า spread หุบ แต่ไม่รู้ว่าขาไหนหุบ · VECM (Vector Error Correction Model) ทำทั้งสองอย่างในระบบเดียว และให้ตัวเลขแยกต่อขา (γB, γA — γ อ่านว่า "แกมมา" คือความเร็วในการปรับตัวของแต่ละขา) ว่าแต่ละตัวขยับเข้าหาความสัมพันธ์ระยะยาวเร็วแค่ไหน · นั่นคือสิ่งที่ตัดสินว่าคุณควรคาดหวังกำไรจากขาไหน และขาไหนเป็นแค่ hedge · และมันคือโมเดลมาตรฐานเมื่อคู่หุ้นกลายเป็นตะกร้าสามสี่ตัว ซึ่ง regression คู่เดียวของ §9.1 ขยายไม่ถึง

🔧 ใช้ทำอะไร
  • แยกความเร็วปรับตัวต่อขา — γB กับ γA บอกว่า B วิ่งหา A หรือ A วิ่งหา B · ตัวเลขนี้ไม่มีใน §9.1
  • พยากรณ์ ΔA และ ΔB พรุ่งนี้พร้อมกัน จากอดีตของทั้งคู่บวก spread เมื่อวาน — ไม่ใช่แค่พยากรณ์ spread
  • ทดสอบ Granger causality (ความเป็นสาเหตุแบบ Granger = อดีตของ X ช่วยพยากรณ์ Y ได้เกินกว่าอดีตของ Y เอง) — ใน VAR อ่านจากสัมประสิทธิ์ข้ามตัว a₁₂, a₂₁ (อ่านว่า "เอ-หนึ่ง-สอง" = สมการที่ 1 ตัวแปรที่ 2) ว่าต่างจากศูนย์ไหม · ใน VECM ต้องทดสอบร่วมกับ γ ของสมการนั้นด้วย เพราะ spreadₜ₋₁ ก็มีราคาอีกตัวเมื่อวานซ่อนอยู่
  • ขยายไป k อนุกรม — VAR/VECM คือภาษาที่โต๊ะ stat-arb ใช้กับตะกร้า ไม่ใช่แค่คู่

🚶 อ่านเป็นภาษาคนก่อน: ประโยคเดียวสำหรับทั้งหัวข้อ — "พรุ่งนี้แต่ละตัวจะขยับตาม (1) การขยับของตัวเองเมื่อวาน (2) การขยับของอีกตัวเมื่อวาน (3) ระยะที่ทั้งคู่หลุดจากความสัมพันธ์ระยะยาวเมื่อวาน" · สองข้อแรกคือ VAR (Vector AutoRegression — AR หลายอนุกรมที่ยอมให้อดีตของกันและกันอยู่ทางขวา) — AR(1) ของ §8.4 ที่ยอมให้ "อดีตของเพื่อน" เข้ามาอยู่ทางขวาด้วย · หน้าตาเหมือน multiple regression ของ เล่ม 2 · A §2.2 เพียงแต่ตัวแปรทางขวาทุกตัวคืออดีต และมีตัวแปรตามหลายตัวพร้อมกัน — ชื่อทางการคือ multivariate regression (กล่อง 🔍 ใน §2.2 ของเล่มนั้นแยกสองคำนี้ให้) · ข้อที่สามคือ error-correction term (พจน์แก้ความคลาดเคลื่อน) — ถ้าเมื่อวาน B แพงกว่าที่ β บอก วันนี้ B ควรลง หรือ A ควรขึ้น หรือทั้งคู่ · ตัวคูณหน้าพจน์นี้ (γ) บอกว่า "ใคร" และ "เร็วแค่ไหน"

VAR(1): ΔAₜ = c₁ + a₁₁·ΔAₜ₋₁ + a₁₂·ΔBₜ₋₁ + ε₁ₜ ΔBₜ = c₂ + a₂₁·ΔAₜ₋₁ + a₂₂·ΔBₜ₋₁ + ε₂ₜ VECM: ΔBₜ = c + γB·(Bₜ₋₁ − β·Aₜ₋₁) + (พจน์ VAR) + εₜ ← error-correction term ΔAₜ = c′ + γA·(Bₜ₋₁ − β·Aₜ₋₁) + (พจน์ VAR) + ε′ₜ γB − β·γA = φ − 1 (φ = AR(1) ของ spread บนตัวแปรทางขวาชุดเดียวกัน)

📖 อ่านสูตรว่า: บรรทัด VECM แรกอ่านว่า "เดลตา-บี ณ เวลาที เท่ากับ ซี บวก แกมมา-บี คูณ (บี เมื่อวาน ลบ เบต้า คูณ เอ เมื่อวาน) บวก พจน์ VAR บวก เอปไซลอน" · Δ อ่านว่า "เดลตา" แต่แปลว่า "การเปลี่ยนแปลงของ" — ΔBₜ = Bₜ − Bₜ₋₁ คือผลต่างจาก §8.1 ที่ทำให้ราคานิ่ง · วงเล็บ (Bₜ₋₁ − β·Aₜ₋₁) คือ spread ของเมื่อวาน ตัวเดียวกับ §9.1 เป๊ะ · โครงที่ต้องเห็น: error-correction term คือ "AR(1) บน spread" ที่มองจากข้างในแต่ละขา — γB < 0 แปลว่าเมื่อ spread เป็นบวก (B แพงเกิน) B จะตกลงหา β·A · γA > 0 แปลว่า A จะขึ้นไปหา B/β · พิสูจน์บรรทัดเดียว: เอาสมการ ΔB ลบด้วย β คูณสมการ ΔA จะได้ ΔBₜ − β·ΔAₜ = Δspreadₜ = (γB − β·γA)·spreadₜ₋₁ + … ขณะที่ AR(1) ของ spread ที่มีตัวแปรทางขวาชุดเดียวกัน เขียนได้ว่า Δspreadₜ = (φ − 1)·spreadₜ₋₁ + … + εₜ เทียบสัมประสิทธิ์จึงได้ γB − β·γA = φ − 1 (ตัดพจน์ VAR ออกทั้งสามสมการ φ ตัวนี้จึงกลายเป็น φ ของ §9.1 — ข้อ 5 ในกล่อง 🧮 ตรวจให้ดู) · แปลว่า φ ตัวเดียวของ §9.1 ถูกแบ่งออกเป็นสองส่วน ส่วนของ B กับส่วนของ A และ VECM คือเครื่องมือที่บอกสัดส่วนการแบ่ง · เขียนแบบ E[·|·] ตามตารางถอดโครง: E[ΔBₜ | ΔAₜ₋₁, ΔBₜ₋₁, spreadₜ₋₁] — หลังขีดมีสามอย่าง ล้วนเป็นของเมื่อวาน · กับดักการอ่าน: ตัวห้อยคู่ a₁₂ อ่านว่า "สมการที่ 1 ตัวแปรที่ 2" คือแถวก่อนคอลัมน์ ธรรมเนียมเดียวกับ a₁₂ ในระบบสมการของ เล่ม 2 · B §3.1 ไม่ใช่ "lag 12" · Δ ที่นี่ไม่ใช่ Greek delta ของ options — มีตัวแปรตามหลังเสมอ (ดู notation หมวด 0) · γ (แกมมา) ในที่นี้คือ speed of adjustment (ความเร็วในการปรับตัว) ไม่ใช่ความกลัวความเสี่ยงหรือ Greek gamma ที่ใช้ตัวอักษรเดียวกันในเล่มอื่น · β ในวงเล็บคือ cointegrating vector ที่ได้จาก OLS ของ §9.1 และล็อกไว้ — สมการนี้ไม่ได้ประมาณ β ใหม่ มันประมาณแค่ γ กับพจน์ VAR (นี่คือวิธีสองขั้นของ Engle-Granger) · ค่าคงที่ c, c′ คือ drift ของ ΔB, ΔA — ควรใกล้ศูนย์เมื่อราคาไม่มีแนวโน้มและ spread หักค่าเฉลี่ย (α) ออกแล้ว

  2. สมการ ΔB — γB = −0.9053 (SE 0.0806 · t = −11.23) · พจน์ VAR: ΔAₜ₋₁ ได้ +0.1554 (t = 1.14) · ΔBₜ₋₁ ได้ −0.0363 (t = −0.63)
  3. สมการ ΔA — γA = +0.0559 (SE 0.0338 · t = +1.66) · พจน์ VAR: ΔAₜ₋₁ ได้ +0.0354 (t = 0.62) · ΔBₜ₋₁ ได้ −0.0390 (t = −1.61)
  4. ตรวจสมการ γB − β·γA = φ − 1 — −0.9053 − 1.5068 × 0.0559 = −0.9053 − 0.0842 = −0.9895 (คิดจากทศนิยมเต็มได้ −0.9896) · regress Δspread บนตัวแปรทางขวาชุดเดียวกันได้สัมประสิทธิ์ของ spreadₜ₋₁ = −0.9896 ตรงกันทุกหลัก — ไม่ใช่เรื่องบังเอิญ OLS เป็นเชิงเส้น regression ของ (ΔB − β·ΔA) จึงเท่ากับ regression ของ ΔB ลบ β คูณ regression ของ ΔA เสมอ · φ ที่ VECM บอกเป็นนัย = 1 − 0.9896 = 0.0104 → ครึ่งชีวิต −ln 2 / ln 0.0104 = 0.15 วัน

ประเด็นที่ต้องเห็นจากตัวเลขชุดนี้: ในข้อมูลจำลอง A คือ random walk ที่ไม่เคยดู B เลย (สร้างจาก cumsum ของ noise ล้วน) ค่าจริงของ γA จึงเป็น 0 และการปรับตัวทั้งหมดอยู่ที่ B · ตัวเลขบอกอย่างนั้นจริง: γA = 0.056 ± 0.034 ห่างศูนย์แค่ 1.66 SE ปฏิเสธ "ศูนย์" ที่ระดับ 5% ไม่ได้ ส่วน γB = −0.91 ± 0.08 ห่างศูนย์ 11 SE · และค่าจริงของ γB (คิดจาก β = 1.5 ที่ใช้สร้างข้อมูล) ไม่ใช่ −0.97 แต่คือ −1 — เพราะ B วันนี้ = 5 + 1.5·A วันนี้ + noise ใหม่ spread เมื่อวานจึงหายไปทั้งหมดในวันเดียว (φ จริง = 0 ตรงกับ "ครึ่งชีวิต 0.2 วัน" ที่ §9.1 บอกว่าเป็นไปไม่ได้) · ค่าประมาณ −0.9053 ห่างจาก −1 อยู่ 1.2 SE ส่วน "−0.97" ที่คำนวณจาก φ̂ = 0.0339 ก็เป็นแค่ค่าประมาณของ 0 อีกตัวหนึ่ง

🐍 Python — VECM ด้วย OLS ธรรมดา บนคู่ A/B ของ §9.1
# pip install numpy · ของจริงใช้ statsmodels.tsa.vector_ar.vecm.VECM(...) และ coint_johansen(...)
# โค้ดนี้ทำด้วย lstsq เพื่อให้เห็นว่า VECM สองขั้นคือ OLS ธรรมดา ไม่มีอะไรซ่อน
import numpy as np

rng = np.random.default_rng(0)                        # ★ seed เดียวกับ §9.1 — ข้อมูลชุดเดียวกันเป๊ะ
n = 500
A = 100 + np.cumsum(rng.normal(0, 1, n))
B = 5.0 + 1.5*A + rng.normal(0, 2, n)

beta, alpha = np.polyfit(A, B, 1)                     # ขั้น 1: β จาก OLS (§9.1) แล้วล็อกไว้
spread = B - (alpha + beta*A)
dA, dB = np.diff(A), np.diff(B)

X = np.column_stack([np.ones(n-2), spread[1:-1], dA[:-1], dB[:-1]])   # [1, spread_{t-1}, ΔA_{t-1}, ΔB_{t-1}]
def ols(y):
    b = np.linalg.lstsq(X, y, rcond=None)[0]
    e = y - X@b
    se = np.sqrt(e@e/(len(y)-X.shape[1]) * np.diag(np.linalg.inv(X.T@X)))
    return b, b/se
bB, tB = ols(dB[1:])                                  # ขั้น 2: สมการ ΔB_t
bA, tA = ols(dA[1:])                                  #         สมการ ΔA_t — ตัวแปรทางขวาชุดเดียวกัน
print(f"γ_B = {bB[1]:+.4f} (t = {tB[1]:+.2f})   γ_A = {bA[1]:+.4f} (t = {tA[1]:+.2f})")
# γ_B = -0.9053 (t = -11.23)   γ_A = +0.0559 (t = +1.66)
print(f"พจน์ VAR ใน ΔB: a(ΔA_t-1) = {bB[2]:+.4f} (t = {tB[2]:+.2f})  a(ΔB_t-1) = {bB[3]:+.4f} (t = {tB[3]:+.2f})")
# พจน์ VAR ใน ΔB: a(ΔA_t-1) = +0.1554 (t = +1.14)  a(ΔB_t-1) = -0.0363 (t = -0.63)
print(f"พจน์ VAR ใน ΔA: a(ΔA_t-1) = {bA[2]:+.4f} (t = {tA[2]:+.2f})  a(ΔB_t-1) = {bA[3]:+.4f} (t = {tA[3]:+.2f})")
# พจน์ VAR ใน ΔA: a(ΔA_t-1) = +0.0354 (t = +0.62)  a(ΔB_t-1) = -0.0390 (t = -1.61)

ident = bB[1] - beta*bA[1]                            # ★ γ_B − β·γ_A ควรเท่ากับ φ − 1 ของ spread
bS, _ = ols(np.diff(spread)[1:])                      # regress Δspread บนตัวแปรชุดเดียวกัน
print(f"γ_B − β·γ_A = {ident:+.4f}   |  φ−1 ของ Δspread (ตัวแปรชุดเดียวกัน) = {bS[1]:+.4f}")
# γ_B − β·γ_A = -0.9896   |  φ−1 ของ Δspread (ตัวแปรชุดเดียวกัน) = -0.9896
phi = 1 + ident
print(f"φ ที่ VECM บอกเป็นนัย = {phi:.4f} → ครึ่งชีวิต = {-np.log(2)/np.log(abs(phi)):.2f} วัน  (§9.1: φ = 0.0339 → 0.20 วัน)")
# φ ที่ VECM บอกเป็นนัย = 0.0104 → ครึ่งชีวิต = 0.15 วัน  (§9.1: φ = 0.0339 → 0.20 วัน)

  • พจน์ VAR ทั้งสี่ตัวไม่มีนัยสำคัญ (|t| < 1.7 ทุกตัว) — ΔA เป็น white noise โดยสร้าง จึงไม่มีอะไรพยากรณ์มันได้ และ ΔB ก็ไม่มีอะไรพยากรณ์ได้นอกจาก spread เมื่อวาน · ความสามารถในการพยากรณ์ทั้งหมดอยู่ใน error-correction term — นี่คือคำนิยามของ "pairs trading ทำงานได้" ในภาษา VECM: ราคาแต่ละตัวทำนายไม่ได้ (§8.6) แต่ระยะห่างทำนายได้
  • สองครึ่งชีวิต 0.15 กับ 0.20 วัน อยู่ในช่วงคลาดเคลื่อนของกันและกัน — φ̂ สองตัว (0.0104 กับ 0.0338) ต่างกัน 0.023 ขณะที่ SE ของมันคือ 0.062 (VECM) กับ 0.045 (AR(1)) จึงแยกจากกันและจากศูนย์ไม่ได้ · ที่ต่างกันในหลักที่สองเพราะพจน์ VAR ทางขวา ไม่ใช่เพราะโมเดลตัวหนึ่งผิด · และครึ่งชีวิตที่คิดจาก φ̂ ใกล้ศูนย์ก็ไวต่อ φ̂ มาก (−ln 2 / ln φ̂ เปลี่ยนเร็วเมื่อ φ̂ เข้าใกล้ 0) · ทั้งสองตัวเลข "เป็นไปไม่ได้ในโลกจริง" ตามที่ §9.1 วินิจฉัยไว้ — VECM ไม่ได้ทำให้ข้อมูลปลอมกลายเป็นของจริง มันแค่บอกเพิ่มว่าความปลอมนั้นอยู่ที่ขา B
  • อย่าอ่านเครื่องหมายของ γA — มันเป็นบวก (ทิศที่ "ถูก" ถ้า A ปรับตัว) แต่ที่ t = 1.66 เครื่องหมายนั้นคือ noise · สัมประสิทธิ์ที่ไม่มีนัยสำคัญไม่มีทิศ มีแต่ "ยังไม่รู้"

ตัวเลขข้างบนคือกรณีที่ง่ายที่สุด — ขาเดียวปรับ อีกขาไม่รู้เรื่อง · ของจริงมักอยู่ระหว่างกลาง และคำถามที่ต้องถามก่อนเชื่อ γ ตัวไหนก็ตามคือสามข้อข้างล่าง

✅ ใช้ได้เมื่อไร
  • ผ่านการทดสอบ cointegration ของ §9.1 ก่อน — VECM คือ "ขั้นที่ 4" ต่อจาก Engle-Granger สามขั้น ไม่ใช่ตัวแทนของขั้น 1–3 · ถ้า coint() ไม่ผ่าน ห้ามใส่ error-correction term
  • ทุกอนุกรมเป็น I(1) และ β คงที่ตลอดช่วง — วิธีสองขั้น (OLS หา β แล้ว OLS หา γ) ยืนอยู่บนข้อนี้ทั้งตัว
  • เลือกจำนวน lag อย่างมีเหตุผล — เริ่มที่ 1 เสมอ · ถ้าจะเพิ่ม ใช้ AIC/BIC แบบกล่องเจาะลึกของ §8.5 บน VAR ของผลต่าง แล้วล็อกไว้ก่อน backtest
  • ข้อมูลยาวพอกับจำนวนพารามิเตอร์ — VAR(p) ของ k อนุกรมมี k²·p + k ตัว (2 อนุกรม 1 lag = 6 ตัว) บวก γ อีก k ตัว (รวม 8) · ตะกร้า 5 ตัว 2 lag = 55 + 5 ตัว ซึ่งข้อมูล 1 ปีเลี้ยงไม่ไหว
❌ พังเมื่อไร
  • ไม่ได้ cointegrated แต่ใส่ error-correction term อยู่ดี — spreadₜ₋₁ ของคู่ที่ไม่ cointegrated เป็น I(1) · เอาตัวแปรที่ไม่นิ่งไปวางทางขวาของ regression คือญาติสายตรงของ spurious regression ในบทเปิดก่อนบทที่ 8 · γ ที่ได้จะดูมีนัยสำคัญบ่อยกว่าที่ควร และ backtest จะสวยด้วยเหตุผลเดียวกับที่ R² = 0.818 ในบทเปิดสวย
  • β เลื่อน — γ ถูกประมาณจาก spread ที่คำนวณด้วย β ผิด จึงปน "ความสัมพันธ์ที่เปลี่ยน" เข้ากับ "การปรับตัว" จนแยกไม่ออก · แก้ด้วย β รายวันจาก §9.4 หรือ rolling β ก่อนค่อยหา γ
  • มากกว่า 2 อนุกรม — regression คู่เดียวขยายไม่ได้ ต้องใช้ Johansen test: ทดสอบว่า k อนุกรมมี cointegrating vector กี่ตัว (เรียกว่า rank r · ตั้งแต่ 0 ถึง k−1) แล้วประมาณทั้ง β และ γ พร้อมกันทั้งระบบ · ค่าวิกฤตของมันมีตารางเฉพาะ (trace / maximum eigenvalue) ใช้ตาราง ADF หรือ coint แทนไม่ได้ · ใน statsmodels คือ coint_johansen
  • Granger causality ≠ causality — a₂₁ (หรือ γB) มีนัยสำคัญบอกแค่ว่า "อดีตของ A ช่วยพยากรณ์ B" · ปัจจัยที่สามที่ A สะท้อนเร็วกว่า B (เช่นข่าวเดียวกันที่หุ้นสภาพคล่องสูงรับก่อน) ให้ผลหน้าตาเดียวกันโดยไม่มีเหตุ-ผลระหว่าง A กับ B เลย
  • โครงสร้างเปลี่ยนกลางทาง — ข้อแรกของ §9.3 ใช้กับ VECM เต็ม ๆ · วันที่ความสัมพันธ์ขาด γ ที่ประมาณจากอดีตจะบอกให้คุณคาดหวังการหุบที่ไม่มาถึง
⚖️ ข้อดี
  • ระบบเดียวตอบทั้ง "หุบเร็วแค่ไหน" และ "ขาไหนหุบ" — §9.1 ตอบได้แค่ข้อแรก
  • ได้ SE และ t ของ γ แต่ละขา ไม่ต้องเดาว่าตัวไหนเป็นตัวลาก
  • ขยายเป็นตะกร้า k ตัวด้วยโครงเดิม — เปลี่ยนแค่ขนาดของ X
  • เป็น OLS ธรรมดา (ตามโค้ด) ตรวจสอบเองได้ทุกตัวเลข
⚖️ ข้อเสีย
  • พารามิเตอร์โตตาม k² — ตะกร้าใหญ่ต้องการข้อมูลยาวกว่าที่ความสัมพันธ์จะอยู่ให้
  • วิธีสองขั้นถือว่า β̂ เป็นค่าแน่ — ในตัวอย่างสั้น SE ของ γ อาจแคบกว่าจริงเล็กน้อย (Engle-Granger แสดงว่าเมื่อข้อมูลยาว β̂ ลู่เข้าเร็วกว่าปกติจนปัญหานี้หายไป)
  • ต้องตัดสินใจเพิ่มสองอย่างที่ไม่มีคำตอบตายตัว (จำนวน lag · rank)
  • อธิบายให้คนอื่นเข้าใจยากกว่า "ครึ่งชีวิต 13 วัน" ตัวเดียว
🧠 มุมที่มองต่าง — cointegrated แปลว่าทั้งคู่ดึงกันกลับ?

มือใหม่เห็น: "cointegrated แปลว่าทั้งสองขา mean-revert — long ตัวถูก short ตัวแพง แล้วรอให้ทั้งคู่วิ่งเข้าหากัน"
quant เห็น: ขาที่ γ ไม่มีนัยสำคัญไม่ได้วิ่งหาใคร มันคือตัวลาก อีกขาคือตัววิ่งตาม · กำไรที่คาดหวังอยู่ที่ขาที่ γ มีนัยสำคัญ ส่วนอีกขาคือ hedge ที่ถือไว้กันทิศตลาด — มีไว้เพื่อไม่ขาดทุน ไม่ใช่เพื่อได้กำไร

📍 ปัจจุบันใช้จริง

VECM คือโมเดลมาตรฐานของ stat-arb หลายสินทรัพย์ — คู่หุ้นใช้วิธีสองขั้นแบบ Engle-Granger อย่างในโค้ด ตะกร้าใช้ Johansen เพื่อหาทั้ง rank และ cointegrating vector พร้อมกัน · เส้นทางที่ใช้ในงานจริงคือ statsmodels.tsa.vector_ar.vecm.VECM กับ coint_johansen (ให้ทั้ง γ, β, lag selection และการทดสอบ Granger ในชุดเดียว) ส่วนโค้ด lstsq ในหน้านี้มีไว้ให้เห็นว่าข้างในคือ OLS · มักทำบน log ราคาเพื่อให้ β อ่านเป็นอัตราส่วนมูลค่า · และในทางปฏิบัติมักจับคู่กับ β รายวันจาก §9.4 เพราะสมมติฐาน "β คงที่" คือจุดอ่อนที่รู้กันของวิธีนี้

9.5½ Johansen — เมื่อคู่ไม่พอ และตะกร้าที่ประหยัดขา

🚶 อ่านเป็นภาษาคนก่อน: §9.1 ทดสอบทีละคู่ · §9.5 บอกว่าเกินสองตัวต้องใช้ Johansen แล้วส่งคุณไป statsmodels · หัวข้อนี้เดินเลขให้ดูจริง ๆ ว่า Johansen ทำอะไร ด้วยตะกร้า 3 ตัวที่รู้คำตอบ และแสดงกรณีที่ทำให้มันจำเป็น: สามคู่ที่ทดสอบทีละคู่แล้วสอบตกทั้งหมด แต่ตะกร้าทั้งสามคือ cointegrated จริง · ปิดด้วยการ์ดสั้นเรื่องตะกร้าที่ "ประหยัดขา" (sparse portfolio) — เพราะตะกร้า 30 ตัวที่ทุกตัวมีน้ำหนักคือ 60 fills ต่อรอบ

VECM ของ k อนุกรม: Δyₜ = μ + Π yₜ₋₁ + (พจน์ VAR) + εₜ Π เป็นเมทริกซ์ k × k rank(Π) = r = จำนวน cointegrating vector r = 0 ไม่มีเลย · r = k ทุกตัวนิ่งอยู่แล้ว · 0 < r < k คือกรณีที่เทรดได้ Π = α βᵀ β (k × r) = เวกเตอร์ที่ทำให้ βᵀyₜ นิ่ง · α (k × r) = ความเร็วปรับตัวของแต่ละขา (γ ของ §9.5 ในรูปเมทริกซ์) trace statistic ทดสอบ H₀: rank ≤ r λ_trace(r) = −T Σ_{i > r} ln(1 − λ̂ᵢ) เทียบตารางค่าวิกฤตของ Johansen ไม่ใช่ตาราง ADF

📖 อ่านสูตรว่า: "เดลตา-วาย เท่ากับ มิว บวก พาย คูณ วาย เมื่อวาน บวก … บวก เอปไซลอน" — yₜ เป็นเวกเตอร์ราคาทั้ง k ตัว Π (พายใหญ่) เป็นเมทริกซ์ ไม่ใช่ 3.1416 · โครงที่ต้องเห็น: นี่คือ VECM ของ §9.5 ที่เขียนรวมทุกขา — บรรทัด Π = αβᵀ คือการแยก "ใครปรับ (α)" จาก "ปรับเข้าหาอะไร (β)" ซึ่ง §9.5 ทำด้วยมือทีละขา · rank ของ Π คือจำนวนความสัมพันธ์ระยะยาวที่ซ่อนอยู่ ตะกร้า k ตัวมีได้ตั้งแต่ 0 ถึง k − 1 (ถ้า rank = k ราคาทุกตัวนิ่งเอง ไม่ต้องทำ spread) · λ̂ᵢ คือ eigenvalue ของ reduced rank regression (regression แบบลดอันดับ) อ่านว่า "ความแรงของความสัมพันธ์ตัวที่ i" — ตัวที่ใกล้ 0 คือทิศที่ไม่นิ่ง · กับดักการอ่าน: λ ที่นี่เป็น eigenvalue ตัวเดียวกับ 2 · A §1.4 ในเชิงคณิต แต่มาจากเมทริกซ์คนละตัว: λ̂ᵢ คือ correlation ยกกำลังสองระหว่าง Δyₜ กับ yₜ₋₁ ในทิศที่ i (ไม่ใช่ variance ของราคา) จึงอยู่ใน [0, 1) และไม่ใช่เปอร์เซ็นต์ variance · trace statistic ทดสอบ "ไม่เกิน r" เรียงจาก r = 0 ขึ้นไป หยุดที่ค่าแรกที่ปฏิเสธไม่ได้ — อ่านผลจากบนลงล่าง ไม่ใช่เลือกแถวที่ชอบ · Σ_{i > r} คือรวมเฉพาะ eigenvalue ที่เล็กกว่า r ตัวแรก

🐍 Python — Johansen บนตะกร้าที่รู้คำตอบ
# pip install numpy statsmodels
import numpy as np
from statsmodels.tsa.vector_ar.vecm import coint_johansen
from statsmodels.tsa.stattools import coint

rng = np.random.default_rng(4); n = 500
A = 100 + np.cumsum(rng.normal(0, 1, n))           # เดินสุ่ม
B = 80 + np.cumsum(rng.normal(0, 1.2, n))          # เดินสุ่ม อิสระจาก A
u = rng.normal(0, 1, n); s = np.zeros(n)
for t in range(1, n): s[t] = 0.8 * s[t-1] + u[t]   # OU φ = 0.8
C = 10 + 0.5 * A + 0.8 * B + s                    # ★ ผูกกับทั้งสองตัว
Y = np.column_stack([A, B, C])

for i, j, nm in [(0, 1, "A,B"), (0, 2, "A,C"), (1, 2, "B,C")]:
    t, p, _ = coint(Y[:, i], Y[:, j]); print(f"คู่ {nm}: t = {t:.2f}  p = {p:.3f}")
# คู่ A,B: t = -0.96  p = 0.910   ← ทีละคู่ตกหมด
# คู่ A,C: t = -1.47  p = 0.773
# คู่ B,C: t = -1.83  p = 0.613

jo = coint_johansen(Y, det_order=0, k_ar_diff=0)  # det_order 0 = มีค่าคงที่ · k_ar_diff 0 = ไม่มีพจน์ VAR
print("eigenvalues", jo.eig.round(4))
print("trace      ", jo.lr1.round(2))                # H0: rank ≤ 0, ≤ 1, ≤ 2
print("crit 95%   ", jo.cvt[:, 1].round(2))
# eigenvalues [0.1082 0.0185 0.0024]
# trace       [67.65 10.49  1.18]
# crit 95%    [29.8  15.49  3.84]      → rank = 1
beta = jo.evec[:, 0] / -jo.evec[2, 0]             # ปรับให้ C = −1
print("β =", beta.round(3))                        # β = [ 0.488  0.733 -1.   ]   (จริง 0.5, 0.8, −1)

  • rank ที่ได้ขึ้นกับจำนวน lag และแบบของค่าคงที่ (k_ar_diff, det_order) — ตัวอย่างนี้ใช้ lag 1 ได้ trace 63.62 / 8.54 / 1.47 คำตอบเดิม แต่กับข้อมูลจริงมันพลิกได้ · ล็อกทั้งสองก่อนดูผล (บทเรียน AIC/BIC ของ §8.5) และรายงานว่า rank ทนต่อการเปลี่ยน lag ไหม
  • rank = 2 ในตะกร้า 3 ตัวไม่ได้แปลว่ามีสอง spread ให้เทรดแยกกัน — β สองคอลัมน์ไม่ unique (ผลรวมเชิงเส้นของมันก็เป็น cointegrating vector) ต้องเลือกโดยมีเหตุผลทางเศรษฐศาสตร์ ไม่ใช่เอาตามที่ eigenvector ออกมา
  • k ใหญ่ T สั้น — Π มี k² พารามิเตอร์ (บวก k² ต่อ lag ที่เพิ่ม) แต่ละสมการประมาณจาก T จุดเท่ากัน ตะกร้า 10 ตัว lag 2 บนข้อมูล 1 ปี = 30 พารามิเตอร์ต่อสมการจาก 250 จุด · ค่าวิกฤตในตารางเป็นค่าเชิงลิมิต (T → ∞) กับ T เล็กจะปฏิเสธบ่อยเกินจริง — ยิ่ง k/T ใหญ่ยิ่งบ่อย

เมื่อ rank = 1 ในตะกร้า 30 ตัว β ที่ประมาณได้จะมีน้ำหนักไม่เป็นศูนย์แทบทุกตัวจาก 30 ตัว — และนั่นคือปัญหาถัดไป

Sparse mean-reverting portfolio — ตะกร้าที่ประหยัดขา d'Aspremont 2011 ★★ ควรรู้

🎯 Thesis

"Johansen และ Box-Tiao ให้ตะกร้าที่นิ่งที่สุดโดยไม่สนว่าใช้กี่ตัว · ของจริงทุกตัวที่มีน้ำหนักคือสอง fills ต่อรอบ ค่ายืมหุ้น และความเสี่ยงที่ตัวนั้นเปลี่ยนพฤติกรรม — ตะกร้าที่นิ่งกว่า 5% แต่ใช้หุ้น 30 ตัวแทน 4 ตัว แพ้หลังหักต้นทุน · sparse portfolio คือการใส่เงื่อนไข 'ใช้ได้ไม่เกิน k ตัว' เข้าไปในการหาตะกร้าที่นิ่ง"

❓ ทำไมต้องรู้จัก — คำถามที่ค้างจากบทนี้

§9.3 คำนวณไว้ว่า pairs 21 เทรดคือ 84 fills และต้นทุน 25 bps กินกำไรไปครึ่ง · ตะกร้า Johansen 30 ตัวคือ 60 fills ต่อรอบ และ β 30 ตัวที่ประมาณจากข้อมูลจำกัดแต่ละตัวมีช่วงความเชื่อมั่นของตัวเอง (2 · C §6.4) · ตะกร้าที่ "นิ่งที่สุดในตัวอย่าง" จึงมักเป็นตะกร้าที่ overfit ที่สุดและแพงที่สุดพร้อมกัน · sparse คือคำตอบของคำถาม "ตัดเหลือกี่ตัวแล้วยังนิ่งพอ"

  • อ่าน ACF ออก และรู้ว่า φ = 1 คือเส้นแบ่งระหว่างเทรดได้กับเทรดไม่ได้
  • รู้ว่า ARIMA ทำนายราคาหุ้นไม่ได้ — และรู้ว่าควรใช้กับอะไรแทน
  • ทดสอบ cointegration ครบ 3 ขั้น และสร้างสัญญาณ pairs trading จาก z-score ได้
  • รู้ว่ากลยุทธ์นี้เจ๊งได้ยังไง — และทำไม stop ถึงจำเป็น

AR(1)E[xt | xt−1] = φ·xt−1 — พรุ่งนี้คือสัดส่วน φ ของวันนี้อดีตก่อน t−1 (มีผลผ่าน xt−1 เท่านั้น) · ความผันผวนที่เปลี่ยน
Random walk (φ = 1)E[Pt+1 | อดีต] = Pt — ราคาวันนี้คือพยากรณ์ที่ดีที่สุดทุกอย่าง — อดีตไม่ช่วยเลย
OUE[dx | x] = θ(μ − x)dt — แรงดึงกลับตามระยะห่างจาก μμ ที่อาจเลื่อน (regime) · กระโดด

VECME[ΔBt | ΔAt−1, ΔBt−1, spreadt−1] — ขาหนึ่งของระบบ อีกขาคือ E[ΔAt | ตัวเดียวกัน] · ตัวคูณของ spreadt−1 คือ γการเปลี่ยนของ β เอง (§9.4) · ตัวแปรภายนอก · จำนวน lag ที่ถูก
