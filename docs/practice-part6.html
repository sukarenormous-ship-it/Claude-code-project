6.1 ทวน z-score band — จุดตั้งต้นที่ทุกคนใช้

Part I §1.2 แนะนำ spread = A − β×B แล้ว · z-score band คือวิธีตัดสินใจเข้า-ออกที่ง่ายที่สุด:

z = (spread − mean) / std

z > +2 → short spread (spread แพงเกินไป คาดว่าจะกลับลง)
z < −2 → long spread (spread ถูกเกินไป คาดว่าจะกลับขึ้น)
z ≈ 0 → ปิดสถานะ (spread กลับสู่ปกติแล้ว)
🚶 อ่านเป็นภาษาคนก่อน

z-score บอกว่า "วันนี้ spread ห่างจากปกติกี่ SD" — ที่ ±2σ มักถูกเลือกเพราะในโลกที่ spread แจกแจงแบบ normal โดยประมาณ มีโอกาสแค่ ~5% ที่จะเจอค่าไกลขนาดนี้โดยบังเอิญ (สถิติล้วน ๆ ไม่เกี่ยวกับต้นทุนการเทรดเลย)

📉 จุดอ่อนของ z-score band — มันไม่รู้จักต้นทุน

±2σ มาจากสถิติ ไม่ใช่เศรษฐศาสตร์ — มันไม่รู้ว่าคุณเสียค่าคอมฯ เท่าไร เสีย spread เท่าไร หรือคู่นี้ vol สูง/ต่ำแค่ไหน คู่ vol ต่ำมาก ±2σ อาจแคบมาก (คุ้มค่าคอมฯ ไม่พอ) ส่วนคู่ vol สูงมาก ±2σ อาจกว้างเกินจำเป็น (พลาดโอกาสเข้าดี ๆ)

6.2 ★ ATR band → จริง ๆ คือ "Cost-Aware Band"

ไอเดียดั้งเดิม: ใช้ ATR (Average True Range) กั้นแบนด์แทน z-score — สัญชาตญาณนี้ถูก band ควรกว้างพอให้ spread ที่ถ่างออก "คุ้มค่าคอมฯ + เหลือกำไร" แต่ต้องแก้ 2 จุดให้ตรงหลัก

จุดแก้ที่ 1 — คำนวณ ATR บน spread ไม่ใช่ราคาดิบ

🚶 อ่านเป็นภาษาคนก่อน

ATR วัด "ระยะวิ่งเฉลี่ยต่อวัน" ของสิ่งที่คุณกำลังเทรด — สิ่งที่คุณเทรดคือ spread (A − β×B) ไม่ใช่ราคา A หรือ B เดี่ยว ๆ ถ้าคำนวณ ATR จากราคาดิบของขาใดขาหนึ่ง คุณกำลังวัดความผันผวนของสิ่งที่ไม่ได้เทรด — เหมือนวัดความสูงของคลื่นทะเล เพื่อทำนายว่าเรือลำหนึ่งจะโคลงแค่ไหน ทั้งที่จริง ๆ ต้องวัด "ความต่างระดับน้ำระหว่างหัวเรือกับท้ายเรือ"

จุดแก้ที่ 2 — เป้าหมายคือ band ≥ round-trip cost + edge

คำถามที่ถูกไม่ใช่ "ATR ของ spread เท่าไร" (แค่ตัวเลขสถิติ) แต่คือ "spread ต้องถ่างแค่ไหน ถึงจะคุ้มค่าคอมฯ ไป-กลับ แล้วยังเหลือกำไร"

🧮 ตัวอย่างเชิงตัวเลข (สมมติ เพื่อให้เห็นภาพ)

สมมติเทรด 1 คู่ ทุน 100,000 บาท:

ค่าคอมฯ ไป-กลับ (2 ขา × 2 รอบ) ≈ 0.20% ของทุน
Bid-ask spread ทั้ง 2 ขา ≈ 0.15% ของทุน
กำไรขั้นต่ำที่อยากได้ (edge) ≈ 0.30% ของทุน
─────────────
Band ขั้นต่ำที่ต้องถ่าง ≈ 0.65% ของทุน

ถ้า ATR ของ spread คู่นี้ (แปลงเป็น % ของทุน) วิ่งเฉลี่ยแค่ 0.30% ต่อวัน — z=±2σ อาจถ่างไม่ถึง 0.65% เลย = เทรดแล้วไม่คุ้มค่าคอมฯ ตั้งแต่ต้น ไม่ว่า z-score จะดูสวยแค่ไหน

✍️ ลองคิดเอง

ถ้าคู่ A มี ATR ของ spread สูงกว่าคู่ B ถึง 3 เท่า — band ขั้นต่ำที่ควรใช้ของคู่ A ควรกว้างกว่าคู่ B ไหม? (ไม่จำเป็น! ต้นทุน round-trip cost มักไม่ได้ขึ้นกับ ATR — คู่ A อาจแค่ "ต้องการ SD น้อยกว่าเพื่อชน band เดียวกัน" สิ่งที่ควรเทียบคือ band ขั้นต่ำ ≈ cost คงที่ vs ATR ที่ต่างกัน ไม่ใช่ปรับ band ตาม ATR โดยตรง)

6.3 ★ Optimal Threshold — ไม่ต้องเดา มีทฤษฎีรองรับ

ตัวอย่างเชิงตัวเลขข้างบนคือ "cost-aware" แบบหยาบ — มีงานวิจัยที่ทำเรื่องนี้อย่างเข้มงวดกว่า: Leung & Li (2015) โมเดล spread เป็น OU process (Part I §1.7) แล้วแก้โจทย์ optimal stopping หา entry/exit threshold ที่ทำกำไรคาดหวังสูงสุดหลังหักต้นทุนต่อรอบ

🚶 อ่านเป็นภาษาคนก่อน

แทนที่จะเดา band จาก "สถิติ" (z-score) หรือ "กฎมือ" (ATR แบบง่าย) — โจทย์นี้ถามตรง ๆ ว่า: "ถ้าฉันรู้ว่า spread นิ่งขนาดไหน (κ), แกว่งแค่ไหน (σ), และเสียต้นทุนต่อรอบเท่าไร (c) — เข้า-ออกตรงไหนถึงจะทำกำไรคาดหวังมากที่สุดในระยะยาว" คำตอบออกมาเป็นสูตร ไม่ใช่การเดา

รูปร่างของคำตอบ (ผลเชิงคุณภาพที่ต้องจำ)
  • ต้นทุนสูงขึ้น → band ต้องกว้างขึ้น (สมเหตุผล — ยิ่งเสียเยอะ ยิ่งต้องรอ mispricing ใหญ่กว่าเดิม)
  • mean-reversion เร็วขึ้น (κ สูง, half-life สั้น) → band แคบลงได้ (spread กลับเร็ว ไม่ต้องรอไกลก็กลับ)
  • threshold ที่ได้ไม่ใช่ค่าคงที่สากล — เป็นฟังก์ชันของพารามิเตอร์เฉพาะคู่นั้น ๆ
⚠️ ข้อจำกัดที่ต้องซื่อสัตย์

วิธีนี้ต้องการ ประมาณ κ, σ, c ให้แม่น — ถ้าประมาณ half-life ผิด (ย้อนไปดู notebook 02: half-life ประมาณจากข้อมูลจำลอง 1,000 จุดยังคลาดเคลื่อนเกือบครึ่ง!) threshold "optimal" ที่คำนวณได้ก็ผิดตามไปด้วย — ความแม่นยำของ output ไม่มีวันดีกว่าความแม่นยำของ input

6.4 เทียบ 3 วิธี — เลือกใช้เมื่อไร

z-score bandCost-aware / ATR bandOptimal OU-cost threshold
คิดจากสถิติล้วน (SD)สถิติ + cost หยาบ ๆOU parameters + cost เต็มรูป
รู้จักต้นทุนไหม❌ ไม่รู้จัก✅ รู้จักคร่าว ๆ✅✅ ผูกโดยตรง
ทำง่ายแค่ไหนง่ายสุดง่ายต้องประมาณ κ,σ,c แม่น
ใช้เมื่อไรสำรวจเบื้องต้น / คู่ที่ยังไม่มั่นใจใช้งานจริงระดับรายย่อย ส่วนใหญ่พอคู่ที่เทรดจริงจัง มี capital มากพอจะคุ้มลงทุนเวลาประมาณค่า
⚠️ ธงกันโม้ (สำคัญ — อย่าให้ใครหลอกด้วยตัวเลขลอย)

คุณอาจเคยได้ยินคำกล่าวอ้างแบบ "เปลี่ยนมาใช้ cost-aware band แล้วเทรดลด 60-80% กำไรสุทธิสูงขึ้น" — ตัวเลขแบบนี้ต้องพิสูจน์ด้วย backtest ของคุณเองเท่านั้น มันขึ้นกับคู่ที่เทรด ต้นทุนจริงของคุณ และ volatility regime ตอนนั้น ไม่ใช่ค่าคงที่สากล — ใครอ้างตัวเลขนี้ลอย ๆ โดยไม่โชว์โค้ด/ข้อมูลที่มาที่ไป ให้สงสัยไว้ก่อน (โยง Part IX เรื่อง backtest ที่ไม่โกหก)

6.5 Band คงที่ vs Band ปรับตัว

อีกมิติที่ต้องตัดสินใจ: band ควรคงที่ตลอด หรือปรับตามเวลา?

Band คงที่
  • เข้าใจง่าย ทำนายได้ ไม่กระตุก
  • เหมาะกับคู่ที่ volatility ค่อนข้างนิ่ง
Band ปรับตัว (rolling ATR/vol)
  • ตามทัน volatility regime ที่เปลี่ยน
  • ⚠️ เสี่ยง look-ahead ถ้าคำนวณไม่ระวัง (ต้องใช้ข้อมูลถึงเมื่อวานเท่านั้น) — เหมือนกับดักที่ Part I §1.6 เตือนเรื่อง rolling window
🧠 มุมที่ quant มองต่าง

คนทั่วไปเห็น: "band กว้างกว่า = ปลอดภัยกว่า"
quant เห็น: band ที่ "ถูกต้อง" ไม่ใช่กว้างสุดหรือแคบสุด — แต่คือ band ที่สะท้อนต้นทุนจริงของคุณ band แคบเกินไป = เทรดถี่จนค่าคอมฯ กินกำไร · band กว้างเกินไป = พลาดโอกาสดี ๆ ที่แท้จริงคุ้มเทรด

✓ 3 อย่างที่ต้องจำจาก Part VI
  1. ATR/cost-aware band = สัญชาตญาณถูก แต่ต้องคำนวณบน spread (ไม่ใช่ราคาดิบ) และเป้าหมายคือชนะ round-trip cost
  2. Optimal OU-cost threshold มีทฤษฎีรองรับ (Leung-Li 2015) — แต่แม่นได้แค่ที่ input (κ,σ,c) แม่น
  3. ตัวเลขผลลัพธ์เชิงพาณิชย์ต้องพิสูจน์เอง — ไม่มีค่าคงที่สากลที่ใช้ได้ทุกคู่ทุกตลาด

ทุกอย่างที่ผ่านมา (β ดี, band ที่คำนวณถูก) ตั้งอยู่บนสมมติฐานเงียบ ๆ ข้อหนึ่ง: ความสัมพันธ์ระหว่าง A กับ B ยังคงอยู่ — แต่ถ้าวันหนึ่งมันเลิกคงอยู่แล้วล่ะ? band ที่คำนวณมาสวยแค่ไหนก็ช่วยไม่ได้ ถ้า spread ที่ "ควรกลับ" ไม่มีวันกลับอีกแล้ว

"band บอกว่าเมื่อไรควรเข้า — แต่ไม่เคยบอกว่าเมื่อไรควรเลิกเชื่อว่ามันจะกลับ"
📖 ศัพท์ใหม่ในตอนนี้
  • Round-trip cost — ต้นทุนรวมของการเข้า+ออกสถานะ 1 รอบ (ค่าคอมฯ + spread + ค่ายืมช็อต)
  • Cost-aware band — band ที่กำหนดโดยผูกกับต้นทุนจริง ไม่ใช่แค่สถิติ (SD)
  • Optimal stopping — กรอบคณิตศาสตร์หาจุดตัดสินใจ (เข้า/ออก) ที่เหมาะสมที่สุดภายใต้เงื่อนไข
