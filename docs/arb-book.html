บทที่ 1: Arbitrage คืออะไร?

1.1 นิยาม

Arbitrage = การทำกำไรจากความแตกต่างของราคาสินทรัพย์เดียวกัน โดยไม่มีความเสี่ยงและไม่ใช้เงินทุนสุทธิ (หรือใช้น้อยมาก)

ตัวอย่างง่ายที่สุด

ร้านทอง A ขายทองแท่ง ฿30,000 / บาท
ร้านทอง B รับซื้อทองแท่ง ฿30,500 / บาท
→ ซื้อที่ A ฿30,000 → ขายที่ B ฿30,500 → กำไร ฿500 ทันที ไม่มีความเสี่ยง

Arb อยู่รอบตัว — ไม่ใช่แค่ในตลาดหุ้น!

ตั๋วคอนเสิร์ต: ซื้อตั๋วราคาหน้าเว็บ ฿2,000 → ขายต่อวันงาน ฿5,000 (แต่เสี่ยง: คอนเสิร์ตอาจยกเลิก)
iPhone ข้ามประเทศ: ซื้อญี่ปุ่น ฿28,000 → ขายไทย ฿32,000 (แต่มี: ค่าส่ง ฿500 + ภาษี ฿1,000 + เวลา 5 วัน)
Bitcoin ข้าม Exchange: ซื้อ Bitkub ฿2,100,000 → ขาย Binance ฿2,103,000 (แต่: ค่าถอน + เวลาโอน 10 นาที ราคาอาจเปลี่ยน)

สังเกต: ทุกตัวอย่างมี "แต่" — ค่าธรรมเนียม เวลา ความเสี่ยง → นี่คือเหตุผลที่ arb ไม่ได้ "ฟรี" จริงๆ

1.2 No-Arbitrage Principle

ถ้ามี Arbitrage opportunity → คนจะรีบทำ → ราคาจะ converge จนหมดโอกาส

  • ซื้อที่ A มาก → ราคา A ขึ้น (demand สูง)
  • ขายที่ B มาก → ราคา B ลง (supply สูง)
  • จนกว่า A ≈ B → Arb หายไป
No-Arbitrage Principle

"ในตลาดที่ทำงานปกติ Arbitrage opportunity จะหายไปอย่างรวดเร็ว เพราะ arbitrageurs เข้ามาทำกำไรจนราคา converge"

ผลลัพธ์: ถ้าสมมติว่าไม่มี arb → เราสามารถ หาราคาที่ถูกต้อง ของทุกสินทรัพย์ได้ (No-Arbitrage Pricing)

1.3 Law of One Price

"สินทรัพย์ที่ให้ payoff เดียวกันทุกสถานการณ์ → ต้องมีราคาเดียวกัน"

  • ทองที่ร้าน A = ทองที่ร้าน B → ราคาต้องเท่ากัน
  • Long Call + Short Put + Bond = Stock → ราคาต้องเท่ากัน (Put-Call Parity!)
  • SET50 Futures ≈ SET50 Spot × e^((r-d)T) → ราคาต้องสอดคล้องกัน
วิธีใช้ Law of One Price หา Arb

ทุกครั้งที่เห็นสินทรัพย์ ถามตัวเองว่า:
"มีวิธีอื่นสร้าง payoff เดียวกันไหม? ถ้ามี ราคาเท่ากันไหม?"
ถ้าราคาต่างกัน → อาจมี Arb!

บทที่ 2: เครื่องมือพื้นฐาน

2.1 Short Selling — ยืมมาขาย

"ซื้อถูกขายแพง" ทุกคนเข้าใจ แต่ Arb ต้องทำได้ทั้ง 2 ทิศ — ต้อง "ขายก่อนซื้อ" ได้ด้วย

Short Selling: ยืมหุ้นมา → ขาย → ซื้อคืนทีหลัง (หวังว่าราคาจะลง)
กำไร = ราคาขาย - ราคาซื้อคืน - ค่ายืม (borrow cost)
ทำไม Short Selling สำคัญสำหรับ Arb?

Arb ส่วนใหญ่ต้องทำ 2 ขาพร้อมกัน: ซื้อที่ถูก + ขายที่แพง
ถ้า "ที่แพง" คือสินทรัพย์ที่ยังไม่มี → ต้อง short sell
เช่น Conversion: Long Stock + Long Put + Short Call ← ต้อง "ขาย" Call ที่ไม่มี

ความเสี่ยงของ Short Selling

ขาดทุนไม่จำกัด: ราคาขึ้นได้ไม่มีเพดาน แต่คุณต้องซื้อคืน
Margin Call: ถ้าราคาขึ้นมาก broker อาจบังคับให้วางเงินเพิ่มหรือปิดสถานะ
Recall Risk: เจ้าของหุ้นอาจขอคืนเมื่อไรก็ได้ → ต้องหาหุ้นยืมใหม่หรือปิดสถานะ
Borrow Cost: ต้องจ่ายค่ายืมหุ้นทุกวัน → กิน profit ของ arb

2.3 Transaction Costs — ศัตรูตัวฉกาจของ Arb

Net Profit = Gross Arb
  − Commission (ค่านายหน้า ทุกขา)
  − Bid-Ask Spread (ซื้อที่ ask ขายที่ bid)
  − Slippage (ราคาเปลี่ยนระหว่าง execute)
  − Borrow Cost (ถ้า short sell)
  − Margin Interest (ถ้าใช้ leverage)
  − Funding Cost (ถ้าใช้ perpetual)
กฎทอง: คิดค่าใช้จ่ายก่อนเสมอ!

Arb ที่ดูเหมือนกำไร ฿0.80 อาจขาดทุนจริง ฿0.10 หลังหักค่าใช้จ่าย
มือใหม่ลืมคิด bid-ask spread บ่อยที่สุด — ต้องซื้อที่ Ask ขายที่ Bid ไม่ใช่ราคากลาง!

2. มี arb opportunity net ฿500 แต่ต้อง trade 4 ขา commission ขาละ ฿50 bid-ask ขาละ ฿80 → Net เท่าไร? คุ้มไหม?

บทที่ 3: คณิตศาสตร์ของ Arbitrage

3.1 No-Arbitrage Pricing

ถ้าสมมติว่าไม่มี arb → เราสามารถหาราคาที่ถูกต้องของทุกสินทรัพย์ได้

หลักการ

ถ้า Portfolio A และ Portfolio B ให้ payoff เท่ากันทุกสถานการณ์ ณ เวลา T:
→ ราคาวันนี้ต้องเท่ากัน
ถ้าไม่เท่ากัน → ซื้อถูก ขายแพง = Arbitrage

3.2 Replication Principle

"ราคาที่ถูกต้องของ X = ต้นทุนในการสร้าง X ขึ้นมาเอง (replicate)"

สินทรัพย์ XReplicate ด้วยสมการ

CallLong Stock + Long Put - BondC = S + P - PV(K)

3.3 Bounds & Inequalities

แม้ไม่รู้ราคา exact แต่รู้ขอบเขตที่ราคาต้องอยู่ภายใน:

Call Bounds: max(0, S - Ke⁻ʳᵀ) ≤ C ≤ S
Put Bounds: max(0, Ke⁻ʳᵀ - S) ≤ P ≤ Ke⁻ʳᵀ
Spread: 0 ≤ C(K₁) - C(K₂) ≤ (K₂-K₁)e⁻ʳᵀ เมื่อ K₁ < K₂
Butterfly: C(K₁) - 2C(K₂) + C(K₃) ≥ 0 (Convexity)
วิธีใช้ Bounds หา Arb

1. คำนวณ bounds ก่อนดูราคาจริง
2. ดูราคาจริง → อยู่ในหรือนอก bounds?
3. นอก bounds = Arb ที่พิสูจน์ได้ทางคณิตศาสตร์ [Exact Identity]
4. ใกล้ขอบ bounds = อาจเป็น Near-Arb หลังหักค่าธรรมเนียม

3.4 Put-Call Parity — สมการเริ่มต้นของทุกอย่าง

C + K·e⁻ʳᵀ = P + S
e⁻ʳᵀ คืออะไร?

e⁻ʳᵀ = "ตัวคูณลดค่า" (discount factor) — แปลงเงินในอนาคตเป็นมูลค่าวันนี้
ตัวอย่าง: K=100, r=5%, T=1 ปี → K·e⁻ʳᵀ = 100 × 0.9512 = ฿95.12
หมายความว่า: เงิน ฿100 ในอีก 1 ปี = เงิน ฿95.12 วันนี้ (เพราะฝาก 95.12 ดอกเบี้ย 5% จะได้ 100 พอดี)
อ่านละเอียดเพิ่มเติมในเล่ม "คณิตศาสตร์สำหรับ Options" บทที่ 3

สมการนี้คือ Law of One Price ของ Options (สำหรับ European Options ที่ไม่มี dividend, สมมติ short sell ได้และกู้ยืมที่ rate r ได้):

  • ซ้าย (Long Call + Bond) ให้ payoff = ขวา (Long Put + Stock) ทุกสถานการณ์
  • ถ้าซ้าย ≠ ขวา → ซื้อฝั่งถูก ขายฝั่งแพง = Conversion/Reversal Arbitrage
  • เป็น [Exact Identity] — จริงเสมอ ไม่มีเงื่อนไข (European options)
Epistemology Label: [Exact Identity]

Put-Call Parity เป็นความจริงทางคณิตศาสตร์ — ไม่ขึ้นกับ model, regime, หรือ platform
ต่างจาก "Funding rate จะกลับมา" ซึ่งเป็นแค่ [Heuristic] — จะเรียนการจำแนกในบทที่ 6

ลองคิดดู (บท 3)

1. C=12, P=7, S=100, K=100, r=2%, T=1 → PV(K) = 100×e⁻⁰·⁰² = 98.02 → ซ้าย=12+98.02=110.02 ขวา=7+100=107 → มี arb ไหม? ทำอย่างไร?
2. Call K=90 ราคา ฿15, Call K=100 ราคา ฿16 → ผิดปกติตรงไหน? (คำใบ้: monotonicity)
เฉลย: 1. ซ้าย>ขวา ฿3.02→Conversion (ซื้อขวา ขายซ้าย) 2. C(90)=15 < C(100)=16 → ผิด monotonicity! K ต่ำกว่าต้องแพงกว่า→ซื้อ C(90) ขาย C(100)

บทที่ 4: หลักการคิดแบบ Arbitrageur

บทนี้ไม่ได้สอนสูตร — สอนวิธีมองโลกที่ทำให้เห็น Arb ที่คนอื่นมองไม่เห็น

4.1 หลักการที่ 1: "ของเดียวกันต้องราคาเดียวกัน"

ทุกครั้งที่เห็นสินทรัพย์ ถามว่า: "มีวิธีอื่นสร้าง payoff เดียวกันไหม? ราคาเท่ากันไหม?"

ฝึก

เห็น SET50 Futures → ถามทันที: "Spot × e^((r-d)T) เท่าไร? ตรงกับ Futures price ไหม?"
เห็น Call K=100 → ถามทันที: "P + S - PV(K) เท่าไร? ตรงกับ Call price ไหม?"

4.2 หลักการที่ 2: "ถ้าสร้างเองได้ = รู้ราคา"

ราคาที่ถูกต้อง = ต้นทุน replicate ถ้าราคาจริง ≠ ต้นทุน replicate → opportunity

4.3 หลักการที่ 3: "ได้อะไรมาต้องเสียอะไรไป"

ถ้าเจอ "กำไรแน่นอน 5% ต่อวัน" → 99% มี risk ซ่อนอยู่

Devil's Advocate Checklist

เจอ "arb" แล้วถามตัวเอง 6 ข้อ:
1. ข้อมูลผิดหรือเปล่า? (stale quote, wrong symbol)
2. ค่าธรรมเนียมคิดครบไหม?
3. Liquidity จริงไหม? (bid-ask wide, size เล็ก)
4. Execute ได้ทั้ง 2 ขาพร้อมกันไหม?
5. มี structural reason ไหม? (ex-div, corporate action)
6. ทำไมคนอื่นไม่ทำ? ← ข้อสำคัญที่สุด

4.4 หลักการที่ 4: "ไม่รู้ exact แต่รู้ขอบเขต"

ราคานอกขอบเขต = Arb ที่พิสูจน์ได้ เช่น Call ≥ max(0, S-Ke⁻ʳᵀ) ← ถ้า Call < ค่านี้ → ซื้อทันที

4.5 หลักการที่ 5: "ลำดับต้องถูก"

Monotonicity: C(K₁) ≥ C(K₂) เมื่อ K₁ < K₂ ← Call ถูกลงเมื่อ Strike สูงขึ้น
Convexity: C(K₁) - 2C(K₂) + C(K₃) ≥ 0 ← Butterfly ต้อง ≥ 0
(เมื่อ K₂ = (K₁+K₃)/2 คือ strikes ห่างเท่ากัน; สำหรับ strikes ไม่เท่ากันใช้ weighted version)

4.6 หลักการที่ 6: "Call บอก Put, Put บอก Call"

จาก PCP: รู้ Call → คำนวณ Put ได้ทันที ถ้า market price ≠ theoretical → opportunity

บทที่ 5: Payoff Algebra — "เขียนสิ่งที่อยากได้เป็นสมการ แล้ว solve"

หนังสือส่วนใหญ่สอนย้อนกลับ: "นี่คือ Bull Call Spread มันมีหน้าตาแบบนี้"
บทนี้สอนไปข้างหน้า: "คุณอยากได้ payoff แบบนี้ → ต้องใช้ instruments อะไร?"

5.1 Building Blocks — ชิ้นส่วนที่ใช้ประกอบ

2 ชั้น ที่ต้องคิดพร้อมกัน:

5.2 Step 1: เขียน Desired Payoff เป็น Piecewise Function

ตัวอย่าง: "อยากได้กำไรถ้าราคาขึ้น แต่ไม่เกิน 2500 ไม่อยากเสียถ้าลง"

แปลเป็น piecewise:

P(S) = { 0           ถ้า S < 2000 (ราคาปัจจุบัน)
       { S - 2000   ถ้า 2000 ≤ S ≤ 2500
       { 500        ถ้า S > 2500

5.3 Step 2: Decompose เป็น Known Building Blocks

Building block payoffs:
  Long Call(K)     = max(S - K, 0)
  Short Call(K)    = -max(S - K, 0)
  Call Spread(K₁,K₂) = max(S-K₁, 0) - max(S-K₂, 0)
  PM Above Yes(K) = 1 ถ้า S > K, else 0

5.4 Step 3: Solve — หา instruments ที่ตรงกัน

P(S) = { 0 ถ้า S < 2000, S-2000 ถ้า 2000≤S≤2500, 500 ถ้า S > 2500 }

นี่คือ: Call Spread(2000, 2500)
= max(S-2000, 0) - max(S-2500, 0)
= { 0        ✓ | S-2000   ✓ | 500 ✓ }

คำตอบ: ซื้อ 1× Call Spread (2000/2500)

5.5 ตัวอย่างซับซ้อน: Piecewise → PM + Options

"อยากได้ +$100 ถ้า S > 2500, +$50 ถ้า 2200 < S ≤ 2500, -$20 ถ้า S ≤ 2200"

Decompose by jumps:
  ที่ S=2200: payoff เปลี่ยนจาก -20 เป็น +50 (กระโดด +70)
  ที่ S=2500: payoff เปลี่ยนจาก +50 เป็น +100 (กระโดด +50)

P(S) = -20 + 70 × 1(S > 2200) + 50 × 1(S > 2500)

คำตอบ:
  -$20 (ต้นทุน entry)
  + 70 × PM Above Yes($2200) ← จ่าย $70 ถ้าเกิน 2200
  + 50 × PM Above Yes($2500) ← จ่าย $50 ถ้าเกิน 2500

5.6 ตัวอย่างที่ 3: Collar (ป้องกันด้าน + จำกัดด้านบน)

"มีหุ้นอยู่ ฿2000 ไม่อยากเสียเกิน ฿200 แต่ยอมจำกัดกำไรที่ ฿300"

Piecewise:
  P(S) = { -200        ถ้า S < 1800
         { S - 2000    ถ้า 1800 ≤ S ≤ 2300
         { +300        ถ้า S > 2300

Decompose: Stock position (slope +1 from 2000)
  + Long Put(1800) → ตัดขาดทุนที่ -200
  + Short Call(2300) → จำกัดกำไรที่ +300

= Collar = Stock + Put(1800) + Short Call(2300)
พลังของ Payoff Algebra

ไม่ต้องจำชื่อกลยุทธ์ — เขียนสิ่งที่อยากได้เป็นสมการ → solve → ได้ instruments
สร้าง payoff shape อะไรก็ได้ที่นึกออก → ถ้า instruments มีอยู่ → สร้างได้!

ลองคิดดู (บท 5)

"อยากได้กำไร ฿100 ถ้าราคา > 2000 แต่ไม่อยากเสียเกิน ฿20" → เขียนเป็น piecewise → decompose เป็น instruments อะไร?
เฉลย: P(S) = {-20 ถ้า S≤2000, +100 ถ้า S>2000} = jump +120 ที่ 2000 → -20 + 120 × PM Above Yes(2000) หรือ -20 + 120 × tight Call Spread at 2000

7.1 Position Sizing: Kelly Criterion

f* = (b×p - q) / b

b = odds (จ่ายเท่าไรต่อ 1 บาทที่เสี่ยง)
p = probability of winning
q = 1 - p = probability of losing

ในทางปฏิบัติ: ใช้ Half-Kelly (f*/2) เพราะ overestimate edge ง่ายกว่า underestimate
ตัวอย่าง

Merger arb: Spread = ฿2.50 ถ้า deal สำเร็จ, เสีย ฿15 ถ้า fail
b = 2.50/15 = 0.167, p = 85%, q = 15%
f* = (0.167×0.85 - 0.15) / 0.167 = (0.142 - 0.15) / 0.167 = -0.05 → ไม่คุ้ม!
ถ้า p = 92%: f* = (0.167×0.92 - 0.08) / 0.167 = 0.074/0.167 = 0.44 → ใช้ 22% ของพอร์ต (Half-Kelly)

ลองคิดดู (บท 7)

Merger arb: spread ฿3 ถ้า deal สำเร็จ, เสีย ฿20 ถ้า fail → b=3/20=0.15, p=90% → Kelly f* = (0.15×0.9-0.1)/0.15 = ? คุ้มไหม?
เฉลย: f*=(0.135-0.1)/0.15 = 0.233 → Half-Kelly = 11.7% ของพอร์ต → คุ้ม แต่ size เล็ก

บทที่ 8: Non-Negative Design Principle

จาก quant-arb-engine: วิธีออกแบบ trade ที่ ขาดทุนสูงสุด = 0 (หรือใกล้ 0) by design

บทที่ 11: Put-Call Parity Arbitrage

11.1 ทบทวน PCP

C + K·e⁻ʳᵀ = P + S

ถ้าซ้าย ≠ ขวา → Arb [Exact Identity]

11.2 Conversion — ซ้าย > ขวา

ถ้า C + Ke⁻ʳᵀ > P + S:
→ ขายฝั่งซ้าย (Short Call + Lend K) + ซื้อฝั่งขวา (Long Put + Long Stock)
= Long Stock + Long Put + Short Call = Conversion
กำไร = (C + Ke⁻ʳᵀ) - (P + S) > 0 [locked at entry]

11.3 Reversal — ซ้าย < ขวา

ถ้า C + Ke⁻ʳᵀ < P + S:
→ ซื้อฝั่งซ้าย (Long Call + Borrow K) + ขายฝั่งขวา (Short Put + Short Stock)
= Short Stock + Short Put + Long Call = Reversal

11.4 ตัวอย่างตัวเลข

S = ฿100, K = 100, r = 5%, T = 0.5 ปี
Call = ฿8.50, Put = ฿5.80
PV(K) = 100 × e⁻⁰·⁰²⁵ = ฿97.53

ซ้าย: C + PV(K) = 8.50 + 97.53 = ฿106.03
ขวา: P + S = 5.80 + 100 = ฿105.80
Violation = 106.03 - 105.80 = ฿0.23

ทำ Conversion: กำไร gross = ฿0.23
หัก commission (4 legs × ฿0.03) = ฿0.12
หัก bid-ask (avg ฿0.05 × 4) = ฿0.20
Net = 0.23 - 0.12 - 0.20 = -฿0.09 ← ขาดทุน! ไม่คุ้ม!
ทำไม PCP Arb หายาก

Market makers คอย scan PCP violations ตลอด → violations เล็กมาก → หลังหัก bid-ask มักไม่เหลือ
ต้องมี edge ด้าน execution (เร็วกว่า, commission ถูกกว่า) ถึงจะทำได้

📊 หลักฐานวิจัย: PCP ที่ "ผิด" จริงๆ มีอยู่ — แต่มันผิดตรงที่รายย่อยเข้าไม่ได้พอดี

งานวิจัยปี 2004[1] พบว่า PCP ของออปชันหุ้นรายตัวละเมิดได้จริงและไม่หายแม้หักต้นทุนแล้ว — ในกรณีสุดขั้ว ราคาหุ้นสูงกว่าราคาที่ออปชันบอกได้ถึงราว 7.5%

แต่จุดสำคัญคือ "ทำไมมันไม่หาย": การละเมิดเกิดในทิศทางเดียวเสมอ คือทิศที่ต้อง short หุ้นเพื่อจะเก็บกำไร และขนาดของมันผูกกับค่ายืมหุ้นโดยตรง — พูดง่ายๆ คือ ยิ่งหุ้นตัวไหน short ยาก/แพง ส่วนต่างยิ่งกว้าง

เกินกำลัง นี่คือ limits to arbitrage แบบตำรา: ส่วนต่างที่เห็นคือค่าเช่าของสิ่งที่คุณไม่มี (สิทธิ์ยืมหุ้นราคาถูก) ไม่ใช่เงินที่รอให้เก็บ — และรายย่อยคือกลุ่มที่ค่ายืมแพงที่สุด

ซ้ำร้าย ต้นทุนฝั่งออปชันก็แพงกว่าหุ้นมาก: bid-ask ของออปชันแม้ตัวที่สภาพคล่องดีก็กว้างระดับหลายเปอร์เซ็นต์ของราคาออปชัน เทียบกับหุ้นใหญ่ที่กว้างไม่ถึง 0.1% — และงานวิจัยปี 2023[2] พบว่าออปชันรายสัปดาห์ที่รายย่อยนิยมเล่น มี bid-ask กว้างได้ถึงราว 12% กลยุทธ์ 4 ขาอย่าง conversion/box จึงจ่ายส่วนต่างนี้ 4 ครั้ง

บทที่ 12: Box Spread & Synthetic Arbitrage

12.1 Box Spread = Bond

Box(K₁,K₂) = Bull Call Spread(K₁,K₂) + Bear Put Spread(K₁,K₂)
= PV(K₂ - K₁) [Exact Identity]

ถ้า Box Price ≠ PV(K₂-K₁) → Arbitrage!

12.2 ตัวอย่าง Box Arb

K₁=90, K₂=110, r=5%, T=0.25 ปี
Fair Box Value = PV(110-90) = 20 × e⁻⁰·⁰¹²⁵ = ฿19.75

Market prices: Bull Call Spread = ฿12, Bear Put Spread = ฿6.50
Box Price = 12 + 6.50 = ฿18.50 ← ถูกกว่า fair ฿19.75!
→ ซื้อ Box ฿18.50, settle ได้ ฿20 ที่ expiry
→ รับเพิ่มตอน expiry = 20 − 18.50 = ฿1.50
→ แต่ กำไร arb จริง = 19.75 − 18.50 = ฿1.25 (ส่วนต่างจาก fair value)

⚠️ อย่าสับสนสองตัวเลขนี้: ฿1.50 คือเงินที่ได้เพิ่มตอน expiry ซึ่งรวมดอกเบี้ยไร้ความเสี่ยงที่เงิน ฿18.50 ควรได้อยู่แล้ว (~฿0.23 ใน 3 เดือน) ส่วนที่เป็น arb จริงคือ ฿1.25 — หลักการเดียวกับบท 15: เทียบกับ fair value เสมอ ไม่ใช่เทียบกับตัวเลขนาม

💀 กรณีศึกษาที่ต้องอ่าน: Box Spread ที่ "risk-free" จนพอร์ตติดลบ

ปี 2019 มีเทรดเดอร์รายย่อยคนหนึ่งเปิด short box บนออปชันของ ETF ตัวหนึ่ง (UVXY) ด้วยบัญชีราว $5,000 โดยเชื่อว่า box = risk-free จึงเก็บเงินสดเข้ามาก่อนแล้วรอจ่ายคืนตอน expiry

สิ่งที่พัง: ออปชันของ ETF เป็นแบบ American — ใช้สิทธิ์วันไหนก็ได้ ขาที่เป็น call in-the-money ลึกมากจนแทบไม่มี time value เหลือ จึงถูกใช้สิทธิ์ก่อนกำหนด (early assignment) → box ที่ควร "ปิดตาย" กลายเป็นสถานะ short หุ้นเปล่าๆ ที่เขาไม่มีเงินค้ำ → ถูกบังคับปิดในราคาที่แย่

ผลลัพธ์: ขาดทุนราว $58,000 จากบัญชี $5,000 — คือขาดทุนเกินเงินทั้งหมดที่มีหลายเท่า และหลังเหตุการณ์นี้โบรกเกอร์รายนั้นเลิกรองรับ box spread

บทเรียน 3 ข้อ: (1) "Risk-free" ในสูตร ≠ risk-free ในทางปฏิบัติ — สูตรสมมติว่าถือจนครบกำหนดได้ (2) ขาดทุนเกินเงินต้นเป็นไปได้จริง เมื่อมีขา short (3) รายละเอียดที่ดูน่าเบื่อ (American vs European) คือสิ่งที่ตัดสินว่ารอดหรือไม่รอด

📊 เงื่อนไขที่ทำให้ Box "ปลอดภัยจริง" (และทำไมรายย่อยส่วนใหญ่ยังไม่ควรทำ)

Box จะไม่มี early-assignment risk ก็ต่อเมื่อใช้ออปชัน European แบบ cash-settled เท่านั้น (เช่น SPX) — ไม่ใช่ "index option ทุกตัว" ปลอดภัย เช่น OEX เป็น index option แต่เป็น American style

  • American (หุ้นรายตัว, ETF ส่วนใหญ่) → ถูกใช้สิทธิ์ก่อนกำหนดได้ → อันตราย
  • European + cash-settled (เช่น SPX) → ไม่มี early assignment, ไม่มีการส่งมอบหุ้นจริง → ปลอดภัยกว่ามาก
  • ต้องไม่มี เงินปันผลระหว่างทาง ที่ทำให้การใช้สิทธิ์ก่อนกำหนดคุ้มค่า

การใช้งานจริงที่ถูกต้องของ box ทุกวันนี้ไม่ใช่ "หา arb" แต่คือ "เครื่องมือกู้เงิน": การขาย box บน SPX = การกู้ในอัตราราว พันธบัตรระยะเดียวกัน + 25–50 bps ซึ่งมักถูกกว่าอัตรา margin ของโบรกเกอร์อย่างมีนัยสำคัญ

เกินกำลัง แต่ประตูนี้แคบ: ต้องมี Portfolio Margin (มักต้องมีทุนตั้งแต่ ~$100,000 ขึ้นไป) และสิทธิ์เทรดออปชันระดับสูง; ขนาดที่คุ้มค่าจริงเริ่มที่หลักหลายหมื่นดอลลาร์; ต้องส่งคำสั่งเป็น combo order ขาเดียว ไม่ใช่ทยอยส่งทีละขา (4 ขา = จ่าย spread 4 ครั้ง)

13.1 IV vs RV — ซื้อ/ขาย Volatility

Implied Volatility (IV) = ตลาดคาดว่า vol จะเป็นเท่าไร
Realized Volatility (RV) = vol ที่เกิดขึ้นจริง

ถ้า IV > RV → Options "แพงเกินไป" → ขาย options (seller's edge)
ถ้า IV < RV → Options "ถูกเกินไป" → ซื้อ options (buyer's edge)
📊 หลักฐานวิจัย: IV > RV เป็นเรื่องจริง — แต่มันคือ "เบี้ยประกัน" ไม่ใช่ช่องโหว่ของตลาด

ส่วนต่างนี้เรียกว่า variance risk premium (VRP) เป็นหนึ่งในปรากฏการณ์ที่หลักฐานหนาแน่นที่สุดในวิชาการเงิน: งานวิจัยปี 2009[3] พบว่าราคา variance ที่ตลาดคิดสูงกว่าความผันผวนที่เกิดจริงอย่างเป็นระบบในดัชนีหลัก และงานปี 2003[4] พบว่าพอร์ตออปชันที่ hedge delta แล้วให้ผลตอบแทนติดลบ — คือผู้ซื้อออปชันจ่ายเบี้ยเกินอย่างเป็นระบบ

ข้อสำคัญที่เปลี่ยนวิธีคิด: VRP เข้มข้นในดัชนี แต่อ่อนมากหรือไม่มีในหุ้นรายตัว[3] เพราะสิ่งที่ตลาดจ่ายเบี้ยให้คือความเสี่ยงที่ทุกอย่างพังพร้อมกัน ซึ่งหุ้นเดี่ยวไม่มี → ขาย vol หุ้นรายตัวคือเวอร์ชันที่แย่ที่สุด: เบี้ยน้อยที่สุด, ความเสี่ยงกระโดดเฉพาะตัวมากที่สุด, bid-ask กว้างที่สุด

และข้อจำกัดที่แหลมที่สุด: งานวิจัยปี 2009 อีกชิ้น[5] ชี้ว่าผลตอบแทนของการขาย put ไม่มีนัยสำคัญทางสถิติ เมื่อทดสอบอย่างเข้มงวด เพราะการแจกแจงสุดโต่งเกินไปและอดีตมีวิกฤตน้อยเกินกว่าจะประมาณค่าเฉลี่ยที่แท้จริงได้ — ถ้าสถาบันที่มีข้อมูล 30+ ปียังสรุปไม่ได้ คนที่ขาย vol ชนะติดกัน 12 เดือนก็ยังไม่ได้พิสูจน์อะไร

เกินกำลัง ขาย vol เปล่าบน margin ไม่ใช่กลยุทธ์สำหรับรายย่อย — เพราะโบรกจะเพิ่ม margin ตอนตลาดผันผวนพอดี แล้วบังคับปิดสถานะตอน IV สูงสุด ซึ่งตรงข้ามกับการ mean-revert ที่กลยุทธ์นี้พึ่งพา
ระวัง ตัวเลข Sharpe สวยๆ ของกลยุทธ์ขาย put ที่มักถูกอ้าง มาจากดัชนีที่ วางเงินสดค้ำเต็มจำนวนและไม่ใช้ leverage เลย ผลลัพธ์คือ "ผลตอบแทนใกล้หุ้น แต่ drawdown ราว 2 ใน 3 ของหุ้น" — เป็นเครื่องมือจัดพอร์ตที่ชอบธรรม แต่ไม่ใช่ "รายได้สม่ำเสมอ" และไม่ใช่สิ่งเดียวกับที่คนขายออปชันบน margin กำลังทำ

13.2 Delta-Neutral Trading

ซื้อ/ขาย Option + Hedge Delta ด้วย Spot/Futures
→ เหลือเฉพาะ vol exposure (Gamma + Vega)

ถ้า IV = 30% แต่ RV = 20% → ขาย option + hedge delta
→ เก็บ premium ส่วนเกิน 10% → กำไรจาก vol spread

13.3 Gamma Scalping

ซื้อ Options (Long Gamma) + Rehedge delta ทุกวัน:
ถ้า actual price moves > IV implied → กำไรจาก rehedging > time decay ที่จ่าย

Gamma Scalping P&L

Daily P&L ≈ ½ × Gamma × (ΔS)² - Theta
ถ้า actual (ΔS)² > implied → positive P&L → RV > IV = buyer wins

13.4 Vol Surface Arbitrage

Vol surface (IV vs Strike vs Expiry) ต้อง smooth + convex:
ถ้า Butterfly < 0 ที่ใด → Arb!
ถ้า Calendar spread < 0 (near-term IV > far-term IV ผิดปกติ) → investigate

13.5 Dispersion Trading

Index Vol vs Component Stocks Vol:
Index Vol ≤ weighted average of Component Vols (เพราะ correlation < 1)

ถ้า Index Vol "แพง" เทียบกับ Components → ขาย Index Options + ซื้อ Component Options

หัวใจของ Dispersion: กำไรจริงๆ มาจาก implied correlation สูงเกินไป — Index vol สูงเพราะตลาดสมมติว่าหุ้นทุกตัวจะเคลื่อนไหวพร้อมกัน (ρ สูง) ถ้า realized correlation ต่ำกว่า implied → dispersion trader ได้กำไร

บทที่ 15: Futures-Spot Arbitrage (Cash & Carry)

15.1 Cost of Carry Model

F = S × e(r-d)T

F = Fair Futures Price, S = Spot, r = risk-free rate, d = dividend yield, T = time to expiry

15.2 Cash & Carry — ถ้า F > Fair

Futures "แพงเกินไป":
1. ซื้อ Spot (S)
2. ขาย Futures (F)
3. ถือจน expiry → Futures converge สู่ Spot
กำไร = F - S×e(r-d)T [locked at entry, Lv.2]

15.3 Reverse Cash & Carry — ถ้า F < Fair

Futures "ถูกเกินไป":
1. Short Spot (ยืมขาย)
2. ซื้อ Futures
3. ถือจน expiry
กำไร = S×e(r-d)T - F [ต้อง short sell ได้ + มี borrow cost]

15.4 ตัวอย่าง: SET50 Futures

SET50 Spot = 900, r = 2%, d = 2.5%, T = 3 เดือน (0.25 ปี)
Fair F = 900 × e(0.02-0.025)×0.25 = 900 × e-0.00125 = 900 × 0.99875 = 898.88

Actual F = 905 → Overpriced by 905-898.88 = ฿6.12
→ Cash & Carry: ซื้อ SET50 spot basket + Short Futures → locked profit ≈ ฿6

15.5 Contango vs Backwardation

สภาพลักษณะArb
Contango (F > S)ปกติ: carry cost เป็นบวกCash & Carry ถ้า premium สูงเกินไป
Backwardation (F < S)เกิดได้ทั้งปกติ (เมื่อ d > r) และช่วง panicReverse Cash & Carry ถ้า F ต่ำกว่า fair มากพอ (ต้อง short spot ได้)

อย่าเทียบ F กับ S ตรงๆ — เทียบกับ fair value เสมอ: ถ้า d > r (เช่นตัวอย่าง SET50 ด้านบน) fair จะต่ำกว่า spot อยู่แล้ว backwardation อ่อนๆ จึงไม่ใช่สัญญาณ arb

📊 หลักฐานวิจัย: Index Arb เคยกำไรจริง — แล้วถูกทุนสถาบันกินเรียบ

งานบุกเบิกปี 1983[1] วางโมเดล cost-of-carry และพบว่า index futures ยุคแรก mispricing มีจริง ต่อมางานปี 1988[2] ใช้ข้อมูล intraday S&P 500 (1983–1987) พบ mispricing คงอยู่นาน ~15–40 นาที — นานพอให้ arbitrageur เก็บกำไรได้สม่ำเสมอ

แต่เมื่อสัญญาโตเต็มวัย + ETF เกิด (1993) + ทุนสถาบันเข้า → mispricing หดจนอยู่ ในกรอบต้นทุนของสถาบัน — ของที่เหลือรายย่อยเก็บไม่ได้เพราะต้นทุนเราสูงกว่า

เกินกำลัง Index cash & carry วันนี้เป็นสนามสถาบัน — เรื่องนี้สำคัญเพราะมันคือ ต้นแบบของวงจร ที่จะเห็นซ้ำใน crypto ด้านล่าง

📊 หลักฐานวิจัย: Crypto Basis Trade — วงจรเดิมกำลังฉายซ้ำ

งานวิจัยปี 2023 ของ BIS[3] วัด carry ของ long spot + short futures ใน BTC/ETH พบเฉลี่ย ~6–8% ต่อปี บ่อยครั้งเกิน 20% และ peak 40–60% ต่อปี (เช่นต้นปี 2021 — futures รายไตรมาสใน exchange offshore แตะ ~40%+)

จุดเปลี่ยน: spot Bitcoin ETF อนุมัติ ม.ค. 2024 → สถาบันมีขา spot ที่ถูกกำกับ → เงิน hedge fund ไหลเข้า basis trade เป็นประวัติการณ์ → ข้อมูลตลาด/รายงานอุตสาหกรรมชี้ว่า basis ถูกบีบเหลือ ~5% ปลายปี 2025 ต่ำสุดในรอบหลายปี — ซ้ำรอย index arb ยุค 1980s แบบตำราเป๊ะ

ระวัง carry ที่เหลือบางจนใกล้ดอกเบี้ยไร้ความเสี่ยง — และมันมาพร้อมความเสี่ยงที่ T-bill ไม่มี (ดูส่วน "ลงมือทำ" ท้าย Part)

⚠️ ความจริง SET50 (TFEX) สำหรับรายย่อยไทย

ขา futures ทำง่าย (multiplier ฿200/จุด — ขนาดเล็กพอ) แต่ปัญหาคือ ขา spot:

  • ซื้อ basket หุ้น 50 ตัวตามน้ำหนักจริง — ทำไม่ได้ในขนาดรายย่อย
  • ตัวแทนที่ใกล้สุด (ETF อิง SET50) มีสภาพคล่องต่ำและมีค่าธรรมเนียมรายปี — กิน edge บางๆ หมด
  • Reverse cash & carry ต้อง short หุ้น — ติดข้อจำกัด SBL (บริการยืม–ให้ยืมหุ้น) + กฎ uptick (ห้าม short ที่ราคาต่ำกว่าล่าสุด) ของตลาดไทย
  • d (dividend yield) ของ SET50 ต้องพยากรณ์ — ผิดนิดเดียว "fair value" ก็เพี้ยน

mispricing ใน SET50 futures ยังพบเห็นได้เป็นระยะ — และมันคงอยู่ได้เพราะ arb ทำยากนั่นเอง: mispricing ที่มองเห็น ≠ กำไรที่เก็บได้

บทที่ 16: Forex & Triangular Arbitrage

16.1 Covered Interest Rate Parity (CIP)

F/S = (1 + r_domestic) / (1 + r_foreign)

ถ้า CIP ไม่เท่ากัน → Arb ระหว่าง FX spot, forward, และ interest rate [No-arb bound — เบี่ยงได้จริงหลังปี 2008 ดูกล่องหลักฐานด้านล่าง]

16.2 Triangular Arbitrage

3 exchange rates: USD/EUR, EUR/GBP, GBP/USD
ถ้า USD→EUR→GBP→USD ≠ 1.0 → กำไร!

ตัวอย่าง:
USD/EUR = 0.92, EUR/GBP = 0.86, GBP/USD = 1.28
เริ่ม $1,000 → €920 → £791.20 → $1,012.74
กำไร = $1,012.74 - $1,000 = $12.74

อ่านค่า: USD/EUR = 0.92 หมายถึง 1 USD แลกได้ 0.92 EUR — ส่วนต่าง 1.27% ในตัวอย่างนี้จงใจเว่อร์เพื่อการสอน ของจริงเล็กระดับต่ำกว่า basis point และหายในเสี้ยววินาที

Forex Arb แทบไม่มีแล้ว

HFT firms scan ทุก currency pair ทุก millisecond → violations หายใน microseconds
ต้องมี co-located servers + direct market access ถึงจะแข่งได้

📊 หลักฐานวิจัย: FX Arb ตายอย่างไร — และข้อยกเว้นเดียวที่เหลือ (ซึ่งรายย่อยก็เก็บไม่ได้)

งานวิจัยปี 2014[4] ใช้ข้อมูล high-frequency ที่แยกได้ว่า order ไหนมาจากคอมพิวเตอร์ พบว่า algorithmic trading ทำให้ โอกาส triangular arbitrage ลดลงชัดเจน — ราคา FX มีประสิทธิภาพขึ้นเพราะเครื่องแข่งกันเก็บส่วนต่างจนหมด

ข้อยกเว้นที่ยังอยู่: Covered Interest Parity แตกจริงหลังปี 2008 — งานปี 2018[5] พิสูจน์ว่า cross-currency basis เบี่ยงหลักสิบ bps แบบเรื้อรัง ไม่ใช่เพราะ credit risk หรือ transaction cost แต่เพราะ กฎกำกับงบดุลธนาคาร — คนที่เก็บได้ต้องเข้าถึงตลาด FX swap ระดับสถาบันเท่านั้น

เกินกำลัง ฝั่งรายย่อย: ข้อมูลกำกับดูแลยุโรป (ESMA 2018)[6] พบว่า 74–89% ของบัญชี retail CFD/FX ขาดทุน (เฉลี่ย €1,600–29,000 ต่อราย) — "FX arb สำหรับรายย่อย" ในทางปฏิบัติไม่มีอยู่จริง บทนี้จึงเป็นบทเรียน เพื่อเข้าใจกลไก ไม่ใช่เพื่อลงเทรด

บทที่ 17: ETF, ADR & Platform Arbitrage

17.1 ETF NAV Arbitrage

ถ้า ETF Price > NAV → Authorized Participant ซื้อ basket → create ETF shares → ขาย
ถ้า ETF Price < NAV → AP ซื้อ ETF shares → redeem for basket → ขาย basket
📊 หลักฐานวิจัย: ETF premium มีจริง — แต่ประตูเปิดให้ AP เท่านั้น

งานวิจัยปี 2017[7] วัดราคา ETF เทียบ NAV พบเบี่ยงเบนในกรอบ ~±2% (ยิ่งใหญ่ใน ETF ที่ถือสินทรัพย์ต่างประเทศ/สภาพคล่องต่ำ) — แต่ครึ่งหนึ่งเป็น ภาพลวงจาก stale NAV (ตลาดบ้านของสินทรัพย์ปิดอยู่ NAV เลยค้าง) เหลือส่วนจริง ~1% และกำไรจากกลยุทธ์ในเปเปอร์เป็นตัวเลขก่อนหักต้นทุน (gross)

เกินกำลัง Create/redeem ทำได้เฉพาะ Authorized Participant (สถาบันที่มีสัญญากับกองทุน, ขั้นต่ำหลักหมื่นหุ้น/ครั้ง) — รายย่อยเข้ากลไกนี้ไม่ได้เลย
ทำได้ สิ่งเดียวที่รายย่อยใช้จากเรื่องนี้: อย่าเป็นฝ่ายจ่าย premium — ใช้ limit order, เช็ก iNAV (ค่า NAV เรียลไทม์โดยประมาณ), เลี่ยงซื้อขายช่วงเปิด/ปิดตลาดและช่วงตลาดป่วน

📊 หลักฐานวิจัย: ADR Arbitrage — ส่วนต่างเฉลี่ยเล็กกว่าต้นทุนรายย่อยมาก

งานวิจัยปี 2010[8] วัดราคา ADR ในสหรัฐเทียบราคาหุ้นตัวเดียวกันในตลาดบ้านเกิด (506 บริษัท 35 ประเทศ แบบ intraday) พบเบี่ยงเบนเฉลี่ยแค่ ~4.9 bps — เล็กกว่าต้นทุนไป-กลับของรายย่อยหลายเท่า ส่วนกรณีเบี่ยงแรงๆ จะกระจุกในหุ้นที่ ถือแล้วเสี่ยง/แปลงยาก พอดี (limits to arbitrage: ช่องว่างกว้างตรงที่ปิดยากที่สุด)

เกินกำลัง การแปลง ADR ↔ หุ้นบ้านเกิดต้องผ่าน depositary bank + ค่าธรรมเนียม + บัญชีสองตลาด + FX — เกมของสถาบัน

17.4 กรณีศึกษา: Flash Crash 2010

Flash Crash — ETF Arb Breakdown

6 May 2010: ดัชนีหุ้นสหรัฐร่วงเพิ่ม ~5–6% ในไม่กี่นาที (รวมทั้งวันติดลบ ~9%) แล้วดีดกลับ
ETFs ตกหนักกว่า underlying → NAV arb mechanism พัง → premium/discount กว้างสุดขีด
รายงานทางการ SEC/CFTC[9]: เทรดกว่า 20,000 รายการถูกยกเลิกเพราะราคาหลุดเกิน 60% — และ ~70% ของหลักทรัพย์เหล่านั้นคือ ETF (บางตัวเทรดที่ $0.01!)
บทเรียน: Arb mechanism ทำงานได้ เมื่อตลาดปกติ — ช่วง panic คนทำ arb ถอนตัวพร้อมกัน ราคา ETF หลุดจาก NAV ได้มหาศาล
ระวัง สำหรับรายย่อย นี่คืออันตรายไม่ใช่โอกาส — stop-loss แบบ market order ของรายย่อยคือเทรดที่ไปเติมที่ $0.01

เรื่องจริง: Kimchi Premium (2017–ปัจจุบัน)

Bitcoin ในเกาหลีใต้ (Upbit, Bithumb) เคยแพงกว่าตลาดโลกมหาศาล — งานวิจัยปี 2020[10] วัดได้: ช่วง ธ.ค. 2017–ก.พ. 2018 premium เฉลี่ย เกิน 15% ต่อเนื่องหลายสัปดาห์ peak ~40–50% และกำไร arb รวมช่วงนั้น เกิน $1 พันล้าน
ทำไมยัง arb ไม่หมด? เพราะ capital controls — เงินวอนออกนอกประเทศยาก + ต่างชาติเปิดบัญชี exchange เกาหลีไม่ได้ → friction กันทั้งสถาบันและรายย่อย
อัปเดต 2024–25: premium หดเหลือ ~1–10% เป็นช่วงสั้นๆ (เช่นต้นปี 2025 แตะ ~9–10% ช่วงสั้นๆ; ช่วงการเมืองเกาหลีป่วน ธ.ค. 2024 กลับพลิกเป็น discount ชั่วคราว — ช่องว่างวิ่งได้สองทาง) — กลายเป็นดัชนีอารมณ์ตลาด ไม่ใช่ arb ที่รอให้เก็บ
บทเรียนที่ยังจริง: Friction = Arb opportunity สำหรับคนที่ข้ามมันได้ถูกกฎหมาย — ถ้าคุณข้ามไม่ได้ อย่าฝืน

จากทั้ง Part นี้ สนามเดียวที่รายย่อยลงมือได้จริงคือ delta-neutral funding/basis harvest: long spot + short perp (perpetual futures — สัญญาไม่มีวันหมดอายุ) เหรียญเดียวกัน ที่เดียวกัน → เก็บ funding (เงินที่ฝั่ง long/short ของ perp จ่ายให้กันเป็นรอบๆ เพื่อดึงราคา perp เข้าหา spot — ตลาดร้อน ฝั่ง long มักเป็นผู้จ่าย) โดยความเสี่ยงราคาหักล้างกัน

ความเสี่ยง 3 ตัวที่ต้องรู้ก่อนตัวเลขกำไร

⚠️ "Delta-neutral" ไม่ใช่ "risk-neutral"
  • Exchange counterparty — FTX ล่ม (พ.ย. 2022): เงิน collateral ของสาย delta-neutral ติดอยู่ใน exchange ทั้งก้อน (กองทุนดังรายหนึ่งติดไป ~ครึ่งพอร์ต) — ความเสี่ยงนี้ไม่มีใน T-bill
  • Funding พลิกลบ — ช่วงตลาดหมี funding ติดลบต่อเนื่องได้เป็นสัปดาห์ๆ (เกิดจริงปลายปี 2022) → รายได้กลายเป็นรายจ่าย
  • Liquidation ขา short — ราคาพุ่งแรง ขา perp โดน margin call ทั้งที่ "รวม" ไม่ขาดทุน เพราะกำไรฝั่ง spot ไม่ถูกนับเป็น margin อัตโนมัติ → ต้องเผื่อ margin เยอะ + เติมทัน

Basis/funding ช่วงปลายปี 2025 เหลือ ~5%/ปี (ข้อมูลตลาด) ขณะที่ T-bill สหรัฐให้ ~4% แบบไร้ความเสี่ยงแพลตฟอร์ม
→ ส่วนต่าง ≈ 0–1% แลกกับความเสี่ยง FTX-style = ไม่คุ้ม → รอ

18.1 Correlation vs Cointegration

Engle-Granger Cointegration Test[13]

1. Regress A vs B: A = α + β×B + ε
2. ทดสอบ residuals (ε) ว่า stationary ไหม (ADF test)
3. ถ้า ε stationary → A กับ B cointegrated → Spread = ε = A − α − β×B จะ mean-revert!

ข้อควรระวัง: ผล regress ไม่สมมาตร — regress A กับ B vs B กับ A ได้ β และผล ADF ต่างกัน ควรลองทั้งสองทิศ (หรือใช้ Johansen test[17] ซึ่งไม่ขึ้นกับทิศทางและรองรับมากกว่า 2 ขา)

📊 เข้าใจ p-value ให้ถูก: "ระดับของหลักฐาน" ไม่ใช่สวิตช์ผ่าน/ตก

เข้าใจผิดที่พบบ่อย: "ราคาหุ้นไม่เป็น normal → p-value ของ ADF/cointegration ใช้ไม่ได้" — ไม่จริง ADF ไม่ได้ต้องการให้ข้อมูลเป็น normal เลย: test statistic ของมันมี distribution เฉพาะตัว (ไม่ใช่ normal หรือ t) ที่สร้างจาก limit theory + simulation โดยตรง[14][18] ดังนั้นการทดสอบ normality (เช่น Shapiro–Wilk) ไม่ใช่ด่านก่อนใช้ ADF — สองอย่างตอบคนละคำถาม

กับดักที่คน DIY พลาดบ่อยสุด: ADF บน residual ที่ประมาณ β มาแล้ว ห้ามใช้ critical values ปกติ — OLS จะ "ดูด" ให้ residual ดู stationary เกินจริง ต้องใช้ critical values เฉพาะของ Engle–Granger/MacKinnon ที่ติดลบมากกว่า[18] → ในทางปฏิบัติ: ใช้ coint() ของ statsmodels ซึ่งจัดการให้แล้ว อย่ารัน adfuller() บน residual เอง

ถ้า p-value สูง แปลว่าอะไร: ADF มีปัญหา power ต่ำเมื่อ spread กลับช้าหรือ sample สั้น (แยก φ=0.98 จาก φ=1 ไม่ออก) — p สูงจึงแปลว่า "ยังสรุปไม่ได้" ไม่ใช่ "ไม่ mean-revert แน่นอน" ทางแก้ที่ดีกว่าการลดเกณฑ์: cross-check ด้วย KPSS[16] ซึ่งมี null กลับด้าน (null = stationary) — ถ้า ADF reject และ KPSS ไม่ reject = หลักฐานแข็งสองทาง; ขัดกัน = ก้ำกึ่ง เก็บไว้ดูต่อ

สรุป: significance เป็น "ระดับของหลักฐาน" — จะอ้างว่าคู่ cointegrated ต้องมีผล reject จาก test ที่ถูก spec แต่การไม่ reject = ยังอ้างไม่ได้ (เข้า Watchlist) ไม่ใช่หลักฐานว่าความสัมพันธ์ไม่มีอยู่ — ใช้ p-value เป็นหลักฐาน อย่าใช้เป็น strategy

18.2 Trading the Spread

Spread = Price_A − β × Price_B
Z-score = (Spread - Mean) / StdDev

Entry: Z > +2 → Short Spread (Short A, Long β×B)
Entry: Z < -2 → Long Spread (Long A, Short β×B)
Exit: Z ≈ 0 → Close ทั้งสองขา
Stop: |Z| > 4 → Cut loss (structural break?)
🪤 กับดักที่กฎ Z-score ข้างบนไม่ได้บอก: "3σ ที่ไม่มี headroom"

ช่วงที่ตลาดนิ่ง spread แคบ ค่า σ จะยุบลงตาม → เส้น mean กับ ±1σ ±2σ ±3σ เบียดกันจนเกือบทับกัน พอราคาขยับนิดเดียวก็แตะ 3σ แล้ว → ระบบเปิดออร์เดอร์ → ค่าธรรมเนียมกับ spread กินกำไรหมดตั้งแต่ยังไม่เริ่ม

ถ้ามองด้วยตา คุณจะไม่เข้าเทรดตอนนั้น เพราะเห็นว่า "ระยะทางมันสั้นเกินจะคุ้ม" — แต่โมเดลมองไม่เห็น เพราะ z-score เป็นค่าที่ไม่มีหน่วย: มันบอกว่า "ห่างกี่ σ" แต่ไม่บอกว่า "ห่างกี่บาท" การหารด้วย σ ได้ทิ้งข้อมูลที่จำเป็นต่อการเทียบกับต้นทุนไปแล้ว

นี่คือความผิดพลาดแบบเดียวกับที่บท 18 เตือนเรื่อง p-value เป๊ะๆ — z = 3 ในช่วงบีบตัวคือ "มีนัยสำคัญทางสถิติ แต่ไร้ความหมายทางเศรษฐกิจ" เวอร์ชันเทรด (แบบเดียวกับ r = 0.08 ที่ p < 0.001)

⚠️ อันตรายซ้อน: ช่วงที่แบนด์บีบตัวยังเพิ่มโอกาส breakout ด้วย (ความผันผวนต่ำมักตามด้วยความผันผวนสูง) — การเข้า mean-reversion ตอนนั้นจึงแย่สองชั้น: headroom น้อย และ โอกาสที่ spread จะวิ่งหนีสูงกว่าปกติ

🔧 ทางแก้: บังคับให้สัญญาณมี "หน่วยเงิน" ก่อนยิง

อนุมานเกณฑ์ออกมาตรงๆ ได้: กำไรที่จะจับได้ = (zเข้า − zออก) × σ และเราต้องการให้มันเป็น k เท่าของต้นทุนไป-กลับ

(z_เข้า − z_ออก) × σ ≥ k × ต้นทุนไป-กลับ แทนค่าจริง z_เข้า = 2, z_ออก = 0.5, k = 3 (อยากได้กำไร 3 เท่าของต้นทุน): 1.5 × σ ≥ 3 × cost → σ ≥ 2 × ต้นทุนไป-กลับ ← ถ้าต่ำกว่านี้ ไม่ต้องดู z เลย

วิธีที่ 1 — ตั้งพื้นให้ σ (แก้ที่ต้นเหตุ): บังคับ σ ไม่ให้ต่ำกว่าพื้น แล้ว z จะไม่พองเองตอนตลาดนิ่ง ไม่ต้องเขียนตัวกรองแยก

sigma_floor = 2 × ต้นทุนไป-กลับ sigma_eff = max(sigma_rolling, sigma_floor) z = (spread − mean) / sigma_eff

วิธีที่ 2 — เพิ่มด่านหน่วยเงินคู่กับ z (อ่านออกชัด):

เข้าเทรดเมื่อ: |z| ≥ 2 ← นัยสำคัญทางสถิติ และ |spread − mean| ≥ 3 × cost ← นัยสำคัญทางเศรษฐกิจ

แนะนำ ใช้ทั้งสองวิธีคู่กัน — วิธีที่ 1 กัน z พอง วิธีที่ 2 เป็นด่านสุดท้ายที่อ่านแล้วเข้าใจทันทีว่าทำไมถึงไม่เข้า
ทางเลือก ถ้าอยากให้สะอาดที่สุดเชิงแนวคิด: เลิกใช้ z เป็นตัวตัดสิน แล้วใช้ edge_ratio = |spread − mean| / ต้นทุนไป-กลับ เข้าเมื่อ ≥ 3 — วิธีนี้ไม่มีทางเกิดปัญหานี้ตามนิยาม เพราะหน่วยถูกโดยโครงสร้าง

โค้ดใน code/pairs_trading_starter.py ใส่ทั้งสองด่านให้แล้ว (พารามิเตอร์ cost_bps และ edge_k) — บรรทัด [6] สัญญาณวันนี้ จะบอกด้วยว่าถูกด่านไหนปฏิเสธ

⚠️ ก่อน Short — ความเสี่ยงที่ไม่สมมาตรกับ Long

ขา short ของ pairs trade ไม่เหมือนการ Long:
• ขาดทุนได้ไม่จำกัด (ราคาขึ้นได้ไม่มีเพดาน) + อาจโดน margin call / forced buy-in / ถูกเรียกหุ้นคืน (recall)
• เสีย ค่า borrow ทุกวันที่ถือ
• stop ที่ |Z|>4 ไม่รับประกันราคา — structural break ทำให้ spread พุ่งทะลุแล้วออกได้แพงกว่าที่คิด (นี่คือสิ่งที่ทำให้ LTCM เจ็บ — ดูกล่องท้ายบท 21)

📊 หลักฐานวิจัย: Pairs Trading ได้ผลจริงไหม?

งานวิจัยต้นฉบับปี 2006[1] ใช้ distance method (formation 12 เดือน, เทรด 6 เดือน, เปิดที่ 2σ) บนหุ้นสหรัฐ ปี 1962–2002 พบผลตอบแทนส่วนเกิน ~11% ต่อปี (ก่อนหักต้นทุน)

แต่การศึกษาต่อมาปี 2010[2] แสดงว่ากำไร เสื่อมลงชัดเจน: top-20 pairs ได้ 0.86%/เดือน (1962–1988) → 0.37% (1989–2002) → 0.24% (2003–2009) และงานปี 2012[3] พบว่า เมื่อหักค่าคอม + market impact + ค่า borrow แล้ว เหลือ ~0.30%/เดือน เฉพาะคู่ที่จับคู่ดีมากเท่านั้น — คู่ทั่วไปต้นทุนกินกำไรเกือบหมด

ระวัง ค่าคอม $0 ช่วยได้ แต่ spread + slippage + ค่า borrow ฝั่ง short คือต้นทุนจริงที่ยังอยู่ และโอกาสที่เหลือมักอยู่ในหุ้นเล็กที่ short ยาก — บทวิจารณ์รวมปี 2017[4] สรุปว่าวิธี distance แบบง่ายเสื่อมไปนานแล้ว ส่วน cointegration มีพื้นฐานทฤษฎีแข็งกว่า

ดูคำเตือนเรื่อง data-snooping และ short-sale constraints ในบทวิจารณ์ [4] — รายการอ้างอิง [1]–[4] ท้าย Part

บทที่ 19: Mean Reversion

19.1 Ornstein-Uhlenbeck Process

เปรียบเทียบ: "ยางยืด"

ลองนึกว่า spread ถูกผูกด้วยยางยืดกับค่าเฉลี่ย μ — ยิ่งดึงออกไกล ยิ่งถูกดึงกลับแรง
θ = ความแข็งของยาง (สูง = กลับเร็ว), σ = ลมที่พัดให้แกว่ง (noise)

dX = θ(μ - X)dt + σdW

θ = speed of mean reversion (ยิ่งสูง ยิ่งกลับเร็ว)
μ = long-run mean (ค่าที่ดึงดูดกลับ)
σ = volatility

Half-life = ln(2) / θ ← "นานแค่ไหนกว่า spread จะกลับครึ่งทาง"
ตัวอย่าง

ถ้า Half-life = 5 วัน → spread กลับครึ่งทางใน 5 วัน → ดีมาก trade ได้
ถ้า Half-life = 60 วัน → ช้าเกินไป → tie up capital นาน → อาจไม่คุ้ม

📊 หลักฐานวิจัย: OU + Half-life ใช้กันจริง

โมเดล "ยางยืด" นี้ไม่ใช่แค่ทฤษฎี — มืออาชีพใช้จริง งานวิจัยปี 2010[5] ใช้ OU จับ residual ของหุ้นหลังหักปัจจัย (PCA / sector ETF) บนตลาดสหรัฐ 1997–2007 ได้ Sharpe ~1.44 (PCA) แต่ ลดเหลือ ~0.9 ช่วงปลาย (2003–2007)

⚠️ ตัวเลขนี้เป็น gross (ก่อนต้นทุน) + สมมติเทรดทั้ง universe รายวันและ short ได้ทุกตัว; 1.44 เป็นค่าช่วงต้น ไม่ใช่ค่าคงที่ที่คาดหวังได้ — ตอกย้ำธีม edge เสื่อมเหมือนบท 18

ทำได้ ส่วนคำนวณ (fit OU/half-life ด้วย AR(1)/OLS) ทำได้ 100% บน statsmodels — ไม่ต้อง short ไม่ต้องใช้ทุน ใช้กรองคู่ที่ half-life สั้น (~5–30 วัน) ได้เลย แต่ สั้นเกินไป (1–2 วัน) มักเป็น noise/bid-ask bounce และยิ่งสั้นยิ่งเทรดถี่ = ต้นทุนสูง

19.2 Kalman Filter — Dynamic Hedge Ratio

ปัญหา: β (hedge ratio) เปลี่ยนตามเวลา → ใช้ rolling regression ไม่ดีพอ
Kalman Filter: อัปเดต β แบบ real-time ตามข้อมูลใหม่ → adaptive pairs trading

เปรียบเทียบง่ายๆ

Kalman = "ปรับ β ทีละนิดทุกวันตามข้อมูลใหม่" แทนที่จะคำนวณ β ใหม่หมดทั้งหน้าต่าง — เหมือนหมุนพวงมาลัยแก้ทีละนิด ไม่ใช่เลี้ยวกระชากทุกครั้งที่เจอโค้ง

📊 หลักฐานวิจัย: Kalman ดีกว่า rolling regression อย่างไร

ตำราวิชาการปี 2025 (Cambridge)[6] แสดงว่า hedge ratio จาก rolling regression แกว่งแรงและ noisy (เช่น 0.6–1.2) ขณะที่ Kalman ให้ค่าที่ นิ่งกว่าแต่ยังปรับตามได้ (เช่น 0.55–0.65) และตัด parameter "ความยาว window" ที่ต้องเดาออกไป

ทำได้ มีไลบรารีพร้อม (pykalman, statsmodels) — ส่วนการเทรดจริงยังติดข้อจำกัด short เหมือนทุกกลยุทธ์ long/short

Long stocks ที่มี positive alpha + Short stocks ที่มี negative alpha
→ กำไรจาก alpha เท่านั้น ไม่ขึ้นกับทิศตลาด [Lv.4 Structured]

PC1 มักคล้าย market factor; PC ถัดๆ ไป อาจ สะท้อน sector/style แต่ไม่เสมอ และตีความยาก/ไม่นิ่ง

⚠️ ความจริงสำหรับรายย่อย: Market-Neutral เต็มรูปแบบ = เกินกำลัง

การถือพอร์ต long-short หลายสิบ–หลายร้อยตัวเพื่อให้ beta = 0 ต้องใช้:

• Short ได้ทุกตัว — แต่หุ้นเล็กที่มี alpha สูงมักหา borrow ไม่ได้/ค่า borrow แพง (HTB 5–50%+/ปี)
• ทุนมาก — margin ทั้งสองขา + ต้องกระจายหลายตำแหน่งเพื่อลด single-pair risk
• ข้อมูลคุณภาพสถาบัน — point-in-time, survivorship-bias-free (CRSP/Compustat)

งานวิจัยปี 2010[5] เองก็จำกัดเฉพาะหุ้นใหญ่ที่ borrow ได้ และผลตอบแทนที่รายงานเป็น gross — งานปี 2015–2025 ชี้ว่า edge ถูกบีบจากการแข่งขัน + ค่า borrow ที่ สูงขึ้น

ทำได้ เริ่มจากพอร์ต pairs ไม่กี่คู่ในหุ้นใหญ่/ETF สภาพคล่องสูง — เก็บ market-neutral หลายร้อยตัวไว้เป็น "ของสถาบัน"

21.3 Overfitting — ศัตรูตัวฉกาจ

Backtest Sharpe สูงผิดปกติ (เช่น 4–5) → สันนิษฐานไว้ก่อนว่า overfit
Backtest Sharpe ~1–2 → "พอเป็นไปได้" → ต้องทดสอบ out-of-sample จริง

(ตัวเลข 5 vs 1.5 เป็น rule of thumb ไม่ใช่เกณฑ์ที่พิสูจน์ในงานวิจัย — ดูหลักฐานด้านล่าง)
📊 หลักฐานวิจัย: ทำไม Backtest Sharpe สวยๆ ถึงหลอก

งานวิจัยปี 2014[7] พิสูจน์ว่า แค่มีข้อมูลรายวัน 5 ปี แล้วลองสัก ~45 กลยุทธ์ ก็คาดได้โดยเฉลี่ยว่าจะเจออย่างน้อย 1 ตัวที่ in-sample Sharpe = 1.0 ทั้งที่ out-of-sample ที่แท้จริง = 0 — Sharpe สูงสุดที่ "ฟลุก" ได้โตตาม √(2·ln N) ของจำนวนครั้งที่ลอง (N)

ทางแก้: Deflated Sharpe Ratio[8] ปรับ Sharpe ตามจำนวนครั้งที่ลอง + ความยาวข้อมูล + skew/kurtosis ส่วนงานสำรวจ "factor zoo" 316+ ปัจจัย ปี 2016[9] แนะนำว่าสัญญาณใหม่ควรผ่าน t-stat > 3.0 ไม่ใช่ 2.0

ระวัง การจูน parameter หลายๆ ค่าแล้วเก็บตัวที่ดีสุด = กระบวนการ overfit ตรงเป๊ะ — และเครื่องมือ retail มักไม่นับ N ให้ ทำให้ Sharpe ที่เห็น "มองโลกในแง่ดีเกินจริง" เสมอ

📊 หลักฐานวิจัย: "Linear ชนะ Neural Net เสมอ" — จริงหรือไม่?

ไม่จริงตามที่เคยเชื่อ. งานวิจัยใหญ่ปี 2020[10] (หุ้นสหรัฐ 1957–2016) พบว่า neural net ตื้นๆ และ tree ชนะ linear ใน gross — long-short Sharpe ≈ 1.35 (NN) เทียบ 0.61 (linear) [วัดแบบ value-weighted ทั้งคู่] เก่งจากการจับ ปฏิสัมพันธ์ที่ไม่เป็นเส้นตรง; ที่น่าสนใจคือ NN ตื้น (~3 ชั้น) ชนะ NN ลึก เพราะ finance noise สูง deep net จึง overfit

แต่หลังหักต้นทุน edge หด/หาย: งาน ML บน S&P 500 ปี 2017[11] gross >0.45%/วัน เหลือ ~0.25%/วันหลังต้นทุน และงานปี 2023[12] พบว่าความได้เปรียบของ ML หายไปเมื่อตัดหุ้นเล็ก/distressed และคิดต้นทุนจริง

แนวทางรายย่อย เริ่มจากโมเดลง่ายก่อน เทรดไม่ถี่ — ลดทั้ง overfitting และต้นทุน (สอดคล้องกับที่ NN ตื้นชนะ NN ลึก) รายย่อย replicate งานวิจัยได้ แต่เก็บกำไร gross หลังต้นทุนแทบไม่ได้; โมเดลซับซ้อน ≠ กำไรมากกว่าเสมอ

เรื่องจริง: Pairs Trading — Royal Dutch Shell A vs B (1907-2005)

Shell มีหุ้น 2 classes (Dutch=A, English=B) สัดส่วน 60:40 → ราคาควรเป็น 60:40 ตลอด
จริงๆ: ratio เบี่ยงเบน ±15% เป็นประจำ → pairs traders ทำกำไรหลายทศวรรษ
แต่ LTCM ก็เทรดคู่นี้แล้วเจ็บ เพราะ ratio กว้างขึ้นก่อน converge → margin call
บทเรียน: Pairs ที่ดีที่สุดก็มี timing risk — ต้อง size ให้รอดถึงวัน converge

🗂️ ตัดสินเป็น "ระดับ" ไม่ใช่ ผ่าน/ตก — Evidence Tiers

อย่าใช้ p-value ตัวเดียวเป็นสวิตช์ ให้จัดคู่ที่สกรีนได้ลง 5 ระดับตามหลักฐานที่สะสม:

🔴 Reject — ไม่มีเหตุผลเศรษฐกิจว่าทำไมต้องวิ่งด้วยกัน / EG ไม่ reject และ KPSS ชี้ไม่ stationary / short ไม่ได้ → ทิ้ง
🟡 Watchlist — เหตุผลเศรษฐกิจแน่น แต่หลักฐานสถิติก้ำกึ่ง (p ≈ 0.05–0.15, sample สั้น) → เก็บข้อมูลเพิ่ม/ดู rolling ห้ามเทรด
🔵 Research candidate — EG reject + half-life ดี แต่ OOS Sharpe < 1 → paper trade / ปรับโมเดล
🟢 Trade candidate — หลักฐานครบทุกชั้น + OOS Sharpe > 1 → paper trade 2–3 เดือน
🟢 Trade (size เล็ก) — paper ตรงกับคาด ≥20–30 สัญญาณ → เงินจริง ≤1–2%/คู่

กฎเหล็ก: ถ้า test ไม่ผ่านเพราะสงสัยว่า spec ผิด (lag ไม่พอ, structural break, β เปลี่ยนตามเวลา) → แก้โมเดล ไม่ใช่ลด threshold จนคู่ผ่าน
การจัดอันดับใน Watchlist: ใช้ ขนาด + ความเสถียร (half-life, ความถี่ที่ spread ตัดผ่านค่าเฉลี่ย, β นิ่งข้าม rolling windows) — อย่าจัดอันดับด้วย p-value เพราะมันผสม effect size กับความยาวข้อมูล: คู่ข้อมูลยาวได้ p ต่ำทั้งที่ effect อ่อน ส่วนคู่เศรษฐกิจแน่นแต่ข้อมูลสั้นได้ p สูงทั้งที่น่าค้นกว่า (และ p=0.04 กับ 0.06 แทบไม่ต่างกันจริง)

เครื่องมือสถิติแต่ละตัว — ต้อง "significant" ไหม?

เครื่องมือใช้ significance อย่างไร
Correlationอย่าใช้ p เป็นด่าน — ดูขนาด + ความเสถียร (r=0.08 ที่ p<0.001 ก็ไร้ประโยชน์เชิงเทรด)
ADF / PP[14][15]ต้อง reject ถ้าจะอ้างว่า spread stationary; ไม่ reject = ยังสรุปไม่ได้ (power ต่ำ)
KPSS[16]null กลับด้าน (null = stationary) — ใช้ cross-check กับ ADF ให้หลักฐานสองทาง
Engle–Granger[13][18]ต้อง reject ด้วย critical values เฉพาะ (ห้ามใช้ ADF ปกติบน residual)
Johansen[17]หลักฐานสำคัญเมื่อขา > 2 หรือกังวลเรื่องทิศทาง regression
Shapiro–Wilk (normality)ไม่ใช่ด่านก่อน ADF/cointegration — ตอบคนละคำถาม
Backtest P&Lดู OOS + ต้นทุน + selection bias — ไม่ใช่ p-value ตัวเดียว

• p-value (train) = 0.03 → ผ่าน (cointegrated) ✓
• half-life = 12 วัน → อยู่ในช่วง 5–30 ✓
• Sharpe: in-sample 2.1 → out-of-sample 0.8 (หลังต้นทุน 20bps + borrow) → ก้ำกึ่ง ⚠️
• ทั้งสองตัวเป็นหุ้นใหญ่ borrow ง่าย ✓

คำตัดสิน: โครงสร้างดี แต่ OOS Sharpe เพียง 0.8 — จัดเป็น 🔵 Research candidate (ไม่ใช่ Trade candidate) → paper trade ≥ 2–3 เดือน (≥20–30 สัญญาณ) ถ้าผลยังตรงค่อยเลื่อนระดับเป็น Trade size เล็กมาก; ถ้า OOS Sharpe ติดลบ → ลดเป็น Reject ทันที

บทที่ 22: Merger Arbitrage (Risk Arb)

22.1 Cash Deal

Company A ซื้อ Company B ที่ ฿50/หุ้น (cash deal)
B ตอนนี้ซื้อขาย ฿47.50
Spread = 50 − 47.50 = ฿2.50
ผลตอบแทนถ้า deal สำเร็จ = 2.50 / 47.50 (เงินที่จ่ายจริง) = 5.26%
ถ้า close ใน 3 เดือน → Annualized ≈ 5.26% × 4 = ~21% ต่อปี

ระวังฐานการหาร: ต้องหารด้วย ราคาที่จ่าย (47.50) ไม่ใช่ราคา deal (50) — หารผิดฐานจะได้ 5.00% ซึ่งต่ำกว่าความจริง และตัวเลข "21% ต่อปี" นี้เป็นผลตอบแทน เฉพาะกรณี deal สำเร็จ ยังไม่ได้หักความน่าจะเป็นที่ deal ล่ม (ดูกล่องหลักฐานด้านล่าง)
⏳ และคำว่า "ต่อปี" อ่อนไหวมากต่อเวลาปิดดีล: ถ้าถูกขอข้อมูลเพิ่มจากหน่วยงานกำกับจนเลื่อนจาก 3 เดือนเป็น 12 เดือน ตัวเลข ~21% จะเหลือ 5.26% ทันที ทั้งที่ยังไม่มีอะไรผิดพลาดเลย

Risk: Deal Break

ถ้า deal ไม่สำเร็จ → B อาจตกกลับไป ฿35 → เสีย ฿12.50 (คิดจากเงินที่จ่าย 47.50 = −26.3%)
Risk/Reward = เสีย ฿12.50 เพื่อได้ ฿2.50 → ต้องมั่นใจ >83.3% ว่า deal จะสำเร็จ (P > 12.50/15 = 83.3%)

📊 หลักฐานวิจัย: Merger Arb ได้ผลจริง — แต่เป็น "การขายประกันภัยตลาด"

งานวิจัยปี 2001[1] ศึกษาดีล 4,750 รายการ (1963–1998) พบผลตอบแทนส่วนเกิน ~4% ต่อปี หลังหักต้นทุนแล้ว — มีจริง แต่ไม่ใช่ตัวเลขหวือหวาแบบที่ spread รายดีลชวนให้คิด

ข้อค้นพบที่สำคัญที่สุดของงานนี้: ผลตอบแทน merger arb ไม่สัมพันธ์กับตลาดในภาวะปกติ แต่สัมพันธ์เชิงบวกอย่างแรงเมื่อตลาดดิ่งหนัก — ผู้เขียนสรุปว่ามันมีลักษณะเหมือน "การขาย put ดัชนีแบบไม่มีของค้ำ" (selling uncovered index put options)

แปลเป็นภาษาคน: คุณเก็บเบี้ยประกันทีละนิดในวันปกติ แล้วจ่ายก้อนใหญ่ในวันที่ตลาดพัง — ซึ่งเป็นวันเดียวกับที่พอร์ตส่วนอื่นของคุณกำลังเจ็บพอดี

ระวัง นี่คือเหตุผลที่ ห้ามใช้ leverage กับกลยุทธ์นี้ ทั้งที่ spread บางๆ ชวนให้อยากกู้ — เพราะการขาดทุนจะกระจุกตัวในช่วงที่โดน margin call พอดี

📊 หลักฐานวิจัย: ทำไมส่วนต่างนี้ถึงไม่หายไป (และทำไมรายย่อยอยู่ผิดฝั่ง)

งานวิจัยปี 2002[2] (ดีล 1,901 รายการ, 1981–1996) พบผลตอบแทนผิดปกติ 0.6–0.9% ต่อเดือน และอธิบายว่าทำไมมันอยู่ได้: จำนวนคนทำ arb มีจำกัดและรับความเสี่ยงได้จำกัด — ส่วนต่างจึงเป็น ค่าตอบแทนของการแบกความเสี่ยง deal ล่ม ไม่ใช่ความผิดพลาดของตลาด

สองข้อค้นพบที่รายย่อยต้องอ่านให้ดี:

  • ผลตอบแทนลดลงเมื่อเงินทุน arb ไหลเข้ามากขึ้น — เป็น capacity-constrained premium ที่บางลงตามการแข่งขัน
  • ผลตอบแทนสูงที่สุดในดีลที่เสี่ยงล่มมากที่สุดและขนาดใหญ่ที่สุด — ของที่จ่ายดีคือของที่น่ากลัวและกินทุน

เกินกำลัง แปลว่ารายย่อยอยู่ผิดฝั่งของสมการทั้งสองด้าน: ทุนน้อยกว่า และเครื่องมือวิเคราะห์ (กฎหมาย/antitrust) ด้อยกว่า

⚠️ เลขคณิตที่โหดร้าย: ทำไม 95% สำเร็จถึงยังไม่พอ

ข้อมูลอุตสาหกรรมยุคใหม่ (นับเฉพาะดีลที่เซ็นสัญญาแล้ว) ชี้ว่า ~94–95% ของดีลปิดสำเร็จ[3] ฟังดูปลอดภัย — จนกระทั่งดูขนาดของความเสียหายเวลาล่ม:

ดีลเหตุการณ์ราคาหุ้นเป้าหมาย
JetBlue / Spiritศาลบล็อก (ม.ค. 2024)−47% ในวันเดียว
Tapestry / CapriFTC ขอคำสั่งห้าม (ต.ค. 2024)−49%

คิดเป็นตัวเลข: ดีลเงินสดทั่วไปถือ ~3 เดือนได้กำไรราว 1.5–2% ถ้าเจอดีลล่มระดับ −45% หนึ่งครั้ง ต้องใช้ดีลที่สำเร็จ ราว 20–30 ดีล เพื่อกลบ
→ edge ทั้งหมดของกลยุทธ์นี้อยู่ที่ การหลบดีลที่จะล่มให้ได้ ซึ่งเป็นการตัดสินเชิงกฎหมาย/antitrust ไม่ใช่การประเมินมูลค่า

⚠️ อย่าเอาสองตัวเลขนี้มาคูณกันตรงๆ แล้วสรุปว่ากลยุทธ์นี้ขาดทุน — เพราะ −45/−49% คือกรณีหางที่รุนแรงที่สุด (โดนหน่วยงานแข่งขันฟ้องบล็อก) ไม่ใช่ค่าเฉลี่ยของดีลที่ล่ม และที่สำคัญกว่า: ดีลที่ตลาดมองว่าเสี่ยงจะมี spread กว้างกว่ามาก คนที่รับความเสี่ยงนั้นจึงได้ค่าตอบแทนสูงกว่า 1.5–2% ที่ยกมา — นี่คือเหตุผลที่หลักฐาน [1] ยังพบผลตอบแทนส่วนเกินเป็นบวก ทั้งที่หางน่ากลัวขนาดนี้

ข้อสังเกตเพิ่ม: เวลาดีลล่ม หุ้นผู้ซื้อมักขึ้น — ถ้าคุณ hedge แบบ long target + short acquirer จะเจ็บทั้งสองขาพร้อมกัน

22.2 Stock Deal

A ซื้อ B ด้วยหุ้น A ในอัตรา 0.8 หุ้น A ต่อ 1 หุ้น B
→ Long B + Short 0.8×A = ล็อกส่วนต่างได้ก็ต่อเมื่อ deal ปิดจริง
กำไร = 0.8×A − B − ต้นทุนธุรกรรม − ค่ายืมหุ้น − เงินปันผลที่ต้องจ่ายฝั่ง short

⚠️ อ่านสูตรให้ถูกทิศ: ต้อง 0.8×A > B ตั้งแต่ตอนเข้า จึงจะมีส่วนต่างให้เก็บ (คือหุ้นเป้าหมายซื้อขายต่ำกว่ามูลค่าดีล)
และคำว่า "ล็อก" ใช้ได้เฉพาะกรณีดีลปิด — ถ้าดีลล่ม หุ้นเป้าหมายร่วงและหุ้นผู้ซื้อมักเด้งขึ้น = เจ็บทั้งสองขาพร้อมกัน อีกทั้งรายย่อยต้องหา borrow (ยืมหุ้นผู้ซื้อมา short) ให้ได้ก่อน ซึ่งมักเป็นข้อจำกัดที่ทำให้ทำไม่ได้จริง

บทที่ 23: Special Situations

23.1 Spin-Off Arbitrage

Parent แยก SpinCo ออก → นักลงทุนขาย SpinCo เพราะไม่ต้องการ (forced selling) → SpinCo อาจถูกกดราคาชั่วคราว

⚠️ ผลตอบแทนส่วนเกินของ spin-off ที่งานวิจัยยุค 1990 พบ เดินตามรอยเดียวกับ index effect ในหัวข้อถัดไป: เมื่อกลไกเป็นที่รู้กันทั่ว ก็มีคนดักหน้าไปแล้ว — ก่อนเชื่อว่า "ถูกเกินไป" ต้องตอบให้ได้ว่าใครยังเป็นฝ่ายถูกบังคับขายอยู่ และเขาขายเมื่อไร

23.2 Index Rebalancing

หุ้นเข้า index → index funds ต้องซื้อ → demand spike → ราคาขึ้นชั่วคราว
หุ้นออก index → index funds ต้องขาย → supply spike → ราคาลงชั่วคราว
→ ตำราคลาสสิกบอก: ซื้อก่อนวัน rebalance → ขายหลัง index funds ซื้อเสร็จ
📊 หลักฐานวิจัย: "Index Effect" หายไปแล้ว — อย่าเรียนเพื่อไปเทรด

นี่คือกรณีศึกษาที่ดีที่สุดของ arb ที่ตายต่อหน้าต่อตา งานวิจัยปี 2025[4] วัดผลตอบแทนผิดปกติของหุ้นที่ถูกเพิ่มเข้า S&P 500:

ยุคผลตอบแทนผิดปกติ (หุ้นเข้า index)
ทศวรรษ 1990ราว +7% — ของจริง ทำเงินได้
ทศวรรษล่าสุดไม่ถึง +1% — หดจนแทบไม่เหลือ

ฝั่งหุ้นที่ถูกถอดออกก็เดินทางเดียวกัน: เคยติดลบแรงในยุค 90 เหลือใกล้ศูนย์ในช่วงปี 2010–2020

ที่น่าสนใจคือมันหายทั้งที่เงินใน index fund โตขึ้นมหาศาล — สวนทางกับสามัญสำนึก เหตุผลหลักที่งานวิจัยเสนอคือ องค์ประกอบของการเข้า index เปลี่ยนไป: หุ้นที่เข้า S&P 500 ส่วนใหญ่ย้ายขึ้นมาจาก index กลาง — กองทุนที่อิง index ใหญ่ต้องซื้อ ขณะที่กองทุนที่อิง index กลางต้องขายพอดี แรงซื้อ-แรงขายจึงหักล้างกัน ไม่เกิด demand shock จริง; เสริมด้วยการที่รายการเข้า/ออกคาดเดาง่ายขึ้นจนมีคนซื้อดักหน้า

ข้อควรระวังในการอ่าน: ตัวเลข "แทบไม่เหลือ" คือค่าเฉลี่ยรวม — หุ้นที่เข้า index แบบไม่ได้ย้ายมาจาก index กลาง (direct addition) ยังพอมีผลอยู่บ้าง แต่ก็เล็กเกินกว่ารายย่อยจะเก็บได้หลังหักต้นทุน

เกินกำลัง สำหรับรายย่อย: ถ้ามืออาชีพยังดักหน้ากันจนเหลือไม่ถึง 1% ก่อนหักต้นทุน — รายย่อยที่เข้าทีหลังและจ่าย spread แพงกว่า จะได้ผลตอบแทนติดลบ
ทำได้ สิ่งที่ควรเก็บจากบทนี้คือ บทเรียนเรื่องกลไก (forced flow สร้าง price pressure) ไม่ใช่ตัวกลยุทธ์ — และเป็นตัวอย่างชั้นดีว่า ตำราที่ไม่อัปเดตจะสอนของที่ตายแล้ว

23.3 Stub Trading

Parent ถือ SpinCo 80% + Other Business
Other Value = Parent Market Cap - 0.8 × SpinCo Market Cap
ถ้า Other Value ≤ 0 → ตลาดให้ราคา Other = ศูนย์หรือติดลบ! → ซื้อ Parent Short SpinCo
กรณีศึกษา: Yahoo / Alibaba (2015)

Yahoo ถือหุ้น Alibaba → มูลค่า stake สูงกว่า market cap ของ Yahoo ทั้งบริษัท → ดูเหมือนตลาดให้ราคา core business ของ Yahoo ติดลบ
Stub trade: Long Yahoo + Short Alibaba → รอให้ส่วนต่างแคบลง (ใช้เวลาเป็นปี)

⚠️ บทเรียนที่สำคัญกว่าตัวเลข: "stub ติดลบ" ที่เห็นมักไม่ใช่ของฟรี — ส่วนใหญ่อธิบายได้ด้วย ภาระภาษีแฝง (ถ้าบริษัทแม่ขาย stake ที่กำไรมหาศาลออกมา ต้องเสียภาษีก้อนใหญ่ มูลค่าที่ผู้ถือหุ้นได้จริงจึงต่ำกว่าราคาตลาดของ stake) บวกกับต้นทุน holding company และความไม่แน่นอนว่าจะ unlock เมื่อไร
ก่อนสรุปว่า "ตลาดโง่" ให้ถามก่อนว่า ส่วนต่างนี้อธิบายด้วยภาษี/ต้นทุน/เวลาได้เท่าไร — เหลือเท่าไรจึงเป็น mispricing จริง

จาก Special Situations ที่เป็น "เหตุการณ์ระดับบริษัท" (M&A, Spin-Off, Index Rebalancing) ตอนนี้เราจะขยายไปสู่ เหตุการณ์ที่เกิดซ้ำๆ เช่น ประกาศผลประกอบการ การประชุม Fed — และใช้ Options เป็นเครื่องมือ:

บทที่ 24: Event-Driven with Options

24.1 Earnings Arbitrage: IV vs Realized Move

ก่อนประกาศผล: IV (implied volatility — ความผันผวนที่ตลาดฝังไว้ในราคา option) พุ่งสูง
สมมติค่าเฉลี่ยการเคลื่อนไหววันประกาศผล ≈ 1.6%
แปลงเป็น σ: 1.6% ÷ 0.8 ≈ 2.0% ต่อวัน → × √252 ≈ 32% ต่อปี
ถ้า IV = 45% → overpriced ≈ 13 vol points
→ ขาย straddle/strangle (ขาย call+put พร้อมกัน = เดิมพันว่าราคาจะนิ่งกว่าที่ตลาดคิด) [Lv.4 Structured] [Heuristic]

⚠️ กับดักสถิติที่ทำให้ "ส่วนเกิน" ดูใหญ่เกินจริง: ค่าเฉลี่ยของขนาดการเคลื่อนไหว (mean absolute move) ไม่เท่ากับ σ — สำหรับการแจกแจงปกติ ค่าเฉลี่ยขนาด ≈ 0.8σ ดังนั้นต้องหารด้วย 0.8 ก่อน ถ้าเอา 1.6% ไปคูณ √252 ตรงๆ จะได้ 25% ซึ่งต่ำกว่า σ จริง แล้วทำให้ตัวเลข overpriced พองจาก ~13 เป็น ~20 points
และวิธีที่ถูกต้องกว่าคือเทียบ implied move (ราคา straddle ÷ ราคาหุ้น) กับการกระจายตัวของการเคลื่อนไหวในอดีต (ดูทั้งค่ากลางและเดไซล์ที่แย่ที่สุด) — เพราะค่าเฉลี่ยคือสถิติที่ซ่อนหางซึ่งเรากำลังขายพอดี

📊 หลักฐานวิจัย: IV > RV มีจริง — แต่มันคือ "เบี้ยประกัน" ไม่ใช่ความผิดพลาดของตลาด

ส่วนต่าง IV เหนือ RV เรียกว่า variance risk premium (VRP) และเป็นหนึ่งในปรากฏการณ์ที่มีหลักฐานหนาแน่นที่สุดในวิชาการเงิน — งานวิจัยปี 2009[6] พบว่าราคา variance ที่ตลาดคิดสูงกว่าความผันผวนที่เกิดขึ้นจริงอย่างเป็นระบบในดัชนีหลัก และงานปี 2003[7] พบว่าพอร์ต option ที่ hedge delta แล้วให้ผลตอบแทนติดลบ — คือคนซื้อ option จ่ายเบี้ยเกินอย่างเป็นระบบ

แต่คำอธิบายของมันคือ "ค่าตอบแทนการรับความเสี่ยงวิกฤต" ไม่ใช่ของฟรี — เหมือนกับ merger arb ในบท 22 ที่เป็นการ "ขาย put ดัชนี" นี่คือรูปแบบเดียวกัน: เก็บเบี้ยเล็กๆ สม่ำเสมอ แล้วจ่ายก้อนใหญ่ในวันที่ตลาดพัง

ข้อจำกัดที่แหลมคมที่สุด: งานวิจัยปี 2009 อีกชิ้น[8] ชี้ว่าผลตอบแทนมหาศาลของการขาย put นั้น ไม่มีนัยสำคัญทางสถิติ เมื่อทดสอบอย่างเข้มงวด เพราะการแจกแจงมันสุดโต่งเกินกว่าเครื่องมือสถิติปกติจะรับมือ และตัวอย่างในอดีตมีวิกฤตน้อยเกินไป — แปลว่าแม้แต่สถาบันที่มีข้อมูล 35 ปีก็ยังประมาณค่าเฉลี่ยที่แท้จริงของกลยุทธ์นี้ไม่ได้ แล้วรายย่อยที่ชนะติดกัน 18 เดือนจะรู้อะไรได้?

💀 Tail Risk — ทำไม "ชนะ 9 ใน 10" ถึงยังไม่พอ

5 ก.พ. 2018 "Volmageddon": VIX พุ่งจาก 17.31 เป็น 37.32 (+116% ในวันเดียว — มากที่สุดในประวัติศาสตร์) กองทุน ETN ที่ short vol อย่าง XIV ขาดทุนราว 96% ในวันเดียว และถูกปิดกองถาวร — ผู้ถือไม่มีโอกาส "รอให้กลับมา" เพราะกองถูกยุบ

วันเดียวกันนั้น กองทุนรวมที่ขาย option บน margin ชื่อ LJM Preservation & Growth (สังเกตคำว่า "Preservation" = การรักษาเงินต้น) ขาดทุน ~80% ใน 2 วัน เงินลงทุนราว $600 ล้านหายไป

ทำไม "กระจายหลาย earnings" ไม่ช่วยอย่างที่คิด: Law of Large Numbers ต้องการเหตุการณ์ที่เป็นอิสระต่อกัน — แต่วันที่ตลาดพัง หุ้นทุกตัวเคลื่อนไหวพร้อมกัน การขาย vol 20 ตัวจึงกลายเป็นเดิมพันเดียว ในวันที่สำคัญที่สุด (หลักการเดียวกับที่ดีล merger ล่มพร้อมกันในบท 22)

เกินกำลัง ขาย straddle/strangle เปล่า (naked) ด้วยบัญชี margin = สิ่งที่รายย่อยไม่ควรทำ — ขาดทุนไม่จำกัด, โบรกเพิ่ม margin ตอนตลาดผันผวนพอดี, และถูกบังคับปิดสถานะที่จุดแย่ที่สุด (ตอน IV สูงสุด) ซึ่งตรงข้ามกับการ mean-revert ที่กลยุทธ์นี้พึ่งพา

ตัวเลข Sharpe สวยๆ ของกลยุทธ์ขาย put ที่มักถูกอ้าง มาจากดัชนีที่ วางเงินสดค้ำเต็มจำนวน (fully cash-collateralized) และไม่ใช้ leverage เลย — ผลลัพธ์คือ "ผลตอบแทนใกล้เคียงหุ้น แต่ drawdown ราว 2 ใน 3 ของหุ้น" ซึ่งเป็นเครื่องมือจัดพอร์ตที่ชอบธรรม แต่ไม่ใช่ "รายได้สม่ำเสมอ" และไม่ใช่สิ่งเดียวกับที่คนขาย option บน margin กำลังทำ

24.2 Binary Events: FDA, Election

เหตุการณ์ที่ผลออก 2 ทาง → ราคากระโดด → ใช้ PM probability cross-check กับ IV

PM + Options — อ่านส่วนต่างให้ถูก

PM (prediction market — ตลาดทำนายผล) ให้ "FDA approve" = 65% แต่ options implied probability = 50% → ส่วนต่าง 15 จุดความน่าจะเป็น

ระวัง 15 จุด ≠ กำไร 15% — ผลตอบแทนจริงขึ้นกับราคาและโครงสร้าง option ที่ใช้ ไม่ใช่ผลต่างความน่าจะเป็น

และก่อนจะเรียกว่า edge ต้องผ่าน 3 คำถามนี้ก่อน:

  • เป็นเหตุการณ์เดียวกันจริงไหม? วันหมดอายุ option กับวันที่ PM ใช้ตัดสิน มักไม่ตรงกัน
  • ความน่าจะเป็นจาก option เป็นแบบ risk-neutral ซึ่งฝังเบี้ยความเสี่ยงไว้ — มันจึงไม่เท่ากับความน่าจะเป็นจริงโดยธรรมชาติ ส่วนต่างที่คงอยู่จึง "คาดหวังได้" ไม่ใช่ arb
  • ราคา PM ก็ไม่ใช่ความน่าจะเป็นสะอาด — มีค่าธรรมเนียม, spread, สภาพคล่องบาง และอคติชอบเดิมพันม้ารอง

ถ้าจะเทียบให้ตรงกันจริง ต้องใช้ call spread แคบๆ (จำลอง payoff แบบ binary) ไม่ใช่ซื้อ call เปล่า — เพราะ call เปล่าคุณถือ vega และ theta ติดมาด้วย ทายผลถูกแต่ขาดทุนจาก IV ที่ยุบหลังประกาศได้
สันนิษฐานเริ่มต้นที่ดีต่อส่วนต่าง 15 จุด: "เราอ่านตัวเลขใดตัวเลขหนึ่งผิด หรือมันคนละเหตุการณ์กัน" — วินัยเดียวกับกล่อง breakeven ในบท 22

เรื่องจริง: Porsche-VW Squeeze (2008)

Porsche ค่อยๆ สะสมหุ้น VW + options จนถือ 74% โดยไม่มีใครรู้ → ประกาศ → short sellers ต้องซื้อคืน (short squeeze) → VW กลายเป็นบริษัทที่ market cap สูงสุดในโลกชั่วคราว (€1,000/หุ้น จาก €200!)
บทเรียน: Merger/Event arb มี hidden risks ที่ model ไม่จับ — ใครจะคิดว่า VW จะเป็นหุ้นแพงสุดในโลก?

ลองคิดดู (บท 22–24)

1. Deal: A ซื้อ B ที่ ฿80, B ตอนนี้ ฿76, close ใน 6 เดือน → annualized return (ถ้าสำเร็จ)?
2. ก่อน earnings: IV=50% หุ้นนี้มีส่วนเบี่ยงเบนมาตรฐานรายวัน (daily vol) ≈ 2% → annualized vol ≈ ? overpriced กี่ vol points?
3. ข้อ 1 ถ้าประเมินว่า deal ล่มแล้ว B ตกไป ฿64 → ต้องมั่นใจกี่ % ว่า deal สำเร็จจึงคุ้ม?
เฉลย: 1. Spread ฿4 ÷ ฿76 (เงินที่จ่าย) = 5.26% ใน 6 เดือน → annualized ≈ 10.5% เฉพาะกรณีสำเร็จ 2. 2%×√252=31.7% → overpriced 50−31.7=18.3 vol points → sell vol 3. ได้ +4 / เสีย −12 → breakeven P = 12/(12+4) = 75% — ต่ำกว่านี้คือ EV ติดลบ

สูตรเดียวที่ต้องจำ: Breakeven Probability

กำไรถ้าสำเร็จ = Deal Price − ราคาปัจจุบัน (เรียก G) ขาดทุนถ้าล่ม = ราคาปัจจุบัน − ราคาก่อนประกาศดีล (เรียก L) Breakeven P = L / (L + G) ถ้าคุณเชื่อว่าโอกาสสำเร็จ < P นี้ → EV ติดลบ → ไม่เข้า

สูตรนี้ยังมองโลกในแง่ดีเกินจริง 3 ทาง ต้องเผื่อไว้เสมอ:
① ยังไม่คิดค่าเสียโอกาสของเงิน — เงิน ฿47.50 ถ้าฝากไว้เฉยๆ 3 เดือนก็ได้ดอกเบี้ย ถ้ารวมเข้าไปด้วย เกณฑ์จะขยับจาก 83.3% ขึ้นไปอีก
② "ราคาก่อนประกาศ" ไม่ใช่พื้นที่แน่นอน — เวลาดีลล่มจริง หุ้นมักหลุดต่ำกว่านั้น (ธุรกิจถูกรบกวนระหว่างรอดีล, ตราบาปดีลล่ม) ดูตัวอย่างในบท 22 ที่ร่วง −47/−49%
③ ผลลัพธ์ไม่ได้มีแค่ 2 ทาง — ดีลอาจถูกต่อรองราคาลง หรือยืดเวลาออกไป ซึ่งไม่ใช่ทั้ง "สำเร็จเต็ม" และ "ล่ม"

ลองกับตัวอย่างในบท 22.1

Deal ฿50, ราคาปัจจุบัน ฿47.50, ราคาก่อนประกาศ ฿35
G = 2.50, L = 12.50 → Breakeven P = 12.50 / 15 = 83.3%
คำถามที่ต้องตอบให้ได้: คุณมีเหตุผลอะไรที่จะเชื่อว่าดีลนี้สำเร็จเกิน 83.3%? ถ้าตอบว่า "ก็ดีลส่วนใหญ่สำเร็จ ~95%" — ระวัง เพราะตลาดก็รู้ ดีลที่ spread กว้างผิดปกติมักกว้างเพราะมีเหตุผล (antitrust, financing, MAC)

📊 ทางเลือกที่สมจริงกว่าสำหรับรายย่อย: กองทุน/ETF

ETF/กองทุน merger arb แก้สองปัญหาที่รายย่อยแก้เองไม่ได้: การกระจาย 20–25 ดีล และ การหา borrow เพื่อ hedge stock deal

แต่ต้องคาดหวังให้ถูก — ETF merger arb ที่ใหญ่ที่สุดในสหรัฐทำผลตอบแทนราว 3% ต่อปีในรอบ 10 ปี[5] คือระดับ "cash-plus" ไม่ใช่ตัวแทนหุ้น และค่าธรรมเนียมกินส่วนแบ่งจากผลตอบแทนที่บางอยู่แล้ว

ระวัง อย่าคาดหวังตัวเลข 7–11% จากงานวิจัยยุค 1980–90[2] — นั่นคือยุคก่อนที่เงินทุน arb จะไหลเข้ามาบีบผลตอบแทน (ซึ่งงานวิจัยชิ้นเดียวกันทำนายไว้เอง) และก่อนหักค่าธรรมเนียม
ทำได้ ใช้เป็น ตัวกระจายความเสี่ยงที่สหสัมพันธ์ต่ำ ในพอร์ต — โดยจำไว้ว่าความสัมพันธ์นั้นหายไปตอนตลาดพัง ตามหลักฐาน [1]

25.3 คิดต้นทุนให้ครบ — สูตรที่ Part III–VI อ้างถึงตลอด

เหตุผลที่กลยุทธ์ส่วนใหญ่ในเล่มนี้ "ดูดีบนกระดาษแต่ไม่รอดจริง" อยู่ในบรรทัดเดียวนี้ — คนส่วนใหญ่นับไม่ครบ

ต้นทุนรวมต่อรอบเทรด (ไป-กลับ) = ค่าคอมมิชชัน × จำนวนขา × 2 (เข้า+ออก) + ครึ่งหนึ่งของ bid-ask × จำนวนขา × 2 ← มักใหญ่ที่สุด + slippage ← ยิ่งรีบ ยิ่งแพง + ค่ายืมหุ้น (ถ้ามีขา short) × จำนวนวันที่ถือ + ดอกเบี้ย margin (ถ้ากู้) × จำนวนวันที่ถือ + ภาษี (ตามเขตที่อยู่) เกณฑ์ตัดสิน 3 ชั้น — ต้องผ่านทั้งสามข้อ: ① กำไรสุทธิ > 0 (ไม่งั้นคือทำฟรี) ② กำไร/ทุน > อัตราไร้ความเสี่ยง (ไม่งั้นซื้อพันธบัตรดีกว่า) ③ ส่วนต่างจาก ② คุ้มกับความเสี่ยง+เวลา (ไม่งั้นก็ซื้อพันธบัตรอยู่ดี)
⚠️ กับดักที่พบบ่อยที่สุด: นับ bid-ask แค่ครั้งเดียว

กลยุทธ์ 4 ขาอย่าง conversion หรือ box จ่ายส่วนต่าง bid-ask 4 ครั้งตอนเข้า และอีก 4 ครั้งตอนออก — ถ้าออปชันมี spread 5% ของราคา ต้นทุนรวมอาจเกิน 20% ของ premium ก่อนที่กลยุทธ์จะเริ่มทำงานด้วยซ้ำ (ดูบท 11–12)

กฎง่ายๆ ที่ใช้ได้จริง: ถ้าต้นทุนคาดการณ์เกิน ~20% ของกำไรที่คาดหวัง ให้ข้ามไป เพราะประมาณการกำไรมักผิดพลาดได้ง่ายกว่าประมาณการต้นทุนมาก

ข้อมูลคุณภาพสถาบันสิทธิ์ที่จะไม่เทรด — ไม่มีใครบังคับให้ลงเงิน รอได้ไม่จำกัด

ถ้าอ่าน Part III–VI มาแล้วจะเห็นว่าข้อค้นพบเดียวกันโผล่ซ้ำสามครั้ง ในกลยุทธ์ที่ดูไม่เกี่ยวกันเลย:

  • Merger arb (บท 22) — ผลตอบแทนเหมือน "ขาย put ดัชนี": ไม่สัมพันธ์กับตลาดตอนปกติ แต่เจ็บพร้อมตลาดตอนพัง; ดีลล่มพร้อมกันเมื่อสินเชื่อตึงหรือนโยบายกำกับเปลี่ยน
  • ขาย volatility (บท 13, 24) — เก็บเบี้ยได้เกือบทุกเดือน แล้วคืนทั้งหมดในวันเดียว (5 ก.พ. 2018)
  • Pairs / stat arb (บท 18–21) — คู่ที่ "ไม่เกี่ยวกัน" แยกออกจากกันพร้อมกันเมื่อทุกคนถูกบังคับปิดสถานะ

โครงสร้างเดียวกันทั้งหมด: เก็บเล็กๆ บ่อยๆ แล้วจ่ายก้อนใหญ่ครั้งเดียว — และวันที่จ่ายคือวันที่ทุกตำแหน่งจ่ายพร้อมกัน

ระวัง การถือ 20 ตำแหน่งลดได้เฉพาะความเสี่ยงเฉพาะตัว — แต่ความเสี่ยงที่ทำให้พอร์ตศูนย์คือความเสี่ยงร่วม ซึ่งการกระจายไม่ช่วยเลย
คำถามที่ถูกต้องจึงไม่ใช่ "ฉันถือกี่ตำแหน่ง" แต่คือ "ถ้าทุกตำแหน่งพังพร้อมกัน ฉันเหลือเท่าไร"

26.5 ขนาดตำแหน่ง: กฎที่ทำให้รอด

กฎขั้นต่ำ: ขาดทุนกรณีเลวร้ายสุด ต่อ 1 ตำแหน่ง ≤ 1–2% ของพอร์ต กฎรวมพอร์ต: ถ้าทุกตำแหน่ง "ประเภทเดียวกัน" พังพร้อมกัน → ต้องยังเหลือทุนเทรดต่อได้ คำนวณย้อนกลับ (ไม่ใช่คำนวณไปข้างหน้า): ① ถามก่อน: กรณีเลวร้ายสุดของตำแหน่งนี้คือเท่าไร? (ไม่ใช่ "น่าจะ" แต่ "ถ้าซวยสุด") ② ตั้งขนาดจากคำตอบข้อ ① ไม่ใช่จากกำไรที่คาดหวัง
⚠️ ทำไม "กรณีเลวร้ายสุดในอดีต" ยังไม่พอ

กองทุน LJM ที่ล้มในปี 2018 เปิดเผยว่าประเมิน "ขาดทุนวันเดียวกรณีเลวร้ายสุด ~20%" โดยเอาขาดทุนวันที่แย่ที่สุดในอดีต (~9%) มาคูณสอง แล้วปัดขึ้น — ฟังดูอนุรักษ์นิยม แต่ของจริงคือ −80% ใน 2 วัน

บทเรียน: สำหรับกลยุทธ์ที่มีหางยาว (ขาย vol, merger arb, carry) อดีตมีวิกฤตน้อยเกินกว่าจะบอกได้ว่าหางยาวแค่ไหน — ตรงกับที่งานวิจัยในบท 13 สรุปว่าประมาณค่าเฉลี่ยที่แท้จริงไม่ได้ ดังนั้นให้เผื่อไว้มากกว่าที่ข้อมูลบอก ไม่ใช่เท่ากับ

และกฎเหล็กของ leverage: กลยุทธ์ที่ขาดทุนกระจุกตัวตอนตลาดพัง ห้ามกู้ เพราะ margin call จะมาถึงในวันเดียวกับที่กลยุทธ์ขาดทุนพอดี (LTCM, บท 26.2)

27.3 Two-Leg Failure Recovery — ส่วนที่คนข้ามแล้วเจ็บ

ในกลยุทธ์สองขา สิ่งที่แย่ที่สุดไม่ใช่ขาดทุน แต่คือ ได้ขาเดียว — เพราะคุณกลายเป็นคนถือความเสี่ยงทิศทางโดยไม่ได้ตั้งใจ ทั้งที่ทั้งกลยุทธ์ออกแบบมาเพื่อไม่ถือมัน

สถานะที่ระบบต้องรู้จัก: IDLE → SENDING → LEG1_FILLED → COMPLETE ↓ (ขา 2 ไม่ fill ใน T วินาที) RECOVERING นโยบายกู้คืน — ต้องเลือกไว้ก่อน ไม่ใช่ตัดสินใจตอนเกิด: A. ปิดขา 1 ทันทีที่ราคาตลาด → ยอมขาดทุนเล็ก จบเร็ว (ปลอดภัยสุด) B. ไล่ราคาขา 2 ในขอบเขตที่ตั้งไว้ → ได้ครบคู่ แต่จ่ายแพงขึ้น C. ถือขาเดียวชั่วคราว + stop เข้ม → เสี่ยงสุด ใช้เมื่อมั่นใจว่าสภาพคล่องจะกลับมา
กฎปฏิบัติ 3 ข้อที่ลดโอกาสเข้าสู่ RECOVERING
  • ส่งขาที่ยากกว่าก่อนเสมอ — ขาที่สภาพคล่องน้อย/spread กว้างกว่า ถ้าขายากไม่ได้ ก็ไม่ต้องส่งขาง่ายเลย (ถ้าส่งขาง่ายก่อนแล้วขายากพลาด = ติดขาเดียวแน่นอน)
  • ตั้ง timeout เป็นวินาที ไม่ใช่นาที — ยิ่งค้างนาน ความเสี่ยงทิศทางยิ่งสะสม
  • บันทึกทุกครั้งที่เข้า RECOVERING — ถ้าเกิดบ่อย แปลว่าขนาดใหญ่เกินสภาพคล่อง หรือเกณฑ์ freshness หลวมเกินไป ไม่ใช่ "โชคร้าย"

สำหรับรายย่อยที่เทรดมือ: หลักการเดียวกันใช้ได้ — เตรียมคำสั่งทั้งสองขาไว้ก่อน ส่งขายากก่อน และตั้งใจไว้ล่วงหน้าว่าถ้าอีกขาไม่ได้จะทำอะไร ความผิดพลาดที่พบบ่อยคือ "ได้ขาแรกแล้วค่อยคิด" ซึ่งเป็นเวลาที่แย่ที่สุดในการตัดสินใจ

28.2 Drills ยุคใหม่ — ฝึกสิ่งที่ 24 drills ข้างบนไม่ได้ฝึก

Drill ชุดแรกฝึก "หา mispricing ให้เจอ" — ซึ่งเป็นทักษะที่จำเป็นแต่ไม่พอ เพราะเล่มนี้แสดงให้เห็นว่าคนส่วนใหญ่แพ้ตรงด่านหลังจากเจอ ไม่ใช่ตรงการหา
Drill ชุดนี้จึงมีเฉลยครบ และหลายข้อคำตอบที่ถูกคือ "ไม่เทรด"

Drill A — ด่าน headroom (บท 18.2)

คู่หนึ่งให้ค่า: z = 2.8 (เกินเกณฑ์ ±2 แล้ว), σ ของ spread = ฿0.40, ต้นทุนไป-กลับ = ฿0.35
ใช้กฎ exit ที่ |z| < 0.5 — คำถาม: เข้าเทรดไหม?

เฉลย: ไม่เข้า — คำนวณสองทาง ได้คำตอบเดียวกัน
① เช็ก σ floor: σ ขั้นต่ำที่ยอมรับได้ = 2 × 0.35 = ฿0.70 แต่ σ จริง = ฿0.40 → ต่ำกว่าพื้น = อยู่ในภาวะแบนด์บีบตัว z ที่เห็นพองขึ้นมาเอง
② เช็กกำไรที่จับได้: (2.8 − 0.5) × 0.40 = ฿0.92 เทียบต้นทุน ฿0.35 = 2.6 เท่า ต่ำกว่าเกณฑ์ 3 เท่า
บทเรียน: z สูงไม่ได้แปลว่ามีเนื้อกำไร — ต้องแปลงกลับเป็นหน่วยเงินเสมอ

Drill B — จัด Evidence Tier (บท 18, 33)

คู่หุ้นหนึ่งให้: Engle-Granger p = 0.02, KPSS p = 0.11, half-life = 9 วัน, Sharpe out-of-sample หลังต้นทุน = 0.6
จัดอยู่ Tier ไหน และขั้นต่อไปคืออะไร?

เฉลย: 🔵 Research candidate
EG reject ที่ 0.02 ✓ · KPSS ไม่ reject (0.11 ≥ 0.05) ✓ → หลักฐาน stationarity แข็งสองทาง · half-life 9 วันอยู่ในช่วง 5–30 ✓
แต่ OOS Sharpe 0.6 < 1 → โครงสร้างดีแต่ยังพิสูจน์ไม่ได้ว่ากำไรรอดต้นทุน → paper trade 2–3 เดือน ยังไม่ลงเงินจริง
กับดักที่ต้องเลี่ยง: เห็น p = 0.02 แล้วรีบสรุปว่า "ผ่านแล้ว" — p-value เป็นเพียงหนึ่งชั้นของหลักฐาน

Drill C — ด่าน decay (บท 23, 33)

มีคนเสนอกลยุทธ์พร้อม backtest ปี 1995–2005 ให้ผลตอบแทน 12%/ปี ดูสวยงามมาก
คำถามแรกที่ต้องถามคืออะไร?

เฉลย: "มันยังใช้ได้อยู่ไหม — และถ้าไม่ ทำไม?"
เล่มนี้แสดงรูปแบบเดียวกันซ้ำ 4 ครั้ง: index arb (ตายยุค 1990), index effect (ราว 7% → ไม่ถึง 1%), pairs (0.86% → 0.24%/เดือน), crypto basis (40–60% → ~5%)
ทุกครั้งกลไกเหมือนกัน: ทุนไหลเข้า → ส่วนต่างหด — ดังนั้น backtest ที่จบก่อนที่ทุนจะไหลเข้า บอกอะไรเกี่ยวกับวันนี้ได้น้อยมาก
คำถามที่ 2: ผลตอบแทนนี้เป็น gross หรือ net?

Drill D — breakeven probability (บท 22)

ดีลเงินสด: ผู้ซื้อเสนอ ฿100/หุ้น · หุ้นเป้าหมายตอนนี้ ฿96 · คาดปิดใน 4 เดือน · ราคาก่อนประกาศดีล ฿78
หา (ก) ผลตอบแทนต่อปีถ้าสำเร็จ (ข) ต้องมั่นใจกี่ % ถึงจะคุ้ม (ค) ควรเข้าไหม?

เฉลย:
(ก) กำไร ฿4 ÷ ฿96 (เงินที่จ่ายจริง) = 4.17% ใน 4 เดือน → ต่อปี ≈ 12.5%
(ข) G = ฿4, L = 96 − 78 = ฿18 → breakeven P = 18 ÷ (18+4) = 81.8%
(ค) ต้องถามต่อ ไม่ใช่ตอบทันที — อัตราปิดดีลยุคใหม่อยู่ราว 94–95% แต่ตลาดกำลังให้ราคาดีลนี้ที่ ~82% ซึ่งต่ำกว่าค่าเฉลี่ยมาก
แปลว่า ตลาดเห็นความเสี่ยงบางอย่างที่คุณยังไม่เห็น → ต้องหาให้เจอก่อน (antitrust? การเงินผู้ซื้อ? MAC?) — spread ที่กว้างผิดปกติคือคำเตือน ไม่ใช่ของถูก
และอย่าลืม: ถ้าเลื่อนปิดจาก 4 เดือนเป็น 12 เดือน ตัวเลข 12.5% จะเหลือ ~4.2% ทันที

Drill E — two-leg failure (บท 27.3)

ระบบส่งคำสั่งสองขา ขาแรก fill แล้ว แต่ขาที่สองไม่ fill ภายใน 5 วินาที
(ก) ตอนนี้คุณถืออะไรอยู่ (ข) ควรทำอะไร (ค) ทำไมต้องตัดสินใจเรื่องนี้ก่อนเทรด?

เฉลย:
(ก) ความเสี่ยงทิศทางเปล่าๆ — คุณกำลังถือสิ่งที่ทั้งกลยุทธ์ออกแบบมาเพื่อไม่ถือ
(ข) เข้าสถานะ RECOVERING แล้วทำตามนโยบายที่เลือกไว้ล่วงหน้า — ปลอดภัยที่สุดคือ ปิดขาแรกทันทีที่ราคาตลาด ยอมขาดทุนเล็กเพื่อจบเร็ว
(ค) เพราะตอนติดขาเดียวคือตอนที่กดดันที่สุดและตัดสินใจแย่ที่สุด — ถ้าไม่ตัดสินใจไว้ก่อน คนส่วนใหญ่จะเลือก "รออีกหน่อย" ซึ่งเป็นทางเลือกที่แย่ที่สุด
ป้องกันล่วงหน้า: ส่งขาที่สภาพคล่องน้อยกว่าก่อนเสมอ และถ้าเข้า RECOVERING บ่อย = ขนาดใหญ่เกินสภาพคล่อง ไม่ใช่โชคร้าย

🎯 สิ่งที่ Drill ชุดนี้ฝึกจริงๆ

สังเกตว่า 3 ใน 5 ข้อ คำตอบที่ถูกคือ "ไม่เทรด" หรือ "ยังไม่เทรด" — ไม่ใช่เพราะหนังสือมองโลกในแง่ร้าย แต่เพราะในทางปฏิบัติ นั่นคือคำตอบที่ถูกบ่อยที่สุดจริงๆ

ทักษะที่ยากที่สุดของ arbitrageur ไม่ใช่การหาโอกาส แต่คือการแยกโอกาสจริงออกจากสิ่งที่ดูเหมือนโอกาส — และการมีวินัยพอที่จะปล่อยผ่านเมื่อด่านไม่ครบ

30.3 PM vs Options

Inconsistency = คำถาม ไม่ใช่โอกาส

PM "Fed cut rate" = 70% แต่ options implied = 55% → ส่วนต่าง 15 จุดความน่าจะเป็น

ระวัง 15 จุด ≠ กำไร 15% — ผลตอบแทนจริงขึ้นกับราคาและโครงสร้างที่ใช้ ไม่ใช่ผลต่างความน่าจะเป็น

ก่อนเรียกว่า edge ต้องผ่าน 3 คำถามนี้ (เหมือนบท 24.2):

  • เหตุการณ์เดียวกันจริงไหม? วันหมดอายุ option กับวันที่ PM ใช้ตัดสิน มักไม่ตรงกัน
  • ความน่าจะเป็นจาก option เป็นแบบ risk-neutral — ฝังเบี้ยความเสี่ยงไว้ จึงไม่เท่ากับความน่าจะเป็นจริงโดยธรรมชาติ ส่วนต่างที่คงอยู่จึง "คาดหวังได้" ไม่ใช่ arb
  • ราคา PM ก็ไม่สะอาด — ค่าธรรมเนียม, spread, สภาพคล่องบาง, อคติชอบเดิมพันม้ารอง

สันนิษฐานเริ่มต้นที่ดีต่อส่วนต่างใหญ่ๆ: "เราอ่านตัวเลขใดตัวเลขหนึ่งผิด หรือมันคนละเหตุการณ์กัน" — ถ้าจะเทียบให้ตรงต้องใช้ call spread แคบๆ จำลอง payoff แบบ binary ไม่ใช่ซื้อ call เปล่าที่พ่วง vega/theta มาด้วย

32.1 Renaissance Technologies — Stat Arb ที่สำเร็จที่สุด

Medallion Fund: 66% avg gross return/year ก่อนหัก fees (1988-2018)

ใช้ math + physics + data science หาสัญญาณใน noise
ทำ หลายพัน trades/วัน แต่ละ trade edge เล็กมาก → Law of Large Numbers

⚠️ อ่านให้ครบก่อนคิดจะเลียนแบบ: Medallion ปิดรับเงินนอกมาตั้งแต่ปี 1993 และบริหารเงินของพนักงานเป็นหลัก — กองทุนที่ Renaissance เปิดให้คนนอกลงทุนทำผลงานได้ห่างชั้นจากตัวเลขนี้มาก
และ "หลายพัน trades ต่อวัน" คือสิ่งที่ต้องใช้ ต้นทุนต่อรายการระดับสถาบัน — ถ้ารายย่อยลอกวิธีนี้ ค่าธรรมเนียมจะกินก่อนที่ Law of Large Numbers จะทำงาน (ดูสูตรต้นทุนในบท 25.3)
สิ่งที่ลอกได้จริงคือวิธีคิด: edge เล็กแต่พิสูจน์ได้ + ทำซ้ำได้ + ไม่สัมพันธ์กัน — ไม่ใช่ตัวเลขผลตอบแทน

32.5 บทเรียน 10 ข้อ

  1. Pure Arb หายากมาก — ส่วนใหญ่เป็น Near-Arb หรือ Bounded-Loss

  4. Simple > Complex — Baseline comparison ทุกครั้ง
  5. Size < Survival — อยู่รอดก่อน กำไรทีหลัง
  6. Label your claims — Exact ≠ Heuristic ≠ Observed
  7. Automate with safeguards — kill switch + position limit (Knight Capital)
  8. Regime matters — strategy ที่ดีใน bull อาจแย่ใน bear
  9. Diversify across strategies — ไม่ใช่แค่ across assets
  10. Keep learning — ตลาดเปลี่ยน edge หายไป ต้องหาใหม่ตลอด

  2. Edge เสื่อมได้ และเสื่อมจริง — index arb (1980s), index effect (7% → <1%), pairs (0.86% → 0.24%/เดือน), crypto basis (40–60% → ~5%) เป็นรูปแบบเดียวกันซ้ำๆ: ทุนไหลเข้า → ส่วนต่างหด
  3. นัยสำคัญทางสถิติ ≠ นัยสำคัญทางเศรษฐกิจ — p-value ต่ำหรือ z สูงไม่ได้แปลว่าคุ้มเทรด ต้องเช็กเป็นหน่วยเงินเสมอ (บท 18.2)
  4. ความเสี่ยงร่วมสำคัญกว่าความเสี่ยงเฉพาะตัว — กระจาย 20 ตำแหน่งไม่ช่วยถ้าทุกตัวพังวันเดียวกัน; กลยุทธ์เก็บเบี้ยทุกตัวมีโครงสร้าง "ขายประกัน" เหมือนกันหมด
  5. ยิ่งกลไกแม่นยำ ยิ่งไม่เหลือให้รายย่อย — Lv.1 ที่คณิตศาสตร์แน่นอนที่สุด คือชั้นที่ถูกเก็บหมดก่อน; ที่เหลือคือค่าตอบแทนของการรับความเสี่ยงที่คนอื่นไม่อยากรับ

Arb for Manual Traders — "ไม่มี bot ไม่มี API มีเงิน ฿50,000 ทำอะไรได้?"

ทำได้จริง (manual, เงินน้อย) — เรียงจากที่แนะนำที่สุด:

  • ฝึกและวิจัย Pairs Trading (Lv.4) → รันสกรีนวันละครั้ง เขียน Python ฟรีได้ทั้งหมด → paper trade 2–3 เดือนก่อน ไม่ต้อง real-time
  • Earn / Platform promo (Lv.3) → มี cap เล็ก แต่เป็นของจริงและไม่ต้องใช้ bot → อ่านเงื่อนไขให้ครบ
  • Funding harvest (Lv.3) → รอจังหวะที่ผิดปกติจริง ไม่ใช่เปิดทิ้งไว้ตลอด — ถ้า net APR ไม่ถึง ~2 เท่าของพันธบัตร ให้รอ
  • Merger arb ผ่านกองทุน/ETF (Lv.4) → แก้ปัญหาการกระจาย 20+ ดีลที่ทำเองไม่ได้ — แต่คาดหวังระดับ cash-plus
  • ใช้ PCP/Butterfly ตรวจราคา → ไม่ใช่หา arb แต่เพื่อไม่จ่ายแพง — edge ที่ได้จริงและไม่มีวันเสื่อม

ทำไม่ได้ (ต้อง bot/infra หรือเป็นสนามสถาบัน):

  • PCP / Box arb (Lv.1) → หายใน seconds และส่วนต่างที่เหลือคือค่ายืมหุ้น
  • Triangular Forex → หายใน microseconds → ต้อง co-located server
  • Gamma scalping → ต้อง rehedge ถี่ → ต้นทุนกินก่อน
  • Index/ETF/ADR arb, dispersion → ต้องเป็น AP หรือมีโต๊ะเทรด

เกิดไม่บ่อยและต้องระวัง: PM cross-platform (Lv.1) — Yes+No < $1 ดูเหมือนกำไรแน่ แต่ต้องหักค่าธรรมเนียมสองแพลตฟอร์ม, ตรวจว่าเป็นเหตุการณ์เดียวกันและวันตัดสินตรงกันจริง, และมีสภาพคล่องพอปิดทั้งสองขา — ไม่ใช่ "เจอ = กำไรแน่"
