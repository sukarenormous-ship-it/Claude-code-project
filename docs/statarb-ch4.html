4.2 OLS — วิธีที่ใช้บ่อยที่สุด

OLS หา β ที่ minimize ระยะทางแนวตั้ง (vertical residual) จากจุดข้อมูลถึงเส้น regression:

สูตร OLS β
β_OLS = Cov(r_A, r_B) / Var(r_B) = Σ(r_A − r̄_A)(r_B − r̄_B) / Σ(r_B − r̄_B)²

หรือถ้า regress log(P_A) บน log(P_B) โดยตรง (level regression):

log(P_A) = α + β·log(P_B) + ε β_OLS = slope ของ regression นี้

หมายเหตุ: β จาก return regression และ β จาก price-level regression เป็นคนละค่ากัน — สำหรับ synthetic process ε = log(P_A) − β·log(P_B) ค่า β ที่เป็นหลัก (canonical) คือ slope ของ log-price regression

OLS และ TLS ให้ β ต่างกัน — OLS ใช้ B เป็น "หลัก" (no noise), TLS สมมติทั้งคู่ noisy เท่ากัน

สูตร TLS (Total Least Squares)

β_TLS = [Var(r_A) − Var(r_B) + √((Var(r_A)−Var(r_B))² + 4·Cov(r_A,r_B)²)] / (2·Cov(r_A,r_B)) หรือใช้ SVD: β_TLS = v₁₂/v₂₂ (eigenvector ของ covariance matrix [r_A, r_B])

จุดที่สับสนบ่อย: OLS minimize Σε² ซึ่งเป็น quadratic objective — จึงเป็น Quadratic Program (QP) ไม่ใช่ Linear Program แม้จะอยู่ใน "linear regression"
หมายเหตุ: หนังสือเล่มนี้ใช้ OLS เท่านั้น — MLE/Ridge/LAD แสดงไว้เพื่อเทียบนิยามเท่านั้น ไม่ได้ใช้ใน practice

OLS จากหลักการแรก — ทำไมต้อง minimize Σε²

ปัญหา: กำหนด N คู่ราคา (P_A,1,…,P_A,N) และ (P_B,1,…,P_B,N) — หา α และ β ที่ทำให้ residual ε_t ขึ้นๆ ลงๆ รอบ 0 น้อยที่สุด (ε มี variance ต่ำสุดที่เป็นไปได้)

ทำไมต้อง minimize Σε² ไม่ใช่ Σ|ε|?
  • เหตุผล 1 — penalize outlier มากกว่า: ε=3 ให้ ε²=9 แต่ |ε|=3 — squared ทำให้จุดที่ห่างจากเส้นมากถูก penalize หนักกว่า ทำให้เส้น regression ไม่เบี่ยงจากกลุ่มข้อมูลหลัก
  • เหตุผล 2 — มี closed-form solution: Σε² เป็น differentiable ทุกจุด → หา derivative แล้วตั้งเป็น 0 ได้ → ได้สูตร β = Cov/Var โดยตรง ส่วน Σ|ε| ไม่ differentiable ที่ ε=0 → ต้องใช้ linear programming แก้
  • เหตุผล 3 — residual ⊥ x: Σε² ทำให้ residual uncorrelated กับ x (Gauss-Markov) — สมบัตินี้สำคัญสำหรับ inference และ diagnostics

เขียนปัญหาเป็นสมการ:

ให้ y_t = log(P_A,t) และ x_t = log(P_B,t) ε_t = y_t − α − β·x_t ← residual คือสิ่งที่เราสร้าง objective: minimize S(α, β) = Σ ε_t² = Σ (y_t − α − β·x_t)² t=1 t=1

หา minimum โดยหา partial derivative เทียบเท่า 0:

∂S/∂α = −2·Σ(y_t − α − β·x_t) = 0 → Σy_t = N·α + β·Σx_t ∂S/∂β = −2·Σ x_t·(y_t − α − β·x_t) = 0 → Σx_t·y_t = α·Σx_t + β·Σx_t² แก้ระบบสมการ (Normal Equations): β = [N·Σ(x_t·y_t) − Σx_t·Σy_t] / [N·Σx_t² − (Σx_t)²] = Cov(x, y) / Var(x) ← รูปกระทัดรัด (x = log P_B) α = ȳ − β·x̄ ← α เป็นตัวปรับระดับ
ความหมายของ β จาก OLS

β = Cov(log P_A, log P_B) / Var(log P_B)
ตีความ: "ถ้า log(P_B) เพิ่มขึ้น 1 หน่วย (≈ B ขยับ +1%) ค่าเฉลี่ยของ log(P_A) ที่ OLS คาดไว้ จะเพิ่มขึ้น β หน่วย"
หรือพูดในเชิง % ≈ "B ขยับ 1% → A คาดว่าขยับ β%"

ε_t = ส่วนที่ A ขยับ มากกว่า หรือ น้อยกว่า ที่ B อธิบายได้ — นี่คือ inefficiency ที่เราเทรด

OLS แยก log P_A ออกเป็น "ส่วนที่ B อธิบาย" + residual ε — ε ที่ดีควร mean-revert รอบ 0

สิ่งที่ OLS รับประกัน (Gauss-Markov Theorem)

Gauss-Markov: ถ้า ε มี zero-mean, ไม่ correlate กับ x, Var(ε) คงที่ (homoskedastic), และไม่มี autocorrelation → β̂ จาก OLS เป็น BLUE (Best Linear Unbiased Estimator) — ดีที่สุดในบรรดา estimator linear ที่ unbiased ทั้งหมด

  • Σε_t = 0 เสมอ — residuals sum to zero
  • Σ(x_t · ε_t) = 0 — residual uncorrelated กับ x
  • β_OLS = BLUE (Best Linear Unbiased Estimator) ถ้า Gauss-Markov assumptions ถือ (ε i.i.d., homoskedastic)
  • ในราคาจริง assumptions เหล่านี้มักฝ่าฝืน → ดู §4.2b-5 ข้อจำกัด

OLS ใน Python — 3 วิธีทำ

### วิธี 1: statsmodels (แนะนำ — ได้ diagnostics ครบ)
import statsmodels.api as sm
import numpy as np

y = np.log(price_A) # log P_A — dependent variable
x = np.log(price_B) # log P_B — independent variable

# add constant → fit α and β together
X = sm.add_constant(x) # X = [1, x] (N×2 matrix)
model = sm.OLS(y, X).fit()

alpha = model.params.iloc[0] # α (intercept) — iloc safe กับทุก statsmodels version
beta = model.params.iloc[1] # β (hedge ratio)
epsilon = model.resid # ε_t (residuals) — ใช้ทดสอบ stationarity

r2 = model.rsquared # R² — explained variance
p_beta = model.pvalues[1] # p-value ของ β (ต้องการ ≪ 0.05)
ci_beta = model.conf_int().iloc[1] # 95% CI ของ β [lower, upper]

print(f"β = {beta:.4f} (p={p_beta:.4f})")
print(f"R² = {r2:.4f}")
print(model.summary()) # สรุปครบ — AIC, residual std, t-stat

### วิธี 2: numpy (เร็ว ง่าย สำหรับ loop)
beta, alpha = np.polyfit(x, y, 1) # fit linear y = β·x + α
epsilon = y - (alpha + beta * x)

### วิธี 3: สูตรโดยตรง (เข้าใจ mechanism)
beta = np.cov(y, x)[0,1] / np.var(x, ddof=1)
alpha = np.mean(y) - beta * np.mean(x)
epsilon = y - alpha - beta * x
เลือก window ข้อมูลอย่างไร
  • Train window: ข้อมูล N วันล่าสุด (เช่น 30 วัน) — fit β บน window นี้เท่านั้น
  • อย่าใช้ข้อมูลอนาคต: ห้าม fit β บน full dataset แล้วย้อนไปทดสอบ → look-ahead bias
  • Walk-forward: fit β วันนี้ → ใช้ trade พรุ่งนี้ → roll window ไป 1 วัน → fit ใหม่ (ดู บทที่ 3 §3.9)

ตรวจ ε ที่ได้ — 4 การทดสอบหลัก

หลังจาก fit OLS และได้ ε มาแล้ว ต้องตรวจว่า ε มีคุณสมบัติสำหรับ mean reversion trading:

R² คืออะไร — นิยามสั้น

R² = 1 − Var(ε) / Var(y) = สัดส่วน variance ของ y ที่ x อธิบายได้
R²=0: x ไม่ช่วยอธิบาย y เลย | R²=1: x อธิบาย y ได้สมบูรณ์ | R²=0.95: x อธิบายได้ 95%
ใน Stat Arb ต้องการ R² สูง → แสดงว่า B อธิบาย A ได้ดี → ε เป็น idiosyncratic จริง ไม่ใช่ noise

# ตรวจ ε ครบชุด
from statsmodels.tsa.stattools import adfuller
import statsmodels.api as sm

# 1. ADF test
adf_result = adfuller(epsilon, maxlags=1)
print(f"ADF p-value: {adf_result[1]:.4f}") # ต้องการ < 0.05

# 2. AR(1) → Half-life
ar1 = sm.OLS(epsilon[1:], sm.add_constant(epsilon[:-1])).fit()
phi = ar1.params[1] # AR(1) coefficient
half_life = -np.log(2) / np.log(phi) # half-life (same unit as data freq)
print(f"φ = {phi:.4f}, Half-life = {half_life:.1f} bars")

# 3. σ_stat — sample estimator ของ σ/√(2κ) (converges เมื่อ sample size N ใหญ่)
sigma_stat = np.std(epsilon) # use in z-score: z = (ε − mean) / sigma_stat
print(f"σ_stat = {sigma_stat:.4f} ({sigma_stat*100:.2f}%)")

ข้อจำกัดที่ 2 — Spurious Regression เมื่อทั้งสองตัว non-stationary

log P_A และ log P_B เป็น I(1) process (random walk) — ถ้า regress สอง I(1) series ที่ ไม่มี cointegration จะได้ R² สูง, β มีนัยสำคัญ แต่ ε ยังคง non-stationary — ผลที่ได้ไม่มีความหมาย

กับดัก: OLS บอกว่า R² = 0.90, p < 0.001 ดูน่าเชื่อถือมาก แต่: ADF ของ ε ได้ p = 0.45 ← non-stationary! → regression นี้ spurious — เทรดไม่ได้

แก้: ทดสอบ ADF/KPSS บน ε เสมอ — ผ่าน ADF ก่อนจึงใช้ β นั้น (ดู บทที่ 5)

ข้อจำกัดที่ 3 — β คงที่ ไม่ adaptive

OLS สมมติว่า β ไม่เปลี่ยนตลอด lookback window แต่ในตลาดจริง β อาจ drift ตาม regime

สัญญาณ: rolling β (30d vs 60d) ต่างกัน > 15% → ใช้ Rolling OLS หรือ Kalman แทน (§4.3, §4.6.3)
ดูรายละเอียด window และ trap เพิ่มเติม: §4.6.6

ข้อจำกัดที่ 4 — Outliers ดึง β ให้ผิดทิศ

OLS minimize ε² → จุดที่อยู่ห่างจากเส้นมาก (outlier: crash, flash crash, pump) มี weight สูงเป็นพิเศษ → β ถูกดึงให้เข้าหา outlier

4.3 Kalman Filter — Dynamic β ที่เปลี่ยนตามเวลา

OLS และ TLS สมมติว่า β คงที่ตลอด lookback window แต่ในตลาดจริง β อาจเปลี่ยนได้ Kalman Filter แก้ปัญหานี้โดยอัปเดต β ทุก time step:

Kalman State Space Model
β_t = β_{t-1} + w_t (state equation: β เดินแบบ random walk)
r_{A,t} = β_t · r_{B,t} + v_t (observation equation)

w_t ~ N(0, Q) — process noise (ความเร็วที่ β เปลี่ยน)
v_t ~ N(0, R) — observation noise (noise จากราคา)

Kalman Filter ทำงาน 2 ขั้นซ้ำกันทุก time step:

ขั้นสูตรความหมาย
Predictβ̂_t|t-1 = β̂_{t-1}, P_t|t-1 = P_{t-1} + Qคาดว่า β ตอนนี้คืออะไร (ก่อนเห็นข้อมูล)
UpdateK = P·r_B / (r_B²·P + R)
β̂_t = β̂_t|t-1 + K·(r_A − β̂·r_B)
P_t = (1−K·r_B)·P		ปรับ β ตามข้อมูลจริงที่เพิ่งเห็น

K คือ Kalman Gain — ถ้า Q สูง (β เปลี่ยนเร็ว) K ใหญ่ → เชื่อข้อมูลใหม่มาก ถ้า R สูง (noisy market) K เล็ก → เชื่อ model เก่ามากกว่า

Rolling OLS กระโดดตาม window boundary — Kalman ค่อยๆ ปรับ → position ขยับน้อยกว่า

สำหรับ Hybrid Strategy สิ่งที่กำหนด "กว้างพอ" ของ σ_stat คือสมการ Breakeven จาก บทที่ 19.7:

Breakeven σ Condition
σ_stat ≥ total_friction_cost / (z_entry − z_exit)

ถ้า σ_stat ต่ำกว่า threshold นี้ → gross spread ที่ entry ไม่ครอบคลุม friction → net_edge < 0 → ห้ามเทรด

Optimal Substantial Variance — นิยามเชิงปฏิบัติ

σ_stat ที่ "พอเหมาะ" ต้องตอบ สองเงื่อนไขพร้อมกัน:

  • Lower bound: σ_stat ≥ total_cost / (z_entry − z_exit) → กว้างพอกว่า friction (breakeven condition)
  • Upper bound: Half-life ≤ N bars → spread ไม่ค้างนานเกินไปจน margin cost กินกำไร

ช่วงระหว่าง lower–upper bound นี้คือ "Tradeable Window" ของกลยุทธ์ Hybrid

4.6 การหา β ในทางปฏิบัติ — เลือกข้อมูล ประเมินคุณภาพ และข้อผิดพลาด

ก่อนลงรายละเอียดว่าใช้ method ไหน ต้องเข้าใจ ตำแหน่งของ β ในภาพใหญ่ก่อน — สิ่งที่เราต้องการสร้างจริงๆ ไม่ใช่ β แต่เป็น ε (synthetic process) ส่วน β คือแกนสำคัญที่สุดที่ทำให้สร้าง ε ได้ ถูกสัดส่วน

แก่นความคิด — β คือสูตรผสม, ε คือของใหม่ที่เกิดจากการผสม
ε = F(A) − β·F(B)

β คือ อัตราส่วนผสม (mixing ratio / hedge ratio) ที่ตอบว่า "ถ้ามี A 1 หน่วย ต้องใช้ B กี่หน่วยมาหักล้าง?" — ประโยคที่แม่นที่สุดคือ: β คืออัตราส่วนที่ใช้ผสมสองสิ่ง เพื่อให้ได้ ε ที่มีคุณสมบัติเทรดได้

βสมการ εความหมายของการผสม
β = 1ε = A − Bผสม 1:1 — ใช้ B เท่ากับ A
β = 0.8ε = A − 0.8Bใช้ B แค่ 0.8 เท่าของ A
β = 1.3ε = A − 1.3Bใช้ B มากกว่า A เพื่อหักล้าง exposure ให้พอดี
ตัวอย่างจำง่าย — ทำไมไม่ดูแค่ A − B

ให้ A = BTC basis บน Lighter, B = BTC basis บน Bybit — เราไม่ดูแค่ผลต่างดิบ A − B แต่ดู ε = A − βB เพราะ β ตอบว่า "Bybit basis ควรถูกถ่วงน้ำหนักเท่าไร จึงหักล้าง Lighter basis ได้พอดี" ถ้าถ่วงผิดสัดส่วน ส่วนที่เหลือจะไม่ใช่ inefficiency แท้ แต่เป็น market move ที่หักล้างไม่หมด → signal หลอก

β กำหนดว่า process ใหม่จะ "หน้าตา" เป็นอย่างไร — มันไม่ใช่แค่ตัวเลขประกอบสูตร แต่เป็นตัวกำหนดโครงสร้างของ synthetic process:

β ดี → ε ที่เทรดได้

common movement ถูกหักล้าง · ε นิ่งขึ้น · mean reversion ชัดขึ้น · เป็น risk-neutral จริง

β สำคัญมาก แต่ ไม่ใช่ทุกอย่าง — มันเป็นขั้นที่ 3 ของกระบวนการสร้าง process ต้องมี pair selection + transformation มาก่อน และมี diagnostics + execution gate ตามหลัง:

β เป็นขั้นที่ 3 — ขาดขั้นไหนก็สร้าง ε ที่เทรดได้จริงไม่ได้ บทที่ 4 โฟกัสที่ขั้น Beta
β เป็นแนวคิดทั่วไป — ใน option เรียกว่า Delta

หลักการ "หาอัตราส่วนที่ถูกต้องเพื่อสร้าง process ใหม่" ใช้ได้กับทุก asset class — ใน option process: ε = Option − Δ·Underlying โดย Δ (delta) ทำหน้าที่เป็น hedge ratio แทน β แนวคิดเดียวกัน: ไม่จำเป็นต้องผสม 1:1

4.6.2 β หักล้าง exposure — ไม่ใช่ทำมูลค่าให้เท่ากัน

จุดที่หลายคนสับสน: A − βB ไม่ได้แปลว่าต้องทำให้ βB มีค่า "เท่ากับ" A ตลอดเวลา — βB คือ ส่วนของ A ที่ B อธิบายได้ ส่วนที่เหลือคือ ε

การแยกส่วน — A = ส่วนที่เคลื่อนตาม B + ส่วนผิดปกติ
A = βB + ε

βB = "เส้น fair relationship" (ส่วนที่เคลื่อนตาม B) · ε = ส่วนผิดปกติที่เหลือหลังใช้ B อธิบาย A — βB ไม่ใช่ราคาที่ต้องเท่ากับ A เสมอ

สถานะεความหมาย

A > βBε > 0A แพงกว่าที่ควรเป็นเมื่อเทียบกับ B
A < βBε < 0A ถูกกว่าที่ควรเป็นเมื่อเทียบกับ B

แล้ว β ผิด ทำให้กลายเป็น directional ได้อย่างไร? สมมติ A และ B ถูกขับเคลื่อนด้วยแรงตลาดเดียวกัน (เช่น BTC market factor):

A = market_factor + noise_A B = market_factor + noise_B β ถูก: ε = A − βB ≈ noise ← market factor ถูกหักล้าง β ผิด: ε = A − βB = noise + market exposure ที่ค้างอยู่ ← กลายเป็น directional โดยไม่รู้ตัว
ตัวอย่าง: A เคลื่อนไหวแรงกว่า B ราว 2 เท่า (A ≈ 2B)

ใช้ ε = A − 1·B → ยังเหลือ exposure ต่อ B เยอะ เพราะ A ขยับมากกว่าที่ 1B หักล้างได้
ใช้ ε = A − 2·B → ส่วนที่เคลื่อนไหวร่วมกันถูกหักล้างพอดี
→ β ทำให้ ความไวต่อ common factor เท่ากัน ไม่ใช่ทำให้ มูลค่า เท่ากัน

β ที่ถูกต้องทำให้ ε เป็น residual ที่ mean-revert — β ผิดทำให้ ε ยังพก market exposure ค้างอยู่

ทำไมต้องทดสอบ — สมการแสดงที่มาของ exposure ที่เหลือ

เขียน spread change เป็นสมการ:

Δε = (exposure_A − β × exposure_B) × market_return + noise

ถ้า β ถูกต้อง → exposure_A − β × exposure_B ≈ 0 → ε ไม่ขึ้นกับตลาด
ถ้า β ผิด → เทอมแรกไม่ใช่ศูนย์ → ε correlate กับ market_return → directional bet แฝง

β ที่เหมาะสมจึงต้องอยู่ที่:

β ≈ exposure_A / exposure_B

เช่น BTC Lighter vs BTC Bybit — ถ้า Lighter sensitive ต่อ BTC มากกว่า Bybit 1.2× → β ≈ 1.2 ไม่ใช่ 1.0

6 วิธีตรวจว่า ε เป็น residual จริง ไม่ใช่ directional แฝง

Test 1 — Correlation กับ market return

corr(Δε, market_return)
  • |r| < 0.20 → ดี (ε แทบไม่ขึ้นกับทิศตลาด)
  • |r| > 0.50 → β ยัง hedge ไม่ดี → ต้องปรับ β หรือเปลี่ยน pair

Test 2 — Factor regression

Δε = α + γ · market_return + error
  • γ ≈ 0 (p-value > 0.05) → hedged ดี — market exposure ถูกหักล้างแล้ว
  • |γ| ใหญ่ (t-stat > 2) → exposure ยังหลงเหลือ → ε ไม่บริสุทธิ์

Test 3 — PnL แยกตามทิศทางตลาด

  • แบ่ง: ตลาดขึ้น > 1% / ลง > 1% / Sideways (±1%)
  • stat arb จริง → PnL กระจายสม่ำเสมอ ไม่ขึ้นกับทิศทาง
  • PnL ดีเฉพาะ "ตลาดขึ้น" → กำไรมาจาก beta ไม่ใช่ spread reversion

Test 4 — Stationarity (จำเป็นแต่ไม่เพียงพอ)

  • ADF / KPSS ต้องผ่าน — แต่ stationarity ไม่ได้พิสูจน์ว่า β ถูก
  • ε stationary แต่ corr กับตลาดสูง → β ผิด directional ยังแฝงอยู่
  • ε non-stationary และ corr สูง → pair ไม่ดีทั้งคู่

Test 5 — Half-life และ Crossing Rate

  • τ₁/₂ ต้องอยู่ใน target horizon (บทที่ 3)
  • φ ควรอยู่ใน sweet spot 0.85–0.97 สำหรับ swing (บทที่ 5 §5.7)
  • ถ้า Test 1–3 ผ่านแต่ half-life ยาวเกิน → pair ดี แต่ยังไม่เหมาะ intraday

4.7 Pseudo-code

# OLS Beta
function beta_ols(r_A, r_B):
  return cov(r_A, r_B) / var(r_B)

# TLS Beta (via eigenvalue)
function beta_tls(r_A, r_B):
  C = cov_matrix([[r_A], [r_B]]) # 2×2
  eigenvalues, eigenvectors = eig(C)
  v = eigenvectors[:, argmin(eigenvalues)] # smallest eigenvalue
  return -v[0] / v[1]

# Kalman Filter Beta (one-step update)
function kalman_beta_update(beta, P, r_A, r_B, Q, R):
  # Predict
  P_pred = P + Q
  # Kalman gain
  K = P_pred * r_B / (r_B**2 * P_pred + R)
  # Update
  innovation = r_A - beta * r_B
  beta_new = beta + K * innovation
  P_new = (1 - K * r_B) * P_pred
  return beta_new, P_new

โจทย์ 4.1 — คำนวณ β_OLS จากข้อมูล

Log returns รายวัน 5 วัน:

ถาม: คำนวณ β_OLS (Bybit เป็น A, Lighter เป็น B)

ดูคำตอบ

r̄_A = (1.20−0.80+2.10−1.50+0.60)/5 = 1.60/5 = 0.320%
r̄_B = (1.15−0.75+2.05−1.48+0.58)/5 = 1.55/5 = 0.310%

Cov(r_A,r_B) = Σ(r_A−r̄_A)(r_B−r̄_B) / (n−1):
= [(0.88)(0.84) + (−1.12)(−1.06) + (1.78)(1.74) + (−1.82)(−1.79) + (0.28)(0.27)] / 4
= [0.739 + 1.187 + 3.097 + 3.258 + 0.076] / 4 = 8.357/4 = 2.089

Var(r_B) = Σ(r_B−r̄_B)² / (n−1) = [0.706 + 1.124 + 3.024 + 3.204 + 0.073] / 4 = 2.033

β_OLS = 2.089 / 2.033 = 1.028
→ Long Bybit $100,000 ต้อง Short Lighter $102,800

โจทย์ 4.2 — เลือกวิธีหา β

คุณ trade spread ระหว่าง BTC perpetual บน Binance (volume 10× ของ Lighter) กับ Lighter
ทั้งสองตลาดมี liquidity ต่างกันมาก — Binance เป็น "price discovery" หลัก

ถาม: ควรใช้ OLS หรือ TLS? และ Binance ควรเป็น A หรือ B ใน regression?

ดูคำตอบ

ใช้ OLS เพราะ Binance มี volume มากกว่า → ราคา Binance เป็น "true price" ที่ error น้อยกว่า OLS assume B ไม่มี noise ดังนั้น Binance = B (ตัวที่ regress ต่อ)

Regression: r_Lighter = α + β·r_Binance + ε
β = Cov(r_Lighter, r_Binance) / Var(r_Binance)

ความหมาย: ε = r_Lighter − β·r_Binance → trade Lighter เมื่อ Lighter เบี่ยงจาก Binance

โจทย์ 4.3 — Kalman Q/R tuning

คุณตั้ง Kalman กับ Q=1e-9 (เล็กมาก) และ R=1e-4 (ใหญ่มาก)
สังเกตว่า β_Kalman แทบไม่เปลี่ยนเลย แม้ตลาดจะเปลี่ยน

ถาม: อธิบายว่าเกิดอะไรขึ้น และควรปรับ Q หรือ R อย่างไร?

ดูคำตอบ

Q เล็กมาก → model บอกว่า β เปลี่ยนช้ามาก
R ใหญ่มาก → model บอกว่า observation noisy มาก
Kalman Gain K = P·r_B / (r_B²·P + R) → R ใหญ่ทำให้ K เล็กมาก → β ไม่อัปเดต

แก้: เพิ่ม Q (เช่น 1e-6) เพื่อให้ model อนุญาตให้ β เปลี่ยนเร็วขึ้น
หรือลด R (เช่น 1e-5) เพื่อ trust ข้อมูลมากขึ้น
Tune โดย backtest: ดู β ว่า responsive พอแต่ไม่ noisy เกินไป
