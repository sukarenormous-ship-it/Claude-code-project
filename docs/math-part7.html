ตอนเปิดเล่ม สูตรนี้คงดูเหมือนอักษรอียิปต์โบราณ:

C = S₀·N(d₁) − K·e^(−rT)·N(d₂)

วันนี้คุณอ่านมันออกทุกตัวอักษร และรู้ด้วยว่าแต่ละตัวมาจากบทไหน · S₀ กับ K คือฟังก์ชันกับ Strike (Part I) · e−rT คือ PV (Part I) · N(d) คือพื้นที่ใต้ระฆัง (Part II) · d มี σ, ln, √T, และเทอม Ito ซ่อนอยู่ (Part II–IV) · Part นี้คือรอบพิสูจน์ว่าเดินทางมาครบวง

สูตรที่เคยขู่ให้เรากลัว กลายเป็นประโยคที่เราแต่งเองได้ — เพราะเราสร้างมันขึ้นมาทีละคำ

บทที่ 11: อ่าน Black-Scholes ออกทุกตัว

11.1 สูตรฉบับเต็ม

C = S₀·N(d₁) − K·e^(−rT)·N(d₂) P = K·e^(−rT)·N(−d₂) − S₀·N(−d₁) d₁ = [ ln(S₀/K) + (r + σ²/2)·T ] / (σ√T) d₂ = d₁ − σ√T

📖 อ่านสูตรว่า: "ซี เท่ากับ เอสศูนย์ คูณ เอ็นของดีหนึ่ง ลบ เค คูณ อี ยกกำลัง ลบอาร์ที คูณ เอ็นของดีสอง · ดีหนึ่ง เท่ากับ วงเล็บ ล็อกของเอสศูนย์ส่วนเค บวก วงเล็บ อาร์ บวก ครึ่งซิกมากำลังสอง คูณ ที ทั้งหมดหารด้วย ซิกมารูทที · ดีสอง เท่ากับ ดีหนึ่ง ลบ ซิกมารูทที" · โครงที่ต้องเห็น: "สิ่งที่ได้ × โอกาส ลบ สิ่งที่จ่าย × โอกาส" โดยก้อนหลังติดตัวลดค่า e−rT · d₁, d₂ ไร้หน่วย: ln(S₀/K) เป็นล็อกของอัตราส่วน (r + σ²/2)T คือ "ต่อปี × ปี" ตัวส่วน σ√T ก็เป็น % — ทุกอย่างวัดเป็น "จำนวน σ" คือ Z-score ของ Part II · ลอง S₀ = K, r = 0: ln(1) = 0 → d₁ = σ√T/2 และ d₂ = −σ√T/2 สมมาตรรอบศูนย์ · กับดักการอ่าน: N(d₁) คือฟังก์ชัน CDF (ค่า 0–1) ไม่ใช่ N คูณ d₁ · N(−d) = 1 − N(d) ไม่ใช่ −N(d) · d₂ ต่ำกว่า d₁ พอดี σ√T เสมอ จึง N(d₂) < N(d₁): Delta ของ Call มากกว่าโอกาสจบ ITM (กับดักใน 11.2) · ตัวห้อย 1, 2 คือหมายเลข ไม่ใช่เวลา

11.2 ไล่ทีละตัว — มาจากบทไหน

11.3 วิธีทำด้วยมือ — คิดราคา BS ทีละขั้น

🚶 อ่านเป็นภาษาคนก่อน: สูตรดูน่ากลัว แต่การ "แทนเลข" จริง ๆ มีแค่ 4 ขั้น: (1) คิด d₁ (2) คิด d₂ (3) เปิดตาราง N(d) จาก Part II (4) แทนลงสูตร C เราจะทำให้ครบทุกปุ่มกด ด้วยเลขชุดเดียวที่จะใช้ตลอดบทนี้

📋 โจทย์ตัวอย่าง (จำเลขชุดนี้ไว้)
  • ราคาหุ้นวันนี้ S₀ = 100 บาท
  • ราคาใช้สิทธิ์ K = 100 บาท (ATM — at the money)
  • ดอกเบี้ย r = 5% ต่อปี = 0.05
  • ความผันผวน σ = 25% ต่อปี = 0.25
  • เวลาถึงหมดอายุ T = 1 ปี

อยากรู้: Call ตัวนี้ควรราคาเท่าไร?

🧮 คิดทีละขั้น

ขั้น 1 — คิด d₁ เริ่มจากตัวเศษก่อน แล้วค่อยหารด้วย σ√T

ln(S₀/K) = ln(100/100) = ln(1) = 0 ← ATM ทำให้เทอมนี้เป็น 0 พอดี (r + σ²/2)·T = (0.05 + 0.25²/2)·1 = (0.05 + 0.0625/2) = (0.05 + 0.03125) = 0.08125 σ√T = 0.25 × √1 = 0.25 d₁ = (0 + 0.08125) / 0.25 = 0.325

ขั้น 2 — คิด d₂ ง่ายมาก แค่ลบ σ√T ออกจาก d₁

d₂ = d₁ − σ√T = 0.325 − 0.25 = 0.075

ขั้น 3 — หา N(d) (พื้นที่สะสมใต้ระฆัง จาก Part II) · ตาราง N(d) ใน Part II §6.3 เป็นค่ากลม ๆ (d = −2…+2) แต่ d₁=0.325 ละเอียดกว่านั้น จึงคำนวณตรงจากฟังก์ชัน erf (โค้ด Python อยู่ท้าย §6.3): N(d) = ½[1 + erf(d/√2)] — ใส่ d ลงเครื่องคิดเลข/โค้ดได้ค่าเป๊ะ

N(d₁) = N(0.325) ≈ 0.6274 ← โอกาสสะสมถึง Z=0.325 (มากกว่าครึ่งนิดหน่อย เพราะ d₁ > 0) N(d₂) = N(0.075) ≈ 0.5299 ← โอกาสสะสมถึง Z=0.075 (เกินครึ่งมานิดเดียว)

อ่านความหมาย: N(d₂)=0.53 คือ "โอกาส (risk-neutral) ที่ตอนหมดอายุหุ้นจะจบเหนือ K" — ประมาณ 53% · N(d₁)=0.63 คือ Delta ไม่ใช่โอกาส (ย้ำกับดักจาก 11.2)

ขั้น 4 — แทนลงสูตร C

C = S₀·N(d₁) − K·e^(−rT)·N(d₂) = 100 × 0.6274 − 100 × e^(−0.05) × 0.5299 = 62.74 − 100 × 0.9512 × 0.5299 = 62.74 − 50.41 = 12.34 บาท (ค่าละเอียด = 12.336)
✅ อ่านผลลัพธ์เป็นภาษาคน

Call ATM อายุ 1 ปี บนหุ้น 100 บาท ที่ผันผวน 25% ควรมีราคา ≈ 12.3 บาท หรือ ≈ 12.3% ของราคาหุ้น · มีกฎนิ้วโป้งไว้ประมาณในหัว (แม่นสุดเมื่อดอกเบี้ย r ≈ 0): ราคา Call ATM ≈ 0.4 × σ × √T × S₀ = 0.4 × 0.25 × 1 × 100 = 10 บาท · ที่นี่ได้ 10 ต่ำกว่าค่าจริง 12.3 อยู่ ~20% เพราะกฎนี้ยังไม่รวมผลของดอกเบี้ย (r=5% ดันมูลค่าขึ้น) — ใช้เดาคร่าว ๆ ได้ แต่ไม่ใช่ค่าเป๊ะ

11.4 🐍 Python — ราคา + Greeks ครบในไฟล์เดียว

🚶 อ่านเป็นภาษาคนก่อน: ที่คิดด้วยมือข้างบน แปลงเป็นโค้ดได้ตรง ๆ ทีละบรรทัด · โค้ดนี้ไม่ต้องลงไลบรารีอะไรเลย (ใช้แค่ math ที่ติดมากับ Python) คัดลอกไปรันได้ทันที

🐍 Python — ราคา Black-Scholes (ใช้แค่ math ในตัว)
# ไม่ต้อง pip install อะไรเลย — math.erf ให้ N(d) ได้
from math import log, sqrt, exp, erf, pi

def N(x):                       # CDF ของ Normal = พื้นที่สะสมใต้ระฆัง
    return 0.5 * (1 + erf(x / sqrt(2)))

def bs_call(S, K, r, sig, T):
    d1 = (log(S/K) + (r + sig**2/2)*T) / (sig*sqrt(T))
    d2 = d1 - sig*sqrt(T)
    C  = S*N(d1) - K*exp(-r*T)*N(d2)
    return C, d1, d2

S, K, r, sig, T = 100, 100, 0.05, 0.25, 1     # โจทย์เดียวกับที่คิดด้วยมือ
C, d1, d2 = bs_call(S, K, r, sig, T)
print(f"d1 = {d1:.4f}")                        # d1 = 0.3250
print(f"d2 = {d2:.4f}")                        # d2 = 0.0750
print(f"N(d1) = {N(d1):.4f}")                  # N(d1) = 0.6274
print(f"N(d2) = {N(d2):.4f}")                  # N(d2) = 0.5299
print(f"ราคา Call = {C:.4f}")                  # ราคา Call = 12.3360

ตรงเป๊ะกับที่คิดด้วยมือ (12.34) · ทีนี้เติม Greeks ทั้ง 5 ตัว จาก Part III ในฟังก์ชันเดียว — แต่ละบรรทัดคือสูตร Greek หนึ่งตัว:

🐍 Python — Greeks ครบ 5 ตัว (Delta·Gamma·Vega·Theta·Rho)
from math import log, sqrt, exp, erf, pi

def N(x):  return 0.5*(1 + erf(x/sqrt(2)))     # CDF (พื้นที่สะสม)
def phi(x): return exp(-x*x/2) / sqrt(2*pi)    # PDF (ความสูงระฆัง)

def bs_greeks(S, K, r, sig, T):
    d1 = (log(S/K) + (r + sig**2/2)*T) / (sig*sqrt(T))
    d2 = d1 - sig*sqrt(T)
    delta = N(d1)                              # Part III: ∂C/∂S
    gamma = phi(d1) / (S*sig*sqrt(T))          # ∂²C/∂S²
    vega  = S*phi(d1)*sqrt(T) / 100            # ต่อ σ +1% (จึง /100)
    theta = (-(S*phi(d1)*sig)/(2*sqrt(T))
             - r*K*exp(-r*T)*N(d2)) / 365      # ต่อวัน (จึง /365)
    rho   = K*T*exp(-r*T)*N(d2) / 100          # ต่อ r +1%
    return delta, gamma, vega, theta, rho

delta, gamma, vega, theta, rho = bs_greeks(100, 100, 0.05, 0.25, 1)
print(f"Delta = {delta:+.4f}")                 # Delta = +0.6274
print(f"Gamma = {gamma:+.4f}")                 # Gamma = +0.0151
print(f"Vega  = {vega:+.4f}")                  # Vega  = +0.3784  (ต่อ σ +1%)
print(f"Theta = {theta:+.4f}")                 # Theta = -0.0199  (ต่อวัน)
print(f"Rho   = {rho:+.4f}")                   # Rho   = +0.5040  (ต่อ r +1%)
✅ อ่าน Greeks เป็นภาษาคน (โยงกลับ Part III)
  • Delta +0.63 — หุ้นขึ้น 1 บาท option ขึ้น ~0.63 บาท (และ = N(d₁) พอดี)
  • Gamma +0.015 — หุ้นขึ้น 1 บาท Delta เพิ่มอีก ~0.015 (สูงสุดตอน ATM แบบนี้)
  • Vega +0.38 — σ ขยับขึ้น 1% option แพงขึ้น ~0.38 บาท
  • Theta −0.02 — ผ่านไป 1 วันโดยหุ้นอยู่นิ่ง option เสียค่า ~2 สตางค์ (time decay)
  • Rho +0.50 — ดอกเบี้ยขึ้น 1% Call แพงขึ้น ~0.50 บาท
✍️ ลองทำเอง

เปลี่ยนโจทย์เป็น OTM Call: K = 110 (ตัวอื่นเท่าเดิม) แล้วลองทั้งมือและโค้ด · คาดเดาก่อนรัน: ราคาควรถูกลง และ Delta ควรต่ำกว่า 0.5 (เพราะโอกาส ITM น้อยลง)

11.5 Put-Call Parity ร่วงออกมาจาก BS เอง

💎 โมเมนต์ที่ควรหยุดดู — ทุกอย่างบรรจบ

เอาสูตร C ลบ P ตรง ๆ แล้วใช้สมบัติเดียว N(x) + N(−x) = 1 (พื้นที่ระฆังซ้าย+ขวา = 1) Put-Call Parity ที่เราเรียนตั้งแต่ Part I จะร่วงออกมาเอง:

C − P = S₀·N(d₁) − K·e^(−rT)·N(d₂) − [ K·e^(−rT)·N(−d₂) − S₀·N(−d₁) ] = S₀·[N(d₁)+N(−d₁)] − K·e^(−rT)·[N(d₂)+N(−d₂)] = S₀·(1) − K·e^(−rT)·(1) ← N(x)+N(−x) = 1 = S₀ − K·e^(−rT) → C + K·e^(−rT) = P + S₀ ✓ Put-Call Parity!

📖 อ่านสูตรว่า: "ซี ลบ พี เท่ากับ เอสศูนย์ คูณ วงเล็บ เอ็นของดีหนึ่ง บวก เอ็นของลบดีหนึ่ง ลบ เค อี ยกกำลัง ลบอาร์ที คูณ วงเล็บ เอ็นของดีสอง บวก เอ็นของลบดีสอง" · โครงที่ต้องเห็น: จัดกลุ่มตามตัวคูณร่วม (S₀ กับ K·e−rT) แล้วทุกวงเล็บยุบเป็น 1 ด้วยความสมมาตรของระฆัง — ผลลัพธ์ไม่มี σ และไม่มี N เหลืออยู่เลย · กับดักการอ่าน: N(−d) คือ "พื้นที่ฝั่งซ้ายของ −d" ไม่ใช่ −N(d) จึงบวกกับ N(d) ได้ 1 · การที่ σ หายไปแปลว่า Parity ไม่ได้พึ่งสมมติฐานของ BS — จริงแม้ BS จะผิด (11.6)

🔗 ทุกอย่างเชื่อมกัน

Put-Call Parity (Part I) ← ร่วงจาก BS formula ← มาจาก Ito's Lemma (Part IV) ← มาจาก Chain Rule (Part III) + Brownian Motion (Part IV) ← มาจาก Normal Distribution (Part II) ← มาจาก e, ln (Part I) · หนังสือทั้งเล่มคือวงกลมวงเดียวที่ปิดสนิทตรงนี้

12.1 แนวคิด Monte Carlo

🚶 อ่านเป็นภาษาคนก่อน: ถ้าคำนวณตรง ๆ ไม่ได้ ก็ "ลองสุ่มดูเยอะ ๆ แล้วเฉลี่ย" · Law of Large Numbers รับรองว่ายิ่งสุ่มมาก ค่าเฉลี่ยยิ่งเข้าใกล้คำตอบจริง

1. สุ่ม Z ~ N(0,1) จำนวน N ครั้ง (เช่น N = 100,000) 2. S(T) = S₀ · exp( (r − σ²/2)·T + σ√T·Z ) ← drift risk-neutral = r − σ²/2 3. Payoff แต่ละเส้นทาง: max(0, S(T) − K) 4. ราคา Call = e^(−rT) · ค่าเฉลี่ยของ Payoff ทั้งหมด

📖 อ่านสูตรว่า: "เอสที เท่ากับ เอสศูนย์ คูณ เอ็กซ์โพเนนเชียลของ วงเล็บ อาร์ ลบ ครึ่งซิกมากำลังสอง คูณ ที บวก ซิกมารูทที คูณ แซด" · Z ~ N(0,1) อ่านว่า "แซด สุ่มมาจากนอร์มัลมาตรฐาน" (~ = มีการแจกแจงแบบ) · โครงที่ต้องเห็น: "ค่าเฉลี่ย ลบ ครึ่ง variance" คูณเวลา บวก "σ√T คูณช็อก" — drift ใช้ r ไม่ใช่ μ เพราะอยู่ในโลก risk-neutral และ −σ²/2 คือเทอม Ito ที่ทำให้ค่าเฉลี่ยของ S(T) โตแค่ r พอดี · ลอง Z = 0: ได้ S₀·e(r−σ²/2)T คือเส้นทางกลาง (median) ซึ่งต่ำกว่าค่าเฉลี่ย S₀erT · กับดักการอ่าน: exp(…) คือ e ยกกำลังทั้งวงเล็บ · N ในบรรทัด 1 คือจำนวนเส้นทาง ส่วน N(0,1) คือชื่อการแจกแจง และ N(d) ใน BS คือ CDF — ตัว N สามหน้าที่ใน Part เดียว · σ√T ไม่ใช่ σT: ช็อกโตตามรากที่สองของเวลา

12.2 🐍 Python — เขียน Monte Carlo จริง (ทั้ง 4 ขั้น = 5 บรรทัด)

🚶 อ่านเป็นภาษาคนก่อน: 4 ขั้นข้างบนแปลงเป็นโค้ดได้เกือบ 1:1 · ใช้ numpy เพราะต้องสุ่มเป็นแสน ๆ ครั้ง (numpy ทำทั้งก้อนพร้อมกัน เร็วกว่า loop ธรรมดาเป็นร้อยเท่า) · ติดตั้งด้วย pip install numpy

🐍 Python — Monte Carlo pricer + ทดสอบการลู่เข้า
import numpy as np

S, K, r, sig, T = 100, 100, 0.05, 0.25, 1
rng = np.random.default_rng(42)      # ตั้ง seed → ผลซ้ำได้ทุกครั้ง

def mc_call(N):
    Z  = rng.standard_normal(N)                              # ขั้น 1: สุ่ม Z~N(0,1) N ตัว
    ST = S * np.exp((r - sig**2/2)*T + sig*np.sqrt(T)*Z)     # ขั้น 2: ราคาหุ้นวันหมดอายุ
    payoff = np.maximum(ST - K, 0)                           # ขั้น 3: payoff ราย path
    price  = np.exp(-r*T) * payoff.mean()                    # ขั้น 4: เฉลี่ยแล้วคิดลด
    se     = np.exp(-r*T) * payoff.std(ddof=1) / np.sqrt(N)  # ค่าคลาดเคลื่อนมาตรฐาน
    return price, se

for N in [1_000, 10_000, 100_000, 1_000_000]:
    price, se = mc_call(N)
    print(f"N={N:>9,}  ราคา={price:6.3f}  ± {se:.3f}")
# N=    1,000  ราคา=11.643  ± 0.562
# N=   10,000  ราคา=12.269  ± 0.186
# N=  100,000  ราคา=12.313  ± 0.059
# N=1,000,000  ราคา=12.345  ± 0.019   ← ใกล้ BS จริง (12.336) มาก

12.3 Exotic Options — ที่ BS แก้ไม่ได้

🚶 อ่านเป็นภาษาคนก่อน: option พื้นฐานสนใจแค่ราคาวันหมดอายุ แต่ exotic บางตัวสนใจทั้งเส้นทาง (เฉลี่ย, สูงสุด, เคยแตะเส้นไหม) ซึ่ง BS สูตรเดียวจับไม่ได้ — แต่ MC จำลองทั้งเส้นทางอยู่แล้ว จึงตั้งราคาได้สบาย

ExoticPayoff ขึ้นกับทำไมต้อง MC
Asianราคาเฉลี่ยตลอดทางสูตรปิดไม่มี (ค่าเฉลี่ยของ lognormal)
Barrierเคยแตะเส้น barrier ไหมขึ้นกับทั้งเส้นทาง
Lookbackราคาสูงสุดตลอดทางขึ้นกับทั้งเส้นทาง
Basketหลายสินทรัพย์พร้อมกันต้องจำลอง correlation หลายตัว

ลองตั้งราคา Asian Call จริง (payoff = max(0, ราคาเฉลี่ยตลอดปี − K)) — โจทย์ที่ BS สูตรเดียวทำไม่ได้ แต่ MC แค่เพิ่มมิติเวลาเข้าไป แล้วเฉลี่ยตามแถว:

🐍 Python — Asian Option (BS ทำไม่ได้ · MC ทำได้)
import numpy as np

S, K, r, sig, T = 100, 100, 0.05, 0.25, 1
steps, paths = 252, 100_000          # 252 วันทำการ, จำลองแสนเส้นทาง
dt = T / steps
rng = np.random.default_rng(7)

Z = rng.standard_normal((paths, steps))                     # สุ่มทั้งกริด (path × วัน)
logpath = np.cumsum((r - sig**2/2)*dt + sig*np.sqrt(dt)*Z, axis=1)  # เดินทีละวัน
price_path = S * np.exp(logpath)                            # ราคาหุ้นทุกวันตลอดปี

avg = price_path.mean(axis=1)                               # ★ เฉลี่ยตลอดทาง = หัวใจ Asian
asian = np.exp(-r*T) * np.maximum(avg - K, 0).mean()
print(f"Asian call = {asian:.4f}")   # Asian call = 6.8065
✅ อ่านผลลัพธ์

Asian ≈ 6.81 บาท — ถูกกว่า vanilla Call (12.34) เกือบครึ่ง · เพราะ "ค่าเฉลี่ย" ผันผวนน้อยกว่า "ราคาวันสุดท้าย" (ค่าเฉลี่ยกลบ spike ทิ้ง) → σ ที่มีผลต่ำลง → option ถูกลง · จุดสำคัญ: เราแค่เปลี่ยนบรรทัดเดียว (max(0, ราคาสุดท้าย−K) → max(0, ค่าเฉลี่ย−K)) ก็ตั้งราคา exotic ได้ ทั้งที่ไม่มีสูตรปิดเลย — นี่คือพลังของ MC

12.4 Variance Reduction (ทำให้แม่นขึ้นโดยไม่เพิ่มเส้นทาง)

เทคนิควิธีผล
Antitheticสุ่ม Z แล้วใช้ −Z ด้วย (คู่สมมาตร)ลด variance ~ครึ่ง
Control Variateใช้ option ที่มีสูตรปิดเป็น "ตัวคุม"ลด variance มาก

พิสูจน์ว่า Antithetic แม่นขึ้นจริง — ประเมิน payoff เท่ากัน (100,000 จุด) แต่สุ่มเลขจริงแค่ครึ่งเดียว (50,000) แล้วจับคู่ +Z กับ −Z:

🐍 Python — Antithetic ลด se โดยไม่เพิ่มการสุ่ม
import numpy as np

S, K, r, sig, T = 100, 100, 0.05, 0.25, 1
disc, N = np.exp(-r*T), 100_000

# --- วิธีธรรมดา: สุ่ม 100,000 ตัวรวด ---
rng = np.random.default_rng(0)
Z   = rng.standard_normal(N)
pay = disc * np.maximum(S*np.exp((r-sig**2/2)*T + sig*np.sqrt(T)*Z) - K, 0)
print(f"ธรรมดา     : {pay.mean():.4f}   se={pay.std(ddof=1)/np.sqrt(N):.4f}")
# ธรรมดา     : 12.3189   se=0.0585

# --- Antithetic: สุ่มแค่ 50,000 แล้วจับคู่ +Z กับ −Z ---
rng = np.random.default_rng(0)
Zh  = rng.standard_normal(N//2)
up  = disc * np.maximum(S*np.exp((r-sig**2/2)*T + sig*np.sqrt(T)*Zh)    - K, 0)
dn  = disc * np.maximum(S*np.exp((r-sig**2/2)*T + sig*np.sqrt(T)*(-Zh)) - K, 0)
pair = (up + dn) / 2                          # เฉลี่ยรายคู่
print(f"antithetic : {pair.mean():.4f}   se={pair.std(ddof=1)/np.sqrt(N//2):.4f}")
# antithetic : 12.3662   se=0.0437   ← se ลดจาก 0.0585 (แม่นขึ้น ~25% ฟรี)
✍️ ลองทำเอง

เอาโค้ด Monte Carlo พื้นฐาน (12.2) มาเปลี่ยน payoff เป็น Put: np.maximum(K - ST, 0) แล้วรัน N=100,000 · คาดเดาก่อน: ควรได้ราคาใกล้ 7.46 (ค่า Put จาก Put-Call Parity ในบท 11) — ถ้าใกล้ แปลว่าโค้ดคุณถูก ✓

12.5 Euler-Maruyama — เมื่อไม่มีทางลัดให้เดิน

🚶 อ่านเป็นภาษาคนก่อน: โค้ดทุกกล่องในบทนี้เดินราคาด้วยบรรทัดหน้าตาแบบนี้ — (r − σ²/2)·dt + σ·√dt·Z · สิ่งที่ยังไม่ได้บอกคือบรรทัดนั้นไม่ใช่ค่าประมาณ มันเป๊ะ · และมันเป๊ะได้เพราะโชคดีอย่างหนึ่งที่จะหมดไปทันทีที่คุณขยับออกจาก GBM

💎 ทำไม GBM ถึงเดินแบบเป๊ะได้

ย้อนกลับไป Part IV · Itô's Lemma บอกว่าถ้า dS/S = μ dt + σ dW แล้ว d(ln S) = (μ − σ²/2)dt + σ dW

ฝั่งขวาของสมการหลัง ไม่มี ln S อยู่เลย — สัมประสิทธิ์เป็นค่าคงที่ทั้งคู่ · แปลว่าเราอินทิเกรตมันตรง ๆ ได้ และได้คำตอบปิด:

ln S(t+Δt) = ln S(t) + (μ − σ²/2)·Δt + σ·√Δt·Z

📖 อ่านสูตรว่า: "ล็อกของเอสที่เวลาทีบวกเดลตาที เท่ากับ ล็อกของเอสที่เวลาที บวก วงเล็บ มิว ลบ ครึ่งซิกมากำลังสอง คูณ เดลตาที บวก ซิกมา คูณ รูทเดลตาที คูณ แซด" · โครงที่ต้องเห็น: สูตรอ้างตัวเองก้าวก่อน (recursive) บนล็อกราคา — ก้าวหน้า = ค่าเดิม + drift×เวลา + ช็อก×√เวลา · ลอง σ = 0: ln S เพิ่ม μΔt ทุกก้าว = ทบต้นต่อเนื่อง S₀eμt พอดี · กับดักการอ่าน: Δt คือความยาวก้าว (Δ = การเปลี่ยนแปลง ไม่ใช่ Delta) และ √Δt ไม่ใช่ Δt · μ ตรงนี้คือ drift จริงสำหรับจำลองโลกจริง ส่วนตอนตั้งราคาใน 12.1 ต้องแทนด้วย r · S(t+Δt) วงเล็บคือ "ราคา ณ เวลา" ไม่ใช่การคูณ · Z สุ่มใหม่ทุกก้าว ไม่ใช่ตัวเดิม

ไม่ว่า Δt จะใหญ่แค่ไหน บรรทัดนี้ก็ถูกต้อง 100% · จะเดินทีละวัน ทีละเดือน หรือกระโดดข้ามไปทั้งปีในก้าวเดียว ก็ให้การแจกแจงที่ถูกต้องเหมือนกันหมด · นี่คือเหตุผลที่ §12.2 กระโดดจาก t=0 ไป T ในก้าวเดียวได้อย่างสบายใจ

⚠️ แต่ความโชคดีนี้เป็นของ GBM เท่านั้น

ทันทีที่ σ หรือ μ ขึ้นกับสถานะปัจจุบัน ในแบบที่ตัดออกด้วย log ไม่ได้ คำตอบปิดก็หายไป:

โมเดลสมการมีทางลัดไหม
GBMdS/S = μ dt + σ dWมี ✓
Ornstein-Uhlenbeckdx = θ(μ − x)dt + σ dWมี ✓ (เล่ม 2 · D §8.4½)
Heston (stochastic vol)dv = κ(v̄ − v)dt + ξ√v dWไม่มี ❌
Local volatilitydS/S = μ dt + σ(S,t) dWไม่มี ❌
SABRdF = σFβ dW₁ · dσ = ασ dW₂ไม่มี ❌

สามแถวล่างคือโมเดลที่โต๊ะเทรดออปชันใช้จริงเมื่อ BS ไม่พอ (§11.6) · ทั้งสามตัวไม่มีทางลัด — ต้องเดินทีละก้าวเล็ก ๆ แล้วยอมรับความคลาดเคลื่อน

Euler-Maruyama Maruyama 1955 ★★ ควรรู้

🎯 Thesis: "เอานิยามของ SDE มาใช้ตรง ๆ — แทน dt ด้วย Δt เล็ก ๆ และแทน dW ด้วย √Δt·Z แล้วเดินทีละก้าว · ง่ายจนน่าตกใจ และผิดในแบบที่คาดเดาได้"

SDE ทั่วไป: dX = a(X,t)·dt + b(X,t)·dW Euler-Maruyama: X(t+Δt) = X(t) + a(X,t)·Δt + b(X,t)·√Δt·Z Z ~ N(0,1) ↑ ↑ ส่วนที่คาดเดาได้ ช็อกสุ่ม (√Δt ไม่ใช่ Δt!)

📖 อ่านสูตรว่า: "เอ็กซ์ที่เวลาทีบวกเดลตาที เท่ากับ เอ็กซ์ที่เวลาที บวก เอของเอ็กซ์และที คูณ เดลตาที บวก บีของเอ็กซ์และที คูณ รูทเดลตาที คูณ แซด" · a(X,t), b(X,t) คือฟังก์ชันของสองตัวแปร — "ณ ตำแหน่งนี้ เวลานี้ drift เท่าไร ความสุ่มเท่าไร" ไม่ใช่ a คูณ (X,t) · โครงที่ต้องเห็น: drift + noise ของ SDE บรรทัดบน แปลตรงตัว: dt → Δt และ dW → √Δt·Z · ลอง b = 0: เหลือ X + a·Δt คือเดินทีละก้าวแบบไม่มีความสุ่ม · เทียบ GBM: a = μS, b = σS · กับดักการอ่าน: √Δt ไม่ใช่ Δt เพราะ (dW)² = dt (Part IV) · X(t) วงเล็บคือ "ค่า ณ เวลา" · สูตรนี้ประมาณ (แทน d ด้วย Δ) จึงมี error ที่ขึ้นกับขนาดก้าว ต่างจากบรรทัด GBM ข้างบนที่เป๊ะทุก Δt

ทำไมเป็น √Δt ไม่ใช่ Δt: เพราะ (dW)² = dt จาก Part IV · ช็อกสุ่มโตตามรากที่สองของเวลา ไม่ใช่ตามเวลา — เป็นกฎ σ√T เดิมจาก Part II ที่กลับมาอีกครั้ง

ลองใช้กับ GBM ทั้งที่ไม่จำเป็น เพื่อจะได้วัดความคลาดเคลื่อนเทียบกับคำตอบที่รู้อยู่แล้ว:

# pip install numpy
import numpy as np, math

S0, K, r, sig, T = 100, 100, 0.05, 0.25, 1.0
paths = 200_000

def price(steps, seed=11):
    rng = np.random.default_rng(seed)
    Z  = rng.standard_normal((paths, steps)); dt = T/steps
    S = np.full(paths, float(S0))                     # (ก) Euler-Maruyama บน S ตรง ๆ
    for k in range(steps):
        S = S + r*S*dt + sig*S*math.sqrt(dt)*Z[:, k]
    em = math.exp(-r*T)*np.maximum(S - K, 0)
    logS = math.log(S0) + np.cumsum((r - sig**2/2)*dt   # (ข) แบบเป๊ะ ใช้ Z ชุดเดียวกัน
                                    + sig*math.sqrt(dt)*Z, axis=1)[:, -1]
    ex = math.exp(-r*T)*np.maximum(np.exp(logS) - K, 0)
    return em, ex, int((S < 0).sum())

print("steps |  EM ราคา | เป๊ะ ราคา |  EM - เป๊ะ | S_T ติดลบ")
for steps in [1, 4, 12, 52, 252]:
    em, ex, neg = price(steps)
    d = em - ex                                        # ★ จับคู่ทีละเส้นทาง -> noise ตัดกัน
    print(f"{steps:5d} | {em.mean():8.4f} | {ex.mean():9.4f} | "
          f"{d.mean():+9.4f} | {neg:7d}")
print(f"\n(MC standard error ของราคาเดี่ยว ~ {ex.std()/math.sqrt(paths):.4f} "
      f"— ใหญ่กว่า bias ที่ steps สูง จึงต้องจับคู่ถึงจะเห็น)")

1) เพราะเราเดิน ln S ซึ่งเป็นจำนวนจริงใด ๆ ก็ได้ (ติดลบได้) แล้วยกกำลัง e ตอนท้าย · exp(ค่าอะไรก็ตาม) > 0 เสมอ ราคาจึงเป็นบวกโดยโครงสร้าง · ส่วน EM เดินบน S ตรง ๆ จึงเป็นการบวกเลขปกติเข้าไปเรื่อย ๆ ถ้าก้าวใหญ่พอและ Z ติดลบมากพอ ก็ลากข้ามศูนย์ไปได้ · บทเรียน: เลือกตัวแปรที่จะเดินให้ดี บางครั้งเปลี่ยนตัวแปรแก้ปัญหาได้มากกว่าซอยก้าว

2) สำคัญมากขึ้นมาก · Call สนใจแค่ S_T จุดเดียว ความคลาดเคลื่อนระหว่างทางเฉลี่ยแล้วหักล้างกันได้บ้าง · แต่ barrier สนใจว่าเคยแตะ 80 ระหว่างทางหรือไม่ · การเดินทีละก้าวจะมองข้ามการแตะที่เกิดขึ้นระหว่างสองก้าวเสมอ → ประเมินโอกาสตายต่ำเกินไป → ตั้งราคาแพงเกินไปอย่างเป็นระบบ และเพิ่มเส้นทางก็ไม่ช่วย (มีเทคนิคชื่อ Brownian bridge ไว้แก้เรื่องนี้โดยเฉพาะ)

3) ถ้าใช้คนละชุด ผลต่างที่วัดได้จะเป็น discretization bias + ความต่างจากการสุ่มสองครั้ง ปนกัน · จากตาราง se ของราคาเดี่ยว = 0.0411 ส่วน bias ที่ 12 ก้าวมีแค่ 0.0035 — สัญญาณจะจมอยู่ใต้ noise ที่ใหญ่กว่า 10 เท่า · การใช้ตัวเลขสุ่มชุดเดียวกันเทียบสองวิธีเรียกว่า common random numbers เป็นเทคนิคมาตรฐานเวลาเปรียบเทียบอะไรก็ตามด้วย Monte Carlo
