A บอก "พอร์ตนี้เสี่ยงเท่าไร" (wᵀΣw) · B ตอบ "แล้วน้ำหนัก w แบบไหนดีที่สุด" · ศัพท์: Objective = สิ่งที่อยาก max/min · Constraint = ข้อจำกัด · Feasible region = ชุดคำตอบที่ทำได้ · Shadow price = คุณค่าของทรัพยากรเพิ่ม 1 หน่วย · Gradient descent = เดินลงเขาหาค่าต่ำสุด · Efficient Frontier = เส้นพอร์ตที่ดีที่สุด

Optimization คือคณิตของการตอบคำถาม "หาค่าที่ดีที่สุดภายใต้ข้อจำกัด" — และผลลัพธ์ที่สวยที่สุดของมันในการเงินคือ Efficient Frontier ของ Markowitz: เส้นที่รวม "พอร์ตที่เสี่ยงน้อยสุดสำหรับทุกระดับผลตอบแทน" ไว้เส้นเดียว

Optimization ไม่ได้หา "คำตอบที่ถูก" — มันหา "คำตอบที่ดีที่สุดเท่าที่ข้อจำกัดยอมให้เป็นไปได้"

บทที่ 3: Linear Programming — ดีที่สุดเมื่อทุกอย่างเป็นเส้นตรง

LP = หา max/min ของฟังก์ชันเชิงเส้น ภายใต้ข้อจำกัดเชิงเส้น — กรณีที่ง่ายและแก้ได้เร็วที่สุด

3.1 ตั้งโจทย์ — Objective + Constraints

🚶 อ่านเป็นภาษาคนก่อน: ทุกปัญหา optimization มี 2 ส่วน: objective (สิ่งที่อยาก max/min) และ constraints (กติกาที่ห้ามละเมิด เช่น งบ, ลิมิตความเสี่ยง)

Maximize z = c₁x₁ + c₂x₂ ← objective Subject to a₁₁x₁ + a₁₂x₂ ≤ b₁ ← constraint 1 a₂₁x₁ + a₂₂x₂ ≤ b₂ ← constraint 2 x₁, x₂ ≥ 0 ← ห้ามติดลบ
🧮 ตัวอย่าง — จัดพอร์ต Options ในงบจำกัด

Max Expected Payoff = 8x₁ + 5x₂ (x₁ = Call K=100, x₂ = Call K=110)

Subject to: Premium 5x₁ + 2x₂ ≤ 20 (งบ ฿20) · จำนวน x₁ + x₂ ≤ 5 (ไม่เกิน 5 สัญญา) · x₁, x₂ ≥ 0

3.2 วิธีทำด้วยมือ — กราฟ + แก้ระบบสมการหามุม

🚶 อ่านเป็นภาษาคนก่อน: วาดเส้น constraint ทุกเส้น → พื้นที่ที่ผ่านกติกาทุกข้อเรียก feasible region · คำตอบดีที่สุดอยู่ที่มุมเสมอ ไม่เคยอยู่กลางพื้นที่ — จึงเช็คแค่ทุกมุมก็พอ

Corner Point Theorem

คำตอบ optimal ของ LP อยู่ที่ มุม (corner) ของ feasible region เสมอ ไม่เคยอยู่กลางพื้นที่ — จึงเช็คแค่ทุกมุมก็พอ

🧮 วิธีทำเต็ม 4 ขั้น (ทำมือได้จริง)

ขั้น 1 — หามุมทั้งหมดของ feasible region. บางมุมอ่านจากแกนได้เลย: (0,0), (0,5), (4,0) · มุมที่ยากคือ "จุดตัดของ 2 เส้น constraint" ต้องคำนวณ

ขั้น 2 — หาจุดตัด 5x₁+2x₂=20 กับ x₁+x₂=5 ด้วยการแก้ระบบสมการ (วิธี elimination จาก Part I หัวข้อ 2.3):

5x₁ + 2x₂ = 20 …(1) x₁ + x₂ = 5 ×2 → 2x₁ + 2x₂ = 10 …(2) เอา (1) − (2): 3x₁ = 10 → x₁ = 10/3 ≈ 3.33 แทนกลับใน x₁+x₂=5: x₂ = 5 − 10/3 = 5/3 ≈ 1.67

ขั้น 3 — ไล่ค่า objective z = 8x₁ + 5x₂ ที่ทุกมุม:

มุม (x₁, x₂)z = 8x₁ + 5x₂
(0, 0)0
(0, 5)8(0) + 5(5) = 25
(4, 0)8(4) + 5(0) = 32
(10/3, 5/3)80/3 + 25/3 = 105/3 = 35✅ สูงสุด

ขั้น 4 — เลือกมุมที่ z สูงสุด: (10/3, 5/3) → payoff = 35 · แปลว่าซื้อ Call K=100 ≈ 3.33 สัญญา + Call K=110 ≈ 1.67 สัญญา (เศษสัญญาแก้ใน 3.6)

🧠 ทำไมคำตอบต้องอยู่ที่ "มุม" เสมอ

นึกเส้น objective z = 8x₁+5x₂ เป็นไม้บรรทัดที่เลื่อนขนานออกไปเรื่อย ๆ (z ยิ่งมาก ยิ่งเลื่อนไกล) · จุดสุดท้ายที่ไม้บรรทัดยังแตะ feasible region ก่อนหลุดออกไป ต้องเป็นมุมเสมอ — นี่คือหัวใจที่ทำให้ LP แก้ง่าย: ไม่ต้องค้นทั้งพื้นที่ (จุดอนันต์) แค่ค้น "มุม" ซึ่งมีจำกัด

3.3 วิธีทำด้วย Python — ให้คอมพิวเตอร์แก้

🚶 อ่านเป็นภาษาคนก่อน: พอตัวแปรเยอะ ทำมือไม่ไหว เราป้อนโจทย์ให้ library แก้ · 2 ตัวที่นิยม: scipy (ติดมากับชุด Python วิทยาศาสตร์ เช่น Anaconda) กับ PuLP (เขียนอ่านง่ายเหมือนคณิต · ลงด้วย pip install pulp)

🐍 Python — scipy.optimize.linprog
from scipy.optimize import linprog

# ⚠️ linprog "มินิไมซ์" เสมอ → อยาก max 8x1+5x2 ให้ min ของ -(8x1+5x2)
c    = [-8, -5]                 # objective (ใส่เครื่องหมายลบ)
A_ub = [[5, 2],                 # 5x1 + 2x2 <= 20  (งบ)
        [1, 1]]                 # x1  +  x2 <= 5   (จำนวนสัญญา)
b_ub = [20, 5]
bounds = [(0, None), (0, None)] # x1, x2 >= 0

res = linprog(c, A_ub=A_ub, b_ub=b_ub, bounds=bounds, method="highs")
print("x      =", res.x)                   # x      = [3.33333333 1.66666667]
print("payoff =", -res.fun)                # payoff = 35.0        (ลบกลับ)
print("shadow =", res.ineqlin.marginals)   # shadow = [-1. -3.]   (ดู 3.5)
🐍 Python — PuLP (อ่านง่ายเหมือนโจทย์)
import pulp

m  = pulp.LpProblem("options", pulp.LpMaximize)   # อยาก max
x1 = pulp.LpVariable("x1", lowBound=0)            # Call K=100
x2 = pulp.LpVariable("x2", lowBound=0)            # Call K=110

m += 8*x1 + 5*x2                        # objective
m += 5*x1 + 2*x2 <= 20, "budget"        # งบ ฿20
m += x1 + x2 <= 5,      "contracts"     # ไม่เกิน 5 สัญญา

m.solve(pulp.PULP_CBC_CMD(msg=0))      # msg=0 = ปิด log ของ solver
print(x1.value(), x2.value())          # 3.3333333 1.6666667
print(pulp.value(m.objective))         # 34.9999999   ← ไม่ใช่ 35 เป๊ะ! (ดูหมายเหตุ)
print(m.constraints["budget"].pi)      # 1.0          (shadow price ของงบ)
💡 ทำไม PuLP ได้ 34.9999999 ไม่ใช่ 35

solver ทำงานด้วยเลขทศนิยมและหยุดเมื่อ "ใกล้พอ" ตามเกณฑ์ความคลาดเคลื่อนของมัน · 34.9999999 กับ 35 คือคำตอบเดียวกันในทางปฏิบัติ · บทเรียน: อย่าเทียบผลลัพธ์ของ solver ด้วย == ให้ปัดหรือเทียบด้วยความคลาดเคลื่อนที่ยอมรับได้เสมอ (เช่น round(v, 6))

💡 อ่านผลลัพธ์

ทั้งคู่ได้คำตอบเดียวกับที่ทำมือ: x = (3.33, 1.67), payoff = 35 · PuLP อ่านง่ายกว่า (บรรทัด m += … เหมือนเขียนโจทย์เป๊ะ) · ส่วน scipy ต้องระวังว่ามัน "มินิไมซ์" จึงใส่เครื่องหมายลบที่ objective แล้วลบกลับตอนอ่านผล

3.4 Simplex — อัลกอริทึมที่ linprog รันให้เบื้องหลัง

🚶 อ่านเป็นภาษาคนก่อน: เมื่อตัวแปรเยอะจนวาดกราฟไม่ได้ Simplex คือวิธี "ยืนที่มุมหนึ่ง มองรอบ ๆ แล้วเดินไปมุมข้าง ๆ ที่ดีขึ้น ทำซ้ำจนไม่มีมุมไหนดีกว่า" — ไม่ต้องเช็คทุกมุม (ซึ่งมีมหาศาล) แค่เดินขึ้นเนินไปเรื่อย ๆ

เข้าใจหลักการ "เดินตาม edge จาก corner สู่ corner ที่ดีขึ้น" ก็พอ · ในทางปฏิบัติใช้ software (Excel Solver, Python scipy.optimize.linprog)

3.5 Dual & Shadow Price — "ทรัพยากรเพิ่ม 1 หน่วยคุ้มไหม"

🚶 อ่านเป็นภาษาคนก่อน: ทุกปัญหา LP มี "คู่แฝด" (dual) ที่มองจากอีกด้าน · ผลพลอยได้ที่มีค่าที่สุดคือ shadow price = "ถ้าผ่อนข้อจำกัดออกอีก 1 หน่วย (เช่นเพิ่มงบ ฿1) objective จะดีขึ้นเท่าไร"

🟢 ข้ามได้ — สมการรูปเมทริกซ์ข้างล่างเป็นทางการ ใจความอยู่ที่ตัวเลข shadow price ที่คิดจริงด้านล่าง (cᵀ, Aᵀ คือ "สลับแนวตั้ง/นอน" ของ matrix)

Primal: Max cᵀx s.t. Ax ≤ b, x ≥ 0 Dual: Min bᵀy s.t. Aᵀy ≥ c, y ≥ 0 Strong Duality: ที่ optimal ค่าทั้งสองเท่ากันพอดี
🧮 วิธีทำ — คำนวณ shadow price ของโจทย์เรา

ที่คำตอบ (10/3, 5/3) ทั้ง 2 constraint "ตึง" (ใช้เต็มพอดี) → shadow price (y₁ = งบ, y₂ = สัญญา) แก้จากระบบสมการ dual ของ constraint ที่ตึง:

5y₁ + y₂ = 8 (สัมประสิทธิ์ของ x₁) 2y₁ + y₂ = 5 (สัมประสิทธิ์ของ x₂) ลบกัน: 3y₁ = 3 → y₁ = 1 , แทนกลับ y₂ = 8 − 5 = 3

แปล: เพิ่มงบ ฿1 → payoff +1 (y₁=1) · เพิ่มลิมิตได้อีก 1 สัญญา → payoff +3 (y₂=3) → "ผ่อนลิมิตสัญญาคุ้มกว่าเพิ่มงบ 3 เท่า"

พิสูจน์ด้วยการแก้ใหม่: เพิ่มงบเป็น ฿21 → จุดตัดใหม่ (11/3, 4/3), z = 88/3 + 20/3 = 108/3 = 36 = 35 + 1 ✓ (ตรงกับ y₁ = 1 พอดี)

💡 อ่าน shadow price จากโค้ด (ไม่ต้องแก้ dual เอง)

PuLP: m.constraints["budget"].pi → 1.0 · m.constraints["contracts"].pi → 3.0 · scipy: -res.ineqlin.marginals → [1, 3] (ที่เป็นลบเพราะเราใส่ objective เป็นลบ)

เชื่อมกับ Options

shadow price บอกด้วยตัวเลขว่า "จะขยายงบ หรือผ่อนลิมิตความเสี่ยง อันไหนเพิ่ม payoff คุ้มกว่า" — ตัดสินใจด้วยข้อมูล ไม่ใช่ความรู้สึก

3.6 Integer LP + Branch and Bound — เพราะซื้อ Option 2.7 สัญญาไม่ได้

🚶 อ่านเป็นภาษาคนก่อน: LP ตอบ "3.33 สัญญา" ซึ่งซื้อจริงไม่ได้ · Integer LP (ILP) บังคับให้ตัวแปรเป็นจำนวนเต็ม — ฟังดูแค่ปัดเศษ แต่ปัดเศษมั่ว ๆ มักได้คำตอบผิดหรือเกินงบ จึงต้องมีวิธีจริงชื่อ Branch and Bound

🧮 วิธีทำ — Branch and Bound เดินจริง

ขั้น 1: แก้ LP ปกติก่อน (relaxation) → ได้ (3.33, 1.67) — ไม่เป็นจำนวนเต็มที่ x₁

ขั้น 2 — "แตกกิ่ง" ที่ x₁: จำนวนเต็มต้องอยู่ฝั่ง x₁ ≤ 3 หรือ x₁ ≥ 4 (ข้ามช่วง 3–4 ที่เป็นเศษ) แล้วแก้ LP ทั้งสองกิ่ง:

┌ กิ่ง x₁ ≤ 3 : ดัน x₁ = 3 → x₂ ได้มากสุด 2 (จากทั้งงบและลิมิต) │ → (3, 2) z = 8(3)+5(2) = 34 ✔ จำนวนเต็ม └ กิ่ง x₁ ≥ 4 : ดัน x₁ = 4 → งบเหลือให้ x₂ = 0 → (4, 0) z = 32 ✔ จำนวนเต็ม

ขั้น 3 — เลือกกิ่งที่ดีสุด: 34 > 32 → คำตอบ ILP = (3, 2) payoff 34

สังเกต: LP บอก 35 (เศษ) แต่จำนวนเต็มดีสุดได้แค่ 34 · คราวนี้บังเอิญ (3,2) = ปัดเศษ (3.33,1.67) พอดี — แต่ ปัดเศษไม่ได้ผลเสมอ (บางโจทย์ปัดแล้วเกินงบ) นั่นคือเหตุผลที่ต้องมี Branch and Bound

🐍 Python — ILP ด้วย PuLP (เปลี่ยนแค่คำเดียว!)
import pulp
m  = pulp.LpProblem("options_int", pulp.LpMaximize)
# เพิ่ม cat="Integer" — แค่นี้ LP กลายเป็น ILP
x1 = pulp.LpVariable("x1", lowBound=0, cat="Integer")
x2 = pulp.LpVariable("x2", lowBound=0, cat="Integer")

m += 8*x1 + 5*x2
m += 5*x1 + 2*x2 <= 20
m += x1 + x2 <= 5
m.solve(pulp.PULP_CBC_CMD(msg=0))      # msg=0 = ปิด log ของ solver
print(int(x1.value()), int(x2.value()), pulp.value(m.objective))
                                        # 3 2 34.0

📌 PuLP รัน Branch and Bound ให้อัตโนมัติ · (scipy ใช้ scipy.optimize.milp สำหรับจำนวนเต็ม)

❌ ทำไม ILP ยากกว่า LP มาก (NP-hard)

LP แก้ได้ในเวลา polynomial · แต่ ILP เป็น NP-hard — จำนวนกิ่งอาจระเบิดเป็น exponential เมื่อตัวแปรเยอะ ไม่มี algorithm ที่เร็วเสมอ · Branch and Bound เก่งตรงที่ "ตัดกิ่งที่แย่ทิ้ง (bound)" ก่อนไล่ลงไป จึงไม่ต้องดูทุกกิ่ง

เชื่อมกับ Options

Option ซื้อเป็นสัญญา (1 contract = 100 หุ้น) ต้องจำนวนเต็ม → การเลือก combination ของสัญญาที่ max payoff ในงบจำกัด = ILP ตรง ๆ

✍️ ลองทำเอง

ถ้างบเพิ่มเป็น ฿30 (constraint เป็น 5x₁+2x₂ ≤ 30, x₁+x₂ ≤ 5) · คำตอบ (แบบ LP ปกติ) อยู่ที่มุมไหน payoff เท่าไร และคราวนี้ constraint ไหน "ตึง"?

ดูเฉลย

ลองมุม: (5,0) → งบใช้ 25 ≤ 30 (เหลือ ฿5), สัญญา 5 = 5 (ตึง), z = 8(5) = 40 · (0,5) → z = 25 · คำตอบ = (5,0) payoff 40 · คราวนี้ ลิมิตสัญญาตึง แต่งบเหลือ → shadow price ของงบ = 0 (เพิ่มงบไม่ช่วยแล้ว!) พลิกจากตอนงบ ฿20 ที่งบตึง — บทเรียน: constraint ไหน "ตึง" เปลี่ยนได้ตามโจทย์

🎯 3 อย่างที่ต้องจำจากบทที่ 3
  • ตั้งเป็น objective + constraints → คำตอบอยู่ที่มุมเสมอ (หามุมด้วยการแก้ระบบสมการ)
  • โค้ดจริงใช้ PuLP/scipy.linprog · shadow price = ผ่อนข้อจำกัด 1 หน่วยได้ payoff เพิ่มเท่าไร
  • ต้องจำนวนเต็ม → ILP (Branch and Bound · PuLP ใส่ cat="Integer") · อย่าปัดเศษมั่ว

บทที่ 4: Nonlinear Optimization → Markowitz

โลกจริงมักไม่เป็นเส้นตรง — และปัญหาจัดพอร์ตของ Markowitz เป็น Quadratic (เพราะ wᵀΣw ยกกำลังสอง) นี่คือปลายทางของทั้ง เล่ม 2

4.1 Unconstrained + Gradient Descent

🚶 อ่านเป็นภาษาคนก่อน: จุดต่ำสุด/สูงสุดคือจุดที่ความชัน = 0 (f'(x*)=0) · f''>0 = ก้นหลุม (min), f''<0 = ยอดเขา (max) · แต่พอมีหลายตัวแปรและไม่มีสูตรปิด ใช้ gradient descent: "เดินลงเขาทีละก้าวตามทิศที่ชันลงที่สุด"

x(t+1) = x(t) − α·∇f(x(t)) α = learning rate (ขนาดก้าว) · ∇f = ทิศที่ f เพิ่มเร็วสุด → เดินสวน = ลดเร็วสุด
🧮 คิดด้วยมือ — เดินลงเขาหา min ของ f(x) = (x−3)² + 2

ก้นหลุมอยู่ที่ x=3 (เรารู้คำตอบอยู่แล้ว เพื่อเช็กว่า gradient descent เดินไปถูก) · ความชัน f′(x) = 2(x−3) · เริ่มที่ x=0 ก้าว α=0.1 · สูตรเดียว: x ใหม่ = x − α·f′(x)

ก้าวxf′(x)=2(x−3)x − 0.1·f′(x)
00.000−6.000 − 0.1(−6) = 0.600
10.600−4.800.6 − 0.1(−4.8) = 1.080
21.080−3.841.08 − 0.1(−3.84) = 1.464
31.464−3.07→ 1.771 …

เห็นไหมว่ามันคลานเข้าหา x=3 ทีละก้าว — ตอนไกลก้าวใหญ่ (ชันมาก) พอใกล้ก้นหลุมก้าวเล็กลงเอง (ชันน้อยลง) นี่คือพฤติกรรมสวยงามของ gradient descent

🐍 Python — gradient descent 5 บรรทัด
def f_grad(x):  return 2*(x - 3)        # f'(x) ของ (x-3)^2 + 2

x, alpha = 0.0, 0.1
for step in range(60):
    x = x - alpha * f_grad(x)           # เดินสวนทาง gradient
print(f"หาจุดต่ำสุดได้ x = {x:.4f}")     # หาจุดต่ำสุดได้ x = 3.0000
เชื่อมกับ Options

Gradient descent ใช้ calibrate โมเดล — หา parameter ที่ทำให้ราคาจากโมเดล ≈ ราคาตลาด (เช่น fit vol surface, calibrate Stochastic Vol)

4.2 Lagrange Multipliers — optimization ที่มีเงื่อนไข

Lagrange → Markowitz Portfolio Markowitz 1952 ★★★ ต้องรู้จัก

🚶 อ่านเป็นภาษาคนก่อน: ถ้าต้อง optimize "ภายใต้เงื่อนไขที่ต้องเป๊ะ" (เช่น น้ำหนักรวม = 100%) วิธี Lagrange คือ "รวมเงื่อนไขเข้าไปในเป้าหมายด้วยตัวคูณ λ" แล้วแก้พร้อมกัน · λ มีความหมายเหมือน shadow price — "ผ่อนเงื่อนไขนิดนึง เป้าหมายดีขึ้นเท่าไร"

🟢 มือใหม่ไม่ต้องแก้สมการนี้ — ข้ามไปอ่านภาพ Efficient Frontier ด้านล่างก็เข้าใจใจความได้ครบ

L(x, λ) = f(x) − λ·g(x) (g(x)=0 คือเงื่อนไข) แก้ ∂L/∂x = 0 และ ∂L/∂λ = 0
🧮 หัวใจ — ปัญหา Markowitz

Minimize ความเสี่ยง σ²ₚ = wᵀΣw · Subject to ผลตอบแทนเป้าหมาย wᵀμ = r* และ น้ำหนักรวม wᵀ1 = 1

L = wᵀΣw − λ₁(wᵀμ − r*) − λ₂(wᵀ1 − 1)

แก้แล้วได้น้ำหนัก w ที่ดีที่สุดสำหรับผลตอบแทนเป้าหมายนั้น — ทำซ้ำทุกระดับ r* ก็ได้เส้น Efficient Frontier

🧠 มุมที่มองต่าง

มือใหม่เห็น: "หาพอร์ตที่ให้ผลตอบแทนสูงสุด"
คนจัดพอร์ตเห็น: ไม่มี "พอร์ตดีที่สุด" ตัวเดียว — มีเส้น (frontier) ของพอร์ตที่ดีที่สุดในแต่ละระดับความเสี่ยง · เลือกจุดบนเส้นตามความกล้ารับเสี่ยงของแต่ละคน ไม่ใช่หาจุดเดียว · (ข้อยกเว้น: ถ้ามีสินทรัพย์ปลอดความเสี่ยง เช่นเงินสด/พันธบัตร เข้ามาด้วย จะมีพอร์ตเสี่ยง "ดีที่สุด" จุดเดียว = พอร์ต Sharpe สูงสุด แล้วปรับเสี่ยงด้วยการผสมเงินสด — อยู่นอกขอบเขตเล่มนี้)

4.2½ วิธีทำด้วยมือ + Python — จัดพอร์ต 2 สินทรัพย์จริง

🚶 อ่านเป็นภาษาคนก่อน: สูตร Lagrange ข้างบนดูโหด แต่ถ้ามีแค่ 2 สินทรัพย์ จุด "เสี่ยงต่ำสุด" (min-variance) มีสูตรปิดสั้น ๆ คำนวณด้วยมือได้ · เราจะเห็นกับตาว่า ผสมสองตัวแล้วเสี่ยงน้อยกว่าถือตัวปลอดภัยตัวเดียวซะอีก — หัวใจของ "อย่าใส่ไข่ตะกร้าเดียว"

📋 โจทย์ (จำเลขชุดนี้)
สินทรัพย์ผลตอบแทนคาดหวัง μความเสี่ยง σ
A (หุ้นโต)10%20%
B (หุ้นนิ่ง)6%10%

ความสัมพันธ์ ρ = 0.2 (ไปด้วยกันน้อย — ยิ่งดีต่อการกระจายเสี่ยง) · อยากรู้: ผสม A กับ B สัดส่วนไหนเสี่ยงต่ำสุด?

🧮 คิดทีละขั้น — หา Min-Variance Portfolio

ขั้น 1 — หา covariance จาก ρ (เชื่อมกลับ เล่ม 2·A: Cov = ρ·σ_A·σ_B)

Cov(A,B) = ρ·σ_A·σ_B = 0.2 × 0.20 × 0.10 = 0.004 Σ = [ σ_A² Cov ] = [ 0.04 0.004 ] [ Cov σ_B² ] [ 0.004 0.01 ]

ขั้น 2 — แทนสูตรปิด min-variance (สำหรับ 2 สินทรัพย์)

w_A = (σ_B² − Cov) / (σ_A² + σ_B² − 2·Cov) = (0.01 − 0.004) / (0.04 + 0.01 − 2×0.004) = 0.006 / 0.042 = 0.1429 → w_B = 1 − 0.1429 = 0.8571

ขั้น 3 — คิดผลตอบแทนและความเสี่ยงของพอร์ตนี้

ผลตอบแทน = w_A·μ_A + w_B·μ_B = 0.1429×10% + 0.8571×6% = 6.57% ความเสี่ยง² = w_A²σ_A² + w_B²σ_B² + 2·w_A·w_B·Cov = 0.1429²(0.04) + 0.8571²(0.01) + 2(0.1429)(0.8571)(0.004) = 0.000818 + 0.007344 + 0.000980 = 0.009143 ความเสี่ยง σ = √0.009143 = 9.56%
💎 โมเมนต์ที่ควรหยุดดู — 1 + 1 เสี่ยงน้อยกว่า 1

พอร์ตนี้เสี่ยง 9.56% · แต่หุ้น B ตัวที่ "นิ่งที่สุด" ยังเสี่ยงตั้ง 10% เดี่ยว ๆ · การผสมหุ้นเสี่ยงกว่า (A, 20%) เข้าไป กลับทำให้พอร์ตเสี่ยงน้อยลงกว่าถือ B ล้วน ๆ เพราะ A กับ B ไม่ได้ขึ้นลงพร้อมกัน (ρ=0.2) — เวลาตัวหนึ่งตก อีกตัวช่วยพยุง · นี่คือ "free lunch" เดียวในไฟแนนซ์ที่ Markowitz พิสูจน์ด้วยเลข ไม่ใช่คำคม

⚠️ ของจริงไม่ฟรีขนาดนั้น — ระวัง estimation error

ตัวเลข μ, σ, ρ ทั้งหมดเป็น ค่าประมาณจากอดีต ไม่ใช่ความจริงของอนาคต · optimizer มักได้น้ำหนักที่ "ขยายความผิดพลาด" ของ input · ที่แย่สุด: ตอนตลาด crash correlation มักพุ่งเข้าหา 1 (ทุกอย่างร่วงพร้อมกัน) — diversification จางหายตอนที่ต้องการมันที่สุด · ในทางปฏิบัติ risk ที่ลดได้จริงมักน้อยกว่าที่สูตรสัญญา

ทำด้วยมือได้แค่ 2 สินทรัพย์ · พอมี 3 ตัวขึ้นไป หรืออยากได้ทั้งเส้น Efficient Frontier ต้องให้คอมช่วย — ใช้ scipy.optimize.minimize แก้ QP ตรง ๆ:

🐍 Python — Min-Variance + Efficient Frontier ทั้งเส้น
import numpy as np
from scipy.optimize import minimize

mu  = np.array([0.10, 0.06])                 # ผลตอบแทนคาดหวัง A, B
Sig = np.array([[0.04, 0.004],               # เมทริกซ์ความแปรปรวนร่วม Σ
                [0.004, 0.01]])

def port_var(w): return w @ Sig @ w          # ความเสี่ยง² = wᵀΣw (เล่ม 2·A)
budget = {'type':'eq', 'fun': lambda w: w.sum() - 1}   # น้ำหนักรวม = 100%

# --- 1) จุดเสี่ยงต่ำสุด (min-variance) ---
r = minimize(port_var, [.5,.5], constraints=[budget], bounds=[(0,1)]*2)
print("min-var: w =", r.x.round(4), " sigma =", round(port_var(r.x)**.5, 4))
# min-var: w = [0.1429 0.8571]  sigma = 0.0956   ← ตรงกับที่คิดมือ!

# --- 2) ทั้งเส้น Efficient Frontier: ล็อกผลตอบแทนเป้าหมายทีละค่า ---
for r_star in [0.0657, 0.07, 0.08, 0.09, 0.10]:
    target = {'type':'eq', 'fun': lambda w, t=r_star: w @ mu - t}
    r = minimize(port_var, [.5,.5], constraints=[budget, target], bounds=[(0,1)]*2)
    print(f"ret={r_star:.4f}  w={r.x.round(3)}  sigma={port_var(r.x)**.5:.4f}")
# ret=0.0657  w=[0.143 0.857]  sigma=0.0956   ← จุด min-var
# ret=0.0700  w=[0.25 0.75]  sigma=0.0981
# ret=0.0800  w=[0.5 0.5]  sigma=0.1204
# ret=0.0900  w=[0.75 0.25]  sigma=0.1569
# ret=0.1000  w=[1. 0.]  sigma=0.2000   ← A ล้วน = เสี่ยงสุด
✅ อ่านผลลัพธ์ — นี่คือ "เส้น" ที่เห็นในภาพ Efficient Frontier

แต่ละบรรทัดคือ 1 จุดบนเส้น ด้านบน · อยากได้ผลตอบแทนสูงขึ้น (6.57% → 10%) ก็ต้องรับความเสี่ยงสูงขึ้น (9.56% → 20%) และน้ำหนักเงินย้ายจาก B ไป A เรื่อย ๆ · ไม่มีจุดเดียวที่ "ดีที่สุด" — คุณเลือกจุดบนเส้นตามความกล้ารับเสี่ยงของตัวเอง

✍️ ลองทำเอง

เปลี่ยน ρ เป็น −0.5 (A กับ B สวนทางกัน) แก้ Sig[0,1]=Sig[1,0]= −0.5·0.2·0.1 = −0.01 แล้วรันใหม่ · คาดเดาก่อน: min-var จะเสี่ยงต่ำลงกว่า 9.56% อีก (สวนทางกัน = พยุงกันดีกว่าเดิม)

เฉลย: w≈[0.286, 0.714], σ≈6.55% — ต่ำลงชัดเจน (จาก 9.56% → 6.55%) · ยิ่ง ρ ติดลบ ยิ่งกระจายเสี่ยงได้ดี ✓

4.3 Convex & QP — ทำไม Markowitz แก้ได้เสมอ

🚶 อ่านเป็นภาษาคนก่อน: ปัญหา convex (รูปชามใบเดียว) มีก้นหลุมจุดเดียว — gradient descent เดินลงยังไงก็เจอ · ปัญหา non-convex มีหลายหลุม อาจติดหลุมผิด

✅ Markowitz = convex (QP)
  • wᵀΣw เป็น quadratic + Σ เป็น PSD (positive semi-definite — "ชามที่ไม่มีทิศไหนติดลบ" ดู เล่ม 2·A §1.5) → convex
  • มีคำตอบเดียวที่ดีที่สุด แก้ได้เสี้ยววินาที (cvxpy/scipy)
⚠️ Calibration บางโมเดล = non-convex
  • เช่น Stochastic Vol → หลาย local minimum
  • ต้องใช้เทคนิคพิเศษ (multi-start, global solver)
Quadratic Programming (QP): Minimize ½xᵀQx + cᵀx s.t. Ax ≤ b Mean-Variance ของ Markowitz = QP พอดี (Q = 2Σ)
🎯 3 อย่างที่ต้องจำจากบทที่ 4
  • Gradient descent = เดินลงเขาหาค่าต่ำสุด (ใช้ calibrate โมเดล)
  • Lagrange รวมเงื่อนไขเข้าเป้าหมาย → Markowitz → Efficient Frontier
  • Markowitz เป็น convex QP → คำตอบเดียว แก้ได้เสมอ

🎓 รวมร่าง: อ่าน Efficient Frontier เป็น

ปิด เล่ม 2 ด้วยการอ่านผลลัพธ์จริงของ optimization

🧭 นิสัยคิด — อ่าน frontier 3 ขั้น
  1. หาจุด Min-Variance (ซ้ายสุดของเส้น) = พอร์ตเสี่ยงต่ำสุดที่สร้างได้ — ต่ำกว่านี้ทำไม่ได้
  2. เดินขึ้นไปตามเส้น = ยอมเสี่ยงมากขึ้นเพื่อผลตอบแทนมากขึ้น · ทุกจุดบนเส้นคือ "ดีที่สุดของระดับเสี่ยงนั้น"
  3. เลือกจุดตามความกล้ารับเสี่ยง — ไม่ใช่หา "จุดเดียวที่ถูก" แต่เลือกจุดที่เข้ากับเรา · จุดใต้เส้น = แย่กว่าเสมอ (มีพอร์ตที่เสี่ยงเท่ากันแต่ผลตอบแทนสูงกว่า)
✍️ ลองทำเอง

เพื่อนบอก "พอร์ต X ของฉันให้ผลตอบแทน 8% ความเสี่ยง 15%" แต่บนเส้น frontier ที่ความเสี่ยง 15% ให้ผลตอบแทนได้ถึง 11% · พอร์ต X อยู่ตรงไหนของภาพ และควรทำยังไง?

ดูเฉลย

พอร์ต X อยู่ ใต้เส้น frontier (inefficient) — เสี่ยงเท่ากัน 15% แต่ได้ผลตอบแทนน้อยกว่าที่เป็นไปได้ (8% แทน 11%) · ควรปรับน้ำหนัก w ให้ขยับขึ้นไปแตะเส้น = ได้ผลตอบแทนเพิ่ม 3% ฟรี ๆ โดยไม่เพิ่มความเสี่ยง
