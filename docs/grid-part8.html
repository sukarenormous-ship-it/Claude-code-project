Strategy 1

8.1 Rebalancing Grid — ทำกำไรจาก Portfolio Drift

ใช้ grid mechanics เพื่อ rebalance portfolio โดยอัตโนมัติ — แทนที่จะ rebalance ทุกเดือนแบบ fixed, grid ทำ continuous rebalancing ตาม price movement:

Rebalancing Grid Setup: เป้าหมาย: รักษา BTC/USDT = 50%/50% ของ portfolio Portfolio: $20,000 total ($10,000 BTC + $10,000 USDT) BTC = $100k → จำนวน BTC = 0.10 เมื่อ BTC ขึ้น: BTC value เพิ่ม → % เกิน 50% → grid SELL BTC อัตโนมัติ (TP fills) ขาย BTC → ได้ USDT → ratio กลับมา 50/50 เมื่อ BTC ลง: BTC value ลด → % ต่ำกว่า 50% → grid BUY BTC อัตโนมัติ (BUY fills) ซื้อ BTC → ใช้ USDT → ratio กลับมา 50/50 กำไรจาก: "Buy low, sell high" ทุกครั้งที่ rebalance → ได้ทั้ง rebalancing benefit + grid cashflow def rebalancing_grid(total_value, target_btc_pct, btc_price, step_pct=0.02): """ Grid ที่ทำ portfolio rebalancing step_pct: % deviation ก่อน trigger """ target_btc_value = total_value * target_btc_pct target_btc_qty = target_btc_value / btc_price # Grid levels รอบ target allocation levels = [] for i in range(-5, 6): level_price = btc_price * (1 + i * step_pct) if i < 0: # BTC ลง → BUY levels.append({"type": "BUY", "price": level_price, "qty": target_btc_qty * abs(i) * 0.01}) elif i > 0: # BTC ขึ้น → SELL levels.append({"type": "SELL", "price": level_price, "qty": target_btc_qty * i * 0.01}) return levels
⚠️ ความเสี่ยง

Whipsaw cost: ถ้าราคาแกว่งกลับไปกลับมารอบ level เดียวกันบ่อยๆ จะเสีย fee ซ้ำๆ โดยไม่ได้ประโยชน์จาก rebalancing จริง (คล้าย whipsaw ใน trend-following ทั่วไป)

Underperform buy-and-hold ใน trend แรง: ถ้า BTC ขึ้นต่อเนื่องยาวๆ กลยุทธ์นี้ขาย BTC ออกเรื่อยๆ ตาม rebalance ทำให้ได้ upside น้อยกว่าแค่ถือเฉยๆ — นี่คือ trade-off ปกติของการ rebalance เพื่อคุม risk ไม่ใช่ bug

Strategy 2

8.2 Stablecoin Grid — ทำกำไรใน Bear Market

เมื่อ BTC ขาลงและ Hurst สูง (trending down) — grid BTC หยุด แต่ยังทำ Stablecoin Grid ได้ (ไม่ต้องถือ BTC):

Stablecoin Grid Options: 1. USDT/USDC Grid: ซื้อ USDT ตอนราคาต่ำกว่า USDC ขายตอนราคาสูงกว่า USDC (ช่วงเกิด depeg event) Zone: $0.995–$1.005 · Step: $0.0005 กำไรต่อรอบ: Q × $0.0005 − fee (ต่ำมาก แต่ปลอดภัย) 2. Stablecoin Yield + Grid: USDT ใน Standby Zone (Part 1A) → ฝากใน lending protocol (Aave/Compound — ดู "Counterparty Risk" box ใน Part 1A §1A.3 เรื่อง smart contract risk/liquidity risk) ได้ yield 4–8% APY บน idle capital + เมื่อ BTC กลับมา → นำ USDT ออก deploy grid ใหม่ 3. USDT/BTC ที่ระดับ Support แรง: ถ้าเชื่อว่า BTC มี hard support เช่น $70k → เปิด grid ที่ $65k–$80k เป็น "Bottom Fishing Grid" ใน Bear Market def stablecoin_grid_yield(standby_capital, lending_apy=0.05, grid_days=90): """ คำนวณ yield จาก idle capital ใน bear market """ daily_rate = (1 + lending_apy) ** (1/365) - 1 total_yield = standby_capital * ((1 + daily_rate) ** grid_days - 1) return total_yield # ตัวอย่าง: Standby $6,000 · APY 5% · 90 วัน # Yield = $6,000 × ((1.000133)^90 − 1) = $6,000 × 1.21% ≈ $72.6
⚠️ ความเสี่ยง

Depeg risk ไม่ได้มีแค่โอกาสทำกำไร — ถ้า stablecoin ที่ถืออยู่ depeg ถาวร (ไม่กลับ $1) เงินต้นเสียหายจริง ไม่ใช่แค่โอกาส ไม่ใช่แค่ upside

Option 2 (lending yield) มี counterparty/smart-contract risk เหมือนที่เตือนไว้ใน Part 1A §1A.3 — yield ไม่ใช่ risk-free

Strategy 3

8.3 Flash Crash Grid — Capture Extreme Dips

Flash Crash Grid วางเกณฑ์และแผนไว้ล่วงหน้า เพื่อจับช่วง "ต่ำผิดปกติ" ที่ตลาดน่าจะ recover ได้ภายใน 24–72 ชั่วโมง — แต่ order จริงจะถูกวางทันทีหลัง crash เกิดขึ้น ไม่ใช่วางรอไว้ก่อน (รายละเอียดดู Setup ด้านล่าง):

Flash Crash Grid: ลักษณะ Flash Crash ที่เหมาะ: - BTC ลง > 15% ภายใน 1 ชั่วโมง (liquidation cascade) [เหตุผล 15%: ใต้ระดับนี้ market makers มักเข้าซื้อ + liquidation ล้างแล้ว + ราคาต่ำกว่า fair value ชัดเจน] - Volume spike > 5× average - ระดับ macro เหมือนเดิม (on-chain ยังแข็งแกร่ง) - ไม่มี fundamental bad news Setup: วาง BUY orders ทันทีหลัง crash (ไม่ใช่ก่อน crash) Zone: ราคาปัจจุบัน (หลัง crash) ±5% Step: ATR ปัจจุบัน (อาจสูงมาก) Close System: ใช้ capital ที่เตรียมไว้ในส่วน "Flash Crash Reserve" เท่านั้น class FlashCrashGrid: def __init__(self, crash_capital_pct=0.10, recovery_hours=72): """ crash_capital_pct: % ของ total capital สำหรับ flash crash recovery_hours: เวลาที่คาดว่า recover ได้ """ self.capital_pct = crash_capital_pct self.recovery_hours = recovery_hours def is_flash_crash(self, drop_pct, volume_ratio, time_elapsed_hours): """ ตรวจว่านี่คือ flash crash หรือ trend reversal """ is_large_drop = drop_pct > 0.15 # ลง > 15% (ตรงกับเกณฑ์ด้านบน) is_fast = time_elapsed_hours < 1 # เร็ว < 1 ชั่วโมง is_vol_spike = volume_ratio > 5.0 # volume > 5× ปกติ return is_large_drop and is_fast and is_vol_spike Risk: Flash Crash กลายเป็น Trend Reversal → Close System รักษา inventory TP: ปิด grid เมื่อ recover 50% ของ crash depth หรือภายใน recovery_hours ถ้าไม่ recover ภายใน recovery_hours: ลด inventory 50% เพื่อ free capital → ถือ BTC ที่เหลือในฐานะ long-term หรือโอนเข้า Stablecoin Grid (Strategy 2)
Strategy 4

8.4 Cross-Exchange Arbitrage Grid

เมื่อ BTC price บน 2 exchanges ต่างกัน — ใช้ grid ทั้งสองฝั่งพร้อมกัน capture spread:

Cross-Exchange Grid: Exchange A (เช่น Binance): BTC = $100,050 Exchange B (เช่น Bybit): BTC = $99,950 Spread = $100 (ต่าง 0.1%) Grid Strategy: Exchange A: SELL BTC @ $100,050 (ขายแพง) Exchange B: BUY BTC @ $99,950 (ซื้อถูก) Net profit per cycle: $100 − fees def cross_exchange_spread_grid(price_a, price_b, q, fee_a, fee_b): """ คำนวณกำไรจาก cross-exchange spread """ spread = abs(price_a - price_b) fee_cost = q * (price_a * fee_a + price_b * fee_b) net_profit = q * spread - fee_cost return { "gross_spread": spread, "fee_cost": fee_cost, "net_profit": net_profit, "profitable": net_profit > 0 } ความท้าทาย: 1. Transfer BTC ระหว่าง exchange ใช้เวลา (10–60 นาที) → spread อาจหายไปแล้ว 2. ต้องมี capital บน ทั้งสอง exchange ตลอด 3. ค่า withdrawal fee + network fee กินกำไร 4. Slippage เมื่อ Q ใหญ่ วิธีแก้: ใช้ Perpetual บน Exchange A (short) + Spot บน Exchange B (long) → ไม่ต้อง transfer, ใช้ funding rate เป็น P&L indicator
Strategy 5

8.5 Laddered CSP Grid — ขาย Put เป็น Grid

กลไก CSP พื้นฐาน (ขาย put รับ premium แทนวาง BUY limit) สอนเต็มแล้วใน Part 7 §7.3 — กลยุทธ์นี้ต่อยอดด้วยการขายเป็น "ladder" ข้าม expiry หลายช่วงพร้อมกัน แทนที่จะใช้ expiry เดียวทุก level:

Laddered CSP Grid: ตัวอย่าง: BTC = $100k · Grid capital $30,000 · 5 levels Level 1: SELL PUT $98k, expiry 2W, premium $600 Level 2: SELL PUT $95k, expiry 2W, premium $450 Level 3: SELL PUT $92k, expiry 4W, premium $700 Level 4: SELL PUT $88k, expiry 4W, premium $550 Level 5: SELL PUT $84k, expiry 8W, premium $800 Total premium = $3,100 (รับทันที) ถ้าไม่มี level ถูก assign ตลอด 8 สัปดาห์: Income = $3,100 premium = 10.3% บน $30,000 capital ใน 8 สัปดาห์ ถ้า BTC ลงมา $94k ตอน Level 1–2 หมดอายุ (ทั้งคู่ expiry 2W เท่ากัน): Level 1 (strike $98k): $94k < $98k → ITM (In-The-Money — ราคาตลาดต่ำกว่า strike ของ PUT ที่ขายไว้) → assign → ซื้อ BTC ที่ $98k (ต้นทุนสุทธิหลังหัก premium = $97,400) Level 2 (strike $95k): $94k < $95k → ITM → assign → ซื้อ BTC ที่ $95k (ต้นทุนสุทธิ = $94,550) Level 3–5 (strike $92k/$88k/$84k, expiry 4W/8W ยังไม่ถึง): ยังคง pending ข้อดีที่ต่างจาก CSP เดี่ยว (Part 7 §7.3): + Expiry กระจาย (2W/4W/8W) → assignment ไม่มาพร้อมกันทั้งหมดในวันเดียว + Strike ไกลออกไป + expiry ยาวขึ้น (Level 5) → premium ต่อสัญญาสูงกว่า ข้อจำกัดเพิ่มจากการ ladder ข้าม expiry: − ต้องบริหารหลาย expiry date พร้อมกัน (roll/ปิดแต่ละ level ไม่พร้อมกัน) − ข้อจำกัดพื้นฐานของ CSP (liquidity, capital lock, downtrend assign ทุก level) ยังอยู่ — ดู Part 7 §7.3 def laddered_csp_grid(grid_levels, btc_price, put_premiums): """ คำนวณ total income และ effective buy prices """ results = [] for price, premium in zip(grid_levels, put_premiums): effective_cost = price - premium results.append({ "strike": price, "premium": premium, "effective_cost": effective_cost, "discount_pct": premium / price * 100 }) return results

8.6 แบบฝึกหัด

แบบฝึกหัด Part 8 — Quick Review
ข้อ 1: ใน Bear Market ที่ BTC downtrend ชัด — Strategy ไหนในทั้ง 5 ข้อที่เหมาะสมที่สุด?

คำตอบ:

Strategy 2 (Stablecoin Grid) เหมาะที่สุด:

  • ไม่ต้องถือ BTC → ไม่มี inventory risk ใน downtrend
  • นำ USDT ใน Standby Zone ไปฝาก lending protocol → passive yield 4–8% APY
  • วาง "Bottom Fishing Grid" ที่ระดับ hard support (เช่น $60k–$75k) พร้อมรอ

Strategy 3 (Flash Crash) เหมาะกับ event-driven เท่านั้น ไม่ใช่ bear market ทั่วไป

ข้อ 2: Cross-Exchange Grid กำไรจากอะไร และทำไมถึงทำได้ยากในทางปฏิบัติ?

คำตอบ:

กำไรจาก: price difference ระหว่าง exchanges (arbitrage spread)

ยากเพราะ:

  • Transfer time: การโอน BTC ระหว่าง exchange ใช้ 10–60 นาที → spread อาจปิดไปแล้ว
  • Capital lock: ต้องมีเงินทั้งสอง exchange ตลอด → capital ไม่ productive เต็มที่
  • Fee ซ้อน: trading fee + withdrawal fee + network fee
  • Execution risk: ต้อง execute พร้อมกัน → manual ทำยาก, bot ต้องเร็วมาก
ข้อ 3: Laddered CSP Grid ให้ effective buy price ต่ำกว่า Limit Order Grid อย่างไร?

คำตอบ:

ตัวอย่าง: BUY Limit Order $95k vs SELL PUT $95k (premium $450)

Limit Order: ซื้อ BTC @ $95,000 (ถ้า fill)

CSP: ถ้าถูก assign → ซื้อ BTC @ $95,000 แต่ได้ premium $450 ล่วงหน้า → effective cost = $95,000 − $450 = $94,550

ประหยัด $450 ต่อ 1 BTC ≈ 0.47% ต่ำกว่า ($450/$95,000) — ถ้าทำซ้ำทุก 2 สัปดาห์ (ตาม expiry cycle นี้) จะได้ประมาณ 26 รอบ/ปี → 0.47%×26 ≈ 12.2%/ปี บน capital $10k ≈ $1,220/ปี (ตัวเลขนี้เป็น simple ไม่ compound และไม่รวมกรณีที่ไม่ถูก assign ซึ่งได้ premium ล้วนๆ แทน)

ข้อ 4: Flash Crash Grid ต่างจาก Standard Buy-Only Grid อย่างไร และทำไมต้องใช้ capital แยก (Flash Crash Reserve)?

คำตอบ:

ความแตกต่าง:

  • Standard Buy-Only Grid: ทำงาน ตลอดเวลา ในช่วง sideway ปกติ — วาง BUY orders หลายชั้นอย่างต่อเนื่อง
  • Flash Crash Grid: ทำงาน เฉพาะช่วง flash crash (ราคาหลุด zone ปกติลงไปอย่างรวดเร็ว > 15% ใน <1 ชั่วโมง พร้อม volume spike > 5× — ดูเกณฑ์เต็มด้านบน) — ไม่มี order วางไว้ล่วงหน้าในช่วงปกติ

ทำไมต้องแยก capital (Flash Crash Reserve):

  • Standard grid ใช้ capital หมดในช่วงปกติ → ไม่มีเงินเหลือซื้อตอน flash crash
  • Flash Crash Reserve เก็บ capital แยกไว้ "นอก grid ปกติ" — deploy เฉพาะเมื่อเกิด crash เท่านั้น
  • โอกาสซื้อ BTC ราคาต่ำมาก (>15% below market) มีไม่บ่อย → reserve capital ต้อง idle รอ แต่ผลตอบแทนเมื่อ deploy สูงมาก
ข้อ 5: Rebalancing Grid — Portfolio $20,000 (target 50% BTC ที่ BTC=$100k), step_pct=2% — ที่ level i=+2 (ราคาขึ้นเป็น $104k) ต้องขาย BTC เท่าไหร่ตามสูตร?

คำตอบ:

target_btc_value = $20,000 × 50% = $10,000

target_btc_qty = $10,000 / $100,000 = 0.10 BTC

level_price ที่ i=+2: $100,000 × (1 + 2×0.02) = $104,000 ✓ ตรงกับที่โจทย์ให้

qty (SELL, i>0): target_btc_qty × i × 0.01 = 0.10 × 2 × 0.01 = 0.002 BTC

เมื่อ BTC ขึ้นถึง $104k → grid SELL 0.002 BTC อัตโนมัติ ดึง allocation กลับเข้าใกล้ 50/50
