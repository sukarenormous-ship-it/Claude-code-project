2.1 The Screening Funnel — ค่า cut-off ที่ใช้กันจริง

🚶 อ่านเป็นภาษาคนก่อน — funnel คืออะไร

นึกถึงด่านตรวจสนามบินที่ต่อกันหลายชั้น: เช็คตั๋ว → สแกนกระเป๋า → ตรวจร่างกาย · คู่หุ้นก็ต้องผ่านหลายด่านเช่นกัน — แต่ละด่านกรองผีคนละแบบ · คู่ที่ผ่านทุกด่านเท่านั้นถึงจะเข้ารายการเทรด

นี่คือค่าที่พบบ่อยในงานวิจัยและงานจริง (ใช้เป็นจุดตั้งต้น ไม่ใช่กฎศักดิ์สิทธิ์):

ด่านค่าที่ใช้กันจริงด่านนี้กรองอะไร / กับดัก
1. Correlationρ(ผลตอบแทน) > 0.8กรองหยาบ ลดจำนวนคู่ที่ต้องตรวจ · ใน S&P500 มีเพียง ~872 คู่ที่ > 0.8 · ไม่ใช่ข้อพิสูจน์ว่าเทรดได้
2. ADF test (Engle-Granger)p < 0.05 (เข้ม: < 0.01)ทดสอบว่า spread "นิ่ง" (จะกลับ) จริงไหม · แต่ทดสอบหลายร้อยคู่ = เจอผีเยอะ (§2.3)
3. HurstH < 0.5 (ยิ่งต่ำยิ่งดี)ยืนยันซ้ำว่า spread กลับจริง ไม่ใช่ ADF ผ่านโดยบังเอิญ
4. Half-lifeใช้ได้ราว ~1–30 วันสั้นไป = เทรดถี่ ค่าคอมฯ กิน · ยาวไป = ทุนถูกล็อกนาน + คู่มีเวลาพัง
5. Johansentrace/max-eigen > criticalสำหรับตะกร้า >2 ตัว (เล่ม 1 ไม่มี)
🧮 Half-life คำนวณยังไง (แบบเข้าใจง่าย)

Half-life = "spread ใช้เวลากี่วันกว่าจะกลับครึ่งทางสู่ค่าเฉลี่ย" · ยิ่งสั้น = ยางยืดดึงกลับแรง = เทรดจบไว

1. regress: การเปลี่ยนแปลงวันนี้ = a + b × (spread เมื่อวาน)
2. Half-life = ln(2) / (−b) ← ln(2) ≈ 0.693

ตัวอย่าง (สมมติ): ถ้า −b = 0.10 → HL = 0.693/0.10 ≈ 7 วัน → ดี เทรดได้
อ่านเป็น decision funnel ไม่ใช่ท่องค่า

ทุกคู่ต้องผ่านหลายด่านพร้อมกัน — ADF ผ่าน และ Hurst < 0.5 และ half-life สมเหตุผล · ผ่านด่านเดียวไม่พอ เพราะแต่ละ test มีจุดบอดคนละแบบ การให้ยืนยันกันเองคือวิธีกันผีที่ถูกที่สุด

✍️ ลองคิดเอง

ถ้าคู่หนึ่ง ADF ผ่าน (p=0.03) แต่ half-life = 90 วัน — ควรเทรดไหม? (เฉลย: ไม่ควร — 90 วันนานเกิน ทุนถูกล็อกและคู่มีเวลาพังสูง แม้ ADF ผ่านก็ตาม · นี่คือเหตุผลที่ต้องดูหลายด่าน ไม่ใช่ ADF ตัวเดียว)

2.2 "ทุกคนใช้เหมือนกัน แล้วต่างตรงไหน" — 5 จุด

funnel ข้างบนเป็นของสาธารณะ AI เขียนให้ได้ใน 5 นาที · ความต่างไม่ได้อยู่ที่ funnel — อยู่ที่ 5 อย่างนี้

จุดต่างทำอะไร (และทำไมช่วย)
1. Universeสแกนบ่อที่คนอื่นไม่สแกน (small-cap · ไทย/SEA · crypto) — funnel เดิม แต่บ่อใหม่ ← จุดแข็งรายย่อย (ชั้น D)
2. Validation เข้มกว่าทดสอบ cointegration ซ้ำบนช่วงที่โมเดลไม่เคยเห็น (ไม่ fit ครั้งเดียวจบ) + รวมหลาย test กันผี
3. Parameter regimeจูน half-life band / cut-off ให้เข้ากับ cost ของตัวเอง — คนต้นทุนสูงต้องเลือกคู่ half-life สั้นกว่า
4. When-NOT-to-tradeค่า cointegration เริ่มเสื่อม / half-life พุ่ง = ถอย (โยง Part VII kill-switch) ← ชั้น C
5. Dependence ต่างจากฝูงใช้ copula จับความสัมพันธ์ที่เส้นตรงของฝูงพลาด (§2.4)

2.3 กับดักตัวจริง — ที่ทำให้ backtest สวยแต่ live พัง

📉 กับดัก 1 — In-sample สวย → out-of-sample พัง (อันดับ 1)

คู่ที่ cointegrate สวยในอดีตไม่การันตีว่าจะ cointegrate ต่อ — ความสัมพันธ์เสื่อมได้ (บริษัทเปลี่ยนธุรกิจ · ควบรวม · วิกฤตเฉพาะตัว) · ต้อง validate บนช่วงที่โมเดลไม่เคยเห็นเสมอ

📉 กับดัก 2 — Multiple testing (ร้ายกาจสุดตอนสแกนเยอะ)
🚶 เข้าใจง่าย ๆ

ถ้าโยนเหรียญ 1 เหรียญ 5 ครั้งออกหัวหมด — น่าทึ่ง · แต่ถ้าให้คน 1,000 คนโยนคนละ 5 ครั้ง จะมีสัก 30 คนที่ออกหัวหมดโดยบังเอิญ — ไม่ได้เก่งอะไร · การสแกนคู่หุ้นก็เหมือนกัน ยิ่งสแกนเยอะ ยิ่งเจอ "คู่ที่ดูดี" โดยบังเอิญ

คาดหวังจำนวนผี ≈ (จำนวนคู่ที่ทดสอบ) × (ระดับนัยสำคัญ)
500 คู่ × 0.05 = 25 คู่ "ผ่าน" แบบมั่ว ๆ ทั้งที่ไม่มีความสัมพันธ์จริง

ทางแก้: ปรับ threshold ให้เข้มขึ้น (Bonferroni / FDR) หรือใช้ deflated Sharpe ที่หักจำนวนการทดสอบออก (López de Prado) — ลงลึก Part IX

📉 กับดัก 3 & 4 — Look-ahead + Regime dependence
  • Look-ahead ตอนเลือกคู่: เลือกคู่โดยดูข้อมูลทั้งชุด (รวมอนาคต) แล้ว backtest บนชุดเดิม = โกงตัวเอง
  • Regime dependence: คู่ที่ cointegrate ในตลาดขาขึ้น อาจพังในวิกฤต — มันไม่ใช่คุณสมบัติถาวร
🧠 มุมที่ quant มองต่าง

คนทั่วไปเห็น: "เจอคู่ที่ ADF p = 0.001 = เจอขุมทอง"
quant เห็น: ถ้าสแกนมาพันคู่ p=0.001 อาจเป็นแค่ผีตัวหนึ่ง — คำถามไม่ใช่ "p ต่ำแค่ไหน" แต่คือ "ฉันทดสอบมากี่ครั้งกว่าจะเจอมัน"

2.4 Copula สำหรับรายย่อย — จับสิ่งที่เส้นตรงมองไม่เห็น

🚶 อ่านเป็นภาษาคนก่อน — ทำไมต้องมีตัวนี้อีก

correlation/cointegration เป็นเครื่องมือเชิงเส้น — มันสรุปความสัมพันธ์เป็นตัวเลขเฉลี่ยตัวเดียว · แต่คู่หุ้นบางคู่เกาะกันแน่นเฉพาะตอนตลาดตก (แห่ขายพร้อมกัน) ส่วนตอนปกติต่างคนต่างไป · ตัวเลข correlation เดียวจับความต่างนี้ไม่ได้ — copula จับได้

copula แยก 2 อย่างออกจากกัน: marginal (แต่ละตัวมีพฤติกรรมยังไง) กับ dependence (มันเชื่อมกันยังไง) → ทำให้จับ "tail dependence" (เกาะกันตรงหางของการแจกแจง = ตอนสุดโต่ง) ได้

Copulaเกาะกันตรงไหนใช้เมื่อ
Gaussian / Frankไม่มีหางพิเศษเชื่อมกันปกติทั่ว ๆ ไป
Student-t2 หาง สมมาตรเกาะแรงทั้งตอนขึ้น/ลง (คู่ในเซกเตอร์เดียว)
Claytonหางล่างเกาะแรงตอน ตลาดตก (crash together)
Gumbel / Joeหางบนเกาะแรงตอน ตลาดขึ้น
🧮 Signal: Mispricing Index (MI) — ต่างจาก z-score ยังไง

สาย cointegration ใช้ z-score ของ spread · สาย copula ใช้ conditional probability: "ถ้า PEP อยู่ตรงนี้ ปกติ KO ควรอยู่ตรงไหน" แล้ววัดว่าของจริงเบี่ยงจากนั้นแค่ไหน

MI = P(KO อยู่ต่ำกว่านี้ | เห็น PEP แล้ว) − 0.5

MI > 0 → KO แพงเกินที่ควร (เทียบ PEP) → short KO / long PEP
MI < 0 → KO ถูกเกินที่ควร → long KO / short PEP

❌ Copula พังเมื่อไร (ต้องเตือน)
  • ต้อง fit marginal ให้ดีก่อน (ใช้ empirical CDF) — marginal ผิด copula ผิดตาม
  • เลือก family มั่ว = overfit — อย่าลองทุก family แล้วเลือกอันที่ backtest สวยสุด
  • tail-dependence ไม่นิ่งบนข้อมูลน้อย (ตรงหางมีจุดน้อยโดยธรรมชาติ)
  • ต้อง out-of-sample เสมอ

2.5 ขีดจำกัดของโลกทีละคู่ → สะพานสู่ Part III

สังเกตว่าทั้ง correlation · cointegration · copula — ทุกอย่างมองทีละคู่ · แต่ทำไมหุ้น 2 ตัวถึงเดินด้วยกันตั้งแต่แรก? ไม่ใช่เพราะมี "ความสัมพันธ์วิเศษ" เฉพาะคู่ — แต่เพราะมันแชร์ common factor เดียวกัน (ตลาด · sector · style)

"ถ้า co-movement มาจาก factor ร่วม — ทำไมต้องนั่งเลือกคู่ทีละคู่? ทำไมไม่หัก factor ทิ้ง แล้วเทรดสิ่งที่เหลือทั้งกระดาน?"

นั่นคือ Part III — ที่ pairwise กลายเป็นแค่กรณีพิเศษ และ edge (กับความเสี่ยงที่ซ่อนอยู่) เปลี่ยนหน้าตาไปเลย

📖 ศัพท์ใหม่ในตอนนี้
  • Screening funnel — ลำดับด่านคัดคู่ (correlation → ADF → Hurst → half-life → Johansen)
  • ADF test — ทดสอบว่า spread นิ่ง (จะกลับ) จริงไหม
  • Half-life — เวลาที่ spread กลับครึ่งทาง = ln(2)/θ
  • Hurst exponent — วัดว่า mean-revert (H<0.5) / สุ่ม (0.5) / trending (>0.5)
  • Multiple testing — ยิ่งทดสอบเยอะ ยิ่งเจอผีจากความบังเอิญ
  • Copula / Mispricing Index — จับ tail dependence; สัญญาณ = P(เงื่อนไข) − 0.5
