GARCH บน Residuals

Volatility แบบ Conditional σ_t — เมื่อความผันผวนของ Spread รวมตัวเป็นกลุ่ม
σ_t² = ω + α·ε²t−1 + β_G·σ²t−1
แนวคิดหลัก — อ่านก่อน
Spread ε จาก OU ให้ z-score เป็นสัญญาณซื้อขาย โดยแบ่งโซนด้วย threshold ของ z-score GARCH(1,1) ทำให้ σ_t ปรับตัวตามสถานการณ์จริงทุก bar — แถบสัญญาณ ±2σ จะไม่ตายตัว แต่ขยายตัวในช่วง volatile และหดตัวในช่วงสงบ ป้องกันสัญญาณเท็จและสัญญาณพลาด
$$\sigma_t^2 = \omega + \alpha \cdot \varepsilon_{t-1}^2 + \beta_G \cdot \sigma_{t-1}^2 \qquad z_t = \frac{\varepsilon_t - \theta}{\sigma_t}$$
|z_t| > 3: หยุด (STOP)  ·  2 < |z_t| ≤ 3: เข้า (ENTRY)  ·  |z_t| ≤ 2: ถือ/ออก

7.1 ปัญหาของ σ คงที่

OU มาตรฐานสมมติว่า residual ε มีการกระจายแบบ i.i.d. (อิสระต่อกัน) ด้วย σ คงที่ แต่ในตลาด BTC จริง volatility มีลักษณะ heteroskedastic สูง — ผันผวนหนักแล้วสงบ สลับกันเป็นกลุ่ม ถ้าใช้แถบ ±2σ ที่คำนวณจาก unconditional σ ตลอดเวลา จะเกิดความผิดพลาด 2 แบบ:

  • สัญญาณเท็จในช่วง Storm: ช่วง volatility สูง spread ข้ามแถบ ±2σ (static) บ่อยๆ ดูเหมือนมีโอกาสเทรดตลอด แต่จริงๆ σ ขยายตัว 3 เท่า ทำให้ 2σ_static = 0.67 ของ GARCH-σ เท่านั้น — ไม่ใช่ extreme จริง
  • สัญญาณพลาดในช่วงสงบ: ช่วงตลาดเงียบ การเคลื่อนที่ 2σ (static) อาจเป็น 4σ ในแง่ GARCH — สัญญาณที่หายากและ high-conviction กลับถูกมองข้าม
OU path พร้อมโซนสัญญาณ: สีแดง = STOP (|z|>3), สีส้ม = ENTRY (2<|z|<3), สีเขียว = HOLD/EXIT (|z|<2) จุดแดง = จุดเข้าเมื่อ |z| ข้าม 2 สามเหลี่ยมเขียว = ออกเมื่อ |z| กลับต่ำกว่า 0.5
บันทึก Practitioner — การ Calibrate Threshold ของ Zone จาก Backtest

Threshold มาตรฐาน (Entry ±2, Stop ±3) เป็นจุดเริ่มต้นที่ดี แต่ ควร calibrate แยกต่างหากสำหรับแต่ละคู่ ขั้นตอน: (1) ทำ walk-forward backtest บนข้อมูล 90 วัน (2) คำนวณ empirical exceedance rate — ถ้า |z|>2 เกิดขึ้น >8% ของ bar ให้ขยายเป็น ±2.5 (3) ตรวจ average holding time: ถ้าน้อยกว่า 2 bar อาจเป็น microstructure noise แทนที่จะเป็น OU (4) ใช้ threshold ที่ maximize Sharpe บน test window แล้ว validate out-of-sample ก่อน deploy จริง สำหรับ BTC cross-exchange spread มักใช้ Entry ±2.0 Exit ±0.5 สำหรับ equity pair ใช้ Entry ±1.5 Exit ±0.3 เนื่องจาก mean-reversion ช้ากว่า

ความเสี่ยงของแบบจำลอง — Threshold ขึ้นอยู่กับความเสถียรของพารามิเตอร์ OU

Threshold ของ zone คำนวณจากพารามิเตอร์ OU (κ, θ, σ) ที่ estimate จากข้อมูลอดีต ถ้า พารามิเตอร์ OU เปลี่ยน เช่น κ ลดลง (mean-reversion ช้าลง) หรือ σ เพิ่มขึ้น — threshold จะ miscalibrate: entry 2σ อาจเป็นแค่ 1.3σ ในระบอบใหม่ ทำให้สัญญาณเท็จ วิธีป้องกัน: recalibrate OU parameters ทุกเดือน (หรือหลังเหตุการณ์ใหญ่ในตลาด) ตรวจว่า distribution ของ z-score ยังอยู่รอบ 0 โดย std ≈ 1.0 ในข้อมูลล่าสุด และตั้ง alert อัตโนมัติถ้า std(z, 7d) > 1.3 — แสดงว่า σ ที่ใช้ใน denominator เก่าเกินไปแล้ว

7.2 แบบจำลอง GARCH(1,1)

GARCH(1,1) — Generalized AutoRegressive Conditional Heteroskedasticity — อัปเดต variance estimate ทุก period โดยใช้ข้อมูล 2 อย่าง: shock ครั้งล่าสุดยกกำลังสอง และ variance estimate ล่าสุด

สมการ GARCH(1,1)
σ_t² = ω + α · ε²_{t−1} + β_G · σ²_{t−1}
ω (omega) — variance floor ระยะยาว ต้องเป็นบวกเสมอ ป้องกันไม่ให้ σ_t ยุบเป็นศูนย์
α (alpha) — น้ำหนักของ shock ล่าสุด ช่วงปกติ: 0.05–0.15 ยิ่ง α สูง → variance ตอบสนองต่อ shock ได้เร็วกว่า
β_G (GARCH beta) — ความคงอยู่ของ variance ช่วงปกติ: 0.80–0.90 ยิ่ง β_G สูง → variance ลดลงช้า (ความจำยาว) หมายเหตุ: β_G คนละตัวกับ hedge ratio β
เงื่อนไข stationarity: α + β_G < 1 (ถ้าเกิน variance จะระเบิดเป็นอนันต์)
Variance ระยะยาว: σ²_∞ = ω / (1 − α − β_G)
พารามิเตอร์ช่วงทั่วไปผลถ้าเพิ่มค่าผลถ้าสูงเกินไป
ω (omega)1e-7 ถึง 1e-4ยก variance floor ขึ้นประเมิน σ สูงเกินจริงช่วงสงบ
α (alpha)0.05 – 0.15ตอบสนองต่อ shock เร็วขึ้นσ_t ไม่เสถียร, noise มาก
β_G (GARCH beta)0.80 – 0.92ความจำ variance ยาวขึ้นถ้า α+β_G≥1: ไม่ stationary

7.3 GARCH Z-Score — แถบสัญญาณปรับตัว

แทนที่จะใช้ z = (ε_t − θ) / σ_static ให้ใช้ ตัวหาร time-varying จาก GARCH:

หมายเหตุ: z-score คือสัญญาณหลักของการเข้า/ออก — ตอนนี้เข้าใจว่า z = (ε−θ)/σ บอกว่า spread ห่างจากค่ากลางกี่ "ส่วนเบี่ยงเบนมาตรฐาน" ก็พอ — นิยามเต็ม รวมถึง Robust z-score อยู่ใน บทที่ 10

GARCH z-score: z_t = (ε_t − θ) / σ_t สัญญาณเข้า: z_t > +2.0 → short spread (คาดว่า spread จะลดลง) z_t < −2.0 → long spread (คาดว่า spread จะเพิ่มขึ้น) สัญญาณออก: |z_t| < 0.5 → ปิด position
P&L ต่อการเทรดจาก backtest แบบ OU อย่างง่าย (เข้าเมื่อ |z|>2, ออกเมื่อ |z|<0.5) แท่งเขียว = กำไร แท่งแดง = ขาดทุน เส้น teal = Cumulative P&L Win rate และจำนวน trade แสดงมุมขวาบน

7.4 เมื่อไหร่ควรใช้ GARCH แทน σ คงที่

มิติσ คงที่ (OU พื้นฐาน)GARCH(1,1)
สมมติฐานσ คงที่ตลอดเวลาσ_t เปลี่ยนตาม shock ล่าสุด
เหมาะกับคู่ที่เสถียรมาก volatility ต่ำคู่ที่มี volatility clustering
ตรวจ regime ได้ไม่ได้ได้ — σ_t เข้ารหัส regime ปัจจุบัน
สัญญาณเท็จสูงช่วง vol spikeต่ำ — แถบปรับตาม volatility

ทริกเกอร์การรวมตัวของ Volatility

คำนวณอัตราส่วนระหว่าง rolling std 7 วัน กับ rolling std 30 วัน ของ spread residuals ถ้าอัตราส่วนเกิน 1.5 แสดงว่า volatility regime เปลี่ยนแล้ว — สลับไปใช้ GARCH z-score ทันที ถ้าอัตราส่วนต่ำกว่า 1.1 อย่างสม่ำเสมอ σ คงที่เพียงพอแล้วและ GARCH ไม่ได้ช่วยเพิ่มอะไร

7.5 Pseudo-Code: GARCH Update & Z-Score

function garch_update(omega, alpha, beta_G, prev_sigma_sq, prev_residual): # GARCH(1,1) variance recursion — เรียกทุก bar # omega: variance floor ระยะยาว (เช่น 1e-6) # alpha: น้ำหนัก shock (เช่น 0.10) # beta_G: GARCH persistence (เช่น 0.85) # prev_sigma_sq: σ²_{t-1} # prev_residual: ε_{t-1} (spread residual จริง ไม่ใช่ z-score) new_sigma_sq = omega + alpha * (prev_residual ** 2) + beta_G * prev_sigma_sq return new_sigma_sq function garch_zscore(eps, theta, sigma_t): # eps: spread residual ปัจจุบัน ε_t # theta: ค่ากลาง OU ระยะยาว θ # sigma_t: sqrt(GARCH variance ปัจจุบัน) z = (eps - theta) / sigma_t return z function should_use_garch(residuals, window_short=7*24, window_long=30*24): # คืนค่า True ถ้าตรวจพบ volatility clustering std_short = rolling_std(residuals, window_short)[-1] std_long = rolling_std(residuals, window_long)[-1] ratio = std_short / std_long return ratio > 1.5 # Main loop (hourly bar) sigma_sq = long_run_variance # initialize เป็น ω/(1-α-β_G) for each new bar: prev_eps = spread_residual[t-1] sigma_sq = garch_update(omega, alpha, beta_G, sigma_sq, prev_eps) sigma_t = sqrt(sigma_sq) z = garch_zscore(spread_residual[t], theta, sigma_t) if z > 2.0: execute_short_spread() if z < -2.0: execute_long_spread() if abs(z) < 0.5: close_position()

7.6 การ Estimate ω, α, β_G จากข้อมูลจริง (MLE)

ค่า ω, α, β_G ต้องหาจากข้อมูล ไม่ใช่ guess — วิธีมาตรฐานคือ Maximum Likelihood Estimation (MLE) ผ่าน library ที่ optimize log-likelihood ของ GARCH โดยอัตโนมัติ

# Python — ใช้ arch library (pip install arch) from arch import arch_model import numpy as np # residuals: spread residuals ε_t (ใช้ % return หรือ log-diff) # ⚠️ UNIT NOTE: scaling ×100 เปลี่ยนหน่วย ε จาก raw → % ดังนั้น: # ω ที่ได้จาก fit จะมีหน่วย %² (ไม่ใช่ raw²) # ก่อนนำ ω ไปใช้ใน garch_update() ต้องหาร 10000 ถ้า code ทำงานกับ raw units # หรือ scale residuals ×100 ตลอดทั้ง pipeline ให้สม่ำเสมอ residuals = spread_residuals * 100 # scale เป็น % เพื่อ numerical stability # Fit GARCH(1,1) model = arch_model(residuals, vol='GARCH', p=1, q=1, mean='Constant') result = model.fit(disp='off') # disp='off' ปิด iteration output # อ่านพารามิเตอร์ที่ได้ omega = result.params['omega'] # ω (variance floor) alpha = result.params['alpha[1]'] # α (shock weight) beta_G = result.params['beta[1]'] # β_G (GARCH persistence) print(f"ω={omega:.2e}, α={alpha:.4f}, β_G={beta_G:.4f}") print(f"α+β_G={alpha+beta_G:.4f} (ต้อง < 1 เพื่อ stationarity)") # Conditional variances ที่ model fit cond_var = result.conditional_volatility ** 2 # array ของ σ_t² # Forecast σ_{t+1} สำหรับ next bar (ใช้ใน live trading) forecast = result.forecast(horizon=1, reindex=False) sigma_next_sq = forecast.variance.values[-1, 0] sigma_next = np.sqrt(sigma_next_sq)
หน่วย ω: ×100 Scaling ทำให้ ω อยู่ใน %² ไม่ใช่ Raw²

เมื่อ residuals = spread_residuals * 100 (scale จาก fraction เป็น %):
• ε_t มีหน่วย % (เช่น 0.08, 0.15, 0.24)
• ω ที่ fit ได้มีหน่วย %² (เช่น ω ≈ 0.000006 %²)
• σ_t จาก GARCH มีหน่วย % → GARCH z-score = ε_t (%) / σ_t (%) ✓ ไม่มีปัญหา

ปัญหาถ้า mix หน่วย: ถ้า ε_t ใน code เป็น raw (0.0008) แต่ ω ที่ fit ไว้เป็น %² (0.000006%) → σ_t = √(ω_%) × 0.01 ≠ σ_t ที่ถูก
วิธีแก้ที่ง่ายที่สุด: เลือก scale เดียวตลอด pipeline — แนะนำให้ scale ×100 ทั้งหมด หรือใช้ raw ทั้งหมดโดยหาร ω_% ด้วย 10000 ก่อนใช้

# ถ้าอยากทำงานใน raw units หลังจาก fit ด้วย % units: omega_raw = omega_pct / 10000 # %² → raw² (÷ 100²) # จากนั้น garch_update(omega_raw, alpha, beta, ...) ด้วย raw epsilon ได้เลย

ผลที่คาดหวังสำหรับ BTC Spread

จากประสบการณ์กับ crypto spread โดยทั่วไปพบ:
ω ≈ 1e-7 ถึง 1e-5 | α ≈ 0.05–0.15 | β_G ≈ 0.80–0.92
ถ้า α + β_G ≥ 1 → model non-stationary → ลอง EGARCH หรือ ตัดข้อมูล outlier ออกก่อน refit

ทางเลือก: EGARCH (ถ้า volatility asymmetric)

Crypto มักมี "volatility asymmetry" — ราคาลงทำให้ spread volatile มากกว่าราคาขึ้น
ใช้ EGARCH ได้: arch_model(residuals, vol='EGARCH', p=1, q=1)
parameter เพิ่ม γ (asymmetry) — ถ้า γ < 0 แปลว่า negative shock ทำให้ volatile มากกว่า

โจทย์ 7.1 — คำนวณ σ² ใหม่

กำหนดให้: ω = 0.0001, α = 0.10, β_G = 0.85, prev_σ² = 0.0004, prev_ε = 0.025

คำถาม: คำนวณ σ² ใหม่ α + β_G < 1 หรือไม่? Variance ระยะยาวคือเท่าไร?

ดูเฉลย

ขั้นที่ 1: ตรวจ stationarity: α + β_G = 0.10 + 0.85 = 0.95 < 1 ✓ (stationary)

ขั้นที่ 2: σ² ใหม่ = ω + α·ε² + β_G·σ²
= 0.0001 + 0.10 × (0.025)² + 0.85 × 0.0004
= 0.0001 + 0.10 × 0.000625 + 0.00034
= 0.0001 + 0.0000625 + 0.00034
= 0.0005025

Variance ระยะยาว = ω / (1 − α − β_G) = 0.0001 / (1 − 0.95) = 0.0001 / 0.05 = 0.002

ตีความ: shock ล่าสุด (ε = 0.025) ดัน σ² จาก 0.0004 เป็น 0.0005025 — variance เพิ่มขึ้น 25% ค่าสมดุลระยะยาวคือ 0.002 ดังนั้นสภาวะปัจจุบันยังเงียบกว่าค่าเฉลี่ย (0.0005 vs 0.002)

โจทย์ 7.2 — Naive vs GARCH Signal ขัดแย้งกัน

Spread residual ปัจจุบัน ε = 0.48%, θ = 0.00% Static σ = 0.14% GARCH σ_t ปัจจุบัน = 0.26%

Naive z = 0.48/0.14 = 3.5  ·  GARCH z = 0.48/0.26 = 1.8

คำถาม: ควรเปิด short spread หรือไม่? อธิบายเหตุผล

ดูเฉลย

ไม่ควรเข้า GARCH z-score = 1.8 ไม่ถึง threshold 2.0 ที่กำหนด Naive z = 3.5 เป็น สัญญาณเท็จ — ดูสูงเพราะ σ static เก่าเกินไป

สิ่งที่ GARCH บอก: conditional volatility ปัจจุบัน (0.26%) เกือบ 2 เท่าของค่าเฉลี่ยประวัติศาสตร์ (0.14%) ตลาดอยู่ในสภาวะ volatile spread เคลื่อน 0.48% แต่เทียบกับ vol ปัจจุบัน นี่คือแค่เหตุการณ์ 1.8σ — ปกติสำหรับ regime นี้

ความเสี่ยงถ้าเข้าอยู่ดี: ใน high-vol regime spread อาจขยายต่อ (mean-reversion ช้าลงเมื่อ κ ลดลงในสภาวะกดดัน) การเข้าที่ GARCH z = 1.8 ให้ risk/reward ไม่ดี

กฎ: ใช้ GARCH z-score เสมอเมื่อ should_use_garch() คืนค่า True และเพิกเฉยต่อ naive z-score ใน volatile regime
