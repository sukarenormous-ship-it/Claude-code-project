บทที่ 12 — Cross-Validation: วัดผลอย่างซื่อสัตย์

12.1 การแบ่งข้อมูลครั้งเดียว คือการโยนเหรียญ

🚶 อ่านเป็นภาษาคนก่อน: ใน เล่ม 2 · C §6.7 เราแบ่งข้อมูลเป็นชุดฝึกกับชุดทดสอบ แล้วดู R² ของชุดทดสอบ · ฟังดูซื่อสัตย์ดี · แต่ผลที่ได้ขึ้นกับว่าคุณบังเอิญแบ่งตรงไหน — และมันขึ้นกับเยอะกว่าที่ใครคิด

ก่อนอื่น — R²(out) ที่จะเห็นตลอดตอนนี้คืออะไร:

R²(out) = 1 − Σ(y จริง − y ทำนาย)² / Σ(y จริง − ȳ)² ↑ error ของโมเดล ↑ error ของการเดาค่าเฉลี่ยเฉย ๆ = 1 → ทำนายเป๊ะ = 0 → ดีเท่าเดาค่าเฉลี่ย ติดลบ → แย่กว่าเดาค่าเฉลี่ย

📖 อ่านสูตรว่า: "อาร์กำลังสอง เท่ากับ หนึ่ง ลบ ผลรวมของ (จริง ลบ ทำนาย)² หารด้วย ผลรวมของ (จริง ลบ ค่าเฉลี่ย)²" · "(out)" ในวงเล็บเป็นป้ายบอกว่าวัดกับข้อมูลชุดไหน ไม่ใช่อินพุตของฟังก์ชัน · โครงที่ต้องเห็น: ไส้ในคือ "ความผิดพลาดของโมเดล ÷ ความผิดพลาดของการเดาแบบโง่ที่สุด (ทายค่าเฉลี่ย)" — เศษและส่วนหน่วยเดียวกัน อัตราส่วนจึงไร้หน่วย แล้วเอา 1 ลบเพื่อให้ "ยิ่งสูงยิ่งดี" · กับดักการอ่าน: คนจำว่า R² อยู่ระหว่าง 0 กับ 1 เพราะใน in-sample เส้น OLS ชนะค่าเฉลี่ยเสมอ (อัตราส่วน ≤ 1) แต่กับข้อมูลที่โมเดลไม่เคยเห็น ไม่มีอะไรห้ามให้เศษใหญ่กว่าส่วน — อัตราส่วน > 1 จึงเกิดได้และ R² ติดลบ อ่านตรงตัวว่า "ทายค่าเฉลี่ยเฉย ๆ ยังดีกว่าใช้โมเดลนี้"

"(out)" คือ out-of-sample — วัดกับข้อมูลที่โมเดลไม่เคยเห็น ต่างจาก R² ธรรมดา (in-sample) ที่วัดกับข้อมูลที่มันฝึกมา · จำบรรทัดสุดท้ายไว้ให้ดี เพราะ §12.3 จะได้ค่าติดลบ และนั่นคือประเด็นทั้งหมด

ลองแบ่งชุดข้อมูลเดิม (200 จุด · ฝึก 150 ทดสอบ 50) แบบสุ่ม 200 ครั้ง ด้วยโมเดลเดิมเป๊ะ:

🐍 Python — แบ่งชุดเดิม 200 ครั้ง ดูว่า R² เหวี่ยงแค่ไหน
# pip install numpy statsmodels
import numpy as np, statsmodels.api as sm

rng = np.random.default_rng(3)
N = 200
x = rng.normal(0, 1, N)
y = 1 + 1.5*x + rng.normal(0, 1.5, N)          # ความสัมพันธ์จริงมีอยู่แน่นอน
X = sm.add_constant(x)

r2 = []
for s in range(200):                            # แบ่งแบบสุ่ม 200 วิธี
    idx = np.random.default_rng(s).permutation(N)
    tr, te = idx[:150], idx[150:]
    m = sm.OLS(y[tr], X[tr]).fit()
    p = m.predict(X[te])
    r2.append(1 - ((y[te]-p)**2).sum() / ((y[te]-y[te].mean())**2).sum())

r2 = np.array(r2)
print(f"R2(out) ต่ำสุด {r2.min():.3f} | สูงสุด {r2.max():.3f} | เฉลี่ย {r2.mean():.3f}")
# R2(out) ต่ำสุด 0.225 | สูงสุด 0.708 | เฉลี่ย 0.513
print(f"ช่วง 5-95% = [{np.percentile(r2,5):.3f}, {np.percentile(r2,95):.3f}]")
# ช่วง 5-95% = [0.346, 0.650]
❌ ตัวเลขเดียวที่คุณรายงาน คือตัวเลขที่คุณบังเอิญได้

R² เดียวกัน โมเดลเดียวกัน ข้อมูลเดียวกัน — แต่ได้ตั้งแต่ 0.225 ถึง 0.708 · ห่างกัน 0.48 ซึ่งกว้างกว่าความต่างระหว่าง "โมเดลดี" กับ "โมเดลใช้ไม่ได้" เสียอีก

แปลว่าถ้าคุณลองโมเดล 2 แบบแล้วได้ 0.55 กับ 0.48 · คุณยังบอกไม่ได้เลยว่าแบบไหนดีกว่า เพราะความต่าง 0.07 นั้นเล็กกว่าความเหวี่ยงของการแบ่งเองมาก

และในทางปฏิบัติมันแย่กว่านั้น เพราะคนมักลองแบ่งหลายรอบแล้วเลือกจำรอบที่ผลออกมาสวยโดยไม่รู้ตัวด้วยซ้ำ

12.2 k-fold Cross-Validation — ใช้ข้อมูลทุกจุดเป็นทั้งครูและข้อสอบ

k-fold CV Stone 1974 ★★★ ต้องรู้จัก

🎯 Thesis

"แทนที่จะแบ่งครั้งเดียวแล้วลุ้น ให้แบ่งเป็น k ส่วน แล้วผลัดกันให้แต่ละส่วนเป็นข้อสอบ — ทุกจุดข้อมูลได้ทำหน้าที่ทั้งสองอย่าง และคุณได้ค่าเฉลี่ยแทนการโยนเหรียญ"

🚶 อ่านเป็นภาษาคนก่อน: ลองนึกถึงการสอบที่มีข้อสอบชุดเดียว — คะแนนขึ้นกับว่าบังเอิญออกตรงที่อ่านมาไหม · k-fold คือการสอบ 5 ครั้งด้วยข้อสอบคนละชุด แล้วเอาคะแนนเฉลี่ย · ยุติธรรมกว่ามาก และยังบอกได้ด้วยว่าคะแนนเหวี่ยงแค่ไหน ซึ่งเป็นข้อมูลที่การสอบครั้งเดียวให้ไม่ได้เลย

แบ่งข้อมูลเป็น k ส่วนเท่า ๆ กัน (นิยม k = 5 หรือ 10) รอบที่ 1: [ทดสอบ][ ฝึก ][ ฝึก ][ ฝึก ][ ฝึก ] รอบที่ 2: [ ฝึก ][ทดสอบ][ ฝึก ][ ฝึก ][ ฝึก ] รอบที่ 3: [ ฝึก ][ ฝึก ][ทดสอบ][ ฝึก ][ ฝึก ] ... คะแนนสุดท้าย = ค่าเฉลี่ยของ k รอบ (+ ดูส่วนเบี่ยงเบนด้วยเสมอ)
✅ ใช้ได้เมื่อไร
  • ข้อมูลตัดขวาง (cross-sectional) ที่แต่ละแถวเป็นอิสระต่อกัน — เช่น ข้อมูลงบการเงินของบริษัท 500 แห่ง ณ วันเดียวกัน
  • ข้อมูลน้อย จนตัดชุดทดสอบออกไปเฉย ๆ แล้วเสียดาย
  • ต้องการเปรียบเทียบหลายโมเดลอย่างเป็นธรรม
❌ พังเมื่อไร

ทันทีที่ข้อมูลมีลำดับเวลา — ซึ่งคือข้อมูลการเงินแทบทั้งหมด · หัวข้อถัดไปคือเรื่องนี้ทั้งหัวข้อ เพราะมันสำคัญพอที่จะแยกออกมา

12.3 💎 ทำไม k-fold ถึงใช้กับข้อมูลการเงินไม่ได้

🚶 อ่านเป็นภาษาคนก่อน: ลองนึกว่าคุณติวหนังสือสอบ แล้ว "ข้อสอบ" ที่เอามาวัดผล คือข้อที่อยู่ในชีทที่คุณเพิ่งอ่านไป · คะแนนที่ได้ไม่ได้วัดว่าคุณเก่ง มันวัดว่าคุณจำได้

การสลับลำดับข้อมูลก่อนแบ่ง ทำแบบนั้นพอดี — วันที่อยู่ในชุดทดสอบ มีวันข้างเคียงอยู่ในชุดฝึก · และในข้อมูลราคา วันข้างเคียงแทบเป็นคำตอบอยู่แล้ว

💎 นี่คือข้อผิดพลาดที่พบบ่อยที่สุดในงานควอนต์ทั้งหมด

KFold(shuffle=True) สลับลำดับข้อมูลก่อนแบ่ง · ผลคือชุดฝึกมีข้อมูลของวันพุธ ส่วนชุดทดสอบมีข้อมูลของวันอังคารที่อยู่ติดกัน

ในข้อมูลที่ค่าใกล้กันตามเวลา (ซึ่งคือราคาสินทรัพย์ทุกชนิด) การรู้ค่าวันพุธแทบเท่ากับรู้ค่าวันอังคาร · โมเดลจึงไม่ได้ "ทำนาย" อะไรเลย — มันลอกคำตอบจากเพื่อนที่นั่งข้าง ๆ

และในโลกจริงคุณไม่มีเพื่อนคนนั้น เพราะพรุ่งนี้ยังไม่เกิดขึ้น

🐍 Python — เส้นสุ่ม 2 เส้นที่ไม่เกี่ยวกัน · สองวิธีแบ่ง สองคำตอบ
# pip install numpy scikit-learn
import numpy as np
from sklearn.model_selection import KFold, TimeSeriesSplit
from sklearn.linear_model import LinearRegression

rng = np.random.default_rng(0)
n = 500
A = np.cumsum(rng.normal(0, 1, n))       # random walk เส้นที่ 1
B = np.cumsum(rng.normal(0, 1, n))       # random walk เส้นที่ 2 — ไม่เกี่ยวกันเลย
X = A.reshape(-1, 1)

def score(cv):
    out = []
    for tr, te in cv.split(X):
        p = LinearRegression().fit(X[tr], B[tr]).predict(X[te])
        out.append(1 - ((B[te]-p)**2).sum() / ((B[te]-B[te].mean())**2).sum())
    return np.array(out)

k = score(KFold(5, shuffle=True, random_state=0))     # ★ ค่าปริยายที่คนใช้กัน
w = score(TimeSeriesSplit(5))                          # ★ วิธีที่ถูกต้อง
print("k-fold      :", np.round(k, 3), f"เฉลี่ย {k.mean():+.3f}")
# k-fold      : [0.307 0.332 0.117 0.339 0.258] เฉลี่ย +0.271
print("walk-forward:", np.round(w, 3), f"เฉลี่ย {w.mean():+.3f}")
# walk-forward: [-6.698 -1.765 -4.498  0.033 -4.552] เฉลี่ย -3.496
✅ อ่านผลลัพธ์
  • k-fold ให้ +0.271 อย่างสม่ำเสมอทุก fold (0.117–0.339) · ความสม่ำเสมอนี้ยิ่งหลอกหนัก เพราะมันดูเหมือน "ผลที่เสถียร" ทั้งที่มันเสถียรในความผิด
  • walk-forward ให้ −3.496 และเหวี่ยงหนัก (−6.7 ถึง +0.03) · R² ติดลบแปลว่าทำนายแย่กว่าการเดาค่าเฉลี่ยเฉย ๆ ซึ่งคือความจริงของเส้นสุ่มสองเส้นที่ไม่เกี่ยวกัน
  • สังเกตว่า ความเหวี่ยงของ walk-forward เองก็เป็นข้อมูล — มันบอกว่าความสัมพันธ์ไม่คงที่ ซึ่ง k-fold กลบทิ้งไปหมด

💎 กฎเดียวที่ต้องจำจากบทนี้: ถ้าข้อมูลมีแกนเวลา — ชุดฝึกต้องอยู่ก่อนชุดทดสอบเสมอ ไม่มีข้อยกเว้น

💡 บทเรียนที่ลึกกว่านั้น: "ไม่สลับ" ยังไม่พอ ต้อง "ไม่มองไปข้างหน้า" ด้วย — สองอย่างนี้ไม่เหมือนกัน และคนมักหยุดที่อย่างแรก

12.4 ❌ Data Leakage — 4 ทางที่อนาคตรั่วเข้ามาโดยคุณไม่รู้ตัว

🚶 อ่านเป็นภาษาคนก่อน: leakage คือการที่ข้อมูลซึ่ง "ตอนนั้นคุณยังไม่มี" หลุดเข้าไปในขั้นตอนฝึกโมเดล · อาการของมันคือ backtest สวยผิดปกติแล้วเทรดจริงพัง — และมันแทบไม่เคยประกาศตัว คุณต้องไปตามหาเอง

❌ 1. เลือกฟีเจอร์จากข้อมูลทั้งชุด ก่อนแบ่ง

สมมติมีตัวแปรที่อาจใช้ได้ 200 ตัว · คุณดูว่าตัวไหน correlate กับ y ดีที่สุด เลือกมา 10 ตัว แล้วค่อยทำ cross-validation

สายเกินไปแล้ว · การเลือกนั้นใช้ข้อมูลของชุดทดสอบไปเรียบร้อย · CV ที่ทำทีหลังจึงตรวจสอบโมเดลที่ "เห็นข้อสอบมาแล้ว"

ทางแก้: การเลือกฟีเจอร์ต้องอยู่ข้างในลูป CV — ทำใหม่ทุก fold โดยใช้เฉพาะชุดฝึกของ fold นั้น · ถ้าทำถูก คุณมักพบว่าตัวแปรที่ถูกเลือกเปลี่ยนไปเรื่อย ๆ ทุก fold ซึ่งเป็นสัญญาณสำคัญว่ามันไม่เสถียรจริง

❌ 2. ปรับสเกลข้อมูลก่อนแบ่ง

scaler.fit(X) แล้วค่อยแบ่ง — ค่าเฉลี่ยกับ SD ที่ใช้ปรับสเกลคำนวณจากข้อมูลทั้งชุดรวมอนาคต

ผลกระทบมักเล็ก แต่มันคือ leakage จริง ๆ และในข้อมูลที่มีการเปลี่ยนระบอบ (เช่น vol กระโดดตอน crash) มันไม่เล็ก

ทางแก้: scaler.fit(X_train) เท่านั้น แล้ว transform ทั้งสองชุด · หรือใช้ Pipeline ของ sklearn ซึ่งจัดการให้ถูกต้องอัตโนมัติเมื่อใส่เข้า cross_val_score

❌ 3. ป้ายกำกับที่ทับซ้อนกัน (overlapping labels) — ข้อที่ควอนต์เจอบ่อยที่สุด

สมมติคุณทำนาย ผลตอบแทน 5 วันข้างหน้า โดยมีข้อมูลรายวัน · แถวของวันจันทร์มีป้ายว่า "จันทร์→ศุกร์" · แถวของวันอังคารมีป้ายว่า "อังคาร→จันทร์หน้า"

สองแถวนี้ใช้ข้อมูลของวันเดียวกันถึง 4 ใน 5 วัน · ถ้าแถวจันทร์อยู่ในชุดฝึกและแถวอังคารอยู่ในชุดทดสอบ — คุณเพิ่งบอกคำตอบให้โมเดลไปแล้ว 80%

ทางแก้ 2 ชั้น:

  • Purging — ตัดแถวในชุดฝึกที่ป้ายกำกับทับซ้อนกับช่วงของชุดทดสอบทิ้งไป
  • Embargo — เว้นช่องว่างเพิ่มอีกนิด (เช่น 1% ของข้อมูล) หลังชุดทดสอบ เผื่อผลกระทบที่ลากยาวกว่าที่คิด

กฎง่าย ๆ: ถ้าป้ายกำกับกินเวลา h วัน ต้องเว้นอย่างน้อย h วันระหว่างชุดฝึกกับชุดทดสอบเสมอ

❌ 4. ข้อมูลที่ถูกแก้ย้อนหลัง (survivorship & restatement)

ข้อนี้ไม่ได้อยู่ในโค้ดของคุณเลย มันอยู่ในข้อมูล:

  • Survivorship bias — ดึงรายชื่อหุ้นใน SET50 วันนี้ แล้วย้อนไปดูราคา 10 ปี · บริษัทที่เจ๊งไปแล้วหายไปจากลิสต์หมด · คุณกำลัง backtest บนกลุ่มที่รู้ล่วงหน้าว่ารอด
  • Restatement — งบการเงินถูกแก้ย้อนหลังได้ · ตัวเลขกำไรไตรมาสที่คุณเห็นในฐานข้อมูลวันนี้ อาจไม่ใช่ตัวเลขที่ตลาดเห็นในวันนั้น

ทางแก้: ใช้ฐานข้อมูลแบบ point-in-time ที่เก็บว่า "ณ วันนั้นข้อมูลหน้าตาเป็นยังไง" · ถ้าไม่มี อย่างน้อยรู้ไว้ว่าผลที่ได้เอนไปทางดีเกินจริงเท่าไร และอย่ารายงานมันเป็นตัวเลขจริง

🧮 วิธีจับ leakage ที่ได้ผลที่สุด — และใช้เวลาแค่ 5 นาที

ก่อนเชื่อผลใด ๆ ให้ทำ การทดสอบด้วยป้ายมั่ว (label shuffling):

1. สลับ y แบบสุ่มทิ้งความสัมพันธ์ทั้งหมด → y_shuffled 2. รันกระบวนการทั้งหมดซ้ำ (เลือกฟีเจอร์ · ปรับสเกล · CV) ด้วย y_shuffled 3. ผลที่ได้ ต้อง ออกมาราว ๆ ศูนย์ ถ้ายังได้ผลดีอยู่ → มี leakage แน่นอน (โมเดลกำลังลอกจากที่อื่น)

เหตุผลที่มันได้ผล: คุณเพิ่งทำลายสัญญาณจริงทิ้งไปหมดแล้ว · อะไรก็ตามที่โมเดลยังหาเจอ ต้องมาจากช่องทางที่ไม่ควรมี

12.5 💎 Multiple Testing — ช่องโหว่ที่ทำให้ทุกอย่างข้างบนยังหลอกคุณได้

💎 ถ้าอ่านบทที่ 12 ได้หัวข้อเดียว ให้อ่านหัวข้อนี้

จนถึงตอนนี้เราสอนวิธีตรวจสอบหนึ่งกลยุทธ์ให้ถูกต้อง · แต่ไม่มีใครตรวจกลยุทธ์เดียว

ถึงคุณจะใช้ walk-forward ถูกต้อง 100% ไม่มี leakage เลยสักจุด — มันก็ยังหลอกคุณได้เต็ม ๆ ถ้าคุณลองหลายแบบ · และนี่คือสิ่งที่คุณจะทำจริงในสัปดาห์หน้า

🚶 อ่านเป็นภาษาคนก่อน: ถ้าให้คน 1 คนทายผลเหรียญ 10 ครั้งแล้วถูกหมด นั่นน่าทึ่ง · แต่ถ้าให้คน 1,000 คนทายแล้วมี 1 คนถูกหมด — นั่นคือคณิตศาสตร์ ไม่ใช่ความสามารถ

ตอน tune พารามิเตอร์คุณกำลังเป็นคนจัดการแข่งขันนั้น · lookback 10/20/50/100 (4 แบบ) × threshold 5 ค่า × อินดิเคเตอร์ 4 ตัว × หุ้น 10 ตัว = 2,000 การทดลอง · คุณไม่ได้เรียกมันว่า "การทดลอง" คุณเรียกมันว่า "การหาพารามิเตอร์ที่เหมาะสม" — แต่คณิตศาสตร์ไม่สนใจว่าคุณเรียกมันว่าอะไร

🐍 Python — ลอง 200 กลยุทธ์ที่ไม่มี edge เลยสักตัว แล้วเก็บตัวที่ดีที่สุด
# pip install numpy scipy
import numpy as np
from scipy.stats import norm

rng = np.random.default_rng(2024)
T, N_TRY = 756, 200                             # OOS 3 ปี · ลอง 200 แบบ

sr = []
for _ in range(300):                            # ทำซ้ำ 300 รอบเพื่อดูค่าเฉลี่ย
    pnl = rng.normal(0, 0.01, (N_TRY, T))       # ★ edge จริง = 0 เป๊ะ ทุกตัว
    s = pnl.mean(1)/pnl.std(1)*np.sqrt(252)
    sr.append(s.max())                          # เก็บ "ตัวที่ดีที่สุด" เหมือนที่คุณทำ

sr = np.array(sr)
print(f"Sharpe ของตัวที่ดีที่สุด: เฉลี่ย {sr.mean():.2f} | ช่วง 5-95% [{np.percentile(sr,5):.2f}, {np.percentile(sr,95):.2f}]")
# Sharpe ของตัวที่ดีที่สุด: เฉลี่ย 1.60 | ช่วง 5-95% [1.25, 2.01]
print(f"โอกาสที่มันจะได้ Sharpe > 1.5 = {(sr > 1.5).mean():.1%}")
# โอกาสที่มันจะได้ Sharpe > 1.5 = 62.3%

# ★ สูตรปิด (Bailey & Lopez de Prado) — ไม่ต้องจำลองก็หาได้
g = 0.5772                                      # ค่าคงที่ Euler-Mascheroni
def expected_max(N, years):
    return np.sqrt(1/years)*((1-g)*norm.ppf(1-1/N) + g*norm.ppf(1-1/(N*np.e)))

print("\nเกณฑ์ขั้นต่ำที่ต้องผ่าน (Sharpe ที่ 'ไม่มี edge' ทำได้เอง):")
# เกณฑ์ขั้นต่ำที่ต้องผ่าน (Sharpe ที่ 'ไม่มี edge' ทำได้เอง):
for years in [3, 5, 10]:
    row = "  ".join(f"{expected_max(N, years):.2f}" for N in [10, 50, 200, 1000])
    print(f"  OOS {years:2d} ปี | {row}")
#   OOS  3 ปี | 0.91  1.31  1.60  1.88

⚠️ และสูตรนี้สมมติว่า trials เป็นอิสระกัน · การ tune พารามิเตอร์บนหุ้นตัวเดียวกันสร้าง trials ที่ทับซ้อนกันสูงมาก ทำให้ N ที่มีผลจริงน้อยกว่า N ที่นับได้ · ตารางนี้จึงเป็นเพดานบน — ถ้าอยากได้ตัวเลขที่ตรงกับสถานการณ์คุณ ให้เอา SD ของ Sharpe จาก trials ของคุณเอง มาแทน √(1/ปี) ในสูตร

ย้อนกลับไปดู เล่ม 2 · E §10.1 ที่บอกว่า "Sharpe 1.0–2.0 = ดีมาก" · ถ้าคุณลอง 200 แบบบนข้อมูล 3 ปี คุณจะได้ 1.60 มาโดยไม่มีฝีมือเลยแม้แต่นิดเดียว — และมันจะผ่าน walk-forward ของคุณสบาย ๆ เพราะไม่มี leakage จริง ๆ

สังเกตทิศทางของตาราง: เพิ่มข้อมูลช่วยได้มากกว่าเพิ่มความระมัดระวัง · ที่ 10 ปีกับ 200 แบบ เกณฑ์เหลือ 0.87 · แต่ที่ 3 ปีกับ 1,000 แบบ ต้องเกิน 1.88 ถึงจะเริ่มน่าสนใจ

🧮 ทำยังไง — 3 ข้อที่ทำได้จริงคนเดียว
  1. นับ N ให้ได้ก่อน · เปิดไฟล์ไว้ไฟล์หนึ่ง แล้วจดทุกครั้งที่รัน backtest รวมถึงครั้งที่ "แค่ลองดูเฉย ๆ" · ถ้าจำไม่ได้ว่าลองมากี่แบบ ให้ประมาณจากจำนวนพารามิเตอร์คูณกัน · ตัวเลขนี้คือ N ในตารางข้างบน
  2. เทียบกับเกณฑ์ ไม่ใช่เทียบกับศูนย์ · คำถามที่ถูกไม่ใช่ "Sharpe เป็นบวกไหม" แต่คือ "Sharpe สูงกว่าที่ความบังเอิญทำได้ที่ N ของผมไหม"
  3. แบ่ง lockbox ตั้งแต่วันแรก · แยกข้อมูลก้อนสุดท้ายออกไปก่อนเริ่มทำอะไรทั้งสิ้น แล้วห้ามแตะจนกว่าจะเลือกกลยุทธ์เสร็จ · เปิดได้ 1–2 ครั้งต่อกลยุทธ์หนึ่งตัวเท่านั้น · ถ้าเปิดครั้งที่ 3 แล้วปรับต่อ ชุดนั้นก็กลายเป็นชุดฝึกไปแล้ว

และวิธีที่ซื่อสัตย์ที่สุดสำหรับคนที่ไม่มีทีม — paper trade ไปข้างหน้า 3–6 เดือน · นั่นคือชุดทดสอบเดียวที่คุณโกงไม่ได้ เพราะมันยังไม่เกิดตอนที่คุณเลือกกลยุทธ์

✍️ ลองทำเอง

คุณลอง lookback 4 ค่า × threshold 5 ค่า × หุ้น 10 ตัว บนข้อมูล 5 ปี แล้วตัวที่ดีที่สุดได้ Sharpe 1.15 · ควรลงเงินไหม?

ดูเฉลย

N = 4 × 5 × 10 = 200 การทดลอง · เปิดตาราง แถว 5 ปี คอลัมน์ 200 แบบ → เกณฑ์คือ 1.24

Sharpe 1.15 ของคุณ ต่ำกว่าค่าเฉลี่ยที่ความบังเอิญทำได้ (1.24) ด้วยซ้ำ · แปลว่าผลนี้อธิบายได้หมดด้วยการที่คุณลองเยอะ โดยไม่ต้องสมมติว่ามี edge อยู่เลย → ไม่ควรลงเงิน

และจำกล่อง ❌ ข้างบนไว้ — ต่อให้คุณได้ 1.30 ซึ่ง "ผ่าน" 1.24 ก็ยังไม่พอ เพราะ 1.24 เป็นแค่ค่าเฉลี่ยของ noise · เส้นที่ควรใช้จริงอยู่สูงกว่านั้นพอสมควร

⚠️ และระวังกับดักที่ตามมาทันที: อย่าเพิ่งไปลองเพิ่มอีก 50 แบบเพื่อหาตัวที่ผ่าน 1.24 — นั่นทำให้ N กลายเป็น 250 และเกณฑ์ขยับสูงขึ้นตาม · คุณวิ่งไล่เส้นที่ขยับหนีคุณเสมอ

สิ่งที่ควรทำแทนคือลด N: ตัดสินใจจากเหตุผลเชิงเศรษฐกิจว่าทำไม lookback ควรเป็นค่านี้ และทำไมหุ้นกลุ่มนี้ถึงควรมีพฤติกรรมแบบนั้น ก่อนรัน backtest · การทดลอง 3 แบบที่มีเหตุผลรองรับ มีค่ามากกว่า 200 แบบที่กราดหา

12.6 ต้นทุนซื้อขายต้องอยู่ใน CV ไม่ใช่หักทีหลัง

🚶 อ่านเป็นภาษาคนก่อน: ตลอดบทนี้เราวัดคุณภาพด้วย R² ซึ่งไม่รู้จักค่าคอมมิชชันเลย · คนส่วนใหญ่คิดว่า "เดี๋ยวค่อยหักต้นทุนตอนท้าย" · แต่ต้นทุนไม่ได้แค่ลดกำไร มันเปลี่ยนอันดับของกลยุทธ์

เพราะกลยุทธ์ที่ R² สูงสุดมักเป็นกลยุทธ์ที่ซื้อขายถี่ที่สุด · ถ้าคุณใช้ CV เลือกกลยุทธ์โดยดู R² อย่างเดียว คุณกำลังคัดเลือกตัวที่แย่ที่สุดในเงินจริงอย่างเป็นระบบ

🐍 Python — ต้นทุนจริงของรายย่อยไทย กินกลยุทธ์ Sharpe 1.5 ได้แค่ไหน
# pip install numpy
import numpy as np

comm   = 0.00157*1.07                           # ค่าคอมฯ 0.157% + VAT 7%
spread = 0.0010                                 # bid-ask ของหุ้น SET50
rt     = 2*comm + spread                        # ต้นทุนไป-กลับหนึ่งรอบ
print(f"ต้นทุนต่อรอบ = {rt:.3%}")
# ต้นทุนต่อรอบ = 0.436%

sr_gross, vol = 1.5, 0.15                       # กลยุทธ์ที่ backtest บอกว่า Sharpe 1.5
ret = sr_gross*vol
for name, turns in [("รายวัน",252), ("รายสัปดาห์",52), ("รายเดือน",12)]:
    net = ret - turns*rt
    print(f"  {name:10s} หมุน {turns:3d} ครั้ง/ปี | ต้นทุน {turns*rt:6.1%} | net {net:+7.1%} | Sharpe {net/vol:+.2f}")
#   รายวัน     หมุน 252 ครั้ง/ปี | ต้นทุน 109.9% | net  -87.4% | Sharpe -5.82
#   รายสัปดาห์ หมุน  52 ครั้ง/ปี | ต้นทุน  22.7% | net   -0.2% | Sharpe -0.01
#   รายเดือน   หมุน  12 ครั้ง/ปี | ต้นทุน   5.2% | net  +17.3% | Sharpe +1.15
print(f"จุดคุ้มทุน: หมุนได้ {ret/rt:.0f} ครั้ง/ปี ก่อน edge หมดเกลี้ยง")
# จุดคุ้มทุน: หมุนได้ 52 ครั้ง/ปี ก่อน edge หมดเกลี้ยง
❌ กลยุทธ์เดียวกันเป๊ะ — เปลี่ยนแค่ความถี่ ผลต่างกันคนละโลก

Sharpe 1.5 ที่รีบาลานซ์รายวัน กลายเป็น −5.82 · รายสัปดาห์เหลือ −0.01 คือแทบไม่เหลืออะไร · ต้องถอยมาถึงรายเดือนถึงจะเหลือ +1.15

ตัวเลขที่ควรจำ: งบต้นทุนของคุณคือประมาณ 0.44% ต่อรอบ → หมุนพอร์ตได้ราว 50 ครั้ง/ปี ก่อนที่ edge ระดับ Sharpe 1.5 จะหมดเกลี้ยง · ถ้าเป็นหุ้นนอก SET50 ที่ spread กว้าง 0.25% เพดานเหลือ 38 ครั้ง/ปี

ทำยังไง: ให้ทุก fold ของ walk-forward คืนค่าเป็น Sharpe หลังหักต้นทุน ไม่ใช่ R² · ถ้าทำแบบนั้นตั้งแต่แรก CV จะเลือกกลยุทธ์ที่หมุนช้าลงให้คุณเอง โดยที่คุณไม่ต้องตัดสินใจเรื่องนี้ด้วยมือ

พิสูจน์ด้วยตัวเลข

สร้างตลาด sideways ที่คุณสมบัติทุกอย่างเหมือนกันหมด ยกเว้นความผันผวน แล้วปล่อยกฎ Bollinger ตัวเดิมลงไป · ถ้าสัญญาณ "มองเห็น" ความผันผวนจริง จำนวนไม้ต้องลดลงเมื่อตลาดนิ่ง:

🐍 Python — กฎเดิม ตลาดเดิม เปลี่ยนแค่ σ
# pip install numpy
import numpy as np

def ou_price(sigma, n=120_000, theta=0.05, seed=7):
    """ราคาที่ถูกดึงกลับเข้าหาค่ากลางเสมอ = ตลาด sideways ในอุดมคติ"""
    rng = np.random.default_rng(seed)
    e = rng.standard_normal(n)
    x = np.empty(n); x[0] = 0.0
    for t in range(1, n):
        x[t] = (1 - theta)*x[t-1] + sigma*e[t]      # sigma คุมความกว้างของการแกว่ง
    return 100.0*np.exp(x)

def bollinger(p, N=20, k=2.0):
    c1 = np.cumsum(np.insert(p, 0, 0.0)); c2 = np.cumsum(np.insert(p*p, 0, 0.0))
    m  = (c1[N:] - c1[:-N])/N                       # เส้นกลาง
    sd = np.sqrt(np.maximum((c2[N:] - c2[:-N])/N - m*m, 0.0))
    inpos, entry, g = False, 0.0, []
    for i in range(len(m)):
        t = i + N - 1
        if not inpos and p[t] < m[i] - k*sd[i]:
            inpos, entry = True, p[t]               # หลุดกรอบล่าง -2SD -> เข้า
        elif inpos and p[t] > m[i]:
            g.append(p[t]/entry - 1.0); inpos = False   # กลับถึงเส้นกลาง -> ออก
    return np.array(g), float(np.mean(2*k*sd/m))    # กำไรก่อนต้นทุน, BBW เฉลี่ย

COST = 0.00436                                      # ต้นทุนไป-กลับ จาก 12.6
print("sigma/day   BBW    trades   gross/tr    net/tr   gross/BBW")
for sigma in [0.001, 0.002, 0.003, 0.006, 0.012]:
    g, bbw = bollinger(ou_price(sigma))
    print(f"{sigma:8.1%} {bbw:7.2%} {len(g):8d} {g.mean():10.4%} "
          f"{g.mean()-COST:+9.4%} {g.mean()/bbw:10.3f}")
# sigma/day   BBW    trades   gross/tr    net/tr   gross/BBW
#     0.1%   0.62%     2475    0.1307%  -0.3053%      0.209
#     0.2%   1.25%     2466    0.2617%  -0.1743%      0.210
#     0.3%   1.87%     2463    0.3948%  -0.0412%      0.211
#     0.6%   3.74%     2448    0.7994%  +0.3634%      0.214
#     1.2%   7.49%     2412    1.6265%  +1.1905%      0.217

print("\nแล้ว 0.21 นี้เป็นค่าคงที่ของจักรวาลหรือเปล่า? ลองเปลี่ยนความเร็วการดึงกลับ:")
for theta in [0.02, 0.05, 0.10]:
    caps = [bollinger(ou_price(s, theta=theta))[0].mean() /
            bollinger(ou_price(s, theta=theta))[1] for s in [0.001, 0.003, 0.012]]
    cap = float(np.mean(caps))
    print(f"  theta={theta:.2f} -> capture {cap:.3f} -> BBW ขั้นต่ำ {COST/cap:.2%}")
# แล้ว 0.21 นี้เป็นค่าคงที่ของจักรวาลหรือเปล่า? ลองเปลี่ยนความเร็วการดึงกลับ:
#   theta=0.02 -> capture 0.102 -> BBW ขั้นต่ำ 4.29%
#   theta=0.05 -> capture 0.213 -> BBW ขั้นต่ำ 2.05%

OU = Ornstein-Uhlenbeck คือ AR(1) เวอร์ชันเวลาต่อเนื่อง dx = θ(μ − x)dt + σdW — หนังยางที่ดึงราคากลับหาค่ากลาง · ตารางแปลงระหว่างสองภาษาอยู่ที่ เล่ม 2 · D §8.4½ · ที่ใช้ตัวนี้เพราะมันคือนิยามทางคณิตศาสตร์ของ "ตลาด sideways" — มีจุดยึดจริง ไม่ใช่ราคาที่ลอยไปเรื่อย

บรรทัด x[t] = (1 - theta)*x[t-1] + sigma*e[t] คือ Euler-Maruyama ที่ Δt = 1 ไม่ใช่การเดินแบบเป๊ะ · ผลคือความผันผวนที่ได้สูงเกินไปด้วยตัวคูณ √( 2θ ÷ (1 − (1−θΔt)²) ) ซึ่งที่ θ = 0.05 คือ +1.27%

ทำไมข้อสรุปทั้งหัวข้อยังใช้ได้: ตัวเลขที่เราสรุปคือ capture ratio = gross ÷ BBW ซึ่งเป็นอัตราส่วน — ความผันผวนที่เพี้ยนไปปรากฏทั้งเศษและส่วนแล้วตัดกันหมด · ส่วนเกณฑ์ BBW ก็คิดจาก capture ตัวเดียวกัน จึงไม่กระทบเช่นกัน

BBW (Bollinger Band Width) = (แถบบน − แถบล่าง) ÷ เส้นกลาง — เป็น % ของราคา จึงมีหน่วยเทียบกับต้นทุนได้ตรง ๆ · นี่คือตัวเลขที่ตาคุณมองเห็นอยู่แล้วตอนที่คุณตัดสินใจ "ไม่เข้าเพราะกรอบมันแคบ" — เราแค่เขียนมันเป็นสมการ

# pip install numpy
import numpy as np

def ou_price(sigma, n=120_000, theta=0.05, seed=7):     # เหมือนกล่องก่อนหน้า
    rng = np.random.default_rng(seed); e = rng.standard_normal(n)
    x = np.empty(n); x[0] = 0.0
    for t in range(1, n):
        x[t] = (1 - theta)*x[t-1] + sigma*e[t]
    return 100.0*np.exp(x)

def rsi(p, n=14):
    d  = np.diff(p, prepend=p[0])
    up = np.where(d > 0, d, 0.0); dn = np.where(d < 0, -d, 0.0)
    au = np.zeros_like(p); ad = np.zeros_like(p)
    au[n] = up[1:n+1].mean(); ad[n] = dn[1:n+1].mean()
    for t in range(n+1, len(p)):                        # Wilder smoothing
        au[t] = (au[t-1]*(n-1) + up[t])/n
        ad[t] = (ad[t-1]*(n-1) + dn[t])/n
    r = np.full_like(p, 50.0); ok = ad > 0
    r[ok] = 100 - 100/(1 + au[ok]/ad[ok]); r[:n+1] = 50.0
    return r                                            # หารกำไรด้วยขาดทุน -> ไร้หน่วย

def stoch(p, n=14):
    w = np.lib.stride_tricks.sliding_window_view(p, n)
    lo, hi = w.min(1), w.max(1)
    k = np.full_like(p, 50.0)
    k[n-1:] = np.where(hi > lo, 100*(p[n-1:] - lo)/np.maximum(hi - lo, 1e-12), 50.0)
    return k                                            # หารด้วยพิสัยตัวเอง -> ไร้หน่วย

def run(p, sig, lo, mid, warm=20):
    inpos, entry, g = False, 0.0, []
    for t in range(warm, len(p)):
        if not inpos and sig[t] < lo:  inpos, entry = True, p[t]
        elif inpos and sig[t] > mid:   g.append(p[t]/entry - 1.0); inpos = False
    return np.array(g)

# pip install numpy
import numpy as np

def sv_price(n=400_000, theta=0.05, s0=0.004, phi=0.97, eta=0.15, seed=11):
    """ราคาที่ความผันผวนเองก็แกว่ง — มีทั้งช่วงบีบแคบและช่วงเหวี่ยงแรง"""
    rng = np.random.default_rng(seed)
    e, w = rng.standard_normal(n), rng.standard_normal(n)
    v = np.empty(n); x = np.empty(n); v[0] = x[0] = 0.0
    for t in range(1, n):
        v[t] = phi*v[t-1] + eta*w[t]                    # log-vol เดินแบบ AR(1)
        x[t] = (1 - theta)*x[t-1] + s0*np.exp(v[t])*e[t]
    return 100.0*np.exp(x)

def bb_trades(p, N=20, k=2.0):
    c1 = np.cumsum(np.insert(p, 0, 0.0)); c2 = np.cumsum(np.insert(p*p, 0, 0.0))
    m  = (c1[N:] - c1[:-N])/N
    sd = np.sqrt(np.maximum((c2[N:] - c2[:-N])/N - m*m, 0.0))
    bbw = 2*k*sd/m
    inpos, entry, w0, out = False, 0.0, 0.0, []
    for i in range(len(m)):
        t = i + N - 1
        if not inpos and p[t] < m[i] - k*sd[i]:
            inpos, entry, w0 = True, p[t], bbw[i]       # จำ BBW "ตอนเข้า" ไว้ด้วย
        elif inpos and p[t] > m[i]:
            out.append((w0, p[t]/entry - 1.0)); inpos = False
    return np.array(out)

  • ราคาล่วงหน้า / basis — สัญญาณของเกมนี้คือ อัตราต้นทุนถือครองสุทธิที่ตลาดคิดให้ (r − q ที่ implied ออกมา) rimp = ln(F/S) ÷ T ซึ่งเป็น % ต่อปี แต่เงินที่ได้จริงคือ S × Δr × T — มี T คูณอยู่ · แปลว่า dislocation ขนาดเท่ากันยิ่งใกล้หมดอายุยิ่งไม่มีค่า: ที่ต้นทุนไป-กลับ 0.20% เหลืออายุ 3 เดือนต้องเพี้ยน 80 bp แต่เหลือ 1 สัปดาห์ต้องเพี้ยนถึง 1,008 bp · ด่านที่สองคือ Δr × T × S ≥ ต้นทุนไป-กลับ ไม่ใช่ค่า z (สูตร F ดูที่ Part I §3.8)
  • §12.5 — deflated Sharpe ตอบว่า "เก่งจริงหรือฟลุก" · §12.6 ตอบว่า "ถี่เกินไปไหม" · §12.7 นี้ตอบว่า "ใหญ่พอไหม" — สามคำถามคนละคำถาม ต้องผ่านให้ครบทั้งสาม

บทที่ 13 — Bootstrap: ช่วงความเชื่อมั่นที่ไม่ต้องสมมติอะไรเลย

13.1 แนวคิด — ถ้าไม่มีจักรวาลคู่ขนาน ก็สร้างเอง

Bootstrap Efron 1979 ★★★ ต้องรู้จัก

🎯 Thesis

"ความไม่แน่นอนเกิดจากการที่เรามีข้อมูลแค่ตัวอย่างเดียวจากความจริง · ถ้าเก็บข้อมูลใหม่ไม่ได้ ก็สุ่มหยิบซ้ำจากตัวอย่างที่มี แล้วดูว่าคำตอบเหวี่ยงแค่ไหน — ง่ายจนน่าตกใจ และใช้ได้กับสถิติแทบทุกตัว"

🚶 อ่านเป็นภาษาคนก่อน: ใน เล่ม 2 · C §6.4 เราได้ช่วงความเชื่อมั่นของ β มาจากสูตร — และสูตรนั้นตั้งอยู่บนสมมติฐานหลายข้อ (residual เป็น Normal · ความแปรปรวนคงที่ · ฯลฯ) ที่ บทที่ 7 เพิ่งพิสูจน์ว่าข้อมูลการเงินละเมิดแทบทุกข้อ

bootstrap ตอบคำถามเดียวกันโดยไม่ใช้สูตรเลย · แนวคิดคือ: ถ้าเราเก็บข้อมูลใหม่ได้ 1,000 ครั้ง เราจะเห็นเลยว่าคำตอบเหวี่ยงแค่ไหน · เราเก็บใหม่ไม่ได้ — แต่เราสุ่มหยิบจากที่มีอยู่แบบใส่คืนได้

ทำซ้ำ B ครั้ง (นิยม B = 1,000–10,000): 1. สุ่มหยิบข้อมูล n จุด จากข้อมูลเดิม แบบใส่คืน (บางจุดถูกหยิบซ้ำ บางจุดไม่ถูกหยิบเลย) 2. คำนวณสิ่งที่สนใจ (Sharpe · β · ค่ามัธยฐาน · อะไรก็ได้) ช่วงความเชื่อมั่น 95% = เปอร์เซ็นไทล์ที่ 2.5 และ 97.5 ของค่าที่ได้ทั้ง B ค่า
✅ ทำไมมันถึงทรงพลัง
  • ใช้ได้กับสถิติที่ไม่มีสูตร — ค่ามัธยฐาน · max drawdown · อัตราส่วนแปลก ๆ ที่คุณคิดเอง · ตัวไหนที่คำนวณได้ ก็ bootstrap ได้
  • ไม่ต้องสมมติการแจกแจง — ข้อมูลหางหนาหรือเบ้แค่ไหนก็ใช้ได้ เพราะมันสุ่มจากรูปร่างจริงของข้อมูล
  • ช่วงที่ได้ไม่จำเป็นต้องสมมาตร — ซึ่งตรงกับความจริงมากกว่า "±1.96 SE" ที่บังคับให้สมมาตรเสมอ

13.2 ทดสอบกับของจริง — CI ของ Sharpe

🚶 อ่านเป็นภาษาคนก่อน: ก่อนจะเชื่อเครื่องมือใหม่ ต้องเอาไปแข่งกับเครื่องมือที่เรารู้อยู่แล้วว่าถูก ในสนามที่เครื่องมือเก่าใช้ได้ · ถ้ามันให้คำตอบตรงกัน เราถึงจะกล้าใช้มันในสนามที่ไม่มีสูตรให้เทียบ

ใน เล่ม 2 · E §10.1 เราใช้สูตรหา CI ของ Sharpe · ลองให้ bootstrap ตอบคำถามเดียวกัน แล้วดูว่าตรงกันไหม — ถ้าตรง แปลว่าเราเชื่อ bootstrap ในกรณีที่ไม่มีสูตรได้

🐍 Python — bootstrap หา CI ของ Sharpe แล้วเทียบกับสูตร
# pip install numpy
import numpy as np

rng = np.random.default_rng(21)
n  = 756                                        # ข้อมูล 3 ปี
sd = 0.15/np.sqrt(252)
mu = 1.0/np.sqrt(252) * sd                      # Sharpe จริง = 1.0
r  = rng.normal(mu, sd, n)

def sharpe(x): return x.mean()/x.std()*np.sqrt(252)

obs = sharpe(r)
print(f"Sharpe ที่วัดได้จากข้อมูลชุดนี้ = {obs:.3f}")
# Sharpe ที่วัดได้จากข้อมูลชุดนี้ = 1.581

# ★ bootstrap: สุ่มหยิบ n จุดแบบใส่คืน 10,000 รอบ
boot = np.array([sharpe(r[rng.integers(0, n, n)]) for _ in range(10_000)])
lo, hi = np.percentile(boot, [2.5, 97.5])
print(f"bootstrap 95% CI = [{lo:.2f}, {hi:.2f}]")
# bootstrap 95% CI = [0.42, 2.73]

# เทียบกับสูตรจาก เล่ม 2 E §10.1  ·  SE = sqrt((1 + SR^2/504) / T)
se = np.sqrt((1 + obs**2/504)/(n/252))          # 504 = 2 x 252
print(f"สูตรวิเคราะห์  95% CI = [{obs-1.96*se:.2f}, {obs+1.96*se:.2f}]")
# สูตรวิเคราะห์  95% CI = [0.45, 2.71]
✅ อ่านผลลัพธ์ — สองวิธีที่ไม่เกี่ยวกันเลย ให้คำตอบเดียวกัน

bootstrap [0.42, 2.73] · สูตร [0.45, 2.71] — ต่างกันไม่ถึง 0.03 ทั้งสองปลาย

นี่คือการตรวจสอบไขว้ที่มีค่ามาก · bootstrap ไม่รู้จักสูตรของ Lo และสูตรก็ไม่รู้จัก bootstrap · เมื่อทั้งคู่มาบรรจบกัน เรามั่นใจได้ทั้งสองทาง

และสังเกตประเด็นเดิมจาก §10.1: Sharpe จริงคือ 1.0 แต่ข้อมูล 3 ปีนี้บังเอิญวัดได้ 1.581 · ช่วงความเชื่อมั่นกว้างตั้งแต่ 0.42 ถึง 2.73 — ข้อมูล 3 ปีบอกอะไรได้น้อยมาก

💎 คุณค่าที่แท้จริงของ bootstrap: ตอนนี้คุณหา CI ของ max drawdown · Sortino · ครึ่งชีวิตของ spread · หรือ อัตราชนะ ได้ทันทีด้วยโค้ดแบบเดียวกันเป๊ะ — ซึ่งไม่มีสูตรสำเร็จให้ใช้เลยสักตัว

13.3 ❌ กับดักใหญ่ — bootstrap ธรรมดาทำลายลำดับเวลา

🚶 อ่านเป็นภาษาคนก่อน: "ก้อน" (block) คือการหยิบผลตอบแทน 21 วันที่ติดกันมาทั้งแผง แทนที่จะหยิบทีละวันแล้วเอามาปะติดปะต่อ · เหตุผลคือวันที่อยู่ติดกันมันเกี่ยวข้องกัน — ถ้าหยิบทีละวันแบบสุ่ม คุณกำลังทำลายความเกี่ยวข้องนั้นทิ้ง แล้วสร้างประวัติปลอมที่ "สงบ" กว่าของจริง

❌ การหยิบแบบสุ่มทีละจุด = สมมติว่าข้อมูลเป็นอิสระต่อกัน

ทุกครั้งที่คุณสุ่มหยิบทีละจุด คุณกำลังบอกว่า "ลำดับไม่สำคัญ" · แต่ผลตอบแทนสินทรัพย์ไม่เป็นอิสระ — มี momentum · mean reversion · volatility clustering (Part IV)

ผลคือ bootstrap ธรรมดาจะประเมินความไม่แน่นอนต่ำเกินไป เมื่อ autocorrelation เป็นบวก (momentum · volatility clustering) ซึ่งเป็นทิศทางที่อันตราย เพราะทำให้คุณมั่นใจเกินจริง

🔧 แต่ทิศทางกลับด้านได้ ถ้าข้อมูลเป็น mean reversion

mean reversion = autocorrelation ติดลบ · ผมรันโค้ดเดียวกันเปลี่ยนแค่เครื่องหมายของ φ:

φiid bootstrapblock (L=21)ความจริงiid ผิดทางไหน

สังเกตว่า iid ให้ 2.29 เท่ากันทั้งสองกรณี — เพราะมันมองไม่เห็นลำดับเลย · ส่วนความจริงต่างกันคนละโลก (3.29 vs 1.57)

💎 ข้อสรุปที่ปลอดภัยกว่า: iid bootstrap ผิดเสมอเมื่อข้อมูลมีความจำ — ทิศทางขึ้นกับเครื่องหมายของ ACF · ส่วน block bootstrap ต่ำกว่าความจริงทั้งสองทิศ (2.62 < 3.29 และ 1.33 < 1.57) จึงใช้เป็น "ขอบล่าง" ได้จริง

ทางแก้: block bootstrap — แทนที่จะหยิบทีละจุด ให้หยิบทีละ "ก้อน" ที่ต่อเนื่องกัน (เช่นก้อนละ 21 วัน = 1 เดือนทำการ) · โครงสร้างภายในก้อนจึงถูกรักษาไว้

🐍 Python — iid vs block bootstrap เทียบกับความจริง
# pip install numpy
import numpy as np

rng = np.random.default_rng(11)
n, phi = 756, 0.35
e = rng.normal(0, 0.01, n)
r = np.zeros(n)
for t in range(1, n):
    r[t] = phi*r[t-1] + e[t]                    # ★ นี่คือ AR(1) จาก เล่ม 2 D §8.4 — ผลตอบแทนมี momentum
r = r + 0.0004

def sharpe(x): return x.mean()/x.std()*np.sqrt(252)
print(f"ACF lag1 = {np.corrcoef(r[:-1], r[1:])[0,1]:.3f} | Sharpe = {sharpe(r):.3f}")
# ACF lag1 = 0.299 | Sharpe = 1.206

B = 8000
iid = np.array([sharpe(r[rng.integers(0, n, n)]) for _ in range(B)])

def block(x, L, seed=0):                         # ★ หยิบทีละก้อน L วัน
    g  = np.random.default_rng(seed)             # ★ seed ของตัวเอง — เรียกกี่ครั้งก็ได้ผลเดิม
    nb = int(np.ceil(len(x)/L))
    return np.array([sharpe(np.concatenate(
        [x[s:s+L] for s in g.integers(0, len(x)-L+1, nb)])[:len(x)]) for _ in range(B)])

for name, a in [("iid bootstrap", iid), ("block bootstrap L=21", block(r, 21))]:
    lo, hi = np.percentile(a, [2.5, 97.5])
    print(f"{name:22s} CI [{lo:+.2f}, {hi:+.2f}]  กว้าง {hi-lo:.2f}")
# iid bootstrap          CI [+0.06, +2.36]  กว้าง 2.30
# block bootstrap L=21   CI [-0.09, +2.51]  กว้าง 2.60

block bootstrap ดีขึ้นจริง แต่ยังไม่พอ — และผมจะไม่บอกว่ามันแก้ปัญหาได้ เพราะมันไม่ได้แก้

สังเกตจุดที่สำคัญที่สุด: ปลายล่างของช่วงความจริงคือ −1.07 แต่ iid bootstrap บอก +0.06 · แปลว่า iid bootstrap จะทำให้คุณสรุปว่า "Sharpe เป็นบวกแน่นอน" ทั้งที่ความจริงติดลบได้สบาย ๆ

💎 สิ่งที่ต้องเอากลับไป: block bootstrap ประเมินความไม่แน่นอนต่ำกว่าความจริงเมื่อข้อมูลมีความจำ (ส่วน iid ผิดได้ทั้งสองทิศ) · ถือว่าช่วงที่ได้เป็นขอบล่างของความไม่แน่นอน ไม่ใช่ค่าจริง · และ ยิ่งข้อมูลมี autocorrelation สูง ยิ่งต้องเผื่อมากขึ้น

ในทางคณิตศาสตร์มันคือสิ่งเดียวกันเป๊ะ — ที่ตัวเลขต่างกันในหลักที่สองเป็นเพราะโค้ดสองบรรทัดนี้ใช้ RNG คนละสาย (iid ใช้ rng ที่เดินมาไกลแล้ว ส่วน block สร้าง default_rng(0) ใหม่) · ถ้าป้อน generator ตัวเดียวกันให้ทั้งคู่ จะได้ตัวเลขตรงกันทุกหลัก

💎 และนั่นคือบทเรียนที่แท้จริงของข้อนี้: ตัวเลข bootstrap ที่ต่างกันในหลักที่สอง มักเป็นแค่ seed ไม่ใช่วิธี · ก่อนจะสรุปว่า "วิธี A ดีกว่าวิธี B" ให้เพิ่ม B (จำนวนรอบ) แล้วดูว่าความต่างนั้นหายไปไหม — ถ้าหาย แปลว่าคุณกำลังตีความ noise

จำไว้ว่า np.random.integers ไม่รวมขอบบน ต่างจาก random.randint ของ Python ที่รวม · นี่คือบั๊กที่ไม่เคยทำให้โปรแกรม error แต่ทำให้ตัวเลขเพี้ยนเงียบ ๆ และยิ่งข้อมูลสั้นยิ่งเพี้ยนมาก

(2) ไม่ใช่ — มีจุดที่ดีที่สุดอยู่ตรงกลาง · L=63 ให้ CI [+0.34, +2.24] กว้างแค่ 1.90 ซึ่งแคบลงจาก L=21 (2.60) อย่างชัดเจน — แย่ลง ไม่ใช่ดีขึ้น · นี่คือการแลกเปลี่ยนคลาสสิก:

13.4 ❌ ข้อจำกัดที่ใหญ่ที่สุดของ bootstrap — และมันตรงกับผู้อ่านหนังสือเล่มนี้พอดี

🚶 อ่านเป็นภาษาคนก่อน: ถ้าคุณสำรวจความเห็นคนในห้องเดียว แล้วสุ่มหยิบชื่อจากห้องนั้นซ้ำไปมาหมื่นรอบ — คุณจะได้ช่วงความเชื่อมั่นที่แม่นมากสำหรับห้องนั้น · แต่ถ้าคนที่คิดต่างอยู่นอกห้อง คุณจะไม่มีวันเจอเขาเลยสักรอบ

bootstrap ทำงานแบบนั้นเป๊ะ — และ "คนนอกห้อง" ในตลาดการเงินคือวันที่ตลาดพัง ซึ่งอาจยังไม่เกิดในข้อมูลของคุณ

❌ "ไม่ต้องสมมติการแจกแจง" ไม่ได้แปลว่า "รู้ทุกอย่างเกี่ยวกับการแจกแจง"

ใน §13.1 ผมเขียนว่า bootstrap ใช้ได้กับข้อมูลหางหนา "เพราะมันสุ่มจากรูปร่างจริงของข้อมูล" · ประโยคนั้นถูก แต่ต้องอ่านให้ครบ:

bootstrap สุ่มจากรูปร่างของตัวอย่าง ไม่ใช่รูปร่างของความจริง · ถ้าเหตุการณ์หายนะยังไม่เคยเกิดในข้อมูล 3 ปีของคุณ มันจะไม่โผล่ใน bootstrap แม้แต่รอบเดียวจาก 10,000 รอบ — เพราะไม่มีอะไรให้หยิบ

และนี่คือโปรไฟล์ของการขายออปชัน ซึ่งเป็นสิ่งที่หนังสือเล่มนี้ทั้งเล่มพูดถึง: ได้เบี้ยเล็ก ๆ เกือบทุกวัน แล้วเจ็บหนักนาน ๆ ครั้ง

🐍 Python — กลยุทธ์ขายออปชันที่ bootstrap บอกว่า "กำไรแน่นอน"
# pip install numpy
import numpy as np

rng = np.random.default_rng(7)
T, p_jump = 756, 1/504                          # 3 ปี · jump เฉลี่ย 1 ครั้งทุก 2 ปี
def sharpe(x): return x.mean()/x.std()*np.sqrt(252)
def path(g):
    r = np.full(T, 0.0006) + g.normal(0, 0.0015, T)   # เก็บเบี้ยเล็ก ๆ ทุกวัน
    j = g.random(T) < p_jump
    r[j] -= g.uniform(0.12, 0.30, j.sum())            # ★ วันที่ระเบิด
    return r

clean = sum(not (path(rng) < -0.05).any() for _ in range(500))
print(f"P(ข้อมูล 3 ปี ไม่เจอ jump เลย) = {clean/500:.0%}")
# P(ข้อมูล 3 ปี ไม่เจอ jump เลย) = 23%

# ★ หยิบตัวอย่างที่ 'โชคดี' มาหนึ่งชุด แล้วให้ bootstrap ตัดสิน
g = np.random.default_rng(11)
while True:
    r = path(g)
    if not (r < -0.05).any(): break
print(f"ตัวอย่างที่ 'สะอาด': Sharpe = {sharpe(r):+.2f}")
# ตัวอย่างที่ 'สะอาด': Sharpe = +6.93
b = np.array([sharpe(r[g.integers(0, T, T)]) for _ in range(4000)])
print(f"  bootstrap CI = [{np.percentile(b,2.5):+.2f}, {np.percentile(b,97.5):+.2f}]")
#   bootstrap CI = [+5.72, +8.17]
long = np.concatenate([path(np.random.default_rng(3+i)) for i in range(20)])
print(f"ความจริงระยะยาว 60 ปี: Sharpe = {sharpe(long):+.2f}")
# ความจริงระยะยาว 60 ปี: Sharpe = +0.42

ช่วงความเชื่อมั่นไม่ได้แค่ผิด — มันไม่ครอบคลุมค่าจริงเลยแม้แต่นิดเดียว · ปลายล่างสุดของช่วง (+5.72) ยังสูงกว่าความจริงถึง 13 เท่า · และ bootstrap รายงานมันด้วยความมั่นใจเต็มร้อย เพราะจากมุมของมัน ข้อมูลไม่มีวันแย่เลยสักวัน

และ block bootstrap จาก §13.3 ไม่ช่วยอะไรเลยในกรณีนี้ — ผมลองแล้วได้ [+5.66, +8.21] ซึ่งแทบเหมือนเดิม · เพราะปัญหาไม่ใช่ "ความจำของข้อมูล" แต่คือเหตุการณ์ที่ยังไม่เกิด ซึ่งไม่มีวิธี resampling ใดแก้ได้ตามนิยาม

สังเกตว่านี่เป็นคนละเรื่องกับ §13.3 โดยสิ้นเชิง และใหญ่กว่ามาก: §13.3 ทำให้ผิดไป 21–30% · ข้อนี้ทำให้ผิดไป 16 เท่า

14.1 ปัญหาที่ค้างมาจาก §6.6 — เมื่อ OLS ให้คำตอบที่ผิดเครื่องหมาย

🚶 อ่านเป็นภาษาคนก่อน: เล่ม 2 · C §6.6 แสดงให้เห็นว่าเมื่อตัวแปรสองตัวเกือบเป็นตัวเดียวกัน (VIF สูง — VIF คือตัวเลขบอกว่า "ตัวแปรนี้ถูกตัวแปรอื่นอธิบายไปแล้วแค่ไหน" · 1 = อิสระสนิท · เกิน 10 = เริ่มมีปัญหา) β ของทั้งคู่จะเหวี่ยงมั่ว · ตอนนั้นเราบอกว่า "อย่าเพิ่งตัดทิ้ง" แต่ยังไม่ได้บอกว่าแล้วทำอะไรแทน · หัวข้อนี้คือคำตอบนั้น

X    = np.column_stack([mkt, val, size])     # X ชุดนี้เป็น N(0,1) อยู่แล้วจึงข้าม scaler ได้ — ข้อมูลจริงห้ามข้าม ดู §14.5

beta_true = np.array([0.8, 0.4, 0.3])    # ★ คำตอบจริงที่เรารู้
y = X @ beta_true + rng.normal(0, 1.0, n)

Xc = sm.add_constant(X)
print("VIF:", [round(float(vif(Xc, i)), 1) for i in range(1, 4)])
# VIF: [113.3, 113.3, 1.0]

print("จริง        ", np.round(beta_true, 3))
# จริง         [0.8 0.4 0.3]
print("OLS         ", np.round(LinearRegression().fit(X, y).coef_, 3))
# OLS          [-0.199  1.436  0.268]
print("Ridge (a=10)", np.round(Ridge(alpha=10).fit(X, y).coef_, 3))
# Ridge (a=10) [0.528 0.695 0.256]
print("Lasso(a=.05)", np.round(Lasso(alpha=0.05).fit(X, y).coef_, 3))
# Lasso(a=.05) [0.    1.187 0.218]
❌ ดูบรรทัด OLS ให้ดี — มันไม่ได้แค่ "ไม่แม่น" มันบอกผิดเรื่อง

ค่าจริงของ market คือ +0.8 · OLS ตอบ −0.199

ผิดเครื่องหมาย · ถ้าคุณอ่านผลนี้ตามตรง คุณจะสรุปว่า "ตลาดขึ้นแล้วหุ้นตัวนี้ลง" ซึ่งตรงข้ามกับความจริงโดยสิ้นเชิง · และ value ที่ควรเป็น 0.4 ก็พองเป็น 1.436 เพื่อชดเชย

นี่ไม่ใช่ความบังเอิญของ seed นี้ — มันคืออาการมาตรฐานของ multicollinearity · เมื่อตัวแปรสองตัวเล่าเรื่องเดียวกัน OLS ไม่มีทางรู้ว่าควรให้เครดิตใคร จึงเลือกส่วนผสมสุดโต่งที่บังเอิญพอดีกับ noise ในข้อมูลชุดนี้

💎 แต่ดูสิ่งที่ทั้งสามวิธีทำได้ถูก — และมันเปลี่ยนวิธีอ่านผลไปเลย

เอา β ของ market กับ value มาบวกกัน (ค่าจริง = 0.8 + 0.4 = 1.20):

นี่คือหัวใจของ multicollinearity ในประโยคเดียว: ข้อมูลบอกได้ชัดเจนว่า "market กับ value รวมกันมีผลเท่าไร" แต่บอกไม่ได้เลยว่า "แต่ละตัวมีผลเท่าไร" — เพราะในข้อมูลนี้ทั้งสองแทบไม่เคยขยับแยกกัน

💡 ใช้ประโยชน์: ถ้าคุณเจอ VIF สูง ให้เลิกถามคำถามที่ข้อมูลตอบไม่ได้ แล้วไปถามคำถามที่มันตอบได้ — รายงาน "ผลรวมของกลุ่มปัจจัยที่เกี่ยวข้องกัน" แทนที่จะรายงาน β รายตัวที่ไม่มีความหมาย

14.2 Ridge — ดึงทุกสัมประสิทธิ์เข้าหาศูนย์พร้อมกัน

Ridge Regression (L2) Hoerl & Kennard 1970 ★★★ ต้องรู้จัก

🎯 Thesis

"เพิ่มค่าปรับให้กับสัมประสิทธิ์ที่ใหญ่ · โมเดลจึงต้องแลกระหว่าง 'ทาบข้อมูลให้ดี' กับ 'อย่าใช้ตัวเลขสุดโต่ง' — ผลคือคำตอบที่เอนเล็กน้อยแต่เสถียรกว่ามาก"

🚶 อ่านเป็นภาษาคนก่อน: OLS มีเป้าหมายเดียว — ทำให้ผลรวมความคลาดเคลื่อนกำลังสองน้อยที่สุด · มันยอมทำทุกอย่างเพื่อเป้านั้น รวมถึงใช้ β = −0.199 คู่กับ +1.436 ถ้ามันช่วยลด error ได้แม้นิดเดียว

Ridge เติมเงื่อนไขข้อที่สอง: "และอย่าให้ β ใหญ่เกินจำเป็นด้วย" · ทันทีที่มีเงื่อนไขนี้ ส่วนผสมสุดโต่งจะแพงเกินไป โมเดลจึงเลือกส่วนผสมที่สมดุลกว่า

OLS : หา β ที่ทำให้ Σ(y − Xβ)² น้อยที่สุด Ridge: หา β ที่ทำให้ Σ(y − Xβ)² + α · Σβⱼ² น้อยที่สุด ↑ ค่าปรับ — β ยิ่งใหญ่ยิ่งเสียแพง (กำลังสอง) α = 0 → เป็น OLS พอดี α ใหญ่ขึ้น → β ทุกตัวถูกดึงเข้าหาศูนย์ แต่ไม่มีตัวไหนเป็นศูนย์เป๊ะ

📖 อ่านสูตรว่า: Xβ อ่านว่า "เอ็กซ์เบต้า" = เมทริกซ์ข้อมูลคูณ vector สัมประสิทธิ์ = ค่าทำนาย ŷ ของทุกจุดในบรรทัดเดียว (เล่ม 2·A §2.2) · Σ(y − Xβ)² จึงคือผลรวม residual² ตัวเดิมของ OLS · กับดักการอ่าน: Σ สองตัวในบรรทัด Ridge ไล่คนละอย่าง — ตัวแรกไล่ตามจุดข้อมูล (i = 1…n แม้ตำราจะซ่อนตัวห้อยไว้) ตัวที่สอง Σβⱼ² ไล่ตามสัมประสิทธิ์ (j = 1…จำนวนตัวแปร) · ตัวห้อย j ต่างจาก i คือสัญญาณให้รู้ · และ α ตัวนี้เป็นความหมายที่สี่ของตัวอักษรเดียวในเล่ม 2: จุดตัดแกน (2·A) · ขนาดก้าว gradient descent (2·B) · ผลตอบแทนเหนือ CAPM (2·E) · น้ำหนักค่าปรับ (ที่นี่) · โครงที่ต้องเห็น: "หา β ที่ทำให้ … น้อยที่สุด" คือ argmin — ผลลัพธ์คือตัว β ไม่ใช่ค่าต่ำสุดของนิพจน์ · โจทย์เป็น "ค่าผิดพลาด + ค่าปรับ" สองพจน์บวกกัน α คืออัตราแลกเปลี่ยนระหว่างสองพจน์ ที่ α = 0 พจน์ปรับหายไปเหลือ OLS พอดี

⚠️ α ตัวนี้ไม่เกี่ยวอะไรกับ alpha ของ CAPM ใน เล่ม 2 · E §10.4 เลย — บังเอิญใช้ตัวอักษรเดียวกัน · บางตำราเรียกตัวนี้ว่า λ เพื่อเลี่ยงความสับสน

ดูว่าเกิดอะไรขึ้นเมื่อค่อย ๆ เพิ่ม α:

✅ อ่านกราฟ
  • ที่ α เล็กมาก (ซ้ายสุด) — เป็น OLS · market ติดลบ (−0.19) และ value พุ่งไป 1.43 · สองเส้นแยกห่างกันสุดขั้ว
  • พอ α เพิ่มขึ้น — เส้นน้ำเงินไต่ขึ้น เส้นส้มลดลง · ทั้งคู่วิ่งเข้าหากัน เพราะค่าปรับทำให้ "หนึ่งบวกจัดหนึ่งลบจัด" แพงเกินไป
  • ที่ α = 10 ได้ 0.528 / 0.695 — ยังไม่ตรงค่าจริง (0.8 / 0.4) แต่อยู่ในย่านที่สมเหตุสมผลและเครื่องหมายถูกทั้งคู่
  • เส้นเขียว (size) แทบไม่ขยับ — เพราะมันเป็นอิสระจากตัวอื่น (VIF = 1.0) จึงไม่มีปัญหาให้แก้ตั้งแต่แรก · Ridge แตะเฉพาะที่ที่มีปัญหา
🧮 ประโยชน์ที่แท้จริงของ Ridge วัดได้เป็นตัวเลข — ความเสถียร

สุ่มข้อมูลใหม่แบบ bootstrap 500 รอบ (ใช้บทที่ 13 ที่เพิ่งเรียน!) แล้วดูว่า β ของ market เหวี่ยงแค่ไหน:

🐍 Python — วัดความเสถียรของ β ด้วย bootstrap
# pip install numpy scikit-learn
import numpy as np
from sklearn.linear_model import LinearRegression, Ridge

rng = np.random.default_rng(5)
n = 250
mkt = rng.normal(0, 1, n); val = mkt + rng.normal(0, 0.10, n); size = rng.normal(0, 1, n)
X = np.column_stack([mkt, val, size])
y = X @ np.array([0.8, 0.4, 0.3]) + rng.normal(0, 1.0, n)

g = np.random.default_rng(0)                    # ★ generator แยก ผลจึงทำซ้ำได้
ols, rdg = [], []
for _ in range(500):
    i = g.integers(0, n, n)                     # สุ่มหยิบแบบใส่คืน
    ols.append(LinearRegression().fit(X[i], y[i]).coef_[0])
    rdg.append(Ridge(alpha=10).fit(X[i], y[i]).coef_[0])

for name, a in [("OLS", np.array(ols)), ("Ridge(10)", np.array(rdg))]:
    lo, hi = np.percentile(a, [5, 95])          # ★ ใช้เปอร์เซ็นไทล์ ไม่ใช่ min/max ซึ่งไม่เสถียร
    print(f"{name:10s} beta_market: SD {a.std():.3f} | ช่วง 5-95% [{lo:+.2f}, {hi:+.2f}]")
# OLS        beta_market: SD 0.735 | ช่วง 5-95% [-1.59, +0.98]
# Ridge(10)  beta_market: SD 0.077 | ช่วง 5-95% [+0.39, +0.65]
วิธีSD ของ β marketช่วง 5–95%
OLS0.735[−1.59, +0.98] ❌
Ridge (α=10)0.077[+0.39, +0.65] ✓

OLS ให้คำตอบตั้งแต่ −1.59 ถึง +0.98 เพียงเพราะเปลี่ยนตัวอย่างข้อมูลเล็กน้อย — ช่วงนี้คร่อมศูนย์ แปลว่ามันบอกไม่ได้ด้วยซ้ำว่าตลาดมีผลทางบวกหรือลบ · Ridge เหวี่ยงน้อยกว่า 9.5 เท่า และอยู่ในย่านบวกเสมอ

ถ้าคุณใช้ β นี้เป็น hedge ratio จริง — OLS จะสั่งให้คุณสลับข้างระหว่าง long กับ short เพียงเพราะข้อมูลขยับนิดเดียว ซึ่งเป็นหายนะทั้งเรื่องต้นทุนและความเสี่ยง

14.3 Lasso — ตัดตัวแปรทิ้งไปเลย

Lasso Regression (L1) Tibshirani 1996 ★★☆ ควรรู้

🚶 อ่านเป็นภาษาคนก่อน: Lasso เปลี่ยนแค่จุดเดียวจาก Ridge — ปรับด้วยค่าสัมบูรณ์แทนกำลังสอง · การเปลี่ยนที่ดูเล็กนี้ให้ผลที่ต่างกันทั้งเรื่อง: Lasso ผลัก β บางตัวให้เป็นศูนย์เป๊ะ ๆ ซึ่งเท่ากับตัดตัวแปรนั้นทิ้ง

Ridge: Σ(y − Xβ)² + α · Σβⱼ² → β เล็กลงแต่ไม่เป็นศูนย์ Lasso: (1/2n)·Σ(y − Xβ)² + α · Σ|βⱼ| → β บางตัวกลายเป็น 0 เป๊ะ ↑ สังเกตตัวหารนี้ (ตาม sklearn) ผลพลอยได้: Lasso เลือกตัวแปรให้อัตโนมัติ (feature selection)

📖 อ่านสูตรว่า: |βⱼ| ขีดตั้งสองข้างอ่านว่า "ค่าสัมบูรณ์ของเบต้าเจ" = ทิ้งเครื่องหมาย เหลือแต่ขนาด — β = −0.2 กับ +0.2 เสียค่าปรับเท่ากัน · ชื่อ L1/L2 ในหัวการ์ดมาจากตรงนี้: L1 = ผลรวมของค่าสัมบูรณ์ (ยกกำลังหนึ่ง) L2 = ผลรวมของกำลังสอง · โครงที่ต้องเห็น: ทั้งสองสูตรเป็น "ค่าผิดพลาด + α × ขนาดของ β" ต่างกันแค่วิธีวัดขนาด — และความต่างนี้อธิบายพฤติกรรมได้จากสูตรเลย: ค่าปรับกำลังสองมีความชัน 2αβ ที่เข้าใกล้ศูนย์เมื่อ β เล็ก แรงดึงจึงอ่อนลงเรื่อย ๆ ไม่มีวันดันถึงศูนย์พอดี ส่วนค่าสัมบูรณ์มีความชัน ±α คงที่ไม่ว่า β จะเล็กแค่ไหน แรงดึงจึงไม่อ่อนลงและดัน β เล็ก ๆ ทะลุเป็นศูนย์ได้ · กับดักการอ่าน: (1/2n) หน้าพจน์แรกเป็นแค่การหารสเกลตามธรรมเนียมของ sklearn ไม่ใช่ส่วนหนึ่งของทฤษฎี — แต่มันเปลี่ยนความหมายของ α ไป 2n เท่าตามที่กล่อง ❌ ถัดไปแสดง

❌ α ของ Ridge กับ Lasso เทียบกันตรง ๆ ไม่ได้ — ต่างกัน 2n เท่า

Lasso ของ sklearn หารด้วย 2n ส่วน Ridge ไม่หาร · นี่ไม่ใช่รายละเอียดปลีกย่อย — มันคือคำตอบของคำถามที่คุณน่าจะสงสัยอยู่: ทำไมตัวอย่างในบทนี้ใช้ Ridge α=10 แต่ Lasso α=0.05 ทั้งที่ดูห่างกัน 200 เท่า

ในหน่วยเดียวกัน Lasso α=0.05 เทียบเท่า 2n × 0.05 = 25 ซึ่งอยู่ในย่านเดียวกับ Ridge α=10 · ผมยืนยันด้วยการแก้สมการเองตรง ๆ:

ใช้สูตรที่ไม่หาร 2n ที่ α = 0.05 → [−0.175, 1.413, 0.268] ← ไม่มีตัวไหนเป็นศูนย์เลย ใช้สูตรที่ไม่หาร 2n ที่ α = 25 → [ 0.000, 1.187, 0.218] ← ตรงกับ sklearn เป๊ะ

ถ้าคุณเขียนสูตร Lasso เองตามที่เห็นในตำราส่วนใหญ่ (ไม่หาร 2n) แล้วใส่ α = 0.05 คุณจะไม่ได้ศูนย์เลยสักตัว — และเรื่องทั้งหมดของหัวข้อนี้จะไม่เกิดขึ้น

💡 กฎง่าย ๆ: อย่าเทียบ α ข้ามระหว่าง Ridge กับ Lasso · และอย่าย้ายค่า α จากตำราหนึ่งไปอีกไลบรารีหนึ่งโดยไม่ดู objective ก่อน — เปิด docstring อ่านทุกครั้ง

✅ ข้อดี
  • ได้โมเดลที่เล็กและอ่านง่าย — เหลือเฉพาะตัวที่สำคัญ
  • เหมาะมากเมื่อตัวแปรเยอะกว่าข้อมูล (เช่นสแกน 500 ปัจจัย)
  • บอกได้ว่า "ตัวไหนควรตัด" โดยไม่ต้องเดาเอง
⚠️ ข้อเสีย
  • เมื่อตัวแปรทับซ้อนกัน มันเลือกมาตัวเดียวแบบเกือบสุ่ม — ดู §14.5
  • การเลือกนั้นไม่เสถียร เปลี่ยนข้อมูลนิดเดียวอาจเลือกคนละตัว
  • β ที่เหลือถูกหดเข้าหาศูนย์อย่างเป็นระบบ — แต่ระวังความหมาย ดูกล่องข้างล่าง
❌ ดูผลของ Lasso ในตัวอย่างเรา — มันตัด market ทิ้งทั้งตัว

Lasso(alpha=0.05) ให้ [0.000, 1.187, 0.218] · มันตัด market ซึ่งเป็นตัวแปรที่มีผลจริงมากที่สุด (0.8) ทิ้งไปเลย แล้วยกเครดิตทั้งหมดให้ value

Lasso ไม่ได้ทำผิด — มันทำตามที่ถูกสั่ง · ในเมื่อสองตัวนี้แทบเป็นตัวเดียวกัน การใช้ตัวเดียวก็อธิบายข้อมูลได้พอ ๆ กัน และ "ตัวเดียว" มีค่าปรับถูกกว่า · มันจึงเลือกตัวที่บังเอิญเข้ากับ noise ได้ดีกว่านิดหน่อย

ถ้าคุณเอาผลนี้ไปรายงานว่า "งานวิจัยพบว่าปัจจัยตลาดไม่มีผล มีแต่ value ที่สำคัญ" — คุณเพิ่งสรุปผิดสนิทด้วยเครื่องมือที่ทำงานถูกต้อง

🔧 "หดเข้าหาศูนย์" ไม่เท่ากับ "ต่ำกว่าค่าจริง" — จุดที่พลาดกันบ่อย

Lasso หด β ลงเสมอ · แต่มันหดสิ่งที่มันกำลังประมาณ ซึ่งไม่ใช่ค่าจริงรายตัวเมื่อตัวแปรทับซ้อน

ตัวแปรเป็นอิสระต่อกันหดลง ≈ α ต่อตัวต่ำกว่าค่าจริงทุกตัว ✓
ตัวแปรทับซ้อน (ตัวอย่างเรา)β_value = 1.187ค่าจริงรายตัว 0.4 → สูงกว่า 3 เท่า!

ทำไม: พอ Lasso ตัด market ทิ้ง ตัวที่รอดต้องแบกผลของทั้งกลุ่มไว้คนเดียว · สิ่งที่มันประมาณจึงเป็นผลรวมของกลุ่ม = 1.20 ไม่ใช่ 0.4 · แล้วค่อยถูกหดลงจากตรงนั้น → 1.187 < 1.20 ✓ หดจริง

💎 นี่คือ §14.1 กลับมาอีกครั้ง — ข้อมูลบอก "ผลรวมของกลุ่ม" ได้ แต่บอก "รายตัว" ไม่ได้ · Lasso ก็ทำงานอยู่บนผลรวมนั้นเหมือนกัน ไม่ใช่บนตัวเลขที่คุณอยากรู้

14.4 เลือก α ยังไง — วงจรปิดกับบทที่ 12

🚶 อ่านเป็นภาษาคนก่อน: α เป็นตัวเลขที่เราตั้งเอง ไม่ใช่สิ่งที่ข้อมูลบอก · แล้วจะรู้ได้ยังไงว่าควรตั้งเท่าไร · คำตอบคือ cross-validation จากบทที่ 12 นั่นเอง — ลองหลายค่า แล้วเลือกค่าที่ทำนายข้อมูลที่ไม่เคยเห็นได้ดีที่สุด

🐍 Python — ให้ CV เลือก α ให้ + วัดว่ามันช่วยพยากรณ์จริงไหม
# pip install numpy scikit-learn
import numpy as np
from sklearn.linear_model import LinearRegression, Ridge, Lasso, RidgeCV, LassoCV
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

rng = np.random.default_rng(5)
n = 250
mkt = rng.normal(0, 1, n); val = mkt + rng.normal(0, 0.10, n); size = rng.normal(0, 1, n)
X = np.column_stack([mkt, val, size])
bt = np.array([0.8, 0.4, 0.3])
y = X @ bt + rng.normal(0, 1.0, n)

print(f"RidgeCV เลือก alpha = {RidgeCV(alphas=np.logspace(-2,3,60)).fit(X,y).alpha_:.2f}")
# RidgeCV เลือก alpha = 4.24
lc = LassoCV(cv=5).fit(X, y)                     # ข้อมูลชุดนี้ตัดขวางจึงใช้ k-fold ได้ · มีแกนเวลาต้องใช้ TimeSeriesSplit
print(f"LassoCV เลือก alpha = {lc.alpha_:.4f} -> coef {np.round(lc.coef_,3)}")
# LassoCV เลือก alpha = 0.0138 -> coef [0.    1.226 0.254]

# ★ ทดสอบกับข้อมูลใหม่ 5,000 จุดที่ไม่เคยเห็น
rg = np.random.default_rng(77)
m2 = rg.normal(0, 1, 5000); v2 = m2 + rg.normal(0, 0.10, 5000); s2 = rg.normal(0, 1, 5000)
X2 = np.column_stack([m2, v2, s2]); y2 = X2 @ bt + rg.normal(0, 1.0, 5000)

# ★ Pipeline: scaler ถูก fit เฉพาะชุดฝึกเสมอ — ตาม §12.4 ข้อ 2 และ §14.5 ข้อ 1
for name, m in [("OLS",        LinearRegression()),
                ("Ridge(10)",  make_pipeline(StandardScaler(), Ridge(alpha=10))),
                ("Lasso(.05)", make_pipeline(StandardScaler(), Lasso(alpha=0.05)))]:
    p = m.fit(X, y).predict(X2)
    r2 = 1 - ((y2-p)**2).sum()/((y2-y2.mean())**2).sum()
    print(f"{name:11s} R2(out) {r2:.4f}")
# OLS         R2(out) 0.6152
# Ridge(10)   R2(out) 0.6186
# Lasso(.05)  R2(out) 0.6143
🔧 สังเกต make_pipeline — นี่คือวิธีที่ถูกต้อง ไม่ใช่ของประดับ

Pipeline ผูก scaler เข้ากับโมเดลเป็นก้อนเดียว · เวลาเรียก .fit() มันคำนวณค่าเฉลี่ยกับ SD จากชุดฝึกเท่านั้น แล้วใช้ค่าเดียวกันนั้นแปลงชุดทดสอบ

ถ้าคุณทำเองด้วยมือ (scaler.fit(X) ก่อนแบ่ง) คุณจะทำผิดตาม §12.4 ข้อ 2 ทันทีโดยไม่รู้ตัว · และถ้าเอา Pipeline นี้ไปใส่ cross_val_score มันจะ fit scaler ใหม่ทุก foldให้เอง ซึ่งเป็นสิ่งที่ถูกต้องและทำเองยาก

💡 กฎง่าย ๆ: ทุกอย่างที่ "เรียนรู้อะไรบางอย่างจากข้อมูล" ต้องอยู่ใน Pipeline — scaler · การเลือกฟีเจอร์ · การเติมค่าที่หายไป · ไม่ใช่แค่ตัวโมเดล

💎 ผลลัพธ์ที่ตำราส่วนใหญ่ไม่บอกคุณ — regularization แทบไม่ช่วยการพยากรณ์เลย

ดู R²(out) ทั้งสามบรรทัด: 0.6152 · 0.6186 · 0.6143 — ต่างกันในหลักทศนิยมที่สาม

OLS ที่ให้ β ผิดเครื่องหมายอย่างน่าตกใจ ทำนายได้ดีเกือบเท่า Ridge เป๊ะ · ทำไม? เพราะอย่างที่เห็นใน §14.1 — OLS หา "ผลรวม" ได้ถูกต้อง และการพยากรณ์ต้องการแค่ผลรวมนั้น ไม่ต้องรู้ว่าเครดิตควรแบ่งยังไง

นี่คือการยืนยันสิ่งที่ §6.6 บอกไว้: multicollinearity ไม่ทำร้ายการพยากรณ์ · มันทำร้ายการตีความ

เป้าหมายของคุณใช้ regularization ไหม
พยากรณ์ y ให้แม่นช่วยเล็กน้อย — คุ้มเมื่อตัวแปรเยอะหรือข้อมูลน้อย · ที่นี่ได้แค่ +0.003
อ่าน β เพื่อตัดสินใจ (hedge ratio · น้ำหนักพอร์ต)จำเป็นมาก — ต่างกันระหว่าง −0.199 กับ +0.528 คือต่างกันคนละทิศ
ทำ β ให้เสถียรพอจะใช้ซ้ำได้จำเป็นมาก — SD ลดจาก 0.735 เหลือ 0.077

💡 อย่าขาย Ridge/Lasso ว่า "ทำให้โมเดลแม่นขึ้น" · ขายว่า "ทำให้คำตอบเชื่อถือได้และใช้ซ้ำได้" ซึ่งเป็นคนละเรื่องและมีค่ามากกว่าในงานจริง

14.5 ❌ สามกับดักที่ต้องรู้ก่อนใช้จริง

🚶 อ่านเป็นภาษาคนก่อน: สามข้อข้างล่างคือจุดที่ Ridge/Lasso ทำงานถูกต้องตามที่ถูกสั่ง แต่ให้คำตอบที่คุณตีความผิด · ไม่ใช่บั๊กของไลบรารี — เป็นช่องว่างระหว่าง "สิ่งที่สูตรทำ" กับ "สิ่งที่คุณคิดว่ามันทำ"

❌ 1. ต้องปรับสเกลก่อนเสมอ — ไม่งั้นค่าปรับจะลงโทษไม่เท่ากัน

ค่าปรับคือ α·Σβⱼ² ซึ่งไม่รู้จักหน่วยของตัวแปร · ตัวแปรที่มีสเกลใหญ่จะมี β เล็กโดยธรรมชาติ จึงโดนปรับน้อยกว่าโดยไม่มีเหตุผลทางเนื้อหาเลย

ทดสอบง่าย ๆ: เปลี่ยนหน่วยของ size ให้ใหญ่ขึ้น 100 เท่า (เช่นจาก "ล้านบาท" เป็น "หมื่นบาท") แล้วรัน Ridge เดิม:

Ridge บน X เดิม → β_size = 0.2561 Ridge บน X สเกลใหม่ → β_size = 0.0027 → แปลงกลับ = 0.2655 ต่างกัน 3.7% ทั้งที่ข้อมูลเป็นชุดเดียวกันเป๊ะ เปลี่ยนแค่หน่วย

ทางแก้: StandardScaler ก่อนเสมอ (และตาม §12.4 ข้อ 2 — fit บนชุดฝึกเท่านั้น) · หรือใช้ Pipeline ซึ่งจัดการให้ครบ · ห้ามปรับสเกลกับตัว intercept เพราะเราไม่ต้องการลงโทษค่าคงที่

❌ 2. Lasso เลือกตัวแปรแบบไม่เสถียร เมื่อตัวแปรทับซ้อนกัน

อย่างที่เห็นใน §14.3 — Lasso ตัด market ทิ้งแล้วเก็บ value ไว้ · ถ้าเปลี่ยนข้อมูลนิดเดียว มันอาจตัด value แล้วเก็บ market แทน

ผลในทางปฏิบัติ: ถ้าคุณรัน Lasso ทุกเดือนเพื่อเลือกปัจจัย รายชื่อปัจจัยจะเปลี่ยนไปมาโดยที่ตลาดไม่ได้เปลี่ยนอะไรเลย — แล้วคุณจะไล่ปรับพอร์ตตามความสุ่มนั้น

ทางแก้:

  • Elastic Net — ผสมค่าปรับทั้งสองแบบ (L1 + L2) · ตัวแปรที่ทับซ้อนกันจะถูกเก็บหรือถูกตัดไปด้วยกันเป็นกลุ่ม แทนที่จะแย่งกันเอง
  • Stability selection — รัน Lasso บนตัวอย่าง bootstrap หลายรอบ (บทที่ 13) แล้วเก็บเฉพาะตัวที่ถูกเลือกบ่อย เช่นเกิน 80% ของรอบ · ตัวที่ถูกเลือกครึ่ง ๆ กลาง ๆ คือสัญญาณว่ามันแทนกันได้
❌ 3. α ที่ CV เลือกให้ ไม่ใช่ α ที่ดีที่สุดสำหรับการตีความ

RidgeCV เลือก α = 4.24 เพราะนั่นคือค่าที่ทำนายได้ดีที่สุด · แต่เราเพิ่งพิสูจน์ไปว่าการทำนายแทบไม่ต่างกันเลยในช่วง α กว้าง ๆ

ถ้าเป้าหมายคือ β ที่เสถียรพอจะเอาไปใช้เป็น hedge ratio คุณอาจต้องการ α สูงกว่านั้นมาก — และนั่นไม่ผิด ตราบใดที่คุณรู้ว่ากำลังแลกอะไรกับอะไร

วิธีตัดสินใจที่ตรงไปตรงมา: พล็อตกราฟเส้นทางแบบใน §14.2 แล้วเลือก α ที่เส้นเริ่มนิ่ง · จากกราฟนั้น α ราว 10–30 คือจุดที่เส้นน้ำเงินกับส้มหยุดเคลื่อนที่แรง ๆ แล้ว

⚠️ และอย่าลืมว่า CV ที่ใช้เลือก α ต้องเป็น walk-forward ถ้าข้อมูลมีเวลา · ค่าปริยายของทั้งคู่ใช้ไม่ได้ — และ RidgeCV แย่กว่าที่คิด:

ตัวค่าปริยายปัญหา
LassoCVk-fold 5 ส่วน (ไม่สลับ)ไม่สลับก็จริง แต่ยังฝึกด้วย fold ที่อยู่หลัง fold ทดสอบ — ตรงกับที่เฉลย ✍️ §12.3 ข้อ (2) เตือนไว้
RidgeCVLeave-One-Outแย่ที่สุดเท่าที่เป็นไปได้ — เอาข้อมูลออกทีละจุด แล้วฝึกด้วยจุดที่เหลือทั้งหมด รวมอนาคตทุกจุด

ต้องส่ง cv=TimeSeriesSplit(5) เข้าไปเองทั้งคู่ มิฉะนั้นคุณเพิ่งทำผิดตาม §12.3 อีกรอบ — และในกรณีของ RidgeCV คือผิดหนักกว่า k-fold เสียอีก

🧠 มุมที่มองต่าง — regularization ไม่ใช่เทคนิค แต่เป็นการยอมรับความจริง

มือใหม่เห็น: "Ridge/Lasso คือเทคนิคขั้นสูงที่ทำให้โมเดลเก่งขึ้น"
คนที่ใช้จริงเห็น: มันคือการยอมรับว่าข้อมูลของคุณไม่พอจะตอบคำถามที่คุณถาม · α ที่ใหญ่ขึ้นแปลว่า "ผมเชื่อข้อมูลชุดนี้น้อยลง และเชื่อสามัญสำนึก (ว่า β ไม่ควรสุดโต่ง) มากขึ้น"

มองแบบนี้แล้ว คำถามที่ถูกไม่ใช่ "α เท่าไรดี" แต่คือ "ผมควรเชื่อข้อมูลชุดนี้แค่ไหน" — ซึ่งเป็นคำถามที่ตอบด้วยความเข้าใจตลาด ไม่ใช่ด้วย CV เพียงอย่างเดียว

ดูเฉลย

(2) ไม่ผิดแล้ว — OLS ให้ [0.734, 0.504, 0.268] เทียบค่าจริง [0.8, 0.4, 0.3] · เครื่องหมายถูกทุกตัวและอยู่ในย่านที่ใช้งานได้ (ต่างจาก −0.199 ตอน VIF = 113 ลิบลับ) · เพราะตอนนี้ข้อมูลมีข้อมูลพอจะแยกสองตัวออกจากกันแล้ว

(3) แทบไม่จำเป็น — และนี่คือประเด็นสำคัญที่สุดของข้อนี้: regularization ไม่ใช่สิ่งที่ควรใส่ไว้ทุกครั้งโดยอัตโนมัติ · มันคือยาสำหรับโรคเฉพาะ (β ไม่เสถียรเพราะข้อมูลไม่พอจะแยกแยะ) · ถ้าไม่มีโรค ยาก็มีแต่ผลข้างเคียง — คือ β ที่ถูกหดเข้าหาศูนย์โดยไม่ได้อะไรตอบแทน

"เก็บคะแนนเส้นตรง β₀ + β₁x₁ + … ไว้เหมือน OLS ทุกอย่าง แล้วส่งผ่านตัวบีบก่อนออกจากโมเดล — ผลลัพธ์จึงอยู่ระหว่าง 0 กับ 1 เสมอ และอ่านเป็นความน่าจะเป็นของทิศได้ · ตัวบีบตัวนี้คือรูปเดียวกับ 100 − 100/(1 + RS) ของ RSI ที่คุณอ่านมาแล้ว"

❓ ทำไมต้องรู้จัก

คำถามแบบ "สัญญาณนี้ → เทรดหรือไม่เทรด" เกือบทั้งหมดคือ classification (การจำแนกประเภท) ไม่ใช่ regression · และเมื่อโมเดลตอบว่า P(ขึ้น) = 0.55 ตัวเลขนี้มีค่าก็ต่อเมื่ออยู่คู่กับขนาดของกำไร/ขาดทุน — Kelly ใน เล่ม 2 · E §11.2 ต้องการทั้ง p และ b · ความน่าจะเป็นโดยไม่มีขนาดคือครึ่งคำตอบ และหัวข้อนี้จะทำให้คุณเห็นว่าอีกครึ่งไม่ได้อยู่ในโมเดลนี้เลย

🚶 อ่านเป็นภาษาคนก่อน: ลองยัด y ที่เป็น 0/1 เข้า OLS ตรง ๆ ดูก่อน · กับข้อมูลจำลอง 400 แถวในบล็อก 🐍 ข้างล่าง OLS ให้ค่าทำนายตั้งแต่ −0.185 ถึง 1.167 และมี 14 แถวที่ค่าทำนายหลุดออกนอกช่วง [0, 1] · "ความน่าจะเป็นลบ 18%" ไม่มีความหมาย · ปัญหาไม่ใช่ว่าเส้นตรงผิด — คะแนนเส้นตรงยังเป็นความคิดที่ดี · ปัญหาคือเส้นตรงไม่มีเพดานและไม่มีพื้น ต้องมีอะไรมาบีบมันให้อยู่ในช่วงก่อน

ตัวที่บีบคือ sigmoid (ฟังก์ชันรูปตัว S) · notation หมวด 0 เรียกโครงนี้ว่า "ตัวบีบ" — RSI ใช้ 100 − 100/(1 + RS) บีบอัตราส่วนที่วิ่งจาก 0 ถึงไม่จำกัด ให้เหลือ 0 ถึง 100 · logistic ใช้ 1/(1 + e^(−z)) บีบคะแนนที่วิ่งจากลบไม่จำกัดถึงบวกไม่จำกัด ให้เหลือ 0 ถึง 1 · และถ้าตั้ง RS = e^z สองสูตรนี้คือสูตรเดียวกันเป๊ะ (ต่างกันแค่คูณ 100) — ไม่ใช่แค่ "คล้าย"

z = β₀ + β₁x₁ + … + βₙxₙ ← คะแนนเส้นตรง (เหมือน OLS ทุกอย่าง) P(y = 1 | x) = 1 / (1 + e^(−z)) ← sigmoid: บีบ z ให้อยู่ใน (0, 1) log-odds: ln( P / (1 − P) ) = z ← เส้นตรงกลับมา

📖 อ่านสูตรว่า: "ซี เท่ากับ เบต้าศูนย์ บวก เบต้าหนึ่งเอ็กซ์หนึ่ง บวก … " · "ความน่าจะเป็นที่วายเท่ากับหนึ่ง เมื่อรู้เอ็กซ์ เท่ากับ หนึ่ง หารด้วย (หนึ่ง บวก เอ็กซ์โพเนนเชียลของลบซี — อ่านสั้น ๆ ว่า อียกกำลังลบซี)" · "ล็อกธรรมชาติของ พีหารด้วยหนึ่งลบพี เท่ากับ ซี" · โครงที่ต้องเห็น: บรรทัดสองคือ "ตัวบีบ" จาก notation หมวด 0 — ทดสอบด้วยการแทนค่าสามจุดเสมอ: z = 0 → e⁰ = 1 → P = 1/2 · z ใหญ่มาก → e^(−z) ≈ 0 → P ≈ 1 · z ลบมาก → e^(−z) ใหญ่มาก → P ≈ 0 · บรรทัดสามคือประเด็นทั้งหมด: P/(1 − P) เรียกว่า odds (อัตราต่อรอง เช่น P = 0.8 คือ 4 ต่อ 1) และ ln ของ odds กลับมาเป็นเส้นตรงใน x — โมเดลเส้นตรงยังอยู่ครบ แค่ย้ายไปอยู่บนสเกล log-odds · ดังนั้น β₁ อ่านว่า "x₁ เพิ่ม 1 → log-odds เพิ่ม β₁ = odds คูณ e^β₁" ไม่ใช่ "P เพิ่ม β₁" (ตาราง 🧮 ข้างล่างจะแสดงว่า P เพิ่มไม่เท่ากันแต่ odds คูณเท่ากันทุกขั้น) · กับดักการอ่าน: ขีดตั้งใน P(y = 1 | x) คือ "given / เมื่อรู้" ไม่ใช่การหาร — แถว E[·|·] ใน notation หมวด 0 · e^(−z) เลขชี้กำลังติดลบให้ค่าเล็กที่เป็นบวก ไม่ใช่ค่าลบ (e^(−1.4) = 0.2466) ตัวส่วนจึงมากกว่า 1 เสมอและ P ไม่มีวันเกิน 1 · และสิ่งที่ไม่อยู่ในสูตรเลยคือขนาด — P คือความน่าจะเป็นของทิศเท่านั้น ขึ้น 0.1% กับขึ้น 8% เป็น y = 1 เท่ากัน ตามที่แถว Logistic ใน ตาราง E[อะไร | อะไร] ระบุไว้ว่า "สิ่งที่ไม่อยู่หลังขีด: ขนาดของการขึ้น/ลง"

⚠️ เรื่องอ่านค่าปรับใน sklearn อีกหนึ่งประโยค: LogisticRegression มีค่าปรับ L2 แบบ Ridge อยู่ในตัวโดยปริยาย แต่ควบคุมด้วย C ซึ่งกลับด้านกับ α ของ §14.2 — C ทำหน้าที่ราว 1/α (ทิศตรงข้าม แต่สเกลไม่ตรงกันเป๊ะ เพราะ objective เขียนคนละแบบ) · C เล็ก = ปรับแรง · C ใหญ่ = เข้าใกล้ไม่ปรับ · คนที่เคยตั้ง Ridge(alpha=10) แล้วตั้ง C=10 ด้วยความรู้สึกเดียวกัน กำลังทำตรงข้ามกับที่ตั้งใจ

ดูสองคอลัมน์ขวาสุดเทียบกัน · จาก x₁ = 0 → 1 → 2 P เพิ่ม 0.196 แล้วเพิ่ม 0.157 — ไม่คงที่ · แต่ odds คูณ 2.2255 ทุกขั้น (1.8221 / 0.8187 = 4.0552 / 1.8221 = 2.2255 = e^0.8) · นี่คือความหมายของ β₁ = 0.8 ที่ถูกต้อง: "ทุก 1 หน่วยของ x₁ อัตราต่อรองคูณ 2.23" · และที่ x₁ = 0 ได้ P = 0.4502 ไม่ใช่ 0.5 เพราะ β₀ = −0.2 เลื่อนจุดกึ่งกลางไป — จุดที่ P = 0.5 พอดีอยู่ที่ x₁ = 0.25

แล้ว 0.55 มีค่าเท่าไร · ใช้ตัวเลขของมินจาก NQ Part 0 (ต้นทุนไปกลับ 0.2% · เป้ากำไรและขาดทุนที่ยอมรับ ±2%): กำไรคาดหวังต่อไม้ที่ P = 0.55 คือ 0.55 × 2% − 0.45 × 2% − 0.2% = 0.20% − 0.20% = 0.00% — เสมอตัวพอดี ซึ่งก็คือ "อัตราชนะเสมอตัว 55%" ที่ NQ Part 0 คำนวณไว้จากอีกทาง · ที่ P = 0.50 ได้ −0.20% ต่อไม้ · ห่างกันแค่ 0.05 ในความน่าจะเป็น แต่คือความต่างระหว่าง "เสมอตัว" กับ "ขาดทุนช้า ๆ" · และ 0.55 ที่โมเดลบอกยังต้องเป็น 0.55 จริงด้วย — นั่นคือคำถามเรื่อง calibration ในบล็อกถัดไป

🐍 Python — Logistic Regression บนข้อมูลจำลอง 400 แถว + ตาราง calibration
# pip install numpy scikit-learn
import numpy as np
from sklearn.linear_model import LogisticRegression

rng = np.random.default_rng(7)
n = 400
X = rng.normal(0, 1, (n, 2))                          # สองสัญญาณ ปรับสเกลแล้ว
noise = rng.normal(0, 1, n)
y = (0.8*X[:,0] - 0.5*X[:,1] + noise > 0).astype(int) # 1 = ขึ้น · 0 = ลง
print("สัดส่วนวันขึ้น", y.mean())
# สัดส่วนวันขึ้น 0.5025

m = LogisticRegression(C=1.0).fit(X, y)              # ★ C = 1/α — ค่าปริยายมีค่าปรับ L2 อยู่แล้ว
print("coef", np.round(m.coef_[0], 3), "intercept", np.round(m.intercept_[0], 3))
# coef [ 1.158 -0.643] intercept -0.03
print("odds คูณต่อ +1 SD:", np.round(np.exp(m.coef_[0]), 3))
# odds คูณต่อ +1 SD: [3.183 0.526]
print("accuracy in-sample", round(m.score(X, y), 3))
# accuracy in-sample 0.69

# ★ ทดสอบกับข้อมูลใหม่ 2,000 แถวที่ไม่เคยเห็น (ข้อมูลตัดขวาง ไม่มีแกนเวลา จึงสุ่มชุดใหม่ได้ตรง ๆ)
rg = np.random.default_rng(77)
X2 = rg.normal(0, 1, (2000, 2))
y2 = (0.8*X2[:,0] - 0.5*X2[:,1] + rg.normal(0, 1, 2000) > 0).astype(int)
p2 = m.predict_proba(X2)[:, 1]                       # ★ คอลัมน์ 1 = P(y = 1) — คอลัมน์ 0 คือ P(y = 0)
print("accuracy out-of-sample", round(((p2 > 0.5) == y2).mean(), 3))
# accuracy out-of-sample 0.737

# ★ ตาราง calibration — หัวใจของบล็อกนี้: โมเดลบอก 70% แล้วเกิดจริง 70% ไหม
edges = [0, .2, .4, .6, .8, 1.01]
for lo, hi in zip(edges[:-1], edges[1:]):
    b = (p2 >= lo) & (p2 < hi)
    print(f"P ใน [{lo:.1f},{hi:.1f})  n={b.sum():4d}  ทำนายเฉลี่ย {p2[b].mean():.3f}  เกิดจริง {y2[b].mean():.3f}")
# P ใน [0.0,0.2)  n= 333  ทำนายเฉลี่ย 0.122  เกิดจริง 0.105
# P ใน [0.2,0.4)  n= 450  ทำนายเฉลี่ย 0.302  เกิดจริง 0.309
# P ใน [0.4,0.6)  n= 460  ทำนายเฉลี่ย 0.501  เกิดจริง 0.513
# P ใน [0.6,0.8)  n= 474  ทำนายเฉลี่ย 0.699  เกิดจริง 0.726
# P ใน [0.8,1.0)  n= 283  ทำนายเฉลี่ย 0.876  เกิดจริง 0.912

หมายเหตุ: ตัวเลขผลลัพธ์คำนวณจาก objective เดียวกับ sklearn (½·Σβ² + C·log-loss, C = 1) ด้วย Newton's method · sklearn ใช้ lbfgs จึงอาจต่างในทศนิยมที่สาม

✅ อ่านผลทีละบรรทัด — และสิ่งที่ห้ามคาดหวัง
  • coef [1.158, −0.643] ทั้งที่เราปลูกไว้ 0.8 กับ −0.5 — ไม่ใช่บั๊ก · เราสร้าง y ด้วย noise ปกติ N(0, 1) สเกลของ log-odds จึงไม่ตรงกับตัวเลขที่ปลูก · สิ่งที่ต้องได้คืนคือเครื่องหมาย (ถูกทั้งคู่) และลำดับความสำคัญ (x₁ แรงกว่า x₂: อัตราส่วน 1.158/0.643 = 1.80 เทียบ 0.8/0.5 = 1.6 ที่ปลูก ส่วนต่างคือความคลาดเคลื่อนจากการสุ่มที่ n = 400) · อย่าอ่าน β ของ logistic เป็นหน่วยเดียวกับ β ของ OLS

  • accuracy 0.690 ในชุดฝึก แต่ 0.737 ในชุดใหม่ — ชุดใหม่สูงกว่าซึ่งไม่ควรเกิดถ้าโมเดล overfit · มันคือความเหวี่ยงของตัวอย่างแบบเดียวกับ §12.1: 400 แถวชุดฝึกบังเอิญมี noise หนักกว่า · บทเรียนคือ accuracy ตัวเดียวมีช่วงความไม่แน่นอนเหมือน R² และ 0.69 กับ 0.74 อาจเป็นโมเดลตัวเดียวกัน · ฐานเทียบ: ทายว่า "ขึ้น" ทุกแถวได้ 0.506 ในชุดใหม่ (0.503 ในชุดฝึก)
  • ตาราง calibration คือของจริง — อ่านทีละแถว: กลุ่มที่โมเดลบอก 0.699 เกิดขึ้นจริง 0.726 · กลุ่มที่บอก 0.876 เกิดจริง 0.912 · ทุกแถวอยู่ใกล้กันในระดับสองทศนิยม แปลว่าเมื่อโมเดลพูด "70%" มันเกิดราว 70% จริง · accuracy บอกเรื่องนี้ไม่ได้เลย — โมเดลที่ทำนาย 0.51 กับ 0.99 ให้ทุกแถวอาจได้ accuracy เท่ากัน แต่ตัวหนึ่งเอาไปตั้งขนาดสถานะได้ อีกตัวเอาไปเจ๊ง
✅ ใช้ได้เมื่อไร
  • y เป็นสองประเภทจริง ๆ และคำถามของคุณคือ "บ่อยแค่ไหน" ไม่ใช่ "เท่าไร" — ถ้าอยากรู้ขนาดให้กลับไป regression ของ เล่ม 2 · A §2.2
  • ความสัมพันธ์บนสเกล log-odds ใกล้เส้นตรง — หรือคุณสร้างฟีเจอร์ (x², x₁·x₂) ให้มันเป็นเช่นนั้น
  • มีเหตุการณ์ฝั่งละมากพอ · ประเภทที่หายาก (เช่นวันร่วงเกิน 5%) ต้องมีตัวอย่างหลายสิบถึงหลายร้อยครั้ง ไม่ใช่หลักหน่วย
  • ต้องการโมเดลที่อ่านได้ทุกตัวเลข และเป็นฐานเทียบก่อนลองอะไรที่ซับซ้อนกว่า
❌ พังเมื่อไร — ห้าจุดที่สูตรทำงานถูกแต่คุณอ่านผิด
  • accuracy เป็นมาตรที่ผิดเมื่อสองฝั่งไม่สมดุล — ถ้าวันขึ้นเป็น 90% ของตัวอย่าง โมเดล "ทายขึ้นตลอด" ได้ accuracy 90% โดยไม่รู้อะไรเลย · ต้องเทียบกับฐานทายฝั่งใหญ่เสมอ (ในตัวอย่างเรา 0.506)
  • accuracy เป็นมาตรที่ผิดเมื่อผลตอบแทนไม่สมมาตร — ใช้กรอบเส้นเสมอตัวของ NQ Part 0: โมเดลถูก 52% กับเป้า ±2% ต้นทุน 0.2% ได้ 0.52 × 2 − 0.48 × 2 − 0.2 = −0.12% ต่อไม้ (ขาดทุน) · โมเดลถูกแค่ 45% แต่ชนะได้ +3% แพ้เสีย −1.5% ได้ 0.45 × 3 − 0.55 × 1.5 − 0.2 = +0.325% ต่อไม้ (กำไร) · accuracy ไม่รู้ทั้งขนาดและต้นทุน จึงเรียงโมเดลผิดลำดับได้ทั้งสองทาง
  • calibration สำคัญกว่า accuracy เมื่อจะตั้งขนาด — Kelly (b = 1) ให้ f* = 2p − 1: โมเดลที่บอก p = 0.60 สั่งลง 20% ของพอร์ต ถ้าความจริงคือ 0.52 ควรลงแค่ 4% · ต่างกัน 5 เท่าจากโมเดลที่ accuracy อาจเท่ากันเป๊ะแต่ "มั่นใจเกินคำบอก" · ดูตาราง calibration ก่อนคำนวณ Kelly ทุกครั้ง
  • เส้นตัด 0.5 เป็นค่าที่ใครก็ตั้งได้ ไม่ใช่ค่าที่สูตรให้ — เหมือน 70/30 ของ RSI ใน NQ App E ที่มาจากประสบการณ์ของคนคนหนึ่ง · 0.5 คือเส้นที่ทำให้ "ถูกบ่อยที่สุด" ไม่ใช่ "ได้เงินมากที่สุด" · กับต้นทุน 0.2% และเป้า ±2% เส้นที่ควรเริ่มเทรดคือ 0.55 ไม่ใช่ 0.5 · เส้นตัดต้องมาจากต้นทุนและ payoff ไม่ใช่จากโมเดล
  • leakage ผ่าน CV ที่สลับเวลา — cross_val_score กับ classifier ใช้ StratifiedKFold โดยปริยาย ซึ่งจัด fold ให้สัดส่วน 0/1 เท่ากันโดยหยิบตัวอย่างข้ามช่วงเวลาทั้งหมด · ผลคืออนาคตปนในชุดฝึกแบบ §12.3 เป๊ะ · ต้องส่ง TimeSeriesSplit เอง และถ้าป้าย y คือ "ขึ้นภายใน 5 วันข้างหน้า" ป้ายจะทับซ้อนกันข้ามแถว ต้อง purging ตาม §12.4 · อีกจุดเชิงเทคนิค: ถ้าสัญญาณแยก 0/1 ในชุดฝึกได้สมบูรณ์ (perfect separation) β ที่ไม่มีค่าปรับจะพุ่งไปไม่จำกัด — sklearn ไม่ฟ้องเพราะ C กดไว้ ตัวเลขที่ได้จึงเป็นของค่าปรับ ไม่ใช่ของข้อมูล

  • β ทุกตัวอ่านเป็น "odds คูณ e^β" ได้ — อธิบายให้คนที่ไม่ใช่ควอนต์ฟังได้ในประโยคเดียว
