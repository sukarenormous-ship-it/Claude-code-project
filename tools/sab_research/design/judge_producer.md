## 1. สรุปคำตัดสิน

**ผู้ชนะ: A_story "เชือกที่ผูกสองราคา" — แบบมีเงื่อนไข: ต้องรับ "เครื่องจักรการผลิต" ของ D และตัวคุมขอบเขตของ C ก่อนเริ่มเฟส 1**

เหตุผลแบบผู้ผลิต:

1. **D ผลิตง่ายที่สุดแต่ตกเกณฑ์ "ห้ามให้แบบที่เป้าหมายผู้อ่านต่ำชนะ"** — D เก็บร้อยแก้วต้นฉบับ ~59% (D §0 ประกาศเอง) ซึ่งเป็นร้อยแก้วที่ผู้ตรวจ 11 คนให้ U เฉลี่ย 2.4 (brief) และคงเสียง "คุณ" ของต้นฉบับ มินโผล่เฉพาะฉากเปิด/🎬/🧮 (D §0) ต่างจากเล่ม nq ที่ผู้อ่านกลุ่มนี้อ่านจบได้ D เองตั้งงบสำรอง 2 session "เขียนใหม่ระดับย่อหน้าในบทที่ได้ U < 4" (D §10.2 ข้อ 1) — ยอมรับว่าความเสี่ยงหลักคือ U ไม่ถึง ผมจึงไม่ให้ D ชนะ แต่ D มีเครื่องมือการผลิตที่ดีที่สุดในสี่แบบ ซึ่งผู้ชนะต้องรับไป
2. **A, B, C ต้นทุนการผลิตจริงใกล้กัน (ราว 28–34 session ทั้งสามแบบ เมื่อคิดด้วยอัตราเดียวกัน — ดูข้อ 3)** ตัวตัดสินจึงเป็น "ความเสี่ยงที่คุมได้ด้วยสายพาน" กับ "เกณฑ์ผ่านที่ตรวจได้ในสภาพแวดล้อมนี้"
   - ความเสี่ยงหลักของ A คือ ripple (แก้บทหนึ่งกระทบทุกบทหลัง) แต่ A คุมด้วยกลไกที่ตรงปรัชญาสายพานเดิมพอดี: สถานะเรื่อง `เรื่อง.partN.open/close` และ 📒 บัญชีมินอยู่ใน JSON แล้ว `sab_check_figures.py` ตรวจ "open = close ของบทก่อน" อัตโนมัติ (A §9.1, §10.2 ข้อ 2) — เป็นการต่อยอดกฎเหล็ก "ห้ามพิมพ์ตัวเลขลอย" ไปสู่ "ห้ามพิมพ์สถานะเรื่องลอย"
   - ความเสี่ยงหลักของ B คือของนอกบทบวม (สมุดงาน xlsx + แฟ้มเปล่า + แฟ้มกรอกแล้ว + 16 ใบ + 21 กล่อง/บท + กราฟ ~30 ฟังก์ชัน) และ **เกณฑ์ผ่านเฟส 2, 3, 5 ต้องใช้มือใหม่ตัวจริง 2–3 คน** (B §10.1) ซึ่งสภาพแวดล้อมนี้ไม่มี — เกณฑ์ตรวจไม่ได้หรือขวางงาน
   - ความเสี่ยงหลักของ C คืองานวิศวกรรมตัวเลขใหม่มากที่สุด (การศึกษาใหม่ 9 ชุด หนึ่งชุดยัง "ต้องออกแบบพารามิเตอร์" C §9.4) + เปลี่ยนค่าธรรมเนียมเป็นอัตราเดียวจนตัวเลขที่ผู้ตรวจยืนยันแล้วของ 06.05 เปลี่ยนทั้งชุด (820/1,120/−80→+340/+325→−45 กลายเป็น 700/1,000/−200→+220/205→−165) + ขอบเขตใหญ่สุด (กราฟ 33 ตำแหน่ง, เครื่องมือ 8, ภาคผนวก 8, ใบงาน 17) + เกณฑ์เฟส 3 ต้องมีผู้อ่านทดลอง 3 คน
3. **A ได้คะแนนผู้อ่านสูงในช่องที่ผู้ผลิตแก้ทีหลังไม่ได้ (U)** — ลำดับแนวคิดผูกกับกระดูกสันหลังเรื่อง ขณะที่จุดอ่อนของ A ส่วนใหญ่เป็น "ขอบเขต/การบัญชีงาน" ซึ่งแก้ได้ด้วยการรับของจากแบบอื่น (ข้อ 5) โดยไม่ต้องรื้อสารบัญ

## 6. คำตัดสินในหนึ่งย่อหน้า

ในเลนส์การผลิต D คือแบบที่ทำได้เร็วและเสี่ยงต่ำที่สุด (ใช้ร้อยแก้วเดิม ~59%, ตรวจครอบคลุมหัวข้อได้ด้วยสคริปต์, ปล่อย M1 ได้ที่ ~12 session) แต่ถูกตัดสิทธิ์ชนะเพราะเก็บร้อยแก้วและเสียงที่ผู้ตรวจให้ U เฉลี่ย 2.4 ไว้ · A, B, C มีต้นทุนจริงใกล้กัน (~32–35 session ทั้งสามแบบเมื่อคิดอัตราเดียวกัน; A และ B ประเมินตัวเองต่ำเกินจริง) A ชนะเพราะความเสี่ยงหลักของ A (ripple ของเรื่องต่อเนื่อง) ถูกคุมด้วยกลไกที่เป็นธรรมชาติของสายพานเดิม (สถานะเรื่องใน JSON + ตรวจ open = close อัตโนมัติ) ใช้ตัวเลขที่ผู้ตรวจยืนยันแล้วของภาค 1 ครบ และเกณฑ์ผ่านตรวจได้ด้วยสคริปต์ + persona subagent ขณะที่ B พึ่งมือใหม่ตัวจริงในสาม gate และของนอกบทบวม ส่วน C ต้องวิศวกรรมตัวเลขใหม่มากที่สุดและเปลี่ยนชุดเลขที่ยืนยันแล้ว · A ชนะแบบมีเงื่อนไข: ต้องรับ `sab_extract.py` + ป้ายที่มา + errata + G1 diff = 0 + M1 = ภาค 1 + รวมเครื่องมือเหลือ 4 จาก D, แบ่งชั้นกราฟ/เครื่องมือ + qa จับข้อผิดที่จงใจใส่ + เรียงบทเป็นตัวเลข + `_claims` + จุดตัดสินรวมบทจาก C, และ markup ใบงาน `data-key` จาก B ก่อนเริ่มเฟส 1 — บัญชีงานที่ถูกต้องหลังรับ graft คือราว 28–30 session ไม่ใช่ 18–21
