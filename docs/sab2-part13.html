ต้นส่งไฟล์มาพร้อมข้อความสั้น ๆ ว่า "คู่ P–Q ชนะทุกเดือน ปีเดียวได้ +576.38 จากทุน 1,000" ตารางสรุปท้ายไฟล์มีสิบสองเดือน เดือนที่มีไม้ปิดเป็นบวกทุกเดือน ไม่มีเดือนไหนติดลบเลย

มินส่งต่อให้พี่ฝนในกลุ่มอ่านหนังสือ คำตอบกลับมาเป็นคำถามเดียว "ตัวเลขทุกช่องในไฟล์นี้ รู้ได้วันไหน"

เขาเปิดสมุดเขียนสี่บรรทัด

  1. คาดกำไรจากอะไร — ระยะห่างของ P กับ Q ที่ยืดออกแล้วกลับ
  2. ถืออะไรจริง — ยังไม่รู้ ไฟล์บอกแต่กำไร ไม่บอกว่าวันไหนถืออะไร
  3. เงินในบัญชีเปลี่ยนอย่างไร — ยังไม่รู้ ไม่มีบัญชีทีละวัน
  4. ใครจ่าย และเมื่อไรเงินนี้จะหาย — ถ้าไฟล์ใช้ข้อมูลที่ตอนนั้นยังไม่มี ก็ไม่มีใครจ่ายเลย
backtest ที่ไม่หลอกตัวเองต้องมีชิ้นส่วนอะไรบ้าง และจะจับได้อย่างไรว่าสเปรดชีตแอบใช้ข้อมูลที่ ณ วันนั้นยังไม่มีใครรู้

มินตัดสินใจไม่เถียงกับตัวเลขของต้น เขาจะสร้างเครื่องของตัวเองก่อน แล้วเอาคู่ P–Q มาเดินในเครื่องนั้น ถ้าผลตรงกับของต้นก็ดีไป ถ้าไม่ตรง เขาจะรู้ว่าต่างกันตรงไหน เครื่องแบบนี้เล่ม 1 เรียกว่า Backtest (การทดสอบย้อนหลัง) ในบท 15 และภาคผนวก I เคยให้โครงของวงหลักไว้แล้ว บทนี้จะเดินวงนั้นด้วยมือทีละวัน

เริ่มจากคู่ที่คุ้นที่สุด คือคู่ A–B ของเล่ม 1 หนึ่งชุดคือ A หนึ่งเหรียญกับ B สองเหรียญทางตรงข้าม X จึงเท่ากับ A − 2B ไม้บรรทัดของคู่นี้วัดจาก 20 วันในบท 9 ของเล่ม 1 ได้ Mean 0 กับ SD 1 ไม้บรรทัดนี้วัดไว้ ก่อน สิบวันที่เราจะเดิน และไม่ถูกแก้ระหว่างทาง ทุกวัน Z-score (ค่ามาตรฐาน) จึงเท่ากับ X ของวันนั้นพอดี

🚶 อ่านเป็นภาษาคนก่อน: Equity ของวันใดก็ตามคือเงินที่จะเหลือถ้าปิดทุกอย่างที่ราคาปิดวันนั้น จึงเท่ากับเงินสดบวกมูลค่าของที่ถือ ของที่ติดลบคือภาระที่ต้องซื้อคืน จึงลดมูลค่าลง

Equity = เงินสด + จำนวน A ที่ถือ × ราคา A + จำนวน B ที่ถือ × ราคา B

เฉลย 🛑: ถ้ายอมให้ได้ราคาวันที่เห็นสัญญาณ ไม้นี้จะเข้าที่ X 2.3 และออกที่ X 0.4 X ลดลง 1.9 สิบชุดได้ 19 ค่าธรรมเนียมคิดจากราคาวันที่ 3 และวันที่ 7 ได้ 1.05 กับ 0.99 รวม 2.04 เท่าเดิม สุทธิจึงเป็น 16.96 และ Equity จบที่ 1,016.96 มากกว่าของจริง 6 ส่วนที่ต่าง 6 นี้มาจากสองที่ ตอนเข้าได้มากกว่า 10 × (2.3 − 2) หรือ 3 และตอนออกได้มากกว่า 10 × (0.7 − 0.4) อีก 3

ไม่มีใครจ่าย 6 ส่วนนี้ เพราะไม่มีใครซื้อขายที่ราคาที่ยังไม่เกิดได้ เครื่องจึงต้องมีกติกาที่บอกชัดว่าคำสั่งได้ราคาเมื่อไรและเท่าไร กติกานี้มีชื่อว่า Fill Model (แบบจำลองการได้ราคา) ของมินคือ "ได้ราคาปิดวันถัดไป ครบทั้งสองขา บวกค่าธรรมเนียม 0.05% ของมูลค่า" ซึ่งเป็นกติกาที่ง่ายที่สุดที่ยังซื่อ แต่ก็ยังเป็นการสมมติอยู่ดี

def backtest(A, B, h, z, sets, lag=1, fee=0.0005, enter=2, leave=0.5, hold=30):
    cash, held, t_in, eq, n = 1000.0, 0, 0, [], 0   # held: +1 = long X · -1 = short X
    for t in range(len(A)):
        if t >= lag:
            zt = z[t - lag]                     # 1) รู้อะไร: Z ของวัน t - lag
            want = held                         # 2) สัญญาณ
            if held == 0 and abs(zt) >= enter: want = -1 if zt > 0 else 1
            elif held != 0 and (abs(zt) <= leave or t - t_in >= hold): want = 0
            if want != held:                    # 3) คำสั่ง  4) ได้ราคาปิดวัน t
                qa, qb = (want - held) * sets, -(want - held) * sets * h
                cash -= qa * A[t] + qb * B[t] + fee * (abs(qa) * A[t] + abs(qb) * B[t])
                held, t_in, n = want, t, n + 1
        eq.append(cash + held * sets * (A[t] - h * B[t]))   # 5) ลงบัญชี
    return eq, n

from sab2_realdata import load_closes
import sab2_stats as S

def backtest(A, B, h, z, sets, lag=1, fee=0.0005, enter=2, leave=0.5, hold=30):
    cash, held, t_in, eq, n = 1000.0, 0, 0, [], 0
    for t in range(len(A)):
        if t >= lag:
            zt, want = z[t - lag], held
            if held == 0 and abs(zt) >= enter: want = -1 if zt > 0 else 1
            elif held != 0 and (abs(zt) <= leave or t - t_in >= hold): want = 0
            if want != held:
                qa, qb = (want - held) * sets, -(want - held) * sets * h
                cash -= qa * A[t] + qb * B[t] + fee * (abs(qa) * A[t] + abs(qb) * B[t])
                held, t_in, n = want, t, n + 1
        eq.append(cash + held * sets * (A[t] - h * B[t]))
    return eq, n

_, f = load_closes("formation", coins=["BTC", "ETH"])     # ค่าทุกตัววัดจากช่วงเลือก
_, v = load_closes("validation", coins=["BTC", "ETH"])    # เดินในช่วงตรวจ
slope = S.ols(f["ETH"], f["BTC"])["slope"]; h = round(slope)
X = [a - h * b for a, b in zip(f["BTC"], f["ETH"])]; m, s = S.mean(X), S.sd(X)
z = [(a - h * b - m) / s for a, b in zip(v["BTC"], v["ETH"])]
eq, n = backtest(v["BTC"], v["ETH"], h, z, 0.01)
print(round(slope, 2), round(eq[-1] - 1000, 2), n)

  2. ชีต "ชนะทุกเดือน" ของต้นมี Look-ahead Bias สามแบบ คือ h และไม้บรรทัดที่วัดจากทั้งปี กับราคาที่ได้ในวันสัญญาณ แก้ทีละจุดได้ +576.38 → +119.22 → −20.62 → −19.87 และใน 30 โลกที่ไม่มีเชือก ชีตเดิมบวกครบทุกโลก ส่วนเครื่องที่ซื่อมี Median −46.51
  3. บนคู่ BTC–ETH ที่วัดค่าจากช่วงเลือกแล้วเดินในช่วงตรวจ เครื่องที่ซื่อได้ −55.53 และ Equity เคยลงถึง 608.92 ส่วนชีตที่โกงได้ +169.23 ผลยังไวต่อ Fill Model (ช้าอีกวันได้ +38.91) และ Universe 10 เหรียญเป็นรายชื่อของผู้รอด

    เฉลย

🔎 ลงลึก: ลำดับเหตุการณ์ในหนึ่งวัน และทำไม lag ต้องอยู่ที่สัญญาณ

เครื่องในหน้านี้ย่อหนึ่งวันเหลือเหตุการณ์เดียว (ราคาปิด) แล้วให้คำสั่งที่ตัดสินจาก Zt−1 ได้ราคาปิด Pt ซึ่งเท่ากับ "ส่งคำสั่งหลังปิดวัน t−1 ได้ราคาปิดวัน t" ถ้าข้อมูลถี่กว่ารายวัน วงจะต้องมีลำดับย่อยในเหตุการณ์เวลาเดียวกัน: fill ของคำสั่งค้าง → อัปเดตราคา mark → เงินโอน (funding) → คิด Equity → คิดสัญญาณ → ส่งคำสั่งใหม่ แบบภาคผนวก I ของเล่ม 1

ในสเปรดชีตหรือ pandas การเลื่อนต้องอยู่ที่สถานะ ไม่ใช่ที่ผลตอบแทน: pnlt = post−1 × (Xt − Xt−1) โดย post−1 ตัดสินจากข้อมูลถึง t−1 · ถ้าเขียน post × (Xt − Xt−1) ก็คือ lag = 0 · เครื่องในหน้านี้ใช้รูปแบบสมุดบัญชี (เงินสด + ของที่ถือ × ราคา) จึงได้ค่าธรรมเนียมตามมูลค่าจริงของแต่ละ fill และ Equity ตรงกับการคิดจาก X ทุกเซนต์

โลกของต้น: log P = α + log Q + wt + et โดย w เดินสุ่ม SD 0.003 ต่อวัน และ e เป็น AR(1) ที่ φ = 0 SD 0.015 · et ไม่บอกอะไรเกี่ยวกับ et+1 ส่วนที่ "กลับ" จึงหายก่อน fill วันถัดไปเสมอ ค่าคาดหวังของเครื่องที่ซื่อจึงเท่ากับ −ค่าธรรมเนียม (บวกส่วนที่ w ให้โดยบังเอิญ) · ชีตที่ได้ราคาวันสัญญาณเก็บ et ที่ ≥ 2 SD ได้ทุกไม้ จึงชนะ 11 จาก 11 ไม้
