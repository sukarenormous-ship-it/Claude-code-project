บทที่ 4: หลักการคิดแบบ Arbitrageur

บทนี้ไม่ได้สอนสูตร — สอนวิธีมองโลกที่ทำให้เห็น Arb ที่คนอื่นมองไม่เห็น

4.1 หลักการที่ 1: "ของเดียวกันต้องราคาเดียวกัน"

ทุกครั้งที่เห็นสินทรัพย์ ถามว่า: "มีวิธีอื่นสร้าง payoff เดียวกันไหม? ราคาเท่ากันไหม?"

ฝึก

เห็น SET50 Futures → ถามทันที: "Spot × e^((r-d)T) เท่าไร? ตรงกับ Futures price ไหม?"
เห็น Call K=100 → ถามทันที: "P + S - PV(K) เท่าไร? ตรงกับ Call price ไหม?"

4.2 หลักการที่ 2: "ถ้าสร้างเองได้ = รู้ราคา"

ราคาที่ถูกต้อง = ต้นทุน replicate ถ้าราคาจริง ≠ ต้นทุน replicate → opportunity

4.3 หลักการที่ 3: "ได้อะไรมาต้องเสียอะไรไป"

ถ้าเจอ "กำไรแน่นอน 5% ต่อวัน" → 99% มี risk ซ่อนอยู่

Devil's Advocate Checklist

เจอ "arb" แล้วถามตัวเอง 6 ข้อ:
1. ข้อมูลผิดหรือเปล่า? (stale quote, wrong symbol)
2. ค่าธรรมเนียมคิดครบไหม?
3. Liquidity จริงไหม? (bid-ask wide, size เล็ก)
4. Execute ได้ทั้ง 2 ขาพร้อมกันไหม?
5. มี structural reason ไหม? (ex-div, corporate action)
6. ทำไมคนอื่นไม่ทำ? ← ข้อสำคัญที่สุด

4.4 หลักการที่ 4: "ไม่รู้ exact แต่รู้ขอบเขต"

ราคานอกขอบเขต = Arb ที่พิสูจน์ได้ เช่น Call ≥ max(0, S-Ke⁻ʳᵀ) ← ถ้า Call < ค่านี้ → ซื้อทันที

4.5 หลักการที่ 5: "ลำดับต้องถูก"

Monotonicity: C(K₁) ≥ C(K₂) เมื่อ K₁ < K₂ ← Call ถูกลงเมื่อ Strike สูงขึ้น
Convexity: C(K₁) - 2C(K₂) + C(K₃) ≥ 0 ← Butterfly ต้อง ≥ 0
(เมื่อ K₂ = (K₁+K₃)/2 คือ strikes ห่างเท่ากัน; สำหรับ strikes ไม่เท่ากันใช้ weighted version)

📖 อ่านสูตรว่า: "ซีของเคหนึ่ง มากกว่าหรือเท่ากับ ซีของเคสอง เมื่อ เคหนึ่ง น้อยกว่า เคสอง" — สิทธิ์ซื้อที่ราคาถูกกว่า ต้องมีค่าไม่น้อยกว่า · โครงที่ต้องเห็น: บรรทัดแรกคือลำดับ (ราคา Call ไม่เพิ่มเมื่อ K เพิ่ม) บรรทัดสองคือความโค้ง (ผลต่างของผลต่าง ≥ 0) · ลองให้ C เป็นเส้นตรงใน K: C(K₁) − 2C(K₂) + C(K₃) = b(K₁ + K₃ − 2K₂) = 0 พอดีเมื่อ K₂ เป็นจุดกึ่งกลาง — นี่คือเหตุที่เงื่อนไข "ห่างเท่ากัน" ต้องมี · กับดักการอ่าน: วงเล็บหลัง C คือ strike ไม่ใช่คูณ · เลข 2 หน้า C(K₂) คือน้ำหนัก (ขาย 2 สัญญา) ไม่ใช่ตัวห้อย · ตัวห้อย 1–3 เป็นหมายเลข strike จากต่ำไปสูง (ทวนจาก Part I บท 3)

4.6 หลักการที่ 6: "Call บอก Put, Put บอก Call"

จาก PCP: รู้ Call → คำนวณ Put ได้ทันที ถ้า market price ≠ theoretical → opportunity

4.7 หลักการที่ 7: Generalized Option Thinking ★

แนวคิดจาก quant-arb-engine

"ทุกอย่างที่มี conditional payoff คือ option" — ไม่ใช่แค่ Call/Put บน exchange

สิ่งที่เห็นHidden Option ที่ซ่อนอยู่วิธีคิด
Funding rateOption on carry regimeจ่ายถ้า basis กว้าง รับถ้าแคบ
Stop-loss orderSynthetic put (มี execution risk)"ถ้าราคาลงถึง X ขายทันที" = put ที่อาจ slip
Earn yield 11%Option on platform solvencyได้ 11% ถ้า platform ไม่ล้ม
PM Yes/NoNative digital optionจ่าย $1 ถ้าเหตุการณ์เกิด
Weekend price gapOption on reference absenceราคา crypto เคลื่อนไหวแต่ TradFi ปิด
Convert rate gapInstant exercise option on pricing lagถ้าราคา convert ≠ spot → arb ทันที
Liquidation cascadePath-dependent barrier event"ถ้าราคาลงถึง X → forced selling เพิ่ม"
กระบวนการ: เห็น conditional payoff → จัดหมวด → ใช้ประโยชน์

ทุกครั้งที่เจอ conditional payoff ถามว่า:
1. Underlying คืออะไร? (ราคาหุ้น, solvency, เวลา?)
2. Strike/threshold อยู่ที่ไหน?
3. Expiry เมื่อไร?
4. Shape: linear, convex, binary?
5. Long/Short?
6. สามารถ combine กับ block อื่นได้ไหม?

ลองคิดดู (บท 4)

1. Earn yield 15% APR บน platform ใหม่ — นี่คือ [Exact Identity] หรือ [Heuristic]? อะไรคือ "hidden option" ที่ซ่อนอยู่?
2. เห็น Call K=100 ราคา ฿6 แต่ Long Stock + Long Put(100) ราคารวม ฿5 → เกิดอะไรขึ้น? ทำอะไรได้?
เฉลย: 1. [Heuristic] — hidden option on platform solvency ถ้า platform ล้ม=เสียทั้งหมด 2. Synthetic Call ราคา ฿5 < real Call ฿6 → ซื้อ synthetic ขาย real = Arb ฿1

เรื่องจริง: "ตัดไฟตั้งแต่ต้นลม"

ปี 2022 นักลงทุนหลายคนฝากเงินใน Celsius Network (crypto lending) เพราะ yield 17% — treat เหมือน [Exact Identity] ทั้งที่จริงเป็น [Heuristic — Untested]
ผลลัพธ์: Celsius ล้มละลาย สูญเสียรวม $4.7 billion
บทเรียน: ถ้า label claim ถูกระดับตั้งแต่แรก จะ size เล็กลง หรือไม่ทำเลย

บทที่ 5: Payoff Algebra — "เขียนสิ่งที่อยากได้เป็นสมการ แล้ว solve"

หนังสือส่วนใหญ่สอนย้อนกลับ: "นี่คือ Bull Call Spread มันมีหน้าตาแบบนี้"
บทนี้สอนไปข้างหน้า: "คุณอยากได้ payoff แบบนี้ → ต้องใช้ instruments อะไร?"

5.1 Building Blocks — ชิ้นส่วนที่ใช้ประกอบ

2 ชั้น ที่ต้องคิดพร้อมกัน:

5.2 Step 1: เขียน Desired Payoff เป็น Piecewise Function

ตัวอย่าง: "อยากได้กำไรถ้าราคาขึ้น แต่ไม่เกิน 2500 ไม่อยากเสียถ้าลง"

แปลเป็น piecewise:

P(S) = { 0           ถ้า S < 2000 (ราคาปัจจุบัน)
       { S - 2000   ถ้า 2000 ≤ S ≤ 2500
       { 500        ถ้า S > 2500

📖 อ่านสูตรว่า: "พีของเอส เท่ากับ ศูนย์ ถ้า เอส น้อยกว่า 2000 · เท่ากับ เอส ลบ 2000 ถ้า เอส อยู่ระหว่าง 2000 ถึง 2500 · เท่ากับ 500 ถ้า เอส มากกว่า 2500" · โครงที่ต้องเห็น: ฟังก์ชันแบ่งช่วง — สามช่วง สามสูตร ปีกกาคือ "เลือกบรรทัดตามเงื่อนไขทางขวา" · เช็ครอยต่อ: S = 2000 ให้ 2000 − 2000 = 0 ตรงกับช่วงแรก S = 2500 ให้ 500 ตรงกับช่วงสาม ไม่มีรอยกระโดด · กับดักการอ่าน: P(S) คือ "payoff ที่เป็นฟังก์ชันของ S" — ตัว P ตรงนี้ไม่ใช่ราคา Put ในสูตร PCP ตัวอักษรเดียวกันคนละความหมาย ดูจากวงเล็บ (S) ที่ตามหลัง · พื้นฐานสัญกรณ์นี้อยู่ที่ เล่ม 1 Part I §1.6

5.3 Step 2: Decompose เป็น Known Building Blocks

Building block payoffs:
  Long Call(K)     = max(S - K, 0)
  Short Call(K)    = -max(S - K, 0)
  Call Spread(K₁,K₂) = max(S-K₁, 0) - max(S-K₂, 0)
  PM Above Yes(K) = 1 ถ้า S > K, else 0

📖 อ่านสูตรว่า: "Long Call ที่ K เท่ากับ ค่ามากสุดระหว่าง เอส ลบ เค กับ ศูนย์" · โครงที่ต้องเห็น: ทุกชิ้นเลโก้สร้างจาก max() ตัวเดียว — Short คือใส่เครื่องหมายลบหน้าทั้งก้อน (พลิกกราฟกลับหัว) Call Spread คือผลต่างของ max สองตัว ส่วน PM คือขั้นบันได คืน 1 หรือ 0 ไม่มีตรงกลาง · กับดักการอ่าน: max(S − K, 0) เลือกค่าเดียว ทิ้งอีกค่า — ข้อมูลว่า S ต่ำกว่า K "เท่าไร" หายไปตรงนั้น · K ในวงเล็บหลังชื่อ (Call(K), Above Yes(K)) คือพารามิเตอร์ของชิ้น ไม่ใช่ตัวแปร ตัวแปรมีตัวเดียวคือ S · ทวน max() และการพลิกเครื่องหมายที่ เล่ม 1 Part I §1.4–§1.5

5.4 Step 3: Solve — หา instruments ที่ตรงกัน

P(S) = { 0 ถ้า S < 2000, S-2000 ถ้า 2000≤S≤2500, 500 ถ้า S > 2500 }

นี่คือ: Call Spread(2000, 2500)
= max(S-2000, 0) - max(S-2500, 0)
= { 0        ✓ | S-2000   ✓ | 500 ✓ }

คำตอบ: ซื้อ 1× Call Spread (2000/2500)

5.5 ตัวอย่างซับซ้อน: Piecewise → PM + Options

"อยากได้ +$100 ถ้า S > 2500, +$50 ถ้า 2200 < S ≤ 2500, -$20 ถ้า S ≤ 2200"

Decompose by jumps:
  ที่ S=2200: payoff เปลี่ยนจาก -20 เป็น +50 (กระโดด +70)
  ที่ S=2500: payoff เปลี่ยนจาก +50 เป็น +100 (กระโดด +50)

P(S) = -20 + 70 × 1(S > 2200) + 50 × 1(S > 2500)

คำตอบ:
  -$20 (ต้นทุน entry)
  + 70 × PM Above Yes($2200) ← จ่าย $70 ถ้าเกิน 2200
  + 50 × PM Above Yes($2500) ← จ่าย $50 ถ้าเกิน 2500

📖 อ่านสูตรว่า: "พีของเอส เท่ากับ ลบยี่สิบ บวก เจ็ดสิบคูณ หนึ่งของ(เอส มากกว่า 2200) บวก ห้าสิบคูณ หนึ่งของ(เอส มากกว่า 2500)" — 1(·) คือฟังก์ชันตัวชี้ (indicator) คืน 1 เมื่อเงื่อนไขในวงเล็บจริง คืน 0 เมื่อไม่จริง · โครงที่ต้องเห็น: "ค่าฐาน บวก ผลรวมของ (ขนาดกระโดด × ตัวชี้)" — payoff แบบขั้นบันไดทุกแบบเขียนอย่างนี้ได้ หนึ่งตัวชี้ต่อหนึ่งรอยกระโดด · ลองแทน S = 2300: −20 + 70 + 0 = 50 ✓ · S = 2600: −20 + 70 + 50 = 100 ✓ · กับดักการอ่าน: "1(" ไม่ใช่เลขหนึ่งคูณวงเล็บ — เป็นชื่อฟังก์ชัน · สัมประสิทธิ์ 70 และ 50 คือจำนวนสัญญา PM ที่จ่าย $1 ต่อสัญญา ไม่ใช่ราคา

5.6 ตัวอย่างที่ 3: Collar (ป้องกันด้าน + จำกัดด้านบน)

"มีหุ้นอยู่ ฿2000 ไม่อยากเสียเกิน ฿200 แต่ยอมจำกัดกำไรที่ ฿300"

Piecewise:
  P(S) = { -200        ถ้า S < 1800
         { S - 2000    ถ้า 1800 ≤ S ≤ 2300
         { +300        ถ้า S > 2300

Decompose: Stock position (slope +1 from 2000)
  + Long Put(1800) → ตัดขาดทุนที่ -200
  + Short Call(2300) → จำกัดกำไรที่ +300

= Collar = Stock + Put(1800) + Short Call(2300)

📖 อ่านสูตรว่า: โครงเดียวกับ 5.2–5.4 อ่านทีละช่วง: ต่ำกว่า 1800 ค่าคงที่ −200 · ระหว่างนั้นความชัน +1 (หุ้นเปล่า) · เหนือ 2300 ค่าคงที่ +300 · โครงที่ต้องเห็น: ถอดชิ้นด้วยคำถาม "ความชันเปลี่ยนตรงไหน" — Long Put(1800) เพิ่มความชัน −1 ใต้ 1800 จนแบน Short Call(2300) เพิ่มความชัน −1 เหนือ 2300 จนแบน · ตรวจรอยต่อ: S = 1800 ให้ 1800 − 2000 = −200 ต่อกับช่วงแรกพอดี

พลังของ Payoff Algebra

ไม่ต้องจำชื่อกลยุทธ์ — เขียนสิ่งที่อยากได้เป็นสมการ → solve → ได้ instruments
สร้าง payoff shape อะไรก็ได้ที่นึกออก → ถ้า instruments มีอยู่ → สร้างได้!

ลองคิดดู (บท 5)

"อยากได้กำไร ฿100 ถ้าราคา > 2000 แต่ไม่อยากเสียเกิน ฿20" → เขียนเป็น piecewise → decompose เป็น instruments อะไร?
เฉลย: P(S) = {-20 ถ้า S≤2000, +100 ถ้า S>2000} = jump +120 ที่ 2000 → -20 + 120 × PM Above Yes(2000) หรือ -20 + 120 × tight Call Spread at 2000

บทที่ 6: Epistemology (ญาณวิทยา) — "รู้ว่ารู้อะไร แน่ใจแค่ไหน"

Arb ที่ดีต้องแยกได้ว่า: "สิ่งที่รู้แน่ 100%" vs "สิ่งที่แค่เดา" — ถ้าแยกไม่ได้ จะ treat heuristic เหมือน exact identity → อันตราย

6.1 4 ระดับความแน่ใจ

6.2 ตัวอย่าง: Label Claims ที่ถูกต้อง

ClaimLabel ที่ถูกทำไม
C + Ke⁻ʳᵀ = P + S[Exact Identity]จริงเสมอ ไม่มีเงื่อนไข (European)
PM Yes + PM No = $1.00[Exact Identity]โดย contract design
Polymarket ใช้ Binance price เป็น resolver[Contract-specific]อาจเปลี่ยน platform ได้ ต้องเช็ค
BTC funding rate = -0.002% เมื่อวาน[Observed]จริงเมื่อวาน วันนี้อาจต่างแล้ว
Funding rate มักจะ mean-revert[Heuristic]มักจริง แต่ไม่เสมอ (ช่วง bull run funding สูงนาน)
IV > RV → ขาย options ได้กำไร[Heuristic]ส่วนใหญ่จริง แต่ tail event ทำให้เจ็บหนัก
Common Mistake: Treat Heuristic เหมือน Exact Identity

"Funding rate จะกลับมา" ← ถ้า treat เหมือน [Exact Identity] → size ใหญ่เกินไป → เจ็บหนักเมื่อ funding ไม่กลับ
ต้อง label ว่า [Heuristic] → size เล็กลง → รับได้ถ้าผิด

6.3 วิธีใช้: Label ทุก claim ก่อนตัดสินใจ

เจอ "arb" → ก่อน execute ถามว่า:

1. Edge มาจากอะไร?
   → ถ้า PCP violation → [Exact] → size ได้เต็มที่
   → ถ้า "IV สูงเกินไป" → [Heuristic] → size ต้องเล็ก

2. ข้อมูลที่ใช้เป็น level ไหน?
   → ถ้า live quote → [Observed] → ยังต้องเช็ค stale ไหม
   → ถ้า "เมื่อเดือนก่อน IV ≈ 30%" → [Observed - stale] → ใช้ไม่ได้!
ลองคิดดู (บท 6)

"BTC funding rate ติดลบ 3 วันแล้ว → จะกลับเป็นบวกแน่ๆ" — นี่คือ claim ระดับอะไร? ควร size เท่าไร?
เฉลย: [Heuristic — Tested] ไม่ใช่ [Exact] → ห้าม size เต็ม ใช้ Half-Kelly หรือเล็กกว่า เพราะ funding อาจติดลบนานกว่าคาด
