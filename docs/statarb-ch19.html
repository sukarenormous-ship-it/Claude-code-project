Cost Analysis & Edge: คำนวณ Net Edge ก่อนเทรด

Gross spread − 2×fee (round-trip) − bid/ask − slippage − funding − legging buffer = Net edge
ถ้า net edge ≤ 0 → ไม่เทรด ไม่ว่า signal จะดูดีแค่ไหน
แก่นของบทนี้ — อ่านก่อน
Stat arb มีต้นทุนซ่อนอยู่หลายชั้น — signal ที่ดูมี edge 0.20% อาจมี net edge ลบหลัง cost หักออกทั้งหมด คำนวณก่อนเสมอ — ห้าม assume
$$\text{Net Edge} = \underbrace{\sigma_{\varepsilon}}_{\text{gross}} - \underbrace{2f_{\text{taker}} + \text{bid-ask} + \text{slippage} + \text{funding}}_{\text{costs}}$$

ถ้า latency ไม่ critical → ใช้ limit order (maker) ทั้งคู่ — ลด cost จาก 0.17% เป็น 0.02% ต่อ round trip แต่ risk partial fill และ leg mismatch เพิ่มขึ้น

⚠️ ตัวเลขนี้ยังไม่หัก adverse selection cost ของการเป็น maker — fill ที่ได้จริงไม่ใช่ sample สุ่ม แต่ bias ไปทาง fill ที่แย่กว่า (ดู §19.10) ก่อนเชื่อว่า maker "ประหยัดฟรี" ต้องวัด markout หลัง fill ก่อนเสมอ

19.3 Bid-Ask Spread Cost

Cost per leg = (Ask − Bid) / 2 = half-spread สำหรับ 2 legs round trip: Total bid-ask cost = half-spread_A + half-spread_B ตัวอย่าง Bybit BTC: Bid = 65,000, Ask = 65,002 Half-spread = $1 = 1/65,000 = 0.0015% Lighter BTC: Bid = 64,998, Ask = 65,001 Half-spread = $1.50 = 0.0023% Total: 0.0015% + 0.0023% = 0.0038% ต่อ direction Round trip (entry + exit): 0.0076% ≈ 0.008%

19.4 Slippage Model

Market impact (slippage) เพิ่มขึ้นตาม size ที่เทียบกับ average daily volume:

Slippage ≈ σ_daily × sqrt(size / ADV) โดย: σ_daily = daily volatility ของ asset size = ขนาด order (notional) ADV = average daily volume (notional) ตัวอย่าง: σ_daily = 0.02 (2%) size = $100,000 ADV = $500,000,000 (Bybit BTC perp ~$500M/day) Slippage = 0.02 × sqrt(100,000/500,000,000) = 0.02 × 0.014 = 0.00028 = 0.028%

19.5 Funding Cost

Funding cost ต่อ 8h = |funding_rate| × notional Total funding cost = funding_rate × hold_periods × notional ตัวอย่าง: Funding rate = 0.01% ต่อ 8h (positive → longs จ่าย) Hold time = 2 funding periods = 16h Notional = $100,000 Cost (ถ้า short perp) = +0.01% × 2 × $100,000 = +$20 (รับ) Cost (ถ้า long perp) = −0.01% × 2 × $100,000 = −$20 (จ่าย)
Funding Direction ขึ้นกับ Position

ถ้า basis > 0 และ short perp → รับ funding (ลด cost)
ถ้า basis > 0 และ long perp → จ่าย funding (เพิ่ม cost)
ต้องคำนวณรวมในทุก scenario ก่อน decide trade direction

19.6 Legging Buffer

Legging risk = ความเสี่ยงจากช่วงเวลาระหว่าง fill leg A และ fill leg B ในช่วงนั้น position เป็น single-leg → exposed ต่อ market movement Legging buffer estimate: buffer = σ_spread × sqrt(avg_fill_latency_s / seconds_per_period) ตัวอย่าง: σ_spread = 0.05% per period avg_fill_latency = 0.5 วินาที seconds_per_period = 60 วินาที (1 นาที) buffer = 0.05% × sqrt(0.5/60) = 0.05% × 0.091 = 0.0045%

19.7 Break-even Analysis — Minimum Viable σ_stat

σ_stat ที่ใช้ในสมการด้านล่างมาจาก Objective-Driven Design ใน บทที่ 4.5 — กลยุทธ์ Hybrid ต้องการ σ_stat ที่ "Optimal Substantial" (ไม่ต่ำเกินจน edge หมด ไม่สูงเกินจน half-life ยาวเกิน) สมการ Breakeven ด้านล่างคือเส้นขอบล่างของช่วง tradeable นั้น

Minimum σ_stat เพื่อให้ trade คุ้มค่า: Break-even σ = total_cost / (z_entry − z_exit) ตัวอย่าง: total_cost = 0.11% z_entry = 2.0, z_exit = 0.5 σ_stat = z × σ_spread → spread ที่ entry = 2.0 × σ_spread Break-even: 0.11% / (2.0 − 0.5) = 0.073% → ต้องการ σ_spread ≥ 0.073% เพื่อให้ entry at z=2.0 cover cost → ถ้า σ_spread = 0.05% → entry spread = 0.10%, net edge = −0.01% (ไม่ trade!)

19.8 Pseudo-code compute_edge()

from math import sqrt def compute_edge(spread_at_entry_pct, sigma_spread_pct, entry_z, exit_z, fee_a=0.00055, fee_b=0.00030, half_spread_a=0.00002, half_spread_b=0.00003, size=100_000, adv=500_000_000, sigma_daily=0.02, funding_per_8h=0.0001, hold_periods=1, avg_fill_latency_s=0.5, seconds_per_period=60): gross = spread_at_entry_pct / 100.0 # convert to decimal # Fee cost (round trip, taker both sides) fee_cost = (fee_a + fee_b) * 2 # Bid-ask cost (round trip) ba_cost = (half_spread_a + half_spread_b) * 2 # Slippage cost slip_cost = sigma_daily * sqrt(size / adv) * 2 # entry + exit # Funding cost (funding_per_8h in decimal fraction, e.g. 0.0001 = 0.01%/8h) fund_cost = funding_per_8h * hold_periods # Legging buffer leg_buffer = (sigma_spread_pct/100) * sqrt(avg_fill_latency_s/seconds_per_period) total_cost = fee_cost + ba_cost + slip_cost + fund_cost + leg_buffer net_edge = gross - total_cost breakeven_sigma = total_cost / (entry_z - exit_z) * 100 # as percent return { "gross_pct": gross * 100, "total_cost_pct": total_cost * 100, "net_edge_pct": net_edge * 100, "breakeven_sigma_pct": breakeven_sigma, "viable": net_edge > 0 }

สรุป: Gross 15bps แต่ taker cost (17bps) + อื่น ๆ (2.6bps) = 19.6bps → net = −4.6bps → ห้ามเทรดในสภาพ retail taker — ต้องใช้ maker tier (rebate) หรือรอจน z ≥ 3.3

Break-even σ: total cost 19.6bps / (2.0 − 0.5) = 13.1bps → ต้องการ σ_spread ≥ 13.1bps (σ จริง = 7.5bps ❌ ไม่ผ่าน) → ลด cost ด้วย maker pricing หรือเลือก venue ที่ fee ต่ำกว่า

Practitioner Note — Computing Net Edge

Compute net edge before EVERY trade, not just at strategy launch. Use realized slippage from last 20 executions (not theoretical model) to update slippage estimate. If net edge < 0.05% → skip the trade even if z-score > 2.0 — discipline of not trading near-zero edge is more valuable than capturing marginal signals. Track edge decay over time: if average net edge drops 50% over 30 days → pair may be crowded.

Model Risk — สมมติฐานความเสถียรของต้นทุน

การคำนวณ edge ตั้งสมมติฐานว่าต้นทุนคงที่ — แต่ในความเป็นจริง taker fee อาจเปลี่ยนแปลงได้ภายใน 24 ชั่วโมง, bid-ask spread อาจกว้างขึ้น 5–10 เท่าในช่วง volatility สูง, และ funding rate อาจกลับเครื่องหมาย กลยุทธ์ที่มี net edge 0.11% กับต้นทุน 0.10% มี margin เหลือน้อยมาก — ถ้าค่าธรรมเนียมเพิ่ม 20% กลยุทธ์นั้นจะขาดทุนทันที ควรคำนวณ "edge under stress" เสมอ: net edge จะเป็นเท่าไหร่ถ้า slippage เพิ่มสองเท่าและ funding rate กลับเครื่องหมาย?

19.10 Adverse Selection ของ Maker Order — Rebate คือค่าจ้างให้โดน Pick Off

§19.2 คำนวณว่าเปลี่ยนจาก taker เป็น maker ประหยัด 15bps ต่อ round trip — ตัวเลขนี้ถูกต้องในแง่ fee schedule แต่ข้ามข้อเท็จจริงสำคัญ: fill ของ maker order ไม่ใช่ sample สุ่มจากราคาที่แตะ quote เรา

ทำไม Fill ของ Maker ถึง Bias
Limit order ของเราจะถูก fill ก็ต่อเมื่อมีคนยอม cross เข้ามากิน quote — คนที่ทำแบบนั้นมักเป็น informed flow ที่รู้ว่าราคาจะไปต่อทิศทางนั้น (ไม่ใช่คนสุ่มเทรด)

ผล: เทรดที่ ε revert กลับเองโดยไม่แตะราคาเรา = พลาด (ไม่ได้ fill สัญญาณที่ดี) — เทรดที่ ε ทะลุราคาเราไปต่อ = ได้ fill (แต่ได้ของตอนแพงที่สุด/ถูกที่สุดในทิศที่ผิด)
# วัด Adverse Selection จริง — Markout Analysis สำหรับทุก maker fill: log ε ที่ t+5s, t+30s, t+5min หลัง fill # ถ้า ε เฉลี่ยวิ่งสวนทิศที่เราต้องการ (ต่อ) หลัง fill → นั่นคือ adverse selection cost markout_cost = E[ε_{t+Δ} − ε_{t, fill}] ในทิศที่ไม่เป็นผลดีต่อ position
ตัวอย่างหลัก: Markout ของ Maker Fill (ต่อจาก §19.2)
Fee saved จากเปลี่ยน taker → maker = 15bps ต่อ round trip (§19.2) # สมมติ markout เฉลี่ยหลัง fill = −0.5 tick/ขา (~4bps) Adverse markout = 4bps × 2 ขา × (entry+exit) ≈ 16bps # กิน fee ที่ประหยัดได้เกือบหมด Net saving จริง = 15 − 16 ≈ −1bps (แย่กว่าเดิม!) # ซ้ำร้าย: เทรดกำไรจำนวนหนึ่งไม่เคยถูก fill เลย สัดส่วนสัญญาณที่ ε revert ก่อนแตะ quote ≈ 30–50% (ขึ้นกับความชัน κ ของคู่) → กำไรที่ backtest คิดว่าได้ (fill ทุกครั้งที่ราคาแตะ) ไม่มีอยู่จริงเกือบครึ่ง
บทเรียน: Rebate ไม่ใช่เงินฟรี
  • Backtest ที่ใช้ "touch-fill" (ราคาแตะ limit = fill ทันที) จะประเมินกำไรของ maker strategy สูงเกินจริงเสมอ — ต้องใช้ "trade-through" (ราคาต้องเทรดทะลุไปอีก ≥1 tick) ถึงจะนับว่า fill
  • ก่อนสรุปว่า maker คุ้มกว่า taker ต้องวัด markout จริงจาก order log อย่างน้อย 20-50 fills
  • ใน regime ที่ ε มี κ สูง (กลับตัวเร็ว) adverse selection รุนแรงกว่า — เพราะ "คนที่ cross เข้ามากิน quote เรา" มักรู้ข้อมูลที่ทำให้ ε เคลื่อนไหวเร็วพอดี

19.11 Cost of Time: Edge Rate vs Carry Rate

Cointegration ที่ทดสอบผ่านทุกอย่าง (ADF, half-life, z-score) ยังเทรดไม่คุ้มได้ ถ้าไม่เทียบ "edge ต่อหน่วยเวลา" กับ "carry ต่อหน่วยเวลา" — สองตัวเลขที่หนังสือส่วนใหญ่ไม่เคยหารกัน

Edge Rate ต้องชนะ Carry Rate
edge_rate = expected_gross / E[holding_time] ต้อง ≥ 2× carry_rate = 2×(funding+swap+margin_cost)/วัน
Half-life ไม่ใช่ เวลาถือเฉลี่ย — มันคือเวลาที่ระยะทางหด 50% เวลาที่กลับถึง θ จริง (first-passage time) มี mean สูงกว่าและหางขวาอ้วนกว่ามาก — trade จำนวนไม่น้อยถือเกิน 2-3× half-life
ตัวอย่างหลัก: Cointegration ถูกต้องแต่ Carry กินหมด
Half-life = 14 วัน, entry ที่ 2σ คาด gross ≈ 0.9% Carry: funding perp 2 ขา + swap ≈ 0.05%/วัน # เวลาถือจริง (ไม่ใช่ half-life!) — ใช้ P75 ของ first-passage time distribution P75 ของเวลากลับตัว ≈ 30 วัน (ยาวกว่า half-life 14 วันมาก — หางขวาของ first-passage) Carry สะสมถึง P75 = 30 × 0.05% = 1.5% Net = gross − carry = 0.9% − 1.5% = −0.6% → spread กลับ θ จริงตามที่โมเดลทำนาย แต่ net PnL ติดลบเพราะ carry กินหมดก่อน
กติกาก่อนเข้าเทรดทุกครั้ง
  • คำนวณ edge_rate เทียบ carry_rate ก่อนเสมอ — ถ้า edge_rate < 2× carry_rate ห้ามเทรด
  • ตั้ง time-stop จาก P75 ของ first-passage time distribution (ไม่ใช่ half-life) — ออกที่ P75 แทนที่จะถือรอ convergence ไม่จำกัดเวลา
  • ต้นทุนที่มองข้ามอีกตัว: ถ้าใช้ Kalman filter ปรับ β แบบ dynamic (ch15) rebalance cost จากการปรับ hedge บ่อยเกินไปก็เป็น "carry" อีกชนิดที่ต้องรวมเข้าสูตรนี้ด้วย — ดู ch15 §15.8

19.12 Stop-Loss Tax บน Mean-Reversion

State machine ใน ch11 §11.4 ใช้ STOP ที่ |z|≥3 เป็นกฎตายตัว — แต่สำหรับ OU process การตั้ง stop แบบระยะราคามีต้นทุนแฝงที่ต้องนับเข้า edge waterfall

Stop-Loss Tax — ต้นทุนที่ซ่อนอยู่ในกฎ "ต้องมี Stop"
stop_loss_tax = P(แตะ stop ก่อนกลับ θ) × avg_loss_at_stop
เข้าที่ 2σ, stop ที่ 3σ: P(แตะ 3σ ก่อนกลับ θ) ปกติอยู่ที่ 15-25% — ไม่ใช่เหตุการณ์หายาก และจุด 3σ คือจุดที่ expected reversion แรงที่สุดพอดี (ตัด position ตรงจุดที่ควรถือมากที่สุด)
# ตัวอย่าง P(แตะ 3σ ก่อนกลับ θ | เข้า 2σ) = 20% ค่าเสียเฉลี่ยต่อครั้งที่โดน stop = 1.2σ stop_loss_tax = 0.20 × 1.2σ = 0.24σ ต่อไม้ เทียบ expected gross = 0.8σ ต่อไม้ → stop_loss_tax กิน 0.24/0.8 = 30% ของ edge ก่อนคิด fee ด้วยซ้ำ
แยก Stop สองชนิด — อย่าใช้ตัวเดียวทำหน้าที่ทั้งคู่
  • Structural stop (ออกทันที): ADF fail ใน rolling window, θ shift ตรวจด้วย regime filter (ch9), funding structure เปลี่ยนถาวร
  • Price stop (ตั้งไกลพอ ≥4σ): ให้ trigger จาก break จริง ไม่ใช่ excursion ปกติของ OU
  • ใช้ time-stop ควบ (จาก first-passage quantile, §19.11) เพราะ "ช้าเกิน" เป็นหลักฐานของ break ที่ดีกว่า "ไกลเกิน"
  • รายงาน % ของ trade ที่จบด้วย price stop — ถ้าเกิน ~10% ระบบกำลังจ่าย stop-loss tax หนักเกินไป ให้ทบทวน threshold

19.13 ROC จริงเมื่อไม่มี Margin Offset ข้าม Venue

Backtest ส่วนใหญ่วัด return บน notional หรือ margin แบบ netted — แต่ cross-venue/cross-exchange spread (ch17 §17.13) ต้องวาง margin เต็มทั้งสองขาแยกบัญชี ทำให้ ROC จริงต่ำกว่าที่ backtest คิดมาก

ROC จริง — หารด้วยทุนที่จมจริง ไม่ใช่ Notional
ROC_real = (net_edge_ต่อรอบ × รอบ/ปี × notional) / (IM_A + IM_B + buffer_A + buffer_B)
# GC listed calendar (same-clearing, SPAN credit) Margin ≈ $1,500/spread # Cross-exchange (CME↔APEX แยก clearing) — เต็มสองฝั่ง + buffer Margin ≈ $25,000–35,000 สำหรับ exposure เท่ากัน # ทุนจมต่างกัน ~20 เท่า → ROC ที่ backtest คิดบน notional เดียวกัน ต่างกันมหาศาล กลยุทธ์ที่โชว์ 20%/ปี บนกระดาษ (คิดจาก notional) อาจเหลือแค่ 1% บนทุนที่จมจริง
กติกาเลือกตลาด

ถ้า ε อยู่ข้าม clearing (ไม่มี margin offset) ต้องการ edge ต่อรอบอย่างน้อย 3-5 เท่าของ same-clearing listed spread ถึงจะคุ้มทุนที่จมเพิ่ม — คำนวณ ROC_real ก่อนเปรียบเทียบกลยุทธ์ข้าม venue เสมอ อย่าเทียบแค่ % edge ต่อ trade

19.14 แบบฝึกหัด

แบบฝึกหัดบทที่ 19
ข้อ 1: ถ้า σ_spread = 3bps และ total cost = 4bps — ควรเทรดที่ z=2.0 ไหม?

คำตอบ: ไม่ควร — gross spread ที่ z=2.0 = 2.0 × 3bps = 6bps แต่ total cost = 4bps → net edge = 2bps

แม้ net edge เป็นบวก แต่ risk-adjusted มันเล็กมาก margin of safety ต่ำ
ควรรอให้ z ถึง 2.5+ (gross = 7.5bps, net = 3.5bps) หรือหา venue ที่มี cost ต่ำกว่า

ข้อ 2: วิธีลด fee cost จาก 17bps (taker) เป็น rebate (maker) — ทำได้อย่างไร?

คำตอบ: ใช้ limit order (maker) แทน market order (taker)

  • Maker fee Bybit: +0.020% แทน +0.055% → ประหยัด 0.035%/side = 7bps round-trip (Bybit non-VIP ไม่มี maker rebate)
  • Maker fee Lighter: −0.010% (rebate) แทน +0.030% → ประหยัด 0.040%/side = 8bps round-trip
  • Net saving: 7 + 8 = 15bps round-trip (จาก 17bps cost → 2bps cost — ยังเป็นต้นทุน ไม่ใช่ rebate)

Trade-off: limit order อาจไม่ถูก fill ถ้า spread เคลื่อนที่ออกไปก่อน → ต้องออกแบบ order management ให้ดี

⚠️ คำเตือนเพิ่ม: "ประหยัด 15bps" นี้คือตัวเลขก่อนหัก adverse selection — fill ที่ maker ได้จริงไม่ใช่ fill แบบสุ่ม มันคือ fill ที่คนอื่น "เลือก" จะ cross เข้ามากิน quote ของเรา ซึ่งมักเกิดตอน ε กำลังวิ่งทะลุไปต่อ ไม่ใช่ตอนกำลังจะกลับตัว — ต้องวัด markout จริงก่อนสรุปว่า maker คุ้มกว่า taker (ดู §19.10)

ข้อ 3: ถ้าต้องการ minimum net edge 5bps — คำนวณ minimum z_entry ที่ต้องใช้

คำตอบ: ใช้สูตร: gross_needed = net_edge + total_cost

ตัวอย่าง: total_cost = 19.6bps (taker), net_edge_min = 5bps
gross_needed = 24.6bps
z_entry_min = gross_needed / σ_spread = 24.6 / 7.5 = 3.28

แต่ถ้า σ_spread = 3bps: z_min = 24.6 / 3 = 8.2 — แทบเป็นไปไม่ได้ → ต้องลด cost ด้วย maker tier ก่อน
