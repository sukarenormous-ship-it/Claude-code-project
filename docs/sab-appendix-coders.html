1 · ตัวเลขทั้งเล่มมาจากสคริปต์เดียว

ทุกตัวเลขในบทอยู่ใน docs/sab-figures.json ซึ่งสร้างโดย tools/sab_figures.py ไฟล์เดียว ไม่ต่อเน็ต ไม่ใช้ข้อมูลจริง และได้ผลเดิมทุกครั้งที่รัน

  • ค่าใหม่ของแต่ละบท อยู่ในปลั๊กอิน tools/sab_figures_ch/chNN.py หนึ่งไฟล์ต่อบท แต่ละไฟล์มีฟังก์ชัน extend(data, D, q) ที่คืนคีย์ใหม่ไปลงใต้ chNN ห้ามทับคีย์เดิม · ข้ออ้างเชิงตลาดของบทเข้าทะเบียน _claims ผ่านปลั๊กอินเดียวกัน
  • คีย์เป็นภาษาไทย เช่น ch04.ต้องโอน · ค่าเต็มความละเอียดของต้นฉบับเก็บแยกใต้ _ต้นฉบับ

2 · บัญชีตามเหตุการณ์ (วงหลักของทุก backtest)

ลูปนี้ดัดแปลงจากโค้ดเทียมในต้นฉบับ: กำไรของช่วงใช้ของที่ถืออยู่ก่อนราคาขยับ และของที่ถือเปลี่ยนเมื่อซื้อขายได้จริงเท่านั้น ไม่ใช่ตอนส่งคำสั่ง (สูตรเดียวกันอยู่ใน ภาคผนวก F หัวข้อ 5)

# เริ่มด้วยราคาที่ใช้ได้และบัญชีเปิดที่บันทึกไว้
for event in events_sorted_by_time:
    if event.is_market_update:
        update_marks(event)                      # ราคาประเมินล่าสุดของแต่ละขา

    if event.is_fill:                            # ซื้อขายได้จริง (อาจได้ไม่ครบ)
        cash -= event.signed_qty * event.fill_price
        cash -= event.fee
        held[event.asset] += event.signed_qty    # ซื้อ = บวก · ขาย = ลบ
        update_pending_orders(event)

    if event.is_cashflow:                        # funding · ค่าถือ (มีเครื่องหมาย)
        cash += event.signed_amount

    equity = cash + sum(held[i] * mark[i] for i in assets)

    if event.is_signal_time:
        signal = model(data_known_by(event.time))   # ใช้เฉพาะข้อมูลที่รู้แล้ว ณ เวลานั้น
        target = size_positions(signal)
        reconcile_and_submit(target, held, pending_orders)   # หักคำสั่งค้างก่อน ไม่สั่งซ้ำ
  • ส่งคำสั่งแล้วยังไม่เปลี่ยน held · ได้ขาเดียว (บท 16) คือสถานะที่ held ไม่เท่า target
  • ราคาที่แย่กว่าราคาประเมินอยู่ในบรรทัด fill_price แล้ว อย่าหัก slippage ซ้ำ
  • เหตุการณ์เวลาเดียวกันต้องกำหนดลำดับย่อยให้ชัด: ราคาใดพร้อมให้โมเดลใช้ก่อนส่งคำสั่ง และ funding คิดจากสถานะ ณ เวลาใด

3 · การ์ดกติกา 6 บรรทัดของบท 12 เป็นโค้ดเทียม

การ์ดของมิน (คู่ A–B · X = A − 2B · ไม้บรรทัดค่ากลาง 0 ระยะแกว่ง 1 จึงอ่าน X เป็น z ได้ตรง) เข้าเมื่อ X ≥ 2 · ออกเมื่อ X ≤ 0.5 · ถือไม่เกิน 3 ช่วง · งบขาดทุนสุทธิ −15 · ต้นทุน 0.4 + 0.6 ต่อไม้ · ลำดับเมื่อหลายเหตุพร้อมกัน ขาดทุน → สัญญาณ → เวลา · ออกเพราะงบแล้วหยุดเปิดไม้ใหม่

# การ์ดกติกาคู่ A–B (บท 12) — โค้ดเทียม · ค่าของเล่ม ไม่ใช่คำแนะนำ
ENTRY, EXIT, MAX_HOLD = 2, 0.5, 3      # ช่วง = เปิดดู X หนึ่งครั้ง
BUDGET = -15                            # งบขาดทุนสุทธิ รวมต้นทุน
COST = 0.4 + 0.6                        # เข้า + ออก ต่อไม้
SETS = 10                               # 1 ชุด = A 1 เหรียญ คู่ B 2 เหรียญ

mode, pos = "ACTIVE", None
for t, x in enumerate(spread_series):   # x = A - 2 * B ณ ช่วง t
    if pos is None:
        if mode == "PAUSED":
            continue                    # บท 14: ไม่เปิดไม้ใหม่ แต่ยังดูแลของที่ถือ
        if x >= ENTRY:
            pos = open_pair(side=-1, x_in=x, t_in=t)   # short X: ขาย A 10 (ผ่าน perp) ซื้อ B 20
        elif x <= -ENTRY:
            pos = open_pair(side=+1, x_in=x, t_in=t)   # long X: กลับด้าน
        continue

    net_now = SETS * pos.side * (x - pos.x_in) - COST  # ถ้าปิดตอนนี้ได้สุทธิเท่าไร
    if net_now <= BUDGET:                    # 1) ขาดทุนมาก่อน
        close_pair(pos, reason="งบ")
        mode = "PAUSED"                      #    ออกเพราะงบ = หยุดเปิดไม้ใหม่
    elif -pos.side * x <= EXIT:              # 2) สัญญาณ: short ออกเมื่อ x <= 0.5 · long เมื่อ x >= -0.5
        close_pair(pos, reason="เป้า")
    elif t - pos.t_in >= MAX_HOLD:           # 3) เวลา
        close_pair(pos, reason="เวลา")
    if pos.closed:
        pos = None

ตรวจกับสามเส้นทางที่บทซ้อม (เข้าที่ 2.1 ทุกเส้น): 2.1 → 1.7 → 0.4 ออกเพราะเป้า ได้ 16 · 2.1 → 2.0 → 1.9 → 1.8 ออกเพราะเวลา ได้ 2 · 2.1 → 2.8 → 4.1 ออกเพราะงบ ได้ −21 · เส้นทางที่ 4 ครบเวลาและชนงบในช่วงเดียวกัน งบชนะตามลำดับ ได้ −17

⚠️ สามจุดที่โค้ดแบบนี้หลอกได้
  • ราคาที่ปิดได้ไม่ใช่ราคาที่เห็น: โค้ดเช็กงบที่ X ที่สังเกต แต่ X กระโดดจาก 2.8 ไป 4.1 โดยไม่มีจุดให้ซื้อขายระหว่างทาง งบ −15 จึงกลายเป็น −21 · backtest ที่ปิดที่เส้นงบพอดีทั้งที่ข้อมูลกระโดด กำลังหลอก
  • สัญญาณกับการกด: x ของช่วง t รู้หลังราคาปิด คำสั่งจึงได้ราคาของช่วงถัดไป ถ้าโค้ดเข้าที่ x เดียวกับที่ใช้ตัดสิน คือใช้อนาคต
  • ค่าถือและ beta: โค้ดนี้ยังไม่มีค่าถือขา short (funding) และคู่นี้ไม่เป็นกลางต่อตลาด (beta exposure +500 · บท 8) ผลจึงยังไม่ใช่ผลจริง · ต้นทุนจริงด้วยคำสั่งซื้อทันทีราว 2 ต่อไม้ (บท 16)

4 · อ่านงานวิจัยหรือ tutorial ของคนอื่น: เริ่มจากบัญชี

ก่อนดู Sharpe หรือกำไรสะสมทั้งปี ให้ตอบสามแกนนี้ให้ได้ (จากหัวข้อ "ใช้บัญชีนี้แกะกรณีศึกษาของผู้อื่น" ของต้นฉบับ)

แกนคำถามที่ต้องตอบ
เลือกสินทรัพย์ (asset selection)ทำไมสองตัวนี้อยู่ด้วยกัน (เชือกชนิดไหน) · ราคาและหน่วยเข้ากันไหม · แต่ละขาต้องซื้อขายแบบใด (short ได้ไหม ค่ายืมหรือ funding เท่าไร)
ขั้นตอน (workflow)ข้อมูลใดเข้าประมาณ h · สัญญาณเกิดเมื่อไร · ข้อมูลส่วนไหนยังไม่ควรถูกใช้ ณ ตอนนั้น · ช่วงเลือกกับช่วงทดสอบแยกกันไหม · ค้นมากี่คู่
จัดการสถานะ (position management)h แปลงเป็นจำนวนอย่างไร · เปิดหรือปรับเมื่อไร · fill ต้นทุน เงินสด หลักประกันอยู่ตรงไหนในบัญชี
  1. คิดบัญชีด้วยมือหนึ่งช่วงสั้น ๆ ราคา · จำนวนที่ถือ · เงินสด · equity ถ้าไม่ตรงกับโปรแกรม หยุดไล่ช่วงนั้นก่อน มักเป็นเครื่องหมายของขา short · ใช้จำนวนผิดช่วงเวลา · หรือหักต้นทุนซ้ำ
  2. หาตัวแปรที่เก็บจำนวนซื้อขายจริง และดูว่า "spread" ในงานนั้นคือราคา ผลตอบแทน หรือลอการิทึมของราคา และกำไรคิดด้วยจำนวนของช่วงไหน
  3. แยกสิ่งที่ประมาณจากข้อมูลกับสิ่งที่ผู้เขียนเลือก เส้นเข้าออก จำนวนสินทรัพย์ ความเร็วปรับกลับที่ตั้งคงที่ · ดูว่าทำอะไรเมื่อไม่มีคู่ผ่าน และจัดการสถานะค้างอย่างไร
  4. จดสิ่งที่เปลี่ยนเมื่อย้ายตลาด จากหุ้นเป็น perp ต้องเพิ่มชนิดสัญญา ตัวคูณสัญญา funding และหลักประกัน · ถ้าจะใช้คำสั่งตั้งรอเท่านั้น ต้องเปลี่ยนสมมติฐานการได้ของทั้งหมด · คงชื่อโมเดลเดิมไม่ได้แปลว่าบัญชีเหมือนเดิม
  5. ติดระดับหลักฐานให้ข้อสรุป อ่านวิธีแล้ว · ตรวจโค้ดแล้ว · รันตัวอย่างแล้ว · ทำซ้ำผลได้แล้ว — สี่ระดับนี้ต่างกันมาก และกรณีศึกษาทั้งหมดในต้นฉบับไม่มีชุดใดถึงระดับทำซ้ำผล

คำถามระดับสมมติฐาน (ทำไม spread ควรกลับ · คัดคู่ก่อนหรือหลังเห็นผล) ตามมาหลังบัญชีผ่านแล้ว · ใบอ่าน backtest 7 แถวที่ไม่ต้องอ่านโค้ดอยู่ใน บท 18

แหล่งโค้ดที่ต้นฉบับอ้าง (ยังไม่ได้ตรวจ)

ต้นฉบับอ้างเอกสารของแพลตฟอร์ม backtest และไลบรารีพอร์ตหลายรายการ เช่น เอกสาร fill และ order event ของ QuantConnect (R2 · R48) · ไฟล์จัดการ drawdown ใน LEAN (R45) · ตัวอย่างกลยุทธ์เป็นกลางต่อตลาดของ Cvxportfolio (R35) · implementation ของ ArbitrageLab (R11 · R43) เล่มนี้ไม่ได้รันหรือเปิดตรวจแหล่งเหล่านี้ และไม่สอนการใช้ไลบรารีใด รายการพร้อมสถานะอยู่ใน ภาคผนวก H
