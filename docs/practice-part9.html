9.1 Deflated Sharpe — เมื่อ Sharpe ที่ดีสุด ไม่ใช่ของจริง

Part II แสดงให้เห็นแล้วว่าสแกน 300 คู่สุ่ม ๆ ที่ α=0.05 จะเจอ "คู่ผี" ผ่าน ADF ราว 12-15 คู่ทั้งที่ไม่มีความสัมพันธ์จริงเลย — ปัญหาเดียวกันเกิดขึ้นตอนเลือกกลยุทธ์ที่ดีที่สุดจากการลองหลายค่า

🚶 อ่านเป็นภาษาคนก่อน — อุปมา "หวยที่ถูกโดยบังเอิญ"

ถ้าคุณให้คน 1,000 คนทายผลหวยแบบสุ่ม จะมีคนถูกบ้างโดยบังเอิญล้วน ๆ — ถ้าคุณเลือกดูแค่ "คนที่ถูก" แล้วสรุปว่าเขา "เก่งทายหวย" คุณกำลังหลอกตัวเอง เพราะไม่ได้นับว่ามีอีก 999 คนที่ทายผิด
เวลาคุณลอง Q/R 50 ค่า (Part IV), band 10 แบบ (Part VI), คู่ 300 คู่ (Part II) — แล้วเลือก "ตัวที่ backtest ดีที่สุด" มาอวด — Sharpe ที่ได้ก็เหมือนคนที่ถูกหวยบังเอิญ ไม่ใช่ตัวสะท้อนทักษะจริง

ทางแก้: Deflated Sharpe Ratio (Bailey & López de Prado, 2014)

สูตรนี้ "หัก" ความสูงเกินจริงของ Sharpe ที่มาจาก 2 แหล่ง: (1) จำนวนครั้งที่ลอง (ยิ่งลองเยอะ ยิ่งมีโอกาสเจอค่าที่ดีบังเอิญ ต้องหักมากขึ้น) และ (2) ความไม่ปกติของ distribution ผลตอบแทน (skewness/kurtosis ที่ทำให้ Sharpe ธรรมดาตีความผิดได้)

Sharpe ที่รายงาน = 2.5 (ดูดีมาก!)
จำนวนค่าที่ลองก่อนเลือกตัวนี้ = 200 (Q/R × band × คู่ ฯลฯ)
Deflated Sharpe = Sharpe ที่รายงาน หักด้วยผลของ (1) จำนวนครั้งลอง + (2) การแจกแจงที่ไม่ปกติ
→ อาจเหลือแค่ 0.8 หรือต่ำกว่า — "ของจริง" ที่ควรคาดหวัง
⚠️ ทำไมเรื่องนี้ย้อนกลับไปแตะเกือบทุก Part ในเล่ม

ทุกครั้งที่เล่มนี้บอกให้ "ลอง Q หลายค่าดู plateau" (Part IV) หรือ "ลอง band หลายแบบเทียบกัน" (Part VI) — การลองเหล่านั้นนับเป็นการทดสอบหลายครั้งเหมือนกัน จำนวนครั้งที่ลองต้องถูกนับสะสมไว้ ไม่ใช่ลืมไปเมื่อถึงขั้นตอนวัดผลสุดท้าย

9.2 PBO — ตัวเลขเดียวที่บอกว่า "backtest นี้น่าจะ overfit ไหม"

Probability of Backtest Overfitting (Bailey, Borwein, López de Prado & Zhu, 2014/15) ตอบคำถามตรง ๆ ว่า "ถ้าลองกลยุทธ์นี้กับข้อมูลที่ไม่เคยเห็น มันจะยังดีเหมือนตอน backtest ไหม"

🚶 อ่านเป็นภาษาคนก่อน

วิธีการ (เรียกว่า combinatorially symmetric cross-validation) คือ: แบ่งข้อมูลเป็นหลายชิ้นเล็ก ๆ แล้วลองสลับกันว่าอันไหนเป็น "train" อันไหนเป็น "test" หลายรอบ — ถ้ากลยุทธ์ที่ดีที่สุดใน train เกือบทุกรอบก็ยังดีใน test ด้วย = ของจริง (PBO ต่ำ) แต่ถ้ากลยุทธ์ที่ดีสุดใน train กลับแย่ใน test บ่อย ๆ = สัญญาณชัดว่า overfit (PBO สูง)

✅ ใช้ยังไงในทางปฏิบัติ

ก่อนเชื่อ backtest ที่สวยของคุณ ลองรัน PBO ดู — ถ้า PBO สูง (เช่น >50%) แปลว่าโอกาสที่กลยุทธ์นี้เป็นแค่ noise ที่ fit เข้ากับอดีตพอดี มีสูงกว่าที่จะเป็นทักษะจริง

9.3 Purged / Embargoed Cross-Validation

ปัญหาของ CV แบบมาตรฐาน (สุ่มแบ่ง train/test) เมื่อใช้กับข้อมูล time series: ข้อมูลรั่วข้ามเวลาได้

📉 ทำไม CV ธรรมดาถึงหลอกตัวเอง

สมมติแบ่งข้อมูลสุ่ม ๆ เป็น train/test — บางจุดใน test อาจอยู่ติดกันในเวลากับจุดใน train (เช่น train มีวันที่ 100, test มีวันที่ 101) เพราะ half-life/momentum ทำให้ข้อมูลใกล้เวลากันมี "ข้อมูลร่วม" กันอยู่ (autocorrelation) โมเดลที่ "จำ" ลักษณะแถวเวลานั้นได้ จะดูแม่นใน test ทั้งที่จริง ๆ กำลังเห็นข้อมูลที่คาบเกี่ยวกับ train

Purging: ตัดตัวอย่าง train ที่อยู่ในช่วงเวลาใกล้กับ test เกินไปทิ้ง (ไม่ให้ข้อมูลคาบเกี่ยว)
Embargo: เว้นช่วงกันชนหลัง test ก่อนกลับมาใช้ข้อมูลเป็น train รอบถัดไป
🧠 มุมที่ quant มองต่าง

คนทั่วไปเห็น: "แบ่ง train/test แบบสุ่ม 80/20 ก็พอ"
quant เห็น: ข้อมูลการเงินมี autocorrelation ในตัวเสมอ (ราคาวันนี้เกี่ยวกับเมื่อวาน) — CV ที่ไม่คำนึงถึงเวลาจะรายงานผลดีเกินจริงอย่างเป็นระบบ ยิ่ง half-life ยาว (Part II) ยิ่งต้อง purge/embargo กว้างขึ้น

9.4 Look-ahead Checklist + Risk

Look-ahead bias — checklist รวมจากทั้งเล่ม

  • ✅ Rolling window (Part I §1.6): ใช้เฉพาะข้อมูลถึง ณ จุดนั้น ไม่ใช่ทั้ง sample
  • ✅ Pair selection (Part II §2.3): เลือกคู่จาก in-sample แล้ว backtest บน sample เดิม = โกงตัวเอง
  • ✅ Q/R tuning (Part IV §4.6): fit → lock → OOS ที่ไม่เคยแตะ
  • ✅ Band selection (Part VI): เลือก band จาก full-sample performance ก็เป็น look-ahead รูปแบบหนึ่ง

กฎรวม: ที่จุดเวลา t ใด ๆ ต้องพิสูจน์ได้ว่าใช้เฉพาะข้อมูลถึง t เท่านั้น — ถ้าตอบไม่ได้ชัดเจนว่า "ข้อมูลนี้มาจากไหน รู้ตอนไหน" ให้สงสัยไว้ก่อน

Risk — สิ่งที่ต้องคุมนอกเหนือจากสัญญาณ

Position sizing
  • size ตาม "ทน SD ได้กี่ตัว" ไม่ใช่ระดับความมั่นใจ — ความมั่นใจสูงไม่ได้แปลว่าเสี่ยงน้อยลง
Portfolio correlation
  • หลายคู่ stat arb มักสัมพันธ์กันเองมากกว่าที่คิด (พังพร้อมกันตอนวิกฤตสภาพคล่องทั้งตลาด) — ไม่ diversify จริงอย่างที่ตัวเลขบอก
Leg/Gap/Halt Risk

ขาหนึ่งอาจ fill ก่อนอีกขา (leg risk) — ระหว่างนั้นคุณถือ directional exposure โดยไม่ตั้งใจ · ราคาอาจ gap ข้ามคืนก่อนคุณตัดได้ · หุ้นอาจถูกพักการซื้อขาย (halt) ระหว่างที่คุณต้องการปิดสถานะพอดี — ทั้งหมดนี้คือความเสี่ยงด้าน execution ที่ backtest มักไม่จับ

9.5 Case Study — เดินคู่จำลองผ่านทั้งไปป์ไลน์

⚠️ ข้อมูลจำลอง เพื่อสาธิตกระบวนการ ไม่ใช่คำแนะนำการลงทุน

ตัวอย่างนี้เดินผ่านทุกขั้นตอนของเล่มโดยใช้ตรรกะที่สอนไว้ — ตัวเลขเป็นภาพประกอบแนวคิด ไม่ใช่ผลจริงจากตลาด

ขั้นตอนPartสิ่งที่ทำ
1. ScreenIIสแกน universe เล็ก (เช่น หุ้นกลุ่มเดียวกันในตลาดที่คู่แข่งบาง) → ผ่าน corr > 0.8 → ADF (coint) p < 0.05 → Hurst < 0.5 → half-life 1-30 วัน
2. Estimate βI, IVเช็คว่า regress บนราคา (ไม่ใช่ return) → OLS เป็น baseline → Kalman ปรับ β แบบ real-time ด้วย Q ที่จูนผ่าน MLE/EM
3. BandVIคำนวณ cost เต็มรูป (VIII) → ตั้ง band ให้ ≥ round-trip cost + edge ที่ต้องการ
4. Regime monitorVIIตั้งชั้นเร็ว (estimator-disagreement, NIS) + ชั้นช้า (half-life/Hurst/coint re-test) คู่กัน
5. Cost checkVIIIยืนยันยืมช็อตได้จริง + ADV พอสำหรับไซส์ที่จะเข้า
6. Backtest ไม่โกหกIXpurged/embargoed CV, รายงาน deflated Sharpe (ไม่ใช่ Sharpe ดิบ), เช็ค PBO ก่อนเชื่อ
"ทุก Part ในเล่มนี้คือฟันเฟืองหนึ่งชิ้น — คุณค่าจริงอยู่ตอนที่มันขับเคลื่อนพร้อมกันเป็นระบบเดียว ไม่ใช่ใช้ทีละชิ้นแยกกัน"

9.6 Cheat Sheet — เลือก Estimator/แนวทางไหนเมื่อไร

สถานการณ์เลือกใช้
Regress ราคา เพื่อหา cointegrationOLS ตรง ๆ (super-consistent, Part I §1.3)
Regress return เพื่อหา hedge/factor exposureTLS/PCA ถ้าประเมิน δ ได้ · ไม่งั้นใช้ Kalman (Part I §1.5, 1.7)
เชื่อว่า β นิ่งเชิงโครงสร้าง (เช่น share-class เดียวกัน)Kalman + AR(1) mean-reverting β (Part V §5.1)
ไม่แน่ใจว่า β นิ่งแค่ไหนKalman + random-walk β เป็น default ปลอดภัย (Part IV)
อยากเทรดข้าม universe ใหญ่ ไม่เลือกคู่ทีละคู่PCA/factor residual + s-score (Part III)
สงสัย non-linear/tail dependence ที่ cointegration พลาดCopula Mispricing Index (Part II §2.4)
ตั้ง bandเริ่มจาก cost-aware → ขยับสู่ optimal OU-cost threshold เมื่อพร้อม (Part VI)
ตรวจว่า regime กำลังพังชั้นเร็ว (NIS/disagreement) ยกธง → ชั้นช้า (half-life/Hurst/coint) ยืนยัน (Part VII)

สรุปทั้งเล่ม

✓ สิ่งที่ต้องจำที่สุดจากทั้งเล่ม
  1. Estimator ไม่ใช่ edge (Part 0) — ทุกคนมีเครื่องมือเดียวกัน edge อยู่ที่วินัย + บ่อที่คุณเลือก
  2. ทุกสมมติฐานมีจุดพัง — OLS พังกับ return, Kalman พังถ้า Q ผิด, band พังถ้าไม่รู้จักต้นทุน, ความสัมพันธ์พังได้ทุกเมื่อ
  3. Backtest ที่ไม่ตรวจสอบตัวเอง คือหนี้ที่รอเก็บ — deflated Sharpe และ PBO ไม่ใช่พิธีกรรม แต่คือด่านสุดท้ายกันตัวเองหลอกตัวเอง

เล่มนี้ไม่ได้จบด้วยสัญญาว่าคุณจะทำกำไรได้ — มันจบด้วยเครื่องมือคิดที่ทำให้คุณรู้ว่ากำลังเชื่ออะไรอยู่ และรู้ว่าจะจับตัวเองโกหกตัวเองได้ตอนไหน นั่นคือทั้งหมดที่ quant ที่ดีทำต่างจากคนอื่น

📖 ศัพท์ใหม่ในตอนนี้
  • Deflated Sharpe Ratio — Sharpe ที่หักผลของจำนวนครั้งทดสอบ + การแจกแจงไม่ปกติแล้ว
  • PBO (Probability of Backtest Overfitting) — ตัวเลขวัดโอกาสที่ backtest จะไม่ generalize
  • Purging / Embargo — เทคนิค CV ที่กันข้อมูลรั่วข้ามเวลาสำหรับ time series
  • Leg risk / Gap risk / Halt risk — ความเสี่ยงด้าน execution ที่ backtest มักไม่จับ
