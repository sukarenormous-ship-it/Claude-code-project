# มาตรฐานงานฝีมือ v4 + กระบวนการรีวิว

นี่คือสิ่งที่แยก "ร่างที่ถูกต้อง" ออกจาก "หนังสือที่คนรักวิชานี้อยากอ่าน" มาตรฐานนี้สะสมจากการรีวิวจริงหลายรอบ (v2 → v3 → v4)

## กระบวนการทำงานต่อ 1 Part (บังคับ)

1. **เขียนร่าง** ตามเทมเพลตการ์ด (ดู `card-anatomy.md`) + Style Guide
2. **รีวิวโดยคณะผู้เชี่ยวชาญ 3–4 เลนส์** (ดูด้านล่าง) — spawn เป็น subagent หรือสวมบทเอง ทีละเลนส์
3. **แก้ให้ครบทุกข้อที่รีวิวจับได้** ("ผ่านรีวิวผู้เชี่ยวชาญ N คน — แก้ครบ")
4. **commit แยกต่อ Part** + push
5. รอบเก็บงาน: whole-book review (star ratings, notation, index count, coverage gap)

> pattern ของ commit จริง: `docs: เล่ม X Part N — ร่างก่อนรีวิว` → `docs: Part N ผ่านรีวิวผู้เชี่ยวชาญ N คน — แก้ครบ`

## คณะผู้เชี่ยวชาญ (ปรับเลนส์ตามวิชา — ตัวอย่างจากเล่ม quant)

รีวิวจาก **หลายเลนส์อิสระ** จับ error คนละแบบ:
- **เลนส์เนื้อหา-เชิงลึก** (เช่น pricing/stochastic) — ความถูกต้องทางเทคนิค, notation
- **เลนส์วิชาการ** (เช่น asset-pricing academic) — citation แม่นปี/ผู้แต่ง, ที่มาถูกต้อง
- **เลนส์คนใช้จริง** (เช่น buy-side practitioner) — "ในสนามจริงเป็นแบบนี้ไหม", heuristic ระดับโต๊ะ
- **เลนส์บรรณาธิการการสอน** (learning design) — ลำดับการสอน, ช่องว่าง "ใช้เป็น", tooltip/glossary
- **เลนส์ภาษา/typography/i18n** — line-break ไทย, โครงสร้าง HTML (ดู Style Guide)

## v4 — 3 ด้านที่ต้องปรุง (narrative / soul / learning design)

### 🎭 Narrative (เล่าเรื่อง)
- เปิด section ด้วย **ปริศนา/เดิมพัน ไม่ใช่ลำดับเหตุการณ์**
- **breath beat** คั่นตารางยาว ๆ (ย่อหน้าสั้นให้พัก)
- **voice กล้าขึ้น** — โทน mentor "พูดตรง ๆ"
- **ปริศนาข้ามบท + callback** — ตั้งคำถามบทนี้ ไปเฉลยบทหน้า
- **เกร็ดคนจริง**กระจายทั่ว (แต่ยืนยันก่อนใช้)
- **Signature Line (`.pq`):** ยก "ประโยคทอง" ที่มีอยู่แล้วในเนื้อออกมาให้เด่น (งานน้อย ผลเยอะ)
- ปิดทุกตอนด้วย **cliffhanger** เชื่อม Part ถัดไป; ใช้ **metaphor เดียว**ตลอดเล่ม (เช่น "เลโก้")

### 💎 Soul (ทำให้คนรักวิชานี้)
ธีมที่ควรโผล่ซ้ำ ๆ:
- โครงสร้างที่โผล่เอง · เป็น**นักสืบไม่ใช่นักพยากรณ์**
- **ผิดอย่างมีประโยชน์** ("all models are wrong, some useful" = วิธีทำงาน ไม่ใช่คำแก้ตัว)
- **ถ่อมตัว = ซูเปอร์พาวเวอร์**
- ดัน 🧠 (มุมที่มองต่าง) ถึงชั้น **"พลิกวิธีมองโลก"** ไม่ใช่แค่ "คนทั่วไป vs ผู้เชี่ยวชาญ"

### 🎓 Learning design (สอน *กระบวนการ* judgment ไม่ใช่แค่ผลลัพธ์)
- **🎬 "ฉากหน้าจอ"** — การตัดสินใจจริงหน้างาน
- **🧭 "นิสัยคิด"** — ลำดับคำถามที่ควรถามตัวเอง
- **heuristic ระดับโต๊ะ** — กฎนิ้วโป้งที่ใช้จริง (เช่น "Sharpe>2 ให้สงสัยลืมต้นทุน", "ถามว่าใครอยู่อีกฝั่ง")
- reading-path banner (🟢 มือใหม่ / 🔵 มีพื้น); glossary จัดชั้น (3 คำต้องจำก่อน)
- ป้าย [รอบสอง] สำหรับกล่องลึก; mnemonic ช่วยจำ
- worked example + ✍️ ลองทำเอง + 🎯 "3 อย่างที่ต้องจำ" ต่อการ์ด ★★★

## กันการ hallucinate (สำคัญที่สุด)

- **ห้ามแต่ง paper/เกร็ด/ตัวเลข** — อ้างเฉพาะที่มีจริง; ไม่มั่นใจให้ **ตัดออก** หรือใช้สำนวนกลาง
- citation แม่นปี/ผู้แต่ง (เช่น "Harrison-Kreps (1979) & Harrison-Pliska (1981)" แยกกัน; "GARCH = Engle 1982")
- ยืนยันเกร็ดก่อนใช้ (เช่นเกร็ด Savage postcard → ถ้าไม่ยืนยันให้ใช้สำนวนกลาง)
- แยก **📚 Papers** (ต้นฉบับของทฤษฎี) ออกจาก **📖 อ่านต่อ** (survey/handbook มาตรฐาน)

## กฎความสอดคล้องข้ามเล่ม (Consistency)

1. **Write Once, Reference Everywhere** — แต่ละแนวคิดมี "บ้านหลังเดียว" (canonical chapter); ที่อื่น *อ้างอิง* ไม่เขียนซ้ำ
2. **Notation sheet กลาง** — สัญลักษณ์ (เช่น `S, K, r, q, σ, T, Φ(·), w, Σ, β`) ใช้เหมือนกันทั้งเล่ม; ทำหน้า `notation.html` รวม
3. **Single numbering** — เลขบทเรียงต่อเนื่องภายในเล่ม; ติดป้าย gap ที่ปิดทุกบท
4. **Cross-ref** — ลิงก์ไฟล์เดิม (เช่น `<code>theory-part5</code>`) แทนการเขียนซ้ำ
5. **Template เดียว** — ทุกบทโครงเดียวกัน: Intuition → Theory → Formula → Worked example → Drills → Pitfalls → Cheat box
6. **Prerequisite graph + difficulty tier** ทุกบท
