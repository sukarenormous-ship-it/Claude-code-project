# Stat Arb หลายขาข้ามหลายตลาด (Hub-and-Spoke Consensus) — ฉบับปรับจาก "มากกว่า 2 ขา"

> **นี่คือการเดาโครงสร้างจากเบาะแสสาธารณะ ไม่ใช่เนื้อหาคอร์ส "Alpha Leak EP3" จริง** ไม่มีใครในกระบวนการนี้เห็นเนื้อหาคอร์ส
> ข้อเท็จจริงเรื่องแพลตฟอร์มมาจากเอกสาร/ API สาธารณะ ณ วันที่ 6–7 พ.ย. 2026 (ข้อที่ยังไม่แน่นอนติดป้าย **[ตรวจ]**)
> ตัวเลขผลตอบแทนทุกตัวจาก `tools/kvenue_statarb.py` เป็น **ข้อมูลสังเคราะห์** ใช้ดูพฤติกรรมเชิงเปรียบเทียบเท่านั้น
> ฉบับ 2 ขาเดิม: `docs/xvenue-statarb-design.md`

## 0. สรุปสั้น

- เห็นด้วยว่า **เปิดมากกว่า 2 ขา** — เบาะแสที่ชี้ชัดที่สุดคือ "**Lighter (Robinhood)**" ในประกาศคอร์ส:
  ตั้งแต่ 1 ก.ค. 2026 **Lighter on Robinhood Chain (LR)** เป็น *exchange แยกอีกตัว* (สัญญา, sequencer, order book, บัญชี, API คนละชุดกับ Lighter Core; ใช้ USDG เป็นหลักประกัน)
  แต่ราคา BTC/ETH/SPY/QQQ ฯลฯ ตัวเดียวกัน → แค่ Lighter อย่างเดียวก็มี **2 ตลาดที่ค่าธรรมเนียม 0** แล้ว (ถ้า LR ยังเป็น 0/0 หลังโปรเปิดตัว **[ตรวจ]**) บวก Bitget + Bybit = **4 ตลาดต่อสินทรัพย์**
- โครงสร้างที่เข้ากับทุกเบาะแสที่สุด: **ตะกร้า zero-sum ของสินทรัพย์เดียวกันบน K ตลาด**
  ถือ n[a,k] บนหลายตลาดพร้อมกันโดยบังคับ **Σ_k n[a,k] = 0** (ราคาตลาดโดยรวมหักล้างกันหมด) แล้วเทรด "ราคาตลาด k ที่หลุดจาก**ราคากลางข้ามตลาด**" ให้วิ่งกลับ
  - **Hub** = Lighter Core (LC) + Lighter RH (LR): ค่าธรรมเนียม 0 → รับขาที่ต้องข้ามสเปรด (taker) และรับส่วนเกิน/การซ่อม hedge ทั้งหมด
  - **Spoke** = Bitget (BG) + Bybit (BY): วาง post-only (maker) เท่านั้น เปิดเมื่อส่วนต่างชนะค่าธรรมเนียมที่ "ขอลดได้"
  - funding เป็นตัวเสริม ไม่ใช่เครื่องยนต์หลัก
- ต่อสินทรัพย์ถือได้พร้อมกัน 3–4 ตลาด (เช่น **+2 ส่วนที่ LC / −1 ส่วนที่ BG / −1 ส่วนที่ BY**) — ทั้งพอร์ต 4–7 สินทรัพย์ออกแบบให้รับได้ 12–28 ขา
  (แต่ในตัวจำลองที่ค่าธรรมเนียม CEX 1bp สถานะส่วนใหญ่เป็นชั้นละ 2 ขา และถือ ≥3 ตลาดพร้อมกันเพียงบางช่วง — ดูหัวข้อ 11)
  แต่ละตลาดมี margin แยก → **ทั้งพอร์ตไม่มี downside จากทิศทางตลาด** (ยังเหลือความเสี่ยง residual, ADL, ตลาดล่ม) **แต่ตลาดใดตลาดหนึ่ง "ขาขาด" ได้** ถ้าเปิดหนัก — ตรงคำแอดมิน
- คาดการณ์ตรงไปตรงมา (จากทีมวิเคราะห์): ช่วงตลาดเงียบ ~2–6%/ปี, ช่วงผันผวน 20–40% (annualised) ถ้าช่วงผันผวนกิน ~25% ของเวลา รวมแล้ว ~6.5–15%/ปี
  ตัวเลข 10–25% ของคอร์สต้องได้ **ทั้งสามข้อ**: CEX maker ≤ ~1bp, ต้นทุนแฝง taker บน Lighter ≤ ~1bp, และ residual จริงใหญ่พอ (ตัวจำลองบอกว่าต้องราว σ คู่ 3–4bp, half-life หลักนาที) — **ต้องวัดจากข้อมูลจริงก่อนเทรด**
- **ข้อค้นพบจากตัวจำลอง**: book ที่เทรด mean-reversion ระดับนาทีอย่างเดียวแทบไม่ต้องโยกเงินแม้ leverage สูง เพราะถือสั้นและขนาดเฉลี่ยต่ำ —
  การที่แอดมินพูดถึง "โยกเงิน" และ "ขาโดน liquidate" จึงบอกว่า**เขาน่าจะถือสถานะค้างนานพอสมควร** (ชั่วโมง–วัน เช่นถือเก็บ funding/basis หรือ residual ที่ half-life ยาว) ไม่ใช่ scalping ล้วน

## 1. แกะเบาะแส (ฉบับหลายขา)

| เบาะแส | อ่านแบบหลายขา |
|---|---|
| "อาจต้องใช้ **Lighter (Robinhood)** เพราะไม่มีค่าธรรมเนียม" | LR = Lighter บน Robinhood Chain เป็น **ตลาดแยก** ที่ fee 0 (Standard) — Lighter จึงเป็น hub 2 ตัว (LC + LR) และมีคู่ LC–LR ที่ "ฟรีทั้งสองขา" ด้วย (มีเครื่องมือจีนสาธารณะทำ arb RH-Lighter ↔ Lighter อยู่แล้ว) |
| Bitget / Bybit "ทำกลยุทธ์ได้ + ขอลดค่าธรรมเนียมได้" | เหตุผล *ไม่เหมือน* Lighter → บทบาทต่างกัน: CEX เป็น spoke ที่ต้องได้ maker fee ต่ำ (VIP/ โปรแกรม liquidity) |
| "เปิด**ขารวมๆ กันในหลายๆ แพลตฟอร์ม**" | ตะกร้าเดียวกระจาย 3–4 ตลาด ไม่ใช่คู่เดียว |
| "รวมกันไม่มี downside" | Σ_k n[a,k] = 0 → ราคาตลาดโดยรวมหักล้าง เหลือแค่ residual ข้ามตลาด |
| "**บางขา**อาจโดน liquidate ขาขาดไปก่อน" | แต่ละตลาดถือสถานะทิศเดียว (เช่น LC long ทั้งก้อน) margin แยก → ราคาวิ่งแรง ตลาดที่ขาดทุนโดนก่อน; Lighter ปิดทีละ position (partial liquidation) = "ขาขาด" ตามตัวอักษร |
| "เล่น leverage น้อยแทบไม่ต้องโยกเงิน" | equity แต่ละตลาด drift ตามราคาของสถานะที่**ถือค้าง** — ความน่าจะเป็นต้องโยกเงินโตเร็วมากตาม leverage (ตารางหัวข้อ 6) และตัวจำลองชี้ว่าต้องมีสถานะค้างนานคำพูดนี้จึงจะมีความหมาย (หัวข้อ 11) |
| "10–25%/ปี ผันผวนได้เยอะ" | **สมมติ**ว่า residual ข้ามตลาดขยายตามความผันผวน (ตลาดวิ่งแรง book ฝั่งที่บางกว่าตามไม่ทัน/เลยไป) → โอกาสที่ชนะค่าธรรมเนียมเพิ่มหลายเท่า — ต้องวัด σ แยกช่วงเงียบ/ผันผวนจาก Phase 0 (`--calibrate` แสดงให้) |
| "โอกาสได้ airdrop Lighter Robinhood" | LR มี points program ตั้งแต่ 10 ส.ค. 2026 (รายงานขนาดรางวัลไม่ตรงกัน: "11M LIT" กับ "LIT มูลค่า ~$11M" และบางแหล่ง $20–30M **[ตรวจ]**) — ปริมาณเทรดบน hub = แต้ม (นับเป็นโบนัส ไม่นับในผลตอบแทน) |
| "EP3 จริงๆ คือ 2.5 คล้าย EP2" | เดาว่า EP2 = คู่ Lighter vs CEX หนึ่งตัว; EP3 = ขยายเป็น K ตลาด โดยเพิ่ม LR (เปิดหลัง ก.ค. 2026) + CEX ตัวที่สอง |
| พอร์ต $100k, 2 สัปดาห์คืนทุน | 10–25%/ปี × $100k × 2/52 ≈ $385–960 ≈ ราคาคอร์สระดับนั้น |
| "มีโปรแกรมประกอบ" | 4 ตลาด × หลายเหรียญ × ส่งคำสั่งคู่/ซ่อม hedge ภายในวินาที — ทำมือไม่ได้ |

**ข้อมูลที่ขัดกับ "หลายขา" มีไหม:** การตีความ "หลายคู่ 2 ขาแยกกันหลายเหรียญ" ก็เข้ากับเบาะแสได้ แต่เมื่อรวมสถานะต่อตลาดแล้วหน้าตาพอร์ตเหมือนกัน — แบบในเอกสารนี้ครอบคลุมกรณีนั้นเป็นกรณีพิเศษ (K=2 ต่อเทรด)

## 3. คณิตศาสตร์ของ hedge

- n[a,k] = จำนวนเหรียญ (มีเครื่องหมาย) ของสินทรัพย์ a ที่ตลาด k, P[a,k] = ราคาตลาด k, P̄ = ราคากลาง
- **เงื่อนไขบังคับ**: Σ_k n[a,k] = 0 ทุกสินทรัพย์ หลังทุกการกระทำ
- กำไรจากราคา: Σ_k n_k dP_k ≈ P̄·Σ_k n_k (dm + du_k) = **P̄·Σ_k n_k du_k** — การเคลื่อนร่วม dm หักล้างกัน (เหลือ delta เล็กระดับ basis × gross เช่น basis 5bp บน gross $200k ≈ $100) เหลือแต่การเปลี่ยนของ residual แต่ละตลาด
- ระดับตลาด: D_k = Σ_a n[a,k]·P[a,k] **ไม่เป็นศูนย์โดยตั้งใจ** — มีแค่ Σ_k D_k ≈ 0 (ถึงระดับ basis × gross) นี่คือเหตุที่ "รวมกันไม่มี downside" และ "บางขาโดน liquidate" จริงพร้อมกัน
- ถ้าจำเป็นต้องใช้สัญญาที่ไม่เหมือนกัน (เช่น SPY perp vs US500): Σ_k β_k n_k P_k = 0 โดย β จาก OLS ของผลตอบแทน 1 นาที แล้วถือ tracking error เป็น basis

### ทำไมต้องหลายขา (ไม่ใช่แค่ "มีหลายที่ให้เลือก")
ถือ +1 ของ residual ตลาด i แล้ว hedge ด้วยเวกเตอร์ h บนตลาดอื่น S โดย Σh = −1 (ยังเป็น full hedge):
```
min Var(e_i + h'e_S)  →  h* = Σ_SS⁻¹(μ·1 − Σ_Si),   μ = (1'Σ_SS⁻¹Σ_Si − 1)/(1'Σ_SS⁻¹1)
```
ถ้า residual ไม่สัมพันธ์กัน h_k ∝ −1/σ_k² และความแปรปรวนของ hedge = σ_i² + 1/Σ_j(1/σ_j²)
→ 4 ตลาดเท่ากัน: **1.33σ²** เทียบคู่เดียว **2σ²** (ความเสี่ยงต่อหน่วย edge ลดลง ~18% ใน sd)
แต่ LC กับ LR มี residual สัมพันธ์กัน (oracle/flow ร่วม) — ต้องใช้ Σ ที่วัดจริง

## 4. ราคากลางและ residual (ต่อสินทรัพย์ ตัดสินใจทุก 5–15 วินาที live / ทุก bar ในตัวจำลอง)

```
p_k   = ln(mid_k)                                           # หรือ microprice
b̂_k  ← b̂_k + α_b·(p_k − c − b̂_k),   H_b = 24 ชม.            # basis ช้าเชิงโครงสร้าง (RH vs Core, funding-implied)
          • แช่ b̂ ตอนตลาดหุ้น/ทองปิด  • LC/LR ใช้ H_b = 2 ชม. ช่วง ศ. 00:00–06:00 UTC (สัปดาห์ points เปลี่ยน)
c     = Σ_k w_k (p_k − b̂_k)       w: BN .30, BY .25, BG .20, LC .15, LR .10 (normalize เฉพาะตลาดที่ live)
e_k   = p_k − b̂_k − c                                       # residual ของตลาด k
s_ij  = e_i − e_j                                           # spread คู่ (ราคากลางหักล้าง)
σ_ij² = Σ_ii + Σ_jj − 2Σ_ij   (EWMA cov ของ e, H_v = 4 ชม.; แยก state ตลาดหุ้นเปิด/ปิด; floor 0.3bp)
φ_ij  = EWMA(s_t s_{t−1}) / EWMA(s_{t−1}²)  →  HL = ln2/−ln φ   (ปิดการเข้าคู่ถ้า HL > 240 นาที)
z_ij  = s_ij / σ_ij
```
- **กรอง persistence**: เข้าเฉพาะเมื่อ |z| ผ่านเกณฑ์ 2 snapshot ติดกัน (≥5 วินาที) — ไม่ไล่ lead-lag ระดับมิลลิวินาทีที่บัญชี Standard แย่งไม่ทัน
- carry: α_k −= f̂_k·h (funding ต่อชั่วโมงที่ long จ่าย × ระยะถือที่คาด)

## 5. เครื่องยนต์การเทรด (pair-layer + netting ต่อตลาด)

- ทุกคู่ (i = แพง, j = ถูก) ที่ s_ij > 0:
  - ประเภทที่อนุญาต: **CEX–Lighter** (maker ที่ CEX, taker ที่ Lighter), **LC–LR** (maker ที่ LR, taker ที่ LC), CEX–CEX ปิดไว้เว้นแต่ maker ≤ 0
  - ชั้นที่ z = **2.0 / 2.75 / 3.5** สูงสุด 3 ชั้นต่อคู่ 6 ชั้นต่อสินทรัพย์
  - **cost gate**: `s_ij − z_out·σ_ij + carry ≥ κ·RT_ij`, κ = 1.25, RT = 2(c_maker + c_taker) **แบบ dynamic** (ครึ่งสเปรด ณ ตอนนั้น + catch-up ที่คาด λ·E|r|)
  - เรียงผู้สมัครด้วย `(edge − κRT)/(imr_i + imr_j)` (ผลตอบแทนต่อ margin) เปิดไม่เกิน 2 ชั้น/สินทรัพย์/รอบ
- แต่ละชั้น = short u ที่ i / long u ที่ j → **Σ = 0 อัตโนมัติ** ตำแหน่งต่อตลาด = ผลรวมของทุกชั้น (ซื้อขายเฉพาะส่วนต่างสุทธิ)
- **ปิด** เมื่อ z ≤ 0.3, อายุ > min(6·HL, 24 ชม.), stop ที่ z ≥ 8 หรือ b̂ กระโดด > 3σ
- **hub assignment**: LC/LR เป็นผู้สมัครแยกกัน — Lighter ตัวที่ถูกกว่ารับขา long ตัวที่แพงกว่ารับขา short; เสมอกัน → ตัดสินด้วย margin headroom → ทิศ boost ของ points สัปดาห์นั้น → funding
- ส่วนเกิน (เศษ lot, การซ่อม) ไปที่ hub เท่านั้น CEX ไม่รับส่วนเกิน

### ตัวอย่าง (BTC ช่วงผันผวน ทุน $100k: LC 35k / LR 15k / BG 25k / BY 25k, งบ BTC 25%)
- ความจุ: Q_BG = Q_BY = 3·25k·0.25 = $18.75k → u = $6.25k; Q_LC = $26.25k; Q_LR = $11.25k
- residual (bp): LC −5.0, LR −1.0, BG +2.5, BY +3.5; σ คู่ CEX–Lighter 2.5, LR–LC 2.0
- ต้นทุนต่อข้าง (ค่าเริ่มของตัวจำลอง): LC taker 1.0 (ครึ่งสเปรด 0.3 + adverse 0.7), LR maker 0.7, CEX maker 1.3 (fee 1 + adverse 0.3) → RT(CEX,LC) = 4.6 (gate ≥ 5.75), RT(LR,LC) = 2(0.7+1.0) = 3.4 (gate ≥ 4.25)
- BG–LC: s = 7.5, z = 3.0 ✓ 2 ชั้น | BY–LC: s = 8.5, z = 3.4 ✓ 2 ชั้น | LR–LC: z = 2.0 แต่ capture 3.4 < 4.25 ✗
- พอร์ต (เปิดรอบละไม่เกิน 2 ชั้น/สินทรัพย์ → ต้อง ≥2 รอบ): **LC +$25k / BG −$12.5k / BY −$12.5k / LR 0** = +4u/−2u/−2u (u = $6.25k) หรือสัดส่วน +2/−1/−1, Σ = 0
- กำไรคาดถ้า residual กลับถึง z_out ≈ (6.75 − 4.6)·12.5k + (7.75 − 4.6)·12.5k ≈ **$6.6 ต่อรอบ**
- **reality check**: 10%/ปีบน $100k ต้อง ~1,500 รอบแบบนี้ต่อปี (~4 รอบ/วันทั้งจักรวาล) — นี่คือเหตุผลที่ต้องวัด edge จริงก่อน

## 6. Leverage, margin แยกตลาด และการโยกเงิน

- leverage ต่อตลาด ℓ_k = G_k/E_k (gross/equity): เป้าเฉลี่ย ≤ 1.5, เพดานเปิดใหม่ 3, ถึง 4 → reduce-only + เยียวยา, ถึง 5 หรือ E < 0.5·E0 → โยกเงิน
- ใช้ IMR ไม่เกิน 40% ของ equity; ขาหุ้นช่วงตลาดปิดและขาฝั่งที่โดน squeeze จำกัด 2x
- **ระยะราคาที่ทนได้ก่อนขาเดียวโดน liquidate** (Lighter BTC, MMR 1.2%): x* = (1/ℓ − m)/(1 ± m)

| ℓ ต่อตลาด | ขา short (ราคาขึ้น) | ขา long (ราคาลง) |
|---|---|---|
| 2x | 48.2% | 49.4% |
| 3x | 31.8% | 32.5% |
| 5x | 18.6% | 19.0% |
| 10x | 8.7% | 8.9% — crypto วิ่งได้ในวันเดียว |

- เพดานที่ "รัดจริง" สำหรับตลาดที่ถือทิศเดียวคือ **ทิศสุทธิต่อกลุ่มสินทรัพย์ |D_k,B|/E_k ≤ ⅔·ℓ** (= 2 ที่ ℓ = 3) ไม่ใช่เพดาน gross 3 — ตัวจำลองใช้ค่านี้เป็นค่าเริ่ม (`--dir-cap`)

- กลไก Lighter: E < IMR = pre-liquidation (เพิ่มสถานะไม่ได้) → E < MMR = ยกเลิกคำสั่งแล้ว **ปิดทีละ position** ด้วย IOC (ค่าปรับ "สูงสุด 1%" — ฐานคำนวณ **[ตรวจ]**) → E < CMR = LLP รับทั้งบัญชี
- **ความน่าจะเป็นต้องโยกเงิน** (equity ของตลาดแตะ 50% ของตั้งต้น, σ = 60%/ปี): P ≈ 2Φ(−b/(ℓσ√(fT))) โดย f = สัดส่วนเวลาที่ถือ**เต็ม** ℓ (ที่นี่ f = 0.3) — เป็นค่าประมาณสำหรับ book ที่ถือค้าง ถ้าถือสั้นๆ ระดับนาที f จริงเล็กกว่านี้มาก

| ℓ | ต่อเดือน | ต่อปี |
|---|---|---|
| 1x | ≈0 | 13% |
| 2x | 0.8% | 45% |
| 3x | 8% | 61% |
| 5x | 29% | 76% |
| 10x | 60% | 88% |

  = เนื้อหาเชิงตัวเลขของ "leverage น้อยแทบไม่ต้องโยกเงิน"
- **ลำดับการเยียวยาก่อนโยกเงินจริง**: ① หยุดเพิ่มสถานะในตลาดที่ตึง ② ย้ายสัดส่วน hub ไป Lighter อีกตัว / spoke ไป CEX อีกตัว ③ ปิดชั้นที่ขาในตลาดที่ตึงขาดทุนมากสุดแล้วเปิดใหม่โดยสลับบทบาท ("**ย้ายความเสี่ยง ไม่ใช่ย้ายเงิน**") ④ netting ข้ามสินทรัพย์ในตลาดเดียวกัน
- เส้นทางโยกเงิน: sub-account ภายในตลาด = ทันที/ฟรี; **ฝาก**เข้า LC ผ่าน Universal Deposit Address (Arbitrum ฯลฯ) ไม่กี่นาที แต่**ถอน**จาก LC (secure/fast) ลง Ethereum L1 (~20 นาที, fast จำกัด 10 ครั้ง/ชม.) แล้วค่อยส่งต่อ CEX; LR ถอน ~6 นาที; **LC ↔ LR ต้องถอน + bridge + แปลง USDC→USDG — ประมาณการ 2–6 ชม. (ไม่มีแหล่งยืนยัน) → อย่าพึ่งตอนตลาดวิกฤต**
- ระบบต้องรอดการระงับถอนของ CEX 4–8 วันโดยไม่โยกเงินเลย; เป้า ≤ 4 ครั้ง/ปี

## 7. Funding (overlay)

- ปรับเป็นต่อชั่วโมงก่อนเทียบเสมอ:
  - Lighter: จ่ายทุกชั่วโมง F8 = clamp(μ·TWAP + clamp(I − μ·TWAP, ±5bp), ±400bp), จ่าย F8/8; μ = 1 คริปโต, ½ สำหรับ RWA; I = 1bp คริปโต, 0.32bp RWA **[ตรวจเครื่องหมายสูตร]**
  - CEX: ทุก N ชม. (8/4/2/1) ตาม state ปัจจุบัน — Bybit ประกาศว่าชน cap แล้วสลับเป็นรายชั่วโมงภายใน ~4 นาที (ตอนเปิดตัวยกเว้น BTC/ETH) และกลับเป็น 2/4/8 ชม. โดยไม่แจ้ง; Bitget เห็นพฤติกรรมคล้ายกันในบางสัญญาแต่ไม่ทุกตัว **[ตรวจ: อ่าน interval ปัจจุบันจาก API ทุก 5 นาที อย่าเดาจากกฎ]**
- **หมุนก่อนตัดรอบ** (T−60 ถึง T−5 นาที): ถ้าขา spoke จะต้องจ่าย funding รอบนี้ > 2(c_maker,k + c_maker,j) + 0.5bp (~5.7bp ที่ maker 1bp) ให้ย้ายขาไป CEX อีกตัวหรือ hub ด้วย maker — ช่วงปกติแทบไม่เกิด เกิดตอน squeeze
- **squeeze guard**: |F̂| > cap/2 → ขาฝั่งที่ "ได้รับ" funding คือฝั่งที่โดนบีบ ให้จำกัด 2x
- **RWA carry (ไม่บังคับ ≤20% ของงบสินทรัพย์นั้น)**: short perp หุ้นบน Lighter / long perp หุ้นบน Bitget — long บน Lighter จ่ายดอกเบี้ย 0.32bp/8 ชม. (~3.5%/ปีของ notional) ขณะ CEX ฝั่งนี้ ≈ 0

## 8. Points (ไม่ใช่สถานะถาวร)
- ใช้ตัดสินเฉพาะกรณีที่คะแนนสองทางเท่ากัน (tie-break) เท่านั้น: วางขา hub ให้ทิศ LR ตรงกับทิศ boost ของสัปดาห์
- **ห้ามจับคู่คำสั่งตัวเองข้ามบัญชี** (self-trade/common-control ถูกแบน และมีกฎ "standard-to-standard ไม่ได้แต้ม") — ไม่นับ points ในเป้าผลตอบแทน

## 9. การส่งคำสั่งและเมื่อขาหลุด

- ข้อมูล: WebSocket BBO/depth ของ LC, LR, BG, (BY) + Binance เป็นข้อมูลอย่างเดียว; funding จาก `/api/v1/funding-rates` ของ Lighter และ endpoint ของ Bitget; เซิร์ฟเวอร์ที่ AWS Tokyo
- **ขา spoke**: post-only ที่ราคาซึ่งทำให้ z ถึงเกณฑ์ชั้น + กันชน adverse k·σ_1s·√0.3s, TTL 10 วินาที, re-quote ≤ 20 ครั้ง/นาที/ตลาด
- **ขา hub**: IOC taker บน LC/LR (fee 0) ทันทีที่ fill ของ spoke มาทาง WebSocket; เพดาน slippage 3bp (majors) / 5bp (หุ้นตลาดเปิด) / 10bp (หุ้นตลาดปิด)
- **คู่ LC–LR**: post-only บน LR (book บางกว่า) → fill แล้ว IOC บน LC
- งบคำขอ Lighter (สมมติแย่สุด 60/นาทีต่อ address และ 40/นาทีต่อประเภทธุรกรรม): quote ≤15, hedge ≤15 (รวม create ≤30 < 40), cancel ≤10, สำรอง 20 → hedge แบบ event-driven เท่านั้น ถ้าไม่พอให้พิจารณาบัญชี Plus (0.5bp) หรือลดจำนวนสินทรัพย์
- **บันไดเมื่อขาหลุด**:
  1. spoke fill f → IOC ที่ hub ที่ดีที่สุด
  2. +1 วินาที เหลือ r → IOC ที่ Lighter อีกตัว
  3. +3 วินาที ยังเหลือ → taker ที่ CEX อีกตัว (เพดาน 3bp)
  4. +10 วินาที ยังเหลือ → ปิดขา spoke เอง (reduce-only taker) แล้วบันทึก LEG_FAIL
  5. |Σ_k n[a,k]|·P > max(1 lot, 1% ของ gross สินทรัพย์) เกิน 2 วินาที → ซ่อมที่ตลาดถูกสุด; ห้ามมีชั้นที่ไม่ hedge เกิน 1 ชั้น
- **ถูกบังคับลด (liquidation/ADL)** — ตรวจจากสถานะที่ลดลงโดยไม่มี fill ของเรา → ภายใน 5 วินาที ลดขาฝั่งตรงข้ามเท่ากัน (hub ก่อน)
- ตลาดเข้า pre-liquidation → reduce-only, ปิดขาในตลาดนั้นก่อน, re-hedge ที่อื่น (Lighter ไม่ให้เพิ่มสถานะช่วงนั้น)
- ตลาดล่ม (WebSocket เงียบ > 30 วินาที) → แช่ขาไว้ (ยัง hedge อยู่) ไม่เปิดใหม่ที่เกี่ยวข้อง; ถ้า Lighter ล่มทั้งสองตัวห้ามเปิดคู่ CEX–CEX ใหม่ (เหตุการณ์จริง: Lighter ล่มหลายชั่วโมงช่วง crash 10–11 ต.ค. 2025)

## 10. ขีดจำกัดความเสี่ยงและ kill switch
- gross ต่อสินทรัพย์ ≤ 25% ของความจุรวม; คำสั่ง maker ≤ 25% ของ depth ใน 5bp; สถานะ ≤ 2× depth ใน 5bp
- ขาดทุนรายวัน 1% ของทุน → ลดขนาดครึ่ง, 2% → หยุดเปิด 24 ชม., ขาดทุนรายสัปดาห์ 3% → หยุดทั้งหมดและทบทวน
- หุ้นช่วงเสาร์-อาทิตย์ gross ≤ 50% ของวันธรรมดา
- markout + fee ของ maker บน CEX > 1.5bp (7 วันย้อนหลัง) → ปิดขา CEX อัตโนมัติ เหลือแค่ LC+LR
- ADL light ของ Bitget ≥ 4/5 หรืออันดับ ADL ของ Bybit สูง → ลดขานั้นครึ่งแล้วย้ายไป CEX อีกตัว
- |p_k − c| > 1% (majors) / 2% (alt, หุ้นตลาดเปิด) / 3% (หุ้นตลาดปิด) → หยุดตลาดนั้น (กัน oracle/mark เพี้ยน)
- WebSocket เงียบ > 3 วินาที → หยุด quote ตลาดนั้น; funding สลับรอบหรือชน cap → คำนวณใหม่ทันที; ประกาศระงับถอน → ลด lmax ตลาดนั้นเหลือ 1.5
