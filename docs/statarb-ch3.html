Ornstein-Uhlenbeck Process

หัวใจของ Stat Arb — โมเดลที่อธิบายว่า spread "วนกลับ" อย่างไร
κ (speed) · θ (mean) · σ (noise) · Half-life · Calibration
แก่นของบทนี้ — อ่านก่อน

OU Process คือ "สปริงที่มี noise" — ยิ่งดึง spread ออกจากค่ากลาง สปริงยิ่งดึงกลับแรง
Half-life บอกว่า spread ใช้เวลากลับครึ่งทางนานแค่ไหน → กำหนดว่าเราจะ trade แบบ intraday หรือ swing

dε = κ(θ − ε) dt + σ dW

3.1 Parameters ของ OU Process

Parameterชื่อความหมาย tradeค่าปกติ

θLong-run meanค่ากลางที่ entry/exit อิงอยู่ — ถ้าเปลี่ยนบ่อยต้อง re-calibrate≈0 หรือ avg funding diff

3.2 OU Solution — ε เดินไปไหนได้บ้าง

SDE นี้ solve ได้ closed-form ทำให้เราคำนวณ expected value ได้ทุกเวลา:

ε_t = θ + (ε₀ − θ)·e^{−κt} + σ·∫₀ᵗ e^{−κ(t−s)} dW_s ↑ ↑ ↑ ค่ากลาง decay จากจุดเริ่ม noise สะสม
E[ε_t | ε₀] = θ + (ε₀ − θ)·e^{−κt}

เริ่มที่ ε₀ = θ + gap₀ (ห่างจากค่ากลาง gap₀)
หลังเวลา t: ε คาดว่าจะอยู่ที่ θ + gap₀·e^{−κt}
gap ลดลงด้วยอัตรา e^{−κt} → ยิ่งนาน ยิ่งใกล้ θ

3.3 Half-Life — ตัวเลขที่สำคัญที่สุดสำหรับ Trader

Half-Life
τ₁/₂ = ln(2) / κ ≈ 0.693 / κ

เวลาที่ gap ระหว่าง ε และ θ ลดลงครึ่งหนึ่ง
ถ้า spread เบี่ยง 1% จาก θ → หลัง τ₁/₂ จะเหลือ 0.5%

Half-life = ช่วงเวลาที่ spread เดินทางครึ่งทางกลับ — ใช้วางแผน expected holding time

3.4 Stationary Distribution — Band ของ Trade

เมื่อ t → ∞ OU process เข้าสู่ stationary distribution ซึ่งเป็น Normal:

ε_∞ ~ N(θ, σ²/(2κ)) σ_ε = σ/√(2κ) ← stationary std dev (ใช้ตั้ง entry band)
σ_ε ใช้ทำอะไร?
  • Entry threshold: ε > θ + 2σ_ε หรือ ε < θ − 2σ_ε (เกิดราว 5% ของเวลา)
  • Exit threshold: ε ≈ θ ± 0.5σ_ε
  • Stop-loss: |ε − θ| > 3σ_ε (spread "หลุด" ผิดปกติ)
  • ตรวจสอบ: ε ควรอยู่ในช่วง θ ± 3σ_ε กว่า 99.7% ของเวลา — ถ้าไม่ใช่ = signal ให้ re-calibrate

3.5 AR(1): OU Process ในโลกข้อมูล Discrete

ข้อมูลจริงเป็น discrete (รายนาที รายชั่วโมง) เมื่อแปลง OU เป็น AR(1):

OU → AR(1) (time step Δt)
ε_t = a + b · ε_{t-1} + η_t

b = e^{−κΔt} ← mean-reversion coefficient
a = θ(1−b) ← intercept
η_t ~ N(0, σ²(1−b²)/(2κ)) ← noise

อ่าน b บน Scale — b บอกอะไร?

b ≈ 0.9–0.95 ต่อ time step มักเป็น sweet spot สำหรับ intraday stat arb
สูตรแปลง AR(1) → OU parameters
κ = −ln(b) / Δt      θ = a / (1 − b)

ตัวอย่าง: b = 0.90, Δt = 1 ชม. = 1/24 วัน
κ = −ln(0.90) / (1/24) = 0.105 × 24 = 2.53 ต่อวัน
Half-life = ln(2) / 2.53 = 0.274 วัน = 6.6 ชม.

3.6 Calibration — หา κ, θ, σ จากข้อมูลจริง

1
สร้าง spread series: ε_t = log(P_Bybit_t) − β·log(P_Lighter_t)
(β ได้จาก OLS บน log returns — บทที่ 4)
2
Regress AR(1): ε_t = a + b·ε_{t-1} + η_t
บันทึก: a, b, และ residuals η
3
คำนวณ OU parameters:
θ = a/(1−b), κ = −ln(b)/Δt, σ_stat ≈ std(ε − θ)
4
คำนวณ trade parameters:
τ₁/₂ = ln(2)/κ → กำหนด holding time
Entry band = θ ± 2σ_stat → กำหนด entry threshold
# Pseudo-code: OU Calibration
function calibrate_ou(eps_series, delta_t):
  # Step 1: AR(1) regression
  y = eps_series[1:] # ε_t
  x = eps_series[:-1] # ε_{t-1}
  b, a = ols_slope_intercept(x, y)
  residuals = y - (a + b * x)

  # Step 2: OU parameters
  theta = a / (1 - b)
  kappa = -log(b) / delta_t
  sigma_stat = std(eps_series - theta)
  half_life = log(2) / kappa

  # Step 3: Trade bands
  entry_upper = theta + 2 * sigma_stat
  entry_lower = theta - 2 * sigma_stat
  stop_upper = theta + 3 * sigma_stat
  stop_lower = theta - 3 * sigma_stat

  return {theta, kappa, sigma_stat, half_life,
          entry_upper, entry_lower, stop_upper, stop_lower}
ตัวอย่างจริง: Bybit↔Lighter BTC — Calibration ผล
ข้อมูล: 30 วัน, รายนาที (Δt = 1/1440 วัน) ε_t = log(P_Bybit) − 1.003·log(P_Lighter) OLS AR(1) result: b = 0.9985, a = 2.0×10⁻⁶ Residual std = 0.00012 OU Parameters: θ = 2.0e-6 / (1−0.9985) = 0.00133 (basis ≈ 0.133%) κ = −ln(0.9985)/(1/1440) = 2.16 ต่อวัน σ_stat ≈ 0.00080 (≈ 0.08%) Trade Parameters: τ₁/₂ = 0.693/2.16 = 7.7 ชั่วโมง ← intraday trade ได้ Entry: ε > 0.293% หรือ ε < −0.027% (θ ± 2×0.08%) Stop: ε > 0.373% หรือ ε < −0.107% (θ ± 3×0.08%)

สรุป: spread กลับใน ~8 ชม. เปิด position ตอนเช้า → ปิดก่อนค่ำ

3.7 เมื่อไร OU เดี่ยวไม่พอ — และบทถัดไปจะแก้อย่างไร

สมมติฐาน OUเมื่อไรที่ผิดสัญญาณที่เห็นโมเดลที่ใช้แทน
κ, θ คงที่ตลาด regime change: funding rate เปลี่ยนโครงสร้างθ drift ออก, ε ไม่กลับKalman (Ch.4), Regime-Switch (Ch.9)
σ คงที่ช่วง volatile: market crash, newsresidual variance พุ่งGARCH on residuals (Ch.7)
Gaussian noiseliquidation cascade, news spikeresidual มี fat tail, jumpJump-Diffusion OU (Ch.8)
β คงที่ตลาดเปลี่ยน correlationε drift กลับมาKalman Filter β (Ch.4)
Rule of thumb: เมื่อไรต้อง re-calibrate?
  • θ เคลื่อนออกจากค่าเดิม > 1σ_stat ใน 5 วัน → re-calibrate β และ θ
  • Residual variance พุ่ง > 2× baseline → switch ไป GARCH
  • Half-life ยาวขึ้น > 2× → regime เปลี่ยน พิจารณา exit ทั้งหมด

3.8 ตารางสัญลักษณ์ (Notation Reference) — ใช้ตลอดทั้งเล่ม

ทั้งเล่มใช้ σ หลายแบบ ต่างกันที่จุดประสงค์และวิธีคำนวณ — ตารางนี้เป็นอ้างอิงกลางที่ควรกลับมาดูทุกครั้งที่สับสน:

สัญลักษณ์ชื่อเต็มความหมายคำนวณจากใช้ใน
σ (SDE) Diffusion coefficient ขนาด noise ใน OU SDE: dε = κ(θ−ε)dt + σ·dW σ = σ_stat · √(2κ) Ch.2–3 สมการทฤษฎี
σ_stat Stationary std Std ของ spread ε ณ steady state — ใช้กำหนด entry/exit band σ_stat = σ/√(2κ) ≈ std(ε) Ch.3–4 entry band θ ± 2σ_stat
σ_t (GARCH) Conditional std Std ของ spread ε ณ เวลา t — ขยายตัวช่วง volatile σ_t² = ω + α·ε²_{t−1} + β·σ²_{t−1} Ch.7 GARCH z-score
σ_robust Robust std (MAD-based) Estimate σ_stat ที่ทนต่อ outlier — ไม่กระทบจาก jump σ_robust = MAD × 1.4826 Ch.10 robust z-score
σ_EMA EMA-smoothed std Rolling std ด้วย exponential weighting — Welford-style Welford online update (Ch.15) Ch.15 dynamic β tracking
กฎง่าย ๆ ในการเลือก σ
  • ตลาดปกติ: ใช้ σ_stat (OLS residual std) — เร็วและง่าย
  • ช่วง volatile (ratio 7d/30d std > 1.5): เปลี่ยนเป็น σ_t จาก GARCH(1,1)
  • มี outlier / jump: ใช้ σ_robust = MAD × 1.4826 แทน std()
  • β เปลี่ยนตาม Kalman: ε เปลี่ยนทุก bar → ใช้ σ_EMA แบบ Welford update
สัญลักษณ์อื่น ๆความหมาย
ε_tSpread residual at time t: ε = log(P_A) − β·log(P_B)
θLong-run mean ของ OU (equilibrium spread level)
κMean-reversion speed (ต่อวัน); τ₁/₂ = ln(2)/κ
βHedge ratio (OLS, TLS, หรือ Kalman)
HHurst exponent; H < 0.5 = mean-reverting
z_tZ-score ของ spread: (ε_t − θ)/σ_stat หรือ (ε_t − θ)/σ_t
τ₁/₂Half-life ของ mean-reversion: τ₁/₂ = ln(2)/κ
ΔtBar size ในหน่วยวัน (1-hour bar: Δt = 1/24)
โจทย์ 3.1 — คำนวณ half-life และ trade parameters

OLS AR(1) บน spread รายชั่วโมง (Δt = 1/24 วัน): b = 0.94, a = 0.00012
std(residuals) = 0.00015

ถาม: (a) κ ต่อวัน (b) half-life เป็นชั่วโมง (c) entry band (d) spread ปัจจุบัน 0.05% จาก θ — ควร enter ไหม?

ดูคำตอบ

(a) κ = −ln(0.94)/(1/24) = 0.0619×24 = 1.485 ต่อวัน

(b) τ₁/₂ = ln(2)/1.485 = 11.2 ชั่วโมง

(c) θ = 0.00012/(1−0.94) = 0.002 = 0.2%
σ_stat ≈ std(ε) — ถ้าใช้ residual std × √(1/(1−b²)) ≈ 0.00015/√(1−0.94²) ≈ 0.00043 = 0.043%
Entry band: 0.2% ± 2×0.043% = (0.114%, 0.286%)

(d) spread 0.05% จาก θ = ε อยู่ที่ 0.25% (สมมติอยู่เหนือ θ)
0.25% < entry upper 0.286% → ยังไม่ถึง threshold → ยังไม่ enter

โจทย์ 3.2 — แปลง b → strategy design

Spread รายชั่วโมง ให้ผล AR(1): b = 0.97
ค่า fee รวม (open+close) = 0.06% per round-trip

ถาม: (a) half-life (b) ถ้าตั้ง entry ที่ 2σ_stat = 0.10% จะถือ position นานแค่ไหนโดยเฉลี่ย และ expected profit คืออะไร (ก่อน fee)?

ดูคำตอบ

(a) κ = −ln(0.97)/(1/24) = 0.0305×24 = 0.732 ต่อวัน
τ₁/₂ = ln(2)/0.732 = 0.95 วัน ≈ 22.7 ชั่วโมง

(b) Entry ที่ 2σ = 0.10% จาก θ
Exit ที่ θ (ครบ 2σ) → expected travel = 0.10%
แต่ถ้า exit ที่ 0.5σ = 0.025% → expected travel = 0.075%
Gross profit ≈ 0.075%–0.10%, fee = 0.06% → Net ≈ 0.015%–0.04% per trade
Holding time เฉลี่ย ≈ τ₁/₂ = 22.7 ชม. (ถ้า exit ที่ θ) หรือน้อยกว่า

Trade นี้มี edge บาง — ต้อง calibrate ละเอียดและ monitor σ_stat ไม่ให้ขยาย

โจทย์ 3.3 — วินิจฉัย OU breakdown

ใช้ OU trade Bybit↔Lighter มา 2 สัปดาห์ κ เดิม = 2 ต่อวัน, θ = 0.1%
สัปดาห์ที่ 3: spread ออกไปถึง 0.4% และค้างอยู่นาน 3 วัน ไม่กลับ

ถาม: เกิดอะไรขึ้น และควรทำอะไร?

ดูคำตอบ

วินิจฉัย: Regime change — OU parameters เปลี่ยน ที่เป็นไปได้:

  • θ เปลี่ยน (เช่น funding rate structure เปลี่ยน) → θ ใหม่อาจอยู่ที่ 0.3-0.4%
  • κ ลดลง → half-life ยาวขึ้น spread ใช้เวลานานกว่าจะกลับ
  • β เปลี่ยน → ε drift ไม่หาย

ควรทำ:

  1. ปิด position ทั้งหมด (stop-loss triggered ที่ 3σ)
  2. Re-calibrate OU ด้วยข้อมูล 2 สัปดาห์ล่าสุด → ได้ θ และ κ ใหม่
  3. ตรวจสอบว่า ADF test ยังผ่านไหม — ถ้าไม่ผ่าน = ε ไม่ stationary แล้ว หยุด trade คู่นี้
