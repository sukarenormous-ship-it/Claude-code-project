บทที่ 5: Payoff Deconstruction — "ถอดเลโก้"

ทุก financial product = ชิ้นเลโก้หลายชิ้นประกอบกัน ถ้าถอดออกได้ → รู้ว่าแต่ละชิ้นราคาเท่าไร → รู้ว่าราคารวมถูกหรือแพงเกินไป

ตัวอย่าง: Structured Note "คืนเงินต้น + 50% upside"

ธนาคารขาย Structured Note ฿105:
"ได้เงินต้นคืนแน่ + ถ้าหุ้นขึ้น ได้ 50% ของ upside"

ถอดเลโก้:
ชิ้นที่ 1: Bond (คืนเงินต้น) = ฿97 (PV ของเงินต้น)
ชิ้นที่ 2: 0.5 × Call Option = ฿5 (ครึ่งหนึ่งของ Call)
ต้นทุนจริง = 97 + 5 = ฿102

ธนาคารขาย ฿105 → คุณจ่ายแพงเกิน ฿3!
ถ้าซื้อ Bond + Call เอง = ถูกกว่า ฿3
หลักการ: ถ้าถอดได้ = รู้ราคาจริง

ทุก product ที่ "ซับซ้อน" สามารถถอดเป็น building blocks ง่ายๆ ได้
ความซับซ้อน = premium ที่คนจ่ายเพราะไม่เข้าใจ → ถ้าเข้าใจ = ไม่ต้องจ่าย!

ลองคิดดู (บท 5)

DW (Derivative Warrant) ในตลาด SET ราคา ฿1.50 → ถอดดู = Call Option ที่ issuer กิน spread เท่าไร?
(คำใบ้: คำนวณ BS theoretical price → เทียบกับ DW price → ส่วนต่าง = issuer's margin)
เฉลย: ถ้า BS price = ฿1.20 แต่ DW ขาย ฿1.50 → issuer กิน ฿0.30 (25%!) นี่คือ "complexity premium"

3 สิ่งที่ต้องจำจากบท 5

1. ทุก product ซับซ้อน = building blocks ง่ายๆ รวมกัน
2. ถอดได้ = รู้ราคาจริง → ถ้าราคาสูงกว่า = จ่าย complexity premium
3. Structured Note, DW, Insurance package ล้วนมี hidden markup

บทที่ 6: Payoff Construction — "ต่อเลโก้"

กลับด้านจากบท 5: เริ่มจาก "อยากได้ payoff แบบนี้" → ต่อจาก blocks → ได้ structure

ขั้นตอน 3 ขั้น

Step 1: เขียน "สิ่งที่อยากได้" เป็น piecewise function
Step 2: จับคู่กับ building blocks ที่รู้จัก
Step 3: เลือก instruments ที่ถูกที่สุด (อาจมีหลายวิธีสร้าง!)

ตัวอย่าง: "กำไรถ้าขึ้น แต่ไม่เกิน $2,500 ไม่อยากเสียถ้าลง"

Step 1 — Piecewise:
  P(S) = { 0        ถ้า S < $2,000
         { S-2000   ถ้า $2,000 ≤ S ≤ $2,500
         { 500      ถ้า S > $2,500

Step 2 — จับคู่:
  = Long Call($2,000) - Long Call($2,500) = Call Spread(2000,2500)

Step 3 — เลือก:
  วิธี A: ซื้อ Call Spread บน exchange
  วิธี B: ซื้อ PM Above Yes($2,000) + PM Above No($2,500)
  → เทียบราคา → ซื้อวิธีที่ถูกกว่า!
พลังของ Payoff Construction

ไม่ต้องจำชื่อ strategy (Bull Call Spread, Iron Condor, Butterfly...)
แค่เขียนสิ่งที่อยากได้ → solve → ได้ instruments
คุณไม่ได้ "ใช้ strategy ที่มีอยู่" — คุณ "ประดิษฐ์ strategy ที่ต้องการ"

ลองคิดดู (บท 6)

"อยากได้ +$100 ถ้าราคาอยู่ระหว่าง $80K-$100K ไม่อยากเสียเกิน $20"
→ เขียน piecewise → จับคู่ → มี 2 วิธี: Options (Butterfly) vs PM (Range Yes) → อันไหนถูกกว่า?
เฉลย: Piecewise = {-20 นอก range, +100 ใน range} = PM Range Yes($80K-$100K) × N contracts, หรือ = Iron Butterfly centered at $90K → เทียบราคาทั้งสอง!

บทที่ 7: Cross-Market Translation — "ชุดเดียวกัน แค่ใส่ต่างกัน"

บทสำคัญที่สุดของเล่ม — สิ่งเดียวกัน มีชื่อต่างกันในแต่ละตลาด

สิ่งที่ต้องการOptionsPMInsuranceBettingDeFi
"จ่ายถ้าเกิน X"Call(X)Above YesประกันภัยOver XCall on DEX
"จ่ายถ้าต่ำกว่า X"Put(X)Below Yes (Above No)ชดเชยUnder XLiquidation protect
"จ่ายถ้าอยู่ในช่วง"ButterflyRange Yes—Band betRange order
"ไม่เสียเกิน X"Protective Put—Deductible—Stop-loss
เสียงจากสนาม — Sports Bettor (20 ปี)

"Pinnacle (sharp, tight lines) = Deribit. Bet365 (soft, limits winners) = retail CEX. Local bookies (slow, stale lines) = illiquid DEX pools. The principle is identical: latency arbitrage against the slowest price-setter."

แปล: ตลาดทุกประเภทมีลำดับชั้นเดียวกัน: sharp → soft → slow → arb คือซื้อจาก slow ขายใน sharp

Overround = Skew Stripping

Bookmaker: ฟุตบอล ทีม A ชนะ odds 2.10 | เสมอ 3.30 | ทีม B ชนะ 3.50
Implied prob: 47.6% + 30.3% + 28.6% = 106.5% (ไม่ใช่ 100%!)
ส่วนเกิน 6.5% = overround = margin ของ bookmaker

เทียบกับ Options: IV ที่ quote มา ก็มี "skew markup" ซ่อนอยู่
วิธีหา fair probability: ลบ overround ออก = เหมือน strip skew ออกจาก IV
ลองคิดดู (บท 7)

PM "Fed ลดดอกเบี้ยในมีนาคม" = 62¢, CME Fed Funds Futures implied = 74%
→ Gap 12% → เป็น arb ไหม? ต้องเช็คอะไรก่อน?
เฉลย: เช็ค: PM settlement=อะไร? (UMA oracle vs CME official), Timing ตรงกันไหม?, Fees (PM 10% on profit?), Access (คนไทยซื้อ PM ได้ไหม?) → ถ้าตรงหมดและ net > 0 หลังหัก fees = real edge

บทที่ 8: "ราคาต่างกัน ทำไม?" — Adverse Selection + MM View

เมื่อเห็น "ของเดียวกัน ราคาต่าง" อย่ารีบดีใจ → ถามว่า "ทำไม?"

8-Point Checklist

เห็นราคาต่าง → เช็ค 8 ข้อ:
1. Settlement ต่างกันไหม? (cash vs physical)
2. Expiry ตรงกันไหม?
3. Exercise style? (European vs American)
4. Liquidity? (bid-ask ของแต่ละตลาด)
5. Counterparty risk? (exchange vs DeFi vs P2P)
6. Fees? (PM 10% vs Options 0.1%)
7. Capital lock-up? (margin vs full payment)
8. Regulatory? (ทำได้ทั้ง 2 ตลาดไหม?)
9. ภาษี — กำไรจาก 2 ขา อาจถูก treat ต่างกัน (capital gain vs income vs tax-exempt); สำหรับ Thai trader cross-border crypto trade ภาษีอาจกิน spread ทั้งหมด

ผ่านทั้ง 9 ข้อ + ยังราคาต่าง = arb จริง!
ผ่านไม่ครบ = มี "แต่" ที่อธิบายส่วนต่าง → อาจเป็น near-arb
เสียงจากสนาม — Market Maker (20 ปี)

"The 'arbs' retail traders find are usually the ones we've decided aren't worth defending. Your weakness: you need us more than we need you."

แปล: arb ที่คุณเห็น = arb ที่ Market Maker ตัดสินใจแล้วว่าไม่คุ้มปกป้อง คุณต้องการเขามากกว่าเขาต้องการคุณ

Adverse Selection — "ถ้า fill ง่ายเกินไป..."

ถ้าคุณเข้า "arb" แล้ว fill ได้ทันที size ใหญ่ ไม่มีปัญหา → ถามตัวเอง:
"ทำไมอีกฝ่ายยินดีเป็น counterparty ให้ผม?"
→ เขาอาจรู้อะไรที่คุณไม่รู้ → คุณอาจเป็น "เหยื่อ" ไม่ใช่ "arbitrageur"

กฎ: ยิ่ง fill ง่าย ยิ่งต้องสงสัย

เสียงจากสนาม — Insurance Actuary (20 ปี)

"In insurance, healthy people don't buy coverage — the sick do. In arb, if you're easily filled on a 'mispricing,' you're the sick person who thinks they're the underwriter."

ลองคิดดู (บท 8)

คุณเห็น BTC Call K=$70K ราคา $500 บน Exchange X แต่ Exchange Y ขาย $400 → ส่วนต่าง $100
คุณส่ง order ซื้อที่ Y fill ทันที 100 contracts → ดีใจ! แต่...
→ ทำไม fill ง่ายขนาดนั้น? เช็ค 8-point checklist → พบว่า Exchange Y มี settlement delay 3 วัน → ราคาอาจเปลี่ยนก่อน settle!
เฉลย: Adverse Selection — Exchange Y ราคาถูกเพราะ settlement risk สูงกว่า → ไม่ใช่ arb จริง แค่ risk premium

3 สิ่งที่ต้องจำจากบท 8

1. เห็นราคาต่าง → เช็ค 8-point checklist ก่อนสรุป
2. ถ้า fill ง่ายเกินไป = สงสัยไว้ก่อน (Adverse Selection)
3. Market Maker เห็นคุณก่อนที่คุณจะเห็นเขา — เข้าใจอีกฝั่งของ trade

วิธีอ่าน Option Chain → Implied Probability

เปิด Deribit → BTC → Options → เลือก expiry:

Strike = $100,000 | Call Ask = $850 | Call Bid = $800 | Delta ≈ 0.42 วิธีที่ 1 — ใช้ Delta (approximation สำหรับ OTM): Implied prob ≈ |Delta| ≈ 0.42 → approximation ~42% (ดูข้อควรระวังด้านล่าง) วิธีที่ 2 — Tight Call Spread (risk-neutral PDF): C(100,000) = $850, C(100,100) = $840 ($850 − $840) / $100 = 10% ต่อ $100 ← นี่คือ probability DENSITY แปลว่า: โอกาส ~10% ที่ BTC จะ expire ระหว่าง $100,000–$100,100 ≠ โอกาสที่ BTC จะ expire เหนือ $100,000 (นั่นคือ cumulative) → สำหรับ cumulative probability ใช้วิธีที่ 3 (N(d2)) วิธีที่ 3 — ใช้ N(d2) จาก Black-Scholes: Implied prob = N(d2) ← ตัวเลขนี้แสดงใน platform ส่วนใหญ่เป็น "Prob ITM" ⚠️ N(d2) = risk-neutral probability — ใช้สำหรับ pricing/arb ≠ real-world probability ว่า BTC จะขึ้นหรือลงจริง (ใช้ r = risk-free rate เป็น drift ไม่ใช่ real expected return)

กฎง่าย: ดู "Prob ITM" (N(d2)) เสมอ — |Delta| = N(d1) ≠ N(d2) สำหรับ BTC ที่ IV ~70% ต่างกันได้ 5–10pp; ใช้ Delta เป็น quick glance เท่านั้น

⚠️ ทำไม Delta ≠ Prob ITM: Delta = N(d₁), Prob ITM = N(d₂), ต่างกัน σ√T — สำหรับ BTC (σ≈70%, T=30 วัน): σ√T ≈ 0.20 → N(d₁) สูงกว่า N(d₂) ได้ถึง 8pp

8.5 Put-Call Parity — กฎที่ห้ามละเมิด

Put-Call Parity (PCP) คือความสัมพันธ์พื้นฐานที่ต้องเป็นจริงเสมอ:

C − P = S − PV(K) C = ราคา Call option (strike K, expiry T) P = ราคา Put option (strike K, expiry T เดียวกัน) S = ราคา Spot ปัจจุบัน PV(K) = K × e^(−rT) ≈ K (ถ้า r ≈ 0 หรือ T สั้น)
ระวัง: r≈0 ไม่เป็นจริงในปัจจุบัน

USD interest rates ปัจจุบัน ~5%/year — สำหรับ 30-day options บน $95,000 strike:
PV(K) = $95,000 × e^(−0.05 × 30/365) ≈ $94,612 (ต่างกัน ~$388)
ถ้าใช้ PV(K) ≈ K จะได้ false PCP violation signal — เสมอ ใส่ r จริงในสูตร หรือใช้ Prob ITM จาก platform โดยตรง

ถ้า PCP ไม่เป็นจริง → มี arb ทันที: Long ฝั่งที่ถูกกว่า + Short ฝั่งที่แพงกว่า

ตัวอย่าง BTC — PCP Check
BTC Spot = $95,000 | Strike K = $95,000 | T = 7 วัน | r ≈ 0 ทฤษฎี: C − P = S − K = $95,000 − $95,000 = $0 → Call และ Put ATM ต้องราคาเท่ากัน (สำหรับ European, r≈0) ถ้าตลาดแสดง: Call = $2,400, Put = $2,100 C − P = $300 ≠ $0 Gap = $300 → ถ้า round-trip fee < $300 → มี arb Arb: Buy Put + Buy Spot + Sell Call → ได้ $300 − fees
ข้อควรระวัง
  • PCP ใช้ได้กับ European options เท่านั้น — สำหรับ American options PCP กลายเป็น inequality: S − K ≤ C − P ≤ S − PV(K) สำหรับ deep ITM American put ส่วนต่างนี้ อาจสูงมาก เพราะ early exercise premium ห้ามใช้ PCP เป็น equality กับ American options เด็ดขาด (เช่น หุ้นบน TFEX ที่เป็น American-style)
  • Crypto options บน Deribit เป็น European → PCP ใช้ได้
  • PM "Above Yes" ≠ vanilla Call — PCP ไม่ apply ตรงๆ แต่ยังใช้เทียบ implied prob ได้

8.6 Daily Scan Checklist — สแกนทุกวัน

สแกน 3 อย่างนี้ทุกวัน ใช้เวลาไม่ถึง 10 นาที — ถ้าเจอ flag ให้ตรวจต่อด้วย 8-point checklist:

CheckสูตรFlag เมื่อAction
A. PCP|C − P − S + PV(K)|> round-trip fee (~0.2%)ตรวจ exercise style + counterparty risk
B. Basis(Perp − Spot) / Spot × 100%|basis| > 0.3%คำนวณ Cash & Carry net yield vs baseline
C. MonotonicityCall(K₁) > Call(K₂) ถ้า K₁ < K₂?ถ้าไม่จริง (inverse)ข้อมูลผิดหรือ liquidity ต่ำมาก — ระวัง
def daily_scan(spot, perp, call_chain, put_chain, K, fee_pct=0.002): # A: PCP check C = call_chain[K]; P = put_chain[K]; PV_K = K # r≈0 pcp_gap = abs(C - P - spot + PV_K) if pcp_gap > spot * fee_pct: flag("PCP violation", pcp_gap) # B: Basis check basis = (perp - spot) / spot if abs(basis) > 0.003: flag("Basis wide", basis * 100, "%") # C: Monotonicity check strikes = sorted(call_chain.keys()) for i in range(len(strikes) - 1): if call_chain[strikes[i]] < call_chain[strikes[i+1]]: flag("Monotonicity broken", strikes[i])
วิธีใช้ checklist นี้

เมื่อ flag ขึ้น → ไม่ได้แปลว่ามี arb ทันที → แค่บอกว่า "ควรดูให้ละเอียดขึ้น"
ขั้นต่อไปเสมอ: ตรวจ 8-point checklist (บท 8) → ถ้าผ่านทั้ง 8 ข้อ → คำนวณ net edge → Label
