Dynamic Payoff — "Payoff ที่เปลี่ยนระหว่างทาง"

แนวคิด: ทำไมต้องปรับ?

ทุกอย่างที่ผ่านมาสอน payoff ณ expiry — แต่ในชีวิตจริง:

• ราคาไม่ได้อยู่นิ่งรอจนหมดอายุ
• View อาจเปลี่ยน — "เมื่อวานคิดว่าขึ้น วันนี้ไม่แน่ใจ"
• ขาที่เสียอาจต้อง "ซ่อม" ก่อน expiry
• Option ใกล้หมดอายุ → theta กัดเร็วขึ้น → อาจต้อง roll

3 เทคนิคปรับ Payoff ระหว่าง Trade

1. Roll — "ย้ายขาไปข้างหน้า"

Roll Forward: ปิดขาที่ใกล้หมดอายุ → เปิดขาใหม่ที่ expiry ไกลกว่า

ตัวอย่าง: Short Call(100) หมดอายุ 30 เม.ย.
→ Buy to close Short Call(100) 30 เม.ย.
→ Sell to open Short Call(100) 31 พ.ค.

ผลต่อ payoff: shape เดิม แต่ "เลื่อนเวลา" → เก็บ theta premium อีกรอบ
ต้นทุน: debit = ค่าซื้อคืน - ค่าขายใหม่ (อาจ net credit ถ้า IV ดี)
Roll Up/Down: เปลี่ยน strike ด้วย

ตัวอย่าง: Short Call(100) กำลังจะ ITM → Roll Up
→ Buy to close Short Call(100)
→ Sell to open Short Call(110) (same/further expiry)

ผลต่อ payoff: จุดหักศอกเลื่อนจาก K=100 ไป K=110 → ให้ upside room มากขึ้น
ต้นทุน: มักต้องจ่าย debit (Short Call ที่ ITM แพงกว่า OTM)

Net profit (หลังหัก premium)

2. Adjust — "เพิ่มขาเพื่อเปลี่ยน shape"

ตัวอย่าง: Long Call(100) กำลังขาดทุน → เพิ่ม Short Call(120)

ก่อน: Long Call(100) → unlimited upside แต่เสีย premium
หลัง: Long Call(100) + Short Call(120) = Bull Call Spread 100/120

ผลต่อ payoff: จำกัด upside แต่ได้ premium จาก Short Call มาชดเชย
→ ลด max loss, ลด break-even → "ลดความเจ็บปวดถ้าผิดทาง"
วิธีคิด: "เพิ่มขาจะเปลี่ยน payoff อย่างไร?"

ก่อนเพิ่มขา ให้ถาม:
1. เพิ่มขานี้จะเพิ่ม slope ที่ช่วงไหน?
2. จะเปลี่ยน max profit/loss อย่างไร?
3. จะเปลี่ยน break-even ไปตรงไหน?
4. ต้นทุน (debit/credit) เท่าไร?

ลองวาดก่อน → ลองใน payoff-builder.html → ค่อย execute จริง

3. Repair — "ซ่อม position ที่เสียหาย"

ตัวอย่าง: ซื้อหุ้นที่ ฿100 ตอนนี้ลงไป ฿85 → ขาดทุน ฿15

Repair Strategy:
Long Stock(ซื้อที่ 100, ตอนนี้ 85)
+ Long 1 Call(85) ← ATM call (฿5)
+ Short 2 Calls(92.50) ← ขาย 2 ตัว (฿2.50 × 2 = ฿5)
→ Net cost = 0 (premium ชดเชยกัน)

ผลต่อ payoff:
ถ้าราคากลับขึ้นเหนือ 92.50 → ได้เงินคืนครบ (ไม่ต้องรอถึง 100!)
แต่ถ้าราคาขึ้นเกิน 92.50 → ไม่ได้เพิ่มอีก (capped)
ถ้าราคาลงอีก → ขาดทุนเพิ่ม (+ มี ratio risk จาก Short 2 Calls)

ข้อดี: ลด break-even จาก 100 → 92.50 โดยไม่เสียเงินเพิ่ม
ข้อเสีย: cap upside + ratio risk ทางขวา
คำเตือน: Repair ≠ Magic

Repair strategy ไม่ได้ลบ loss — มันเปลี่ยนรูปร่าง payoff เท่านั้น
"ลด break-even" = แลกกับ "cap upside" → ไม่มีอะไรฟรี
ก่อน repair ให้ถาม: "ถ้าเริ่มใหม่ตอนนี้ ผมจะเปิด trade เดิมไหม?"
ถ้าคำตอบคือ "ไม่" → ปิด position ดีกว่า repair

3 สิ่งที่ต้องจำ (Dynamic Payoff)

1. Roll = เลื่อนเวลาหรือ strike → เก็บ theta เพิ่ม หรือให้ room มากขึ้น
2. Adjust = เพิ่มขาเพื่อเปลี่ยน shape → ลด risk แลก upside
3. Repair = ลด break-even โดยไม่จ่ายเพิ่ม → แต่ cap upside + อาจเพิ่ม risk

DW vs Vanilla Options — "สิ่งที่นักลงทุนไทยต้องรู้"

Derivative Warrant (DW) คืออะไร?

DW คือ option ที่ออกโดย broker/issuer (เช่น บล.เกียรตินาคินฯ, บล.แมคควอรี) ซื้อขายบน SET
ดูเหมือน Call/Put option แต่มี ความแตกต่างซ่อน ที่กระทบ payoff จริง

คุณสมบัติDW (Derivative Warrant)TFEX Options (SET50)
ผู้ออกBroker/Issuer (counterparty risk)ตลาด TFEX (clearing house ค้ำ)
Payoff shapeคล้าย Long Call/Put แต่ cappedLong Call/Put มาตรฐาน
Premiumแพงกว่า (มี issuer margin ซ่อน)ตาม market supply/demand
Expiryกำหนดโดย issuer (มักสั้น)มาตรฐาน (รายเดือน/ไตรมาส)
Knock-outบางตัวมี (ถ้าราคาถึง barrier → DW หมดค่าทันที!)ไม่มี
Short ได้ไหมไม่ได้ (ซื้อได้อย่างเดียว)ได้ทั้ง Long/Short
Bid-askIssuer เป็น market maker → spread อาจกว้างหลาย market makers แข่งกัน

DW Knock-out — Risk ที่ payoff chart ไม่แสดง!

DW บางตัวมี knock-out barrier: ถ้าราคา underlying แตะ barrier → DW หมดค่าทันที
Payoff chart ปกติไม่แสดงสิ่งนี้ → ต้องดู term sheet!

ตัวอย่าง: DW Call K=900, Barrier=1050 บน SET50
ถ้า SET50 ขึ้นถึง 1050 → DW หมดค่า! (แทนที่จะกำไร)
= payoff chart "ถูกตัด" ทางขวา → ไม่ใช่ Long Call ธรรมดา

TFEX SET50 Options — ทางเลือกสำหรับคนไทย

TFEX มี SET50 Index Options: European style, cash-settled
ข้อดี: ไม่มี issuer risk, Short ได้, transparent pricing
ข้อเสีย: liquidity ต่ำกว่า DW, ต้องเปิดบัญชี TFEX แยก

กฎ: เปรียบเทียบ DW premium vs TFEX premium เสมอ
ถ้า DW แพงกว่า TFEX option เดียวกัน > 10% → ใช้ TFEX ดีกว่า

จิตวิทยาของ Payoff Shape — "ทำไมคนชอบ Iron Condor"

Kahneman's Prospect Theory กับ Payoff Chart

Daniel Kahneman (Nobel 2002) พบว่า คนมี loss aversion — ความเจ็บปวดจากการเสียเงิน ฿100 รุนแรงกว่า ความสุขจากการได้เงิน ฿100 ประมาณ 2-2.5 เท่า

ผลต่อการเลือก Payoff Shape

เพราะ loss aversion → คนชอบ shape ที่:
• "ชนะบ่อย" (high win rate) → รู้สึกดี
• "เห็น loss จำกัด" (defined max loss) → รู้สึกปลอดภัย
• "เก็บ premium ทุกเดือน" (income feel) → รู้สึกมีรายได้

= Iron Condor, Credit Spreads, Covered Call → ยอดนิยม!

แต่ shape เหล่านี้มักมี negative skew:
ชนะบ่อยแต่ชนะน้อย + แพ้ไม่บ่อยแต่แพ้หนัก → EV อาจ ≤ 0

ShapeWin Rateความรู้สึกReality
Iron Condor~70-80%"เก็บเงินทุกเดือน สบาย"1 gap ลบกำไร 6-12 เดือน
Credit Spread~60-70%"ได้เงินก่อน ขาดทุนจำกัด"Risk/reward อาจ 3:1 ถึง 5:1 ไม่เข้าทาง
Covered Call~65-75%"ถือหุ้นได้ dividend + premium"= Short Put (downside เต็มๆ)
Long Straddle~30-40%"เสียบ่อย ไม่ชอบ"แต่ถ้าชนะ ชนะหนัก (positive skew)
Long OTM Call~10-20%"เหมือนซื้อหวย"แต่ถ้า Black Swan → กำไรมหาศาล
กับดัก "Win Rate สูง = Trade ดี"

Win rate ไม่ได้บอกอะไรเลยถ้าไม่รู้ win/loss size

ตัวอย่าง:
Strategy A: ชนะ 90% ได้ ฿1, แพ้ 10% เสีย ฿20 → EV = 0.9×1 + 0.1×(-20) = -1.10
Strategy B: ชนะ 30% ได้ ฿10, แพ้ 70% เสีย ฿2 → EV = 0.3×10 + 0.7×(-2) = +1.60

Strategy A ชนะ 90% แต่ ขาดทุนระยะยาว
Strategy B ชนะแค่ 30% แต่ กำไรระยะยาว

กฎ: อย่าเลือก strategy จาก win rate → ให้คำนวณ EV เสมอ

4 Cognitive Biases ที่กระทบการอ่าน Payoff Chart

Biasอาการผลต่อ Payoffวิธีแก้
Loss Aversionกลัวเสียมากกว่าอยากได้เลือกแต่ "limited loss" shapeคำนวณ EV ไม่ใช่ดู shape
Anchoringยึดราคาซื้อเป็นจุดอ้างอิงไม่ยอม cut loss, repair แทน"ถ้าเริ่มใหม่จะทำเหมือนเดิมไหม?"
Recency Biasจำแค่ผลล่าสุดขาย vol หลัง vol ต่ำ 6 เดือนดูข้อมูลย้อนหลัง 10+ ปี
Overconfidenceคิดว่ารู้ดีกว่าตลาดเพิ่ม leverage, ลด hedgeใช้ Half-Kelly, ลด size
วิธีป้องกัน: "Payoff Checklist ก่อนทุก Trade"

ก่อนเปิด trade ถามตัวเอง 5 ข้อ:
1. EV เป็นบวกไหม? (ไม่ใช่แค่ "win rate สูง")
2. Max loss รับได้ไหม? (ถ้า worst case เกิดจริง)
3. ผมเลือก shape นี้เพราะ logic หรือเพราะรู้สึกดี?
4. Simple version ชนะไหม? (Baseline Test จาก Part VII)
5. ถ้าเริ่มใหม่วันนี้ ผมจะเปิด trade เดิมไหม?
