# กลยุทธ์ Stat Arb ข้ามตลาดแบบ Full Hedge (Lighter × Bitget/Bybit)

> แกะโจทย์จากข้อมูลสาธารณะของคอร์ส "Alpha Leak EP3" และบทสนทนาในกลุ่ม แล้วออกแบบกลยุทธ์ที่สอดคล้องกับเบาะแสทั้งหมด
> **เอกสารนี้เป็นการเดาโครงสร้างจากเบาะแสสาธารณะ ไม่ใช่เนื้อหาคอร์สจริง** ตัวเลขทุกตัวจากโปรแกรมจำลองเป็นข้อมูลสังเคราะห์ ใช้ดูกลไกเท่านั้น ห้ามใช้เป็นตัวคาดการณ์ผลตอบแทน
> เครื่องมือประกอบ: `tools/xvenue_statarb.py`

## 1. แกะเบาะแส

| เบาะแส (จากประกาศ/แชท) | แปลว่าอะไร |
|---|---|
| "Statistical Arbitrage ไม่ใช่ Arbitrage 100%" | มีขา long และ short ของสินทรัพย์ที่ "ควรราคาเท่ากัน" แต่ไม่มีกลไกบังคับให้บรรจบ (ต่างจาก cash-and-carry ที่หมดอายุแล้วบรรจบแน่) → น่าจะเป็น **perp ตัวเดียวกันต่างตลาด** |
| "เปิดขารวมๆ กันในหลายแพลตฟอร์ม… รวมกันไม่มี downside แต่แต่ละขามี downside ถ้าเปิดหนัก บางขาอาจโดน liquidate ก่อน" | ขา long อยู่ตลาดหนึ่ง ขา short อยู่อีกตลาด margin **แยกกัน** — ราคาขึ้น 20% ขา short ขาดทุน 20% ของ notional แม้ทั้งพอร์ตเป็นกลาง → นี่คือความเสี่ยงหลัก |
| "เล่น leverage น้อย แทบไม่ต้องโยกเงิน" | ต้องโยก collateral จากตลาดที่กำไรไปตลาดที่ขาดทุนเป็นครั้งคราว ยืนยันว่า 2 ขาอยู่คนละตลาด |
| Lighter "ไม่มีค่าธรรมเนียม" + Bitget/Bybit "ขอลดค่าธรรมเนียมได้" | ค่าธรรมเนียมคือตัวตัดสินว่ากลยุทธ์รอดไหม → เป็นกลยุทธ์ **เทรดถี่ กำไรต่อครั้งบาง** (ระดับ bp) ไม่ใช่ถือ carry ยาวๆ อย่างเดียว |
| "10–25% ต่อปี ตลาดผันผวนได้เยอะ" | กำไรมาจาก **ส่วนต่างราคาข้ามตลาดที่ถ่างตอนตลาดวิ่งแรง** (และ funding ที่ต่างกันมากตอนตลาดร้อน) |
| "พอร์ต ~$100,000 เทรด ~2 สัปดาห์คืนทุน" | 10–25%/ปี × $100k ÷ 26 ≈ **$400–950** ≈ ราคาคอร์ส → สอดคล้องกัน |
| "มีโอกาสได้ airdrop Lighter" | เทรดถี่บน Lighter = volume สูง = แต้ม/airdrop เป็น upside เสริม (ไม่นับในผลตอบแทนหลัก) |
| "มีโปรแกรมประกอบ" | ต้องคำนวณ spread/z-score และส่งคำสั่ง 2 ตลาดพร้อมกันแบบเรียลไทม์ — ทำมือไม่ทัน |

**ข้อสรุป:** กลยุทธ์ที่เข้ากับทุกเบาะแสคือ
**Cross-venue perp spread mean-reversion + funding differential, delta-neutral แบบเต็มขา**
คือ long perp ที่ตลาดที่ "ถูกกว่าปกติ" + short perp ตัวเดียวกันที่ตลาดที่ "แพงกว่าปกติ" แล้วปิดเมื่อส่วนต่างกลับสู่ค่าเฉลี่ย ระหว่างถือก็เก็บ/จ่าย funding ส่วนต่าง

## 2. ทำไมส่วนต่างถึงเกิด (ที่มาของ edge)

1. **Mark/oracle และ order book ต่างกัน** — Lighter เป็น perp DEX (ZK rollup) มีผู้ร่วมตลาดคนละกลุ่มกับ CEX; ตอนราคาวิ่งเร็ว book ฝั่งที่สภาพคล่องบางกว่าจะตามช้า/เลยไป
2. **รอบ funding ต่างกัน** — Lighter คิดรายชั่วโมง, Bitget/Bybit ส่วนใหญ่ทุก 8 ชม. (บางเหรียญ 1–4 ชม.) ทำให้ perp แต่ละที่ซื้อขายที่ premium ต่างกันอย่างเป็นระบบ และ premium นี้กระโดดใกล้เวลาตัด funding
3. **กระแสคนเล่นต่างกัน** — รายย่อยบน DEX มักเอียง long หนักกว่า → premium/funding บน DEX สูงกว่าเป็นช่วงๆ
4. **ความผันผวนสูง → ส่วนต่างถ่างบ่อยและกว้าง** → จำนวนครั้งที่เข้าเทรดได้คุ้มค่าธรรมเนียมเพิ่มขึ้น (ตรงกับ "ตลาดผันผวนได้เยอะ")

ทำไมเป็น "เชิงสถิติ": ส่วนต่างอาจไม่กลับ — ตลาดหนึ่งปิดถอนเงิน/ระบบล่ม/ oracle เพี้ยน/ เหรียญถูกถอด หรือค่าเฉลี่ยของส่วนต่างเลื่อน (regime shift) ไม่มีวันหมดอายุที่บังคับให้บรรจบ

## 3. สเปกกลยุทธ์

### 3.1 จักรวาลการเทรด
- ตลาด: A = Lighter (fee 0), B = Bitget และ/หรือ Bybit (ขอ fee ลด/VIP) — ถ้ามี 3 ตลาด ให้คำนวณทุกคู่ (A–B1, A–B2, B1–B2) และเลือกคู่ที่ edge สุทธิสูงสุด
- สินทรัพย์: BTC, ETH, SOL เป็นแกน (สภาพคล่องลึก ความเสี่ยงหลุดต่ำ) + alt ที่มีทั้งสองตลาดและ volume พอ (spread ถ่างกว่าแต่เสี่ยงกว่า) — คัดด้วย volume 24h และ depth ±10bp ขั้นต่ำ

### 3.2 สัญญาณ
ข้อมูลระดับ 1 วินาที–1 นาที (ใช้ mid หรือดีกว่าคือราคา executable: bid/ask ที่ขนาดเทรดจริง)

```
x_t  = ln(mid_A) − ln(mid_B)                   # ส่วนต่าง (log) หน่วย bp
μ_t  = EWMA(x, half-life ≈ 6 ชม.)               # ค่าเฉลี่ยเคลื่อนที่ (ส่วนต่างเชิงโครงสร้าง)
σ_t  = sqrt(EWMV(x − μ))
z_t  = (x_t − μ_t) / σ_t
```
ตรวจทุกวันว่าส่วนต่างยัง mean-revert: ประมาณ AR(1) `x_t − μ = φ(x_{t−1} − μ) + ε` → half-life = ln2 / −ln φ ต้องสั้น (นาที–ชั่วโมง) ถ้า half-life ยาวขึ้นผิดปกติหรือ φ→1 = **หยุดเทรดคู่นั้น**

### 3.3 กฎเข้า/ออก
- **ต้นทุนไป-กลับ** `C = 2×(fee_A + fee_B) + 4×slippage` (Lighter fee 0 ⇒ `C ≈ 2·fee_B + 4·slip`)
- **เข้า** เมื่อ `|z| ≥ 1.5` และ `|x − μ| − C ≥ edge ขั้นต่ำ` (เช่น 1bp)
  - `z > 0` (A แพงไป) → **short A / long B**
  - `z < 0` (A ถูกไป) → **long A / short B**
- **เติมแบบขั้นบันได** ที่ `|z| = 1.5 / 2.5 / 3.5` ชั้นละ 1/3 ของขนาดสูงสุด (ช่วงผันผวน spread ถ่างต่อได้อีก — ไม่ต้องทุ่มหมดทีแรก)
- **ออก** เมื่อ `z` กลับข้ามเกณฑ์ `±0.3`, หรือถือเกิน time-stop (≈ 3–4 เท่าของ half-life), หรือ `|z| > 6` (stop — สงสัยว่าเกิดเหตุผิดปกติ เช่น ตลาดหนึ่งปิดถอน)
- **ปรับด้วย funding**: คะแนนที่ใช้ตัดสินจริง
  ```
  E[กำไร] ≈ |x − μ|·(1 − e^{−H/τ})  +  (funding ที่ได้รับสุทธิ ระหว่างถือ H)  −  C
  ```
  ถ้าอีก ≤ 15 นาทีจะถึงรอบตัด funding และทิศที่ถือ "จ่าย" funding ฝั่งหนึ่งมากกว่าที่ได้อีกฝั่ง ให้ปิดก่อน/เลื่อนการเข้า; ถ้า "ได้รับ" ให้ถือข้ามรอบได้
- **โหมด carry (เสริม)**: เมื่อส่วนต่าง funding รายปีระหว่าง 2 ตลาดสูงกว่าเกณฑ์ (เช่น > 15%/ปี ต่อเนื่อง) ถือ long ฝั่ง funding ต่ำ/short ฝั่ง funding สูงค้างไว้ได้ (ขนาดเล็ก) — นี่คือส่วนที่ทำให้ "ตลาดร้อน" ได้เยอะ

### 3.4 การส่งคำสั่ง (โปรแกรมต้องทำ)
- ขา CEX: **post-only (maker)** เพื่อใช้ maker fee ที่ต่อรองได้ → พอ fill ส่ง **taker ที่ Lighter ทันที** (fee 0) เพื่อปิด hedge
  - เหตุผล: ขา Lighter ไม่มีค่าธรรมเนียมทั้ง maker/taker จึงเป็นขาที่ "ยอมจ่ายข้ามสเปรด" ได้ถูกสุด
  - ข้อควรระวัง: บัญชีฟรีของ Lighter มีความหน่วงการส่งคำสั่ง (ตรวจสเปกปัจจุบันเอง) → ต้องเผื่อ slippage ระหว่างหน่วง
- เปิด-ปิดต้องเป็น **คู่เสมอ**: ถ้าขาสองไม่ fill ใน N วินาที → ยกเลิก/ปิดขาแรกด้วย market — **ห้ามมีขาเปลือยค้าง**
- ปิดใช้ reduce-only ทั้งสองขา
- ตรวจ delta รวมทุก 1–5 วินาที (ขนาดสัญญาต่างกัน, lot size ต่างกัน → ปัดเศษแล้วมี delta ค้างเล็กน้อย ต้องชดเชย)

### 3.5 ขนาดและ leverage ("แต่ละขามี downside")
- แบ่งทุนครึ่ง-ครึ่งไว้สองตลาด: `notional ต่อขา = L × (ทุน/2)`
- ขาที่ขาดทุนจะโดน liquidate เมื่อราคาวิ่งสวน ≈ `1/L − maintenance margin`
  - L = 2 → ทนได้ราว 45–48% / L = 3 → ราว 30% / L = 5 → ราว 18% / L = 10 → ราว 8% (ซึ่ง crypto วิ่งได้ในวันเดียว)
- **กฎแนะนำ: L ≤ 3 ต่อขา** และตั้ง alert เมื่อราคาวิ่ง ≥ 1/(2L) จากจุดเข้า → โยก collateral จากตลาดที่กำไรไปตลาดที่ขาดทุน หรือ **ลดขนาดทั้งสองขาเท่ากัน** (ไม่ลดขาเดียว)
- ใช้ **cross margin** ภายในตลาดเดียวกัน (หลายคู่ช่วยกันรับ margin) แต่ระวัง: ขาที่ขาดทุนของหลายเหรียญที่วิ่งไปทางเดียวกันจะกองอยู่ฝั่งเดียว
- เพดานความเสี่ยงต่อตลาด (counterparty/DEX smart-contract): ไม่เกิน 50–60% ของทุนในตลาดใดตลาดหนึ่ง

## 4. คณิตศาสตร์ผลตอบแทน (เช็กว่า 10–25%/ปี สมเหตุสมผลไหม)

```
ผลตอบแทน/ปี ≈ (notional เฉลี่ยที่ใช้ / ทุน) × [ จำนวนรอบ/ปี × (edge ต่อรอบ − C) + funding สุทธิ/ปี ]
```
ตัวอย่าง: L = 3 ⇒ notional สูงสุด = 1.5× ทุน, ใช้จริงเฉลี่ย ~1/3 ⇒ 0.5× ทุน
ต้องการ 15%/ปี ⇒ ต้องได้สุทธิ ~30% ต่อปีของ notional ที่ใช้ ⇒ ≈ **0.8bp ต่อวัน** สุทธิหลังหักต้นทุน
เช่น 2 รอบ/วัน × edge สุทธิรอบละ ~0.4bp… → เห็นได้ว่า **edge บางมาก และ fee 1bp ก็พลิกผลได้** นี่คือเหตุผลที่ผู้สอนย้ำเรื่อง fee 0 และขอลดค่าธรรมเนียม

### ผลจากโปรแกรมจำลอง (ข้อมูลสังเคราะห์ 90 วัน, spread OU σ 1.5bp ช่วงเงียบ / 3.5bp ช่วงผันผวน, half-life 20 นาที)

ความไวต่อค่าธรรมเนียมฝั่ง CEX (L = 3, slippage 0.5bp/ขา, Lighter fee 0):

| fee ฝั่ง B ต่อข้าง | 0 bp | 1 bp | 2 bp | 4 bp | 5.5 bp (≈ taker ปกติ) |
|---|---|---|---|---|---|
| ผลตอบแทน/ปี | 78.9% | 34.2% | 14.5% | 1.2% | −0.0% |

ไล่ leverage (fee B 2bp):

| L/ขา | 1 | 2 | 3 | 5 | 8 | 10 |
|---|---|---|---|---|---|---|
| ผลตอบแทน/ปี | 4.8% | 9.7% | 14.5% | 24.2% | 38.8% | 48.4% |
| equity ขาแย่สุด (% ของตั้งต้น) | 94% | 89% | 83% | 72% | 55% | 50% |
| ต้องโยกเงิน | 0 | 0 | 0 | 0 | 0 | 1 |

อ่านผล:
1. **ค่าธรรมเนียมคือทุกอย่าง** — จาก fee 2bp → 4bp ผลตอบแทนหายเกือบหมด
2. leverage สูงเพิ่มผลตอบแทนแบบเส้นตรง แต่ equity ขาที่แย่สุดลดลงเร็ว → ต้องโยกเงินบ่อย/เสี่ยง liquidate ขาเดียว (ตรงกับที่แอดมินบอก)
3. Sharpe ในข้อมูลจำลองสูงเกินจริงมาก เพราะไม่มีเหตุการณ์ผิดปกติ (ตลาดล่ม, depeg, ถอนไม่ได้) — ของจริงความเสี่ยงอยู่ที่หาง ไม่ใช่ค่าเฉลี่ย

## 5. ความเสี่ยงและกฎหยุด

| ความเสี่ยง | การรับมือ |
|---|---|
| ขาเดียวโดน liquidate ตอนราคาวิ่งแรง | L ≤ 3, alert ที่ 1/(2L), โยก collateral/ลดทั้งคู่, เก็บ USDC สำรองบนทั้งสองตลาด |
| ขาเปลือย (fill ไม่ครบ/API ล่ม) | timeout + ปิดขาแรกอัตโนมัติ, kill-switch เมื่อ net delta > เกณฑ์ |
| ส่วนต่างไม่กลับ (regime shift) | stop ที่ \|z\| > 6, time-stop, ตรวจ half-life รายวัน, หยุดคู่ที่ φ→1 |
| funding พลิก | คิด funding ในคะแนนเข้าเทรด, ปิดก่อนรอบตัดถ้าต้องจ่าย |
| ตลาดหนึ่งปิดถอน/ล่ม/ DEX bug | จำกัดเงินต่อตลาด, ไม่ใช้เหรียญที่มีแค่ฝั่งเดียวลึก, ติดตามสถานะ bridge/withdrawal |
| ADL (auto-deleverage) ฝั่งกำไรโดนตัด | ADL ทำให้ขาหนึ่งหายไป → ต้องมีตัวตรวจ position จริงจาก API และ hedge ใหม่ทันที |
| กฎ/ข้อตกลงแพลตฟอร์ม (เช่น การต่อรอง fee, wash-trading/farming points) | อ่าน ToS ของแต่ละตลาด, เทรดเพราะ edge จริง ไม่ใช่ปั้น volume |
| edge เสื่อมเมื่อคนทำมากขึ้น | ติดตาม edge ต่อรอบรายสัปดาห์ (ดู `docs/statarb-alpha-decay.html`) |

## 6. ขั้นตอนทดลองจริง (ก่อนใช้เงินจริง)

1. **เก็บข้อมูล** order book top-of-book + funding ของทั้งสองตลาด (WebSocket) อย่างน้อย 2–4 สัปดาห์ ทั้งช่วงเงียบและผันผวน
2. แปลงเป็น CSV `ts,mid_a,mid_b,funding_a,funding_b` แล้วรัน
   `python3 tools/xvenue_statarb.py --csv data.csv --fee-b-bps <fee จริง> --slip-bps <ที่วัดได้>`
   (ควรแทน mid ด้วยราคา executable ที่ขนาดเทรดจริง จะได้ผลไม่สวยเกินจริง)
3. ดู: half-life ของ spread, edge ต่อรอบ vs ต้นทุน, จำนวนรอบ/วันแยกตาม regime ความผันผวน
4. paper trade / เงินเล็ก (เช่น $1–2k) วัด slippage และความหน่วงจริงของ Lighter → ปรับ `--slip-bps`
5. ขยายทีละขั้น และเทียบ live vs backtest ทุกสัปดาห์ (ดู `docs/statarb-live-vs-backtest.html`)

## 7. ทางเลือกที่ "อาจ" เป็นของจริงแทน

ถ้าสิ่งที่คอร์สสอนไม่ใช่ spread mean-reversion ตัวเลือกที่ใกล้เคียงรองลงมาคือ:
- **Funding-rate arbitrage ข้ามตลาดล้วนๆ** (long ที่ funding ต่ำ/short ที่ funding สูง ถือยาว) — โครงสร้างการโยกเงินและความเสี่ยงขาเดียวเหมือนกัน แต่ไม่ต้องเทรดถี่ จึงไม่ค่อยอธิบายเรื่อง "ต้องลด fee"
- **Spot–perp basis** (long spot / short perp) — ไม่ต้องใช้ 2 แพลตฟอร์ม และ leg spot ไม่มี liquidation จึงขัดกับเบาะแส "บางขาโดน liquidate" → ตัดทิ้ง

โครงในเอกสารนี้ครอบคลุมทั้งข้อแรกแล้ว (โหมด carry ในหัวข้อ 3.3)

---

*การศึกษาเท่านั้น ไม่ใช่คำแนะนำการลงทุน — ตัวเลขทั้งหมดจากข้อมูลสังเคราะห์*
