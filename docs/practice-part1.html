Practical Quant: Stat Arb ที่ใช้ได้จริง

Part I — บันได β: หา hedge ratio ยังไง (โลกทีละคู่)
β (hedge ratio) คือหัวใจของทุก spread — Part นี้ค่อย ๆ ไต่บันได 4 ขั้นจาก OLS → TLS → Rolling → Kalman พร้อมตอบคำถามที่คนพลาดบ่อยสุด: ทำไม OLS ที่ทุกคนใช้ ถึงใช้ได้แค่บางสถานการณ์ · ทั้งบทใช้ตัวอย่างเดียว (Coke–Pepsi) เดินไปด้วยกัน
🧭 เส้นทางอ่าน

🟢 มือใหม่: อ่านทุกกล่อง 🚶 (อ่านเป็นภาษาคน) + 🧮 (ตัวอย่าง) + ✍️ (ลองทำเอง) เรียงไป — ข้ามกล่องสูตร .fm ก่อนได้ · 🔵 มีพื้น: เน้น §1.3 (super-consistency) + §1.5 (TLS พังเมื่อไร) · เริ่มด่วน: §1.3 คือจุดพลิกความเข้าใจ

เริ่มจากคำถามเดียว: ถือขาไหนเท่าไร?

🚶 อ่านเป็นภาษาคนก่อน — hedge ratio คืออะไร

ลองนึกถึงการผสมเครื่องดื่ม: ถ้าจะให้รสคงที่ ทุกครั้งต้องผสม "น้ำเชื่อม 1 ส่วน ต่อ น้ำ 3 ส่วน" — อัตราส่วนนั้นสำคัญ ผสมผิดสัดส่วน รสเพี้ยนทันที

Stat arb ก็เหมือนกัน: เราถือหุ้น 2 ตัวสวนทางกัน (ซื้อตัวหนึ่ง ขายชอร์ตอีกตัว) เพื่อให้เหลือแค่ "ส่วนต่าง" (spread) ที่แกว่งไปมารอบค่าเฉลี่ย · β คืออัตราส่วนผสมนั้น — ซื้อ A 1 หุ้น ต้องชอร์ต B กี่หุ้น

ตลอด Part นี้เราจะใช้คู่เดียวเดินเป็นตัวอย่าง — Coca-Cola (KO) กับ PepsiCo (PEP) สองบริษัทน้ำอัดลมที่ธุรกิจคล้ายกัน ราคามักขยับไปด้วยกัน · ตัวอย่างคลาสสิกที่เข้าใจง่าย (ตัวเลขข้างหน้าเป็นสมมติเพื่อสอน ไม่ใช่ราคาจริง)

spread = ราคา_KO − β × ราคา_PEP

ถ้า β = 1.3 → ซื้อ KO 1 หุ้น ต้องชอร์ต PEP 1.3 หุ้น จึงจะได้ spread ที่ "สะอาด"

คำถามคือ — เลข 1.3 นั้นมาจากไหน? นั่นคือทั้งหมดของ Part นี้ และมันมีหลายวิธี ไล่เป็นบันได แต่ละขั้นแก้จุดอ่อนของขั้นก่อน:

ขั้น 0 : OLS β คงที่ ประมาณครั้งเดียว (ง่ายสุด · เริ่มที่นี่)
ขั้น 1 : TLS / PCA แก้ปัญหา "ทั้งสองขามี noise"
ขั้น 2 : Rolling OLS β เดินตามเวลาแบบหน้าต่างเลื่อน
ขั้น 3 : Kalman β เดินแบบจำอดีต + optimal (→ เจาะลึก Part IV)

🔖 ทบทวนพื้นฐาน — 4 คำที่ต้องรู้จักก่อนไปต่อ

ก่อนลงรายละเอียดทีละขั้น นี่คือสรุปสั้น ๆ ว่าแต่ละคำหมายถึงอะไร — ถ้าอ่านรอบแรกแล้วงง กลับมาที่กล่องนี้ได้เสมอ

OLS (Ordinary Least Squares)

วิธีลากเส้นตรงผ่านกลุ่มจุดข้อมูล โดยให้เส้นนั้น "ใกล้จุดทุกจุดที่สุด" วัดความใกล้แบบแนวตั้งเท่านั้น (สมมติว่าแกนนอนไม่มีความคลาดเคลื่อน) — ความชันของเส้นคือ β · เป็นวิธีพื้นฐานที่สุด เร็วที่สุด แต่มีสมมติฐานที่บางครั้งไม่จริง (§1.2–1.3)

EIV — Errors-in-Variables

ไม่ใช่วิธี — แต่คือชื่อของปัญหาที่เกิดขึ้นเมื่อ "ตัวแปรที่เราใช้ทำนาย" (แกนนอน) ก็มีความคลาดเคลื่อน/สัญญาณรบกวนปนอยู่ เหมือนวัดด้วยไม้บรรทัดที่สั่น · ผลคือ OLS จะประมาณ β ต่ำกว่าความจริงอย่างเป็นระบบ เรียกว่า attenuation bias (ลงรายละเอียดเต็มใน §1.2)

TLS (Total Least Squares) / Deming regression

วิธีลากเส้นแบบเดียวกับ OLS แต่วัดความใกล้แบบตั้งฉากกับเส้น — ยอมรับว่าทั้งสองแกนมีความคลาดเคลื่อนได้ · เป็นคำตอบสำหรับปัญหา EIV ข้างบน แต่ต้องแลกด้วยสมมติฐานใหม่ (§1.5)

Kalman Filter

วิธีประมาณ β ที่อัปเดตทุกวันแบบอัตโนมัติ โดยชั่งน้ำหนักระหว่าง "ความเชื่อเดิม" กับ "ข้อมูลใหม่ที่เพิ่งเห็น" — เหมือน rolling OLS เวอร์ชันฉลาดที่จำอดีตอย่างนุ่มนวลแทนที่จะตัดทิ้งดื้อ ๆ (§1.7 ปูพื้น, เจาะลึกจริงใน Part IV)

✍️ เช็คความเข้าใจ (ตอบในใจก่อนอ่านต่อ)
  1. OLS กับ TLS ต่างกันตรงไหน? (ตรงที่วัดระยะห่างจากเส้นคนละแบบ — แนวตั้ง vs ตั้งฉาก)
  2. EIV เป็น "วิธีแก้" หรือ "ชื่อปัญหา"? (ชื่อปัญหา — TLS/Kalman คือวิธีแก้)
  3. Kalman ต่างจาก rolling OLS ตรงไหนแบบคร่าว ๆ? (Kalman ถ่วงน้ำหนักอดีตแบบนุ่มนวล ไม่ตัดทิ้งที่ขอบหน้าต่างเหมือน rolling)
เป้าหมายของ Part นี้ (อ่านก่อน)

ไม่ใช่ให้คุณ "ใช้ Kalman เป็น" (ใครก็ใช้เป็น — Part 0 บอกแล้วว่านั่นไม่ใช่ edge) แต่ให้คุณเข้าใจว่าแต่ละขั้นเชื่ออะไร · พังเมื่อไร · เลือกใช้ตัวไหนเมื่อไร — เพราะเลือกผิดขั้น = ถือความเสี่ยงที่ไม่ได้ตั้งใจ

1.1 ขั้น 0 — OLS: จุดตั้งต้นที่ทุกคนเริ่ม

🚶 อ่านเป็นภาษาคนก่อน

วาดกราฟกระจาย (scatter): แกนนอน = ราคา PEP · แกนตั้ง = ราคา KO · แต่ละวันเป็นจุดหนึ่งจุด · OLS คือการลากเส้นตรงเส้นเดียวที่ "ใกล้จุดทุกจุดที่สุด" — ความชันของเส้นนั้นคือ β และระยะที่จุดจริงห่างจากเส้น คือ spread (ส่วนที่เส้นอธิบายไม่ได้)

KO = α + β × PEP + ε
└─ ε = spread ที่เราจะเทรด

β = Cov(KO, PEP) / Var(PEP) ← สูตรลัดหา ความชัน

เขียนโค้ดบรรทัดเดียวก็ได้ (เช่น statsmodels.OLS) มันเร็ว เข้าใจง่าย มีในทุกไลบรารี · ในหลายกรณีก็ พอใช้ — ปัญหาคือ "หลายกรณี" ไม่ใช่ "ทุกกรณี" และตรงนี้แหละที่มือใหม่พลาด

1.2 ทำไม OLS "ใช้ได้แค่บางสถานการณ์"

OLS มีจุดพัง 2 อย่างที่ต้องเข้าใจก่อนใช้จริง

จุดพัง 1 — ไม่สมมาตร (asymmetric)

🚶 พูดให้เห็นภาพ

ถ้าคุณถาม OLS ว่า "KO ขยับตาม PEP เท่าไร" ได้เลขหนึ่ง · แต่ถ้าถามกลับว่า "PEP ขยับตาม KO เท่าไร" แล้วพลิกกลับหน่วย — คุณจะได้คนละเลข ทั้งที่มันควรเป็นความสัมพันธ์เดียวกัน!

เหตุผล: OLS ต้อง "เลือกข้าง" ว่าตัวไหนเป็นตัวแปรตาม (y) แล้วผลลัพธ์ก็ขึ้นกับการเลือกนั้น · แปลว่า β ที่ได้ ขึ้นกับว่าคุณวางตัวไหนเป็นแกนตั้ง — ซึ่งไม่ควรจะเป็นแบบนั้น

จุดพัง 2 — Errors-in-Variables (EIV / attenuation bias)

🚶 อุปมา "ไม้บรรทัดสั่น"

OLS ตั้งสมมติฐานว่า แกนนอน (PEP) วัดมาแม่นเป๊ะ ไม่มี error เลย · แต่ในตลาดจริง ราคา PEP ก็มี noise (bid-ask, ซื้อขายไม่ต่อเนื่อง) เท่า ๆ กับ KO — เหมือนคุณวัดความยาวด้วยไม้บรรทัดที่สั่นทั้งสองแกน · ผลคือ OLS จะประมาณความชัน (β) ต่ำกว่าจริงเสมอ — เอนเข้าหา 0

β̂_OLS ≈ β_จริง × Var(สัญญาณจริงของ PEP)
─────────────────────────────
Var(สัญญาณจริง) + Var(noise ของ PEP)

└──── ตัวคูณนี้ < 1 เสมอ เมื่อ PEP มี noise ────┘
🧮 ตัวอย่างเชิงตัวเลข (สมมติ เพื่อให้เห็นภาพ)

สมมติความสัมพันธ์จริง β = 1.00 และราคา PEP มี noise = 20% ของสัญญาณจริง:

β̂_OLS ≈ 1.00 × [ 1 / (1 + 0.20) ] ≈ 0.83

→ คุณคิดว่าต้องชอร์ต PEP 0.83 หุ้น แต่ที่ถูกคือ 1.00 → hedge น้อยไป 17% → spread ที่ได้ยังแบกความเสี่ยงทิศทางค้างอยู่โดยไม่รู้ตัว

✍️ ลองคิดเอง

ถ้า noise ของ PEP เพิ่มเป็น 50% ของสัญญาณ — β̂ ที่ OLS ให้จะเป็นเท่าไร? (เฉลย: 1.00 × 1/(1+0.5) ≈ 0.67 → hedge น้อยไปถึง 1 ใน 3) · เห็นไหมว่ายิ่ง noise เยอะ OLS ยิ่งเพี้ยนหนัก

📖 เกร็ด: attenuation bias นี้ Ragnar Frisch ชี้ไว้ตั้งแต่ยุค 1930s — ไม่ใช่ของใหม่ แต่คนเทรดสมัยนี้ลืมมันบ่อยมาก

1.3 ★ จุดพลิกความเข้าใจ — "ราคา" กับ "ผลตอบแทน" ไม่เหมือนกัน

ตรงนี้คือเพชรของ Part I และเป็นคำตอบจริงว่าทำไม "OLS แย่" ถึงเป็นความเชื่อที่ถูกแค่ครึ่งเดียว

🚶 คำถามง่าย ๆ ที่ตอบยาก: คุณ regress อะไร?

คุณเอา ราคา (เช่น KO = 60 บาท) มา regress? หรือเอา ผลตอบแทน (วันนี้ KO +1.2%) มา regress? · ฟังดูเหมือนกัน แต่มันคนละโลก และถ้าเลือกผิด กลยุทธ์พังตั้งแต่บรรทัดแรก

★ ประเด็นหลักที่ต้องจำ

EIV/attenuation ที่เพิ่งเล่า (β เอนเข้า 0) เกิดกับ return regression (regress ผลตอบแทน) — แต่ แทบไม่เกิดกับ cointegration ที่ regress ราคา on ราคา เพราะปรากฏการณ์ชื่อ super-consistency

🚶 super-consistency คืออะไร (ภาษาคนล้วน)

ปกติยิ่งเก็บข้อมูลเยอะ ค่าประมาณยิ่งแม่นขึ้น — แต่แม่นขึ้น "ช้า ๆ" · แต่เมื่อหุ้น 2 ตัว cointegrate กันจริง (ราคามันผูกกันแบบมีระยะห่างคงที่) OLS บนราคาจะลู่เข้าหา β จริง เร็วมากผิดปกติ — เร็วจน noise ที่ทำให้เกิด EIV ถูกกลบหายไปเองเมื่อข้อมูลมากพอ (Stock 1987)

พูดสั้น ๆ: บนราคาที่ cointegrate กัน OLS "ดีเกินคาด" — ข้อกังวลเรื่อง EIV ที่เพิ่งเรียน ใช้ไม่ได้ที่นี่

ราคา / Level (Cointegration)ผลตอบแทน / Return (Correlation, Factor)
regress อะไรราคา on ราคาผลตอบแทน on ผลตอบแทน
β หมายถึงอัตราส่วนที่ทำให้ส่วนต่าง นิ่ง (stationary)ความไว/exposure ณ ขณะนั้น
ตอบคำถาม"spread จะกลับไหม""ตอนนี้ฉัน neutral ต่อ factor ไหม"
OLS ใช้ได้ไหม✅ ดี (super-consistent) · จะเนียนขึ้นใช้ FM-OLS/DOLS⚠️ EIV จริง → TLS/PCA/Kalman ช่วย
ใช้ผิดแล้วพังยังไงถ้าไม่ cointegrate = spurious regressionlevel ลอยห่างได้ แม้ return ขยับด้วยกัน
📉 spurious regression — กับดักที่ฆ่ามือใหม่

ถ้าเอาราคา 2 ตัวที่ไม่ cointegrate จริงมา regress กัน — คอมจะรายงาน R² สูง ค่าสถิติดูดีไปหมด เหมือนเจอขุมทอง — แต่มันปลอมทั้งหมด · residual ไม่นิ่ง "spread" ไม่มีวันกลับ มันลากออกไปเรื่อย ๆ จนพอร์ตพัง (Granger & Newbold 1974)

บทเรียน: R² สูงบนราคา ≠ เทรดได้ → ต้องทดสอบว่า residual นิ่งจริงไหมเสมอ (นั่นคือ ADF test ใน Part II)

🧠 มุมที่ quant มองต่าง

คนทั่วไปเห็น: "OLS มี bias → OLS แย่ → ทิ้ง"
quant เห็น: bias มีจริงเฉพาะบางบริบท — OLS บนผลตอบแทนแย่ แต่ OLS บนราคาที่ cointegrate กลับดีเยี่ยม · คำถามที่ถูกไม่ใช่ "OLS ดีหรือแย่" แต่คือ "ฉันกำลัง regress ราคา หรือ ผลตอบแทน"

1.4 แปลง β เป็นออร์เดอร์จริง — 3 ความ "neutral" ที่สับสน

β เป็นแค่อัตราส่วน · พอถึงเวลากดส่งคำสั่งจริง ต้องแปลงเป็นจำนวนหุ้น และตรงนี้มี 3 คำที่คนปนกันจนพัง

อยากให้ neutral แบบไหนทำยังไงได้ / ไม่ได้อะไร
Share-ratioถือ PEP จำนวน β หุ้น ต่อ KO 1 หุ้น (มาจาก cointegration)✅ ทำให้ spread กลับ · ❌ มักไม่ dollar-neutral
Dollar-neutrallong กับ short มูลค่าเงินเท่ากัน✅ คุมขนาดพอร์ต · ❌ ไม่การันตี spread กลับ
Beta-neutralไม่มี exposure สุทธิต่อตลาด/factor= อาณาเขต Part III
🧮 ตัวอย่างจับต้องได้ (สมมติ)

β = 1.3 · ราคา KO = 60 · ราคา PEP = 170 · คุณจะซื้อ KO 100 หุ้น (1 board lot ไทย = 100)

Share-ratio: ชอร์ต PEP = 1.3 × 100 = 130 หุ้น
มูลค่า long KO = 100 × 60 = 6,000
มูลค่า short PEP = 130 × 170 = 22,100 ← ไม่เท่ากัน!

เห็นไหมว่า share-ratio ที่ถูกต้องสำหรับ spread ไม่ได้ dollar-neutral เลย (6,000 vs 22,100) · ถ้าคุณฝืนปรับให้เท่ากัน คุณจะทำลายอัตราส่วนที่ทำให้ spread กลับ

📉 กับดัก: spread ที่แอบมีความเสี่ยงซ่อน

Share-ratio จาก cointegration โดยทั่วไปไม่ dollar-neutral และไม่ market-neutral → "spread" ของคุณอาจแอบถือความเสี่ยงตลาดอยู่ · นี่คือรากของ "factor bet ปลอมตัว" ที่จะเจาะลึกใน Part III

หลักที่ต้องปัก

เลือกก่อนว่าจะให้ neutral ต่ออะไร — แล้วจำนวนหุ้นจะตามมาเอง · ปกติเลือกได้ไม่ครบทั้งสาม · stat arb เลือก "ให้ spread กลับ" ก่อน แล้วค่อยคุมความเสี่ยงตลาดแยกต่างหาก (Part III)

🖥️ ลงลึกหน้าจอเทรดจริง — กระดานไทย
  • ปัดเป็นจำนวนเต็ม: β × หุ้น มักได้เศษ → ปัดเศษ = hedge เพี้ยนนิดหน่อยทุกครั้ง (เจ็บสุดตอนขาราคาสูง + ทุนน้อย เพราะไม่มี fractional share)
  • board lot ไทย = 100 หุ้น: ต้องสั่งเป็นล็อต → β×100 อาจไม่ลงตัวเป็นล็อต = จุดที่ทฤษฎีชนหน้าจอจริง
  • rebalance = ค่าคอมฯ: พอ β อัปเดต (rolling/Kalman) ต้องปรับจำนวนหุ้น เสียค่าคอมฯ ทุกครั้ง (โยง Part VI/VIII)

1.5 ขั้น 1 — TLS / Deming รู้ · ใช้เป็น · รู้ว่าพังตอนไหน

ถ้า EIV เกิดเพราะ OLS แกล้งว่าแกนนอนไม่มี noise — ทางแก้คือใช้วิธีที่ยอมรับว่าทั้งสองแกนมี noise นั่นคือ TLS (Total Least Squares) / Deming regression

🚶 อ่านเป็นภาษาคนก่อน — ต่างกันตรงวัดระยะ

ทั้ง OLS และ TLS ลากเส้นผ่านจุดเหมือนกัน แต่วัด "ความห่าง" ต่างกัน:

  • OLS วัดระยะจากจุดถึงเส้นในแนวตั้ง (สมมติ error อยู่ที่แกนตั้งเท่านั้น)
  • TLS วัดระยะตั้งฉากกับเส้น (ยอมรับ error ทั้งสองแกน) → สมมาตร + แก้ EIV
เชื่อมกับ PCA (จุดที่จะกลับมาใน Part III)

TLS ของ 2 สินทรัพย์ = ทิศที่ข้อมูลแกว่งมากที่สุด พอดี (เรียกว่า eigenvector ตัวแรก) → นี่คือสะพานสู่ eigenportfolio / PCA hedge ที่ Avellaneda-Lee (2010) ใช้จริง และเป็นแกนของ Part III

❌ TLS พังเมื่อไร (ส่วนที่คนไม่สอน)
  • เดา δ ผิด → แย่กว่า OLS: TLS ไม่ได้ลบ bias — มันแค่แลก bias หนึ่งด้วยสมมติฐานหนึ่ง คือ "noise สองขาแรงเท่ากัน" (δ=1) · ถ้าจริง ๆ ขาหนึ่ง noisy กว่ามาก TLS จะเพี้ยนกว่า OLS อีก
  • ไวต่อ outlier: จุดที่หลุดโด่งจะดึงเส้นแรงกว่าปกติในบางเคส
✅ สรุปกฎเลือก OLS vs TLS (จำแค่นี้พอ)
  • regress ราคา (cointegration) → ใช้ OLS ได้เลย ดีอยู่แล้ว (super-consistent)
  • regress ผลตอบแทน (hedge/factor) → EIV จริง → TLS/PCA ช่วย ถ้าประเมิน δ ได้ · ประเมินไม่ได้ → ใช้ Kalman (ขั้น 3) จัดการให้ดีกว่า

1.6 ขั้น 2 — Rolling OLS: ให้ β เดินตามเวลา

🚶 อ่านเป็นภาษาคนก่อน

β จริงไม่ได้อยู่นิ่ง — ธุรกิจเปลี่ยน ความสัมพันธ์เปลี่ยน · วิธีง่ายสุดคือคำนวณ OLS ใหม่เรื่อย ๆ บน "หน้าต่าง" ข้อมูลล่าสุด (เช่น 60 วันหลังสุด) แล้วเลื่อนหน้าต่างไปทุกวัน · แต่ขนาดหน้าต่างมี tradeoff ที่ต้องเข้าใจ

หน้าต่างสั้น (เช่น 20 วัน)
  • ✅ ไว — ตาม β ที่เปลี่ยนทัน
  • ❌ กระตุก — β เต้นตาม noise
  • ❌ rebalance บ่อย = ค่าคอมฯ พุ่ง
หน้าต่างยาว (เช่น 120 วัน)
  • ✅ นิ่ง — β ไม่เต้น
  • ❌ ช้า — ตาม β ที่เปลี่ยนไม่ทัน
  • ❌ กระโดดตอนข้อมูลเก่าหลุดขอบหน้าต่าง
⚠️ กับดัก look-ahead (มือใหม่พลาดบ่อยสุด)

ถ้าเผลอคำนวณ β หรือ mean/std ของ spread โดยใช้ข้อมูลทั้งชุดรวมอนาคต = คุณกำลัง "รู้อนาคต" ตอนตัดสินใจ → backtest สวยหลอก ๆ แต่ live พัง · กฎเหล็ก: ที่จุดเวลาใด ให้ใช้เฉพาะข้อมูลถึงจุดนั้นเท่านั้น

Rolling OLS คือสะพานสู่ขั้นสุดท้าย — เพราะจริง ๆ แล้ว Kalman filter = rolling regression เวอร์ชันฉลาด ที่ "จำ" อดีตอย่างเหมาะสมและถ่วงน้ำหนักแบบ optimal แทนที่จะตัดข้อมูลเก่าทิ้งดื้อ ๆ ที่ขอบหน้าต่าง

1.7 ขั้น 3 — Kalman: ยอดบันได → เจาะลึก Part IV

🚶 อ่านเป็นภาษาคนก่อน

Kalman อัปเดต β ทุกวันแบบ real-time โดยชั่งน้ำหนักระหว่าง "ความเชื่อเดิมเรื่อง β" กับ "ราคาที่เพิ่งเห็นวันนี้" — ใช้เฉพาะข้อมูลอดีต (ไม่รู้อนาคต) และนุ่มนวลกว่า rolling ที่กระตุก · ปุ่มที่สำคัญที่สุดคืออัตราส่วน Q/R: จะเชื่อความจำเดิม หรือเชื่อราคาล่าสุด แค่ไหน

state: β_วันนี้ = β_เมื่อวาน + การเปลี่ยนแปลง
observation: ราคาที่เห็น = β × ราคาอีกขา + noise

Q = "β เปลี่ยนเร็วแค่ไหน" · R = "เชื่อราคาล่าสุดแค่ไหน"
⏭️ ทำไมยังไม่ลงลึกตรงนี้

Kalman มีเรื่องต้องระวังเยอะ — จูน Q/R ยังไงไม่ให้ overfit · จะรู้ได้ยังไงว่า overfit · β ควรเป็น random walk จริงไหม — ทั้งหมดนี้เป็นหัวใจของ Part IV เต็ม ๆ ที่นี่แค่ให้เห็นว่ามันคือปลายทางของบันได β

สรุป Part I + สะพานสู่ Part II

✓ 3 อย่างที่ต้องจำจาก Part I
  1. "OLS แย่" ถูกครึ่งเดียว — แย่กับผลตอบแทน (EIV) แต่ดีเยี่ยมกับ cointegration บนราคา (super-consistent)
  2. แยก "ราคา" กับ "ผลตอบแทน" ให้ขาด — ราคา→"spread กลับไหม" · ผลตอบแทน→"neutral ไหม" · ปนกัน = spurious regression หรือ hedge หลอก
  3. β เป็นแค่อัตราส่วน — เลือกก่อนว่าจะ neutral ต่ออะไร แล้วจำนวนหุ้นตามมา; ระวังความเสี่ยงซ่อน + board lot

ตอนนี้เรามี β แล้ว และรู้ว่าจะเชื่อมันแค่ไหน — คำถามถัดไปคือ คู่ไหนถึงคู่ควรเทรดตั้งแต่แรก? ทุกคนใช้ correlation + cointegration test ชุดเดียวกัน สแกนหุ้นชุดเดียวกัน...

"ทุกคนมีเครื่องมือคัดคู่เหมือนกันเป๊ะ — แล้วเราจะต่างตรงไหน?"
📖 ศัพท์ใหม่ในตอนนี้
  • Hedge ratio (β) — อัตราส่วนถือ 2 ขาเพื่อสร้าง spread (เหมือนสูตรผสมเครื่องดื่ม)
  • EIV / attenuation bias — OLS ประมาณ β ต่ำไป เมื่อแกนนอนมี noise ("ไม้บรรทัดสั่น")
  • Super-consistency — OLS บนราคาที่ cointegrate ลู่เข้าเร็วผิดปกติ → EIV หายไปเอง
  • Spurious regression — regress ราคาที่ไม่ cointegrate ได้ผลดูดีแต่ปลอม
  • TLS / Deming — regression ที่ยอมรับ noise ทั้ง 2 แกน (วัดระยะตั้งฉาก)
  • Share / Dollar / Beta-neutral — 3 ความหมายของ "ปรับสมดุลขา" ที่ห้ามสับสน
